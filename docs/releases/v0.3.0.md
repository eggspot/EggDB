EggDB v0.3.0 builds on v0.2.0's single-file, crash-safe database and the SQL dialects served over
PostgreSQL, MySQL and SQL Server's protocols. This release is mostly SQL: statements people send
that were refused before, such as `UPDATE ... FROM`, `ROLLUP`, `DISTINCT ON`, `CONNECT BY` and
`SET LOCAL`, plus SQLite's dynamic typing (which adds a table-definition version that v0.2.0
refuses by name), plans for Oracle and SQL Server, agents that can write to tables limited to some
columns, every listener held to one memory budget, and a desktop client with query tabs, familiar
layouts and more. It is not faster than v0.2.0: joins are further from SQLite's speed than the
decisions require, and "Limits" says by how much. What it can't do yet is in one place, "Limits",
and what was tested on which platform in "What was tested".

## What v0.3.0 brings
- **Changing rows through a join** (D297). PostgreSQL's `UPDATE ... FROM` and `DELETE ... USING`,
  SQLite's `UPDATE ... FROM`, MySQL's multiple-table `UPDATE t1 JOIN t2 ... SET` and `DELETE t1, t2
  FROM ...`, and SQL Server's `UPDATE ... FROM` and `DELETE ... FROM` over joins, with `OUTPUT`. A
  target row that joins several rows is changed once, from one of them (which one is not defined,
  as in the manuals). `RETURNING` and `OUTPUT` can read the joined tables' columns, indexes are
  kept up to date and row triggers fire. A SQL Server target named by a table name that the `FROM`
  lists twice under aliases is Msg 8154. Refused with `0A000`: subqueries in `SET` and `RETURNING`
  of a joined statement, a view, partitioned table or table with row-level security as the target,
  and `EXPLAIN` of one ([sql.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/sql.md)).
- **Subtotals** (D298). `GROUP BY ROLLUP (...)`, `CUBE (...)`, `GROUPING SETS (...)` and `()` with
  `GROUPING()` in PostgreSQL, SQL Server and Oracle (`GROUPING_ID` in SQL Server and Oracle,
  `GROUP_ID()` in Oracle, `GROUP BY DISTINCT` in PostgreSQL), MySQL's `WITH ROLLUP` and SQL Server's
  `WITH ROLLUP` and `WITH CUBE`. PostgreSQL's limits apply (more than 4096 sets is `54001`), and so
  does one of EggDB's own: sets times keys may be at most 1,048,576, checked before anything is
  built, so a hostile clause is refused instead of allocating.
- **More query syntax** (D299, D300). PostgreSQL's `DISTINCT ON`; `NATURAL [INNER | LEFT | RIGHT |
  FULL] JOIN` (not in Transact-SQL, and `FULL` not in MySQL); `LIKE ... ESCAPE` in every dialect;
  SQLite's `GLOB` character classes (`[a-f]`, `[^0-9]`); PostgreSQL's `CREATE [OR REPLACE] [TEMP]
  RECURSIVE VIEW`; `FETCH FIRST n ROWS WITH TIES` in PostgreSQL and `TOP (n) [PERCENT] [WITH TIES]`
  in Transact-SQL; and the window forms `STRING_AGG ... OVER (PARTITION BY ...)` in Transact-SQL
  (the shape Azure Synapse documents; SQL Server itself refuses it) and `LISTAGG ... OVER
  (PARTITION BY ...)` in Oracle.
- **Settings that follow transactions and routines** (D301, PostgreSQL's dialect). `SET LOCAL` and
  `set_config(name, value, true)` end with the transaction; `ROLLBACK`, `ROLLBACK TO SAVEPOINT` and
  a failed `COMMIT` give back what a transaction changed; a routine's own `SET` clause (including
  `SET ... FROM CURRENT`, which is stored with the routine) applies while it runs, and `SET` works
  inside routines. Outside a transaction block `SET LOCAL` warns and changes nothing, as in
  PostgreSQL. `refcursor[]` values work too.
- **More SQL/JSON and functions** (D302). `expr IS [NOT] JSON [VALUE | SCALAR | ARRAY | OBJECT]
  [WITH | WITHOUT UNIQUE KEYS]`, `JSON()`, `JSON_SCALAR` and `JSON_SERIALIZE` (PostgreSQL 17's),
  jsonpath's `.decimal(precision, scale)`, a non-NULL base row for `json_populate_record`,
  `scale()`, `min_scale()` and `trim_scale()`, and the `citext` extension's case-insensitive
  `regexp_*`, `replace`, `split_part`, `strpos` and `translate`. The `citext` string functions fold
  case over all of Unicode to agree with EggDB's `citext` `=`, which differs from PostgreSQL for
  characters such as `ß`: `strpos('Straße'::citext, 'SS')` is 5 here and 0 in PostgreSQL.
- **SQL Server's `MERGE`, `OUTPUT ... INTO` and `SELECT ... INTO`** (D303). `MERGE` takes two
  `WHEN MATCHED` clauses, `$action` and `TOP (n) [PERCENT]`; `OUTPUT ... INTO` a table variable or
  table works on `INSERT`, `UPDATE`, `DELETE` and `MERGE`, all or nothing with the statement
  (a missing target is Msg 208, a column count mismatch Msg 213); `SELECT ... INTO new_table`
  (`#name` for a temporary table) works in Transact-SQL, and in PostgreSQL as `SELECT ... INTO
  [TEMPORARY] new_table`.
- **Oracle hierarchical queries and multitable inserts** (D304). `START WITH ... CONNECT BY
  [NOCYCLE] PRIOR`, `LEVEL`, `SYS_CONNECT_BY_PATH`, `CONNECT_BY_ROOT`, `CONNECT_BY_ISLEAF`,
  `CONNECT_BY_ISCYCLE`, `ORDER SIBLINGS BY` and `SELECT LEVEL FROM dual CONNECT BY LEVEL <= n`,
  walked depth first without recursion (a loop is `ORA-01436`, and a runaway `CONNECT BY 1 = 1`
  ends with the memory error), and `INSERT ALL` and `INSERT FIRST` with `WHEN` and `ELSE`, which
  read their source once, fire triggers and undo the whole statement when one target fails.
- **Plans for Oracle and SQL Server** (D312). Oracle's `EXPLAIN PLAN [SET STATEMENT_ID = ...]
  [INTO table] FOR` fills `PLAN_TABLE` and `SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY)` shows it, and
  SQL Server's `SET SHOWPLAN_TEXT ON`, `SET SHOWPLAN_ALL ON` and `SET STATISTICS PROFILE ON`
  answer with SQL Server's result sets (a showplan option stops statements from running, as
  Microsoft documents). `eggdb explain --dialect oracle` and `--dialect sqlserver`, and MCP's
  `explain_query`, print them too (before, both said `not_supported`). Costs and cardinalities are
  empty: EggDB's planner has no estimates. `EXPLAIN ANALYZE` now prints `actual time=` on the steps
  it can attribute, but not yet inside joins.
- **SQLite's dynamic typing, and a file format addition** (D305). Columns declared `TEXT`,
  `NUMERIC`, `REAL` or with no type now store each value in its own storage class and apply the
  column's affinity as [SQLite documents](https://www.sqlite.org/datatype3.html), so `'12'` stored
  in a `NUMERIC` column becomes the integer 12 and a text compared with such a column converts as
  in SQLite. Primary keys, `UNIQUE` constraints and indexes work on all of these columns, ordered
  as SQLite orders them (numbers by exact value, then text, then blobs). `INTEGER` columns keep
  their 64-bit integer type. `PRAGMA table_info` shows the type as declared (`DATETIME`,
  `DECIMAL(10, 2)`, empty for an untyped column). **Files:** the file format stays version 1, but
  a table written with these columns is table-definition version 13 (see "Compatibility from here
  on": v0.2.0 refuses such a table by name). Tables already in a file keep their column types.
- **Agents can write to tables limited to some columns** (D306). With `eggdb mcp --allow-write
  --tables 'orders(id,total),customers'`, an agent can now insert into and change the listed
  columns of such a table: the hidden columns keep their values on a change and take their
  defaults on an insert, indexes over them are kept, and the errors of checks and `NOT NULL` name
  neither a hidden column nor a value.
  A listed table's foreign key to an unlisted table is now checked on writes (it tells the agent
  whether a key exists there; the banner says so and the table can be listed without those
  columns), and a view may be listed with a column list. Still refused with `42501`: deleting
  rows or changing keys of a table listed with columns, and any change whose outcome would depend
  on a hidden value ([mcp.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/mcp.md)).
- **Secrets kept out of debug output, and one memory budget for every listener** (D307).
  Connection options, cancel keys, password messages, roles and the RESP server's settings print
  `***` instead of the secret when formatted for logs or panic messages. `eggdb serve
  --max-connection-memory` now covers the HTTP listeners (REST, Elasticsearch, S3, DynamoDB, SQS,
  metrics, observability, MCP over HTTP), Kafka, NATS, STOMP, MQTT, AMQP 0-9-1 and 1.0, Bolt and
  RESP pub/sub as well, each refusing in its own protocol's way (`413`/`429`/`503`, `-ERR`,
  `ERROR`, `0x97`, `506`, `amqp:resource-limit-exceeded`, a Bolt memory error), and a queue
  consumer is only leased the messages that fit
  ([cli.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/cli.md)).
- **SQLAlchemy's dialect suite runs to its end** (D308). On v0.2.0's code it stopped after 250
  failures with 96 passes; it now creates the two schemas its instructions ask for and runs all of
  it: 1,174 tests passed on batch PR #96's CI run, 272 failed, 99 were skipped and 16 errored, and
  CI fails below 1,160 passes. Materialized views can be created inside a transaction and in any
  schema.
- **The desktop client** (the separate `eggdb-gui` program, built from source with `cargo run
  --release -p eggdb-gui` and not in this release's downloads; designs in
  [docs/ux/workspace.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/ux/workspace.md) and
  [docs/ux/gui-layouts.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/ux/gui-layouts.md), D309
  to D311 and D313):
  - *Familiar layouts.* A picker (opened from the connect card's "Where are you coming from?" or
    with `Ctrl/Cmd+K L`; `--layout` applies a layout for one run) puts the main window's regions where SQL Server Management
    Studio, pgAdmin, DBeaver, DataGrip, MySQL Workbench, MongoDB Compass or Redis Insight put
    theirs, with their labels and keyboard shortcuts routed to EggDB's actions; the choice is
    kept in `gui-settings`. A status bar pill says "Works like <product>" and carries the
    trademark note.
  - *Query tabs.* Many tabs, each on a session kept from its first run until the tab closes (a
    `BEGIN` lasts across runs; closing a tab rolls its transaction back), with a close dialog for
    running, open-transaction and unsaved tabs.
  - *Results.* A full-value view of a cell, a right-click menu with Copy as CSV and Copy as JSON,
    resizable columns and scrollbars.
  - *Object tree.* A right-click menu (Open, Insert name, Copy name, Show DDL, Refresh, Drop...)
    and a Drop dialog, a table's triggers, `Enter` on a key space for its first 100 keys on a
    file, draggable splitters, `Ctrl/Cmd+B` to collapse the sidebar to a rail, and sizes kept
    between runs.
  - *Plans.* The plan view reads Oracle's `EXPLAIN PLAN` and SQL Server's `SHOWPLAN` answers
    (Ctrl/Cmd+E), with hover, a tooltip and click, and shows the `actual time=` of
    `EXPLAIN ANALYZE`.
  - *Motion and input.* 80 ms hover fades that stop under the operating system's reduced-motion
    setting (or `--reduced-motion`), clicking, dragging and pasting in the browser connect card,
    large text through the X11 clipboard, and files dropped with a drag-over ring on Windows and
    on X11 (dropping was not done on X11 in v0.2.0).
- **Everything from v0.2.0 still works.** The single crash-safe file and its transactions, the
  ordered key-value store, the Rust API, the `eggdb` command and `eggdb ui`, SQL in the
  PostgreSQL, MySQL, SQL Server, SQLite and Oracle dialects and the PostgreSQL, MySQL and SQL
  Server listeners, restores and `eggdb follow`, export and import, and the MCP server are as the
  [v0.2.0 notes](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/releases/v0.2.0.md) describe
  them; this release adds to them.

## Migrating
Moving to EggDB starts from the dump or script your database already makes (D13); the guide is
[migrate.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/migrate.md).

```sh
pg_dump --dbname=app > app.sql                                # PostgreSQL, plain SQL format
eggdb restore --create app.db app.sql                         # or: pg_dump --dbname=app | eggdb restore --create app.db
mysqldump shop > shop.sql                                     # MySQL or MariaDB
eggdb restore --dialect mysql --create shop.db shop.sql
eggdb restore --dialect sqlserver --create shop.db shop.sql   # an SSMS Generate Scripts or sqlpackage script
eggdb restore --dialect oracle --create hr.db hr_export.sql   # SQL Developer, SQLcl or impdp SQLFILE= output
```

- Every restore ends with a report: what was restored, the known differences, and what was
  skipped and why. A dump that loads its data with `COPY` restores, each table's data in one
  transaction; `pg_dumpall` output restores too, and so do Redis AOF files and `mongodump`
  directories.
- `eggdb follow <file> <source-url>` copies a running PostgreSQL 10 or newer (through logical
  replication) or SQL Server (through change data capture, or change tracking for tables
  without it) into the file and keeps it in step, so you can switch over without downtime. It
  saves its position in the file with each change it applies, so a stopped follow resumes where
  it was, reconnects after a lost connection (`--reconnect-for`), and applies PostgreSQL's
  column changes (D261, D263).
- A SQLite file opens as it is: `eggdb sql app.sqlite` reads it into memory and says that
  changes are not written back.
- Formats without a public specification are refused with the command that turns them into a
  script: `pg_dump`'s custom, directory and tar formats (`pg_restore -f dump.sql`), compressed
  dumps, SQL Server `.bak` and `.trn` backups, BACPAC and DACPAC files, Oracle Data Pump `.dmp`
  and RMAN files, and a database's data directory.
- Upgrading from v0.2.0 needs no conversion: v0.3.0 opens v0.2.0's files as they are. Going
  back is the one-way part: a file in which v0.3.0 created a SQLite-dialect table with `TEXT`,
  `NUMERIC` or `REAL` columns, or a key or index over a `BLOB` or untyped column, holds a version
  13 table that v0.2.0 refuses by name (see "Compatibility from here on"). A tested downgrade path
  to the previous minor version is still on the roadmap.

## Limits
Everything v0.3.0 doesn't do yet, in one list. Each follows the roadmap
([roadmap.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/roadmap.md), "What is left, per
milestone"). What v0.2.0's notes and docs said it did not do yet and is now done: Oracle's and SQL Server's plans
(`not_supported` before), writes to tables an agent sees with only some columns, the memory budget
missing from the Kafka, NATS, STOMP, MQTT, AMQP, Bolt and HTTP listeners, and dropping files on X11.
- **One writer at a time.** Readers run side by side; writers take turns.
- **Speed against SQLite.** D7 asks that point `SELECT`s, bulk `INSERT`s and joins be at least as
  fast as SQLite's, and D99 and D100 set the condition that they are at most 1.0 on macOS and
  Linux before v0.4.0 (moved from v0.3.0 by D100's note of 2026-11-04) or that a research records why the rest is unavoidable; the decision log
  records no such research. The Linux key join took 1.66 times SQLite's time on batch PR #96's CI
  run (1.50 on `main` before it, 1.40 in the committed baseline), the macOS join 1.40 (0.99 in the
  baseline), and a point `SELECT` by key is about 1.2 times SQLite's on a Mac (0.91 on Linux).
  The committed baseline has other SQL shapes slower than SQLite's on a Mac, for example a
  correlated `EXISTS` 6.4 times, a `UNION` 4.4 times, an `IN` subquery 2.2 times and an indexed
  lookup 1.95 times ([benchmarks.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/benchmarks.md),
  D99, D100).
- **Network.** Without TLS, the PostgreSQL, MySQL and SQL Server listeners bind to loopback
  addresses only (`127.0.0.1`, `::1`); other machines connect only over TLS. Every other
  listener of `eggdb serve` (Redis, MongoDB, Elasticsearch, MCP over HTTP and the rest) is
  loopback only, except the metrics endpoint (`--metrics-listen`).
- **Memory budget.** Replies that are built whole before they are measured (RESP's `EXEC`, a
  single large value, a Bolt record, an HTTP response body) still cost their size for a moment
  when refused, and a Bolt result's rows waiting for `PULL` and the queues' stored messages are
  not counted. AMQP 0-9-1 can't tell its own framing from a raw binary body that happens to parse
  as it, so such a body published through STOMP, SQS or AMQP 1.0 can reach an AMQP 0-9-1 consumer
  cut or misframed (D307).
- **Users and privileges.** Over PostgreSQL, `CREATE ROLE`, `CREATE USER`, `GRANT` and `REVOKE`
  on tables and their columns work; MySQL and SQL Server clients log in as the one server user (`--user`). There
  are no schema privileges, owners or `SET ROLE` yet.
- **PostgreSQL's dialect.** PostgreSQL's `MERGE` (version 15's) is not accepted (Oracle's and SQL
  Server's are), and `CREATE TABLE ... AS` is not accepted in any dialect (`SELECT ... INTO` is);
  `SET LOCAL` and a routine's `SET` clause are PostgreSQL's dialect only, `RESET ALL` and `SET
  eggdb.dialect` inside routines are `0A000`, and so is `set_config` with a PL/pgSQL variable as
  an argument (constants and `$n` parameters work). `IS JSON` on a document nested deeper than 256 levels gives false. Table
  columns of types `refcursor` and `refcursor[]` are stored as `text` and `text[]`.
- **Joined `UPDATE` and `DELETE`.** The refusals listed under "What v0.3.0 brings", and SQL
  Server's `OUTPUT deleted.` of a joined `UPDATE` (Msg 40517).
- **Oracle.** There is no Oracle wire protocol, so Oracle's own clients and drivers cannot
  connect; Oracle's SQL runs through `eggdb sql`, `eggdb shell`, `eggdb restore` and the
  embedded API. `CONNECT BY` over a join, `PRIOR` beside a subquery and `ORDER SIBLINGS BY` a
  pseudo-column are `0A000`; `EXPLAIN PLAN` takes a `SELECT`, `UPDATE` or `DELETE` only and gives
  no costs, cardinalities or predicates, and `DBMS_XPLAN.DISPLAY` always uses the `BASIC` shape;
  an `INSERT ALL` advances a sequence for each use, not once per source row.
- **SQL Server.** `SELECT ... INTO` keeps neither the source columns' `NOT NULL` nor their
  identity, and its computed columns get EggDB's types rather than SQL Server's; `OUTPUT ... INTO`
  a target with triggers, checks or foreign keys fires and checks them where SQL Server refuses;
  `SET STATISTICS PROFILE` counts rows for the statement, not each operator; `SHOWPLAN_XML` is
  `not_supported`; a procedure's `#temporary` tables outlive it. SQL Server clients: no MARS and
  no client certificates; a cancel (TDS attention) stops a running batch at once. `sqlcmd` here
  means go-sqlcmd, the one CI runs.
- **SQLite.** `INTEGER` columns are still plain 64-bit integers, not dynamic (SQLite keeps text
  or a real stored in one as it is); a few comparisons that mix a `TEXT` column with a number
  don't convert as SQLite does yet, and `CAST(x AS NUMERIC)` doesn't give integers (D305). Writing SQLite's own file format comes later: `eggdb sql app.sqlite` reads a file into
  memory.
- **SQLAlchemy.** 272 tests of its dialect suite fail, among them generated columns, two
  identity columns in one table, identity `MAXVALUE`/`MINVALUE`/`CYCLE`, zero-column tables,
  psycopg's named cursors, `nextval` of a `SERIAL` column's sequence and materialized views in
  `pg_class` (D308).
- **GUI tools.** pgAdmin, DBeaver, DataGrip, MySQL Workbench, SQL Server Management Studio and
  Azure Data Studio send catalog queries beyond psql's `\d` family that are not all answered
  yet; they are not tested and may not browse a database. psql's `\d` family, `\d+`, `\dt+`
  and `\df+` included, works.
- **The desktop client.** It is built from source and has no download and no `eggdb gui`
  command. A familiar layout places the regions and sets the labels and shortcuts, but does not
  yet draw each product's own contents (pgAdmin's Query Tool toolbar, DBeaver's run column,
  Compass's filter bar, SSMS's `F4` properties and the rest), and some keys the platform layer
  can't deliver yet (`F7`) and actions EggDB has no command for yet (comment, format) are not
  mapped. Keys of a key space can't be browsed on a server, the full-value view in the keys tab
  shows a value's first 64 bytes, data can't be edited in the grid, a second tab's write while another tab
  holds the write transaction fails at once with `55P03`, and more than 400 tabs are refused.
  There is no native Wayland window and no IME input. The hand check with each screen reader
  (VoiceOver, Narrator, Orca) is still to come (issue #29).
- **Restore.** The formats in "Migrating" that have no public specification are refused, never
  read. Procedures written in C, Python or Perl, user-defined aggregates and event triggers are
  listed in the report as skipped.
- **AI agents.** `eggdb mcp --allow-write` without `--tables` grants the whole file, and an
  agent's `confirm: true` is its own word, not yours. `--tables` does not filter the sessions of
  `eggdb serve`. With `--tables`, a foreign key from a listed table to an unlisted one lets an
  agent learn whether a value exists in the unlisted table by trying it.
- **Files.** A damaged file is reported, not repaired.
- **Downloads.** The binaries are not code-signed (each archive has a checksum and a signed build
  provenance attestation), and there are no packages on crates.io or other registries yet.
- **Platforms.** `x86_64-apple-darwin` and `aarch64-pc-windows-msvc` are built and packaged but
  not run by CI, and on Windows the smoke test does not run the network clients (see "What was
  tested").

## Correctness
Every commit is atomic, and durable when it returns under `Full`. Damage is detected by
checksums and reported, never served as data, and hostile files, exports and arguments produce
errors, never a crash or a hang. The tests behind each promise run on every change: a crash
sweep that fails every I/O operation of a workload in each durability mode and ends it in a
reopen or a simulated power loss, injected faults in every layer, a model test against Rust's
`BTreeMap`, a fuzzer for hostile files and one for hostile exports, the v0.2.0 sample files that
every later release must keep reading, and a smoke test of every release binary that its build
machine can run (see "What was tested"). The one file format change in this release, table
definition version 13 and its key encoding for SQLite's dynamic columns, has test vectors for
every storage class and the integer edges, an ordering test over 50,000 random pairs against an
independent statement of SQLite's order, a 200,000-case test of hostile key bytes that must never
panic and must accept only canonical keys, round-trip and truncation tests, and tests that an
older reader refuses a version 13 table and that no older version can claim one. The SQL
dialects are checked against their manuals' examples: 886 cases for PostgreSQL, 468 for SQL
Server, 242 for MySQL, 263 for SQLite and 662 for Oracle ([correctness.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/correctness.md)).
What is **not** tested is stated as plainly: no real power loss on hardware, no external audit,
one writer only, and the platforms CI doesn't run. The full statement is in the same page.

## Compatibility from here on
- **Files:** every later release reads the files this one writes (D20). The file format is still
  version 1. Table definitions gain version 13 (D305), written only for the tables described in
  "What v0.3.0 brings"; every other table, view and record keeps the version and bytes it had, and
  a release that doesn't know version 13, v0.2.0 included, refuses such a table by name, with an
  error (SQLSTATE `0A000`) saying the table definition was written in format version 13, which
  that EggDB cannot read, instead of misreading it. The two files written by v0.2.0 and the v0.2.0 export stay in
  the repository, and CI opens, reads, checks, replays and writes to them on every change (D96);
  no sample file is added for v0.3.0.
- **Exports:** eggdb-jsonl version 1 stays importable.
- **The command's output:** the JSON fields and the exit codes in [cli.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/cli.md) are stable.
  `eggdb explain` of an Oracle or SQL Server statement now prints a plan where v0.2.0 exited 3
  with `not_supported`.
- **The Rust API** is pre-1.0: it may change between minor releases, and each change is listed
  in the release notes.

**API changes since v0.2.0:**
- `eggdb::sql::SqlType::Dynamic` became `SqlType::Dynamic(TypeAffinity)`, with `TypeAffinity` one
  of `Text`, `Numeric`, `Real` and `Blob` (a `Blob` affinity is what v0.2.0's variant meant). The
  type is defined in `eggdb_sql`, and `eggdb::sql` does not re-export it yet.
- `Session::set_explain_plan_displays(bool)` is new: with `true`, a session's Oracle `EXPLAIN
  PLAN` writes no plan table and answers with the `DBMS_XPLAN.DISPLAY` lines, as `eggdb explain`
  and MCP's `explain_query` need on a read-only file.

## Size and speed
CI measures the stripped release `eggdb` binary on every change (D6, `scripts/footprint.sh`
against `benchmarks/footprint.txt`):

| | macOS (Apple silicon) | Linux (x86-64) |
|-|-----------------------|----------------|
| `eggdb` binary, v0.3.0 | 12,652,424 bytes | 16,450,960 bytes |
| `eggdb` binary, v0.2.0 | 12,089,896 bytes | 15,739,392 bytes |
| Growth | 562,528 bytes (4.7%) | 711,568 bytes (4.5%) |
| C API library, v0.3.0 | 7,837,312 bytes | 9,989,904 bytes |
| C API library, v0.2.0 | 7,423,408 bytes | 9,442,464 bytes |

The growth is joined `UPDATE` and `DELETE`, grouping sets, the new query syntax, transaction and
routine settings, the SQL/JSON additions, `MERGE` and `OUTPUT ... INTO`, Oracle's `CONNECT BY` and
multitable inserts, SQLite's dynamic typing and key encoding, the agent filter's writes, the memory
budget in every listener, and the plans, each with its reason recorded when the budgets were
raised to these sizes plus about 1% (D6, [benchmarks.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/benchmarks.md)).
The window code of the desktop client is linked only into `eggdb-gui`, not into `eggdb` or the C
API library. The exact size of every download is in the release's "Sizes" table. Start time and
the peak memory of `eggdb --version` and `eggdb get` are measured by CI's `bench` job against
`benchmarks/baseline.txt` on every change; the figures in benchmarks.md were last measured on
2026-10-27, so this release gives none of its own. Speed against SQLite is in "Limits": point
gets, scans and batched random overwrites stay faster than SQLite's in the committed baselines
(0.69, 0.55 and 0.61 times its time on Linux), as do bulk `INSERT`s and `GROUP BY`, while the
join and several other SQL shapes are slower (D7, D94, D99, D100, D101). A pass over the join's
per-row work (a cancel check per statement, reused key buffers, borrowed key values) was part of
this batch and didn't bring it to SQLite's speed; its `perf` profiles go to the weekly
performance pass.

## Downloads
One self-contained file per platform, with the licenses and the README:
- Linux: `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` are static and run on any
  distribution; the `-linux-gnu` builds link glibc 2.35 or newer.
- macOS: `aarch64-apple-darwin` (Apple silicon) and `x86_64-apple-darwin` (Intel).
- Windows: `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`.

Next to them: the C API (`eggdb-capi-<version>-<target>`: header, libraries and the Python
binding) for the two Linux `-gnu` targets, both macOS targets and both Windows targets; a
`SHA256SUMS` file; a signed build provenance attestation for every archive
(`gh attestation verify <archive> -R eggspot/EggDB`); and the container image
`ghcr.io/eggspot/eggdb:0.3.0` (and `:latest`) for `linux/amd64` and `linux/arm64`, built from the
static binaries. The desktop client (`eggdb-gui`) is not in the downloads: the release workflow
builds only the `eggdb` binary and the C API, so the client is built from source (`cargo run
--release -p eggdb-gui`).

The binaries are not signed. On macOS, a file downloaded with a browser is quarantined: run
`xattr -d com.apple.quarantine eggdb` once (`curl` and the install script don't set the
quarantine). On Windows, unzip the archive and add its folder to your PATH, so that `eggdb`
works in any terminal and in `claude mcp add mydb -- eggdb mcp app.db`; SmartScreen may ask
once before the first run.

## What was tested
Each statement in these notes is checked by tests that run on every change, and each release
binary is checked as a user gets it.

- **CI** (`.github/workflows/ci.yml`, on every pull request and on `main`; the required check
  is its last job, `check`, which fails when any job failed or was cancelled). A pull request that
  changes only Markdown runs `lint-and-test` and skips the other jobs, and `unix-vms` and
  `other-cpus` run on `main` only:
  - `lint-and-test` (Linux): the check that what ships is only our own crates (D1), `cargo fmt`,
    `cargo clippy`, `cargo test --workspace` and `cargo doc`; `eggdb-gui` opened in a native X11
    window under Xvfb, and the browser connect card linted and tested; `scripts/smoke-test.sh`
    on the built binary with psql, the `mysql` client, the pg8000 and PyMySQL drivers and
    go-sqlcmd; and `scripts/c-api/check.sh` (C, C++, Python, .NET and Java);
  - `platforms` (macOS and Windows): clippy, the tests, the smoke test and the C API check;
    `musl`: the tests on `x86_64-unknown-linux-musl`; `egg-allocator`: the tests with EggDB's
    own allocator installed; `cross`: clippy for FreeBSD, NetBSD, illumos, Solaris, aarch64
    Linux, Android, iOS and WebAssembly (WASI), and the file format without the standard library
    for a Cortex-M microcontroller; `unix-vms`: the platform layer, storage engine and embedded
    API run natively in FreeBSD, NetBSD and OmniOS virtual machines; `other-cpus`: the file
    format, storage engine, cryptography and columnar encodings on i686, ARMv7 and s390x (the
    last two under QEMU);
  - `pg-restore` (PostgreSQL 16 and 17), `pg-catalog`, `pg-functions`, `pg-apps`, `pg-follow`,
    `ss-follow`, `tds-apps`, `oracle-apps`, `tls-clients`, `sqlalchemy-suite`, `resp-clients`,
    `redis-compare` and `compatibility`: real clients and drivers (psql, pgjdbc, psycopg,
    SQLAlchemy, Npgsql, Flyway, mssql-jdbc, Microsoft.Data.SqlClient, EF Core, redis-cli,
    pymemcache, opensearch-py, pymongo, the neo4j driver, confluent-kafka, pika, paho-mqtt,
    boto3, nats-py, stomp.py, python-qpid-proton, cassandra-driver, influxdb-client, dbt)
    against `eggdb serve`, real PostgreSQL servers as the reference for restores, psql's `\d`
    output, function and query results and following, a real SQL Server that `eggdb follow`
    copies and follows through CDC and change tracking, and SQLAlchemy 2.0.36's own dialect
    suite with a floor of 1,160 passes;
  - `kubernetes` (the image and Helm chart in a kind cluster, with a pod restart), `deploy-templates`
    (the AWS and Azure templates), `installers` (the one-line installers on Linux, macOS and
    Windows against the latest release), `footprint` (size budgets), `reproducible` (the same
    commit built twice gives identical binaries), `unicode` (Unicode's normalization conformance
    file), `arrow` (an export read with pyarrow), `browser` (EggDB for WebAssembly and the
    connect card under Node and in headless Chrome), `mobile` (the Kotlin binding on the JVM) and
    `apple-mobile` (the C API as an XCFramework);
  - `bench` and `compare`: the benchmarks and the comparison with SQLite, which report on every
    pull request and fail only on more than twice the baseline (D101).
- **The release** (`.github/workflows/release.yml`, on the version tag, or by hand as a dry run
  that publishes nothing: `gh workflow run release.yml --ref main`) builds and packages every
  target, then unpacks each archive as a user would, checks the binary's `--version` and runs
  `scripts/smoke-test.sh` on the unpacked binary; where the platform allows it it also checks the
  built C API from C, C++ and Python:

  | Target | What ran on the unpacked binary |
  |--------|---------------------------------|
  | `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` (Ubuntu) | every command, the README's commands, the restores of the pg_dump, SSMS and Oracle samples, the v0.2.0 sample files, `eggdb serve` with psql, `mysql`, go-sqlcmd, pg8000 and PyMySQL, and `eggdb ui` and `eggdb shell` in a pseudo-terminal |
  | `aarch64-apple-darwin` (macOS) | the same, except go-sqlcmd |
  | `x86_64-pc-windows-msvc` (Windows) | every command, the README's commands, the restores and the sample files; `eggdb serve` only refusing a missing password and a non-loopback address without TLS, since the smoke test stops the server with SIGTERM, which Windows lacks; no pseudo-terminal |
  | `x86_64-apple-darwin`, `aarch64-pc-windows-msvc` | built and packaged, not run |

  The smoke test's last line lists what it skipped, and on the targets above it fails when one
  of the clients listed for that target is missing (`EGGDB_SMOKE_REQUIRE`), so the table can't
  drift from the run. The smoke test is the same as v0.2.0's; the SQL, MCP, listener and client
  features of this release are covered by the tests in `cargo test --workspace`, the correctness
  suites and the real-client jobs above. After the tag, the release workflow also builds and
  smoke tests the container image.

Not tested: third-party GUI tools (`eggdb-gui` is only opened offscreen and under Xvfb in CI; the
hand check with screen readers is still to come, #29, and so is a hand check of the Windows and X11
drop targets and the X11 clipboard on real desktops: CI checks their protocol logic), real power
loss on hardware, the two targets above that are not run, and an external audit
([correctness.md](https://github.com/eggspot/EggDB/blob/v0.3.0/docs/correctness.md)).
