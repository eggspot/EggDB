EggDB's first release people can use: an embedded, crash-safe, transactional key-value store in
one file, with a Rust API, the `eggdb` command and `eggdb ui`, a full-screen terminal UI (D76).
It opens in your process, like SQLite, with nothing to install beyond one file. `eggdb serve`
serves it to PostgreSQL, MySQL and SQL Server clients, on this machine without TLS and to other
machines over EggDB's own TLS, and `eggdb restore` loads the dump your database already makes
(see "Migrating"). What it can't do yet is in one place, "Limits", and what was tested on which
platform in "What was tested".

## What v0.2.0 brings
- **One file, crash-safe.** EggDB's own file format, version 1 ([format.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/format.md)):
  checksummed pages, a write-ahead log inside the file, checkpoints and recovery that replays
  exactly the durable commits after any crash. Three durability modes, `Full` by default.
- **Transactions.** One writer at a time and any number of snapshot readers on any thread;
  atomic commits, rollback, and hybrid-clock commit stamps that never go back.
- **An ordered key-value store.** Byte-string keys up to an eighth of a page (512 bytes with the
  default 4 KiB pages) and values up to 1 GiB, large ones on overflow pages; get, put, delete,
  and scans over any range or prefix, forwards and in reverse.
- **The embedded Rust API**, `eggdb::Database`, with errors that say what to do and a kind to
  match on ([embedded.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/embedded.md)).
- **The `eggdb` command**: `create`, `put`, `get`, `del`, `scan`, `check`, `stats`, `export` and
  `import`, with text, JSON, hex and raw output, stable exit codes and errors that name the fix
  ([cli.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/cli.md)).
- **`eggdb ui`**: browse a database full screen, view values as text, JSON or hex, filter by
  prefix, edit, add and delete keys (each change confirmed and committed on its own), and run
  the check, in any terminal of 40 × 10 or more.
- **`eggdb check`** reads every page, checks how they fit together and accounts for every page
  of the file.
- **SQL and the PostgreSQL protocol.** `eggdb sql` runs the first parts of the PostgreSQL
  dialect on the same file ([sql.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/sql.md)),
  and `eggdb serve` speaks the PostgreSQL wire protocol v3, so `psql` and PostgreSQL drivers
  connect and run SQL, joins included: SCRAM-SHA-256 authentication always (with our own
  SHA-256, HMAC and PBKDF2), the simple and extended query protocols, parameters in text and
  binary form, several connections. Without TLS it listens on loopback addresses only; with
  `--tls-certificate` and `--tls-key`, or `--tls-self-signed`, it listens on any address and other
  machines must use TLS. `COPY ... FROM STDIN` and `COPY ... TO STDOUT` work, psql's `\copy`
  included, and so do query cancellation and psql's `\d` family (`\d`, `\dt`, `\di`, `\dv`,
  `\ds`, `\dn`, `\l`, `\du`).
- **MySQL's SQL and protocol.** `eggdb sql --dialect mysql` and `eggdb shell --dialect mysql`
  run MySQL's SQL on the same tables (backticks, `AUTO_INCREMENT`, `LIMIT a, b`, `INSERT
  IGNORE`, `REPLACE`, `ON DUPLICATE KEY UPDATE`, `SHOW`, `DESCRIBE`, `USE`, `SET`, MySQL's
  error numbers and messages), and `eggdb serve --mysql-listen 127.0.0.1:3306` serves the file
  to the `mysql` client and MySQL drivers: `caching_sha2_password` and `mysql_native_password`
  (with our own SHA-1), text queries and server prepared statements. Like the PostgreSQL listener, it is loopback only without TLS and takes any address with
  TLS; dates and times, `DECIMAL`, `JSON` and `BLOB` travel in MySQL's own types, and GUI tools'
  catalog queries come later ([sql.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/sql.md)).
- **SQL Server's Transact-SQL and protocol.** `eggdb sql --dialect sqlserver` and `eggdb shell
  --dialect sqlserver` run a first part of Transact-SQL on the same tables (`[brackets]`, `TOP`,
  `IDENTITY`, `GETDATE()`, `@@VERSION`, `BEGIN TRAN`, batches without semicolons, SQL Server's
  error numbers), and `eggdb serve --tds-listen 127.0.0.1:1433` serves the file to Microsoft's
  `sqlcmd` (go-sqlcmd) over TDS 7.4: SQL logins. Without TLS the login sends its password only obfuscated, so in effect in the
  clear, which is why the listener is then loopback only (connect with go-sqlcmd's default or
  `-N disable`); with TLS the connection is encrypted and may come from any address. SQL Server's types (`bit`, `tinyint`, `money`,
  `datetime`, `datetime2`, `datetimeoffset`, `date`, `time`, `uniqueidentifier`,
  `varbinary`, `nvarchar(max)`, ...), its conversion rules, `CAST` and `CONVERT` with the
  common styles, `ISNULL`, `DATEADD`, `DATEDIFF`, `CHARINDEX`, `LEN`, `NEWID`,
  `SCOPE_IDENTITY`, `@@ROWCOUNT`, `OFFSET ... FETCH` and `OUTPUT` work, and travel in TDS's
  own date, time, GUID and decimal types; a column keeps the engine type its SQL Server type
  maps to, so a `datetimeoffset` comes back in UTC and a `tinyint` column isn't range-checked
  ([sql.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/sql.md)). Views (`CREATE VIEW`,
  `ALTER VIEW`, `CREATE OR ALTER VIEW`) and `CHECK` constraints written in Transact-SQL are kept
  in the file with their own dialect and work from every dialect (D124). Microsoft.Data.SqlClient, EF Core and mssql-jdbc connect too, RPC
  calls included.
- **Restoring a SQL Server database.** `eggdb restore --dialect sqlserver --create shop.db
  shop.sql` restores the script SSMS Generate Scripts writes (Schema and data, UTF-16 or UTF-8)
  or `sqlpackage /Action:Script` writes, and `sqlcmd -i` restores an SSMS script against `eggdb
  serve --tds-listen`. The report adds **known differences**, what is restored but not as SQL
  Server had it (`IDENTITY` seeds, `datetimeoffset` offsets, computed columns, index filters,
  disabled constraints), and creates stored procedures and functions as SQL Server does, listing as skipped only what
  EggDB can't run yet (CLR routines, bodies that use what is missing).
  A `.bak`, BACPAC or `.mdf` file is refused by its content with the route to a script (D125,
  [migrate.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/migrate.md)).
- **SQLite's SQL.** `eggdb sql --dialect sqlite`, `eggdb shell --dialect sqlite` and the
  embedded API (`eggdb::sql`) run SQLite's SQL on the same tables: type affinity, `INTEGER
  PRIMARY KEY` row ids and `AUTOINCREMENT`, `INSERT OR REPLACE`/`IGNORE`, upserts, `PRAGMA
  table_info` and friends, `sqlite_schema`, SQLite's functions and error messages with result
  codes. `eggdb sql app.sqlite` reads a file in SQLite's own format into memory; writing that
  format comes later
  ([sql.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/sql.md)).
- **Oracle's SQL.** `eggdb sql --dialect oracle`, `eggdb shell --dialect oracle` and the
  embedded API run Oracle's SQL on the same tables: `DUAL`, `ROWNUM <= n`, `FETCH FIRST` and
  `OFFSET ... ROWS`, upper-case names, the empty string as NULL, `VARCHAR2`, `NUMBER(p,s)`,
  `CLOB` and identity columns, `NVL`, `NVL2`, `DECODE`, `TO_CHAR` and Oracle's string and
  numeric functions, `USER_TABLES` and `USER_TAB_COLUMNS`, Oracle's implicit transactions and
  `ORA-` errors, sequences, subqueries and set operators. Numbers are exact; `TO_DATE`,
  `TO_TIMESTAMP`, `TO_CHAR` and `TO_NUMBER` take Oracle's format models; `ALTER SESSION SET
  NLS_DATE_FORMAT` (and the other NLS formats, `NLS_TERRITORY` and `CURRENT_SCHEMA`) changes how
  text and dates convert; dates add and subtract days; `ADD_MONTHS`, `LAST_DAY`, `TRUNC(date)`
  and `MERGE` with `DELETE WHERE` work. There is no Oracle wire protocol, so Oracle's clients
  cannot connect ([sql.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/sql.md)).
- **Restoring an Oracle schema.** `eggdb restore --dialect oracle --create hr.db hr_export.sql`
  restores a SQL Developer or SQLcl export, `impdp ... SQLFILE=` output or an installer such as
  Oracle's own HR sample schema, which restores unchanged with its documented row counts. The
  script is read as SQL*Plus reads it (`;` and `/`, `DEFINE` and `&name`, `@` and `@@`
  includes, `CONNECT`), users become schemas, blocks of `INSERT` statements load all or nothing,
  storage clauses are accepted, PL/SQL procedures, functions, packages and triggers are created and run, and the other
  SQL*Plus commands are listed.
  `eggdb import --dialect oracle --csv` loads SQLcl `UNLOAD` files; a Data Pump `.dmp` file is
  refused with the `impdp` route (D127,
  [migrate.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/migrate.md#oracle)).
- **Export and import** as JSON lines (eggdb-jsonl version 1), to back up a database, move it,
  or load data made by other tools.
- **AI agents over MCP.** `eggdb mcp <file>` is a built-in MCP server on stdin and stdout, so
  `claude mcp add mydb -- eggdb mcp app.db` lets Claude Code, and any other MCP client, read the
  database: list and describe tables and views, run one SQL statement per call in PostgreSQL,
  MySQL, SQLite or Oracle SQL, explain a query, sample rows, read keys, and read the schema as a
  resource. What agents can do: read, within a time limit per call (`--time-limit`, 5 s by
  default), at most `max_rows` rows and 1 MiB per result, and values it builds of at most 16 MiB.
  With `--allow-write` they can also change it through `write_sql`, one statement per call in a
  transaction of its own and at most 256 MiB of change; destructive statements (`DROP`,
  `TRUNCATE`, dropping a column, constraint or primary key, a column's type change, a `DELETE`
  or `UPDATE` whose `WHERE` does not pin every column of a primary or unique key to values,
  `REPLACE` and upserts, and a `MERGE` that updates or deletes) run only after the user confirms
  them, through the client's own question when it can ask and otherwise through the agent's
  `confirm: true`. That is the agent's word, not the user's: it guards against accidents, not
  against an agent that means harm or was misled by what it read, so without a client that asks
  the user `--allow-write` lets the agent change anything; give unattended agents read-only
  access. `--tables a,b` limits the agent to those tables, for reads and, with `--allow-write`,
  for writes: every change outside them is refused (`42501`), and a listed table tied by a
  foreign key or a view to an unlisted one cannot be changed (D257). What they can't do yet:
  write without `--allow-write` (every call then opens the file read-only), run several
  statements or a transaction in one call, or reach it from another machine (`eggdb serve --mcp-listen` serves MCP over HTTP, on
  loopback only and read-only). Results are
  marked as data, never instructions, and every message is one line of ASCII. Every call is
  recorded in `<file>.mcp-audit.jsonl`, before its result is sent, and `eggdb audit <file>`
  lists them; the log holds the SQL as sent, so protect it like the database, and it is not
  tamper-evident. While a call runs, a program that opens the file for writing waits for it, for
  at most the time limit and a second: `eggdb` commands wait up to five seconds
  (`--busy-timeout`), and the Rust API waits as long as `Options::busy_timeout` says (D258)
  ([mcp.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/mcp.md)).

- **The desktop client, first workspace** (the separate `eggdb-gui` program, built from source with
  `cargo run --release -p eggdb-gui` and not in this release's downloads yet; design in
  [docs/ux/workspace.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/ux/workspace.md), D15, D274–D279). Open,
  create or drop in a `.eggdb` file, or connect to an `eggdb serve` URL over the PostgreSQL protocol; run the statement
  under the caret (Ctrl/Cmd+Enter) or all of them; read results in a virtualized grid that copies as TSV or INSERT
  statements; browse tables, views, indexes, sequences and key spaces with an inspector for DDL, columns and sample
  rows; and see the plan as a tree with cost and rows (Ctrl/Cmd+E), or `EXPLAIN (ANALYZE, BUFFERS)`, which always runs
  in a transaction that is rolled back. It works with the mouse, the system clipboard and Narrator, Orca and VoiceOver;
  the hand check with each screen reader is still to come (issue #29).
- **More of PostgreSQL, SQL Server and Oracle** (D280, D285–D291, D294–D296). Column grants
  (`GRANT SELECT (a) …`) and row security `WITH CHECK` on every row written; `pg_stat_statements`,
  `--log-slow-statements` and `--statement-statistics`; `JSON_EXISTS`, `JSON_VALUE`, `JSON_QUERY` and `JSON_TABLE`;
  numeric ±Infinity; `refcursor` and `COMMIT` inside procedures as PostgreSQL does; SQL Server `AT TIME ZONE` with
  Windows zone names, `MERGE … WHEN NOT MATCHED BY SOURCE` and `OPENJSON` without `WITH`; PL/SQL procedures called
  over TDS RPC with OUT parameters; and `eggdb follow` from PostgreSQL 14+ with pgoutput protocol 2 and from SQL
  Server CDC capture instances of some columns.
- **Safer servers and agents** (D281, D284). `eggdb serve --max-connection-memory <size>` (4 GiB by default) stops a
  local program from exhausting memory through PostgreSQL portals, RESP, MongoDB-compatible, CQL or memcached
  requests, and `eggdb mcp --tables 'orders(id,total),customers'` limits an agent to the listed columns.
- **Collections, the shell and the C API** (D283, D292, D293). `eggdb collection move` (alias `rename`),
  `eggdb stats --collections`, crash-safe drops of large collections; `expire`, `persist`, `cas`, `scan` and `ttl`
  inside an `eggdb shell` `BEGIN` block; and in the C API, stepping through rows, streaming `COPY` both ways, and
  prepare, cancel and COPY on server sessions.
- **File format** stays version 1: this batch's additions (array codes, numeric infinity, collection drop marks,
  column grants, SQLite schema text) are additive, and files from earlier builds open unchanged (D35).

## Migrating
Moving to EggDB starts from the dump or script your database already makes (D13); the guide is
[migrate.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/migrate.md).

```sh
pg_dump --dbname=app > app.sql                                # PostgreSQL, plain SQL format
eggdb restore --create app.db app.sql                         # or: pg_dump --dbname=app | eggdb restore --create app.db
mysqldump shop > shop.sql                                     # MySQL or MariaDB
eggdb restore --dialect mysql --create shop.db shop.sql
eggdb restore --dialect sqlserver --create shop.db shop.sql   # an SSMS Generate Scripts or sqlpackage script
eggdb restore --dialect oracle --create hr.db hr_export.sql   # SQL Developer, SQLcl or impdp SQLFILE= output
```

- Every restore ends with a report: what was restored, the known differences, and what was
  skipped and why. A dump that loads its data with `COPY` restores, each table's data in one
  transaction; `pg_dumpall` output restores too, and so do Redis AOF files and `mongodump`
  directories.
- `eggdb follow <file> <source-url>` copies a running PostgreSQL 10 or newer (through logical
  replication) or SQL Server (through change data capture, or change tracking for tables
  without it) into the file and keeps it in step, so you can switch over without downtime. It
  saves its position in the file with each change it applies, so a stopped follow resumes where
  it was, reconnects after a lost connection (`--reconnect-for`), and applies PostgreSQL's
  column changes (D261, D263).
- A SQLite file opens as it is: `eggdb sql app.sqlite` reads it into memory and says that
  changes are not written back.
- Formats without a public specification are refused with the command that turns them into a
  script: `pg_dump`'s custom, directory and tar formats (`pg_restore -f dump.sql`), compressed
  dumps, SQL Server `.bak` and `.trn` backups, BACPAC and DACPAC files, Oracle Data Pump `.dmp`
  and RMAN files, and a database's data directory.

## Limits
Everything v0.2.0 doesn't do yet, in one list. Each follows the roadmap
([roadmap.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/roadmap.md)).
- **One writer at a time.** Readers run side by side; writers take turns.
- **Network.** Without TLS, the PostgreSQL, MySQL and SQL Server listeners bind to loopback
  addresses only (`127.0.0.1`, `::1`); other machines connect only over TLS. Every other
  listener of `eggdb serve` (Redis, MongoDB, Elasticsearch, MCP over HTTP and the rest) is
  loopback only, except the metrics endpoint (`--metrics-listen`).
- **Users and privileges.** Over PostgreSQL, `CREATE ROLE`, `CREATE USER`, `GRANT` and `REVOKE`
  on tables work; MySQL and SQL Server clients log in as the one server user (`--user`). There
  are no column or schema privileges, owners or `SET ROLE` yet.
- **Oracle.** There is no Oracle wire protocol, so Oracle's own clients and drivers cannot
  connect; Oracle's SQL runs through `eggdb sql`, `eggdb shell`, `eggdb restore` and the
  embedded API.
- **GUI tools.** pgAdmin, DBeaver, DataGrip, MySQL Workbench, SQL Server Management Studio and
  Azure Data Studio send catalog queries beyond psql's `\d` family that are not all answered
  yet; they are not tested and may not browse a database. psql's `\d` family, `\d+`, `\dt+`
  and `\df+` included, works.
- **SQL Server clients.** No MARS and no client certificates; a cancel (TDS attention) stops a
  running batch at once. `sqlcmd` here means go-sqlcmd, the one CI runs.
- **Restore.** The formats in "Migrating" that have no public specification are refused, never
  read. Procedures written in C, Python or Perl, user-defined aggregates and event triggers are
  listed in the report as skipped.
- **AI agents.** `eggdb mcp --allow-write` without `--tables` grants the whole file, and an
  agent's `confirm: true` is its own word, not yours.
- **Files.** A damaged file is reported, not repaired.
- **Downloads.** The binaries are not signed, and there are no packages on crates.io or other
  registries yet.
- **Platforms.** `x86_64-apple-darwin` and `aarch64-pc-windows-msvc` are built and packaged but
  not run by CI, and on Windows the smoke test does not run the network clients (see "What was
  tested").

## Correctness
Every commit is atomic, and durable when it returns under `Full`. Damage is detected by
checksums and reported, never served as data, and hostile files, exports and arguments produce
errors, never a crash or a hang. The tests behind each promise run on every change: a crash
sweep that fails every I/O operation of a workload in each durability mode and ends it in a
reopen or a simulated power loss, injected faults in every layer, a model test against Rust's
`BTreeMap`, a fuzzer for hostile files and one for hostile exports, the v0.2.0 sample files that
every later release must keep reading, and a smoke test of every release binary that its build machine can run (see "What was
tested"). What is **not** tested is stated as plainly: no real power loss on hardware, no
external audit, one writer only, and the platforms CI doesn't run. The full statement is
[correctness.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/correctness.md).

## Compatibility from here on
- **Files:** every later release reads the files this one writes (D20). Two files written by
  v0.2.0 and a v0.2.0 export are committed to the repository, and CI opens, reads, checks,
  replays and writes to them on every change (D96).
- **Exports:** eggdb-jsonl version 1 stays importable.
- **The command's output:** the JSON fields and the exit codes in [cli.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/cli.md) are stable.
- **The Rust API** is pre-1.0: it may change between minor releases, and each change is listed
  in the release notes.

**API renames since the code on `main` before this release** (none of these names was in a
release; they are listed for anyone who built from the repository):
- `eggdb_storage::StorageError::EntryTooLarge` became `ValueTooLarge` (a value over the 1 GiB
  limit) and `ValueExceedsCache` (a value whose pages don't fit the page cache);
- `BTree::max_entry_bytes` became `max_inline_entry_bytes`, since it no longer limits what can
  be stored, only what sits in a leaf;
- `Database::max_entry_bytes` became `max_value_bytes` (D88).

## Size and speed
| | macOS (Apple silicon) | Linux (x86-64) |
|-|-----------------------|----------------|
| `eggdb` binary | 933,312 bytes | 1,133,296 bytes |
| `eggdb --version` | 1.48 ms | 0.78 ms |
| Peak memory of `eggdb get` | 2.3 MB | 5.1 MB |

The binary grew from 302,448 bytes in v0.1.0, which only printed its version, by the storage
engine, the command, `eggdb ui` and export and import, each with its reason stated when it
landed (D6; D90 to D94). Compared with SQLite under matching settings, EggDB is faster on point
gets, scans and batched random overwrites, and about as fast on durable commits. In `Normal`
durability SQLite stays about 1.1 times faster on batched overwrites, because EggDB syncs its
header twice more per checkpoint to keep both header slots safe ([benchmarks.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/benchmarks.md),
D7, D94, D97). The sizes of every download follow below.

## Downloads
One self-contained file per platform, with the licenses and the README:
- Linux: `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` are static and run on any
  distribution; the `-linux-gnu` builds link glibc 2.35 or newer.
- macOS: `aarch64-apple-darwin` (Apple silicon) and `x86_64-apple-darwin` (Intel).
- Windows: `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`.

The binaries are not signed. On macOS, a file downloaded with a browser is quarantined: run
`xattr -d com.apple.quarantine eggdb` once (`curl` and the install script don't set the
quarantine). On Windows, unzip the archive and add its folder to your PATH, so that `eggdb`
works in any terminal and in `claude mcp add mydb -- eggdb mcp app.db`; SmartScreen may ask
once before the first run.

## What was tested
Each statement in these notes is checked by tests that run on every change, and each release
binary is checked as a user gets it.

- **CI** (`.github/workflows/ci.yml`, on every pull request and on `main`; the required check
  is its last job, `check`):
  - `lint-and-test` (Linux): `cargo fmt`, `cargo clippy`, `cargo test --workspace` and
    `cargo doc`, then `scripts/smoke-test.sh` on the built binary with psql, the `mysql`
    client, the pg8000 and PyMySQL drivers and go-sqlcmd, and `scripts/c-api/check.sh` (C, C++,
    Python, .NET and Java);
  - `platforms` (macOS and Windows): clippy, the tests, the smoke test and the C API check;
  - `pg-restore`, `pg-catalog`, `pg-functions`, `pg-apps`, `pg-follow`, `ss-follow`, `tds-apps`,
    `oracle-apps`, `tls-clients`, `sqlalchemy-suite`, `resp-clients` and `compatibility`: real
    clients and drivers (psql, pgjdbc, psycopg, SQLAlchemy, Npgsql, Flyway, mssql-jdbc,
    Microsoft.Data.SqlClient, EF Core, redis-cli, dbt) against `eggdb serve`, and real
    PostgreSQL servers as the reference for restores, psql's `\d` output and following, and a
    real SQL Server that `eggdb follow` copies and follows through CDC and change tracking;
  - `installers`: the one-line installers on Linux, macOS and Windows against the latest
    release; `bench` and `compare`: the benchmarks and the comparison with SQLite.
- **The release** (`.github/workflows/release.yml`, on the version tag, or by hand as a dry run
  that publishes nothing: `gh workflow run release.yml --ref main`) builds and packages every
  target, then unpacks each archive as a user would, checks the binary's `--version` and runs
  `scripts/smoke-test.sh` on the unpacked binary:

  | Target | What ran on the unpacked binary |
  |--------|---------------------------------|
  | `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` (Ubuntu) | every command, the README's commands, the restores of the pg_dump, SSMS and Oracle samples, the v0.2.0 sample files, `eggdb serve` with psql, `mysql`, go-sqlcmd, pg8000 and PyMySQL, and `eggdb ui` and `eggdb shell` in a pseudo-terminal |
  | `aarch64-apple-darwin` (macOS) | the same, except go-sqlcmd |
  | `x86_64-pc-windows-msvc` (Windows) | every command, the README's commands, the restores and the sample files; `eggdb serve` only refusing a missing password and a non-loopback address without TLS, since the smoke test stops the server with SIGTERM, which Windows lacks; no pseudo-terminal |
  | `x86_64-apple-darwin`, `aarch64-pc-windows-msvc` | built and packaged, not run |

  The smoke test's last line lists what it skipped, and on the targets above it fails when one
  of the clients listed for that target is missing (`EGGDB_SMOKE_REQUIRE`), so the table can't
  drift from the run.

Not tested: GUI tools, real power loss on hardware, the two targets above that are not run, and
an external audit ([correctness.md](https://github.com/eggspot/EggDB/blob/v0.2.0/docs/correctness.md)).
