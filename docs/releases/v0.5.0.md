EggDB v0.5.0 builds on v0.4.0. It is one batch of work (D336 to D352) and two fixes after it:
explicit partition selection and identity columns on partitioned tables, SQLite's `UPDATE OR`,
`FOR UPDATE` refused in read-only transactions, the two-variable statistics aggregates, Top-N
sorts and nullable indexes read in place of a sort again, PostgreSQL's and MySQL's `TABLE t`,
SQL-level `PREPARE`/`EXECUTE`, MySQL's `CREATE TABLE ... LIKE`, gzip and deflate request bodies,
the rest of PostgreSQL's privilege catalog, MySQL's `EXPLAIN FORMAT=JSON` and tree costs, MCP key
tools, Redis's blocking commands, Elasticsearch upserts and `search_after`, MongoDB's positional
and pipeline updates, `SQRT` everywhere and MySQL's date parts and `ADD INDEX`, more of Cypher,
TCP keep-alives, heart-beats for STOMP and AMQP, and collection counts in `eggdb ui`. A point
`SELECT` through SQL is about 19% faster than in v0.4.0 (#103), but SQL point selects, bulk
inserts and joins are still slower than SQLite's: "Limits" gives the numbers. What v0.4.0's notes
said it did not do yet and is now done: MySQL's `ORDER BY ... LIMIT` on a nullable indexed column
reads the index again instead of sorting every row (D341). What it can't do yet is in one place,
"Limits", and what was tested on which platform in "What was tested".

## What v0.5.0 brings
- **Named partitions** (D337). MySQL's `t PARTITION (p1, p2)` and Oracle's `PARTITION (p)`,
  `SUBPARTITION (p)` and `PARTITION FOR (key)` in `SELECT`, `INSERT`, `REPLACE`, `UPDATE` and
  `DELETE` read and write only those partitions, with each database's errors (1735, 1747, 1748,
  ORA-02149, ORA-14400, ORA-14401, ORA-14501). Identity and `AUTO_INCREMENT` columns work on
  partitioned tables, with one counter for the whole table. Oracle's `CREATE TABLE ... PARTITION BY`
  now really partitions the table (v0.4.0 skipped the clause). PostgreSQL still reads `partition`
  after a table name as an alias.
- **SQLite's `UPDATE OR ROLLBACK | ABORT | FAIL | IGNORE | REPLACE`** (D338), with SQLite's
  semantics for each. `UPDATE OR REPLACE` needs the `DELETE` privilege, respects `DELETE` policies
  and asks an agent for confirmation, because it deletes the rows it collides with.
  Read-only transactions refuse `SELECT ... FOR UPDATE | NO KEY UPDATE | SHARE | KEY SHARE` with
  `25006` (through views, partitions and derived tables too), accept `LOCK TABLE` as PostgreSQL
  does, take `SET TRANSACTION READ ONLY` in an implicit transaction, answer `25006` for a writing
  volatile function, and apply `default_transaction_read_only` to a `CALL` that commits inside.
- **Collection counts in `eggdb ui`, and progress for `export`, `import` and `restore`** (D339),
  designed by Claude Fable: the picker shows each collection's kept entry count, dimmed, without
  reading keys, and the three commands draw the shared progress line on a terminal.
- **`regr_*`, `covar_samp`, `covar_pop` and `corr`** (D340) in PostgreSQL and Oracle, also as
  window functions, with PostgreSQL's accumulators. SQLite and SQL Server sort NULLs first for
  `ASC`, as they do.
- **Top-N sorts and nullable indexes in place of a sort** (D341). `ORDER BY ... LIMIT n` keeps
  only the rows it returns while sorting, and MySQL, SQLite and SQL Server read a nullable index's
  NULL entries at the right end, so `ORDER BY created_at DESC LIMIT 10` stops after ten entries.
- **`TABLE t`, `PREPARE`/`EXECUTE` and more `CREATE TABLE`** (D342). `TABLE t` is a query in
  PostgreSQL and MySQL (with MySQL's `ORDER BY` and `LIMIT`); SQL `PREPARE`, `EXECUTE`,
  `DEALLOCATE` and `CREATE TABLE ... AS EXECUTE`; PostgreSQL's `USING heap`, `WITH (...)` and
  `TABLESPACE pg_default` in `CREATE TABLE ... AS`; MySQL's `CREATE TABLE t2 LIKE t1`; and SQL
  Server's `SELECT ... INTO` keeps `NOT NULL`.
- **gzip and deflate request bodies** (D343) on the Elasticsearch, REST and InfluxDB listeners,
  decoded under the memory budget (`413` past the body limit, `503` when the budget is full); S3
  and Prometheus remote write keep their bodies as sent. An HTTP/1.1 request needs exactly one
  `Host` header.
- **PostgreSQL's privilege catalog** (D344): `aclexplode`, `acldefault`, `makeaclitem`,
  `has_type_privilege`, `has_tablespace_privilege`, `has_server_privilege`,
  `has_foreign_data_wrapper_privilege`, `has_parameter_privilege`, `information_schema`'s
  `enabled_roles`, `applicable_roles`, `routine_privileges` and `udt_privileges`, and
  `pg_namespace.nspacl`, all answered from the grants the engine enforces.
- **MySQL's `EXPLAIN FORMAT=JSON`, costs in `FORMAT=TREE`** (D345), and `EXPLAIN ANALYZE` of
  multi-table `UPDATE`/`DELETE` and of `TABLE t`. The costs come from EggDB's own model and differ
  from MySQL's numbers.
- **MCP key tools** (D346): an agent with write access can `incr`, `cas`, `expire` and `persist`
  keys, and `put` reports `expires_at`. Deleting forms (`expire` with ttl 0, `cas` with `delete`)
  ask for confirmation like `del`, and SQL row keys are refused.
- **Redis's blocking commands** (D347): `BLPOP`, `BRPOP`, `BLMOVE`, `BRPOPLPUSH`, `BLMPOP`,
  `BZPOPMIN`, `BZPOPMAX`, `BZMPOP` and `XREAD BLOCK`, plus `LMOVE`, `RPOPLPUSH`, `ZPOPMIN`,
  `ZPOPMAX`, `LMPOP` and `ZMPOP`. Waiters are served first come first served, a client that
  disconnects while blocked loses no element, a blocked client costs no write transactions, and
  `INFO` reports `blocked_clients`.
- **Elasticsearch-compatible upserts and paging** (D348): `upsert`, `doc_as_upsert`,
  `scripted_upsert` and `detect_noop` on `_update`, `doc` merged into nested objects, sorting on
  several fields with `sort` values on each hit, `search_after`, and `_source` filtering on
  `_search`.
- **MongoDB positional and pipeline updates** (D349): `$`, `$[]` and `$[<id>]` with
  `arrayFilters`, and updates given as a pipeline (`$set`/`$addFields`, `$unset`, `$project`,
  `$replaceRoot`/`$replaceWith`), bounded by the 16 MiB document size while they apply.
- **`SQRT` in every dialect, MySQL's date parts and `ADD INDEX`** (D350): `YEAR`, `MONTH`, `DAY`,
  `HOUR`, `MINUTE`, `SECOND`, `MICROSECOND`, `QUARTER`, `DAYOFWEEK`, `DAYOFYEAR` and `WEEKDAY`, and
  MySQL's `ALTER TABLE ... ADD INDEX | KEY`, `RENAME INDEX` and `DROP INDEX` with MySQL's errors.
- **Cypher** (D351): label expressions (`n:A|B`, `r:T|U`), `CALL { ... }` subqueries,
  `shortestPath()` as an expression, and Neo4j's error for a `MERGE` on a null property.
- **Connections that stay healthy** (D336, D352): `eggdb serve --tcp-keepalive <seconds>` (default
  300) on every listener; STOMP heart-beats and AMQP 0-9-1 heartbeats; syslog TCP connections
  closed after `--idle-timeout`, and every dropped syslog message counted in
  `eggdb_syslog_messages_dropped_total`.

## Migrating
Moving to EggDB is unchanged from v0.4.0: `eggdb restore` reads the dump or script your database
already makes, and `eggdb follow` keeps a copy of a running PostgreSQL or SQL Server in step
([migrate.md](https://github.com/eggspot/EggDB/blob/v0.5.0/docs/migrate.md)).

- Upgrading from v0.4.0 needs no conversion and nothing changes in the file: v0.5.0 writes no new
  record version, so v0.4.0 still opens every file v0.5.0 writes.

## Limits
Everything v0.5.0 doesn't do yet, in one list. Each follows the roadmap
([roadmap.md](https://github.com/eggspot/EggDB/blob/v0.5.0/docs/roadmap.md), "What is left, per
milestone"), and each decision of this batch lists its own "Left".
- **One writer at a time.** Readers run side by side; writers take turns, and a blocked Redis
  client retries under the same rule.
- **Speed against SQLite.** D7 asks that point `SELECT`s, bulk `INSERT`s and joins be at least as
  fast as SQLite's; D99's condition (at most 1.0 on macOS and Linux) is still not met and has
  moved to v0.6.0 (D100's note of 2026-11-10). CI's `compare` job on the release's code (#103)
  measured, as a ratio to SQLite's time on Linux and then macOS: SQL point `SELECT` 1.584 and
  1.933, bulk `INSERT` 1.242 and 1.185, key join 1.739 and 1.280, `GROUP BY` 1.093 and 1.415. The
  Linux runner's SQLite times vary widely between runs, which moves these ratios. #103 cut a point
  select's own time by about 19%; what is left is copying the cached statement and the B-tree page
  search, for the weekly performance pass.
- **Not built in this batch:** Redis stream consumer groups (they need a new stored value kind
  under D35), Elasticsearch scroll and search templates, an identity column after the partition
  key in a primary key (it needs table definition version 15), SQLite's table-constraint conflict
  clauses, prefix indexes, SQL Server's ranking window functions (`ROW_NUMBER` and the rest; only
  aggregates take `OVER` in that dialect), and on macOS and NetBSD the keep-alive idle time on
  accepted connections (those systems copy only part of the setting from the listener).
- **Everything else** in v0.4.0's "Limits" that this release doesn't name as done still holds.

## Correctness
Every feature above has tests built from its database's manual, with new chapters in the
PostgreSQL, MySQL, SQLite, Oracle and SQL Server correctness suites; a case where EggDB still
differs from the original is marked as a known difference and listed in
[sql.md](https://github.com/eggspot/EggDB/blob/v0.5.0/docs/sql.md). The batch went through two
review passes and two security reviews before it merged (#101); they found and fixed, among
others, a privilege and row-security bypass through `TABLE` subqueries and SQL `EXECUTE` that
never shipped.

## Compatibility from here on
- **Files:** every later release reads the files this one writes (D20). The file format is still
  version 1, and this release adds no record version, feature bit or sample file.
- **Exports:** eggdb-jsonl version 1 stays importable.
- **The command's output:** the JSON fields and exit codes in
  [cli.md](https://github.com/eggspot/EggDB/blob/v0.5.0/docs/cli.md) are stable; `eggdb serve`
  gains `--tcp-keepalive`.
- **The Rust API** is pre-1.0: it may change between minor releases.

**API changes since v0.4.0:** additions only.
- `Database::kept_collection_counts` and `ReadTransaction::kept_collection_counts`, each
  collection's kept count without reading keys.

## Size and speed
CI measures the stripped release `eggdb` binary on every change (D6, `scripts/footprint.sh`
against `benchmarks/footprint.txt`), here from the release's code (#103):

| | macOS (Apple silicon) | Linux (x86-64) |
|-|-----------------------|----------------|
| `eggdb` binary, v0.5.0 | 13,943,064 bytes | 18,158,672 bytes |
| `eggdb` binary, v0.4.0 | 13,545,848 bytes | 17,629,736 bytes |
| Growth | 397,216 bytes (2.9%) | 528,936 bytes (3.0%) |
| C API library, v0.5.0 | 8,548,672 bytes | 10,910,816 bytes |
| C API library, v0.4.0 | 8,333,552 bytes | 10,626,456 bytes |
| C API library growth | 215,120 bytes (2.6%) | 284,360 bytes (2.7%) |

The growth is the batch's seventeen features and the point-select fast paths, each with its
reason recorded where the budgets were raised (#101, #103). The same CI run measured the
key-value paths against SQLite's time on Linux and macOS: point gets 0.73 and 0.87, scans 0.56
and 0.78, and batched random overwrites 0.62 and 0.66, all faster than SQLite's; through SQL, see
"Limits". The exact size of every download is in the release's "Sizes" table.

## Downloads
One self-contained file per platform, with the licenses and the README:
- Linux: `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` are static and run on any
  distribution; the `-linux-gnu` builds link glibc 2.35 or newer.
- macOS: `aarch64-apple-darwin` (Apple silicon) and `x86_64-apple-darwin` (Intel).
- Windows: `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`.

Next to them: the C API (`eggdb-capi-<version>-<target>`) for the two Linux `-gnu` targets, both
macOS targets and both Windows targets; a `SHA256SUMS` file; a signed build provenance
attestation for every archive (`gh attestation verify <archive> -R eggspot/EggDB`); and the
container image `ghcr.io/eggspot/eggdb:0.5.0` (and `:latest`) for `linux/amd64` and `linux/arm64`.
The desktop client (`eggdb-gui`) is built from source (`cargo run --release -p eggdb-gui`).

The binaries are not signed. On macOS, a file downloaded with a browser is quarantined: run
`xattr -d com.apple.quarantine eggdb` once. On Windows, unzip the archive and add its folder to
your PATH; SmartScreen may ask once before the first run.

## What was tested
Each statement in these notes is checked by tests that run on every change, and each release
binary is checked as a user gets it.

- **CI** (`.github/workflows/ci.yml`, on every pull request and on `main`; the required check is
  its last job, `check`): the same jobs as for v0.4.0 (lint and tests on Linux, macOS and Windows,
  the musl, allocator, cross-target, Unix virtual machine and other-CPU jobs, the real clients
  and drivers against `eggdb serve`, the Kubernetes, installer, footprint, reproducible-build,
  Unicode, Arrow, browser and mobile jobs, and `bench` and `compare`), plus the new release tag
  script's test in `lint-and-test` (D353). The Redis blocking-command tests wait for `INFO`'s
  `blocked_clients` instead of sleeping (#102).
- **The release** is the first made from the merge commit's `Release:` trailer (D353): after CI
  passes on `main`, `tag-release.yml` tags the commit and calls `release.yml`, which builds and
  packages every target, unpacks each archive as a user would, checks the binary's `--version`,
  runs `scripts/smoke-test.sh` on it, attests the archives, publishes this Release and pushes the
  image.
