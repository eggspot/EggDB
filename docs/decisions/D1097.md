## D1097 Leaderless quorums between processes, under `eggdb serve --quorum` — Decided by the code-only session (2026-11-13, D355); roadmap M18 (D225, D442, D443, D444)

- **Same rules, real processes.** `eggdb_cluster::quorum_net::QuorumNode` keeps D225's placement (rendezvous hashing over the members), version vectors, hybrid-clock stamps and resolutions. It runs them between processes: the coordinator sends a write's version to all `n` homes at once and counts `w` acknowledgements, sending a hint to the next node in the key's order for each home that fails. A read gathers versions from the homes until `r` answer, reconciles them, and repairs the homes that were behind. The reconciliation is one function, `quorum::reconcile`, shared by the in-memory `Replica`, the simulation and the persisted store, so they cannot drift.
- **Storage.** `ReplicaStore` is the node's replica and hints. `eggdb::quorum_store::DatabaseReplicaStore` keeps them in the database file's `eggdb.quorum` and `eggdb.quorum_hints` collections, each apply being one write transaction (read, reconcile, write), so a replica survives restarts and is in the file's backups. `MemoryReplicaStore` serves tests and embedded use.
- **Wire.** `quorum_wire` frames (length-prefixed, kind byte, big-endian fields, at most 64 MiB, every length checked, no panics on damaged input). One port carries client requests (`Put`, `Get`) and node traffic (`Store`, `Fetch`, `Hint`, `Tree`, `KeysAt`), documented in `docs/quorum.md` for clients in other languages.
- **Background work.** `maintain` hands hints off every second. Every 30 seconds it runs anti-entropy: with each peer it exchanges the 1,024 Merkle leaves (D443) over the keys both are homes of, lists the keys under differing leaves from both sides, and reconciles only those, in both directions.
- **Security.** Every connection starts with `Hello` and the server's password (compared in constant time). Peers outside the machine require TLS, as `--cluster` does: the transport is pluggable (`Dialer`, `Acceptor`), and `serve` plugs in `eggdb-tls` with `--cluster-ca` checking peer certificates.
- **Under `serve`.** `--quorum id=host:port,...`, `--quorum-node`, `--quorum-replicas n,r,w` (default up to three replicas with majorities) and `--quorum-resolution lww|siblings|counter|set`. It runs beside, not inside, the Raft cluster of D1036, which keeps a single leader for SQL.
- **Left.** Membership changes at run time (D444's epochs are in the in-memory model; here members come from the command line), tombstone collection between processes, and RESP or HTTP front ends routing through the quorum.
