## D336 TCP keep-alives: `set_tcp_keep_alive` on a listener in the platform layer, `NetStream::set_keep_alive` with probes across cuts in the simulated network, and `eggdb serve --tcp-keepalive` (default 300 s) on every listener — Decided by the build loop (batch 6, 2026-11-10); roadmap M1, extends D314, applies D8 and D9

A client whose machine loses power, or whose network path disappears without a reset, leaves its
server connection open forever: the server's thread waits on a receive that never completes, and
the connection holds a slot of `--max-connections` and its share of the memory budget until the
server restarts. The idle timeout (D254) closes idle logged-in connections of the SQL protocols
only, not the other protocols' connections. TCP keep-alives are the operating
system's answer: after an idle time it probes the peer, and drops the connection once enough
probes go unanswered.

- **Platform layer.** `eggdb_platform::TcpKeepAlive` holds the idle time, the interval between
  unanswered probes and their count, each time whole seconds from 1 to 32767 and the count from
  1 to 127 (Linux's limits, used everywhere so a setting means the same on every system).
  `TcpKeepAlive::after_idle(idle)` probes every third of the idle time, three times, as Redis's
  `tcp-keepalive` does. `set_tcp_keep_alive(&TcpListener, TcpKeepAlive)` sets `SO_KEEPALIVE` and
  the timing on a listener; `set_tcp_keep_alive_stream(&TcpStream, TcpKeepAlive)` does it for one
  connection. The option numbers are declared per system, as the readiness backends declare
  theirs: `TCP_KEEPIDLE`, `TCP_KEEPINTVL` and `TCP_KEEPCNT` on Linux and Android (on the
  architectures whose socket constants are the generic ones), FreeBSD, DragonFly, NetBSD,
  illumos and Solaris; `TCP_KEEPALIVE` for the idle time on Apple's systems. Windows uses the
  same three options (10 version 1709 and later) and falls back to `SIO_KEEPALIVE_VALS` (idle
  time and interval; the count stays Windows' 10) when they are refused. OpenBSD has no
  per-socket timing, so there only `SO_KEEPALIVE` is set and the system-wide timing applies.
  Other systems answer `Unsupported`.
- **Set once on the listener.** Linux, Android, the BSDs, illumos, Solaris, Apple's systems and
  Windows copy a listener's socket options to the sockets it accepts, so `eggdb serve` sets the
  option once per listener and the protocol servers' accept loops stay unchanged. A
  real-socket test reads `SO_KEEPALIVE` (and the timing, where the system reports it) back from
  an accepted socket, so a system that stops copying them fails the test; such a system would
  call `set_tcp_keep_alive_stream` on each accepted socket instead.
- **Simulated network.** `NetStream` gains `set_keep_alive(Option<TcpKeepAlive>)`, with a default
  body that answers `Unsupported`, so a network that has no keep-alives still compiles; `OsStream`
  and `SimStream` implement it. In the simulation an end with keep-alives and nothing of its own
  unacknowledged (unacknowledged bytes are the retransmission timeout's, D314) remembers when it
  last heard its peer: bytes or an end of sending arriving, and the acknowledgement of its own.
  A peer reachable both ways answers every probe, so keep-alives never end a connection between
  hosts that can reach each other and add no events to the simulated clock while they can.
  Across a cut, the first unanswered probe goes out at the end of the idle period the cut falls
  in (the probes before it were answered), and `count` probes `interval` apart later the end
  gives up as after its retransmissions: its next operation fails with `TimedOut` once, then
  receives return the end of stream and sends fail with `ConnectionReset`. A cut that heals
  before then leaves the connection open, and the end counts its idle time again from the heal.
  A peer that closed its socket and later receives a probe is not modelled as answering with a
  reset; the simulation only models the vanished peer.
- **`eggdb serve --tcp-keepalive <seconds>`** turns keep-alives on for every TCP listener it
  opens (PostgreSQL, MySQL, TDS and every protocol and HTTP listener), with
  `TcpKeepAlive::after_idle(seconds)`; the default is 300 s, Redis's default, so a vanished
  client is dropped within ten minutes; `0` turns them off. Values above 32767 are a usage error.
  A system that refuses the option gets one line on stderr per listener (one in all when the
  system has no keep-alives) and the server still starts, since keep-alives protect the server
  but are not needed to serve.

Left out: a keep-alive setting in a configuration file (serve has no configuration file yet;
the flag is the setting), separate `--tcp-keepalive-interval`/`-count` flags, keep-alives on
outgoing connections (`eggdb follow`, replication), and a reset answer to a probe that reaches
a closed peer in the simulation.
