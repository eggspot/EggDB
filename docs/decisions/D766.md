## D766 Streaming SQL with event time, watermarks and windows (eggdb_streams) — Decided by the code-only session (2026-11-12, D355); roadmap M16, streaming SQL (D55)

- `CREATE EXTENSION eggdb_streams` treats an append-only table as a stream: `create_stream` names its event-time
  column and allowed lateness. The watermark is the newest event time minus the lateness, and only grows. A row
  trigger sends an event older than the watermark (or with no time) to `late_events` instead of the table, so a
  window, once emitted, never changes.
- Windows are emitted micro-batch style by `advance(stream)`, which moves the watermark and then runs each window of
  the stream: a window is emitted once the watermark reaches its end. Tumbling and hopping windows are aligned with
  `time_bucket` and computed by joining a `generate_series` of window starts with the events, between the window
  after the last one emitted and the last one closed; a hopping slide must divide the size. Session windows split each
  group's events wherever two are at least `gap` apart (`lag` and a running `sum` over the group); a session closes
  at its last event plus the gap, and the next run starts from the oldest session still open.
- Results go to an ordinary table the window creates, so they can be queried, indexed or fed to `eggdb_cdc`.
  Aggregates are any SQL aggregate expressions over the stream's columns.
- Scheduling is pg_cron's (`advance` every minute or after loads); continuous push-based evaluation inside the
  engine, stream-stream joins, updating a window for late data instead of setting it aside, and `MATCH_RECOGNIZE`
  are left.
