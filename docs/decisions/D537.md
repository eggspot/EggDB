## D537 MySQL's implicit string-to-number conversion in arithmetic — Decided by the code-only session (2026-11-11, D355); roadmap M10

In the MySQL dialect, `+`, `-`, `*`, `/` and `%` with a text operand now read the text as a
number, as MySQL does (`'5' + 3` is 8, `'12abc' * 2` is 24), instead of failing with "operator
does not exist".

- **Reading:** the longest leading decimal number after spaces (sign, digits, fraction and
  exponent), as a `DOUBLE`, MySQL's type for string arithmetic; text without one reads as 0.
- **Warnings:** text that does not read wholly as a number adds MySQL's warning 1292
  `Truncated incorrect DOUBLE value: '...'` (D536's per-statement list).
- **Then:** the converted values go through the ordinary arithmetic, so a text zero divisor gives
  `NULL` with warning 1365 (D536) and strict writes keep failing on it.
- **Left out:** conversion in comparisons (`'5' = 5`), in function arguments, hexadecimal and
  `0x` text, and strict mode turning 1292 into an error for writes.

**Status:** code written, unbuilt (code-only mode, D355).
