## D310 The client's query tabs: several tabs, each on a session kept from its first run until it closes; the grid's full-value view and menu, column widths and scrollbars — Decided by the build loop (EggAgentCode task 20261103-1926, 2026-11-03); inventory items 68 and 70, extends D275 and D279

`docs/ux/workspace.md` 2.1 and 3 named more query tabs, the full-value view, the grid's
right-click menu, column resizing and scrollbars, but the client had one tab whose runs each
opened and closed a session, so a `BEGIN` ended with its run. Claude Fable designed what those
sections left open in `docs/ux/workspace.md` section 9 (the strip with many tabs, the close
dialogs, how a tab shows its transaction, the value view, the menu with `Copy as CSV` and `Copy as
JSON`, column widths and the scrollbars' geometry).

- **Kept sessions.** `connection::SessionId` names a tab's session; `Connection::run_in_session`,
  `run_rolled_back_in_session`, `transaction_status` and `close_session` run on it. A file keeps
  its sessions on one thread of its own (`KeptSessions`), which owns an `Arc<Database>` clone and
  holds every tab's `Session` borrowed from it, so no session outlives the database and no
  `unsafe` is needed; the thread is started at the first kept run and joined when the connection
  drops, so the file is closed when `Connection` is. On a server every tab opens a `PgClient` of its
  own with the connect's options at its first run, and the client the connect opened serves only
  the catalog, the tree's drops and the inspector's samples, so none of them runs inside a tab's
  transaction (review round 1 found the first tab sharing it, so a drop rolled back with that
  tab); `PgClient::ready_status` reports the last `ReadyForQuery` status for
  `transaction_status`. Closing a session rolls its transaction back (`Session::close`, or
  terminating the tab's client), on the connection's worker thread (`CatalogRead::CloseSessions`),
  never the window's, so a slow server does not freeze the window. A kept session clears its
  cancel signal before and after each run, so a stopped run does not stop the next one.
- **Dialect per session.** A kept session idle outside a transaction follows the tab's dialect (it
  is replaced by one in the new dialect, losing its `SET`s); inside a transaction the dialect pill
  refuses the switch with Fable's toast, and the connection answers a run in another dialect with
  SQLSTATE `25001` as a second guard.
- **Tabs.** `MainWindow` keeps the showing tab in `tab` and the others in `background_tabs`, with
  `tab_position` its place in the strip (so the existing `window.tab` users stay unchanged);
  `tab_strip.rs` holds the widths, the scroll, the lowest free title and the close dialog
  (`ClosePrompt`, by priority running, transaction, unsaved). A window holds at most 400 tabs
  (`tab_strip::MOST_TABS`; one more is refused with a status line), so every tab and close button
  keeps an accessibility node id of its own. `WindowAction::CloseSession` asks
  the workspace to stop the tab's run if needed and close its session, queued until the
  connection comes back from a run. A run's answer goes to the tab whose session ran it, so
  switching tabs during a run is safe; a run asked for while another tab runs is not started and
  the status bar says which tab runs (one connection runs one statement at a time).
- **Grid.** The value view, the menu, column widths and scrollbars follow section 9.3 to 9.6.
  The value view (`value_view.rs`) and the menu (`grid_menu.rs`) live on the query tab
  (`QueryTab::value_view`, `grid_menu`), take every key while open and close on a press outside
  them; their rects are computed from the cell's place each frame, so they follow the familiar
  layouts' results region. The view's header names the value's kind (`ValueKind::label`), since
  results carry no SQL type names yet. `Copy as CSV` and `Copy as JSON` are `ResultGrid::csv` and
  `json`; a JSON or vector cell is embedded only when it parses as JSON (`grid::is_json`, depth
  256), so a PostgreSQL array such as `{1,2}` is a string. `Copy as CSV` gives a JSON cell its
  compact text, and `Copy as JSON` writes a number bare only when its text is a JSON number (`.5`,
  `5.` and `007` become strings). The platform layer gained `Key::F10` and `Key::ContextMenu` on
  Win32, Cocoa, X11 and the browser for `Shift+F10` and the menu key; on Win32 the window answers
  `F10`'s `WM_SYSKEYDOWN` and `WM_SYSKEYUP` itself (`win32::system_key_is_answered`), so Windows
  does not also enter the window menu's keyboard mode, while Alt combinations such as `Alt+F4`
  keep the default.
  Column widths step, fit and clamp in `ResultGrid` (`set_width`, `auto_fit`, `keep_widths_of`)
  and are dragged through `MainWindow::press_grid_handle`; scrollbar geometry is `scrollbar.rs`.
  Scrollbars stay shown while content overflows (the reduced-motion look of 9.6) until the
  client follows the OS's reduced-motion setting and has its fades.
- **Accessibility.** The platform layer has no menu, dialog or scroll bar roles yet, so the value
  view and the menu are a group with a read-only text area and buttons (each menu item with its
  shortcut), and the scrollbars have no nodes; the header gives `width 240 px` as its description.
