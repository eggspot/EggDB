## D862 Text and bytea through a WebAssembly module's memory — Decided by the code-only session (2026-11-12, D355); follow-up of D793

- A `LANGUAGE wasm` function may take and return `text`, `varchar` and `bytea`. Each such value is two `i32`s: an
  address in the module's linear memory and a length in bytes. To pass one in, EggDB calls the module's
  `eggdb_alloc(i32) -> i32` export with the length, writes the bytes (UTF-8 for text) where it says, and passes the
  address and length; a module taking text or bytea must export it, checked at `CREATE FUNCTION`. To return one,
  the function returns the address and length as two results (multi-value, D861), and EggDB copies the bytes out.
- The calling convention is ours, chosen over packing both into one `i64` because multi-value says it directly and
  any language targeting WebAssembly 2.0 can return a pair; a module needs only an allocator, which most toolchains
  provide. Each call still runs on a fresh instance (D793), so nothing has to be freed.
- Returned text that is not UTF-8 is 22021, an address or length outside memory traps (38000), and a returned value
  larger than the session's value limit is refused before it is copied.
- Left: set-returning functions, host functions behind permissions, and per-role limits.
