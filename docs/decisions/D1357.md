## D1357 MCP 2026-07-28 beside the handshake versions — Decided by the code-only session (2026-11-25, D355); roadmap M6d "The 2026-07-28 protocol revision (D190)"

- **Research.** The revision's changelog (modelcontextprotocol.io/specification/2026-07-28/changelog) removes the `initialize` handshake and sessions: every request carries `_meta["io.modelcontextprotocol/protocolVersion"]`, its client capabilities and client info; servers MUST answer `server/discover`; every result has `resultType`; list results and `server/discover` carry `ttlMs` and `cacheScope`; an unknown version is `UnsupportedProtocolVersionError` (`-32022`, data `supported` and `requested`); `ping` and `logging/setLevel` are removed; server-to-client requests (elicitation) become multi round-trip requests (`input_required` results); the HTTP transport drops `Mcp-Session-Id` and adds `Mcp-Method`/`Mcp-Name` headers and `subscriptions/listen`.
- **Decision: dual-era.** `eggdb mcp` keeps the handshake versions for the clients that ship them, and serves a request with modern `_meta` statelessly by the 2026-07-28 rules, as the versioning page's compatibility matrix allows ("Dual-era" server). A request with `_meta` never needs `initialize`; one without still does. `server/discover` is answered in both eras, with the modern and the legacy versions, so a dual-era client's stdio probe finds a modern server.
- **Results.** Modern results get `resultType: "complete"`, and the cacheable ones (`server/discover`, the lists, `resources/read`) `ttlMs` 60000 and `cacheScope: "private"`, as the schema the server serves depends on its flags (`--allow-write`, `--tables`), never on the client. Error answers are unchanged.
- **Confirmations.** Until multi round-trip requests are built, a modern request is treated as a client that cannot be asked mid-call, so a destructive write needs `confirm: true`, as over HTTP without an event stream (D189).
- **Left.** Multi round-trip requests for confirmations (`input_required` with `inputRequests`), `subscriptions/listen`, the Streamable HTTP rules (no sessions, `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` headers) in `eggdb serve --mcp-listen`, per-request `io.modelcontextprotocol/logLevel`, `-32602` for a missing resource under the new revision, and the `extensions` capability.
- **Proof.** An acceptance test discovers the server without `_meta`, lists tools and runs `run_sql` with modern `_meta` and no `initialize` (each result `complete`, the list with its cache fields), gets `-32601` for `ping`, `-32022` with the supported list for `1900-01-01`, and still `-32600` for a legacy request before `initialize`; a unit test pins how the result type is added.
