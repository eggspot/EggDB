## D369 PostgreSQL's exported snapshots: `pg_export_snapshot()` and `SET TRANSACTION SNAPSHOT` — Decided by the code-only session (2026-11-10, D355); roadmap M3, finishes D318's leftover

`pg_dump --jobs` and logical replication tools open several sessions that must see one
snapshot: the first exports it, the others import it before their first query.

- **Storage.** A read transaction already pins a version of the before-images (`register_reader`);
  `Store::begin_read_from(token)` joins a version some reader still holds (`join_reader`) and
  fails with `SnapshotTooOld` otherwise. `ReadTransaction::token()` gives the version, commit
  stamp, catalog root and features that make the second read see exactly what the first sees.
  No file format change.
- **Store trait.** `KeyValueRead::snapshot_handle` gives an opaque, thread-safe
  `SnapshotHandle`, and `KeyValueStore::begin_read_from` opens a read of it, or `None` when the
  handle is another store's or the store cannot share snapshots (the defaults). EggDB's store
  checks the database address in the handle; the test store keeps weak references to the
  exported maps.
- **Export.** `pg_export_snapshot()` works in a block that holds a reader (`BEGIN READ ONLY`, or
  a block turned read-only before its first query) and returns an id in PostgreSQL's
  `XXXXXXXX-XXXXXXXX-1` shape (the process id and a counter). The id goes into a process-wide
  list keyed by the store; when the statement that exported it ends, the block's reader is
  wrapped in `ExportingRead`, which removes its ids when the block ends however it ends. In a
  read-write block or outside a block it is `0A000`, since EggDB's writer sees its own
  uncommitted changes and a single statement's snapshot ends with it.
- **Import.** `SET TRANSACTION SNAPSHOT 'id'` (PostgreSQL dialect) must be in a block (`25P01`),
  outside a savepoint (`25001`), before any query (`25001 SET TRANSACTION SNAPSHOT must be called
  before any query`), and not in `READ COMMITTED` (`0A000`). An unknown or ended id is `22023
  invalid snapshot identifier`. A reader block's reader is replaced by a read of the exported
  snapshot; a writer block accepts the id only when the latest commit is the exported snapshot,
  since the writer cannot read an older one (`0A000` otherwise).
