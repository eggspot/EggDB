## D953 A speedtest1-style workload in the compare job — Decided by the code-only session (2026-11-13, D355); roadmap M4, D41's standard embedded benchmarks

- `eggdb-sqlite-compare` gains `sqlite_compare.speedtest`: one run is a fixed script of phases in SQLite's SQL, on the
  same lines as the test list SQLite publishes for its `speedtest1` program, written by us (no code taken from it):
  2000 inserts into a table without an index, into one with an integer primary key, and into one with an index, each
  in one transaction; 25 range aggregates and 10 `LIKE` aggregates and ordered `LIKE` queries without indexes; three
  `CREATE INDEX`; 100 indexed range aggregates and primary-key lookups; 100 range `UPDATE`s and one full-table
  `UPDATE`; a join and a correlated subquery in the select list; 500 `INSERT OR REPLACE`s; range and modulo
  `DELETE`s; and the `DROP TABLE`s that leave the file as it was, so runs repeat.
- Text columns hold numbers spelled in English words, as speedtest1's do, so `LIKE` and string lengths have real
  work. EggDB runs it through a SQLite-dialect session; SQLite steps every statement and reads every row.
- The ratio is gated like the other compare lines once its baseline is measured (D7); `ns_per_run` and
  `sqlite_ns_per_run` are reported. Running it on the `embedded` build profile (D34) waits for that profile's build in
  the compare job.
