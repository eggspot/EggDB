## D581 MQTT sessions kept in the file — Decided by the code-only session (2026-11-12, D355); roadmap M16, D526

D526's persistent sessions lived in the broker's memory, so a server restart dropped every
subscription and every QoS 1 and 2 message waiting for an absent client. A kept session is now
also written to the MQTT keyspace's database 1 (the file's next MQTT collection), keyed by client
id: when its client goes away, and again each time a message is queued for it. The broker loads
the unexpired ones when it starts; resuming a session or a clean start deletes its row. The stored
form is a format byte, the expiry in milliseconds since 1970 (so the expiry interval keeps running
while the server is down), the next packet id, the filters with their granted QoS, the
unacknowledged messages with their packet ids and released flags, and the queued messages; a
damaged or truncated row is left out at load. Writing on every queued message costs one write
per absent subscriber per message, bounded by the 1,000 messages a session queues.

**Status:** code written, unbuilt (code-only mode, D355).
