## D1214 NEXTVAL once per source row of a multitable insert — Decided by the code-only session (2026-11-17, D355); roadmap M10, Oracle's multitable inserts (D304)

- **What users get.** In `INSERT ALL` and `INSERT FIRST`, every `seq.NEXTVAL` of the `INTO` clauses' `VALUES` gives the same new number for one row of the subquery, and the sequence advances once per row, as Oracle documents: a parent and child row inserted together share one key.
- **How.** The parser already turns each `VALUES` expression and `WHEN` condition into a column of one source query, evaluated in order for each subquery row. After parsing, the first `NEXTVAL` of each sequence in that order stays, and every later one becomes `CURRVAL` of the same sequence, which reads the number the first one just took. Sequence names are matched without regard to case.
- **Left.** A `CURRVAL` written before the first `NEXTVAL` of the row reads the previous number, where Oracle gives the new one; a first `NEXTVAL` inside a `CASE` branch not taken leaves the later ones reading the previous number.
- **Proof.** `multitable_insert_tests.rs`: two `INTO` clauses reading `NEXTVAL` over three rows insert 10, 11, 12 into both tables, and the next `NEXTVAL` is 13.
