## D1009 Several path patterns and bounded quantified edges in GRAPH_TABLE — Decided by the code-only session (2026-11-13, D355); roadmap M13 (D10, D206, D1007)

- `MATCH` in `GRAPH_TABLE` takes several path patterns separated by commas. A variable that appears again, in the
  same pattern or another, is the same element: its table must be the same in every combination, and its second
  appearance adds the edge's join condition to the existing alias instead of joining the table again, so cycles
  such as `(a)-[]->(b)-[]->(a)` work. A pattern that shares no variable with the earlier ones is a `CROSS JOIN`. An
  edge variable may appear only once.
- An edge takes a quantifier `{n}`, `{m,n}` or `{,n}` from 1 to 10 repetitions. The pattern is expanded into one
  path per length, with anonymous vertices between the repetitions; the edge variable becomes `name_1`, `name_2` and
  so on, and its element `WHERE` applies to each repetition through the renamed variable. Unbounded quantifiers
  (`+`, `*`, `{m,}`) and zero repetitions are refused with a message naming an upper bound, because a text rewrite
  into joins needs a fixed length; recursive evaluation stays with the Cypher engine (D727, D884).
- A pattern standing for more than 64 combinations of tables is refused with a message to add labels, instead of
  being cut off silently (the first version of D1007 truncated).
