## D510 ClickHouse's HTTP interface — Decided by the code-only session (2026-11-11, D355); roadmap M10

`eggdb serve --clickhouse-listen <address>` serves ClickHouse's HTTP interface in a new crate,
`eggdb-clickhouse`, the first step of the roadmap's "ClickHouse SQL: first its HTTP interface
with its formats". ClickHouse is Apache-licensed and its HTTP interface and formats are
documented publicly.

- **Requests:** `GET /ping` and `GET /` answer `Ok.`; a query comes in the `query` parameter (a
  `GET` runs only `SELECT`, `WITH`, `SHOW`, `DESCRIBE`, `EXISTS` and `EXPLAIN`, as ClickHouse's
  read-only `GET` does) or the `POST` body, and with both the body follows the parameter, as
  ClickHouse sends insert data. Users sign in with `X-ClickHouse-User`/`X-ClickHouse-Key`, HTTP
  Basic or the `user`/`password` parameters, against the server's user; `database` must be the
  served database or `default`.
- **Formats:** the `FORMAT` clause is found outside strings and comments; without one,
  `default_format`, then `TabSeparated`. Results in TabSeparated (with its `Raw`, `WithNames` and
  `WithNamesAndTypes` forms), CSV, JSON, JSONCompact, JSONEachRow, JSONCompactEachRow, Values and
  Null; 64-bit integers are JSON strings as ClickHouse quotes them by default, and types are
  reported as `Nullable(<ClickHouse type>)` from the SQL types.
- **Inserts:** `INSERT INTO t [(columns)] FORMAT <name>` reads TabSeparated, CSV (an unquoted
  empty field is the column default), JSONEachRow (keys name the columns) or JSONCompactEachRow
  rows from the data and runs them as `INSERT ... VALUES` in batches of 1,000, every value a
  literal the column's type converts.
- **SQL:** statements run in the PostgreSQL dialect as the server's user; `SHOW TABLES`, `SHOW
  DATABASES`, `DESCRIBE TABLE` and `EXISTS TABLE` are rewritten into catalog queries.
  ClickHouse's own SQL dialect, functions and table engines are not.
- **Errors:** `Code: <n>. DB::Exception: <message>. (<NAME>)` with `X-ClickHouse-Exception-Code`,
  SQLSTATEs mapped to `SYNTAX_ERROR`, `UNKNOWN_TABLE`, `UNKNOWN_IDENTIFIER`, `ACCESS_DENIED` and
  `INCORRECT_DATA`, others `STD_EXCEPTION`; `X-ClickHouse-Summary` reports rows read and written.
- **Left out:** the native TCP protocol, RowBinary and the Native and Parquet formats, sessions
  and settings beyond `default_format`, `database` and `query_id`, and TLS (loopback only).

**Status:** code written, unbuilt (code-only mode, D355).
