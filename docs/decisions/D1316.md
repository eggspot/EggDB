## D1316 ORDER SIBLINGS BY what siblings share — Decided by the code-only session (2026-11-25, D355); roadmap M10 CONNECT BY (D304, D1213)

- **What users get.** `ORDER SIBLINGS BY` takes `LEVEL`, `PRIOR <expr>` and `CONNECT_BY_ROOT <expr>` among its keys, as Oracle does. All three are the same for every row of a group of siblings (one level, one parent, one root), so they leave the order to the keys after them, which is what Oracle gives.
- **How.** The sibling-key reader drops these keys instead of refusing them.
- **Left.** `CONNECT_BY_ISLEAF`, `CONNECT_BY_ISCYCLE` and `SYS_CONNECT_BY_PATH` as sibling keys, and `PRIOR` beside a subquery in `CONNECT BY`.
- **Proof.** A hierarchy test orders siblings by each of the three and then by name, and gets the same rows as by name alone; `CONNECT_BY_ISLEAF` is still refused.

**Status:** code written, unbuilt (code-only mode, D355).
