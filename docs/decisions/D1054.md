## D1054 Kafka's new consumer group protocol (KIP-848) — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D33, D213)

- **Flexible versions.** The Kafka server gains the encodings of flexible versions: unsigned varints, compact (nullable)
  strings and arrays, UUIDs and tagged-field sections (skipped on read, written empty), with request header v2 and
  response header v1 for flexible requests. Every length is still checked against the request.
- **Topic IDs.** A topic's ID is a fixed 128-bit hash of its name with the RFC 4122 variant and version bits set, so it
  is the same on every start and never the all-zero "no ID". Metadata now answers versions 0 to 12 (throttle time,
  cluster ID, rack, leader epochs, offline replicas, authorized-operation fields, topic IDs, and topics asked for by
  ID), following each version's field list in Kafka's published message definitions.
- **`ConsumerGroupHeartbeat` (version 0).** The coordinator keeps groups of the new protocol apart from the classic
  ones: each member's subscriptions, the partitions it reports owning, its epoch and when it was last seen. Joining
  (epoch 0, the server naming the member when the client sends none, a static member replacing its old instance),
  leaving (-1, or -2 for a static member), a changed subscription or a member silent for 45 s raises the group epoch,
  and the target assignment is computed again with the range assignor (`range` and `uniform` are accepted names). A
  member is given its target less any partition another member still reports owning, so a partition is never
  assigned twice while it moves; the assignment is sent when it changed, and the member's epoch follows the target's.
  A stale epoch is fenced (`FENCED_MEMBER_EPOCH`), an unknown member refused (`UNKNOWN_MEMBER_ID`), an unknown
  assignor refused (`UNSUPPORTED_ASSIGNOR`).
- Left: `ConsumerGroupDescribe`, `OffsetCommit` version 9 (commits checked against the member epoch), and the
  consumer-side regex subscriptions of later protocol versions.
- Learned from KIP-848 and Kafka's published message definitions (`ConsumerGroupHeartbeatRequest.json`,
