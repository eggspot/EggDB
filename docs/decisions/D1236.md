## D1236 SQLPrimaryKeys, SQLForeignKeys and SQLGetTypeInfo in the ODBC driver — Decided by the code-only session (2026-11-17, D355); roadmap M6f, the ODBC driver (D12, D46, D968)

- **What users get.** `eggdb-odbc` answers `SQLPrimaryKeys` (ODBC's six columns, in key order), `SQLForeignKeys` (ODBC's fourteen columns, for the keys referring to a primary key table, the keys a foreign key table has, or both; update and delete rules as ODBC's `SQL_CASCADE`, `SQL_RESTRICT`, `SQL_SET_NULL`, `SQL_NO_ACTION` and `SQL_SET_DEFAULT` numbers; not deferrable) and `SQLGetTypeInfo` (ODBC's nineteen columns for fourteen EggDB types, `SQL_ALL_TYPES` or one type), with their `W` forms, so tools that draw relationships or build type pickers through ODBC (Excel's Query, Access, report designers) see EggDB's keys and types.
- **How.** Like `SQLTables` and `SQLColumns` (D972): catalog queries over `information_schema.table_constraints`, `key_column_usage` (joined by `position_in_unique_constraint` for multi-column keys) and `referential_constraints`, and a `VALUES` list for the types, run on the connection with bound names.
- **Left.** `SQLStatistics`, `SQLSpecialColumns`, `SQLProcedures`, `SQLProcedureColumns`, `SQLTablePrivileges` and `SQLColumnPrivileges`, and catalogs (EggDB has one per file, so catalog arguments are ignored).
- **Proof.** An ODBC integration test: a primary key's column and position, a foreign key from another table found from the referenced table, and the type list filtered to `SQL_INTEGER` and listed whole.

**Status:** code written, unbuilt (code-only mode, D355).
