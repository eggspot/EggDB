## D404 `$$NOW` and `$$CLUSTER_TIME` in MongoDB's `aggregate` and update pipelines — Decided by the code-only session (2026-11-10, D355); roadmap M9, closes D349's leftover

MongoDB binds `$$NOW` (a date) and `$$CLUSTER_TIME` (a timestamp) once per command, so every
document of one command sees the same values. D349 bound `$$NOW` in pipeline-style updates by
replacing it with `{$literal: <date>}` before the stages run. Now:

- `$$CLUSTER_TIME` is bound the same way, to a timestamp of the command's second with increment
  1 (EggDB has no oplog, so the increment carries no order).
- `aggregate` binds both before it parses the pipeline (`pipeline_with_time`): in every stage's
  expressions, and in `$match` only inside `$expr`, because elsewhere in a filter `"$$NOW"` is a
  string the documents are compared with, as in MongoDB.
- `$literal` values are left as written, so `{$literal: "$$NOW"}` stays the string.
