## D960 A `sqlite3`-compatible module for TypeORM and Sequelize — Decided by the code-only session (2026-11-13, D355); roadmap M6f, D16 and D182's ORM list

- TypeORM's SQLite driver (`driver:` option) and Sequelize's SQLite dialect (`dialectModule:` option) both accept the
  module they would otherwise load, the `sqlite3` package, and use only its callback API. `eggdb/sqlite3` offers that
  API over an embedded EggDB `Database` in EggDB's SQLite dialect: `Database` (an `EventEmitter`, opened with
  sqlite3's mode flags and callback), `run` (with `this.lastID` from `last_insert_rowid()` and `this.changes` from the
  command tags), `all`, `get`, `each`, `exec`, `prepare` with `Statement`, `serialize`, `parallelize`, `configure`,
  `close`, the `OPEN_*` constants and `verbose()`. So both ORMs run with their own SQLite SQL, migrations and schema
  synchronisation unchanged, with one adapter instead of two dialects.
- Callbacks run on a later turn of the event loop (`setImmediate`), as sqlite3's do, so callers that rely on that order
  keep it; the work itself runs in the call, since EggDB is embedded and fast enough that a worker thread would cost
  more than it saves (D17).
- Placeholders: sqlite3 takes `?`, `?NNN`, `$name`, `:name` and `@name` with an array or an object; the module
  rewrites them to positional `?` with the values in order, skipping quoted text, so EggDB's driver binds them.
- `loadExtension` is refused: EggDB loads no SQLite extensions. Prisma is left: it needs a driver adapter in its own
  interface.
