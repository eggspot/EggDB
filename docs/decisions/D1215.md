## D1215 pgRouting's graph structure and all-pairs functions — Decided by the code-only session (2026-11-17, D355); roadmap M12, topology and routing at pgRouting's level (D57)

- **What users get.** After `CREATE EXTENSION pgrouting`: `pgr_strongComponents(edges_sql)` (`seq`, `component`, `node`; a component is named by its smallest node, as pgRouting documents), `pgr_articulationPoints(edges_sql)` (`node`), `pgr_bridges(edges_sql)` (`edge`), `pgr_topologicalSort(edges_sql)` (`seq`, `sorted_v`), and `pgr_floydWarshall(edges_sql [, directed])` and `pgr_johnson(edges_sql [, directed])` (`start_vid`, `end_vid`, `agg_cost` for every two different connected nodes).
- **How.** New graph code in `routing/structure.rs`, over the same edge JSON and `graph` builder as D782 (a negative cost means no way): Tarjan's strongly connected components and Hopcroft–Tarjan articulation points and bridges, both as iterative depth-first walks so deep graphs cannot overflow the stack, bridges tracked by edge id so of two parallel edges neither is a bridge; Kahn's topological order taking the smallest ready node first, so the order is stable; and all-pairs costs as one Dijkstra run from each node (costs are never negative here, so Johnson's reweighting is not needed and both names give the same rows), bounded at 4,096 nodes (`54000`). The SQL functions are thin wrappers like D782's, through five new `eggdb_route_*` functions.
- **Left.** Turn restrictions and contraction; Bellman–Ford, DAG shortest paths and biconnected components came next (D1216).
- **Proof.** Unit tests in `routing/structure.rs` (cycles named by their smallest node, two triangles joined by a bridge, parallel edges, topological order and a cycle refused, all pairs directed and undirected) and an SQL test in `pgrouting.rs`.

**Status:** code written, unbuilt (code-only mode, D355).
