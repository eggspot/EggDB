## D688 OTLP protobuf for EggDB's own telemetry — Decided by the code-only session (2026-11-12, D355); roadmap M6c, OTLP export (D25, D188, D567, D666)

- `eggdb serve --otlp-endpoint` can now post its metrics, log lines and slow-statement spans in OTLP's protobuf
  encoding (`ExportMetricsServiceRequest`, `ExportLogsServiceRequest`, `ExportTraceServiceRequest`, sent as
  `application/x-protobuf`), the encoding every OpenTelemetry collector and many backends that take no JSON accept.
- The encoding is chosen as OpenTelemetry's own exporters choose it, by `OTEL_EXPORTER_OTLP_PROTOCOL`:
  `http/protobuf` picks protobuf. Any other value, or none, keeps OTLP/HTTP JSON, so D567's default does not change
  under a running deployment (OpenTelemetry's SDKs default to protobuf; EggDB keeps JSON until the option is
  in the command registry). `grpc` is not offered; there is no HTTP/2 yet (D34).
- The protobuf messages carry the same content as the JSON ones: the `service.name` and `service.version` resource,
  the `eggdb` scope, gauges and cumulative monotonic sums of integer points (`as_int`) with a `database` attribute,
  `INFO` log records, and server spans with the database attributes. They are written by a small protobuf writer in
  `serve_otlp.rs`, with no new dependency.
- Still left: TLS to the collector (`https://` endpoints).
