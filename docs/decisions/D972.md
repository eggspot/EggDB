## D972 `SQLTables` and `SQLColumns` in the ODBC driver — Decided by the code-only session (2026-11-13, D355); roadmap M6f, follow-up of D968

- BI and query tools list tables and columns before anything else. The ODBC driver now answers `SQLTables` (schema and
  table patterns, and a comma-separated list of table types such as `'TABLE','VIEW'`) and `SQLColumns` (schema,
  table and column patterns) with ODBC's result columns (`TABLE_CAT` … `REMARKS`, and the eighteen of `SQLColumns`
  from `TABLE_CAT` to `IS_NULLABLE`, with ODBC type codes mapped from the data types).
- Both read `information_schema` through a second C API session in PostgreSQL's dialect on the same database, opened
  the first time a catalog call needs it and closed with the connection, as the JDBC driver's catalog session does,
  so the answers are the same whatever dialect the connection runs; EggDB's own schemas (`pg_catalog`,
  `information_schema`, `eggdb_internal`) are left out. Patterns are bound as parameters, never spliced into SQL.
- The ODBC test now lists the table it created and its three columns in order.

**Status:** code written, unbuilt (code-only mode, D355).
