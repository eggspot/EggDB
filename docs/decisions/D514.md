## D514 SQL Server `CONTAINS` and `FREETEXT` — Decided by the code-only session (2026-11-11, D355); roadmap M8

The SQL Server dialect parses `CONTAINS (column | (columns), condition [, LANGUAGE x])` and
`FREETEXT (column | (columns), text [, LANGUAGE x])` into boolean predicates evaluated over the
named columns' text, as D513 did for MySQL's `MATCH ... AGAINST`.

- **CONTAINS:** words and `"phrases"` matched as whole, case-insensitive words; `"prefix*"`;
  `AND`, `OR`, `AND NOT` and their `&`, `|`, `&!` forms with SQL Server's precedence (`AND`
  before `OR`) and parentheses; `NEAR` and `NEAR((a, b), n)` read as all terms present (the
  distance is not checked); `FORMSOF(INFLECTIONAL|THESAURUS, ...)` and `ISABOUT(...)` read as any
  of the listed terms, with `WEIGHT` ignored. A malformed condition fails with error 7630 and an
  empty one with 7645, as SQL Server does.
- **FREETEXT:** true when the columns hold any of the text's words other than a short list of
  noise words; SQL Server's stemming and thesaurus are not applied.
- **Left out:** `*` for every column (refused with a message), full-text catalogs and indexes,
  `CONTAINSTABLE` and `FREETEXTTABLE` with their ranks, language-specific word breakers and
  stemmers, and SQLite's FTS5.
