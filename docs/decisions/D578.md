## D578 The SQL:2023 conformance list and its check — Decided by the code-only session (2026-11-12, D355); roadmap M5, D32

D32 asks for a published conformance list with each feature's status and the test that shows it.
[sql-conformance.md](../sql-conformance.md) starts it: one table row per feature ID of SQL/Foundation
and SQL/JSON with its name, a status of `done`, `partial` or `not yet`, and for a done feature the
test as `<file>::<function>` under `crates/eggdb-sql/src`. `conformance_tests` (a unit test of
`eggdb-sql`, so CI runs it with the others) reads the list at build time and fails when a row has
an unknown status, a feature appears twice, or a done feature's test is missing or is not marked
`#[test]`. The first rows cover features whose tests were found by name (constraints, schema
manipulation, joins, recursion, savepoints, grouping sets, `LATERAL`, windows, SQL/JSON) and a few
known gaps; a feature not listed has not been assessed, and each later feature added must bring
its test.

**Status:** code written, unbuilt (code-only mode, D355).
