## D1005 Agent memory as MCP tools and `eggdb memory` — Decided by the code-only session (2026-11-13, D355); roadmap M12, agent memory (D31, D205, D740)

- Agent memory (D740) is offered to agents as three MCP tools of `eggdb mcp`, each with its CLI twin, as every tool has
  one (D119, the command model):
  - `memory_add` / `eggdb memory add <file> <agent> <text>`: `eggdb_ai.remember`, returning the new id;
  - `memory_get` / `eggdb memory get <file> <agent> <text> [-n <count>]`: `eggdb_ai.recall`, the best matches by
    reciprocal rank fusion of embedding distance and full-text rank, 5 by default and at most 100;
  - `memory_delete` / `eggdb memory delete <file> <agent> <id>`: `eggdb_ai.forget`.
- `memory` is a new noun. Its verbs are core verbs (`add`, `get`, `delete`) as the command model requires; `get`
  rather than `list`, since a recall is ranked by a query, not a page of everything.
- `memory_get` is read-only and offered to every agent; `memory_add` and `memory_delete` change data and are offered
  only with `--allow-write`, and they run through the server's write path (audited, one transaction each, the
  agent's role applied) with the statement built by the server from the arguments, so an agent never sends SQL to
  use them. Text is passed as SQL literals with quotes doubled; an id must be a whole number.
- Results are the statement results `run_sql` gives, so agents read them the same way; memories are data stored in
  the database, never instructions.
- The extension is not installed by the tools: without `CREATE EXTENSION eggdb_ai` they fail with a message saying so.
