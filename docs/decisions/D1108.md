## D1108 Sync log compaction, partial sync, field merges and CRDTs as sub-keys, and end-to-end sealing — Decided by the code-only session (2026-11-13, D355); roadmap M18 (D228, D1106)

- **Compaction keeps positions.** `Replica::compact_log` empties every logged change that a later change of the same key superseded, keeping one entry per key: the newest, deletions included, since peers still need tombstones. Entries are rewritten in place rather than removed, so every cursor any device holds stays valid with no coordination, and a device catching up from an old cursor receives each key once.
- **Partial sync.** A request may name key prefixes (`prefix=<hex>`, repeatable; `SyncOptions::prefixes`). The server sends only matching changes and still moves the cursor past the rest, so a device can hold, say, its user's notes but not their photos. Rows written locally under other prefixes still go up.
- **Merges as sub-keys.** Finer merges are built from D228's last-writer-wins keys, so the wire format, the server and conflict resolution stay as they are. A record's fields are separate keys (`write_fields`, `fields`), so concurrent edits to different fields both survive. A counter keeps one key per replica holding that replica's running total, written only by it, and its value is the sum: a positive-negative counter. A set keeps one key per element, present or removed, newest wins: a last-writer-wins element set. Text CRDTs (sequence merges) are not attempted; text fields merge per field.
- **End-to-end sealing.** With a `Sealer` (a 32-byte secret on every device of the user), each change leaves sealed. Its key becomes HMAC-SHA-256 of the key, so the server still keeps one row per key and orders by the untouched stamp. Its value becomes the original key and value under AES-256-GCM, with the stamp as associated data and a nonce derived by HMAC from the stamp and key. The stamp is unique per write, so a nonce never repeats under one key. Opening checks the tag and that the key matches its HMAC, so a server cannot move or alter a change undetected. The server never sees keys or values. A prefix filter then only matches whole sealed keys.
