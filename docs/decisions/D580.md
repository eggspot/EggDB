## D580 `match` on a `keyword` field compares the whole text — Decided by the code-only session (2026-11-12, D355); roadmap M8, D559

A `keyword` field is not analyzed, so Elasticsearch's `match` on one compares the query's whole
text with the value: `{"match": {"status": "In Progress"}}` finds `"In Progress"` and not
`"in progress"` or `"Progress"`. D559 could not do this, since `match` kept only the analyzed
tokens. A single-field `match` now parses to `Query::Analyzed`, the usual `Match` together with
the text as written; `mappings::apply` turns it into a `term` on the field's source path when the
field resolves to a `keyword` (a mapped `keyword`, a multi-field, or the dynamic `.keyword`), and
into the plain `Match` otherwise. Code that scores or highlights a query that has not been through
the mappings (aggregation filters) looks through the wrapper to the `Match`, so it behaves as
before. `multi_match` and `query_string` are unchanged.

**Status:** code written, unbuilt (code-only mode, D355).
