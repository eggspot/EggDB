## D1292 SQL Server's PATINDEX, QUOTENAME, ISNUMERIC, DATEFROMPARTS and Oracle's BITAND, REMAINDER, NANVL — Decided by the code-only session (2026-11-18, D355); roadmap M4 dialects (D10, D1291)

- **What users get.** In SQL Server's dialect: `PATINDEX('%pattern%', text)` (the position where a `LIKE` pattern with `%`, `_`, `[abc]`, `[a-z]` and `[^...]` first matches, case-insensitive as the default collation, 0 when it does not), `QUOTENAME(name[, quote])` (brackets, quotes, parentheses, angle brackets or braces, the closing character doubled inside, NULL past 128 characters or for another quote), `ISNUMERIC(expr)` (1 for what converts to a number: signs, currency symbols, thousands separators, exponents, and SQL Server's lone `+`, `-`, `$` and `.`) `DATEFROMPARTS(y, m, d)`, `DATETIMEFROMPARTS` (milliseconds), `DATETIME2FROMPARTS` and `TIMEFROMPARTS` (fractions at a precision of 0 to 7) and `SMALLDATETIMEFROMPARTS`. In Oracle's: `BITAND(a, b)`, `REMAINDER(n2, n1)` (`n2 - n1 * ROUND(n2 / n1)`, ORA-01476 for a zero divisor) and `NANVL(n2, n1)`. Stored procedures and reports written for those databases call these often.
- **How.** One module answering each name in its own dialect only, after MySQL's (D1291) in the evaluator's chain, with result types in typing; `DATEFROMPARTS` builds its date as `make_date` does and fails with 22008 for impossible dates.
- **Left.** `PATINDEX` under case-sensitive collations, `ISNUMERIC`'s acceptance of tabs and of `d` exponents, and `DATETIMEOFFSETFROMPARTS`.
- **Proof.** Unit tests follow SQL Server's documented `PATINDEX` and `QUOTENAME` examples and check `ISNUMERIC` on numbers, money, exponents, a lone sign, letters and the empty string.

**Status:** code written, unbuilt (code-only mode, D355).
