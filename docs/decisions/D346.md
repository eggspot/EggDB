## D346 MCP agents count, compare-and-set and expire keys with `incr`, `cas`, `expire` and `persist` under D328's permission model, and `put` says when its key expires — Decided by the build loop (batch 6, part P11, 2026-11-10); roadmap M6d, finishes two of D328's "Left", applies D9, D11, D35, D140, D143 and D190; security-critical (D35)

D328 gave agents `put` and `del` and left counters, compare-and-set and `expire` as tools, and
`expires_at` in `put`'s result, which `eggdb put --json` prints and the tool did not.

**What users can do.**

- With `eggdb mcp --allow-write` (and without `--tables` or a role), an agent gets four more
  tools, each the twin of the `eggdb` command of the same name with `--json`:
  - `incr` adds `by` (1 by default, any 64-bit whole number; negative subtracts, so it is also
    `eggdb decr`) to the counter under a key and returns the new `value` as text. A missing key
    counts as 0, the key keeps its time to live, and a value that is not a counter or a sum
    outside the range fails with `sql_error`, SQLSTATE `22000` and a `fix`, changing nothing.
  - `cas` stores `new` only while the key holds `expected` (`if_absent: true`: only while it is
    not there), or removes the key with `delete: true`, in one transaction; `swapped` says
    whether it did and, when it did not, `value`/`value_hex` is what the key holds.
  - `expire` gives a key a time to live of `ttl` whole seconds (0 to 3,155,760,000, about 100
    years); `expires` says whether the key was there, with `ttl_ms` and `expires_at`. A `ttl`
    of 0 deletes the key at once, as Redis's `EXPIRE key 0` does, and answers `deleted`.
  - `persist` removes a key's time to live; `persisted` says whether the key is there.
- `put` with a `ttl` now answers `expires_at` too, the same RFC 3339 UTC time to the
  millisecond as `eggdb put --json`.

**The permission model (D328, D35).**

- **Grant.** All four need `key_value_write`: `--allow-write` on a server that grants the
  key-value store. They are not offered, and are refused with `read_only`, `limited_to_tables` or
  `limited_to_role`, on a read-only server (the default), under `--tables`/`--mcp-tables` and for
  an agent acting as a role (D190).
- **SQL's key space.** Every key tool goes through `key_write_request`, which refuses a key
  under `RESERVED_KEY_PREFIX` in the default key space with `invalid_arguments` before the file
  is opened or anything is audited as started, so a counter, a swap or a time to live never lands
  on a table's row, an index entry or the catalog. The engine refuses its own keys (collections
  and deadlines) underneath. Tests call every tool with every row key of a sample table.
- **Confirmation.** A call that deletes at once asks the user exactly as `del` does
  (`elicitation/create` naming the key and its collection, or `confirm: true`; the confirm check
  `key_delete`): `expire` with `ttl` 0 and `cas` with `delete` and an `expected` value. Their
  effect is `destroy`. `incr`, `persist`, a `cas` that stores and an `expire` above 0 do not ask
  (effect `change` for `incr` and `persist`): they name one key and replace its value or its
  time to live, which `put` already does without asking (D328); a short time to live is
  something `put`'s own `ttl` can already give. A `cas` with `if_absent` and `delete` cannot
  delete anything and does not ask.
- **Audit and limits.** They run through the same path as `put` and `del`: a `call_started`
  record before the write, a `call` record with `confirmation`, `committed` and `warning` after;
  the call's time limit and its 256 MiB change limit count the key, the collection name and the
  stored bytes.
- **Defence in depth.** `VisibleWrite` refuses all four with `42501` whenever it confines tables,
  as it refuses `put_with_expiry` and the collection writes.

**How it works.**

- **Store.** `eggdb_sql::KeyValueWrite` gains `increment`, `compare_and_set`, `set_expiry` and
  `clear_expiry`, each taking `collection: Option<&str>` and answering `None` when the
  collection is missing; their defaults refuse with `0A000`, so every SQL-internal writer
  (savepoint and PL/pgSQL undo writers, read-only and temporary writers) refuses them.
  `compare_and_set` also returns the value that was there, read in the same transaction, and
  `clear_expiry` whether the key is there, as `eggdb persist` reports. `eggdb::sql::SqlWriter`
  and `SharedWriter` implement them over `WriteTransaction` and `WriteCollection`; the boxed
  writer, the MCP server's `LimitedWrite` and `VisibleWrite` forward them. `TransactionWriter`
  (SQL inside `WriteTransaction::sql`) keeps the refusing defaults: its statement undo log puts
  back plain values and could not put back a time to live.
- **Errors.** The engine's `NotAnInteger` maps to SQLSTATE `22000` (data exception) instead of
  `XX000`, the class both of its cases (not a counter, out of range) belong to; the message says
  which.
- **Registry (D143).** The tools are named after their twins' words. A new argument type,
  `ArgumentType::SignedInteger { least, most, default }`, gives `by` its negative range and
  `ttl` no default, so a client that fills in defaults never sends the destructive 0. The tool
  reads its bounds from the registry, the one place they are written.
- **One time format.** The RFC 3339 formatter (`utc_rfc3339`) and the expiry time
  (`expires_at`) moved into `eggdb-commands`, which the CLI (`eggdb put`, `ttl`, `expire`, the
  shell) and the MCP server (`put`, `expire`, the audit file's times) all use; the CLI's and the
  audit module's copies of the civil-date code are gone.

**Decided by research.**

- *`ttl` in seconds, not the CLI's `30s` grammar.* The plan's review chose whole seconds, as
  Redis's `EXPIRE` takes; `put` keeps D328's grammar since it shipped.
- *`ttl` 0 deletes instead of being refused.* `eggdb expire` refuses 0, but an agent that ports
  Redis code writes `EXPIRE k 0` to delete; it is allowed and treated as the delete it is.
- *`cas` with `delete` asks.* Without it an agent could read a key with `kv_get` and delete it
  with `cas` without the confirmation `del` needs.
- *`incr`'s `value` is text.* It matches `eggdb incr --json` and the stored counter's form.

**Tests.** `eggdb-mcp` (`tests/all/key_writes.rs`): the four refused and not listed on a
read-only server, under `--tables` and for a role; every key tool refused on every SQL row key
of a sample table, nothing opened or changed; `incr` up and down, a non-counter value and bad
`by` values; `cas` taking and releasing a lock, binary values shown as hex, a delete that needs
`confirm: true`, conflicting arguments; `expire` with a time, an absent key, 0 unconfirmed and
confirmed, bad `ttl` values, and an `elicitation/create` accepted and declined; `persist`;
`put`'s `expires_at`; a confined `VisibleWrite` refusing all four. `tools.rs`: the tools list
with the grant, `by`'s and `ttl`'s schemas. `call_store.rs`: the 256 MiB limit counts a `cas`.
`eggdb-sql` `store_tests.rs`: the boxed writer forwards them and the defaults refuse with
`0A000`. `eggdb` `sql.rs`: both writers count, swap, expire and persist in both key spaces, and
refuse the engine's own keys. The built binary (`tests/all/mcp.rs`): counters, a collection
lock, `expire` read back with `eggdb ttl`, `persist`, `expire` 0 in a collection, and a SQL key
refused. `eggdb-commands`: the grants and confirm checks of the new tools and the time format.

Left: the MCP key tools for agents with a role and under `--tables` (D328's key-level grants and
allow-list), and `incr` on floating-point values (Redis's `INCRBYFLOAT`).
