## D1133 A published branch-coverage target for the core — Decided by the code-only session (2026-11-14, D355); roadmap M4 (D41)

- **What is measured.** The branch coverage of the core's unit tests: `eggdb-format`, `eggdb-storage` and the
  `eggdb` library, the code a file's safety depends on. Line coverage is reported beside it. Test files and code
  outside the repository are excluded.
- **How, with no third-party tool.** `scripts/coverage.sh` builds the tests with rustc's own instrumentation
  (`-C instrument-coverage -Z coverage-options=branch`, under `RUSTC_BOOTSTRAP=1` while branch counters are unstable
  on the pinned toolchain), runs them, and merges and reports with `llvm-profdata` and `llvm-cov` from the
  toolchain's `llvm-tools` component. No crate is added.
- **Published and gated.** The target is one line in `benchmarks/coverage.txt`, and `docs/coverage.md` says how it
  moves. The `Coverage` workflow runs weekly on Saturdays, with the performance pass (D354), and on request. It fails
  when the figure drops below the target. It is not a PR check: instrumented builds of the whole core would add tens
  of minutes to every PR, which D101's fast-feedback rule rules out.
- **Rising every release.** Each minor release raises the target to the last measured figure rounded down, never
  lowering it, until it reaches SQLite's 100%. The first run writes the starting value with `--update`. Until then the
  file holds 0.
