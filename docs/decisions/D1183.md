## D1183 Live queries woken by commits — Decided by the code-only session (2026-11-15, D355); roadmap M6a, follows D878, D1178 and D1182

- `eggdb_sql::commit_signal` keeps a process-wide commit generation, a counter under a mutex with a condition variable. `activity::committed()`, which every write transaction's successful commit already calls, now moves it and wakes every waiter. `commit_generation()` reads it and `wait_for_commit(seen, timeout)` sleeps until it moves or the timeout passes.
- Server-Sent Events live queries (D878) wait on it instead of sleeping their interval, so a change is sent as soon as it commits; the interval is now the longest wait. A run follows a wake at least 100 ms after the last, so a busy database does not make a live query re-run for every commit; and D1178's version check still skips the query when the commit did not touch this store.
- WebSocket subscriptions (D1178) and realtime channels (D1182) read the generation between socket reads: a moved generation checks at once (at most every 50 ms) instead of at the next 250 ms tick.
- The signal is per process and not per table, so a commit anywhere wakes every live query, which then checks its store's committed version (cheap) before it re-runs. Per-table wake-ups are left to the change capture (D1030) when it is on.
- Test: `a_commit_wakes_a_waiter_before_its_timeout`.
