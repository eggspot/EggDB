## D710 geotiff_info — Decided by the code-only session (2026-11-12, D355); roadmap M12, raster, GeoTIFF and Cloud-Optimized GeoTIFF (D57)

- `geotiff_info(bytea) → jsonb` reads the first image directory of a TIFF or BigTIFF file (either byte order) and
  returns its `width`, `height`, `bands`, `bits_per_sample`, `sample_format` (unsigned, signed or float),
  `compression` (none, LZW, JPEG, deflate, PackBits, zstd, or the code), `photometric`, `tiles` (`[width, height]`) or
  `rows_per_strip`, and whether it is `bigtiff`.
- For a GeoTIFF it adds the `pixel_scale` and `tie_point` tags, the `epsg` code from the GeoKey directory (the
  projected CRS key, else the geographic one), `raster_type` (pixels as areas or points), GDAL's `no_data` value, and
  the `bbox` `[west, south, east, north]` from the tie point and scale. Cloud-Optimized GeoTIFFs are TIFFs with tiles
  and overviews, so their first image reads the same way.
- Every offset and count is checked against the file. Pixel values, reprojection and raster SQL types are left.
