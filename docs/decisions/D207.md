## D207 The Bolt protocol in our own eggdb-bolt, versions 5.0 and 4.4, statements committed one at a time — Decided by the build loop (by judgement, 2026-10-31); refines D48

Part 4.M13-2 asks for Neo4j-compatible drivers over Bolt and TinkerPop clients over Gremlin.

- **Written from the public Bolt protocol and PackStream documentation**: the handshake with
  version ranges, chunked messages, `HELLO` with basic authentication, `RUN`, `PULL` (with batch
  sizes), `DISCARD`, `BEGIN`, `COMMIT`, `ROLLBACK`, `RESET` and `GOODBYE`, failure and ignored
  states, and nodes and relationships as Bolt structures (with element ids in 5.0). Versions
  5.0 and 4.4 are the two that carry credentials in `HELLO`; drivers that offer either connect.
- **Statements commit one at a time.** The key-value interface runs a transaction inside one
  call, so a Bolt transaction cannot stay open across messages yet. `BEGIN`/`COMMIT` are
  accepted and every statement commits when it runs; a `ROLLBACK` after a write is refused with
  `TransactionRollbackFailed` rather than pretending. Auto-commit sessions (`session.run`), the
  common case, behave exactly.
- **`bolt://` only**: routing (`neo4j://`, the `ROUTE` message) is refused, since one server has
  nothing to route.
- **Loopback only and SHA-256 compared passwords**, like the other new listeners, until TLS is
  added to them together.

Left: open transactions across messages (they need a session-held engine transaction), Bolt
5.1+ `LOGON`, TLS, routing tables, temporal and spatial PackStream types, bookmarks, Gremlin,
and a benchmark against Neo4j.
