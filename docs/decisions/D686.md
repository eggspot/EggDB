## D686 SQL*Plus output binds in PL/SQL blocks in eggdb shell — Decided by the code-only session (2026-11-12, D355); roadmap M5, SQL*Plus in `eggdb shell` (D150, D622)

- D622 set a bind variable only through `EXEC :name := expression`. Now a PL/SQL block typed in the shell
  (`BEGIN ... END;` or `DECLARE ... END;`, and `EXEC proc(:name)`, which is run as `BEGIN proc(:name); END;`) that
  uses declared bind variables treats them as output binds, as SQL*Plus does: `BEGIN :total := 42; END;`,
  `SELECT count(*) INTO :n FROM t;` and `OUT` parameters all set the variables.
- How: the shell rewrites the block. Each bind it uses becomes a local variable `eggdb_bind_<NAME>` of the declared
  type, set to the variable's current value; the block runs nested inside the new one; and at its end each value is
  written to the server output after a control-character marker (`~` for null, `=` and the text otherwise). The
  shell reads those lines back into the variables and never prints them. If `SERVEROUTPUT` is off, the shell turns it
  on for the block alone and drops the block's other output lines, so nothing extra is shown.
- A block that fails sets no variable. A value longer than `DBMS_OUTPUT`'s line limit fails the block. Numbers come
  back in Oracle's text form (`.5`), as `PRINT` shows them.
