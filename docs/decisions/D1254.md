## D1254 DBMS_METADATA for users and object grants — Decided by the code-only session (2026-11-18, D355); roadmap M10, Oracle's `DBMS_METADATA` (D1234, D1235)

- **What users get.** In the Oracle dialect, `DBMS_METADATA.GET_DDL('USER', 'SCOTT')` answers the `CREATE USER` statement of a user that may log in, and `DBMS_METADATA.GET_GRANTED_DDL('OBJECT_GRANT', 'SCOTT')` (the grantee defaulting to the current user) one `GRANT <privilege> ON "<table>" TO "SCOTT"` a table privilege it holds, `WITH GRANT OPTION` where it may pass it on, as migration and schema-export scripts read them.
- **How.** Both read the catalog snapshot already loaded for `GET_DDL`: the stored roles and the table grants. The password is never shown: `IDENTIFIED BY VALUES '********'`, where Oracle shows its stored hash, which EggDB keeps in another form and does not hand out. The tablespaces are Oracle's defaults, `USERS` and `TEMP`. A grantee holding nothing raises ORA-31603, another object type ORA-31600, as Oracle does.
- **Left.** Synonyms in `GET_DDL` (synonyms are not in the catalog snapshot yet), `ROLE_GRANT` and `SYSTEM_GRANT` in `GET_GRANTED_DDL`, column grants, and `UTL_FILE`.
- **Proof.** The Oracle `DBMS_METADATA` test creates a user, grants it two privileges and reads both back, and sees a grantee with none refused.
