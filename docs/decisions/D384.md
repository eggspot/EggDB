## D384 SQLite's `VACUUM` and `REINDEX` accepted as statements that change nothing — Decided by the code-only session (2026-11-10, D355); roadmap M5

SQLite applications and tools run `VACUUM` after large deletes and `REINDEX` after collation
changes, and fail when the statement is refused. In EggDB neither has work to do inside a
session: the file reuses freed pages and `eggdb compact` (offline) returns space to the file
system, and indexes are written with their rows, so they are never stale (collations do not
change under them). So in the SQLite dialect `VACUUM [schema]` and `REINDEX [collation | table |
index]` parse and return their tags without doing anything. `VACUUM INTO 'file'`, which writes a
copy, stays `0A000` until EggDB can write SQLite files (M5), and `ATTACH`/`DETACH` stay refused.
PostgreSQL's `VACUUM` keeps its refusal.
