## D859 Oracle `DBMS_METADATA.GET_DDL` — Decided by the code-only session (2026-11-12, D355); roadmap M10, the other Oracle-supplied packages (D857)

- `DBMS_METADATA.GET_DDL(object_type, name [, schema [, version]])` is an Oracle package function like
  `UTL_COMPRESS` (D733). For `TABLE` it returns `CREATE TABLE` in Oracle's form, written by the same
  `TableSchema::create_statement_in(Oracle)` that `eggdb dump --dialect oracle` uses, so the two never disagree; for
  `VIEW` it returns `CREATE OR REPLACE FORCE VIEW name AS <query>;` with the view's kept text.
- Names follow Oracle's case rule (`'EMP'` finds `emp`); a schema equal to the user's own means the search path. A
  missing object, or one of the other type, is ORA-31603; another `object_type` is ORA-31600. NULL arguments give
  NULL.
- The function reads the catalog snapshot, so `get_ddl` joins the words that load it for a statement.
- Left: the other object types (`INDEX`, `SEQUENCE`, `PACKAGE`, `FUNCTION`, `TRIGGER`), `GET_DEPENDENT_DDL`, the
  `SET_TRANSFORM_PARAM` switches (storage, segment attributes, terminators) and the XML form (`GET_XML`).
