## D1013 The W3C SPARQL test suite, run weekly — Decided by the code-only session (2026-11-13, D355); roadmap M13 (D38, D886 to D889)

- A new workspace tool, `eggdb-sparql-suite` (never shipped, like `eggdb-sqllogictest`, D664), reads every
  `manifest.ttl` under the directories it is given with EggDB's own Turtle reader and runs the SPARQL 1.0 and 1.1
  tests: positive and negative query and update syntax tests, and query evaluation tests, each on a fresh in-memory
  store loaded with the test's `qt:data` and `qt:graphData`.
- Expected results are read from SPARQL XML (`.srx`), SPARQL JSON (`.srj`) and the RDF result-set vocabulary or
  graphs in Turtle and N-Triples, with small readers written for the tool. Solutions compare as multisets (as
  sequences when the query has `ORDER BY`), graphs as sets, both with blank nodes matched one to one by a bounded
  search. Withdrawn tests, update evaluation tests and results in RDF/XML, CSV or TSV count as skipped, and are
  reported apart from failures so the rate stays honest.
- `.github/workflows/sparql-suite.yml` clones `w3c/rdf-tests` (test data only, never shipped) every Saturday and on
  demand, publishes the total pass rate in the run summary and the per-manifest rates and every failure as an
  artifact, and fails below `SPARQL_SUITE_MINIMUM` (0 until the first runs set a floor), the same pattern as the
  sqllogictest and MySQL suites (D664, D994).
