## D188 Our own HTTP/1.1 crate, and Prometheus metrics from process-wide session counters — Decided by the build loop (by judgement, 2026-10-31); refines D25 and D34

Part 4.M6c-1 asks for a Prometheus endpoint, OpenTelemetry export and live activity views, on
an HTTP server of our own that later REST and MCP-over-HTTP work shares.

- **`eggdb-http`**, a crate with no dependencies: HTTP/1.1 from RFC 9110 and RFC 9112, one
  request per connection (`Connection: close`), `GET` and `HEAD` only for now, a 16 KiB head
  and 100 headers at most, five-second read and write timeouts, sixteen connections at once
  (`503` beyond), and a stop flag like the wire servers'. TLS and request bodies come with the
  first endpoint that needs them.
- **Counters live in `eggdb-sql`** (`eggdb_sql::activity`): sessions open, statements,
  failed statements, commits and rollbacks, as process-wide atomics, so every protocol and the
  embedded API count the same way at the cost of a relaxed add per statement.
- **`eggdb serve --metrics-listen <address>`** serves `/metrics` in Prometheus' text format
  (version 0.0.4) with those counters and each served database's file size, free pages, cache
  pages, hits, misses and log since the last checkpoint, labelled by database. The endpoint
  holds no data, so it needs no password, and the operator chooses where it listens.

Left: OTLP export of traces and logs, wait events, `pg_stat_activity` for every session (it
shows the caller's own today), `sys.dm_exec_requests`, `SHOW PROCESSLIST` across sessions, and
TLS for the HTTP server.
