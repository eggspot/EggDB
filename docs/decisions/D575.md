## D575 MySQL's `information_schema.EVENTS` — Decided by the code-only session (2026-11-12, D355); roadmap M10, D421

D421 keeps MySQL events in `eggdb_internal.mysql_events` but left `information_schema.EVENTS`
empty, so MySQL Workbench, DBeaver and `SHOW`-free scripts saw no events. The catalog snapshot now
reads that table once when it is built (`internal_rows`, the same reader D556's materialized views
now share), and `EVENTS` gives one row per event with MySQL's columns: the schema and name, the
body as `EVENT_DEFINITION`, `ONE TIME` or `RECURRING` with `EXECUTE_AT` or `INTERVAL_VALUE` and
`INTERVAL_FIELD`, `STARTS`, `ENDS`, `ENABLED`/`DISABLED`, `PRESERVE`/`NOT PRESERVE`, `CREATED`,
`LAST_ALTERED`, `LAST_EXECUTED` (times in the session's zone, from the stored epoch seconds), the
comment, and the definer `root@localhost`, `SYSTEM` time zone and character set and collations the
other catalog views give. Rows are ordered by schema and name.

**Status:** code written, unbuilt (code-only mode, D355).
