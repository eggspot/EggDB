## D860 Arrow Map, FixedSizeList and Union columns — Decided by the code-only session (2026-11-12, D355); follow-up of D835

- The Arrow reader now reads Map columns: the list-like validity and 32-bit offsets, then the `entries` struct's node
  and validity, then its key and value children. A map with text keys becomes a JSON object (`{"a":1}`); a map with
  other keys becomes an array of `[key, value]` pairs, so the JSON shape follows the column's type rather than each
  row's data. A null key in a text-keyed map, or offsets outside the entries, is damage.
- FixedSizeList columns (`listSize` up to 2^20) read as JSON arrays: a validity buffer only, and a child of exactly
  rows × size values; a child of another length is damage, and the total stays under the reader's row limit.
- Union columns, sparse and dense, read as the JSON of each row's member (`5`, `"x"`): a type-id byte per row, which
  must name a member (by the type's `typeIds`, or the member's position when there are none), and for a dense union
  a 32-bit offset into that member. As Arrow 1.0's IPC layout has it, a union has no validity buffer, and a sparse
  union's members are as long as the union. The member that was chosen is not recorded in the JSON.
- Left: dictionary-encoded values inside nested columns (still refused by name), and the pre-1.0 (V4) union layout
  with its validity buffer.
