## D152 User-defined types, domains, stored arrays and deferred constraints: types as catalog records with stable OIDs loaded per statement, one `Defined` type and value in the engine, domains stored as their base type with a per-column domain, table-definition version 10, foreign keys deferred to `COMMIT` — Decided by the build loop (by judgement and PostgreSQL's public documentation, 2026-10-30); roadmap item 35b (batch part 3.08), applies D1, D9, D19, D20, D35, D111, D114, D118, D129, D131, D146

Item 35 (D118) left enum, composite and range types, domains, array columns, deferred foreign
keys, `NOT VALID`, `RENAME CONSTRAINT`, identity options and `pg_dump --clean` to later, and
pgjdbc's `getPrimaryKeys` (D131) needs a composite value from
`information_schema._pg_expandarray`. They are built here on one design.

**One type and one value for every defined type.** The engine's `SqlType` gains
`Defined(DefinedType { kind, oid })` and `Value` gains `Defined(DefinedValue)`, with kinds enum,
composite, range and domain as PostgreSQL's `typtype` has them. The OID is PostgreSQL's for a
built-in (`record`, `int4range`, `numrange`, `daterange`, `tsrange`, `tstzrange`, `int8range`)
and the type's own otherwise. Everything that already matches on types (casts, comparison,
equality keys, wire type OIDs, the catalogs, other dialects' type names) handles the new arm
once, instead of one variant per kind. Enum values carry their label's sort order (a 64-bit
float), so comparing and indexing them needs no catalog lookup; `ALTER TYPE ... ADD VALUE`
puts a new label halfway between its neighbours without rewriting rows, and is refused when the
floats run out of room between two labels.

**Types are catalog records, loaded per statement.** A type is a record under the catalog prefix,
`0x0A` and its schema-qualified name (record version 1, layout in sql.md "How SQL is stored").
Its OID is picked once from a hash of its name in 16384..2^31-1 (skipping OIDs in use) and kept,
so a client that caches type OIDs (pgjdbc, Npgsql) sees the same one across connections. The
parser resolves a type name against a registry of the definitions held in a thread-local frame
for the statement; when the registry is not loaded, the parse fails, the session loads it once
from the statement's snapshot and parses again, so statements that name no user type never read
the type records. Statements that change types forget the frame's registry, so the next statement
of a script sees the change. Value input, output and checks read the same frame.

**Domains are their base type plus a column's domain.** A domain column stores its base type,
so rows, keys, indexes and every operation on it stay those of the base type; the table records
which columns are of which domain, and the statement's prepared checks add the domain's `NOT
NULL` and checks (over `VALUE`, kept as text and parsed against a one-column scope) to the
table's own. A cast to a domain checks it; the domain's default fills a column with none.

**Table-definition version 10.** A table is written in version 10 only when it has an array or
defined-type column, a column of a domain, a `NOT VALID` constraint or an `INITIALLY DEFERRED`
foreign key; every other table keeps its version and bytes, so files without these features stay
readable by v0.2.0 (D35, D96). Version 10 adds the column types `21` (array) and `23` (defined),
the domain columns and the constraint statuses, and rows gain enum, composite and range tags.
Decoding is strict (ascending entries, names that exist, deferral only on deferrable keys, OIDs in
the user range) and every damaged byte is an error, never a panic (D9). Keys and indexes on
array, composite and range columns are refused until their key encodings keep PostgreSQL's
order; enum keys are ordered by sort order.

**Deferred foreign keys.** A foreign key check of a constraint deferred at that moment (`INITIALLY
DEFERRED`, or `DEFERRABLE` and named by `SET CONSTRAINTS ... DEFERRED`) is not run; the check is
queued in the statement's frame and moved to the transaction. `COMMIT`, `SET CONSTRAINTS ...
IMMEDIATE` and the end of an autocommit statement run the queued checks against the current
state, so a child inserted before its parent passes. A transaction queues at most 2^22 checks.
Unique keys and primary keys declared `DEFERRABLE` are still checked immediately.

**`NOT VALID`, `RENAME CONSTRAINT`, identity options, `--clean`.** `NOT VALID` skips the existing
rows and is recorded until `VALIDATE CONSTRAINT`; renames move the constraint's status and its
key's index name. Identity options in `CREATE TABLE` and `ALTER COLUMN ... SET` keep `START WITH`
and `INCREMENT BY` (and the rest on sequence-backed identities); ranges ended before the type's
range stay refused. The restore runs `pg_dump --clean`'s drops and ignores those naming nothing,
and lists `pg_dumpall`'s globals in its report.

**Records.** A composite value is a list of fields with the type's OID (or `record`'s, with its
field names). `ROW(...)`, `(a, b)` and `(value).field` are internal functions in the expression
tree; `information_schema._pg_expandarray(anyarray)` is a set-returning function of `(x, n)`
records, and a field selection over a set-returning call in a select list expands in lock-step
with the others (D131).
