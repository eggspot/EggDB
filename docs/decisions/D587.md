## D587 CQL conditional `UPDATE` and `DELETE` — Decided by the code-only session (2026-11-12, D355); roadmap M16, D218

EggDB's CQL listener answered lightweight transactions only for `INSERT ... IF NOT EXISTS`.
`UPDATE ... IF EXISTS`, `UPDATE ... IF <column conditions>`, `DELETE ... IF EXISTS` and
`DELETE ... IF <conditions>` now run as one SQL statement whose `WHERE` holds the full primary
key and then the conditions, with `RETURNING 1`; the answer is Cassandra's `[applied]` row, true
when a row matched. A conditional `UPDATE` is a plain update, not the upsert an unconditional one
is, so `IF EXISTS` never creates the row, as in Cassandra; a counter `+` reads as `COALESCE(c, 0) +`.
Conditions take the same operators as `WHERE` (`=`, `<>`, `<`, `<=`, `>`, `>=`, `IN`). Each
statement is atomic on its own (one SQL transaction), which is the guarantee Paxos gives a single
partition. When not applied, Cassandra also returns the row's current values; EggDB returns
`[applied] = false` alone, which drivers accept (`wasApplied()`).
