## D399 `_source` filtering on `GET _doc`, and `GET <index>/_source/<id>` — Decided by the code-only session (2026-11-10, D355); roadmap M8, closes one of D331/D348's leftovers

`GET <index>/_doc/<id>` returned the whole source whatever the URL asked. It now reads `_source`
(`false`, `true` or a comma list of patterns), `_source_includes` and `_source_excludes` (and the
singular spellings) through the same filter `_mget` and `_search` use (`multi::flag_filter`):
`_source=false` leaves the `_source` member out, patterns keep or drop fields as there. Elastic's
`GET <index>/_source/<id>` returns only the (filtered) source object, `404
resource_not_found_exception` when the document is missing, and `HEAD` answers `200` with no
body when it exists.
