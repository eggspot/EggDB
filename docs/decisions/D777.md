## D777 Opt-in remote embedding and language-model providers — Decided by the code-only session (2026-11-12, D355); roadmap M12, opt-in remote embedding and language-model providers (D31, D205)

- `eggdb_remote_embed(endpoint, model, text [, api_key])` and `eggdb_remote_complete(endpoint, model, prompt
  [, api_key])` speak the OpenAI-compatible embeddings and chat-completions request and answer shapes, which most
  hosted providers and the local servers (Ollama, vLLM, llama.cpp's server) accept, so one pair of functions covers
  them without naming a vendor. Embeddings come back as vector literals, ready for `vector` columns and `<=>`.
- Off by default, like `eggdb_foreign` (D229, D770): the SQL layer only builds the request and hands it, with the
  calling role, to a provider the program registers. `eggdb sql` and `eggdb serve` register one that allows the URL
  prefixes in `EGGDB_MODEL_ENDPOINTS` (matched at a path boundary, so a look-alike host or path is refused), lets
  superusers and the roles an entry names after `#roles=` call them, posts over TLS with the certificate checked
  (`EGGDB_REPORT_CA_FILE` or the system's roots), allows plain HTTP only to loopback for local models, reads
  `Content-Length` or chunked answers up to 16 MiB, and waits at most two minutes.
- Keys come from the secrets store (D751) as an argument (`eggdb_secrets.get(path, sealing_key)`), so they are never
  stored in the server's environment or in plain text; a key with a line break is refused before anything is sent.
- Provider-specific APIs, streaming answers, batching many inputs per call, and caching through `eggdb_ai`'s semantic
  cache automatically are left.
