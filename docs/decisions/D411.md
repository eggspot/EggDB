## D411 MongoDB's `explain` — Decided by the code-only session (2026-11-10, D355); roadmap M9

- The `explain` command takes `find`, `count`, `distinct`, `aggregate`, `update`, `delete` and
  `findAndModify` with MongoDB's three verbosities (`allPlansExecution` by default), and
  `aggregate` with `explain: true` answers at `queryPlanner`, as MongoDB does.
- The plan says what EggDB really does: `IDHACK` when the filter is only an `_id` equality (the
  store reads that one key), otherwise `COLLSCAN` with the filter, under `UPDATE`, `DELETE`,
  `COUNT` or `PROJECTION_DEFAULT` for those commands; `rejectedPlans` is empty since no secondary
  index is used yet (the M9 index item will add `IXSCAN`). For `aggregate` the plan describes the
  first `$match`, which is what chooses the documents read.
- `executionStats` runs the filter: `nReturned` (0 for writes, which explain never performs),
  `totalDocsExamined` (the collection's size for a scan), `totalKeysExamined` (the `_id` key for
  `IDHACK`) and the time taken. Skip, limit and sort are not reflected in `nReturned`: a known
  difference.
