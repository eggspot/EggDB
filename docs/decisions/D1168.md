## D1168 `pg_cast` lists PostgreSQL's built-in casts — Decided by the code-only session (2026-11-14, D355); roadmap M6a (D129, D131)

- **What tools see.** `pg_cast` existed with PostgreSQL's columns but no rows, so tools that list casts (psql's
  `\dC`, pgAdmin's and DBeaver's cast browsers, ORMs that read cast contexts to decide implicit conversions)
  saw none. It now holds 58 rows: the built-in casts among the integer, floating-point and `numeric` types,
  `bool` and `int4`, `oid`, the character types and `name`, the date and time types, and `json`/`jsonb` and
  `uuid`/`bytea`.
- **Each row's contents.** Each carries PostgreSQL's context:
  - `i` implicit, for example `int4` to `int8`, `varchar` to `text`, `date` to `timestamp`;
  - `a` assignment, for example `int8` to `int4`, `float8` to `numeric`, `timestamptz` to `timestamp`;
  - `e` explicit, for example `int4` to `bool`.

  Each also has its method: `b` binary-coercible for the character types and `oid`/`int4`, `i` I/O for `json`,
  `jsonb` and `uuid`, and `f` otherwise. The rows have stable OIDs from 11000.
- **Not the rule source.** The engine's conversion rules stay in code (`types::convert`); these rows describe
  them for tools and do not drive them.
- **Known difference.** `castfunc` is 0 where PostgreSQL names a conversion function: EggDB's conversions are
  not `pg_proc` entries, and a join through `castfunc` finds no function, as for a binary cast.
- **Still open in this roadmap item:** the other system columns (`ctid`, `xmin` and the rest), composite
  types' `typrelid`, the remaining `information_schema.routines` and `parameters` columns, and OIDs kept across
  renames.
- **Tests.** Contexts and methods of three casts, and distinct OIDs.

**Status:** code written, unbuilt (code-only mode, D355).
