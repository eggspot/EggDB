## D461 PostgreSQL's function call protocol — Decided by the code-only session (2026-11-11, D355); roadmap M6a, extends D103

- The `F` (FunctionCall) message is read and answered instead of refused: the function's OID is
  looked up in `pg_catalog.pg_proc` (with its schema from `pg_namespace`), each argument is
  decoded with the type OID from `proargtypes` in the format the message gives (text, or binary
  through the same decoder as Bind parameters), and the call runs as
  `SELECT "schema"."name"('arg', ...)` with untyped literals, so overloads resolve as in SQL.
- The first column of the first row is sent in a `V` (FunctionCallResponse), encoded for
  `prorettype` in the requested format, NULL as length -1; then `ReadyForQuery`. The call runs in
  an implicit transaction of its own, as a simple query does.
- An unknown OID answers `42883`; an argument count different from `proargtypes` answers
  `08P01`. Only functions `pg_proc` lists can be called: built-ins without a row there (libpq's
  large-object calls, which also need large objects) are not written.
