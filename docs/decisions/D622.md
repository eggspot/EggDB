## D622 SQL*Plus bind variables in eggdb shell — Decided by the code-only session (2026-11-12, D355); roadmap M5, D150, D544

Oracle scripts declare bind variables and use them across statements:

```sql
VARIABLE total NUMBER
EXEC :total := 42
SELECT * FROM orders WHERE amount > :total;
PRINT total
```

D544 gave `eggdb shell` `DESCRIBE`, `PROMPT` and `SPOOL`, and left `VARIABLE`/`PRINT`.

- `VAR[IABLE] name type` declares a variable. The type is one of SQL*Plus's bind types: `NUMBER`,
  `BINARY_FLOAT`, `BINARY_DOUBLE`, `VARCHAR2(n)`, `NVARCHAR2(n)`, `CHAR(n)`, `NCHAR(n)`, `CLOB`,
  `NCLOB`.
  - `VARIABLE` alone lists the variables, and `VARIABLE name` shows one.
  - A bad name or type, or a missing variable, gets SQL*Plus's SP2 message.
- `EXEC :name := expression` evaluates `SELECT expression FROM dual`, with the other variables
  already bound, and keeps the result. SQL*Plus prints "PL/SQL procedure successfully
  completed."
- `PRI[NT] [names]` prints each variable as SQL*Plus does: its name as a heading, a rule and its
  value.
- In the Oracle dialect, every statement the shell runs, and `EXEC` blocks, have each `:name` of a
  declared variable replaced by its value as a literal before running.
  - Numbers stay bare and text is quoted. An unset variable is `NULL`.
  - Quoted text, `:=` and names that are not declared are left alone.
- Unit tests cover declaring, binding a number and a quoted text, substitution outside quotes,
  and printing.

Differences from SQL*Plus: values are bound as literals, not through OCI binds. A PL/SQL block
that assigns to `:name` itself (`BEGIN :total := 1; END;`) is not an output bind, so only the
`EXEC :name := …` form sets a variable.
