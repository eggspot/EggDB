## D576 MySQL events run to the second — Decided by the code-only session (2026-11-12, D355); roadmap M10, D421

D421's events ran from the job scheduler's once-a-minute tick, so an event `EVERY 10 SECOND` ran
once a minute and every event up to a minute late. Events keep their next run in epoch seconds
already, so `eggdb serve`'s scheduler now looks for due events every second, beside the
second-granular jobs, instead of every minute. A due event runs within about a second of its time;
the look costs one indexed read of `eggdb_internal.mysql_events` a second, and nothing when no
MySQL event was ever created (the table is missing and the read stops at once).

**Status:** code written, unbuilt (code-only mode, D355).
