## D1039 The shard map and the decision log replicated on Raft, as keys of the cluster's database — Decided by the code-only session (2026-11-13, D355); roadmap M15 (D212)

- D212 said the map and the coordinator's record live in the Raft log once the cluster runs. With D1038 every write to
  a cluster's database already goes through the log as a replication batch, so the map and the decisions are stored as
  reserved keys of that database (`cluster` keys, `docs/format.md`) rather than as a second kind of log entry with a
  state machine of its own: every voter applies them in log order, a new leader has them all, they travel in
  `--cluster-seed` copies and backups, and followers' fences refuse to write them.
- `Database::publish_shard_map(map, expected_epoch)` is a compare-and-set: it writes only when the stored epoch is the
  one the change was planned on and the new map raises it, so two concurrent moves cannot both cut over, and a stale
  plan is refused rather than undoing a newer one. `shard_map` reads it back; `ShardMap::encode`/`decode` give its
  stored form, with every count checked against the bytes left.
- Two-phase commit's coordinator gets a `DecisionLog` trait (`begin`, `decide`, `outcome`), implemented by the
  in-memory `Coordinator` and by `Database::decision_log()`. A decision is a write transaction that commits through
  Raft before the coordinator tells a participant (the presumed-abort rule of D212 still holds: `outcome` records an
  abort when nothing was decided, and the first recorded decision always stands). Transaction ids come from a counter
  key, so ids stay unique across leaders. `recover_from` settles in-doubt participants from any log; `forget` drops a
  decision once every participant applied it.
- Found while writing this: D1036's consensus writes went through ordinary write transactions, which a leader's
  replication capture would have turned into batches, proposing its own Raft state back into the log. Those writes now
  call `keep_local`, which keeps them out of replication, the change archive and change data capture.
