## D759 Clean rooms: query-output policies and private set intersection (eggdb_cleanroom) — Decided by the code-only session (2026-11-12, D355); roadmap M6b, clean rooms (D52, D245)

- `CREATE EXTENSION eggdb_cleanroom` keeps rooms, their members (role names) and analyses in the `eggdb_cleanroom`
  schema. A member proposes an analysis with `propose(room, name, query)`, which also records their approval; the
  other members `approve(room, name)`. An analysis's text never changes once proposed, so an approval covers exactly
  the query it was given.
- The query-output policy: `run(room, name)` refuses (42501) until every member has approved, then runs the query
  and returns each output row as `jsonb` only if its `n` column, the size of the group behind it, reaches the room's
  `minimum_group` (10 by default, at least 2). Rows below it are suppressed, an output without `n` is refused, and
  each run is logged in `runs` with the rows returned and suppressed. Who may read the members' tables directly is
  left to ordinary grants.
- Private set intersection by commutative blinding in RFC 3526's 2048-bit MODP group (a safe prime; elements hashed
  with SHA-256 in counter mode and squared into the prime-order subgroup), new in `eggdb-crypto` as `psi_blind` and
  `psi_reblind` and in SQL under the same names, with keys of 32 to 64 bytes. `psi_reblind` refuses values outside
  the subgroup, so a crafted value cannot probe a key. In a room, each member `publish_set`s `(tag, identifier)` rows
  blinded with its own key, which never gets stored; the other member `double_set`s them with its key; and
  `intersection(room, other)` returns the caller's tags whose doubly blinded values the other member also has,
  refusing (42501) when there are fewer than the room's minimum group. Tags mean something only to their owner.
- Elliptic-curve PSI (faster, smaller), PSI-cardinality without tags, differential privacy on analysis outputs, and
  column-level output rules are left.
