## D175 Databases in memory through the platform layer's memory file — Decided by the build loop (by judgement, 2026-10-31); refines D41 and D87

Part 4.M4-1 adds databases that live in memory: `Database::in_memory()`, and the file name
`:memory:` on the command line, as SQLite's does.

- **The platform layer gives a `DatabaseFile`**: an operating-system file, or a memory file. The
  memory file is the simulated file system's file, opened in a file system of its own, so it is
  the code the crash tests exercise. Syncs on a memory file do nothing. The embedded database
  now runs on `DatabaseFile` instead of `OsFile`, which costs one match per file call.
- **Storage opens a file it is given**: `PageFile::create_in` and `PageFile::open_in` take a
  file that is already open, and `create` and `open` open one by path and call them.
- **Rules.** A database in memory starts empty, so a read-only one is refused. It has no file to
  compact, so `compact` is refused. `backup_to` writes an ordinary file from it.
