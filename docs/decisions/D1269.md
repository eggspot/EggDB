## D1269 The original ispell affix format — Decided by the code-only session (2026-11-18, D355); roadmap M4 PostgreSQL text search (D1212)

- **What users get.** `CREATE TEXT SEARCH DICTIONARY ... (TEMPLATE = ispell, DictList = '...', AffixList = '...')` also takes an affix file in the original ispell format, as PostgreSQL's `ispell` template does (the `.affix` files of ispell's own dictionaries): `prefixes` and `suffixes` sections of `flag *X:` blocks, each rule a condition, `>` and the affix to add, or `-strip,affix` to replace an ending (`[^AEIOU] Y > -Y,IES`), with `#` comments.
- **How.** A file with no `PFX` or `SFX` line and a `prefixes` or `suffixes` line is read in the original format into the same affix rules the Hunspell format gives (D1212), so reducing a word is unchanged: conditions lose their spaces and are lower cased, `*` before a flag allows cross products, `-strip,-` strips without adding, and lines outside a section (`allaffixes`, `wordchars`, ispell's other settings) are left out. A flag name of more than one character, or a rule with neither strip nor affix, is an error.
- **Left.** Compound words (`compoundwords controlled`, `COMPOUNDFLAG`), several lexemes per word, and the `thesaurus` template.
- **Proof.** A unit test reduces plural, `-Y,IES`, past-tense and cross-product forms from an original-format file and refuses an empty rule and a two-letter flag.

**Status:** code written, unbuilt (code-only mode, D355).
