## D715 Zarr arrays in SQL: `read_zarr` — Decided by the code-only session (2026-11-12, D355); roadmap M11, "Arrays: SQL/MDA, Zarr, HDF5 and NetCDF"

`read_zarr(path)` returns one row per element of the Zarr array stored under the directory `path`, with the
columns `coordinates bigint[]` and `value double precision`, like `read_netcdf` (D709). It reads the metadata from
`zarr.json` (Zarr v3) or, when that is absent, `.zarray` (Zarr v2), then every chunk in C order through the
session's file reader (D703), so servers refuse it with `0A000` as they do the other file readers.

- Data types: booleans, signed and unsigned integers of 1, 2, 4 and 8 bytes, and 4- and 8-byte floats, in either
  byte order (v2's `<` / `>` prefix, v3's `bytes` codec `endian`).
- Chunks: raw, zlib, gzip or zstd. Blosc and any other compressor, v2 filters and Fortran order are refused with
  a message naming what is missing, rather than read wrong.
- A chunk file that is absent reads as the fill value, as Zarr defines. Chunk keys follow v2's
  `dimension_separator` and v3's `chunk_key_encoding` (`default` with `c/` or `v2`).
- An array may hold at most 10,000,000 elements and 32 dimensions; larger ones are refused.

Sharding, string and complex data types, groups and consolidated metadata are left for later.
