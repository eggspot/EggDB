## D713 Flux row expressions: filter after transformations, map, pivot, rename and duplicate — Decided by the code-only session (2026-11-12, D355); roadmap M16, the rest of Flux (D682)

- Flux expressions now take arithmetic (`+ - * / %`, with `+` joining strings), `if ... then ... else ...`, the type
  conversions `float()`, `int()`, `string()` and `bool()`, and record literals `{name: expr}` and
  `{r with name: expr}`. They are evaluated on each row in Rust, with Flux's types (null, bool, int, float, string,
  time) taken from and given back to EggDB's values.
- `filter()` right after `range()` is still pushed into SQL when it can be (D682); one that cannot (it uses a record,
  a conversion or a conditional), and any `filter()` after a transformation, is evaluated on the rows. Regular
  expressions are only supported in the pushed filters.
- `map(fn: (r) => ({r with ...}))` changes or adds columns and keeps the rest; `map(fn: (r) => ({...}))` keeps the
  group key's columns and the given ones, as Flux does.
- `pivot(rowKey:, columnKey:, valueColumn:)` turns rows into columns, naming each new column by its column-key
  values joined with `_`, and drops the column key from the group key. `rename(columns: {old: "new"})` and
  `duplicate(column:, as:)` work on rows and the group key.
- Still left: `join()`, variables, several `yield`s, and the standard library's packages.
