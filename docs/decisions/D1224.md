## D1224 Float and string chunks in eggdb-columnar — Decided by the code-only session (2026-11-17, D355); roadmap M11, float and string chunks and compression beyond the encodings (D201)

- **What it gives.** The columnar building blocks next to D201's `IntegerChunk`, for the columnar tables, time series and Parquet and Arrow work still to come: `FloatChunk` and `StringChunk`, each encoded the smallest way, with statistics kept beside the data (count, least and greatest, and for floats the sum) so scans and aggregates can skip a chunk, and `to_bytes`/`from_bytes` that check the data against those statistics, so damaged bytes are an error, never a panic.
- **Floats.** Plain (eight bytes each) or XOR: each value's bits XORed with the previous value's, a repeated value as one bit and a change as its meaningful bits inside a leading/trailing-zero window that is reused while it fits (the scheme Facebook's Gorilla paper describes, written from that description). Values come back bit for bit, NaN payloads and negative zero included; NaN is left out of the least and greatest. Slow-changing series take a few bits per value.
- **Strings.** Plain (a varint length and the bytes of each value), a dictionary (distinct values once and each row's index as D201's hybrid runs) when fewer than half the rows are distinct, or the plain form compressed with D201's Snappy, whichever is smallest. Least and greatest compare bytes. Decoding refuses more than 1 GiB of decompressed bytes.
- **Left.** Columnar tables themselves (row groups of these chunks, deletes as bitmaps, `USING columnar`), nulls inside chunks, and dictionary indexes shared across chunks.
- **Proof.** Tests in `tests.rs`: a slow float series compressed below two bytes a value, odd floats round-tripped bit for bit through bytes, statistics, cut and flipped bytes refused; a repetitive column chosen as a dictionary, near-identical long strings as Snappy, short ones plain, trailing and unknown bytes refused.

**Status:** code written, unbuilt (code-only mode, D355).
