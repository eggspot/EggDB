## D1118 CXL memory, persistent memory and GPUs — Decided by the code-only session (2026-11-13, D355); roadmap M1 (optional accelerators behind build features, D40, D45, D60, D65, D77)

- **CXL memory is a NUMA node, nothing more.** Linux shows a CXL Type 3 memory expander as a NUMA node with memory
  and no CPUs. `CpuTopology::memory_only_numa_nodes()` lists those nodes from `/sys/devices/system/node` (empty
  elsewhere), and the `eggdb` crate's `cxl` build feature adds `Options::cache_on_memory_expander(true)`. That places
  the page cache on the first such node through the same `mbind` path as `cache_numa_node` (D948). The cache stays an
  anonymous allocation: no `mmap` of a device or file (D60). The log stays in the file (D77).
- **Persistent memory goes the same way.** Intel Optane and NVDIMMs used through `daxctl reconfigure-device
  --mode=system-ram` (the kernel's `kmem` driver) also become CPU-less NUMA nodes, so the same option puts the cache
  there. Mapping a DAX device or file and writing pages in place would bypass the log and the checksums, which D60 and
  D77 rule out. Durability still comes from the file on its own device, never from persistent memory.
- **GPUs run work on copies, never hold the data.** A GPU path takes vector distance, columnar scan and aggregation
  kernels over batches copied from the page cache, writes results back to host memory, and stays optional. A machine
  without a GPU, or a build without the feature, runs the same plans on the CPU with identical results; the GPU is
  never part of durability. There are no third-party crates: the work is submitted through the systems' own compute
  interfaces, declared by us (Vulkan compute on Linux and Windows, Metal on Apple's systems). The code waits for M12's
  vector kernels, which are the first workload worth sending.
- **Check.** The cache benchmarks run on a machine with an expander or `kmem` memory in the build-and-fix pass. CI
  runners have none, so the unit test covers the node discovery and the option is refused cleanly elsewhere.
