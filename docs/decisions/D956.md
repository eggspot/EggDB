## D956 SQL Server's server-level DDL events and security events — Decided by the code-only session (2026-11-13, D355); roadmap M5, follow-up of D872 and D907

- DDL triggers gain SQL Server's login events (`CREATE_LOGIN`, `ALTER_LOGIN`, `DROP_LOGIN`, groups
  `DDL_LOGIN_EVENTS` and `DDL_SERVER_SECURITY_EVENTS`), database events (`CREATE_DATABASE`, `ALTER_DATABASE`,
  `DROP_DATABASE`, group `DDL_DATABASE_EVENTS`), user and role events (`CREATE_USER` … `DROP_ROLE`, groups
  `DDL_USER_EVENTS`, `DDL_ROLE_EVENTS`, `DDL_DATABASE_SECURITY_EVENTS`) and the `DDL_SERVER_LEVEL_EVENTS` group.
- **Scope.** The login events, `CREATE_DATABASE`, `DROP_DATABASE` and the groups made only of them are server-level:
  naming one in a trigger `ON DATABASE` is error 1098, as in SQL Server, and only `ON ALL SERVER` triggers fire for
  them. `DDL_DATABASE_LEVEL_EVENTS` no longer matches them; `DDL_SERVER_LEVEL_EVENTS` and `DDL_EVENTS` match
  everything. `ALTER_DATABASE` fires at both levels, as in SQL Server.
- **Telling statements apart.** `CREATE LOGIN`, `CREATE USER` and `CREATE ROLE` all parse to one role statement, so the
  event comes from the statement's own text (its second word), which the session already keeps for `EVENTDATA()`'s
  `CommandText`; `CREATE DATABASE` and `DROP DATABASE` come from their statements.
- **Left.** Endpoint events wait for endpoints, which EggDB does not have; `EVENTDATA()` for a login names no
  `LoginName` or `ObjectName` yet.
