## D762 Row holds, records schedules and eDiscovery export in eggdb_retention — Decided by the code-only session (2026-11-12, D355); roadmap M6b, retention (D53, D246)

- **Holds over some rows.** `eggdb_retention.holds` gains `row_condition`, and `place_hold` an optional last argument
  for it. The row trigger checks each active hold: a hold without a condition still covers the whole table, and one
  with a condition refuses a change or delete (55000) only when the old row satisfies it, evaluated over the row
  through `jsonb_populate_record` with the table's own row type. `TRUNCATE` stays refused under any hold. Erasure
  requests wait on whole-table holds as before; one that meets a held row waits with
  `retention or a legal hold on some rows` and is retried by `process_erasures`.
- **Records schedules.** `record_classes` holds each class's retention period, disposition (`delete` or `review`) and
  citation; `schedule(schema, table, time_column, class)` installs the class as a permanent retention rule (D246) and
  records it in `scheduled_tables`. `due_for_disposition()` counts each table's rows past retention that no row hold
  covers; `dispose(schema, table [, reviewed])` deletes them (a `review` class needs `reviewed => true`, a whole-table
  hold refuses) and logs the disposal with who and how many in `disposals`.
- **eDiscovery export in the EDRM style.** `export_ediscovery(matter, schema, table [, condition, key_column])`
  returns an EDRM XML load file: `Root` / `Batch` / `Documents`, one `Document` per row with a `DocID` from the key
  column (or the row's position), a `#Table` tag and one text `Tag` per column; text is XML-escaped and control
  characters XML 1.0 forbids are dropped. Each export is logged in `ediscovery_exports` with its SHA-256, for the
  chain of custody.
- Engine-level WORM (refusal below the trigger layer, which a superuser cannot switch off), native files and
  attachments in the export, and EDRM's family relationships are left.
- Installing this version of the extension creates the new `holds.row_condition` column; there is no upgrade script
  for an earlier installation.
