## D1294 to_regproc, to_regnamespace, to_regrole, array_to_json, timeofday and the inet_ functions — Decided by the code-only session (2026-11-18, D355); roadmap M4 PostgreSQL catalog compatibility (D12)

- **What users get.** `to_regproc`, `to_regprocedure`, `to_regnamespace` and `to_regrole` (NULL for a name that does not exist, as `to_regclass` already was), `array_to_json`, `timeofday()` (the wall clock in PostgreSQL's text form, where `now()` stays the statement's time), and `inet_server_addr()`, `inet_server_port()`, `inet_client_addr()` and `inet_client_port()`, which answer NULL as PostgreSQL does over a Unix socket. Admin tools and migration frameworks call these on connect or before creating objects (Flyway and Liquibase check functions and schemas with `to_reg*`).
- **How.** The `to_reg*` functions reuse the registry lookup of `regproc`, `regnamespace` and `regrole` input; an undefined function (42883) now joins the errors they turn into NULL. `array_to_json` is `to_json` of an array. `timeofday` is written in UTC.
- **Left.** The server's and client's real addresses on network connections (the session does not carry them yet), `timeofday` in the session's time zone, and `array_to_json`'s pretty form.
- **Proof.** `pg_catalog/tests.rs` resolves a schema and refuses unknown schema, function and role names, reads NULL for the server address, converts an array to JSON and reads the clock text.

**Status:** code written, unbuilt (code-only mode, D355).
