## D1003 Writing Apache Iceberg tables — Decided by the code-only session (2026-11-13, D355); roadmap M11, lakehouse tables (D29, D1002)

- `eggdb export <file> --table <name> --iceberg <directory>` writes the table as a new Iceberg table, from the
  Iceberg table specification with no third-party code: one Parquet data file (D202's writer) under `data/`, a
  manifest and a manifest list (Avro object container files written by EggDB, with Iceberg's field ids in their
  schemas: `manifest_entry` 0 to 2 and 100 to 105, `manifest_file` 500 to 514), `metadata/v1.metadata.json` and
  `metadata/version-hint.text`.
- Format version 1, unpartitioned, one snapshot, an `append` summary. Every column is optional and typed from the
  table (`boolean`, `int`, `long`, `float`, `double`, `string`, `binary`, `date`, `timestamp`, `timestamptz`,
  `decimal(p, s)`). Paths are absolute `file://` URIs; D1002's reader follows a moved table.
- EggDB's Parquet writer records no Parquet field ids, so the table carries `schema.name-mapping.default`, Iceberg's
  documented way to map columns by name, so Spark, Trino, PyIceberg and DuckDB read the columns.
- The directory must not hold a table already: appending a snapshot to an existing table, partitioned tables, format
  version 2 and the REST catalog are left.
