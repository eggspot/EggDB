## D179 Vectorized execution starts with batched ungrouped integer aggregates — Decided by the build loop (by judgement, 2026-10-31); refines D40

Part 4.M5-2 asks for batch-at-a-time execution with SIMD. The executor works a row at a time,
and changing its operators to batches touches every one of them. So the first step batches the
inner loop where a single kernel pays off:

- An ungrouped query whose aggregates are all `count(*)`, or `count`, `sum`, `min` and `max` of
  a `smallint`, `integer` or `bigint` column (no `DISTINCT`, `FILTER`, `ORDER BY` inside the
  call, or `HAVING`), gathers each column's values 1,024 at a time. It reduces them with
  kernels the compiler turns into SIMD. A sum adds the high and low 32-bit halves in eight
  64-bit lanes and joins them as a 128-bit total, so no batch can overflow.
- The kernels hand back the same accumulator states the row-at-a-time path builds (a 128-bit
  integer sum marked wide when a `bigint` was seen, extremes in the column's own integer type),
  and the same code finishes them. So the results, types and overflow errors are identical,
  and a test compares both paths at the integer extremes.

grouped aggregates.
