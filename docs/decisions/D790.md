## D790 Program-defined SQL functions and more of SQLite's C interface — Decided by the code-only session (2026-11-12, D355); roadmap M5, libsqlite3

- `eggdb-sql` gets `NativeFunctions`, a set of scalar functions an embedding program supplies (a Rust closure from
  argument values to a value or an error message), keyed by lower-case name and argument count, `None` meaning any
  count; an exact count wins over any count. `with_native_functions(&functions, || ...)` makes them callable from
  the SQL run inside it on that thread; the evaluator asks them after evaluating a call's arguments and before the
  built-in functions it has not already matched, so a program can override most built-ins, as SQLite allows. A
  failing function fails the statement with 38000 and SQLite code 1. They are exported through `eggdb::sql`.
- A thread-local set rather than a field on `Session`, since SQLite's contract binds functions to a connection and
  the connection already serializes its calls; nothing else in EggDB defines functions this way yet.
- `libsqlite3`'s connection keeps its `NativeFunctions` and runs every statement inside them.
  `sqlite3_create_function` and `_v2` define one (`xFunc`), replace one, or remove one (every callback NULL); bad
  argument counts (outside -1..=127), names (empty or over 255 bytes) and mixed scalar and aggregate callbacks are
  `SQLITE_MISUSE`; an aggregate (`xStep`/`xFinal`) is refused with `SQLITE_ERROR` for now. `xDestroy` runs when the
  function is replaced or removed, when the connection closes, or at once when registering fails, as SQLite
  specifies. The callback gets `sqlite3_value`s it reads with `sqlite3_value_type`, `_int`, `_int64`, `_double`,
  `_text`, `_blob` and `_bytes`, and answers through `sqlite3_result_null`, `_int`, `_int64`, `_double`, `_text`,
  `_blob`, `_value`, `_error`, `_error_nomem` and `_error_toobig`; `sqlite3_user_data` and
  `sqlite3_context_db_handle` work. Text and blobs are always copied, so a destructor other than `SQLITE_STATIC` and
  `SQLITE_TRANSIENT` is called at once.
- Also added: `sqlite3_errstr` (SQLite's English texts), `sqlite3_extended_errcode` (the primary code: EggDB has
  no extended codes), `sqlite3_extended_result_codes` (accepted), `sqlite3_get_autocommit` and `sqlite3_txn_state`
  (from the session's transaction status; EggDB's transactions are writers from `BEGIN`), `sqlite3_busy_timeout`
  (accepted: writers already wait), `sqlite3_interrupt` (the session's cancel signal), `sqlite3_threadsafe` (2),
  `sqlite3_sourceid`, `sqlite3_complete` (a `;` outside quotes, comments and a trigger's `BEGIN ... END`),
  `sqlite3_sql`, `sqlite3_data_count`, `sqlite3_stmt_readonly` (by the statement's first word),
  `sqlite3_stmt_busy`, `sqlite3_db_handle`, `sqlite3_column_decltype` (the result column's type name) and
  `sqlite3_bind_parameter_name`/`_index` (`?NNN` names; plain `?` has none). `include/sqlite3.h` declares them.
- Left: aggregate and window functions, collations, `sqlite3_backup_*`, `:name`/`@name`/`$name` parameters (the
  dialect has none yet), and rows streamed per step.
