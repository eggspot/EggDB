## D279 The pointer acts through the accessibility tree's bounds and the same focus moves and keys a screen reader uses, and the clipboard is the system's on every desktop — Decided by the build loop (EggAgentCode task 20261103-0137, 2026-11-03); issue #29, applies D8, D9, D15, D256 and D278

Until now the GUI answered only the keyboard and screen readers (D256's "Not yet": mouse,
clipboard, live resize), copies went to an in-memory clipboard (D275) and the caret never
blinked. `docs/ux/workspace.md` 6 specifies hover, pressed and click behaviour, the caret's
timing, the clipboard per platform and the minimum window size.

- **Events.** `WindowEvent` gains `PointerMoved`, `PointerPressed`, `PointerReleased` (with a
  `PointerButton` and the modifiers), `Wheel` (lines down and right, already turned by the
  user's scrolling direction) and `PointerLeft`, in device pixels; the GUI divides by the scale.
  X11 selects `ButtonPress`, `ButtonRelease`, `PointerMotion` and `LeaveWindow` (buttons 4 to 7
  are wheel steps); Win32 reads `WM_MOUSEMOVE`, the button messages with `SetCapture` so a
  release outside still arrives, `WM_MOUSEWHEEL`/`WM_MOUSEHWHEEL` (3 lines a notch,
  `ScreenToClient`) and `WM_MOUSELEAVE` through `TrackMouseEvent`; Cocoa adds the view's mouse,
  drag, scroll and `mouseExited:` methods and an `NSTrackingArea` in the visible rectangle
  (precise touchpad deltas become lines of 20 points).
- **Clipboard.** `Window::put_clipboard_text` and `Window::clipboard_text`, at most 8 MB
  (`MAX_CLIPBOARD_TEXT_BYTES`). macOS uses `NSPasteboard`'s general pasteboard with
  `public.utf8-plain-text`; Windows `OpenClipboard` (retried while another program holds it),
  `CF_UNICODETEXT` with `\r\n` line breaks in a `GlobalAlloc` block; X11 owns `CLIPBOARD` with
  `SetSelectionOwner` and serves `SelectionRequest` for `TARGETS`, `UTF8_STRING`,
  `text/plain;charset=utf-8` and `STRING` (Latin-1) from its own event loop, answering with
  `SendEvent`, and reads another owner's text through `ConvertSelection` into a property of its
  own, waiting at most 2 s. `eggdb_gui::clipboard::SystemClipboard` implements D275's
  `Clipboard` trait over the window and keeps the last copy in memory when the platform refuses.
- **Hit testing is the accessibility tree.** A click reaches the last node in reading order
  whose bounds hold it and that offers an action (`pointer::hit_test`), so the pointer, the
  keyboard and screen readers share one map of the screen and cannot drift apart. A press then
  goes through `Workspace::access` (D278): inputs and the editor take the focus and the caret at
  the click (the nearest character boundary of the drawn face), grid cells become the current
  cell (`Shift` keeps the anchor), tree rows are selected and a double-click opens them;
  buttons, links, checkboxes, combo boxes and tabs act on release only when the release is on
  the same node, so a release outside cancels. A drag extends the input's, the editor's or the
  grid's selection; a double-click selects the word, a triple-click the line (the whole value in
  an input; a password selects whole). Multi-clicks are counted by the GUI (500 ms, 4 px) so
  every platform behaves the same.
- **Looks.** `PointerLook` (hovered, pressed, focus moved by the pointer) lives on the
  `ConnectCard` and the `MainWindow`: hover fills `bg2` (`accentHover` on the default button),
  pressed fills `bg2` with a `borderStrong` edge (`accentPressed`); a focus moved by a click
  draws no ring on buttons, links, checkboxes and the dialect pill, and inputs keep theirs. The
  next key brings the ring back.
- **Caret.** Solid for 500 ms after a key or click, then 530 ms on and 530 ms off
  (`pointer::caret_look`); solid under reduced motion; solid `textDisabled` while the window is
  inactive (`WindowEvent::Focused`). Only a window started with `Workspace::start_caret_blink`
  blinks, so offscreen frames and tests are unchanged; the event loop wakes when the blink turns
  (`Workspace::until_caret_changes`).
- **Clipboard keys.** `Ctrl/Cmd+C` copies the editor's selection (`Copied 12 characters`) and an
  input's selection (never the password), `Ctrl/Cmd+X` cuts in the editor, `Ctrl/Cmd+V` pastes
  into the editor (one undo step, `\r\n` and `\r` become `\n`) and into the card's inputs (made
  one line); a paste over 1 MB is refused with `Paste too large (limit 1 MB); open the file
  instead`. The browser card's host gets action codes 7 (stop opening), 8 (copy) and 9
  (paste), named in `web/card.js`'s `ACTIONS`; for 8 and 9 it lets the browser's own `copy` and
  `paste` events through and answers them on the system clipboard with
  `eggdb_wasm_card_copied_text` and `eggdb_wasm_card_paste` (the same 1 MB limit).
- **Wheel and resize.** The wheel scrolls the grid by 3 rows a notch and `Shift`+wheel by 3 whole
  columns, keeping the current cell and selection (`ResultGrid::scroll_by`), and the object tree
  by 3 rows. Every size event relayouts the main window at the new width (the inspector docks
  from 1440 as before) with the grid's first row and current cell unchanged; a size below the
  800 × 560 minimum that a window manager allows anyway is laid out at the minimum
  (`pointer::clamp_to_minimum`).

Not yet: the 800 px sidebar rail, the inspector closing under 1024 and the splitters' tree of
sizes (the main window still lays out at 1280 wide or more and 800 tall); fades of 80 ms (fills
change at once); reading the system's reduced-motion setting (`Workspace::set_reduced_motion`
exists, nothing calls it yet); the browser build's pointer and clipboard (the card's host has
the action codes; `web/card.js` does not send pointer events or use the async clipboard API
yet); the X11 `INCR` protocol for clipboard text larger than one request in either direction;
hover on tree rows, grid rows and plan nodes, the column-resize band, right-click menus,
double-click on a cell for the full value, on the tab strip and on splitters; clicks on the
result-view segments, the dialect menu's items and the editor's horizontal scroll; the caret
drawn only in the focused editor (it still draws while the tree has the focus); click placement
in the sidebar filter.

**Extended by D311 (2026-11-03).** The rail, the inspector closing by width and the splitters with
their kept sizes are built (the main window lays out from 800 px wide); hover and pressed fills fade
over 80 ms; the system's reduced-motion setting is read on macOS, Windows and X11 at start and when
the window gains the focus (`Window::reduced_motion`), and `--reduced-motion` forces it; a
right-click opens the grid's (D310) and the tree's (D311) menus, and a double-click on a splitter
resets it. What is left of the list above is in the roadmap's M6e line.

**Extended by D313 (2026-11-03).** The browser card answers the pointer (`web/card.js` sends
pointer events to `browser::CardPointer`) and falls back to the async clipboard API, and X11 moves
clipboard text larger than one request with `INCR` in both directions.
