## D1029 Jepsen-style checks against real processes — Decided by the code-only session (2026-11-13, D355); roadmap M14 (D9, D209, D1024, D1026)

- `eggdb-jepsen` (a workspace tool, never shipped) starts three real `eggdb serve` processes as one replication group:
  a primary and two replicas, every one with a replication listener, peers, automatic failover after 3 seconds and
  one synchronous acknowledgement per commit (D1024, D1026). Four clients add unique elements to one RESP set, each
  writing to whichever server takes writes and recording each element as acknowledged, refused, or unknown (the
  connection failed mid-call). A nemesis, seeded, every four seconds kills a server with `SIGKILL` and restarts it
  five seconds later as a replica of whichever server then takes writes, or pauses one with `SIGSTOP` for five
  seconds, or leaves the group alone.
- After the workload the tool heals the group (continues every paused process, restarts every stopped one, waits 15
  seconds) and checks, as Jepsen's set test does: every acknowledged element is in the final primary's set (no lost
  writes), every element there was acknowledged or unknown (nothing invented), and every replica holds exactly the
  primary's set (convergence). It prints the history's counts, the nemesis's actions and every violation, and exits
  with status 1 on one.
- With `--partitions 1` the nemesis also cuts a server's replication listener off for eight seconds with an
  `iptables` rule on the loopback interface (through `sudo -n`, as GitHub's runners allow), so its peers and, for a
  primary, its replicas lose it while it keeps running and taking writes: the case the primary's majority lease
  (D1026) exists for. The rule is removed afterwards however many copies were added.
- `.github/workflows/jepsen.yml` runs three seeds with partitions every Saturday and on demand, with the results in
  the summary and as an artifact.
