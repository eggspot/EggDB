## D930 Key-value transactions and collections in the Python driver — Decided by the code-only session (2026-11-13, D355); roadmap M4, collections in the drivers (D292)

- `eggdb.open_key_value(path, read_only=False)` opens an embedded file's key-value store on the C API. `read()` and
  `write()` begin transactions; as context managers a write commits when its block ends normally and rolls back on
  an exception, and a read just ends.
- A `Transaction` has `get`, `put` (with `ttl_ms` for a time to live), `delete`, `scan` (a range, a `prefix`,
  `reverse`, `end_inclusive`, read in the C API's batches as a generator), `create_collection`, `drop_collection`,
  `rename_collection`, `collections()` and `collection_stats(name)`; every key call takes `collection=`, the default
  key space when it is `None`. Keys and values are `bytes`, or `str` encoded as UTF-8; values come back as `bytes`.
- Buffers the C API hands out are freed with `eggdb_free` as soon as they are copied, and a scan handle is freed when
  its generator ends or is closed.
- The other drivers follow the same shape in their own idioms.
