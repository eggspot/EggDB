## D1210 An ActiveRecord adapter for the Ruby driver — Decided by the code-only session (2026-11-17, D355); roadmap M6f, ActiveRecord and Sequel for Ruby (D16, D182)

- **What users get.** `adapter: eggdb` in `database.yml` (`drivers/ruby/lib/active_record/connection_adapters/eggdb_adapter.rb`, registered with `ActiveRecord::ConnectionAdapters.register` on Rails 7.2 and later): Rails models, migrations and queries on an embedded EggDB file through the Ruby driver, beside D958's Sequel adapter.
- **How.** A subclass of Rails' own SQLite3 adapter, since the driver opens EggDB in its SQLite dialect: Rails' SQLite quoting, schema statements, type map and migrations apply unchanged, and the adapter replaces only the connection (`EggDB::Database` in place of `SQLite3::Database`), the query path of Rails 7.2's adapter contract (`perform_query`, `cast_result`, `affected_rows` from the command tag, `last_inserted_id` from `last_insert_rowid()`), the connection's setup (`PRAGMA foreign_keys = ON`) and the reported SQLite version. Driver errors map by SQLSTATE onto `RecordNotUnique`, `InvalidForeignKey`, `NotNullViolation` and `StatementInvalid`. A thin Ruby layer with no protocol or storage logic (D16).
- **Left.** Rails 7.1 and earlier (a different adapter contract), prepared statements across calls, and Rails' adapter test suite.
- **Proof.** `drivers/ruby/test/active_record_test.rb` defines a table through a schema migration and creates, finds, updates and destroys models; it skips without the `activerecord` gem (a test-only dependency, D1).

**Status:** code written, unbuilt (code-only mode, D355).
