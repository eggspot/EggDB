## D534 Cypher list predicates, and path predicates pushed into shortest-path searches — Decided by the code-only session (2026-11-11, D355); roadmap M13

- **List predicates:** `all(x IN list WHERE p)`, `any(...)`, `none(...)` and `single(...)` are
  now Cypher expressions (they were parsed as unknown functions). Their nulls follow openCypher:
  `all` is false when one element fails, else null when one is null, else true; `any` is true
  when one holds, else null when one is null, else false; `none` is `any`'s negation; `single` is
  false when two hold, else null when one is null, else whether exactly one holds. A null list
  gives null.
- **Push-down:** in `MATCH ... p = shortestPath(...) WHERE ...`, each top-level conjunct of the
  `WHERE` shaped `all(r IN relationships(p) WHERE ...)`, `all(n IN nodes(p) WHERE ...)` or
  `all(r IN rels WHERE ...)` (over the pattern's relationship list variable) whose condition reads
  only its own variable, parameters and variables bound before the pattern is checked during the
  breadth-first search: a step whose relationship or next node fails it is not followed, and a
  start node that fails a node condition is not searched from. So the search returns the
  shortest path that meets the condition, as Neo4j's planner does, instead of finding the
  shortest path and then filtering it away. The `WHERE` still runs afterwards, so nothing it
  says is lost. `allShortestPaths` is steered the same way.
- **Left out:** pushing `none`, `any` or conditions over several path variables, and pushing
  into variable-length patterns that are not shortest paths.
