## D442 CRDT counters and sets as resolution policies — Decided by the code-only session (2026-11-11, D355); roadmap M18, extends D225

- `eggdb_cluster::crdt` adds two conflict-free replicated data types, from Shapiro, Preguiça,
  Baquero and Zawirski's definitions: a **PN-counter** (each node's increments and decrements kept
  apart, merged by per-node maximum, its value the difference of the sums) and an **observed-remove
  set** (each element with the unique tags of its additions and the tags its removals saw, so a
  removal takes away only the additions it observed and a concurrent addition survives). Both
  encode to bytes and decode only what they wrote.
- `quorum::Resolution` gains `Crdt(CrdtKind)`: when a replica holds concurrent versions of a key,
  their values are joined by the type's merge into one version whose vector is the merge of
  theirs and whose stamp is the latest, instead of picking one (last writer wins) or keeping
  siblings. A deletion or a value that doesn't decode counts as the empty state, so a concurrent
  write is never lost to it. The merge is commutative, associative and idempotent, so D225's
  convergence check holds for the new policy too.
- Left: the policies chosen per table for multi-primary SQL rows, more types (registers, maps,
  sequences), and the network wiring of D225's quorums.
