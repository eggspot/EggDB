## D707 read_vcf, and gzip for the text file readers — Decided by the code-only session (2026-11-12, D355); roadmap M11, genomics: VCF, BAM, CRAM and htsget (D57)

- `read_vcf(path)` (PostgreSQL dialect) reads a VCF file through the session's file reader (D703) into one row per
  variant line, with fixed columns: `chrom`, `pos` (`bigint`), `id`, `ref`, `alt`, `qual` (`double precision`),
  `filter`, `info` (`jsonb`), `format` and `samples` (`jsonb`). `.` is `NULL`; `info` is an object of the `INFO`
  entries with flags as `true`; `samples` is `{sample: {key: value}}` by the `#CHROM` line's sample names and each
  line's `FORMAT` keys. Values stay text inside the JSON; the header's `##INFO` and `##FORMAT` types are not applied.
  As with the other readers, a definition list may pick or retype columns (D706).
- `read_vcf` and `read_csv` read gzip files, BGZF (the blocked gzip of `.vcf.gz`) included, with `eggdb-content`'s
  `gunzip`, recognised by gzip's magic bytes.
- The readers' module is renamed `file_readers` (it held only Parquet when named `parquet_files`).
