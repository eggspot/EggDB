## D427 SQL Server's ranking and offset window functions — Decided by the code-only session (2026-11-11, D355); roadmap M10

- The Transact-SQL dialect parses its functions itself, and until now only aggregates took
  `OVER` there. `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`, `NTILE(n)`, `PERCENT_RANK()`,
  `CUME_DIST()`, `LAG(value [, offset [, default]])`, `LEAD(...)`, `FIRST_VALUE(value)` and
  `LAST_VALUE(value)` now go to the window functions every dialect shares (`window.rs`), so their
  results, partitions, frames and `ORDER BY` follow the same code as PostgreSQL's.
- SQL Server's errors come first: a call without `OVER` is error 10753 ("The function 'RANK'
  must have an OVER clause."), and an `OVER` without `ORDER BY` is error 4112 ("The function
  'RANK' must have an OVER clause with ORDER BY."), both severity 15 and ending the statement. The
  `ORDER BY` is found by looking ahead inside the `OVER (...)` parentheses, so a named window
  (`OVER w`), which Transact-SQL has since SQL Server 2022, is read as lacking one: a known
  difference. A wrong argument count is SQL Server's argument-count error.
- `NTH_VALUE` stays outside the dialect (SQL Server has none); `IGNORE NULLS` on `FIRST_VALUE`,
  `LAST_VALUE`, `LAG` and `LEAD` (SQL Server 2022) is left.
