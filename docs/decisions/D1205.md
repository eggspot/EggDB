## D1205 A dbt adapter of our own: `dbt-eggdb` — Decided by the code-only session (2026-11-17, D355); roadmap M6f, a dbt adapter (D46, D239)

- **What users get.** `pip install dbt-eggdb` and `type: eggdb` in `profiles.yml` (`connectors/dbt-eggdb`): dbt projects run on `eggdb serve` with EggDB's own adapter, which adds a `dialect` per profile (`postgresql`, `mysql`, `sqlserver`, `oracle`, `sqlite`; set as `eggdb.dialect` when a connection opens), so a project migrated from another database keeps its models' SQL.
- **How.** A plugin in dbt's own adapter system (D16's rule: a tool's plugin is written in the tool's language) built on `dbt-postgres`, since EggDB speaks the PostgreSQL protocol: the credentials, connection manager and adapter subclass PostgreSQL's, and `dependencies=["postgres"]` lets every macro fall back to `postgres__` ones. EggDB's own macros list relations from `information_schema` (EggDB's `pg_class` and `pg_namespace` answer, but the standard views are the contract D12 keeps), and the timestamp is `now()`. The package depends on `dbt-core` and `dbt-postgres` from dbt's ecosystem; nothing of it ships inside `eggdb`.
- **Left.** Publishing to PyPI (an account, the owner's), the compatibility job running `dbt-eggdb` beside `dbt-postgres`, the embedded mode through the Python driver, and dbt's adapter test suite (`dbt-tests-adapter`).

**Status:** code written, unbuilt (code-only mode, D355).
