## D294 `USE` refuses to leave a temporary table or a session lock behind, and `sqlite_schema` keeps SQLite's text across `ADD COLUMN` and `RENAME TO` and for indexes, views and triggers — Decided by the build loop (EggAgentCode task 20261103-0137, 2026-11-03); follows D270 and D273, applies D9, D10 and D20

Two follow-ups that D270 and D273 left.

**What a switch would leave behind (D270).** A `USE` (MySQL and T-SQL) or `COM_INIT_DB` moves
a connection to another served database by closing its session and building a new one there.
Anything that lives only in the session went with it without a word: `#temp` tables and
`CREATE TEMPORARY TABLE` tables were dropped, and session-level locks (`pg_advisory_lock`,
`sp_getapplock` with `@LockOwner = 'Session'`) were released while the application still
believed it held them. SQL Server and MySQL keep both across a `USE`; carrying them would mean
a session that spans two stores, which D270 ruled out.

- **Decision.** While the session holds a temporary table or view, or a session-level lock, the
  switch is refused before anything moves, and the message names what is held (up to eight
  items, then "and N more"): `cannot switch to database "audit" while this session holds
  temporary table #work and application lock 'nightly'`. The hint says to drop and release them
  first or to open another connection to the target.
- **Compatibility gap.** This differs from the originals: SQL Server and MySQL keep `#temp`
  tables, `CREATE TEMPORARY TABLE` tables and session-level locks across a `USE` (a temporary
  table stays usable, under its own database, after the connection moves), so an application
  that creates a temporary table and then runs `USE` works there and gets the refusal on EggDB.
  It must drop the table and release the lock before the `USE`, or open a second connection
  to the other database. The refusal is chosen over silently dropping them, which would lose
  the application's data and locks without an error.
- **Numbers.** `0A000` everywhere. SQL Server clients get error `40508`, the number SQL Server's
  cloud edition uses for a `USE` it does not run ("use a new connection"), so drivers and tools
  that already handle it open a new connection. MySQL clients get `1235` (`ER_NOT_SUPPORTED_YET`).
- **Where.** `Session::use_database` (the `USE` statement, so the rest of the batch runs on the
  current database) and `Session::switch_to` (also reached by `COM_INIT_DB` and by the TDS
  server), in `crates/eggdb-sql/src/session/database_switch.rs`. The temporary relations come
  from `TemporaryObjects::relations`, the locks from `AdvisoryLocks::session_lock_names`;
  transaction-level locks need no check, since a switch inside a transaction is already `25001`.

**SQLite's text (D273).** SQLite keeps the text of every `CREATE TABLE`, `CREATE INDEX`,
`CREATE VIEW` and `CREATE TRIGGER` in `sqlite_schema.sql`, normalized as its file-format
document describes (the first keywords as `CREATE TABLE ` and so on, `IF NOT EXISTS` and a
schema before the name left out), and its `ALTER TABLE` edits that text rather than writing a
new one.

- **Indexes and views.** A `CREATE [UNIQUE] INDEX` or `CREATE VIEW` in SQLite's dialect that
  makes a new, non-temporary object saves its text in key space `0x15` with D273's record
  layout (version 1, the generated text's length, the generated text, the original). A view's
  key is the view's internal name, like a table's (a view and a table never share a name). An
  index's key is its table's internal name, the byte `0xFF`, `i` and the index's name: `0xFF`
  never occurs in UTF-8, so the key never meets a table's (internal names of other schemas
  contain `0x00`, so `0x00` could not be the separator). The index's key belongs to its table
  for `eggdb mcp --tables` (`owning_relation`).
- **Triggers** already keep their text in their own definition; `sqlite_schema` now shows a
  SQLite trigger's text with `IF NOT EXISTS` and a schema before its name left out.
- **Views are listed** in `sqlite_schema` (they were missing): type `view`, `tbl_name` the view,
  `rootpage` 0, after the tables and their indexes and before the triggers.
- **`ALTER TABLE`.** Before the change, the table's kept text and its indexes' are read (only
  where they still match the generated text) and removed. After it, when every action is
  `ADD COLUMN` or `RENAME TO`, they are saved again, edited: `ADD COLUMN` inserts `, ` and the
  column definition as written after the last column definition, before any table constraint
  (as SQLite appends the column to the column list); `RENAME TO` replaces the table's name in
  its text and the name after `ON` in each index's text with the new name in double quotes (as
  SQLite writes it). The edit works on tokens of the kept text; text it cannot read is left
  out and the generated text is shown. Any other `ALTER TABLE` drops the kept texts, as before.
- **Dropping.** `DROP TABLE` deletes the table's and its indexes' records, `DROP INDEX` the
  index's, `DROP VIEW` and moving a view to another schema the view's.
- **Compatibility.** New entries in an existing space; no existing encoding changes. A file
  written before (no index or view records, or no records at all) shows the generated text, and
  its next `ADD COLUMN` or `RENAME TO` edits whatever text it kept. Older releases ignore the new
  keys (they read `0x15` only under a table's name) and treat an index record as unrelated, so
  they open such a file unchanged.

Tests: `session/database_switch.rs` (SQL Server's and MySQL's refusals and that the switch
goes through once they are dropped and released), `advisory_locks.rs` and `temporary.rs`
(listing), `crates/eggdb-tdswire/tests/databases.rs` (end to end over TDS),
`sqlite_schema_text.rs` (the text edits and the key layout) and `table_ddl_tests.rs` (texts
kept across `ADD COLUMN` and `RENAME TO`, indexes, views and triggers, and a catalog written
without the new records). No sample file in `crates/eggdb/tests/data` holds SQL tables, so the
compatibility test removes the new records from a catalog written in memory.

Not yet: carrying temporary tables and session locks across a `USE` instead of refusing it;
MySQL's `GET_LOCK` named locks (not implemented, so not listed); SQLite's text edits for
`RENAME COLUMN` and `DROP COLUMN`, and for a renamed table's references inside views and
triggers (these show the generated text, or the old text for views and triggers).
