## D657 Variables a MySQL stored function sets outside CALL — Decided by the code-only session (2026-11-12, D355); roadmap M10, D419

D419 recorded the user and system variables a routine body sets in a per-thread journal, but
applied the journal only after a `CALL`. A function called from a `SELECT` that counted its calls
in `@calls`, or set `@last_id` for the caller, lost the assignment, which was dropped at the next
`CALL`.

- After every MySQL statement, `after_statement` now applies the journal through the same
  `apply_routine_assignments` the `CALL` path uses. The values a function set while the statement
  ran therefore reach the session, as in MySQL, whose variables are not transactional.
- A `CALL` still applies its journal itself, before its `OUT` parameters, so nothing is applied
  twice.
- A system variable the session refuses becomes a warning on the statement, not a failure. The
  statement has already run, and MySQL would have failed the `SET` inside the function.
- A failing statement leaves its journal for the next statement to apply. MySQL keeps such
  variables too, though it shows them at once.
- Test: `a_function_called_from_a_select_leaves_the_user_variables_it_set`.
