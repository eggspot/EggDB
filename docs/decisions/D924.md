## D924 SPARQL `SERVICE` to allowed endpoints — Decided by the code-only session (2026-11-12, D355); roadmap M13, follow-up of D923

- A `SERVICE [SILENT] <endpoint> { pattern }` in a query now runs the pattern on the remote endpoint: the parser keeps
  the pattern's own text and sends `SELECT * WHERE { pattern }` with the query's `BASE` and every `PREFIX` before it,
  and the solutions that come back join the rest of the query like any other pattern. `SILENT` turns a failure into
  one solution that binds nothing, as the recommendation says.
- As for `LOAD` (D923), the engine never connects by itself: `eggdb_rdf::set_remote_query` installs what runs the
  query, and without it `SERVICE` is refused. The `eggdb` program installs one only when `EGGDB_SPARQL_SERVICE` lists
  endpoint URL prefixes; it sends the SPARQL protocol's `GET ?query=...` over `http://` or `https://` (D920), asks for
  SPARQL 1.1 Query Results TSV, reads at most 256 MiB within 30 s, and refuses an endpoint outside the list.
- The TSV cells are read as Turtle terms (IRIs, literals with language or datatype, the numeric and boolean short
  forms), an empty cell is an unbound variable, blank nodes are renamed apart from local ones, and at most 1,000,000
  rows are taken.
