## D233 Unicode text from Unicode's own data, by our own generator — Decided by the build loop (by judgement, 2026-10-31); refines D1, D30 and D6

Track 4.X-5 asks for Unicode collation (UCA, from Unicode's public data), locale-aware ordering,
case folding and normalization in every dialect, checked by Unicode's conformance tests.

- **Data, not code, from Unicode.** `scripts/unicode/generate.py` reads `UnicodeData.txt`,
  `CompositionExclusions.txt` and `CaseFolding.txt` of Unicode 16.0.0 (the Unicode Character
  Database, under Unicode's permissive data licence) and writes `crates/eggdb-text/src/tables.rs`
  as sorted arrays. The algorithms are ours, written from UAX #15 and the Unicode Standard's
  chapter 3. Hangul is computed rather than tabled. CI regenerates the tables from the published
  files and fails if the committed copy differs, so nobody edits them by hand.
- **`eggdb-text`** gives the four normalization forms, full case folding, and two comparisons,
  case-insensitive and accent- and case-insensitive (with `primary_key` for indexes). Both end in
  an exact tie-break, so only identical strings compare equal and an ordering never loses rows.
  The tables cost about 130 KB in the binary, which D6 accepts for text correctness in every
  dialect.
- **Checked by Unicode's own `NormalizationTest.txt`**: every listed line, all four forms, in CI.
- **SQL**: PostgreSQL's `normalize(text [, form])` and `is_normalized(text [, form])`, with the
  form as a string (`'NFKC'`). PostgreSQL's keyword spelling (`normalize(x, NFKC)`, `x IS NFC
  NORMALIZED`) needs parser support and comes next.

Left: the Unicode Collation Algorithm with the DUCET and CLDR tailorings per locale (`COLLATE
"de-DE"`, ICU-style names, MySQL's and SQL Server's collation names mapped onto it), collation
keys in indexes, locale-aware `upper`/`lower` (Turkish dotless i), the keyword forms above, and the
collation conformance test.
