## D945 Timed reaps and cancel on the file I/O queue, and batched io_uring submission — Decided by the code-only session (2026-11-13, D355); roadmap M1, follow-up of D72

- **The contract.** `IoQueue` gains `reap_timeout(completions, min, timeout)` and `cancel(user_data)`, worded as
  `NetQueue`'s: a timed reap returns what finished in time, possibly fewer than `min`, and running out of time is not
  an error; a canceled operation still comes back exactly once, with `ErrorKind::Canceled` when it was stopped before
  it ran (moving no bytes) or with its own result when it had already run or could not be stopped, and canceling a
  tag with nothing in flight answers `NotFound`. A file operation that reached the disk usually cannot be stopped, so
  callers must accept both answers.
- **`OsIoQueue`.** It counts the tags in flight, so `cancel` answers `NotFound` the same way on every backend, and keeps
  the operations it cancels itself to hand back at the next reap. Inline: canceled jobs never run. Thread pool: a
  shared set of canceled tags, checked by each worker before it runs a job (a job already running finishes); the tag
  leaves the set when its last operation is reaped, and `receive` waits with `recv_timeout` until the deadline.
  Completion port: inline jobs are dropped, worker jobs go through the pool's set, and operations in the port get
  `CancelIoEx`, completing with `ERROR_OPERATION_ABORTED`, now reported as `Canceled`; the reap waits on the port at
  most until the deadline.
- **io_uring.** A submit now only writes the entry to the submission ring; entries enter the kernel together at the
  next reap (a reap with `min` 0 submits them), or when the ring is full, so a batch of submits costs one
  `io_uring_enter` instead of one each. A timed reap arms an `IORING_OP_TIMEOUT` (kernel 5.4) tagged with a generation,
  waits for one completion at a time until enough arrived or it fired, and removes it with
  `IORING_OP_TIMEOUT_REMOVE`; stale timer and removal completions are recognised by their tag bits and ignored, so the
  5.6 floor (D72) stays and `IORING_ENTER_EXT_ARG` (5.11) is not needed. `cancel` pushes `IORING_OP_ASYNC_CANCEL`
  for each matching slot; `-ECANCELED` on a canceled slot becomes `Canceled`. Dropping the ring submits what is still
  waiting before it waits for it.
- **Simulation.** `SimIoQueue::reap_timeout` performs operations until `min` are done but runs out of time with one
  chance in four before each, drawn from the seed; `cancel` turns its pending operations into `Canceled` completions
  without performing them.
- **Checks.** Two contract tests run on every backend and on the simulation: a timed reap returns what finished and the
  rest arrive later, and a canceled read comes back once, canceled or with its bytes, beside an untouched write.
