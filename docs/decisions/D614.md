## D614 AMQP queue TTL (x-expires) — Decided by the code-only session (2026-11-12, D355); roadmap M16, D214, D516, D613

RabbitMQ deletes a queue declared with `x-expires` once it has been unused that long. RPC reply
queues, per-session queues and Celery's result queues rely on this to clean up after clients that
vanish. EggDB accepted the argument and kept such queues forever.

- `QueuePolicy` reads `x-expires` (milliseconds, more than 0).
- The broker keeps, per queue, how many consumers it has and when it was last used. A queue is
  used when:
  - it is declared or redeclared, passively too;
  - `basic.get` reads it;
  - a consumer starts or ends, so the timer starts again when the last consumer leaves.
- `delete_expired_queues` deletes every queue with `x-expires` that has no consumer and has gone
  unused for at least that long, through the same path as `queue.delete`: its messages, policy,
  usage and bindings.
  - It runs when a connection declares a queue, publishes, starts a consumer or calls `basic.get`.
  - There is no background timer, so a queue past its time is deleted at the next such command
    from any client. A queue no one asks about is not seen to be gone until then, which only
    differs in the memory held meanwhile.
- A unit test drives the broker directly: an idle queue survives before its time and is deleted
  after it, and a queue with a consumer survives.
