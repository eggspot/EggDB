## D1307 PostgreSQL's current_query() — Decided by the code-only session (2026-11-24, D355); roadmap M4 functions (D10)

- **What users get.** `current_query()` answers the text the client sent for the request now running, the whole string when it holds several statements, as PostgreSQL does; a SQL function or procedure that calls it sees the client's text, not its own body. Monitoring scripts and audit triggers that log `current_query()` work unchanged.
- **How.** The session keeps the outermost text it runs in a per-thread buffer, reused from one request to the next (no allocation once it is large enough, and a buffer above 64 KiB is let go when the request ends); statements run inside it leave the buffer alone. The function answers from the administration functions (D1301).
- **Left.** Nothing of its own.
- **Proof.** A unit test keeps the outer text while an inner one runs and answers nothing outside a request; an SQL test answers a two-statement text and the client's text from inside a SQL function.

**Status:** code written, unbuilt (code-only mode, D355).
