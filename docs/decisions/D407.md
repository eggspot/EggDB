## D407 MongoDB's `$out` and `$merge` — Decided by the code-only session (2026-11-10, D355); roadmap M9

- `split_output` takes a final `$out` or `$merge` off the pipeline; either one anywhere else is
  MongoDB's error 40601, and both stay refused inside `$facet` and `$lookup` sub-pipelines. The
  aggregate command runs the rest, writes the results and returns an empty first batch.
- **`$out`** (a collection name, or `{db, coll}`) replaces the target's documents with the results
  in one write transaction (`Store::replace_documents`), keeping the collection and its index
  definitions as MongoDB does; results without an `_id` get a new object id, and two results with
  the same `_id` fail the whole stage with a duplicate key error, leaving the target as it was.
  Writing to a `system.` collection is refused.
- **`$merge`** (`into` as a name or `{db, coll}`) merges by `_id` in one write transaction
  (`Store::merge_documents`). `on` may only name `_id`: other fields need a unique index, which
  EggDB doesn't enforce yet besides `_id`, so they fail with MongoDB's error 51183, "Cannot find
  index to verify that join fields will be unique". `whenMatched` is `merge` (the default; sets the
  result's top-level fields), `replace`, `keepExisting`, `fail` (a duplicate key error) or an
  update pipeline whose `let` variables (by default `new: "$$ROOT"`) are bound to the result's
  values as `$lookup`'s are (D406); `let` with any other mode is error 51199. `whenNotMatched` is
  `insert` (the default), `discard` or `fail` (error 13113). A null, undefined or array `_id` is
  error 51132; an update that changes `_id` is `ImmutableField`. Unlike MongoDB, which writes in
  batches and may leave earlier batches written when a later one fails, a failure leaves the
  target unchanged.
