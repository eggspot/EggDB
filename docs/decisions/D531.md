## D531 PostgreSQL `EXPLAIN (FORMAT JSON | YAML)` — Decided by the code-only session (2026-11-11, D355); roadmap M6c

`EXPLAIN (FORMAT JSON)` and `EXPLAIN (FORMAT YAML)` in the PostgreSQL dialect now answer, where
only `FORMAT TEXT` did; tools such as pgAdmin's graphical explain, DBeaver and explain
visualizers ask for JSON.

- **One plan, three writings:** the JSON and YAML plans are built from the same text plan
  (`postgresql_lines`, D286 and D327), read back into a tree: each node's `Node Type`, `Relation
  Name`, `Alias` and `Index Name` from its line, its `Filter`, `Index Cond`, `Sort Key` and other
  `Key: value` lines as fields, `SubPlan n` and `InitPlan n` labels as the children's `Parent
  Relationship` and `Subplan Name`, and other children `Outer`, `Inner` or `Member` by position,
  under `Plans`. So the three formats never disagree about the plan.
- **Shape:** JSON is one row of type `json`, `[{"Plan": {...}}]`; YAML one text row starting
  `- Plan:`, with PostgreSQL's key names and double-quoted values.
- **Left out:** `XML`, `ANALYZE` in JSON or YAML (refused: the measured fields are written for
  text only), and the cost, row and width estimates PostgreSQL adds to each node (EggDB's text
  plans do not show costs yet).

**Status:** code written, unbuilt (code-only mode, D355).
