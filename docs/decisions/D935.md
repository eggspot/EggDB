## D935 Key-value transactions and collections in the Ruby driver — Decided by the code-only session (2026-11-13, D355); roadmap M4, collections in the drivers (D292), follow-up of D930 to D934

- `drivers/ruby/lib/eggdb.rb` gains `EggDB::KeyValue` (`open(path, read_only:)`, with a block that closes the store)
  and `EggDB::Transaction`, over the C API through Fiddle like the SQL calls.
- `read { |txn| }` rolls back when the block ends; `write { |txn| }` commits when the block returns and rolls back when
  it raises, returning the block's value, as Sequel's and ActiveRecord's `transaction` blocks do.
- A transaction has `get`, `put(ttl_ms:)`, `delete`, `scan(start:, end_key:, prefix:, reverse:, end_inclusive:)`
  (yielding key and value, or an enumerator without a block), `create_collection`, `drop_collection`,
  `rename_collection`, `collections` and `collection_stats`; `collection:` is a keyword, `nil` for the default key
  space. Keys and values are binary strings; buffers from the C API are copied and freed at once.
