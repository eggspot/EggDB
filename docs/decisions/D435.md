## D435 TimescaleDB's `first(value, time)` and `last(value, time)` — Decided by the code-only session (2026-11-11, D355); roadmap M11

- In the PostgreSQL dialect, a two-argument `first` or `last` call without `OVER` or `FILTER` is
  TimescaleDB's aggregate: the value of the row with the earliest (or latest) time in the group.
  It is built on the evaluator Oracle's `KEEP (DENSE_RANK FIRST | LAST ORDER BY ...)` already uses
  (`oracle_keep`): the values and the times are gathered with `array_agg(... ORDER BY time)`, and
  the rows of the first or last rank are kept. Rows whose time is `NULL` sort after the others for
  `first` and before them for `last`, so they are picked only when no row has a time.
- Among rows that share the earliest (latest) time, `first` gives the smallest value and `last`
  the largest, where TimescaleDB gives whichever it met first: a known difference that only ties
  show. Values must be comparable (the pick uses `min`/`max`).
- A user function named `first` or `last` taking two arguments is shadowed in queries, as
  TimescaleDB's would be once installed; the result's type is not known before the rows are, so
  the PostgreSQL protocol describes it as text. Gap filling (`time_bucket_gapfill`, `locf`,
  `interpolate`) and automatic hypertables are left.
