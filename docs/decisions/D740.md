## D740 `CREATE EXTENSION eggdb_ai`: a semantic cache and agent memory — Decided by the code-only session (2026-11-12, D355); roadmap M12, a semantic cache and agent memory (D31, D205)

- `CREATE EXTENSION eggdb_ai` installs, in SQL and PL/pgSQL on the vector functions D205 built, two ordinary tables
  in the `eggdb_ai` schema and functions over them:
  - a semantic cache: `cache_put(namespace, prompt, answer [, embedding, ttl])` keeps an answer;
    `cache_get(namespace, prompt [, embedding, max_distance])` returns the closest unexpired answer of the
    namespace whose embedding is within `max_distance` (cosine distance, 0.1 by default), counting the hit;
    `cache_evict([namespace])` removes expired entries;
  - agent memory: `remember(agent, content [, embedding, metadata])`, `recall(agent, query [, k, embedding])`
    returning the `k` best memories by reciprocal rank fusion of embedding distance and English full-text rank
    (`rrf_score`), and `forget(agent, id)`.
- Embeddings are vector text; when none is given, `eggdb_embed` (the local hashed embedding, D205) makes one, so it
  works with no model and nothing leaves the server. Applications with their own model pass its embeddings.
- Lookups read every entry of the namespace or agent (exact search), as SQL has no vector index yet. Offering memory
  as MCP tools is still left.
