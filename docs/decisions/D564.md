## D564 `flattened` fields and the `sparse_vector` query — Decided by the code-only session (2026-11-11, D355); roadmap M8, D196, D559

- **`flattened`.** A field mapped `flattened` keeps a whole object as keywords. `term` and
  `terms` on the field itself now match any leaf value in it, at any depth up to 20 levels
  (`{"term": {"labels": "db"}}` finds `{"labels": {"team": {"name": "db"}}}`), comparing numbers
  and booleans by their text as Elasticsearch's keywords do; `labels.team.name` already read
  that one leaf.
- **`sparse_vector`.** ELSER-style retrieval stores token weights in a `sparse_vector` field. The
  `sparse_vector` query (`{"field", "query_vector": {"token": weight}}`) and the older
  `text_expansion` (`{"<field>": {"tokens": {...}}}`, or `query_vector`) score a document by the sum
  of each query token's weight times the document's weight for it, and match documents that share
  at least one token. A `model_id` with `model_text`, which needs an inference model, is refused
  with a message that names it.
