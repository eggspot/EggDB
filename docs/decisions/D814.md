## D814 SQLite's `.scanstats` in the shell — Decided by the code-only session (2026-11-12, D355); roadmap M6c, D327

- `Session::set_scan_stats(true)` makes each `SELECT` in the SQLite dialect run under the step timer that
  `EXPLAIN ANALYZE` uses (D327) and adds a second result after its rows: the `EXPLAIN QUERY PLAN` table
  (`id|parent|notused|detail`) with `(loops=1 rows=n)` after each scan the executor measured, n being the rows read
  from that table. The statement runs once; the plan is made before it from the same statement.
- `eggdb sql`'s shell has `.scanstats on|off` (and completion and help for it); turning it on in another dialect
  says it applies to SQLite's.
- SQLite's own output is a tree (`QUERY PLAN` / `` `--SCAN t (loops=1 rows=3) ``); EggDB prints the same facts in the
  table form its `EXPLAIN QUERY PLAN` already uses. Joins report rows for the first source only, as `EXPLAIN ANALYZE`
  measures them.
