## D806 Zarr sharding and Blosc chunks — Decided by the code-only session (2026-11-12, D355); roadmap D57, arrays

- `read_zarr` reads Zarr v3's `sharding_indexed` codec: the chunk grid names the shard shape, the codec's `chunk_shape`
  the inner chunks, which must divide the shard. The index (16 bytes per inner chunk, offset then length, little-endian;
  both all-ones for an empty inner chunk) is read from the end or, with `index_location: "start"`, the start, and its
  CRC-32C is checked when `index_codecs` names `crc32c`. Empty inner chunks and absent shards read as the fill value.
  The last shard read is held, so inner chunks of one shard read its file once. Nested sharding is refused.
- Blosc 1 chunks (the v2 `blosc` compressor and the v3 `blosc` codec) are decoded from their self-describing header:
  stored (memcpyed) chunks, block starts, split streams (when the don't-split flag is clear, the block is not the
  leftover one, the type size is at most 16 and the block holds at least 128 elements), stored streams, byte shuffle,
  and the compressors BloscLZ (decoded here), LZ4 blocks (`eggdb_storage::decompress_lz4_block`, newly public),
  Snappy (`eggdb-columnar`), zlib (`eggdb-content`) and Zstandard. The decoded size is bounded by the chunk's size.
- Bitshuffle and Blosc2's extended header (both shuffle bits set) are refused with a clear error for now.
