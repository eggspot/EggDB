## D1289 PostgreSQL's mathematical functions — Decided by the code-only session (2026-11-18, D355); roadmap M4 PostgreSQL functions (D10, D19)

- **What users get.** In the PostgreSQL dialect (and the MySQL, Oracle and SQL Server dialects where the names match): `exp`, `ln`, `log(x)`, `log(b, x)`, `log10`, `power`/`pow`, `cbrt`, `degrees`, `radians`, `pi()`, `sign`, `mod`, `div`, `gcd`, `lcm`, `width_bucket`, `sin`, `cos`, `tan`, `cot`, `asin`, `acos`, `atan`, `atan2`, their degree forms (`sind` … `atan2d`, exact at whole angles as PostgreSQL makes them), `sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh`, `erf`, `erfc`, `gamma`, `lgamma` and `random()`, with PostgreSQL's errors: logarithms of zero and negatives (2201E), zero to a negative power and negatives to fractional powers (2201F), division by zero (22012), inputs out of range (22003), and `width_bucket`'s count and bounds (2201G). Only SQLite's dialect had these before (its own `sqlite_math` functions), so EggDB's own PL/pgSQL helpers that call `exp`, `ln`, `cos` and `pi()` (the privacy functions' noise and k-anonymity), and the trigonometric ODBC escapes (D1257), failed in the PostgreSQL dialect.
- **How.** One module, `math_functions.rs`, reached through the evaluator's function chain after the rounding functions, with result types in typing: `numeric` arguments give `numeric` results (computed in double precision, 17 significant digits), integer `mod`, `gcd` and `lcm` keep their integer type, and the rest are `double precision`. One-argument `log` is the natural logarithm in the MySQL and SQL Server dialects, and SQL Server's `LOG(x, base)` takes its base second. `erf` uses its Taylor series near zero and `erfc`'s continued fraction beyond 2.5; `gamma` and `lgamma` use Lanczos's approximation with reflection; `random()` draws 53 bits from the engine's random source.
- **Later the same night.** `setseed(x)` seeds `random()` with SplitMix64 on the session's thread, so a seeded sequence repeats (refusing seeds outside [-1, 1]); `factorial(n)` multiplies exact `numeric`s up to 1000.
- **Left.** Exact `numeric` precision for the transcendental functions, and `random_normal`.
- **Proof.** Unit tests in `math_functions.rs` check logarithms, powers and their errors, integer arithmetic, `width_bucket`'s documented example, exact degree results, `erf(1)`, `erfc(3)`, `gamma(5)` and `random()`'s range.
