## D1251 Oracle's ROWID in UPDATE and DELETE — Decided by the code-only session (2026-11-18, D355); roadmap M10, Oracle's `ROWID` (D1233)

- **What users get.** In the Oracle dialect, `UPDATE t SET ... WHERE ROWID = :r` and `DELETE FROM t WHERE ROWID = :r` change the row a query showed that `ROWID` for, as Oracle tools and ORMs do after reading a row (`ROWID` in `RETURNING` and in `SET` expressions works the same way).
- **How.** A query reads `ROWID` from the generated table (D1233), whose address for a table with a primary key is a hash of the key's stored bytes. A write evaluates its expressions against the row's columns only, so the write's name resolution rewrites `ROWID` into an internal function of the table's OID and its primary key's columns, which encodes the key as the store does and builds the same 18 characters. The PostgreSQL system-column rewrite of writes (D1170) is the same pass, now also run in the Oracle dialect.
- **Left.** Tables without a primary key, whose address is their hidden row number, which a write's row does not carry: `ROWID` there still answers that the column does not exist in a write. Keys of dynamically typed columns, which the store encodes differently.
- **Proof.** The Oracle `ROWID` test now renames a row and deletes it by the `ROWID` a query returned.

**Status:** code written, unbuilt (code-only mode, D355).
