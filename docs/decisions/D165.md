## D165 Sockets on io_uring and I/O completion ports, on request, beside the readiness backends — Decided by research (build loop, 2026-10-31); refines D67, D69, D70 and D74

Part 4.M1-2 adds two completion backends to the network queue. The research of 2026-10-31
("keep every part, add new engines behind switches instead of rewriting in place") sets the
shape: both are chosen only when a queue asks for them, and the automatic choice stays epoll,
kqueue or `poll(2)` until a benchmark on each system says otherwise.

- **`NetBackend::IoUring` (Linux).** Accepts, receives and sends are io_uring operations
  (`IORING_OP_ACCEPT`, `IORING_OP_RECV`, `IORING_OP_SEND` with `MSG_NOSIGNAL`); a connect starts
  without waiting, as in D71, and waits for its socket with `IORING_OP_POLL_ADD`. Submissions
  are queued in the ring and reach the kernel together, in the one `io_uring_enter` a reap makes
  to wait, so a batch of operations costs one system call. Timed reaps pass their timeout through
  `IORING_ENTER_EXT_ARG`. The ring needs `IORING_FEAT_NODROP`, `IORING_FEAT_FAST_POLL` and
  `IORING_FEAT_EXT_ARG` (Linux 5.11); a kernel without them, or one that disables io_uring,
  refuses the request. The file queue and the network queue share one ring core (`RawRing`).
- **Would-block answers are waited for in the ring.** A kernel that answers `EAGAIN` (a socket in
  non-blocking mode on some kernels) or `ECONNABORTED` for an accept gets a `POLL_ADD` on the
  socket and the operation again, so no backend retries in a loop in user space.
- **Cancel is a kernel cancel.** `cancel` submits `IORING_OP_ASYNC_CANCEL` for each tagged
  operation; the operation completes through a later reap with `Canceled`, or with its own result
  when it finished first, as the queue's contract allows. Ring keys carry a generation per slot,
  so a cancel that arrives late never hits a newer operation in the same slot. Dropping a queue
  cancels what is in flight and waits for it, as the file ring does.
- **`NetBackend::Iocp` (Windows).** Accepts, connects, receives and sends are overlapped
  `AcceptEx`, `ConnectEx`, `WSARecv` and `WSASend` calls on a completion port, with the extension
  functions looked up through `WSAIoctl`. Windows ties a socket to one completion port for life,
  so each listener and connection records the port it was tied to: another completion-port queue
  refuses it with `Unsupported`, while the portable and readiness backends still take it.
  `cancel` is `CancelIoEx` on the one operation.
- **Measured.** `eggdb-bench` gains `net.round_trip`: a one-byte round trip through the
  completion backend against the automatic backend on the same machine. Making a completion
  backend the automatic choice is a later decision, taken from these lines.
