## D842 Roles, grants, routines and triggers in the SQL dump — Decided by the code-only session (2026-11-12, D355); roadmap M14, D24

- `dump_sql` in the PostgreSQL dialect (`eggdb export --sql`, and so the start of `eggdb dump`) now writes the
  database's whole logical state in an order that restores: stored roles first (`CREATE ROLE ... LOGIN|NOLOGIN
  [SUPERUSER] [CREATEDB] [PASSWORD 'SCRAM-SHA-256$...']`, the verifier as stored, never a clear password) and their
  memberships, then sequences, tables, rows, indexes and constraints as before, then functions and procedures (their
  stored `CREATE` text), views, table grants (from `information_schema.role_table_grants`, to stored roles and
  `PUBLIC`), and last triggers, so loading the rows fires none.
- `DumpReport` counts roles, grants, routines and triggers. Routines and triggers of the other dialects are not
  written into a PostgreSQL dump.
- Left: `eggdb dump` as one command with collections and the other dialects' dumps, and object owners.
