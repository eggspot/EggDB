## D1282 ODBC static scrollable cursors — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1278, D1279)

- **What users get.** A statement with `SQL_ATTR_CURSOR_TYPE` set to `SQL_CURSOR_STATIC` (or `SQL_ATTR_CURSOR_SCROLLABLE` on), as grid views, report previews and Access's datasheets ask, scrolls with `SQLFetchScroll`: `SQL_FETCH_FIRST`, `SQL_FETCH_LAST`, `SQL_FETCH_PRIOR`, `SQL_FETCH_ABSOLUTE` (from the start, or from the end when negative) and `SQL_FETCH_RELATIVE`, a rowset at a time with block fetches (D1279). A position before the first row or past the last gives `SQL_NO_DATA`. Forward-only cursors keep refusing other directions with HY106; `SQLGetStmtAttr` answers the cursor type and scrollability set.
- **How.** The driver already holds a result's rows whole, so a static cursor only moves the next row to fetch to the rowset's start and fetches as `SQLFetch` does; the statement keeps the current rowset's start for `PRIOR` and `RELATIVE`.
- **Left.** Keyset-driven and dynamic cursors (rows changed by others are not seen), `SQL_FETCH_BOOKMARK`, `SQLSetPos`, and the warning ODBC gives when `PRIOR` meets the start partway.
- **Proof.** The ODBC test is refused scrolling a forward-only cursor, then scrolls a static one last, prior, first, relative, absolute from the end and absolute, and meets both ends.

**Status:** code written, unbuilt (code-only mode, D355).
