## D1002 Reading Apache Iceberg tables — Decided by the code-only session (2026-11-13, D355); roadmap M11, lakehouse tables (D29, D46)

- `eggdb import <file> --iceberg <location> --table <name>` loads the current snapshot of an Iceberg table into a SQL
  table, read from the Iceberg table specification with no third-party code: the metadata file (the one
  `metadata/version-hint.text` names, else the highest-numbered `*.metadata.json`, or a metadata file given directly),
  the current snapshot, its manifest list (format version 2) or manifests (version 1), each manifest's live entries,
  and their Parquet data files.
- Manifests and manifest lists are Avro files, read with the Avro reader of `eggdb import --avro` (D509); data files
  with the Parquet reader (D202). Data files are merged by column name, a column missing from a file reading as
  `NULL` there.
- Paths are local: `file://` URIs and plain paths are read; a path under the table location the metadata names is
  read under the location given, so a copied or moved table loads; object store URIs (`s3://`, `gs://`, `abfs://`)
  are refused, as the import reads the file system.
- Row-level deletes (version 2 position and equality delete files) are refused rather than ignored, so an import never
  shows deleted rows. Non-Parquet data files are refused.
