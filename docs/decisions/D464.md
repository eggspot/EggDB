## D464 Prometheus `query_range` results sent as a stream — Decided by the code-only session (2026-11-11, D355); roadmap M6a, extends D325

- `Endpoint::reply` answers `/api/v1/query_range` with a `StreamedResponse`: the range is
  evaluated as before (its samples are already held against the query's work budget), then each
  series' `{"metric":...,"values":[...]}` is rendered only when it is written, instead of the
  whole matrix being joined into one string first.
- Every other path, and `/api/v1/query` (one instant, small by nature), keeps the whole response;
  `Endpoint::answer` stays for tests and embedders. `eggdb serve` serves the observability
  listener through `serve_replies_with_limits`.
- Evaluating step by step while sending is not written: a later step can still fail the query
  (work budget, a range error), and Prometheus reports such failures as an error response, which
  cannot follow a body that has started.
