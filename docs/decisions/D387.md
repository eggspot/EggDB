## D387 `ALTER TABLE ... ADD COLUMN ... serial` in PostgreSQL — Decided by the code-only session (2026-11-10, D355); roadmap M5

`serial` in `CREATE TABLE` is EggDB's auto-increment column, which must sit in the primary key
(D337, D364), so adding one to an existing table was refused. PostgreSQL's `serial` is only an
integer column with `NOT NULL` and a default of `nextval` on a sequence it owns, and EggDB has
named sequences with no such limit, so `ADD COLUMN c serial` (and `smallserial`, `bigserial`) now
does what PostgreSQL does:

- creates the sequence `<table>_<column>_seq` in the table's schema (a number appended when the
  name is taken) with the column's type,
- adds the column as `NOT NULL DEFAULT nextval('<sequence>'::regclass)`, which numbers the
  existing rows through the existing `ADD COLUMN` path,
- marks the sequence `OWNED BY` the column, so dropping the column or table drops it and
  `pg_get_serial_sequence` finds it.

The parser now records `serial` on the column definition (`ColumnDefinition::serial`), since a
`serial` column and a default identity column looked the same after parsing. Adding an identity
column (`GENERATED ... AS IDENTITY`) or a `PRIMARY KEY` column stays refused.
