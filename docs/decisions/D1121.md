## D1121 The downgrade path, and upgrade, downgrade and mixed-version tests against the previous release — Decided by the code-only session (2026-11-13, D355); roadmap M2 (online upgrades with a tested downgrade path, D20, D35)

- **A downgrade is a copy.** An earlier release cannot open a file with features it does not know, and must not
  silently ignore them. The way back is the entry-by-entry copy that backups and compaction already make. A copy
  writes every value plain, so it never carries `COMPRESSED_VALUES` or `ZSTD_VALUES` unless it compresses (it does
  not), and it folds LSM tables into B-tree tables and drops `LSM_TABLES` (D1119). What is left is encryption,
  expiring keys and kept collection counts, which a release knows from 0.2, 0.2 and 0.4 on.
- **`eggdb backup <file> <copy> --for-release <major.minor>`** checks before copying that the copy will open in that
  release (`Database::check_copy_for_release`), from the table of what each release knows
  (`Features::incompatible_known_by`, `read_only_compatible_known_by`). Otherwise it refuses with an `Incompatible`
  error that names the missing features. `--clone` is refused with it, since a clone keeps the pages as they are.
- **CI's `release-compat` job** downloads the newest published release and runs `scripts/release-compat.sh`:
  - **upgrade:** a file written by the release is checked and read by this build;
  - **mixed versions:** both write the same file in turn and read each other's writes;
  - **downgrade:** this build writes a file with an LSM table and a plain table, copies it `--for-release` for the
    previous release, and that release checks it and reads every row.

  `check` waits for the job.
- **Online upgrades in a cluster** are the rolling restart D18 describes. Mixed versions of the replication and
  consensus protocols are tested when those protocols carry a version byte, which is left for M14 and M15's
  wire-format work.
- **Left:** copies for releases before 0.2, and a catalog record version table, so a copy can also refuse SQL catalog
  records newer than the target release knows (today the `release-compat` run is what would catch one).
