## D1102 Serverless: stop when idle, wake by socket activation, and a timed cold start — Decided by the code-only session (2026-11-13, D355); roadmap M18 (D18, D226, D1099)

- **Idle means no client connection.** `eggdb_platform::activity` counts connections open across the PostgreSQL, MySQL and SQL Server servers (a guard in each one's connection loop) and when the count last changed. `eggdb serve --idle-exit <seconds>` checks it each second. Background work (scheduled jobs, replication, metrics scrapes) does not count, or a server would never be idle. Commits and reads are not counted either: an open connection already keeps the server up, and a server with no connection has no queries.
- **Before stopping.** With `--restore-from s3://...`, the server archives its database into that bucket (the verified copy of D1100, in memory up to 1 GiB) and stops only when that succeeded. A failed archive keeps it running and says why. With `--page-store` (D1099) every commit is already in the bucket, so it just stops. Without either, `--idle-exit` is refused, because stopping would lose the data with the instance.
- **What wakes it, decided by research.** PostgreSQL clients speak TCP, and the HTTP-only wake-ups (Knative, Cloud Run, KEDA's HTTP add-on) cannot see them. Two mechanisms wake a TCP server on its first connection: systemd socket activation and Fly.io Machines' proxy (`auto_start_machines`). Both need nothing from EggDB beyond starting fast, except socket activation, which needs the server to take the listening socket it is given. So `serve` takes descriptor 3 when `LISTEN_PID` names it and `LISTEN_FDS` is at least 1 (`eggdb_platform::socket_activation`, one `unsafe` call with its proof). That socket follows the same rule as `--listen`: off this machine only with TLS.
- **Timed cold start.** `scripts/cold-start.sh` runs the whole loop on one machine against EggDB's own S3 endpoint. It times a server with an empty disk starting over a page store and answering a query on 20,000 rows, then a server restoring the newest archive with `--restore-from` and answering. It reports `cold_start_page_store_ms` and `cold_start_restore_ms` against first budgets of 3 seconds in `benchmarks/footprint.txt`, checked in the weekly pass (D354).
