## D1322 The documentation site, built by our own tool — Decided by the code-only session (2026-11-25, D355); roadmap M6e documentation site (D32)

- **What users get.** `cargo run -p eggdb-docsite -- docs site` writes EggDB's whole documentation as a static site: every Markdown page under `docs/` (the guides, the CLI and SQL references, the roadmap, every decision and the UX designs) becomes an HTML page at the same place, its `.md` links point at the `.html` pages, each page has a bar of the top-level pages and, when it has three sections or more, a table of contents, and `index.html` lists every page. The pages need no JavaScript, read well on a phone and follow the system's dark mode; pictures and other files are copied as they are. Any static host serves the output.
- **How.** `crates/eggdb-docsite` is a workspace tool with no dependencies and is never shipped. Its Markdown renderer is ours, written for the Markdown these documents use: ATX headings with ids, paragraphs, fenced code with its language, bullet and numbered lists with nesting and continuation lines, pipe tables (with `\|` and code spans holding `|`), block quotes, rules, and inline code, links, autolinks, strong and emphasis; everything else is escaped text.
- **Left.** Publishing the site from the release workflow, search, and the rest of CommonMark (reference links, HTML blocks, setext headings).
- **Proof.** Renderer tests cover headings and inline marks, escaped fenced code, nested lists, tables, quotes, rules and autolinks; a site test builds two pages in two directories and an image, and checks the rewritten links, the titles, the navigation's path from a subdirectory, the index and the copied file.
