## D548 The keys tab's prefix field moves its caret, and the editor's caret stays solid under its menu — Decided by the code-only session (2026-11-11, D355); roadmap M6e, issue #29, D329

Two of D329's leftovers, both as `docs/ux/workspace.md` already describes them.

- **The prefix field's caret** (10.10). The field kept no caret position: typing appended and
  `Backspace` dropped the last character. It now keeps `prefix_caret` (characters from the start):
  `Left` and `Right` move it one character (from a selected text, to the selection's start or end),
  `Home` and `End` to the ends, typing inserts at the caret, `Backspace` deletes before it and
  `Delete` after it, and the caret is drawn at its own place. Taking the focus, `Esc` and a value
  set through accessibility put it at the end. Edits still run the prefix 150 ms after the last
  key.
- **The editor's menu** (10.9). While the right-click menu is open the caret is drawn solid
  instead of blinking off, so the range every item acts on stays visible; the selection already
  kept its `selection` fill.
- **Left out:** `Tab` stops on `Back` and `Next 100`, which need focus states and rings of their
  own.

**Status:** code written, unbuilt (code-only mode, D355).
