## D837 PostgreSQL's MERGE — Decided by the code-only session (2026-11-12, D355); roadmap M5, sql.md

- The PostgreSQL dialect parses `MERGE INTO target [AS alias] USING source ON condition` with `WHEN MATCHED [AND
  ...] THEN UPDATE SET ... | DELETE | DO NOTHING`, `WHEN NOT MATCHED [BY TARGET] [AND ...] THEN INSERT [(columns)]
  VALUES (...) | DO NOTHING` and PostgreSQL 17's `WHEN NOT MATCHED BY SOURCE [AND ...] THEN UPDATE | DELETE | DO
  NOTHING`, into the same `MergeStatement` the SQL Server and Oracle dialects run (D303), so triggers, constraints
  and the executor are shared.
- Limits of that executor, refused as not supported yet: more than two clauses of one kind (or a second after one
  without a condition), more than one `INSERT` clause, a clause after a `DO NOTHING` of the same kind (a trailing
  `DO NOTHING` is simply dropped, since rows no clause takes are left alone), `INSERT DEFAULT VALUES`, `DEFAULT` in
  `VALUES`, and `RETURNING`.

**Status:** code written, unbuilt (code-only mode, D355).
