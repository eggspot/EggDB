## D1032 Invisible columns: SQL Server's HIDDEN period columns, MySQL's and Oracle's INVISIBLE — Decided by the code-only session (2026-11-13, D355); roadmap M14 (D28, D795)

- A column declared `GENERATED ALWAYS AS ROW START|END HIDDEN` (SQL Server's system-versioned tables), or
  `INVISIBLE` (MySQL 8 and Oracle 12c), is left out of `SELECT *` and out of the implicit column list of an `INSERT`
  without one, while naming it still reads and writes it, as in those databases.
- The parser accepts `INVISIBLE` and `VISIBLE` (it already skipped `HIDDEN`); the session finds the declared columns
  in a `CREATE TABLE` that ran and records them in `eggdb_internal.invisible_columns`, so the table definition's
  stored format does not change. Before a statement that could expand `*` or an implicit column list, the session
  loads them into a per-statement frame that star expansion and implicit insert columns consult beside the
  engine's own hidden columns; a database that has none is remembered as such per store, so other statements pay
  nothing.
- Left: `ALTER TABLE ... ALTER COLUMN ... SET INVISIBLE|VISIBLE` (MySQL) and `MODIFY (... INVISIBLE)` (Oracle), and
  dropping a table's entries when the table is dropped (a later table with the same name and column inherits them).
