## D966 The Dart package as a Flutter plugin, and the Swift package on an XCFramework — Decided by the code-only session (2026-11-13, D355); roadmap M6f, D16's mobile frameworks

- **Flutter.** `drivers/dart/flutter` is `eggdb_flutter`, a Flutter FFI plugin (`ffiPlugin: true` for Android, iOS and
  macOS) that depends on the `eggdb` package and bundles EggDB's library: Android loads `libeggdb_capi.so` from the
  plugin's `jniLibs`, built for arm64-v8a, armeabi-v7a and x86_64 by `scripts/android/jnilibs.sh` with the NDK's
  clang as each Rust target's linker; iOS and macOS vendor `EggDB.xcframework` from `scripts/apple/xcframework.sh`,
  static libraries linked into the app with `-all_load` so their symbols survive for `dart:ffi`. `openDatabase` and
  `openKeyValue` pick the right library per platform.
- **Dart.** The `eggdb` package accepts the library name `processLibrary` (`:process:`), which looks EggDB's symbols up
  in the running process, as a statically linked library on iOS needs.
- **Swift.** `Package.swift` uses `EGGDB_XCFRAMEWORK` (a path inside the package) as a binary target when it is set,
  for iOS apps, and the system library otherwise, as before; the package now states macOS 11 and iOS 13.
- No library is checked in: apps and CI build them with the scripts, since release binaries are published per
  release (D353).
