## D961 A Prisma driver adapter for the Node.js driver — Decided by the code-only session (2026-11-13, D355); roadmap M6f, the last of the Node.js ORM list

- `eggdb/prisma` exports `PrismaEggDb`, a driver adapter factory in the shape Prisma's own SQLite adapters have from
  Prisma 6 (`new PrismaClient({ adapter: new PrismaEggDb({ url: 'file:app.db' }) })`, with the `driverAdapters`
  preview where the Prisma version needs it). `connect()` opens an embedded `Database` in EggDB's SQLite dialect and
  returns the adapter, whose `provider` is `sqlite`, so Prisma's query engine generates SQLite SQL.
- `queryRaw` answers column names, column types and rows; the types are Prisma's `ColumnTypeEnum`, inferred from the
  values (EggDB's driver returns typed values, not declared types): integers `Int64`, other numbers `Double`, bytes
  `Bytes`, the rest `Text`, and an all-`NULL` column `Int32`, as Prisma's adapters answer for an untyped `NULL`.
  64-bit integers come back as decimal text, as Prisma expects for `Int64`. `executeRaw` answers the changed rows.
- Transactions: `startTransaction` opens one `BEGIN` block per connection and returns a transaction whose `commit` and
  `rollback` end it; isolation levels other than `SERIALIZABLE` are refused, as EggDB runs every transaction
  serializable. `executeScript` runs migrations' scripts; `dispose` closes the file.
- Prisma's adapter interface has changed between versions; the adapter follows the published Prisma 6 interface and is
  checked by `test/orm.test.js` against `@prisma/driver-adapter-utils` when it is installed.
