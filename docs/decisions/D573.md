## D573 Reading Apache Arrow IPC streams and files — Decided by the code-only session (2026-11-12, D355); roadmap M11, D240

D240 writes Arrow IPC streams; nothing read them back. `eggdb_arrow::read` now reads an IPC
stream, or an IPC file (`.arrow`, Feather 2: the `ARROW1` magic, then the same messages), into the
columns the Parquet and Arrow writers already share, and `eggdb import <file> --arrow <in> --table
<name>` loads them as `--parquet` does (the table is created from the columns when missing).

- **Parsing.** Our own FlatBuffers reader (vtables, offsets, strings, vectors of tables and of
  structs), every read bounds-checked, so damaged or hostile input is an error, never a panic;
  both the continuation-marker framing and the older one without it are read, up to the
  end-of-stream marker. The file format's footer is not needed and not read.
- **Types.** Booleans; signed and unsigned 8- to 64-bit integers (an unsigned 64-bit value past
  the largest bigint is an error); 32- and 64-bit floats; `utf8` (checked as UTF-8), `binary` and
  their large forms; `date32`/`date64`; timestamps in any unit, kept as microseconds (`UTC` when
  the field names a time zone); 128-bit decimals. Several record batches append in order, up to
  2^28 rows.
- **Writing files.** `eggdb_arrow::write_file` writes the IPC file format: the magic, the
  stream's schema and record batch, and a footer holding the schema and the batch's `Block`
  (offset, metadata length with its prefix, body length), then the footer's length and the
  trailing magic, so readers that seek can open it. `eggdb export --arrow <out>` writes it when
  `<out>` ends in `.arrow` or `.feather`, and a stream otherwise.
- **Refused by name:** dictionary-encoded columns, compressed batches, nested types, half floats,
  256-bit decimals and the other types, each with a message that says so.

**Status:** code written, unbuilt (code-only mode, D355).
