## D1068 FHIR validation against StructureDefinitions and profiles — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D50, D243, D834)

- `fhir_validate(resource, profile [, value_sets])` validates a resource against a StructureDefinition the
  caller gives (a base resource definition or a profile), after D834's structural checks, and returns the
  same `OperationOutcome`. The one-argument form is unchanged.
  - The profile's `snapshot.element` is used, or, without a snapshot, its `differential.element` (with an
    informational note that base constraints are not applied).
  - `value_sets` is a ValueSet, an array of them, or a Bundle of them.
- For each ElementDefinition (`crates/eggdb-sql/src/fhir/profile.rs`), every instance of its parent path is
  found, following arrays and choice elements (`value[x]`). On each one the checks are:
  - `min` and `max`, reported on the parent;
  - each value's type: a choice element by the type its name carries (`valueQuantity` is `Quantity`),
    others by JSON kind and the primitive formats (boolean, integers with their signs, decimal, the string
    types, date, dateTime, instant, time, integer64, Resource);
  - `fixed[x]` as JSON equality, numbers by value;
  - `pattern[x]` as containment: every member and array item of the pattern is present;
  - `required` bindings: a code, Coding or CodeableConcept must have a code (and system, when both sides
    name one) from the ValueSet's `compose.include[].concept` or its `expansion.contains`, nested included.
- Reported as `information`/`not-supported` rather than silently passed:
  - slices (`sliceName`);
  - FHIRPath `constraint`s other than the base specification's own;
  - bindings whose ValueSet was not given.
- Limits: 5,000 ElementDefinitions and 100,000 instances per path. The inputs together may be at most four
  times the one-resource limit.
- The profile must constrain the resource's type. Profiles and ValueSets are data the user loads: the FHIR
  specification and its definitions are published under CC0, so EggDB can also ship them later without a
  licence question.
- Left: slicing and discriminators, FHIRPath invariants, terminology beyond given ValueSets
  (`compose.include` by filter or system only), and the full FIX and EDIFACT dictionaries of the same
  roadmap line.
- Learned from: the FHIR R5 specification (StructureDefinition, ElementDefinition, ValueSet and the
  validation chapter). No validator source was read.
