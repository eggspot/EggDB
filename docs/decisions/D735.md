## D735 ORC files in SQL: `read_orc` — Decided by the code-only session (2026-11-12, D355); roadmap M11, NDJSON, ORC and Avro (D29)

- `read_orc(path)` reads an Apache ORC file through the session's file reader (D703), like `read_parquet`: with a
  column definition list or with the file's own columns (D706). It is written from Apache ORC's published format
  specification with EggDB's own code (`orc.rs`), and returns the same column model as the Parquet reader.
- Read: the postscript, footer, stripes and stripe footers (protobuf, decoded by a small reader of our own); no,
  ZLIB, Snappy or ZSTD compression (ZSTD chunks must carry their content size); byte and boolean run-length
  encoding; integer run-length encodings 1 and 2 (short repeat, direct, patched base and delta); direct and
  dictionary string encodings; `PRESENT` streams for nulls.
- Types: `boolean`, `tinyint`, `smallint` and `int` (as `integer`), `bigint`, `float`, `double`, `string`,
  `varchar` and `char` (as `text`), `binary`, `date`, `timestamp` and `timestamp with local time zone` (as
  `timestamp`, from seconds since 2015-01-01 and the nanosecond stream, read as UTC), and `decimal(p, s)` (each
  value brought to the column's scale).
- Nested columns (lists, maps, structs, unions) are left out of the result; LZO and LZ4 compression are refused.
  A file may hold at most 268,435,456 values and each stream at most 1 GiB once decompressed.
