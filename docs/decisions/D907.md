## D907 SQL Server logon triggers and Oracle `BEFORE LOGOFF` — Decided by the code-only session (2026-11-12, D355); roadmap M5, event triggers, follow-up of D872 and D873

- SQL Server: `CREATE TRIGGER name ON ALL SERVER [WITH ...] FOR LOGON AS <batch>` makes a logon trigger, kept with the
  DDL triggers (D872). `LOGON` is valid only on `ALL SERVER` and alone; anything else fails with 1098, as SQL Server
  does. `ENABLE`/`DISABLE`/`DROP TRIGGER ... ON ALL SERVER` work on them as on DDL triggers. A logon trigger never
  fires for DDL, and a DDL trigger naming a group never fires at logon.
- When a SQL Server-dialect connection signs in (`eggdb serve`'s TDS listener calls
  `Session::fire_login_event_triggers` once the session exists), the enabled logon triggers run in creation order in
  one transaction, with `EVENTDATA()` giving `EventType` `LOGON`, the login, SPID and database. An error, or a
  `ROLLBACK` inside one, refuses the login: the listener sends error 17892 ("Logon failed for login ... due to trigger
  execution") and closes the connection. The listener has already sent its login acknowledgement by then, so a client
  sees the error right after the acknowledgement rather than in place of it.
- Oracle: `CREATE TRIGGER name BEFORE LOGOFF ON {DATABASE | SCHEMA | user.SCHEMA} <block>` (Oracle allows only
  `BEFORE` for logoff; `AFTER LOGOFF` is refused). The triggers run when an Oracle-dialect session closes, after its
  open transaction is rolled back, with `ora_sysevent` `LOGOFF` and `ora_login_user`; their errors are ignored, as the
  session ends either way.
- Left: SQL Server's other server-level events (`CREATE_LOGIN`, `ALTER_DATABASE` and the rest) and Oracle's
  `STARTUP`, `SHUTDOWN` and other database events, which need the server's start and stop to run a session.
