## D102 Every listener binds only to loopback or a local socket until EggDB's own TLS exists — Decided (owner, 2026-10-26); an exception to D22's network rules, removed when TLS lands — superseded in part by D161: with TLS configured, listeners may bind any address and other machines must use TLS; without TLS this rule still holds
**The rule (owner, 2026-10-26).** Until EggDB has its own TLS (D23), every network listener it
opens binds only to a loopback address (`127.0.0.0/8` or `::1`) or a local (Unix domain) socket,
and refuses any other address before binding, with a message that says why and what to type
instead. Nothing EggDB serves is reachable from another machine, so no password or query
crosses a network in the clear. Authentication stays mandatory on loopback too: there is no
unauthenticated mode (D22, D45).

**How it applies today.** `eggdb serve` (roadmap item 21) is the first listener. Its address
goes through `eggdb_pgwire::listen_on_loopback`, which refuses any address whose IP is not a
loopback address (an IPv4-mapped IPv6 address such as `::ffff:127.0.0.1` is refused too) before
anything is bound; the command exits 2 with `cannot listen on <address>: it is not a loopback
address …` and a `try:` line. `SSLRequest` and `GSSENCRequest` are answered `N`, so clients
with `sslmode=prefer` fall back to the clear-text connection on loopback, and clients with
`sslmode=require` fail cleanly. Unix domain sockets are not offered yet (this release listens on
TCP loopback only; std has no Unix sockets on Windows).

**When it ends.** The pull request that brings EggDB's own TLS removes this rule from
`listen_on_loopback`, `docs/sql.md` ("Connecting with psql"), `docs/cli.md` (`eggdb serve`),
the release notes and the roadmap, and records the new network rules here as a superseding
decision.
