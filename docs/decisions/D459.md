## D459 Embedded resources in the generated REST API — Decided by the code-only session (2026-11-11, D355); roadmap M6a, extends D235

- `select=` items of the form `table(columns)`, `alias:table(*)` and `table!hint(...)` embed a
  related table, found through `information_schema`'s foreign keys between the two tables in the
  API's schema. A key on the child pointing at the parent embeds a JSON array
  (`coalesce(json_agg(...), '[]')`); a key on the parent pointing at the child embeds one JSON
  object or `null`. Each embed is a correlated subquery over `json_build_object`, so the parent's
  filters, order, paging and counts work as before.
- No relationship answers 400 `PGRST200`; several answer 300 `PGRST201` until `!hint` names the
  constraint or one of its columns, as PostgREST does.
- `select=*` items mix with embeds; at most 8 embeds per request; embeds nest one level deep, and
  filters on embedded columns (`orders.total=gt.5`) and embeds in `return=representation` are not
  written.
- This finishes the "Generated REST" roadmap line except those two refinements.
