## D288 PostgreSQL's integer `#` and `~`, `void` results as PostgreSQL gives them, array bounds in literals, `citext[]` and `hstore[]`, hstore's `%%`, `%#`, `#=` and `populate_record`, and regular expressions on `citext` — Decided by the build loop (EggAgentCode task 20261103-0137, 2026-11-03); roadmap items 38, 45 and the citext/hstore item, completes D131, D259 and D265, applies D9, D10 and D20

Several small PostgreSQL behaviours were still missing or different: the integer operators `#`
and `~` (D131 had `&` and `|`), the value a user function declared `RETURNS void` gives (D265
left it NULL in every language), arrays whose first subscript is not 1 arriving in a literal or a
binary parameter, arrays of `citext` and `hstore` (D259 listed their array types in `pg_type`
but refused them), hstore's `%%`, `%#`, `#=`, `hstore_to_matrix` and `populate_record`, and
case-insensitive regular expressions on `citext`. Each follows PostgreSQL 17's documentation;
where the documentation is silent (the `void` value), PostgreSQL's behaviour was checked by a
research subagent.

- **`#` and `~`.** In the PostgreSQL dialect `a # b` is the bitwise exclusive or and prefix `~a`
  the bitwise not of `smallint`, `integer` and `bigint`. `#` sits with every other operator at
  PostgreSQL's "any other operator" level, left-associative, like `&` and `|`; prefix `~` takes
  as its operand everything that binds tighter than that level (`~ 1 + 2` is `~3`), as
  PostgreSQL's grammar does for prefix operators. The result has the wider operand's type, NULL
  gives NULL, and other types are `42883`. Both become internal functions (`*integer_xor*`,
  `*integer_not*`) beside D131's, so no new AST operator touches every exhaustive match; their
  columns are named `?column?`. Infix `~` stays the regular expression match.
- **`void` results.** PostgreSQL gives a non-NULL empty `void` from a PL/pgSQL function declared
  `RETURNS void` (its `RETURN` adds one, and so does falling off the end) and NULL from an
  SQL-language one. EggDB now does the same: PL/pgSQL `void` functions return the empty value,
  sent as zero bytes with type OID 2278; SQL-language ones still return NULL, sent as `-1`.
- **Array bounds.** An array literal may begin with one dimension's bounds, `[lower:upper]=` or
  `[upper]=` (lower 1), with spaces and signs as PostgreSQL reads them. Bounds that do not match
  the number of elements, an upper bound below the lower, a missing `]` or `=` or a bound that is
  not a number are `22P02` with PostgreSQL's detail; a bound outside `integer` is `22003`; a
  second dimension is `0A000` as before. Since binary array parameters were already decoded to
  this text (D265), they now keep their lower bound; the binary writer already sent it.
- **`citext[]` and `hstore[]`.** Two new array element kinds, `Citext` and `Hstore`, with array
  element codes 27 and 28 in the file format (D20: added codes only, nothing existing changes)
  and the array type OIDs 9001 and 9003 D259 already listed. Their elements compare as their
  type does, so `citext[]` equality and `= ANY` ignore case; they are stored, printed and sent
  in both formats like every other array.
- **hstore.** Prefix `%%` is `hstore_to_array`. `populate_record(record, hstore)` and
  `record #= hstore` return the record with each field whose name is a key set to that key's
  value read with the field's type (NULL for a NULL value); a NULL record of a named composite
  type gives a row of NULLs filled from the hstore, a NULL hstore returns the record unchanged,
  and a first argument that is not a row is `22023`. The result has the first argument's type.
  `hstore_to_matrix` and prefix `%#` give `{}` for an empty hstore; a non-empty one needs a
  two-dimensional array, which EggDB does not have yet, so it is `0A000`.
- **Regular expressions on `citext`.** As in the citext extension, `~` and `!~` ignore case
  when the tested value is `citext` (they become `~*` and `!~*`); a `citext` pattern against a
  `text` value is read as text and keeps case, as PostgreSQL resolves that operator.

Not yet: multidimensional arrays, so `hstore_to_matrix` and `%#` of a non-empty hstore; the
`citext` versions of `regexp_match`, `regexp_matches`, `regexp_replace`, `regexp_split_to_array`,
`regexp_split_to_table`, `replace`, `split_part`, `strpos` and `translate`; `populate_record`
over a table's row type when tables have no composite type of their own; the new operators in
`pg_get_viewdef` and `pg_operator`.
