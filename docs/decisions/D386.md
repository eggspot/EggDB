## D386 Storage options in a plain PostgreSQL `CREATE TABLE` — Decided by the code-only session (2026-11-10, D355); roadmap M5, extends D342

D342 checked PostgreSQL's `USING heap`, `WITH (storage parameters)`, `WITHOUT OIDS` and
`TABLESPACE pg_default` in `CREATE TABLE ... AS` and kept refusing them in a plain `CREATE
TABLE`, where `pg_dump` and ORMs (`WITH (fillfactor = 70)`) write them most. A plain `CREATE
TABLE` now takes them after its columns and any `PARTITION BY`, in PostgreSQL's order (`USING`,
`WITH`/`WITHOUT OIDS`, `ON COMMIT`, `TABLESPACE`), through D342's own checks: the same errors
for another access method or tablespace and for an unknown, mistyped, out-of-range or repeated
parameter, and nothing kept, since EggDB has one table format. `INHERITS` keeps its refusal.

**Status:** code written, unbuilt (code-only mode, D355).
