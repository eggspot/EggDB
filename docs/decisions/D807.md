## D807 CQL collection element updates and CONTAINS — Decided by the code-only session (2026-11-12, D355); roadmap M16, CQL collections (D19, D218)

- `UPDATE` assignments gain CQL's collection forms, translated into SQL over the stored JSON (D730's layout):
  `l = l + [..]` appends, `l = [..] + l` prepends, `s = s + {..}` takes the union (distinct, sorted with jsonb's order,
  which is numeric for numbers and by text for strings, as D730 sorts), `m = m + {k: v}` and `m[k] = v` put entries
  (new keys replace old ones; entries sorted by key), `l = l - [..]` and `s = s - {..}` remove every equal item,
  `m = m - {k, ..}` removes keys, `l[i] = v` replaces an item (`jsonb_set`), and `c = c - n` decrements a counter.
- Since CQL's `UPDATE` is an upsert, the new row's value is the added collection, the single map entry, the negated
  counter step, or null for removals and list index updates; the conflict branch combines with the stored value.
  The same expressions serve conditional updates (`IF`).
- `WHERE c CONTAINS v` on a list or set becomes `c::jsonb @> jsonb_build_array(to_jsonb(v))`; on a map, and with
  `CONTAINS KEY`, an `EXISTS` over the map's entries compares the value or the key, so a key never matches a value.
  Bind markers work for the element, the key and the value, typed by the collection's element types.
- The CQL lexer now has a `-` symbol (a minus directly before a digit after an operator is still a negative number).
- Left: deleting single elements (`DELETE m[k]`, `DELETE l[i]`) and user-defined types.
