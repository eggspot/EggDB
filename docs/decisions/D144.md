## D144 Command model slice 2: every command in the registry; the table, explain and `sql --read-only` twins share the catalog code with the MCP tools; `table_not_found` for the CLI with parity by category; SQLSTATE 25006 is `read_only` — Decided by the build loop (by research, 2026-10-30); command model slice 2 (batch part 2.2), builds on D143 and the approved design of 2026-10-28, Claude Fable's design in [ux/cli.md](../ux/cli.md) section 24

**Every command is registered.** `eggdb-commands` now defines all 33 commands of `eggdb`
(`collection` and the new `table` as nouns with core verbs, `help` and `version` as kept names
the main help describes), and every MCP tool has a CLI twin. A test fails on a command of the
parser that is not in the registry, on a registered command the parser does not know, on a
command whose JSON form disagrees with whether it takes `--format`, and on an error code that
two commands declare with different exits. `eggdb help` and `help <command>` print the usage
lines and help bodies from the registry; the commands of a noun share one help page, and
`help <noun> --json` prints one object per verb. `ui`, `shell` and `mcp` declare no output and a
`null` default format, since their stdout is not data. `help --json` keeps `other_commands`, as
an empty array. Command aliases are spellings of the last word (`del` for `delete`, and for
`collection delete`).

**One catalog for both twins.** The tables and views, their order, the name matching (exact,
then lower-cased, `public` when no schema is given), the bounded row count and the sample
statement moved from `eggdb-mcp` into `eggdb_sql::relations` (`Session::relations`,
`find_relation`, `Relation::bounded_count_statement`, `first_rows_statement`,
`EXACT_ROW_COUNT_UP_TO`), and both `eggdb-mcp`'s tools and the `eggdb table` commands use it,
so a twin cannot drift from its tool. `eggdb-mcp` still does not depend on the `eggdb` library
(D98).

**Codes.** A table that `table show` or `table sample` names and the file does not have is
`table_not_found` (category `not_found`, exit 1, `fix_command: eggdb table list <file>`): the
CLI's `not_found` is the missing file at exit 3, and one code has one exit. The MCP tools keep
their shipped `not_found`; for this one failure the parity test compares the category, which is
the same. A statement refused because the session is read-only (SQLSTATE `25006`) is `read_only`
in `sql --json`, exit 3, as SQLSTATEs already pick `damaged` and `database_busy`; a write on a
read-only store now reads as PostgreSQL's own `cannot execute <command> in a read-only
transaction`. `explain`'s second statement is `one_statement_per_call` at exit 2, its Oracle and
SQL Server dialects `not_supported` at exit 3. `create`, `backup` and `compact` give
`already_exists` where a file is in the way, and `audit` gives `not_found` for a missing file;
their text and exit codes do not change.

**Pipes.** `version` and `help` keep text in a pipe, as `sql` does; `version --json` prints
`{"version":"..."}`. `table` and `explain` follow the pipe rule (JSON in a pipe).
