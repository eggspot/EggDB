## D540 A dead-letter queue for rejected messages — Decided by the code-only session (2026-11-11, D355); roadmap M16

Messages a consumer rejects now go to the queue's dead-letter queue, `<queue>.dlq`, instead of
being dropped (AMQP 1.0) or redelivered forever (STOMP).

- **Queue store:** `eggdb-queues` gains `dead_letter`, which in one transaction removes a received
  message and appends its body to `<queue>.dlq`, creating that queue when missing, so the
  rejected messages stay readable by every protocol that reads queues (AMQP 0-9-1 and 1.0, STOMP,
  SQS). A queue whose name leaves no room for the suffix (255 characters) has its rejected
  messages dropped, as they were before.
- **AMQP 1.0:** a `disposition` with the `rejected` outcome dead-letters the deliveries it settles;
  `released` and `modified` still make them visible again, and `accepted` removes them.
- **STOMP:** `NACK` with `requeue:false` (RabbitMQ's header) dead-letters, inside a transaction
  too; a plain `NACK` still redelivers.
- **Unchanged:** AMQP 0-9-1 queues keep their own dead-letter exchanges (D516); a rejected AMQP
  0-9-1 message without one is still dropped, as RabbitMQ drops it.
- **Left out:** the in-process inbox for embedded consumers, the rest of this roadmap item, and
  a redelivery limit that dead-letters a message after too many receives.

**Status:** code written, unbuilt (code-only mode, D355).
