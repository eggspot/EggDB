## D219 S3-compatible objects in our own eggdb-s3, with SigV4 shared in eggdb-auth — Decided by the build loop (by judgement, 2026-10-31); refines D2, D33 and supersedes part of D216

Part 4.M16-7 asks for blobs and objects through the S3 API: buckets, multipart uploads and
presigned URLs.

- **Objects live in EggDB's key-value transactions**, in the collection `objects0`: one entry
  per bucket, one description per object (size, MD5, part count, modification time, content
  type, user metadata) and the bytes in 256 KiB pieces, so a put, a copy or a completed upload
  replaces an object atomically and backups, replication and encryption at rest cover objects
  like every other model (D2). Multipart parts are kept under their upload until it completes or
  is aborted.
- **Path-style URLs only** (`/<bucket>/<key>`), which SDKs use for an endpoint on an IP address
  or with path style forced; virtual-hosted buckets need DNS this release does not set up.
- **AWS Signature Version 4 moved to `eggdb_auth::sigv4`**, shared by the SQS (D216) and S3
  endpoints: header and presigned-URL signatures, the URI encoded once as S3 does (the same for
  SQS, whose path is `/`), the request's date within 15 minutes of the server's clock (closing
  the replay gap D216 left), presigned URLs valid for at most seven days, and the stated
  `x-amz-content-sha256` checked against the body. The access key is the server's user and the
  secret its password, kept in memory only while an AWS-compatible listener runs.
- **MD5 moved to `eggdb-crypto` as `md5_checksum`**, with RFC 1321's constant table instead of
  computing it with floating-point sines, which are not guaranteed identical on every platform.
  It serves ETags, `Content-MD5` and SQS digests only, never security.
- **`eggdb-http` gained per-listener body limits and `100 Continue`**, and a response may state
  its own `Content-Length` so `HEAD` does not read an object. S3 accepts 64 MiB per request,
  so a larger object is uploaded in parts.

Left: versioning, object lock, ACLs and bucket policies (beyond the one signing user),
tagging, lifecycle rules, server-side encryption headers, `aws-chunked` streaming uploads
(boto3 1.36 and later send them by default for some calls), `ListParts` and
`ListMultipartUploads`, virtual-hosted buckets, conditional requests (`If-Match` and the rest),
streaming large objects instead of reading them whole, listing without loading a bucket's
descriptions, TLS, and a benchmark against MinIO.
