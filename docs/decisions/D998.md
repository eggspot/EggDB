## D998 Oracle's `DBMS_SQL` — Decided by the code-only session (2026-11-13, D355); roadmap M10, Oracle-supplied packages (sql.md)

- PL/SQL blocks can run dynamic SQL through `DBMS_SQL` as Oracle documents it: `OPEN_CURSOR`, `PARSE`,
  `BIND_VARIABLE` (and `BIND_ARRAY` for one value), `DEFINE_COLUMN`, `EXECUTE`, `FETCH_ROWS`, `EXECUTE_AND_FETCH`,
  `COLUMN_VALUE`, `VARIABLE_VALUE`, `IS_OPEN`, `LAST_ROW_COUNT` and `CLOSE_CURSOR`, with or without the `SYS.` owner.
- Cursors live in the session's PL/SQL state, numbered from 1, at most 300 open (ORA-01000), so a cursor number can be
  passed between blocks and procedures. Unknown numbers raise ORA-29471.
- The procedures are run where the PL/SQL runner already runs `DBMS_OUTPUT` and `DBMS_LOB` calls; the functions,
  which run or fetch, are run when an expression that calls them is evaluated (an assignment, an `IF` or a loop
  condition), and their results take their place, so `WHILE DBMS_SQL.FETCH_ROWS(c) > 0 LOOP` fetches once per test.
- `PARSE` runs DDL at once, as Oracle does. `EXECUTE` fills the bind placeholders (`:name`, outside quoted strings)
  with literals of the bound values (ORA-01008 for one never bound), runs the statement, keeps a query's rows for
  `FETCH_ROWS` and `COLUMN_VALUE`, and returns the rows a DML statement processed.
- Left: array binds and fetches of several rows at once (`DEFINE_ARRAY` reads one), `DESCRIBE_COLUMNS`, `TO_REFCURSOR`
  and `TO_CURSOR_NUMBER`.
