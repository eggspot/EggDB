## D1159 TLS 1.3 session resumption with tickets — Decided by the code-only session (2026-11-14, D355); roadmap M6a (D161, D35)

- **What it saves.** A client that has connected once resumes its next handshake from a ticket, so the server skips
  the certificate chain and the signature. It keeps a fresh (EC)DHE exchange, so forward secrecy holds. This
  follows RFC 8446 sections 2.2, 4.2.11, 4.6.1 and 7.1, written from the RFC.
- **Issuing tickets.**
  - `ServerConfig::session_tickets` holds a `resumption::SessionTickets` key: 32 random bytes made once per
    process, so a restart invalidates every ticket.
  - When the client offered the `psk_dhe_ke` mode and the server asks for no client certificate, the server ends
    every full handshake with one NewSessionTicket, after verifying the client's Finished:
    - lifetime seven days;
    - a random `age_add`;
    - nonce `00`;
    - the PSK is HKDF-Expand-Label(resumption master secret, "resumption", nonce).
  - The ticket seals, with AES-256-GCM under a random nonce and the associated data `eggdb ticket`, the cipher
    suite, the time it was issued in milliseconds, `age_add`, the `server_name` and the PSK. No server state is
    kept per ticket.
- **Accepting one.** A ClientHello's `pre_shared_key` must be its last extension; otherwise the handshake fails
  with `illegal_parameter`. The server resumes from the first identity when all of these hold:
  - the ticket opens under the server's key;
  - its cipher suite is the one chosen;
  - its `server_name` is the one asked for now;
  - it is within its lifetime;
  - its de-obfuscated age agrees with the server's clock within 10 s, which limits replays of an old hello;
  - the client offers `psk_dhe_ke`;
  - the server asks for no client certificate.

  The binder is checked in constant time over the partial ClientHello, after the `message_hash` and
  HelloRetryRequest when there was one. A wrong binder fails the handshake with `decrypt_error`, as the RFC
  requires. Any other mismatch falls back to a full handshake. A resumed ServerHello carries `pre_shared_key`
  selecting identity 0, the key schedule starts from the PSK, and the server sends EncryptedExtensions and
  Finished with no Certificate or CertificateVerify. `SessionInfo::resumed` reports it.
- **Not taken.** Early data (0-RTT) is not accepted, since it can be replayed. The `psk_ke` mode without (EC)DHE is
  not accepted either.
- **Where it applies.** `eggdb serve` makes the key whenever it has TLS, so PostgreSQL, MySQL, TDS and every
  relayed listener (D1155) issue and accept tickets.
- **Left for later.** EggDB's own client (`ClientConfig`) neither offers nor stores tickets yet, so replication
  and cluster links still make full handshakes; that is left in the roadmap.
- **Tests.**
  - Unit tests: a sealed ticket opens only under its key and unchanged; age and lifetime checks; parsing the
    offered identities and binders and cutting the partial hello; a binder verifies only with its key and
    transcript.
  - A handshake test: a server issuing tickets still serves a client that offers no resumption.
  - CI's `tls-clients` job: `openssl s_client -tls1_3 -sess_out`, then `-sess_in`, must print
    `Reused, TLSv1.3`.

**Status:** code written, unbuilt (code-only mode, D355). Security-critical (D35): it needs the extra security
review pass when the batch is built.
