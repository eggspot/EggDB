## D716 MySQL bit literals and `0x` hexadecimal literals — Decided by the code-only session (2026-11-12, D355); roadmap M10, MySQL's types (D19, D684)

- D684 left `b'...'` out because the lexer's binary token borrowed its digits from the statement text. The token
  now holds a `Cow`, so the MySQL lexer reads `b'0101'`, `B'0101'` and `0b0101` as binary strings: the bits are
  padded on the left to whole bytes, as MySQL does, so `b'1'` is the byte `0x01` and `b''` is the empty string.
  A quoted bit literal holding anything other than `0` and `1` is a syntax error.
- `0x41` and `0xABC` are read the same way as `x'41'`; an odd count of digits gets a leading `0`, as MySQL does.
  `0x` or `0b` with no digits, or followed by letters, stays the numeric token it was (MySQL reads those as names).
- The literals are byte strings everywhere, as in a string context in MySQL. MySQL's numeric reading of them
  (`b'1010' + 0` is 10) is not built: they compare and insert as `bytea`.
