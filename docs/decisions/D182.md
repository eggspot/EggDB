## D182 The official drivers are thin layers over the C API, one per language, tested in CI against the built library — Decided by the build loop (by judgement, 2026-10-31); refines D16 and D17

Parts 4.M5-5 to 4.M5-9 add EggDB's own drivers. Each one is a layer in its language over
`eggdb-capi` (`eggdb_open`, `eggdb_sql_open`, `eggdb_sql_execute_with_parameters`) with no
protocol or storage logic of its own (D16). One call crosses into Rust per statement, never
one per value (D17).

- **Python** (`drivers/python/eggdb`): DB-API 2.0 through `ctypes`, so it needs no compiler.
  `connect(path, dialect="sqlite")`, `?` placeholders in every dialect (renumbered to `$n` for
  PostgreSQL's), implicit transactions with `commit` and `rollback`, PEP 249's exception
  classes chosen by SQLSTATE, and rows as Python `int`, `float`, `str`, `bytes` and `None`. The
  C API check runs its unit tests against the built library on every system it runs on.
- **.NET** (`drivers/dotnet/EggDB.Data`): an ADO.NET provider through P/Invoke (`LibraryImport`):
  `EggDbConnection` with a connection string (`Data Source=app.db;Dialect=sqlite`), commands with
  `?` parameters, a forward data reader, transactions and `EggDbException` with the SQLSTATE.
  The C API check builds and runs its check program wherever the .NET SDK is installed.
- **Node.js** (`drivers/node`, package `eggdb`): `new Database(path, { dialect, readOnly })`
  with `query` (rows as objects), `run` (`{ changes }`), `execute` (every statement's tag,
  columns and rows), `transaction(fn)` and `close`, and `EggDbError` with the SQLSTATE; integers
  beyond 2^53 come back as `BigInt`, blobs as `Buffer`; TypeScript types in `index.d.ts`. Its
  native part is a small N-API addon in C (`src/addon.c`), because Node's native interface is a C
  header: it only converts values between N-API and the C API, with no logic of its own. The C
  API check compiles it with the system C compiler where Node's headers are installed and runs
  its tests with `node --test`.
- **Java** (`drivers/java`, package `app.eggspot.eggdb`): a JDBC driver through Java's foreign
  function and memory API (Java 22 and newer, no JNI and no compiler): `jdbc:eggdb:<path>` with
  `?dialect=` and `mode=ro`, registered through `java.sql.Driver`'s service file, statements and
  prepared statements with batches, forward read-only result sets with metadata, auto-commit off
  with commit, rollback and savepoints, and SQLSTATEs on every `SQLException`. The C API check
  compiles and runs its check program wherever a Java 22 or newer `javac` is installed; CI
  installs one.

Left: SQLAlchemy's dialect and Django's backend over the Python driver, the EF Core provider,
Hibernate's dialect, the Node.js ORMs' adapters (TypeORM, Drizzle, Sequelize, Prisma), Go
(`database/sql`, GORM) drivers, packaging for each language's registry (accounts the owner sets
up), and the benchmarks against each language's SQLite binding.
