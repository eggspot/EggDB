## D480 MQTT 5 topic aliases, message expiry, forwarded properties and reason strings — Decided by the code-only session (2026-11-11, D355); roadmap M16, D215

- A version 5 `PUBLISH`'s properties are read instead of skipped: payload format, message expiry,
  topic alias, content type, response topic (no wildcards), correlation data and user properties
  (at most 256); a subscription identifier or any other property is a protocol error.
- Topic aliases: `CONNACK` advertises a Topic Alias Maximum of 16; a `PUBLISH` with a topic and an
  alias sets the alias for the connection, one with an empty topic uses it. An alias of 0, above
  16 or never set ends the connection with `DISCONNECT` reason `0x94` (Topic Alias invalid).
- Version 5 subscribers receive the publisher's payload format, content type, response topic,
  correlation data and user properties, so request/response over MQTT 5 works; version 3.1.1
  subscribers get the message alone, as before.
- Message expiry: a retained message keeps its expiry time and is no longer replayed once it has
  passed; a replayed one carries the remaining seconds. An expiry of 0 on a retained `PUBLISH`
  clears the retained message. Retained values gain a new layout (a `0x80` flag on the QoS byte,
  then the expiry time, the kept properties and the payload); values in the old layout are still
  read.
- Reason strings: when a version 5 client breaks the protocol, the server sends `DISCONNECT` with
  reason `0x82` (Protocol Error), or `0x94`, and the problem as a Reason String property before it
  closes, as MQTT 5 allows on `DISCONNECT` whatever Request Problem Information says.
- Not written: shared subscriptions (`$share/`), server-to-client topic aliases, and expiry of
  messages queued for offline sessions (EggDB has no persistent sessions yet).

**Status:** code written, unbuilt (code-only mode, D355).
