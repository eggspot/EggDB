## D253 The full binary's size line is raised, with its reason, when a change adds features; doubling still blocks a change that adds none — Decided by research (2026-11-01); refines D6, D34, D101, D115 and D230

The batch that built the roadmap's remaining parts (KQL, the dialects' further features, about
25 protocol crates, the WebAssembly VM, graph, GIS, content and privacy functions) grew the
stripped `eggdb` binary on macOS from the 2,605,600 bytes of its baseline line to 12,253,408.
`eggdb-bench` reported `footprint.binary` as blocked (more than 2x, D101). On Linux, CI measured
14,159,040 bytes against the line's 3,251,776 (main itself was already about 5.2 MB).

- **What was removed first.** The SQL `Session` was generic over its store and was compiled four
  times (`Store`, `OwnedStore` and the MCP server's two call stores). It now holds its store as a
  trait object with boxed transactions, so the engine is compiled once: 10,865,136 bytes, with
  no benchmark slower. The engine's own code (`eggdb_sql`, every dialect) is 4.4 MB of the 9.6
  MB text section; the CLI 0.86 MB, storage 0.29 MB, TLS 0.21 MB, MCP 0.2 MB, the terminal UI
  0.18 MB, and each protocol crate 20 to 140 KB.
- **Why the line is raised instead.** `footprint.binary` measures the `eggdb` binary, which is
  the `full` profile (D230). The engine alone is above what a 2x limit allows the whole binary,
  so getting back under it would mean removing dialects or protocols, which the owner's rules
  forbid (D2, D46). Main had already grown 61% past its Linux line before this batch. D115 moved
  this line once already for the same reason, growth that is the price of features the owner
  requires; this decision makes that reading explicit. D6 asks for a stated reason and D34 for
  `full` to be kept as small as possible. A change that adds models or protocols may therefore
  raise this line, stating the sizes before and after and where the bytes went. A change that
  adds none still follows D101: more than 2x blocks. Because it reads the owner's D101 for
  added features, the owner is told in the pull request and may overrule it.
- **Per-package `opt-level = "s"`** was not used: with fat LTO and one codegen unit the merged
  code is optimized again at the root's level, so the gain is small and unpredictable, and a
  smaller setting for the whole build would slow hot paths (D5).
- **`benchmarks/footprint.txt`** now holds measured budgets (D230); it was empty, so its gate
  checked nothing. The budgets are taken from CI's own `footprint` job, since a local build of
  the same commit differs by a few kilobytes.

Left: the `server` profile split of D230, so the headline profiles get their own gated lines,
and a size audit in the weekly performance pass (D101) for further code compiled more than
once, such as protocol servers generic over their store.
