## D1372 The plan view prints a looped step's loops and total — Decided by the code-only session (2026-11-25, D355); roadmap M6e "Showing in the plan view the join-step times ..." (D277, D312), designed in `docs/ux/editor-and-plan.md` section 3.1

- **What users get.** Under `EXPLAIN ANALYZE`, a step that ran more than once (the inner side of a join, D1350; the scan inside a subplan, D1363) reads `0.04 ms · rows 1 · loops 3 · buffers 12 · 0.12 ms total`: the time and rows per loop as the engine prints them, the loops, and the step's own total over every loop, which is the figure its share bar and hot and warm marks already use, so a cheap lookup run a million times reads hot and says why. A measured plan's step that carries no time (a hash join's build scan) says `not measured`.
- **Left.** Oracle's measured plan from `DISPLAY_CURSOR`, SQL Server's `STATISTICS PROFILE` rows as unmeasured nodes, the spoken description with the per-loop figures, and the node tooltip as a `tooltip` in the accessibility tree.
- **Proof.** The plan view's analyze test reads `0.00 ms · rows 1 · loops 1,000 · 3.0 ms total` on an index scan run 1,000 times.

**Status:** code written, unbuilt (code-only mode, D355).
