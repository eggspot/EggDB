## D390 PostgreSQL's `regprocedure` — Decided by the code-only session (2026-11-10, D355); roadmap M6a

`pg_dump`, `\df` and extension scripts name functions as `'f(integer, text)'::regprocedure`.
EggDB had `regproc` (a name alone) and now has `regprocedure` (type oid 2202, array 2207) beside
it:

- **Input** `name(type, ...)` (the name schema-qualified or not): each argument type is read as
  `regtype` reads it (so `int4` and `integer` agree), and the function is the built-in one or the
  user routine of that name whose input arguments (`IN`, `INOUT`, `VARIADIC`) have exactly those
  types; none is `42883 function "..." does not exist`, a missing parenthesis `22P02`. A number is
  an OID, as for every `reg*` type.
- **Output** is the name as `regproc` shows it (qualified only when not visible) and the argument
  types as `format_type` names them, joined by commas without spaces, as PostgreSQL prints.
- It is in `pg_type` and loads the catalog snapshot like the other `reg*` casts.
