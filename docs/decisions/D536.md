## D536 MySQL's division by zero: `NULL` with warning 1365 — Decided by the code-only session (2026-11-11, D355); roadmap M10

In the MySQL dialect, `x / 0`, `x % 0` and `MOD(x, 0)` (by an integer, decimal or floating-point
zero) now give `NULL` and add MySQL's warning 1365 `Division by 0` to the statement, which
`SHOW WARNINGS` and the protocol's warning count report, as MySQL does outside strict writes.
They failed with SQLSTATE 22012 before.

- **Strict writes:** MySQL's default `sql_mode` has `STRICT_TRANS_TABLES` and
  `ERROR_FOR_DIVISION_BY_ZERO`, which make a division by zero an error in `INSERT`, `UPDATE` and
  `REPLACE`; those statements keep failing, as MySQL's do. Other dialects are unchanged.
- **Plumbing:** expressions raise warnings into a per-thread list that each statement clears
  when it starts and the MySQL session moves into its result when it ends, so evaluation code
  does not need a session to warn; the list holds at most 64 warnings, as MySQL caps a
  statement's.
- **Left out:** the rest of this roadmap item: `sql_mode` changing these rules, `DECIMAL`
  division scale, implicit string-to-number conversion and booleans as integers outside
  conditions (numbers as conditions came with D513).

**Status:** code written, unbuilt (code-only mode, D355).
