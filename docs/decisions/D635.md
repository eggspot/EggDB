## D635 SQL Server Agent operators and alerts — Decided by the code-only session (2026-11-12, D355); roadmap M10, D523, D623, D624

DBA setup scripts create operators and alerts next to their jobs (`sp_add_operator`,
`sp_add_alert @severity = 17`, `sp_add_notification`), and monitoring tools read
`msdb.dbo.sysalerts`. In EggDB those calls failed, so the scripts stopped before their jobs.

- `sp_add_operator`, `sp_update_operator` (with `@new_name`), `sp_delete_operator`,
  `sp_add_alert`, `sp_update_alert`, `sp_delete_alert`, `sp_add_notification`,
  `sp_delete_notification` and `sp_notify_operator` keep operators, alerts and their
  notifications in internal tables beside the jobs. `msdb.dbo.sysoperators`, `sysalerts` and
  `sysnotifications` are views over them, like D623's.
- Checks follow SQL Server's messages: an existing name is 14261, a missing alert, operator or job
  14262, an alert with both or neither of a message id and a severity 14500, a severity outside
  1–25 or a bad notification method 14266. Performance-condition and WMI alerts are refused as
  not supported.
- An alert fires when the server writes an event to its log. In EggDB that is a
  `RAISERROR ... WITH LOG`, now parsed into a `logged` flag. The event counts against every enabled
  alert whose message id matches, or whose severity matches when it has no message id, filtered by
  its database and its event description keyword. Each match raises `occurrence_count` and
  `last_occurrence`. When its delay between responses has passed, the alert:
  - sets `last_response`;
  - records one notification per operator (subject `SQL Server Alert System: 'name' occurred`, the
    message and the alert's notification message as the body);
  - runs its job.
- A thread-local guard keeps an alert's job from firing alerts again while it runs.
- EggDB sends no mail. Notifications, including `sp_notify_operator`'s, are recorded in an internal
  table for a later Database Mail.
- Errors EggDB raises itself are not logged events, so they fire no alert. Nor does `xp_logevent` yet.
