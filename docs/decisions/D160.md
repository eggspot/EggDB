## D160 PL/SQL on the shared routine store: compiled to PL/pgSQL's statement tree and run by the same interpreter in Oracle's semantics, packages as their own records with per-session state, units refused at CREATE when they do not compile — Decided by the build loop (by judgement, 2026-10-31); part 3.16, extends D158 and D159, applies D9, D35, D45, D108, D127, D134, D157

Part 3.16 adds Oracle's PL/SQL: anonymous blocks, standalone procedures and functions,
packages (specification and body), Oracle triggers, `DBMS_OUTPUT`, the PL/SQL views of the data
dictionary, and Oracle restores that run PL/SQL instead of listing it. The plan reserved D153;
that number was taken, so the part's decision is recorded here.

**One compiled form, one interpreter.** PL/SQL compiles to the same statement tree as D158's
PL/pgSQL (blocks, declarations, steps, SQL fragments), extended with what only PL/SQL has:
exception declarations with `EXCEPTION_INIT`, nested subprograms, record, collection,
`REF CURSOR` and subtype declarations, `RAISE name`, `RAISE_APPLICATION_ERROR`, `FORALL`,
collection methods, `BULK COLLECT` and `FETCH ... LIMIT`. The interpreter of D158 runs it,
dialect-aware: fragments are parsed as Oracle SQL, expressions run as `SELECT expr FROM dual`,
handlers match Oracle error numbers, and errors carry one `ORA-06512` line per unit they leave.
A second interpreter would have doubled the cursor, dynamic SQL, limit and cancellation code
that D158 already tests. PL/SQL-only behaviour lives in child modules of the interpreter.

**Routines on the shared store.** Standalone procedures and functions are D158's routine records
(`0x0C`) with Oracle's dialect and the language `plsql`; no format change. Like Transact-SQL
(D159), a name holds one PL/SQL routine and shares Oracle's one name space with tables, views
and packages (`ORA-00955`). The stored body is the unit as `USER_SOURCE` shows it, from its
`PROCEDURE` or `FUNCTION` keyword to its `END`, so line numbers in errors and the dictionary
agree. The declared types of parameters and results are kept next to the engine types; a
`%TYPE`, `%ROWTYPE` or named type is resolved when the call binds its arguments, so a changed
column is followed as Oracle's recompilation follows it.

**Packages are their own records.** A package is one record in a new key space `0x0D`, version
1, holding the `CREATE PACKAGE` text and, once created, the `CREATE PACKAGE BODY` text (D35:
described in format.md, decoded strictly). Members are not separate routine records: the body
is compiled as one unit against the specification's scope, its subprograms become synthetic
definitions named `pkg.member` (overloads allowed, private members reachable only from inside),
and the compiled package is cached per table cache, checked against the store's version.

**Package state belongs to the session.** Each session keeps, for every package it used, the
values of its variables and its open cursors, created on first use by running the
specification's and the body's declarations and then the body's initialization once; at most
1,000 packages per session (D45). The state, together with the `DBMS_OUTPUT` buffer, is moved
into a thread-local for each statement, so the interpreter, which runs below the session over
the statement's writer, reaches it. Values move between the state and the running unit's frame
instead of being copied. `CREATE OR REPLACE` and `DROP` reset a session's state of that package;
a state whose package another session replaced is re-created silently (Oracle raises
`ORA-04068` once first).

**Oracle's semantics where they differ from PL/pgSQL.** A handled exception undoes only the
statement that failed, not the block (Oracle's rule; PL/pgSQL undoes the block): inside a block
with handlers each statement is undone on its own. A variable wins over a column of the same
name in embedded SQL, as in EggDB's PL/pgSQL, because fragments are bound before the tables'
columns are known (Oracle takes the column; documented as a difference). `COMMIT` and `ROLLBACK`
in a block or procedure are recorded and applied by the session when the statement that ran
the block ends (the last one wins); an error after an in-block `COMMIT` therefore rolls back the
whole statement. They are `ORA-14552` in functions and `ORA-04092` in triggers. An EggDB error
with no Oracle number shows to handlers as `SQLCODE` -600, `ORA-00600: message`.

**Collections are record values.** A PL/SQL collection is a record value whose field names are
its keys (integers in decimal, kept in numeric order; text in byte order) and whose fields are
its elements; an atomically null nested table or varray is NULL. The collection's kind, limit
and element type live in the variable's slot, not in the value. A deleted nested-table element
is removed rather than kept as a gap. At most 4,194,304 elements (D45). This reuses the record
machinery for storage, copying and comparison instead of adding a value type to the engine.

**Units that do not compile are refused.** A procedure, function, package, body or trigger is
compiled at `CREATE` and refused with `ORA-06550: line L, column C:` and the `PLS-` message
when it does not compile; Oracle would create it invalid. Keeping invalid units would need a
status and error store that nothing else in EggDB has; `USER_ERRORS` exists and is empty.
Restores list such a unit as skipped with the message and continue (D127).

**Oracle triggers** are D157's trigger records with a fourth action kind, a PL/SQL block with
its `REFERENCING` names; a `CALL` body is stored as a block that makes the call. Line numbers
count from the block. A trigger does not fire itself again, and the mutating-table check
(`ORA-04091`) is not made.

**Calls.** A name is resolved in this order: subprograms declared in the enclosing blocks, the
current package's members, a schema routine, then `pkg.member`. Unknown function names in
Oracle SQL become routine calls resolved at run time, so standalone and package functions work
in any expression, read-only as D158's functions are. Wrong arguments are `ORA-06553 PLS-306`.

**Restores** run PL/SQL: units are created, blocks run. A block with a substitution variable
that has no value is skipped (HR's installer checks its prompted password that way), and so is
a block that calls an Oracle-supplied package EggDB does not have (any `DBMS_`, `UTL_` or `OWA_`
package but `DBMS_OUTPUT`); `ALTER ... COMPILE` in a restore stays a PL/SQL setting with no
effect.

**Refused and ignored.** `GOTO`, `PRAGMA AUTONOMOUS_TRANSACTION`, call specifications
(`LANGUAGE`, `EXTERNAL`), `AGGREGATE USING`, `PIPELINED USING` and `OUT` binds in `EXECUTE
IMMEDIATE ... USING` are refused at compile with `0A000`; the pragmas `SERIALLY_REUSABLE`,
`RESTRICT_REFERENCES`, `INLINE`, `UDF`, `DEPRECATED`, `COVERAGE` and
`SUPPRESSES_WARNING_6009` are accepted and have no effect.

**Limits (D45)**: D158's nesting (64), routine text (1 MiB) and call depth (100) apply; at most
10,000 nested subprograms in scope, 1,000 package states per session, a `DBMS_OUTPUT` buffer of
1 MiB when no size is given (`ORU-10027`) and lines of 32,767 bytes (`ORU-10028`).

**Not decided here:** autonomous transactions, `GOTO`, pipelined functions in `TABLE(...)`,
collections in SQL, object types, compound triggers and Oracle-supplied packages other than
`DBMS_OUTPUT`; they come later without changing these records.
