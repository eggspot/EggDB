## D1281 ODBC data at execution — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1278, D1280)

- **What users get.** Applications that send long values in pieces (Microsoft Access, Crystal Reports and LOB-loading tools bind a parameter with `SQL_DATA_AT_EXEC` or `SQL_LEN_DATA_AT_EXEC(n)`) can: `SQLExecute` and `SQLExecDirect` return `SQL_NEED_DATA`, `SQLParamData` names each such parameter in turn by its bound value pointer, `SQLPutData` appends a piece (or sends `SQL_NULL_DATA`), and the last `SQLParamData` runs the statement with the sent values. `SQLGetFunctions` lists both calls.
- **How.** The statement keeps the waiting run: its text, the parameters to send, the one being sent and what was sent. When the run goes on, sent values take the place of the bound buffers and are converted from their C type as any bound value is, so text sent in pieces is joined before conversion.
- **Left.** Data at execution with parameter arrays, `SQLCancel` of a waiting run, and data-at-execution columns in `SQLSetPos`.
- **Proof.** The ODBC test inserts a value sent in two pieces and reads it back.

**Status:** code written, unbuilt (code-only mode, D355).
