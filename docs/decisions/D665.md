## D665 Prometheus remote write 2.0 — Decided by the code-only session (2026-11-12, D355); roadmap M16, D220

Prometheus 3 and the OpenTelemetry Collector can send remote write 2.0
(`application/x-protobuf;proto=io.prometheus.write.v2.Request`). That version replaces label
strings with references into a per-request symbol table, and carries native histograms. EggDB's
endpoint read only version 1.

- `remote_write::decode_v2` reads the Snappy-compressed request. It takes the symbols (field 4)
  and resolves each series' label references (field 1, packed or not) through them. A reference
  past the table, an odd count of references, or a series without `__name__` is a 400.
- Float samples (field 2) become points of the metric's measurement with the field `value`, as in
  version 1.
- A native histogram (field 3) becomes two points at its timestamp: `<name>_count` (its integer or
  float count) and `<name>_sum`, the series Prometheus' classic histograms expose. Queries such as
  `rate(latency_sum[5m]) / rate(latency_count[5m])` therefore work. The buckets (spans and
  deltas) are not kept.
- Exemplars and metadata are skipped.
- The endpoint picks the version from the `Content-Type`. A version 2 write answers 204 with
  `X-Prometheus-Remote-Write-Samples-Written`, `-Histograms-Written` and `-Exemplars-Written`
  (always 0), which version 2 senders read to confirm what was stored.
- The same limits on points and label bytes as version 1 apply.
- Test: `remote_write_two_resolves_symbols_and_splits_histograms`.
