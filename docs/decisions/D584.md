## D584 CQL `ALTER TABLE` — Decided by the code-only session (2026-11-12, D355); roadmap M16, D218

Schema migration tools for Cassandra (cassandra-migrate, Liquibase's extension, application
startup code) add and drop columns with `ALTER TABLE`, which EggDB's CQL listener refused. It now
takes the forms Cassandra 4 accepts:

- `ADD [IF NOT EXISTS] name type` or `ADD (name type, ...)`: refused when a name is already a
  column, as Cassandra does; collection and user-defined types stay refused as in `CREATE TABLE`.
- `DROP [IF EXISTS] name` or `DROP (name, ...)`: refused for a primary key column or an unknown
  one.
- `RENAME [IF EXISTS] a TO b [AND c TO d]`: only primary key columns, as Cassandra allows, and not
  onto a name another column has.
- `WITH options`: read and ignored, as `CREATE TABLE`'s options are.

Each change runs as the SQL `ALTER TABLE` on the table and rewrites the table's row in
`eggdb_cql.tables` (column CQL types, partition, clustering and descending keys) in the same
request, and the answer is a `SCHEMA_CHANGE` `UPDATED` `TABLE`, after which the connection forgets
its cached table descriptions. `ALTER TABLE ... ALTER col TYPE` (removed in Cassandra 3.10) is not
taken.
