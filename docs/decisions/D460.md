## D460 Rate limits on every generated HTTP API (`--rate-limit`) — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D25 and D37

- `eggdb serve --rate-limit <requests>` gives each client address a token bucket of that many
  requests a second, holding up to twice that for bursts. It applies to every listener served by
  `eggdb-http`: the REST API, MCP, S3, DynamoDB, SQS, Elasticsearch, observability and metrics.
- The check runs in `eggdb-http` after a request is read and before the handler sees it, so no
  API needs its own code: a request over the rate gets `429 Too Many Requests` with
  `Retry-After` in whole seconds, and the connection stays open.
- Buckets are keyed by the peer's IP address (behind a proxy that is the proxy; trusting
  `X-Forwarded-For` waits for a proxy setting). At most 16,384 addresses are tracked; when full,
  buckets that have refilled are dropped, and a new address that still finds no room waits a
  second.
- Off unless given. Per-role or per-key limits and limits on the wire protocols (PostgreSQL,
  MySQL, RESP) are not written.
