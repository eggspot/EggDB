## D1063 A benchmark against Cassandra and ScyllaDB — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D7, D218)

- New excluded crate `crates/eggdb-cql-compare`, never shipped, like the other compare crates (D94). It has no
  dependencies and its own CQL native protocol v4 client:
  - `STARTUP`, and the password authenticator's `AUTH_RESPONSE` when the server asks for it;
  - `QUERY`, `PREPARE`, `EXECUTE` and unlogged `BATCH`;
  - up to 64 requests in flight on one connection, told apart by their stream ids;
  - rows counted by reading the result metadata's column types.
- The same three workloads run on every server, after the `eggdb_compare` keyspace is dropped and created
  with a `kv (id int PRIMARY KEY, value text)` table:
  - 20,000 prepared single-row inserts;
  - 20,000 more rows in unlogged batches of 50;
  - 20,000 prepared point reads spread over every key.
  - A full scan then checks that each server holds all 40,000 rows, so no ratio compares unequal work.
- The report gives operations per second, the p50 and p99 time per window of 64, and EggDB's ratio against
  each server. It is reported, not gated (D7's 2x gate is for `benchmarks/baseline.txt` lines).
- CI job `cql-compare` (added to `check`'s `needs`):
  - Cassandra 4.1 runs as a service container with a 1 GB heap.
  - ScyllaDB 5.4 is started with `docker run` (`--smp 1 --memory 1G --overprovisioned 1 --developer-mode 1`),
    because a service container cannot take arguments.
  - The program waits up to four minutes for each server to accept a session. A server that never does is
    left out, not failed.
  - The results are uploaded as an artifact, like the other comparisons.
- Learned from: the public CQL native protocol v4 specification. No Cassandra or ScyllaDB source was read.

**Status:** code written, unbuilt (code-only mode, D355).
