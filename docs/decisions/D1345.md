## D1345 The Unicode Collation Algorithm over DUCET, and PostgreSQL's ICU-style COLLATE names — Decided by the code-only session (2026-11-25, D355); roadmap M5 "The Unicode Collation Algorithm with CLDR tailorings ..." (D30, D233)

- **What users get.** `ORDER BY name COLLATE "en-US-x-icu"` (and `"und-x-icu"`, `"unicode"`, `"de-DE-x-icu"`, `"fr-x-icu"`, libc-style `"de_DE.utf8"`, ...) orders text linguistically, as PostgreSQL's ICU collations do: `Äpfel`, `apple`, `Apple`, `APPLE`, `banana` instead of byte order. Comparisons, `MIN`/`MAX`, `DISTINCT` and `GROUP BY` of a collated value follow the collation. `-u-ks-level1` (ignoring accents and case) and `-u-ks-level2` (ignoring case) give PostgreSQL's nondeterministic collations: `count(DISTINCT w COLLATE "und-u-ks-level2")` counts `apple`, `Apple` and `APPLE` once.
- **The algorithm.** UTS #10 written from the standard: canonical decomposition (our NFD, D233), the longest contraction at each position, then single code points, then the implicit weights for Han ideographs (core and extension bases), the `@implicitweights` scripts and unassigned code points; sort keys of primary, secondary and tertiary weights, each level closed by a zero, variable elements not ignorable (CLDR root's default). Deterministic collations end ties on the code points, as PostgreSQL's deterministic collations do, so only identical texts are equal.
- **The data.** `scripts/unicode/generate_collation.py` turns Unicode 16.0's `allkeys.txt` (the DUCET, under Unicode's permissive data licence, as D233's tables are) into `crates/eggdb-text/src/ducet.bin`: 38,443 single code points, 964 contractions and 45,509 collation elements packed in 32-bit words, read in place through `include_bytes!` with binary search, about 500 KB. CI is to regenerate it and compare, as it does for D233's tables.
- **Which names.** Only languages whose CLDR standard collation is the root collation are accepted (`und`, `root`, `unicode`, `en`, `de`, `fr` but not `fr-CA`, `it`, `pt`, `nl`, `ru`, `id`), with any two-letter region. Swedish, Spanish, Czech, Turkish and the other tailored languages are refused with PostgreSQL's "collation does not exist" rather than ordered wrongly.
- **Left.** CLDR tailorings (their rule syntax and per-locale data), discontiguous contractions (combining marks between the parts of a contraction), the shifted alternate option, column collations (`text COLLATE "..."` in `CREATE TABLE`), MySQL's and SQL Server's collation names, collation keys in indexes and the UCA conformance test (`CollationTest_NON_IGNORABLE`).
- **Proof.** `eggdb-text` tests order letters, case and accents, French words, digits and spaces as UTS #10 does, and check strengths and implicit weights; SQL tests order six words by a collation and by bytes, count distinct values under a case-insensitive collation, compare a collated literal, and check which names are accepted.
