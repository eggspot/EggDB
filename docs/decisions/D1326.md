## D1326 The EF Core provider — Decided by the code-only session (2026-11-25, D355); roadmap M6f (D16, D182)

- **What users get.** `optionsBuilder.UseEggDb("Data Source=app.eggdb")` (or `Data Source=postgresql://user:password@host/db` for a server) makes EggDB an Entity Framework Core 8 database: `EnsureCreated` and `EnsureDeleted`, migrations with their history table, LINQ queries (filters, ordering, projections, joins and counts, `Skip` and `Take`), and `SaveChanges` with the keys EggDB generates read back. Integer keys EF Core generates become `GENERATED BY DEFAULT AS IDENTITY` columns. .NET types map to EggDB's PostgreSQL-dialect types (`int` to `integer`, `string` to `text` or `varchar(n)` with a length, `decimal` to `numeric` with its precision, `DateTime` to `timestamp`, `DateTimeOffset` to `timestamptz`, `DateOnly`, `TimeOnly`, `TimeSpan`, `Guid` to `uuid`, `byte[]` to `bytea`, `bool` to `boolean` with `TRUE` and `FALSE` literals).
- **How.** `drivers/dotnet/EggDB.EntityFrameworkCore` is a thin C# layer (D16): EF Core's relational base classes with EggDB's type mappings, `LIMIT` and `OFFSET`, `RETURNING` for generated values, identity columns in migrations, `CREATE SCHEMA IF NOT EXISTS`, a database creator that treats an embedded database as its file, and the history repository; every statement runs through `EggDB.Data`, the ADO.NET provider over the C API, so embedded and server mode are the same code. An embedded connection without a `Dialect` runs in PostgreSQL's, since EF Core's SQL is written for it. Writing the provider from EF Core's documented provider model was chosen over pointing users at Npgsql's provider, which reaches only `eggdb serve` and not embedded files.
- **Left.** Idempotent migration scripts (`--idempotent`), batching several changes in one command, EggDB-specific translations (full-text, JSON, vector search) and EF Core's provider specification tests.
- **Proof.** `EggDB.EntityFrameworkCore.Check`, run by `scripts/c-api/check.sh` beside the ADO.NET check, creates a database with two related entities, saves three rows and reads an identity key back, runs a filtered and ordered projection, a page with `Skip` and `Take` and a join with a count, updates and deletes, and deletes the database.
