## D864 PostgreSQL `table_rewrite` event triggers fire — Decided by the code-only session (2026-11-12, D355); follow-up of D787

- `table_rewrite` triggers (accepted since D787, never fired) now fire for `ALTER TABLE` that changes a column's
  type, the rewrite EggDB's `ALTER COLUMN ... TYPE` does: after `ddl_command_start` and before the command, inside
  its transaction, filtered by `WHEN TAG` like the other events.
- `pg_event_trigger_table_rewrite_oid()` returns the table's OID from the catalog snapshot and
  `pg_event_trigger_table_rewrite_reason()` returns PostgreSQL's reason code, 4 (`AT_REWRITE_COLUMN_REWRITE`); both
  fail with 39P03 outside a `table_rewrite` trigger, as in PostgreSQL. The snapshot is built only when a
  `table_rewrite` trigger would fire.
- Other commands PostgreSQL rewrites for (a volatile default on `ADD COLUMN`, `SET LOGGED`/`UNLOGGED`, `SET ACCESS
  METHOD`, `CLUSTER`, `VACUUM FULL`) do not fire it: EggDB adds columns without rewriting rows, and has no
  persistence or access-method changes.
- Left: sub-commands of `ALTER TABLE` as separate rows, and SQL Server's and Oracle's DDL and logon triggers.
