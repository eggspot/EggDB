## D834 FHIR structural validation — Decided by the code-only session (2026-11-12, D355); roadmap D50, D243

- `fhir_validate(resource jsonb or text)` returns a FHIR `OperationOutcome` as `jsonb`: one issue per problem with
  `severity`, a FHIR issue `code` (`structure`, `required`, `value`, `code-invalid`, `too-costly`), `diagnostics` and
  the element's path in `expression`; or a single `informational` "All OK" issue, as FHIR's `$validate` answers.
- Checked, written from the FHIR specification's JSON format and datatype rules: a resource is an object with a
  `resourceType` naming a type; `id` and `meta.versionId` are FHIR ids; no empty objects, arrays or strings; no
  `null` outside arrays of primitives; no nested arrays; no key twice; `_element` holders match their primitives
  (arrays of the same length); extensions have a `url` and exactly one `value[x]` or nested extensions; narratives
  are an XHTML `<div>`; references are `Type/id`, `Type/id/_history/v`, `#id`, a URN or an absolute URL (a warning
  otherwise); `birthDate` is a date, `lastUpdated`, `issued` and `instant` are instants, `*DateTime`, `recorded` and
  `authoredOn` are dateTimes; the required elements of eleven common resources (Observation, Encounter, Condition,
  Procedure, MedicationRequest, DiagnosticReport, AllergyIntolerance, Immunization, Bundle, OperationOutcome,
  Consent); and the code values of Observation, DiagnosticReport and Encounter status, Patient gender, Bundle type
  and Narrative status. Bundle entries and contained resources are validated inside.
- It is a structural check, not a profile validator: element types and cardinalities beyond these, terminology
  bindings and profiles need FHIR's StructureDefinitions, which are left (with a licence check of loading them).

**Status:** code written, unbuilt (code-only mode, D355).
