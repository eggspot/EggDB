## D1327 SQL Server's CONTAINSTABLE and FREETEXTTABLE — Decided by the code-only session (2026-11-25, D355); roadmap M8 full-text (D195, D514)

- **What users get.** `CONTAINSTABLE (table, column | (columns) | *, condition [, LANGUAGE x] [, top_n])` and `FREETEXTTABLE (...)` in `FROM`, with the columns `KEY` and `RANK` that applications join back to the table, as SQL Server returns them. The condition is read as `CONTAINS` and `FREETEXT` read it (D514); `*` takes the table's text columns; `top_n` keeps that many rows of the highest rank. `KEY` is the table's one-column primary key, which stands for SQL Server's full-text key since EggDB keeps no full-text catalogs; a table without one is refused with error 7601.
- **RANK.** From 0 to 999, growing with how often the condition's terms (those not after `AND NOT`; `FREETEXT`'s words other than noise words) occur in the row's columns: `1000 × n / (n + 3)`. SQL Server documents its ranks as relative within one query only, which this keeps.
- **How.** A SQL Server session rewrites each call, before parsing, into a derived table `(SELECT [key] AS [KEY], eggdb_contains_rank(...) AS [RANK] FROM table WHERE CONTAINS(...))` (with `TOP (n) ... ORDER BY [RANK] DESC` for a count), reading the table's primary key and text columns from the catalog.
- **Left.** Full-text indexes behind them, `ISABOUT`'s weights in the rank, and `CONTAINSTABLE` over an indexed view.
- **Proof.** A SQL Server test joins `CONTAINSTABLE` back to its table ordered by rank, uses `*` with a prefix term and a count, and `FREETEXTTABLE` over two columns with `LANGUAGE`, leaving out noise words.
