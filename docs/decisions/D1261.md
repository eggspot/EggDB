## D1261 The ODBC driver connects to servers — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1236, D17)

- **What users get.** A connection string with `Server` (or `Host`), and optionally `Port`, `UID`, `PWD`, `Database` and `SSLMode`, connects the ODBC driver to an EggDB server, or to any server speaking PostgreSQL's protocol, instead of opening a file; `Dialect=mysql` (or `URL=mysql://...`) connects over MySQL's protocol, the password then coming from `MYSQL_PWD` as the C API reads it. `URL=postgresql://...` gives the address whole. Statements, parameters, escapes, `SQLNativeSql` and the catalog calls work as on a file, `ReadOnly=1` makes the session read-only on the server, and a refused sign-in fails with SQLSTATE 08001.
- **How.** The driver stays a thin layer over the C API (D17): a server session is `eggdb_sql_connect`'s, and the catalog calls, which an embedded connection runs on a second PostgreSQL-dialect session, run on the same server session, which already speaks PostgreSQL. The user, password and database are percent-encoded into the URL. Connection strings are now read as ODBC defines them: a value in braces may hold `;` and `=`, with `}}` for a `}`.
- **Left.** Catalog calls over MySQL's protocol (they read `pg_catalog`), and TLS options beyond `sslmode`.
- **Proof.** Unit tests read braced values and build encoded URLs; the ODBC test starts a server in the process, connects with a braced password, runs an escape, lists a primary key and is refused with a wrong password.

**Status:** code written, unbuilt (code-only mode, D355).
