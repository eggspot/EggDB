## D836 Nested ORC columns — Decided by the code-only session (2026-11-12, D355); roadmap D29, ORC

- `read_orc` now returns the file's list, map and struct columns (they were skipped) as text columns holding JSON,
  like nested Arrow columns (D835): a list as an array, a struct as an object of its field names, a map as an object
  keyed by its keys (text keys as they are, other keys as their JSON text), a null value as SQL NULL at the top and
  JSON `null` inside; dates and timestamps as ISO 8601 text, decimals with their scale, binary as hex.
- Decoding follows ORC's layout: each nested type's `PRESENT` stream covers its parent's slots; a list or map has
  one `LENGTH` per present value and its children cover the sum of those lengths; a struct's children cover its
  present values. The type tree is walked from the footer's type list to 32 levels, a cycle or excess nesting is an
  error, and slot counts are capped like the flat reader's.
- Left: union columns.
