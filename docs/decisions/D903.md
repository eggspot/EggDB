## D903 IMAP `IDLE` — Decided by the code-only session (2026-11-12, D355); roadmap M16, follow-up of D893

- The IMAP server advertises and serves `IDLE` (RFC 2177) in the authenticated and selected states: it answers
  `+ idling`, then, each time its one-second read poll passes with nothing from the client, compares the selected
  mailbox's UIDs with what the client last saw and sends `* n EXPUNGE` for each message gone (highest sequence number
  first, so the numbers stay right as they are sent) and `* n EXISTS` when messages arrived. `DONE` ends it with
  `OK IDLE terminated`; any other line ends it with `BAD`; a line longer than 64 bytes closes the connection.
- The store has no change notifications yet, so changes are found by polling: at most a second late, and only for
  the session's selected mailbox. Flag changes made by other sessions are not reported during `IDLE` yet (they show
  on the next `FETCH`).

**Status:** code written, unbuilt (code-only mode, D355).
