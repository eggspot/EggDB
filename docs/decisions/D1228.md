## D1228 Subqueries in Oracle's EXPLAIN PLAN — Decided by the code-only session (2026-11-17, D355); roadmap M6c, subqueries in the tabular plans (D327)

- **What users get.** `EXPLAIN PLAN FOR` a query with subqueries writes them into the plan table and `DBMS_XPLAN.DISPLAY` shows them as Oracle draws them: a subquery in `WHERE` puts a `FILTER` operation over the outer query's access and the subquery's own access beside it under the `FILTER`; a subquery in the select list comes first, under the statement, above the outer access; a subquery that aggregates gets a `SORT AGGREGATE` row; each subquery's objects carry its own query block (`@SEL$2`, ...). `UPDATE` and `DELETE` with subqueries plan the same way under their `UPDATE` or `DELETE` row.
- **How.** Oracle's `EXPLAIN PLAN` now plans with D327's subplans (`explain_with_subplans`, which D1223 taught writes too), and the operation list is built per query block, recursively for nested subqueries.
- **Left.** Oracle's semijoin and antijoin forms (`HASH JOIN SEMI`, `NESTED LOOPS ANTI`) that its optimizer often picks for `IN` and `EXISTS`, `VIEW` rows for derived tables, and SQL Server's showplan.
- **Proof.** `dialect_plan_tests.rs`: an `EXISTS` subquery under a `FILTER` beside the outer full scan, and a scalar aggregate subquery in the select list as `SORT AGGREGATE` above the outer scan.
