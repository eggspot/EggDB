- The EF Core check program takes its target framework and EF Core version as MSBuild properties (`EfCoreTarget`,
  `EfCoreVersion`, 8 by default). `scripts/tds-apps/check.sh` builds it a second time for .NET 9 and EF Core 9.0.0
  and runs it against a fresh database; its output must equal EF Core 8's expected output, since the program's
  migrations, saves and queries are the same. EF Core 9's migration lock (`sp_getapplock`) runs on D448's
  application locks.
- mssql-jdbc's metadata check calls `DatabaseMetaData.getSchemas()`. Its expected rows follow SQL Server's: every
  schema of `sys.schemas` in name order, with no catalog for the built-in ones and the database name for user schemas.
- `sys.schemas` now lists the nine fixed database role schemas (`db_owner` 16384 to `db_denydatawriter` 16393) with
  SQL Server's ids, as every SQL Server database has them.
