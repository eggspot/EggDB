## D799 Redis Functions kept across restarts, FUNCTION DUMP and RESTORE — Decided by the code-only session (2026-11-12, D355); roadmap M7, Lua scripting and Redis Functions

- `eggdb-keyspace`'s `Keyspace` trait gains `read_record` and `write_record`: a protocol's own records, kept apart from
  every numbered database's keys so `KEYS`, `SCAN`, `FLUSHALL` and replication of keys never see them. The defaults keep
  nothing (wrappers and test keyspaces stay as they are); `MemoryKeyspace` keeps them in a map, `eggdb`'s
  `DatabaseKeyspace` in the collection `<prefix>_records` of the file (`resp_records` for the RESP server), and the
  RESP server's notifying and evicting wrappers pass them through.
- Every `FUNCTION LOAD`, `DELETE`, `FLUSH` and `RESTORE` that succeeds writes all libraries' code as one record
  (`function-libraries`); `eggdb serve` loads it into the server's scripting state when the RESP listener starts and
  logs, rather than fails on, a library that no longer loads. Keeping them fails the command with an error if the
  record cannot be written, while the libraries stay loaded in memory.
- `FUNCTION DUMP` answers the same bytes: the magic `EGGDBFN\x01`, the library count, each library's code with its
  length, and a 64-bit FNV-1a checksum. It is EggDB's own payload, not Redis's RDB encoding, so dumps move between
  EggDB servers only. `FUNCTION RESTORE payload [FLUSH | APPEND | REPLACE]` checks the magic and checksum (Redis's
  "DUMP payload version or checksum are wrong"), and with `APPEND`, the default, refuses a library that exists.
