## D779 Text-to-SQL through a language model (eggdb_ai.text_to_sql) — Decided by the code-only session (2026-11-12, D355); roadmap M6d, text-to-SQL in every dialect through the MCP server (D31, D205)

- `eggdb_ai.text_to_sql(endpoint, model, question [, dialect, api_key, schema])` builds a prompt from the schema's
  tables and columns (`schema_outline`, from `information_schema`, so only what the caller may see) and the
  question, asks the opt-in chat-completions provider (D777) for one read-only query in the chosen dialect, strips a
  code fence and trailing semicolons, and returns the SQL with whether it was checked and any problem.
- Answers in the PostgreSQL dialect are checked with `EXPLAIN` in a nested block, so a statement that names a
  missing column or does not parse comes back with its SQLSTATE and message instead of failing the call; the other
  dialects' answers are returned unchecked until a session can switch dialect for one statement.
- The function never executes the query. Running it is the caller's choice, and through the MCP server it goes
  through `run_sql`, whose read-only rules and confirmation (D121, D255) apply, so a model's answer cannot write.
- An MCP tool of its own (`text_to_sql` beside `run_sql`), schema retrieval for large schemas (only the tables the
  question names), and few-shot examples are left.
