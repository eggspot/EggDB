## D719 MongoDB's `$where` on a JavaScript expression interpreter of our own — Decided by the code-only session (2026-11-12, D355); roadmap M9, `$where` (D197)

- `$where` takes a string, JavaScript code or code with a scope, as MongoDB does. EggDB has no JavaScript engine and
  takes no third-party one, so `$where` runs on a small interpreter of its own (`where_script.rs`) for the scripts
  `$where` is used for: one expression, or a function whose body is one `return` statement.
- The expressions: number, string, `true`, `false`, `null`, `undefined`, `NaN` and `Infinity` literals; `this` and
  `obj` for the document; the scope's variables by name; `.name` and `[key]` member access, `length` of strings and
  arrays; `!`, unary `-` and `+`; `* / % + -`; `< <= > >=`; `== != === !==`; `&&`, `||` and `?:`. Values follow
  JavaScript's rules for truthiness, number conversion, `+` on strings and loose equality.
- Documents, arrays, ObjectIds and dates compare by value with `==` and `===`, where JavaScript compares objects by
  identity; dates convert to their milliseconds for `<` and `>`.
- A script that does not parse, or is longer than 10,000 characters or nested deeper than 100 levels, fails the
  command with `JSInterpreterFailure` (139). A script that fails while it runs (a property of `undefined`) does not
  match that document, where MongoDB fails the whole command: matching runs where no error can be returned.
- Statements, loops, local variables, calls (`Math`, `Date`, string and array methods) and regular expressions are
  not supported yet; those scripts fail to parse rather than run differently.
