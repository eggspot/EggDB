## D1060 JetStream mirrors and sources from other servers — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D216, D811)

- A mirror or source may name `"external":{"api":"<prefix>"}`, as JetStream's stream configuration does for
  another domain or account. It is kept in the stream's configuration and written back in its info.
  The check that refuses a stream mirroring or sourcing itself applies only to origins on the same server, so
  `ORDERS` may source the hub's `ORDERS`.
- `eggdb serve --nats-remote <prefix>=<[user:password@]host:port>` names the NATS server that holds the origins
  with that prefix. There may be several. EggDB has no leaf nodes or JetStream domains yet, so the prefix
  selects a server and is not routed as a subject.
- Each second, after the in-server tick, the JetStream thread pulls every external origin:
  - It connects with a small client of its own (`remote.rs`: `INFO`, `CONNECT` with headers on, an inbox
    subscription, `PUB` requests, `MSG` and `HMSG` answers, `PING` answered with `PONG`).
  - It asks the remote's `$JS.API.STREAM.INFO.<stream>` for the last sequence.
  - It then reads up to 256 messages through `$JS.API.STREAM.MSG.GET.<stream>`, one per sequence.
  - A sequence the remote no longer holds is skipped. Filters and `opt_start_seq` apply as they do within one
    server.
  - Each message is stored through the publish path. Sources get the `Nats-Stream-Source: <stream> <seq>`
    header; mirrors keep the original headers.
- The next sequence for each origin is kept under its own key (`X` stream, prefix, origin), so a restart
  continues where the copy stopped. Deleting the stream removes that key.
- An unreachable remote is tried again on the next tick. Nothing it sends can panic the server: lengths are
  checked, payloads above 8 MiB are refused, and replies that cannot be parsed are skipped.
- Left out: pushing to the remote, flow control, and leaf-node routing of the prefix. These belong with clusters
  and leaf nodes (D216's line).
- Learned from: the public NATS client protocol and JetStream API documentation (stream source `external`, the
  `STREAM.MSG.GET` request).
