## D391 `pg_sequences.last_value` for identity columns — Decided by the code-only session (2026-11-10, D355); roadmap M6a

An identity column in EggDB has no stored counter: its next value follows the furthest value in
the table (D337, D364), and the catalog shows an implicit sequence `<table>_<column>_seq` for it.
That sequence's `last_value` was always NULL (`is_called` false). The catalog snapshot now reads
the furthest value the table holds (`partition_dml::furthest_in_table`: the key's last entry, a
leading index, or one scan) when it builds the implicit sequence, so `pg_sequences.last_value` is
that value, or NULL for an empty table, as PostgreSQL shows a sequence nothing has drawn from. A
partitioned table's root holds no rows, so its implicit sequence still shows NULL; the build pass
can count across its partitions. A deleted largest value makes `last_value` go back, where
PostgreSQL's counter does not (D337's known difference).

**Status:** code written, unbuilt (code-only mode, D355).
