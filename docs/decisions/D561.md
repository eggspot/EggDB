## D561 `knn` search over `dense_vector` fields — Decided by the code-only session (2026-11-11, D355); roadmap M8, D196

Elasticsearch 8's vector search is a `knn` section in the `_search` body; LangChain's,
LlamaIndex's and Kibana's vector stores send it. EggDB now answers it exactly (every document is
compared; there is no HNSW graph behind `dense_vector` yet, so `num_candidates` is read and
ignored):

- `knn` is one object or an array: `field`, `query_vector`, `k` (the search's `size` when left
  out; 1 to 10,000), `filter` (a query or an array of them that a document must pass first),
  `similarity` (a minimum score) and `boost`. A missing field or vector is a `parsing_exception`.
- The score follows the field's mapped `similarity` as Elasticsearch scores it: `cosine` (the
  default, also for unmapped fields) `(1 + cos) / 2`, `dot_product` `(1 + dot) / 2`, `l2_norm`
  `1 / (1 + d²)`, `max_inner_product` `dot + 1`, or `1 / (1 - dot)` when negative. Documents whose
  vector has another length or no direction (cosine of a zero vector) are skipped.
- Each section keeps its `k` best documents. With no `query`, the hits are those documents; with a
  `query`, the hits are the union, each scored by the sum of its query score and its kNN scores,
  as Elasticsearch combines them. `_count` counts the same documents.

Not yet: the mappings applied inside `knn.filter`, `rank` with reciprocal rank fusion, and
`script_score` with `cosineSimilarity`.
