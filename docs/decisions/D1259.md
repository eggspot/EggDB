## D1259 unnest(tsvector) — Decided by the code-only session (2026-11-18, D355); roadmap M4 PostgreSQL text search (D1230)

- **What users get.** `SELECT * FROM unnest(v)` with a `tsvector` returns one row per lexeme, in lexeme order, with PostgreSQL's columns `lexeme`, `positions` (`smallint[]`) and `weights` (the letters `A` to `D`), both NULL for a lexeme stored without positions. `WITH ORDINALITY` and column aliases work as for every other function in `FROM`.
- **How.** `unnest` keeps one entry in the set-returning functions; when its one argument is a `tsvector` it answers three columns instead of the array's element, and its rows come from the vector's weighted positions, the same ones `ts_filter` and `setweight` read.
- **Left.** `unnest(tsvector)` in the select list, which returns rows of the array kind only; `ts_stat`, which runs a query of its own and needs the session from inside a function.
- **Proof.** A test unnests a written vector with weights and a lexeme without positions, one from `to_tsvector` with its ordinality, and checks `unnest` of an array still returns its elements.
