## D712 InfluxQL SHOW SERIES, WITH MEASUREMENT, DROP MEASUREMENT, DROP SERIES and DELETE — Decided by the code-only session (2026-11-12, D355); roadmap M16, the rest of InfluxQL (D220, D521)

- `SHOW SERIES [FROM m] [WHERE ...]` lists series keys as InfluxDB writes them (`cpu,host=a,region=x`, tags sorted
  by key, empty tags left out), from the distinct tag values of each measurement, using D678's tag keys.
- `SHOW MEASUREMENTS WITH MEASUREMENT = name | != name | =~ /re/ | !~ /re/` filters the measurement list, the regular
  expression evaluated by the SQL engine as `FROM /re/` is (D676).
- `DROP MEASUREMENT m` drops the measurement's table and its recorded tag keys. `DELETE [FROM m] [WHERE ...]` and
  `DROP SERIES [FROM m] [WHERE ...]` delete the matching points from one measurement, or from every measurement
  without `FROM`; InfluxDB's rule that one of `FROM` and `WHERE` must be given is kept. They answer with an empty
  result, as InfluxDB does.
- `WHERE` here takes the same conditions as in `SELECT` (tags, fields, `time` with `now()` and durations, regular
  expressions).
- Still left: `SHOW TAG VALUES ... WITH KEY IN (...)` and `=~`, `SHOW FIELD KEY CARDINALITY` and the other
  cardinality statements, continuous queries and retention policy management.
