## D1278 More ODBC calls: functions, several result sets, statement attributes and diagnostic fields — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1236, D1255)

- **What users get.** `SQLGetFunctions` (one function, ODBC 2's array of 100, or ODBC 3's bitmap of 250 words, as Driver Managers ask before calling anything else), `SQLMoreResults` over a statement text that ran several queries (each result set in order), `SQLGetStmtAttr` (a forward-only, read-only cursor, one row at a time, no timeout or row limit, and the current row number), `SQLCancel`, `SQLFetchScroll` with `SQL_FETCH_NEXT` (other directions refused with HY106), `SQLDescribeParam` (text of unknown size and nullability) and `SQLGetDiagField` (the record count, return code and row count, and each record's SQLSTATE, native code, message and origins).
- **How.** A statement now keeps every result set its text produced: the first is read first, as ODBC expects, and the rest wait for `SQLMoreResults`; before, only the last was kept. The functions bitmap lists exactly the calls the driver exports.
- **Left.** Scrollable cursors and block fetches (`SQL_ATTR_ROW_ARRAY_SIZE` above 1), descriptors (`SQLGetDescField` and the rest), `SQLParamData` and `SQLPutData`, `SQLSetPos` and `SQLBulkOperations`, catalog calls over MySQL's protocol.
- **Proof.** The ODBC test reads the functions bitmap, walks two result sets with `SQLMoreResults`, and reads a failure's record count and SQLSTATE through `SQLGetDiagField`.

**Status:** code written, unbuilt (code-only mode, D355).
