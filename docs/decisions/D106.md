## D106 MySQL protocol: caching_sha2_password fast-auth, native as second; the MySQL dialect in the SQL core — Decided by research and the build loop (2026-10-27); roadmap item 22, applies D1, D5, D9, D10, D12, D20, D22, D35, D102

**The crate.** `eggdb-mysqlwire` speaks MySQL's client/server protocol from MySQL's public
protocol documentation (D1): packet framing with sequence ids and payloads of 16 MiB or more
split into frames, `HandshakeV10`, `HandshakeResponse41`, OK, ERR and EOF packets, text and
binary result sets. Like `eggdb-pgwire` (D103) it is generic over `eggdb_sql::KeyValueStore`,
runs one thread and one `eggdb_sql::Session` per connection (in the MySQL dialect), at most 64
connections (the 65th gets error 1040 in place of the handshake), at most 16 still
authenticating, reads with a deadline checked before every read and never more than 200 ms
per read, 30 s to finish authentication, packets before authentication up to 16 KiB and after
it up to `@@max_allowed_packet` (64 MiB, error 1153 beyond), a sequence id out of order ends
the connection with error 1156, and a stop ends idle connections with error 1053. `eggdb serve
--mysql-listen <address>` runs it beside the PostgreSQL listener on the same database, same
user and password; the address goes through the same loopback-only check (D102) in
`eggdb_mysqlwire::listen_on_loopback`. The small server pieces the two protocol crates share
(the loopback check, the slot counters, the login throttle, the log escaping) are duplicated
for now and move into one crate when the third protocol (item 23) needs them.

**Authentication (research, followed).** The handshake offers `caching_sha2_password`, MySQL's
default since 8.0, with a 20-byte nonce (bytes 1 to 127, as MySQL's are, since its second part
is zero-terminated). Only its fast path: the server keeps `H2 = SHA256(SHA256(password))`,
computes `x = SHA256(H2 || nonce)`, takes `H1 = response XOR x` and accepts when `SHA256(H1) =
H2`, compared in constant time; it answers `AuthMoreData 01 03` and OK, and never asks for full
authentication (`01 04`), which needs TLS or RSA. `mysql_native_password` comes second: the
server keeps `SHA1(SHA1(password))` and accepts `SHA1(password) XOR SHA1(nonce ||
SHA1(SHA1(password)))`. A client that names `mysql_native_password` (MariaDB's clients do) is
checked against the handshake's nonce directly, as a MySQL server does for an account of that
method (decided by judgement: the response was computed on our fresh nonce, and it saves a
round trip); a client that names any other method gets an `AuthSwitchRequest` to
`mysql_native_password` with a fresh nonce. A wrong password is error 1045 `Access denied for
user 'u'@'localhost' (using password: YES)`, after the same growing delay as PostgreSQL's
(D103), logged with the client's address. An unknown user goes through the same exchange
against credentials that match nothing. An empty response matches only an empty password, and
`eggdb serve` refuses an empty password. Both stored digests are unsalted, fast hashes,
weaker at rest than SCRAM's salted verifier: they let the server check a password, not log in,
and are derived at startup from `EGGDB_PASSWORD` or `--password-file` and kept in memory only
(nothing is written to the file); stored users with their verifiers come with D22's roles.
SHA-1 is our own in `eggdb-crypto` (FIPS 180-4, checked against FIPS 180's vectors, the
million-`a` message, every block boundary and split updates), used only where a protocol
requires it. Known-answer vectors for password `secret` and nonce bytes 1 to 20 are in the
crate's tests.

**Capabilities.** Offered: `LONG_PASSWORD`, `FOUND_ROWS`, `LONG_FLAG`, `CONNECT_WITH_DB`,
`PROTOCOL_41`, `TRANSACTIONS`, `SECURE_CONNECTION`, `MULTI_STATEMENTS`, `MULTI_RESULTS`,
`PS_MULTI_RESULTS`, `PLUGIN_AUTH`, `CONNECT_ATTRS`, `PLUGIN_AUTH_LENENC_CLIENT_DATA`. Not
offered: TLS (`CLIENT_SSL`; a client requiring TLS fails cleanly, one preferring it connects in
the clear on loopback), compression, `LOAD DATA LOCAL`, `DEPRECATE_EOF` (result sets end with
EOF packets) and query attributes. A client without `PROTOCOL_41` is refused. The server
version is `8.0.36-EggDB`, without "MariaDB", so clients take the MySQL 8.0 code paths.

**Commands.** `COM_QUIT`, `COM_INIT_DB`, `COM_QUERY` (several statements per query when the
client asked for `MULTI_STATEMENTS`, each result flagged `SERVER_MORE_RESULTS_EXISTS` but the
last; without it, a second statement is a syntax error before anything runs, as in MySQL),
`COM_PING`, `COM_RESET_CONNECTION`, `COM_STMT_PREPARE`, `COM_STMT_EXECUTE` (null bitmap,
new-parameters-bound flag, every fixed-width type, strings, and dates and times as text;
integers bound as `bigint`, floating point as `double`, strings untyped so their place types
them, D104; binary rows with the null bitmap at offset 2), `COM_STMT_SEND_LONG_DATA` (no reply,
up to 64 MiB per statement), `COM_STMT_RESET`, `COM_STMT_CLOSE` (no reply), `COM_SET_OPTION`
and `COM_FIELD_LIST`; any other command is error 1047 `Unknown command`. Column types follow
the values: `int`, `bigint`, `smallint`, `double`, `float`, `tinyint` for booleans (`1` and
`0`), `VAR_STRING` for text and for anything whose type is not known before the rows.

**The dialect.** `Session::with_dialect(store, Dialect::MySql)` reads MySQL's SQL on the same
tables: backtick identifiers (folded to lower case like unquoted names, which is
`lower_case_table_names = 1`, so `@@lower_case_table_names` reports 1, decided by judgement
over the research's 0 because it describes what the engine does), `"..."` strings and
backslash escapes, `#` and `-- ` comments, `/*! ... */` executed, `?` placeholders, `LIMIT
a, b`, `AUTO_INCREMENT`, `INSERT IGNORE`, `REPLACE`, `INSERT ... ON DUPLICATE KEY UPDATE` with
`VALUES(col)`, MySQL's types as aliases of the engine's (`TINYINT(1)` and `BOOLEAN` as
boolean, `TINYINT` and `SMALLINT` as `smallint`, `MEDIUMINT` and `INT` as `integer`,
`UNSIGNED` one size wider, `DECIMAL`, `NUMERIC` and `REAL` as `double` until the `numeric`
type exists, `CHAR(n)` and `VARCHAR(n)` as `varchar(n)`, the `TEXT` family as `text`; dates
and times wait for item 19d), `IFNULL`, `IF`, `CONCAT` (NULL if any argument is), `LENGTH` in
bytes, `UCASE`, `LCASE`, `DATABASE()`, `VERSION()`, `USER()`, `CONNECTION_ID()`,
`LAST_INSERT_ID()`, `DIV`, `MOD`, `/` in floating point, `<=>`, `||` and `&&` as `OR` and
`AND`, `!`, column names from the expression's text, `SHOW TABLES`, `SHOW DATABASES`,
`DESCRIBE` and `SHOW COLUMNS`, `SHOW CREATE TABLE`, `SHOW VARIABLES [LIKE]`, `SHOW WARNINGS`,
`SHOW COUNT(*) WARNINGS`, `SHOW STATUS` (empty), `USE`, `SET` of session and user variables
(unknown names are remembered; `SET GLOBAL` is refused), `@@var`, `@var`, `LOCK TABLES` and
`UNLOCK TABLES` accepted (one writer at a time already), and errors with MySQL's numbers,
SQLSTATEs and wording (`ERROR 1146 (42S02): Table 'db.t' doesn't exist`), translated from the
engine's at the session's edge. The system variables answer as the research listed them
(`@@version` `8.0.36-EggDB`, `@@version_comment` `EggDB`, `@@max_allowed_packet` 67108864,
utf8mb4 with `utf8mb4_0900_ai_ci`, MySQL 8's default `sql_mode`, `autocommit` 1,
`REPEATABLE-READ`, `SYSTEM` and `UTC` time zones, 28800 s timeouts, `license` `MIT OR
Apache-2.0`, `performance_schema` 0, the query cache off).

**Transactions as MySQL has them.** A failing statement inside a transaction does not abort
it: an error found before the statement wrote anything (a syntax error, a missing table) leaves
the transaction open, as in MySQL; one found after it wrote rolls the whole transaction back,
since the engine has no statement savepoints yet (a known difference). `SET autocommit = 0`
opens a transaction at the first write and keeps it until `COMMIT` or `ROLLBACK` (reads before
it see the latest commit); `CREATE TABLE`, `DROP TABLE` and `BEGIN` commit an open transaction
first, and `SET autocommit = 1` commits it.

**`AUTO_INCREMENT` in the file format (D20).** The column must be an integer, have no
`DEFAULT`, and be the first column of the primary key; the next value is one more than the
largest in the table (found by one backward step over the rows) or than the last given in the
statement, so a deleted largest value is used again (MySQL 8 does not reuse it; a known
difference until tables keep counters). A table with such a column is written as table
definition version 2, whose column default marker 2 means "numbered by the table"; every other
table stays version 1, byte for byte, and older EggDB releases refuse a version 2 definition
with their "written in format version 2" message rather than misreading it.

**The correctness suite.** `crates/eggdb-sql/correctness/mysql.test` (118 cases, from the MySQL
8.0 Reference Manual's documented behaviour, never MySQL's source) runs in the same runner as
PostgreSQL's (D105); its `error` lines may name MySQL's error number after the SQLSTATE. Three
cases are marked as differing and listed in docs/sql.md.

**Size (D6).** The binary grows by the MySQL server, the dialect and SHA-1; the growth is
measured by CI's `bench` job and reported in the pull request. The reason is roadmap item 22:
the `mysql` client and MySQL drivers connecting is one of the protocols D5 lists first.
