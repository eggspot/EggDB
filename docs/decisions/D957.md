## D957 A SQLAlchemy dialect and asyncio support for the Python driver — Decided by the code-only session (2026-11-13, D355); roadmap M6f, D16 and D182's ORM list

- **SQLAlchemy.** `eggdb.sqlalchemy` defines `EggDBDialect`, registered as `eggdb` when imported:
  `create_engine("eggdb:///app.db")` (`:memory:`, `?mode=ro`). It subclasses SQLAlchemy's own SQLite dialect and
  connects through the DB-API driver in EggDB's SQLite dialect, so SQLAlchemy's SQLite compiler, types and
  reflection (`sqlite_master`, `PRAGMA table_info`) are used unchanged, as EggDB answers them as SQLite does (D10). It
  is a thin layer in Python with no protocol or storage logic (D16). The DB-API module is handed to SQLAlchemy with
  the `sqlite_version_info` SQLAlchemy's SQLite dialect reads, set to the SQLite language level EggDB speaks; the pool
  is a single-thread pool for `:memory:`, as SQLAlchemy uses for SQLite's. Isolation is `SERIALIZABLE`, with
  `AUTOCOMMIT` mapped to the driver's `autocommit`.
- **asyncio.** `eggdb.aio.connect` gives an `AsyncConnection` and `AsyncCursor` with awaitable calls and `async for`
  over rows. Each connection owns one worker thread (the DB-API connection is `threadsafety = 1`), so the event loop
  never blocks on the database and no connection crosses threads.
- **Left.** Django's SQLite backend registers Python user functions (`django_date_extract` and others) through
  `sqlite3`'s `create_function`, which EggDB's DB-API driver does not offer yet; the Django backend waits for it.
- Tests: `tests/test_sqlalchemy.py` (Core, reflection and the ORM; skipped without SQLAlchemy) and `tests/test_aio.py`.
