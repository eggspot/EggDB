## D643 Transact-SQL numbered procedures — Decided by the code-only session (2026-11-12, D355); roadmap M10, D159, item 33d

Older SQL Server databases group variants of a procedure under one name: `CREATE PROCEDURE
orders;2 ...`, run with `EXEC orders;2` and dropped together with `DROP PROCEDURE orders`. The
feature is deprecated but still accepted, and EggDB refused such scripts.

- `CREATE [OR ALTER] PROCEDURE name;n` takes a number from 1 to 32767 (msg 2730 otherwise).
  `name;1` is `name` itself, and any other number keeps the routine under the name `name;n`. A
  function with a number is a syntax error, as in SQL Server.
- `EXEC name;n` resolves `name;n` in the same way, with arguments after it as usual. A `;` that is
  followed by anything but an integer still ends the statement.
- `DROP PROCEDURE name` drops `name` and every `name;n` of its group. An individual numbered
  procedure cannot be dropped alone, as in SQL Server.
- Not done: `sys.numbered_procedures` and `sys.numbered_procedure_parameters`. Each numbered
  procedure shows in the catalogs under its `name;n`.
- "Temporary functions" in item 33d stay refused, since SQL Server has none (`#name` functions are
  an error there).
- Test: `numbered_procedures_are_created_run_and_dropped_as_a_group`.
