## D554 `DateStyle` beyond ISO — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D19, sql.md

`SET DateStyle` was remembered as typed and every date was written in ISO. It now works as
PostgreSQL's does (`crate::date_style`):

- **The setting.** A list of an output style (`ISO`, `SQL`, `Postgres`, `German`) and a field
  order (`DMY`, `MDY`, `YMD`, with `EURO`/`US` spellings, and `DEFAULT` for `ISO, MDY`). A part left
  out keeps the current one, except that switching to `German` without an order also means `DMY`.
  The value is kept and shown in PostgreSQL's spelling (`SET datestyle TO sql, dmy` then
  `SHOW DateStyle` gives `SQL, DMY`, and that is the `ParameterStatus` clients see); an unknown
  word or two conflicting ones is `22023` with the list of values as a hint.
- **Output.** `date`, `timestamp` and `timestamptz` turned into text (results, casts to text,
  `COPY`) follow it: `SQL` writes `12/17/1997 07:37:16` (`17/12/1997` with `DMY`), `German`
  `17.12.1997 07:37:16`, `Postgres` `Wed Dec 17 07:37:16 1997` (`Wed 17 Dec ...` with `DMY`) and
  `12-17-1997` for a date; `timestamptz` adds the session zone's abbreviation (`PST`), or the
  numeric offset where the zone has none, and ` BC` comes last. Fractional seconds show as many
  digits as they need, as in ISO. `ISO` output is unchanged and takes the old path. JSON keeps
  ISO dates whatever the style, as PostgreSQL's does.
- **Input.** A date written with numbers in another order (`12/17/1997`, `17.12.1997`,
  `12-17-1997`, `97/12/17`), alone or before a time, is read by the setting's field order; a first
  field of three or more digits is always the year, and a two-digit year means 1970 to 2069. ISO
  input never reaches this step. Postgres style's `Wed Dec 17 07:37:16 1997` is not read back
  yet.
- **Cost.** Each date written or read in another order looks the setting up for the running
  statement, as `IntervalStyle` does.

**Status:** code written, unbuilt (code-only mode, D355).
