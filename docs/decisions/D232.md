## D232 User functions in WebAssembly run on our own interpreter, bounded per call — Decided by the build loop (by judgement, 2026-10-31); refines D1, D27 and D45

Track 4.X-4 asks for functions in any language compiled to WebAssembly, sandboxed by our own
interpreter, and loadable extensions.

- **Our own interpreter** (`eggdb-wasm-vm`), from the WebAssembly 1.0 core specification, with no
  third-party runtime (D1). It runs straight from the bytecode, with each block's `else` and
  `end` found once at instantiation. That keeps memory small and start-up instant, which suits
  short functions called from SQL. A compiler to native code can come later behind the same
  `Instance` interface.
- **Sandboxed by construction**: a module has no imports (no host functions yet), so it can
  compute only on its arguments and its own memory. Every call has **fuel** (one unit per
  instruction), a **memory ceiling** in pages and a **call-depth limit**. An infinite loop, a
  runaway recursion or a hostile `memory.grow` becomes a `Trap` returned as a value, never a hang,
  a crash or an exhausted server (D45). Malformed binaries are refused at parse time with an
  error, never a panic (D9).
- **This slice runs the integer instruction set**: `i32` and `i64` arithmetic, comparisons,
  conversions and sign extension; blocks, loops, `if`, `br`, `br_if`, `br_table`, `return` and
  calls; locals and globals; loads, stores, `memory.size`, `memory.grow`; and active data
  segments. Floating point, tables (`call_indirect`), imports, start functions and the bulk
  memory and SIMD proposals are refused at parse time for now.
- **The crate name.** `eggdb-wasm` is already EggDB built *as* WebAssembly (D221), so the
  interpreter that runs WebAssembly *inside* EggDB is `eggdb-wasm-vm`.

Left: floating point and the rest of the 1.0 instruction set, the official spec test suite in CI,
host functions (reading rows, logging) behind permissions, SQL integration (`CREATE FUNCTION ...
LANGUAGE wasm` with the module as `bytea`, and type mapping), extensions that add types and
index methods, a native-code compiler for hot functions, and benchmarks against other runtimes.
