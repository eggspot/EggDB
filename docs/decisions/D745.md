## D745 A semantic layer of metrics and dimensions in `eggdb_bi` — Decided by the code-only session (2026-11-12, D355); roadmap M11, a semantic layer used by BI and OLAP (D46, D238)

- `eggdb_bi` gains `models` (a name and a source table or query), `dimensions` and `metrics` (named SQL expressions
  over the model; metrics are aggregates), so each business measure is written once.
- `metric_sql(model, metrics[], dimensions[] [, filter, order_by, row_limit])` builds the query: the chosen
  dimensions and metrics with their names as columns, from the model's source, filtered, grouped by the dimensions,
  ordered and limited; unknown models, metrics and dimensions are errors (`42704`, `42703`). `metric_query(...)`
  runs it and returns the rows as a `jsonb` array, the shape reports and dashboards take.
- Filters and orders are SQL text run with the caller's own privileges, as the reports of D238 are. Joins between
  models, time grains, metric formulas built on other metrics, MDX and XMLA are left.
- Databases that installed `eggdb_bi` before keep the earlier objects; the semantic layer comes with a new
  `CREATE EXTENSION`.
