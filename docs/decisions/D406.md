## D406 MongoDB's `$expr` and `$lookup` with `let` and `pipeline` — Decided by the code-only session (2026-11-10, D355); roadmap M9

- **`$expr`** is a filter node holding an aggregation expression; a document matches when the
  expression is truthy (`false`, `null`, missing and numeric zero are not). It works in `find`,
  `update`, `delete`, `count`, `distinct` and `$match`. `$$NOW` and `$$CLUSTER_TIME` are bound once
  per command inside `$expr`, at the top level and under `$and`, `$or` and `$nor`
  (`filter_with_time`), as `pipeline_with_time` already does for `$match`. Known difference: an
  expression that fails at run time (a type error, an undefined variable) makes the document not
  match, where MongoDB fails the command.
- **`$lookup` with `let` and `pipeline`** reads the other collection once per stage, then for each
  input document evaluates the `let` expressions, binds `$$name` and `$$name.path` in the
  sub-pipeline to those values as `$literal`s (a missing value becomes `$$REMOVE`), and runs it over
  the other collection's documents. In `$match` the variables bind only inside `$expr`, as in
  MongoDB; they bind through nested `$lookup` and `$facet` sub-pipelines too. When `localField`
  and `foreignField` are given as well (MongoDB 5.0), the equality join narrows the documents
  before the sub-pipeline runs; giving only one of them is MongoDB's error. A `let` name must
  start with a lowercase letter or a non-ASCII character and hold only letters, digits and `_`.
  `$out` and `$merge` are refused in the sub-pipeline. The joined array is held to the document
  size budget.
