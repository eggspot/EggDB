## D453 `DISTINCT` in Oracle's window aggregates — Decided by the code-only session (2026-11-11, D355); roadmap M10

- Oracle allows `COUNT(DISTINCT x) OVER (PARTITION BY ...)`, and the other aggregates with
  `DISTINCT`, as long as the window has no `ORDER BY` (ORA-30487 otherwise); PostgreSQL refuses
  `DISTINCT` in any window function and still does. In Oracle's dialect the parser now keeps
  `DISTINCT` and passes it as part of the call's value treatment (`ValueTreatment::distinct`, beside
  `IGNORE NULLS` and `FROM LAST`, and encoded into the window call the same way), so it reaches the
  evaluator without a new field on the window specification.
- The evaluator feeds each frame's aggregate only the first row of each distinct value of the first
  argument (after the `FILTER`, when there is one); with no `ORDER BY` the frame is the whole
  partition, so the result is the aggregate over the partition's distinct values, as in Oracle.
- `LISTAGG (DISTINCT ...) OVER` and `KEEP` on `LISTAGG` go through `LISTAGG`'s own parser and are
  left.
