## D914 A MySQL client, and MySQL as a foreign source — Decided by the code-only session (2026-11-12, D355); roadmap M16 and M18, follow-up of D229 and D769

- `eggdb_mysqlwire::client` is a MySQL client written from MySQL's protocol documentation, like the server (D1): it
  reads the version 10 handshake, signs in with `mysql_native_password` or `caching_sha2_password`'s fast path (and
  follows an authentication switch to either), sends `COM_QUERY` and reads text result sets (column names, rows as
  text or `NULL`), several per query (`CLIENT_MULTI_RESULTS`), with packets split at 16 MiB joined and a 1 GiB limit
  per result. Every read is bounds-checked; damaged packets are errors, never panics. Its options print without the
  password, and a password in the URL is refused.
- Not yet: TLS, and `caching_sha2_password`'s full authentication, which needs TLS or the server's RSA key; the error
  says so and how to get past it (the server's cache filled by a TLS sign-in, or `mysql_native_password`).
- `eggdb_foreign('mysql://user@host[:port]/database', query)`, and so `eggdb_etl`'s scheduled copies, read MySQL: the
  last result with columns becomes JSON rows with every value as text, which the target's column types convert. The
  password comes from the password file (`EGGDB_FOREIGN_PASSFILE`) or `MYSQL_PWD`, as MySQL's own client reads it; an
  `EGGDB_FOREIGN_SOURCES` entry allows a source by host, port, user and (when it names one) database, as for the
  other databases.

**Status:** code written, unbuilt (code-only mode, D355).
