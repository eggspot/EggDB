## D812 A FIPS-only mode in TLS — Decided by the code-only session (2026-11-12, D355); roadmap D23, a mode that uses FIPS-approved algorithms only

- `ServerConfig.fips_only` and `ClientConfig.fips_only` (off by default) keep a connection to FIPS-approved
  algorithms: the AES-GCM suites only (ChaCha20-Poly1305 is not approved), and for key exchange P-256 (SP 800-56A) or
  the X25519MLKEM768 hybrid, whose ML-KEM-768 part is approved (FIPS 203) as the hybrid guidance allows. X25519 alone
  is not offered or accepted. TLS 1.2 keeps to P-256.
- The server picks suites and groups from the approved lists, and asks a client that sent only unapproved shares
  for an approved one with a HelloRetryRequest. The client offers only approved suites and groups and sends the hybrid
  and P-256 shares.
- `eggdb serve` turns it on for every TLS listener with `EGGDB_FIPS=1` (or `true`, `on`).
- This is a mode that restricts algorithms, not a FIPS 140-3 validated module: claiming that needs a CMVP
  certificate for EggDB's own crypto, which is left, as are logins (MySQL's SHA-1 `mysql_native_password`) and a
  `serve` option in place of the variable.

**Status:** code written, unbuilt (code-only mode, D355).
