## D125 Restoring a SQL Server script: SSMS Generate Scripts and sqlpackage scripts through `eggdb restore --dialect sqlserver`, sharing item 35's restore runner — Decided by the build loop (by judgement, by plan review and by research, 2026-10-29); roadmap item 40, applies D9, D13, D15, D96, D118, D119, D122, D123, D124

D13 puts SQL Server's generated scripts in the group EggDB restores directly, and its `.bak`,
`.trn`, BACPAC and `.mdf` files behind a documented route. Item 40 builds both, on item 35's
restore (D118) and the Transact-SQL dialect (D122, D123, D124). No file-format change.

**Two ways in.** `eggdb restore --dialect sqlserver` (`mssql`, `tsql`) runs a session in the
Transact-SQL dialect and restores the script statement by statement, each in its own
transaction, with item 35's `--create`, `--keep-going`, `--report` and exit codes. An SSMS script
also restores with `sqlcmd -i` against `eggdb serve --tds-listen`, which needs only engine syntax:
go-sqlcmd splits at `GO` and reads the UTF-16 byte-order mark itself (research, below). A
sqlpackage script restores only through `eggdb restore`: its `:on error exit` stops sqlcmd at the
first batch EggDB refuses.

**One restore runner for every dialect (item 43's requests).** `Restore` takes a `ScriptSource`
(`next_item`, `line_number`, `skip_data`, and the `COPY` channel the PostgreSQL reader alone
fills) and `RestoreRules` (the classifier, `table_key(name, default_schema)`, the name key for
skipped objects, the `WordRules` of its words, the client-command reasons, the known differences
of a statement and what counts as "not supported"). `RestoreRules::postgresql()` keeps item 35's
behaviour and its tests unchanged; `RestoreRules::sqlserver()` is new; item 43 adds
`RestoreRules::oracle()`. Every listed item carries `script`, an index into
`RestoreReport::scripts`. `DecodedLines` (UTF-8 and UTF-16LE, original bytes kept) is the line
source both script readers wrap. The CLI's dialect names come from one list, and content routes
are one `Archive::Binary { kind }` with a table of extension wording per dialect.

**Reading the script.**
- Text: a UTF-16LE byte-order mark (SSMS's "Unicode") is decoded as a stream, surrogate pairs
  across reads included; a lone surrogate or an odd byte count is an error naming the line. A
  UTF-8 mark is skipped. UTF-16 big-endian is refused with the `iconv` command. A `\r` inside a
  value is kept.
- `GO` ends a batch alone on its line (any case, indented, with a count and a `--` or closed
  `/* */` comment), outside strings, names and comments, a state carried across lines. `GO n`
  repeats the batch, with n times its bytes at most 1 GiB.
- sqlcmd commands are lines starting with `:` or `!!`. `:setvar` defines a variable (at most
  1,024), and `$(name)` is replaced, inside strings too, only in lines after the script's first
  sqlcmd command, so an SSMS script's data keeps a literal `$(x)`; an undefined one is sqlcmd's
  error. `:quit` and `:exit` end the script. `:r`, `!!`, `:connect` and the rest are listed and
  never run.
- **Statements in a batch.** A batch starting with a kind that takes the rest of it (procedure,
  function, trigger, view, `MERGE`, `IF`, `WHILE`, `DECLARE`, `BEGIN` other than `BEGIN TRAN`) is
  one statement, classified by its leading words and never tokenized, so a procedure using
  `#temp`, `{` or `$action` is skipped, never an error. Any other batch is tokenized by item 23a's
  lexer and its statements found by 23a's parser, through the one function `check_batch_syntax`
  uses. A statement the parser refuses ends at a `;` at depth 0 or at the next line whose first
  word starts a statement, and goes by its leading words: a kind EggDB skips or ignores is
  skipped or ignored; a `CREATE TABLE` loses its computed and `rowversion` columns and has its
  `IDENTITY(s, i)` reset to (1, 1), and is parsed again; a refusal that remains `0A000` or Msg
  195 or 2715 makes the object "not supported yet" (a table takes its rows with it, D118); any
  other error is a syntax error, and the batch part holding it runs nothing (SQL Server compiles
  a batch before running it). A batch the lexer refuses goes by its leading words the same way.
- **Memory (decided by research and judgement, changed from the plan).** SSMS writes many
  `INSERT` rows per batch, without `GO` between them (research). So the reader cuts a batch
  that does not take the rest of itself before a line starting `INSERT` or `SET IDENTITY_INSERT`
  once it holds 1 MiB, and a batch part over 4 MiB is split at those lines. A part over 4 MiB
  that is one `INSERT` (SSMS writes a large `varbinary(max)` value as one) runs as one statement,
  up to item 35's 1 GiB; any other is an error that says to add `GO`. Tokens take about 48 bytes
  each, so 4 MiB of text needs at most about 200 MiB of tokens; the plan's 16 MiB would have
  allowed 768 MiB. `GO n` after a batch that was cut is refused. A syntax error in one part of a
  cut batch does not stop the earlier parts (a known difference).

**Classification**, by leading words in SQL Server's terms (`classify_sqlserver`):
- **Runs:** `CREATE`, `ALTER` and `DROP` of tables, views, indexes and schemas; `INSERT` (with or
  without `INTO`), `UPDATE`, `DELETE`, `TRUNCATE`, `SELECT`; the `SET` options EggDB has;
  `SET IDENTITY_INSERT`; `ALTER TABLE ... [WITH CHECK|NOCHECK] ADD` and `CHECK CONSTRAINT`.
- **Skipped and listed:** procedures, functions, triggers, synonyms, types, sequences; users,
  logins, roles and their membership; rules and bound defaults; XML, spatial, columnstore and
  full-text indexes; server objects; `EXEC` of any procedure but the ones below; batch logic,
  once per batch, as "comes with item 47"; and **by default every leading word not on these
  lists** (`DBCC`, `MERGE`, `BULK INSERT`, ...) as "not supported yet".
- **Ignored and counted:** `USE`; `CREATE DATABASE` and every `ALTER DATABASE`; `GRANT`,
  `REVOKE`, `DENY`, `ALTER AUTHORIZATION`; transaction control; `PRINT`; extended properties;
  `sp_db_vardecimal_storage_format` and `sp_fulltext_database`; partition functions and schemes;
  `CREATE STATISTICS`, `UPDATE STATISTICS`, `ALTER INDEX`, `ALTER TABLE ... SET (...)`, `ENABLE`
  and `DISABLE TRIGGER`; `NOCHECK CONSTRAINT`; `SET` options EggDB does not have
  (`XACT_ABORT`, `NOEXEC`, ...) and the ON-only ones set `OFF`.
- **When a statement fails** (D118's rules, plus two): a constraint added over rows that violate
  it (`23505`, `23503` or `23514` from an `ALTER TABLE ... ADD CONSTRAINT`, keyed on SQLSTATE for
  item 43) is not created and listed as a known difference, its name remembered so that a later
  `CHECK CONSTRAINT` of it, Msg 4917, is a consequence; an `ADD DEFAULT ... FOR` whose
  expression EggDB cannot keep (D124's cut) is listed as "default not kept". Data statements are
  never consequences.

**Known differences**, a new list of the report, dialect-neutral: computed and `rowversion`
columns cut; `IDENTITY` seeds and increments reset to (1, 1) (40a's tier was cut, D124);
defaults not kept; each `datetimeoffset` column ("values are stored in UTC; their offsets are
lost"); each non-binary `COLLATE` per table (text compares by code point); an index's `INCLUDE`
columns, a non-unique index's filter and `DESC`; constraints disabled with `NOCHECK CONSTRAINT`
(enforced here) or not created over violating rows; `SET ANSI_NULLS`, `QUOTED_IDENTIFIER` or
`ANSI_PADDING OFF`. At most 10,000, then a count. Not noted: default-constraint names, extended
properties, filegroups and partitioning.

**Routes on content (D13).** Before any file is opened, from the first 64 KiB: `TAPE` (the
Microsoft Tape Format of `.bak` and `.trn`), `PK\x03\x04` (BACPAC, DACPAC or any zip), and NUL
bytes without a UTF-16 mark (`.mdf`, `.ndf`, `.ldf`, any binary) are refused with exit 2 and the
route: restore or attach it in a SQL Server you run, then Generate Scripts. The extension only
words the message, so a plain-text pg_dump named `backup.bak` still restores. A UTF-16 file
without `--dialect sqlserver` is refused with that advice.

**Engine syntax in the Transact-SQL dialect** (what both ways in need): `SET IDENTITY_INSERT`
(Msg 544, 545, 8101, 8106, 8107, 1088; explicit 0 and negative values kept; `SCOPE_IDENTITY`
sees them); `INSERT` without `INTO`; `CREATE TABLE` as SSMS and sqlpackage write it (`CLUSTERED`,
`NONCLUSTERED`, `ASC`/`DESC`, index options, `ON [fg]`, `TEXTIMAGE_ON`, `ROWGUIDCOL`, `COLLATE`
accepted with binary comparison, `NOT FOR REPLICATION`; `IGNORE_DUP_KEY = ON`, FILESTREAM,
sparse, masked, encrypted, memory-optimized and temporal tables are 40517); `ALTER TABLE ...
WITH CHECK|NOCHECK ADD` (`NOCHECK` still validates), `ADD DEFAULT ... FOR` as `SET DEFAULT` (rows
not filled, the name not kept), `CHECK CONSTRAINT n|ALL` (Msg 4917 when missing), `NOCHECK
CONSTRAINT` 40517; `CREATE [UNIQUE] [CLUSTERED|NONCLUSTERED] INDEX` with `INCLUDE` ignored, a
non-unique filter dropped, a unique `col IS NOT NULL` filter a plain unique index, any other
unique filter 40517; `DROP INDEX i ON t`; `CREATE SCHEMA ... AUTHORIZATION`; `SET
NUMERIC_ROUNDABORT OFF`; `TOP (100) PERCENT ... ORDER BY` in a view read as neither (Microsoft
documents that `ORDER BY` there only selects `TOP`'s rows).

**Decided by research (sonnet, before coding).**
- SSMS writes `INSERT [s].[t] (...) VALUES (...)` without `INTO`, many rows per batch, wrapped in
  `SET IDENTITY_INSERT`, and a line break inside a value as a raw CR LF, not `CHAR(13) +
  CHAR(10)`; so `CHAR(n)` (the plan's E9) stays a known gap. Confidence medium.
- sqlpackage's header is `:setvar`, `:on error exit`, the `__IsSqlCmdEnabled` check, `USE
  [$(DatabaseName)]` and `PRINT`s (high).
- go-sqlcmd 1.10.0 reads a UTF-16LE byte-order mark itself (`-f i:1200` is not needed), and
  supports `-x` and `-N disable` (high).
- SSMS saves as Unicode (UTF-16LE with a mark) with CRLF by default (medium).

**Fixtures** are written by us in the tools' shape, and their expected results by hand from the
scripts' data and Microsoft's documented semantics, never captured from EggDB. The SSMS sample
of the smoke test (`ssms-sample.sql`) is frozen at v0.2.0's tag (D96).
