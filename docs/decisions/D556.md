## D556 Materialized views are `relkind` `m` in `pg_class` — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D308

A materialized view is kept as a table plus a row in `eggdb_internal.materialized_views`, so
`pg_class` listed it as a table (`relkind` `r`). SQLAlchemy's `get_materialized_view_names` asks
for `relkind = 'm'` and its `get_table_names` for `'r'` and `'p'`, so it found the view among the
tables and not among the materialized views; psql's `\dm` missed it the same way. The catalog
snapshot now reads the registry's names once when it is built (`materialized_view_keys`, through
the same key spelling the session stores, `session::materialized_view_key_text`), and `pg_class`
gives `m` for those tables. Nothing else about the relation changes; `relispopulated` stays true,
including for a view made `WITH NO DATA`.
