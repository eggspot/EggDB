## D1046 Chaos testing of Raft clusters with eggdb-jepsen — Decided by the code-only session (2026-11-13, D355); roadmap M15 (D44, D252)

- `eggdb-jepsen` (D1029) gains `--cluster 1`: the three processes run as voters of one `serve --cluster` group
  (D1038), each with its RESP listener for the workload, instead of a primary with replicas. The workload and the
  check are unchanged: clients add unique elements to one set through whichever server accepts writes (followers
  refuse, fenced with the leader's id, so clients move on), and after healing every acknowledged element must be on
  the server that takes writes, nothing never written may appear, and every other server must hold exactly its set.
- The nemesis now also kills the current leader on purpose (one choice in six), slows the loopback network by 150 ms
  for six seconds with `tc netem` (`--delays 1`), and cuts the cluster port off with `iptables` in cluster mode. A
  server that stops by itself (a cluster node that finds its last writes as leader were lost, or that fell behind the
  compacted log) is restarted with `--cluster-seed`, as an operator would, and the history notes it.
- `jepsen.yml` runs three seeds of the cluster scenario after the replication ones, weekly and on demand, with the
  same summary and artifact.
- Clock skew between real processes needs a fake clock per process, which a standard runner does not offer; it is
  covered by the rebalancing simulation (D1045) and the hybrid-clock tests (D1042).
