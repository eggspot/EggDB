## D593 Stored scripts and stored search templates — Decided by the code-only session (2026-11-12, D355); roadmap M8, D196, D331, D348

Applications keep search templates on the cluster and call them by id (`"id": "by-title"`), and
keep update scripts there too. EggDB refused any `id` with "stored ... are not supported".

- `PUT` or `POST _scripts/<id>` (and `_scripts/<id>/<context>`) takes
  `{"script": {"lang": "mustache" | "painless", "source": …}}`.
  - A mustache source may be an object, kept as its JSON text.
  - The script is compiled when stored: mustache is rendered with no parameters, painless goes
    through `Script::from_node`. A bad one gets `script_exception`, and other languages
    `script_lang not supported`.
  - Scripts are kept under record kind 4 (`[4] + id`) in the Elasticsearch keyspace, as
    `lang \0 source`, at most 64 KiB, with an id of at most 512 bytes and no `#`.
- `GET _scripts/<id>` answers `{"_id", "found": true, "script": {"lang", "source"}}`, or 404 with
  `"found": false`. `DELETE` answers `acknowledged`, or 404 `resource_not_found_exception`.
- `_search/template`, `_msearch/template` and `_render/template` take `id`. It must name a mustache
  script and cannot come with `source`.
- `_update`, `_update_by_query` and `_delete_by_query` take `"script": {"id": …, "params": …}`. The
  server replaces it with the stored painless source and the request's params before compiling.
- A missing id answers 404 `unable to find script [<id>] in cluster state`, and a script of the
  other language answers 400.

Not done: `_script_context` and `_script_language`, and the Painless language beyond the update
subset, which is still left.
