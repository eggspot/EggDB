## D923 SPARQL `LOAD` from allowed URLs — Decided by the code-only session (2026-11-12, D355); roadmap M13, follow-up of D889

- SPARQL Update's `LOAD [SILENT] <iri> [INTO GRAPH <g>]` reads the document at the IRI and inserts its triples (into
  `g`, or the default graph; quads keep their own graphs) in the update's transaction. The format comes from the
  response's `Content-Type`, else the IRI's extension, else Turtle; blank nodes are renamed apart from the store's.
  `SILENT` turns a failure into no change.
- The engine never opens a connection itself (as D229 decided for `eggdb_foreign`): `eggdb-rdf` calls a fetcher the
  host installs with `eggdb_rdf::set_remote_fetch`, and refuses `LOAD` without one. The `eggdb` program installs one
  for `eggdb serve` and `eggdb sql --sparql` only when `EGGDB_SPARQL_LOAD` lists URL prefixes: a document is fetched
  (`GET`, with an `Accept` for the RDF formats, over `http://` or `https://` through the shared client, D920, at most
  256 MiB, 30 s) only when its IRI is under a listed prefix of the same scheme, host and port, with no `.` or `..`
  segments, so a query cannot make the server reach other addresses.
- `SERVICE` (federated queries) stays refused; it needs the same allow-list plus a results reader.

**Status:** code written, unbuilt (code-only mode, D355).
