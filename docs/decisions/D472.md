## D472 Elasticsearch aliases and more of `_cat` — Decided by the code-only session (2026-11-11, D355); roadmap M8, D196

- Aliases are keyspace records of their own (`3`, alias, `0`, index; the index and document
  records are `1` and `2`). `POST /_aliases` applies `add` and `remove` actions (`index`/`indices`,
  `alias`/`aliases`, index patterns) in one write, all or nothing; `PUT|POST /<index>/_alias/<name>`
  adds, `DELETE /<index>/_alias/<name>` removes (404 `aliases_not_found_exception` when missing),
  and `GET|HEAD /_alias[/<name>]` and `/<index>/_alias[/<name>]` answer
  `{"index":{"aliases":{...}}}`. An alias may not be named like an existing index, and deleting an
  index drops its aliases.
- Wherever a request names indices (search, count, `_msearch`, by-query, point in time), a name
  that is not an index but an alias reads every index the alias points to. Wildcards still expand
  over index names only, and writes through an alias (`is_write_index`), alias filters and routing
  are not written.
- `_cat/aliases`, `_cat/count[/<index>]` and `_cat/health` answer JSON rows like `_cat/indices`
  does.
- Index templates (`_index_template`) wait for mappings to be applied (the M8 mappings line), as a
  template is mostly mappings and settings.
