## D339 `eggdb export`, `import` and `restore` draw their progress on the shared progress line, and `eggdb ui`'s collection picker ends each counted row with its dim entry count, read from the kept counts only — Decided by the build loop (batch 6, 2026-11-10); roadmap M4, designed by Claude Fable (docs/ux/cli.md section 20 "The shared progress line", docs/ux/ui.md "Entry counts in the picker"), finishes D320's leftovers, applies D6 and D15

D320 kept each collection's entry count on every write and drew `eggdb collection delete`'s
progress through `cli/progress.rs`, but `export`, `import` and `restore` still had their own
copies of the line (`exported 1,204,000 entries…`, which read like a result and named nothing),
the picker showed no counts, and Claude Fable's review of D320's built text asked for five fixes.

- **One progress line.** `export`, `import` and `restore` draw through `ProgressLine`, with the
  design's rules: stderr only, only on a terminal, first after one second and then at most once
  a second, erased before the result line or an error; `--format json` does not silence it.
  - `export`: `exporting app.db: 1,204,000 entries…`; with `-C <name>`,
    `exporting collection cache of app.db: 120,000 of 1,000,000 entries…` when the collection
    keeps a count (read in the export's own read transaction), and the form without `of N`
    when it keeps none or the count is 0. No line when the export itself goes to stdout and
    stdout is a terminal, since it would land in the data.
  - `import`: `importing dump.eggdb into app.db: 1,204,000 entries…` (`stdin` for `-`), counting
    entries read from the export, skipped ones included. `--dry-run` reads
    `checking dump.eggdb: …`. An import from a regular file first checks the whole export
    without writing and then writes it, so its first pass shows the `checking` form and its
    second the `importing` form: each line says what the pass does.
  - `restore`: the same words as before
    (`restoring dump.sql: line 41,220, 14 tables, 1,180,002 rows…`), now drawn by the shared line.
- **Kept counts only.** `Database::kept_collection_counts` and
  `ReadTransaction::kept_collection_counts` give each collection's name with the entry count it
  keeps (`Option<u64>`, `None` for a collection made before D320 and not counted since). They
  read one record per collection and never a collection's keys, unlike `collection_stats`, and
  never write. `eggdb_ui::Source` gains `kept_collection_counts` with a default that gives every
  name `None`; the `eggdb` command implements it on the database.
- **The picker's counts.** Each counted row ends with its count, grouped with commas, never
  shortened, right-aligned to the picker's inner edge in the `Dim` role (the row's inverse when
  highlighted). The column is as wide as the widest count in the list. A row with a count gives
  its name `inner − 2 − (column + 2)` cells, cut with `…`; when that would leave a name fewer
  than 12 cells the column is left out for every row. The default key space and an uncounted
  collection end blank; with no counted row the picker is as it was. Counts are read with the
  names (opening the picker, after an add or a rename), so an added collection shows `0` and a
  renamed one keeps its count. The sidebar shows none.
- **Fable's five fixes to D320's text.**
  - The picker's title while adding or renaming cuts the old name with `…` and shows the end of
    the text being typed, so the text and the cursor stay in view.
  - The help's second Collections line reads
    `e renames; the dim number counts keys; Tab: sidebar at 110 columns`.
  - `eggdb collection list` pads names by display cells (`eggdb_ui::text_width`, now public), so
    wide characters line the counts up.
  - The drop's progress uses the form without a total when the kept count is 0, never
    `0 of no entries`.
  - The shell's refusal inside a block names `rename` too:
    `collection add, delete, move and rename run outside a transaction block: COMMIT or ROLLBACK first`.

Not in this release: cutting the progress line to the terminal's width; progress for the Redis
and `mongodump` restores and for `import --csv`/`--parquet`, which keep their own design.
