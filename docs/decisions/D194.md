## D194 memcached's protocol in our own eggdb-memcached, over the RESP server's keyspace interface — Decided by the build loop (by judgement, 2026-10-31); refines D48

Part 4.M7-5 asks for memcached clients (text and meta protocol).

- **`eggdb-memcached`**, written from memcached's published protocol description: the text
  commands `set`, `add`, `replace`, `append`, `prepend`, `cas`, `get`, `gets`, `gat`, `gats`,
  `delete`, `incr`, `decr`, `touch`, `flush_all`, `version`, `verbosity`, `stats`, `quit` with
  `noreply`, and the meta commands `mg` (flags `v`, `f`, `c`, `t`, `s`, `k`, `q`), `ms` (`F`, `T`),
  `md` and `mn`. Keys follow the protocol (1 to 250 bytes, no spaces or control bytes), items
  at most 1 MiB, `exptime` as the protocol defines it (relative up to 30 days, absolute after,
  negative already expired), and a CAS value per change.
- **Same keyspace interface as RESP.** It stores items through `eggdb_resp::Keyspace`, in the
  collection `memcached0` of the served file, each command one engine transaction; an item is a
  format byte, its flags, CAS value, expiry and data. The trait staying in `eggdb-resp` keeps
  one interface for the key-value servers; it moves to a crate of its own if a third one needs
  it without RESP.
- **Loopback only**: memcached's text protocol has no authentication (SASL is binary-protocol
  only), so `eggdb serve --memcached-listen` refuses other addresses.

Left: the binary protocol and SASL, the rest of the meta flags (`N` autovivify, `I` invalidate,
`E` explicit CAS, base64 keys), `stats` details, LRU eviction for memcached items (the RESP
wrapper's eviction can wrap it), and a memtier-style benchmark.
