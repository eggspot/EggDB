## D198 Restoring mysqldump files through the restore framework in the MySQL dialect — Decided by the build loop (by judgement, 2026-10-31); refines D13 and D106

Part 4.M10-1 asks that `mysqldump` output restores (`eggdb restore --dialect mysql`).

- **The same restore framework as PostgreSQL, SQL Server and Oracle scripts**, with a MySQL
  reader and classifier, so the report, `--keep-going`, staging and progress work the same. The
  reader splits statements as the `mysql` client does (the current delimiter, `DELIMITER`
  lines, quotes with backslash escapes, backquoted names, `--`, `#` and block comments) and
  keeps `/*!NNNNN ... */` comments in the statement, since EggDB's MySQL lexer runs their
  content as MySQL does. Written from MySQL's documentation of `mysqldump` and the `mysql`
  client; no MySQL code read (D1).
- **Statements run in the MySQL dialect as written.** The classifier only decides what to
  report and what to leave out: `LOCK TABLES`, `ALTER TABLE ... DISABLE/ENABLE KEYS`, `CREATE
  DATABASE`/`USE` (a file is one database), users, grants, and replication settings of GTID
  dumps (`@@GLOBAL.*`, `SQL_LOG_BIN`). Session settings such as `NAMES`, `TIME_ZONE`,
  `FOREIGN_KEY_CHECKS` and user variables run.
- **`--dialect mariadb`** is the same reader: `mariadb-dump` writes the same format, and its
  `/*M!` comments are left for a later slice.

Left: deferring foreign keys to tables created later (the effect of `FOREIGN_KEY_CHECKS=0`),
`/*M!` MariaDB comments, `mysqldump --tab` directories (`LOAD DATA` files), `--xml` output,
`mysqlpump` and MySQL Shell dump formats, the rest of 4.M10-1 (dates, `DECIMAL` and collation
completeness, `information_schema`, stored users), and a PyMySQL check of a restored file.
