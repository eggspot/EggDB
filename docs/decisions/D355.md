## D355 Code-only mode: every roadmap item written and merged first, built and fixed later in one pass — Decided (owner, 2026-11-10, through Main Chat); suspends D7's per-PR measurement, D80, D101's merge gate and the two review passes for this work, until the owner orders the build-and-fix pass

**The owner's order (2026-11-10).** "Just ignore build and test for now, in both eggdb and eggos
write all code for me and merge the main don't care ci build all code for all milestone have in
plan." One session writes the code of every open item in the roadmap's "What is left, per
milestone", in roadmap order, and merges it into `main` without building, testing,
benchmarking or waiting for CI.

**How it runs.**
- Batches of related items, each on its own branch, squash-merged with an admin merge after one
  self-review of the diff. Red CI and branch protection don't stop the merge.
- No `Release:` trailer (D353), no tags and no releases: nothing ships until the owner orders the
  build-and-fix pass, which builds, tests, benchmarks and fixes everything merged this way, and
  then releases.
- Every such PR says "unbuilt, untested (code-only mode)". The roadmap marks each item it covers
  "Code written, unbuilt", never done, and names what of the item is still left.
- The rest of CLAUDE.md holds: no comments in code, clean room and no third-party crates in what
  ships, no panics on input, `unsafe` with a `SAFETY:` comment per block, decisions recorded here.

**Batch 1 (M1, platform layer).**
- kqueue: adds are queued and handed to the waiting `kevent` call as its change list, so a wait
  costs no separate change call (D74). A cancel before the wait drops the queued add without a
  call; deletes still go out at once, while the socket is open. A refused change comes back as
  an `EV_ERROR` event and fails that direction's waiters with its error; if the combined call
  fails outright, the changes are retried one at a time so each failure names its socket.
- `poll(2)` backend: connects start non-blocking on FreeBSD, NetBSD, OpenBSD, DragonFly, illumos
  and Solaris, with each system's `sockaddr` layout and `EINPROGRESS`.
- `eggdb_platform::accept_tcp` accepts and, on macOS and NetBSD, copies the listener's
  keep-alive timing that those systems don't copy (D336). Every server's accept loop uses it.
- Uncached opens read the device's direct-I/O alignment (`statx`'s `STATX_DIOALIGN` on Linux 6.1
  and later, `FILE_STORAGE_INFO`'s logical sector size on Windows) and are refused with
  `Unsupported` when it does not divide `AlignedBuffer::ALIGNMENT`, so the caller falls back to
  cached I/O instead of failing every read.
- Pinning and the CPUs a thread may use on FreeBSD (`cpuset_*affinity`, 1024- then 256-bit
  masks), DragonFly and NetBSD (`pthread_*affinity_np`; NetBSD refuses unprivileged pinning by
  default, which comes back as the error), and their topology by counts (`hw.ncpu`,
  `kern.smp.cores`).
- Solaris file locks: POSIX `F_SETLK` locks on the whole file, plus a process-wide table by
  device and inode so two handles in one process conflict as on every other system. A POSIX lock
  is dropped when the process closes any descriptor of the file, so EggDB must not open its
  locked file twice on Solaris.
- IOCP file queue: operations in flight are tracked by address, and a packet that names none of
  them (one for an operation that finished at once) is ignored instead of freeing it twice.
