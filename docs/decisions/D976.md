## D976 A weekly sqllogictest job publishing EggDB's pass rate — Decided by the code-only session (2026-11-13, D355); roadmap M5, D45 and D664's published rate

- `.github/workflows/sqllogictest.yml` runs on Saturdays (with the weekly performance pass, D7) and by hand. It clones
  sqlite.org's sqllogictest corpus with `fossil` (public-domain test data, fetched at run time, never in the repo or a
  release), builds D664's runner in release mode and runs it over the corpus's `test` directory. Each file's rate and
  the total go to the step summary and to a 90-day artifact, which is where the rate is published.
- The minimum is `SQLLOGICTEST_MINIMUM` (a repository variable, or the manual run's input), 0 until the first run
  measures the rate; the Saturday pass then states it, and it only rises (D45). The job is not part of `check`: the
  corpus is large (four hours at most) and it gates the rate, not pull requests.
- The workflow is new and does not touch `ci.yml`; it follows the CI rules for a public repo: standard runner, a
  timeout, no cancelling of a running scheduled job, a shallow checkout and the shared cargo cache.
