## D1284 SQLSetPos positioning and cursor names — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1279, D1282)

- **What users get.** `SQLSetPos(stmt, row, SQL_POSITION, ...)` makes row `row` of the rowset a block fetch returned the current row, so `SQLGetData` reads it, as applications do to read long columns of each row of a rowset; `SQLSetCursorName` and `SQLGetCursorName` name the cursor (the driver's own names start with `SQL_CUR`, which an application's name may not). `SQLGetFunctions` lists the three.
- **How.** The cursor is read-only, so the other `SQLSetPos` operations (refresh, update, delete, add) are refused with HYC00; a row outside the rowset is HY107 and positioning before any fetch 24000.
- **Left.** Positioned updates and deletes (`WHERE CURRENT OF` and `SQLSetPos`'s write operations) and `SQLBulkOperations`.
- **Proof.** The ODBC test reads the second row of a two-row rowset through `SQLSetPos` and `SQLGetData`, is refused a row past the rowset and an update, and names a cursor.

**Status:** code written, unbuilt (code-only mode, D355).
