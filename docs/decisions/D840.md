## D840 An admin API with the MCP tools' actions — Decided by the code-only session (2026-11-12, D355); roadmap M6c, D11 and D25

- `eggdb serve`'s MCP listener (`--mcp-token-file`) also answers plain REST: `GET /admin/tools` lists the tools as
  `tools/list` does, and `POST /admin/tools/<name>` with the tool's arguments as a JSON object body calls it and
  answers its result (200), a tool error (422, `isError`) or a JSON-RPC error object (400). So scripts and
  dashboards get every MCP tool's action without speaking JSON-RPC, under the same rules.
- Same rules as `/mcp`: a Bearer token from the token file (each token's role, time limit, writes setting and
  `calls_per_minute` quota apply), requests with an `Origin` header refused, every call in the audit file. Each
  admin call runs in a fresh MCP session that is initialized for it and dropped after; a destructive `write_sql`
  needs `"confirm": true` in its arguments, as for a client that cannot be asked.
- Left: admin actions that are not MCP tools yet (backup, restore, user management).

**Status:** code written, unbuilt (code-only mode, D355).
