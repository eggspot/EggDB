## D538 AMQP 1.0 dynamic nodes — Decided by the code-only session (2026-11-11, D355); roadmap M16

An AMQP 1.0 `attach` whose source (for a receiving client) or target (for a sending client) has
`dynamic: true` now gets a queue the server names, as request/reply clients (Qpid JMS temporary
queues, the .NET and Python clients' `create_dynamic_receiver`) expect, where the link was refused
for having no address.

- **Naming:** each dynamic node is a new queue `amq.dynamic-<n>`, numbered with the counter AMQP
  0-9-1's server-named queues use (`amq.gen-<n>`), and the attach reply's terminus carries that
  address, so the client learns where replies go.
- **Lifetime:** dynamic queues live as long as the connection that made them, the expiry
  AMQP's default `session-end` policy gives in practice, and are deleted with whatever they hold
  when it ends; a connection makes at most 1,000.
- **Left out:** `dynamic-node-properties` (lifetime policies, supported distribution modes) and
  the other `expiry-policy` values, and the rest of this roadmap item: annotations and
  properties end to end, transactions, link resumption, `amqp:modified`'s delivery-failed counts
  and enforcing `idle-time-out`.

**Status:** code written, unbuilt (code-only mode, D355).
