## D1283 More ODBC column attributes — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1236, D1278)

- **What users get.** `SQLColAttribute` (and its wide form) answers the fields report and spreadsheet tools ask for each column before showing it: the concise type, type name and local type name, display size, length and octet length, precision, scale, radix, unsigned, case sensitivity, searchability, updatability, auto-increment, fixed precision, the base column name, empty table, schema and catalog names, literal prefix and suffix, and ODBC 2's `SQL_COLUMN_*` forms of them. Before, every field but the name, type, count and nullability failed, which tools such as Excel's Microsoft Query treat as a broken driver.
- **How.** A column's ODBC type comes from its values as before (`BIGINT`, `DOUBLE PRECISION`, `VARCHAR`, `VARBINARY`); fixed types have their fixed sizes (a `BIGINT` shows in 20 characters, 19 digits, 8 bytes), and text and binary columns are as long as their longest value in the result, at least 1. A column number out of range is 07009 and an unknown field HY091. `SQLDescribeCol` gives the same precision as the column size, where it gave 0.
- **Left.** The table, schema and catalog a column comes from, and declared types and lengths from the catalog rather than from the values.
- **Proof.** The ODBC test reads a text column's type name and length, a number's display size and signedness, and is refused a column that is not there.

**Status:** code written, unbuilt (code-only mode, D355).
