## D105 `eggdb shell` and the query screen reuse the UI's terminal layer and the `sql` command's printers; the correctness suite is a table-driven file per dialect — Decided by the build loop (2026-10-27); roadmap item 20, designed by Claude Fable (D15)

**One terminal layer.** The shell reads lines with `eggdb-ui`'s own pieces: the escape-sequence
decoder, the single-line editor (gaining `replace` and `delete_word_before`) and a new
`LineReader` (readline keys, history with `Up`/`Down` and `Ctrl-R`, `Tab` completion, pastes
sent line by line). The platform layer gains `RawTerminal::enter_inline`: raw mode on the
normal screen with bracketed paste and the cursor shown, restored with its own sequence (the
alternate screen's restore would move the cursor). Raw mode is on only while a line is read,
so a statement runs with the terminal as every `eggdb` command finds it, and `Ctrl-C` during a
statement keeps the CLI's meaning (exit 130). Per-user files (`eggdb_platform::user_files`) are
platform code: the state directory by each system's convention (`$XDG_STATE_HOME/eggdb`, else
`~/.local/state/eggdb`; `%LOCALAPPDATA%\EggDB`), directories 0700 and files 0600 on Unix.

**One set of commands and printers.** A key-value line at the prompt is parsed by the CLI's own
argument parser and run by the same command code on the shell's open database (an `Opened`
handle, owned or shared), so its output, errors and exit codes are the command's. SQL results
and errors are printed by the functions `eggdb sql` uses, now shared with the shell (table,
expanded and CSV modes) and with the UI's query screen (`error_lines`, `result_cells`). The SQL
crate gains `Session::tables` and `TableSchema` for `.tables`, `.schema` and completion.

**As built, where the design could not be followed in this release.** Key-value writes inside an
open `BEGIN` block fail with the busy error instead of joining the block: the block holds the
database's one write transaction and the key-value commands open their own. The banner leaves
out the key count, which only a full scan gives. The query screen runs a script on the UI's
thread (a statement cannot be cancelled yet, so a worker would only animate a wait), and shows
engine errors as error lines. The editor's hint bar names `F1 help` and `Ctrl-C quit`, the keys
that work while typing.

**The correctness suite.** `crates/eggdb-sql/correctness/<dialect>.test` holds one case per block:
`ok`, `rows` with the expected output, or `error <SQLSTATE>`, each under a `chapter` line naming
the PostgreSQL manual's chapter it comes from; the expected results are the manual's documented
behaviour, never PostgreSQL's source. The runner takes the dialect's name, so items 22 to 25 add
their files. A case EggDB does not match yet is marked `... differs`, keeps the documented
expectation, and must be listed in docs/sql.md "Known differences" with a roadmap line; the
runner fails when a marked case starts to match, so the mark and the doc are removed with the
fix. Fewer than one case in ten may be marked.
