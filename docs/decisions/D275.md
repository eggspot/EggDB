## D275 The query tab runs: statements split by each dialect's own rules, runs go off the window's thread on one session through `Connection::run_script`, and the results grid is virtualized, keyboard-driven and copies to a `Clipboard` — Decided by the build loop (EggAgentCode task 20261103-0137, 2026-11-03); roadmap M6e, applies D8, D9, D10, D15, D191 and D256, builds sections 2 and 3 of `docs/ux/workspace.md`

Until now the main window drew `docs/ux/gui.md`'s golden frame from fixed strings: one line of
SQL, a hand-placed result and a summary nobody computed. Sections 2 and 3 of Fable's
`docs/ux/workspace.md` say how the query tab and the grid behave. This decision builds them.

- **The tab is state, the frame stays a pure function of it.** `QueryTab`
  (`crates/eggdb-gui/src/query_tab.rs`) holds the editor, the dialect, the dialect menu, the
  focus (editor, dialect pill, grid), the results header's segment (`Results` or `Messages`),
  the last result in a `ResultGrid`, the `Messages` lines, the inline error, and the strings the
  summary and the status bar show. `MainWindow` holds one `QueryTab`; `MainWindow::sample()`
  builds gui.md's golden state through it, so the golden frame keeps its pixels.
- **One lexer per dialect, shared by the highlighter and the splitter.** `highlight::lex`
  knows each dialect's strings and quoted names (MySQL's backticks, backslash escapes and
  double-quoted strings; SQL Server's and SQLite's brackets), comments (MySQL's `#` and `-- `,
  nested `/* */` in PostgreSQL and SQL Server) and PostgreSQL's dollar quotes, and carries an
  open one across lines (`Carry`). The highlighter colours its runs with the base keywords plus
  each dialect's own (`LIMIT` everywhere, `TOP` in SQL Server, `PRAGMA` in SQLite), so switching
  the dialect re-highlights the same text. `statements::statements` and
  `statements::statement_at` split on the `;` the lexer finds outside those; in Oracle and SQL
  Server a `BEGIN`/`DECLARE` block or a `CREATE PROCEDURE` (`FUNCTION`, `TRIGGER`, `PACKAGE`)
  runs to a line holding only `/` or `GO`. A caret just after a line's last `;` runs the
  statement before it.
- **Running never blocks the window.** `Ctrl/Cmd+Enter` and `F5` run the selection's
  statements or the statement under the caret, `Ctrl/Cmd+Shift+Enter` all of them. `Workspace`
  moves the `Connection` into a worker thread and takes it back with the outcomes; `tick` polls
  for them and moves `Running · 1.2 s` on. `Connection::run_script` runs the statements one
  after another on one session in the tab's dialect (so a `BEGIN` holds for the next statement
  of the same run) and stops at the first failure. `CancelHandle` stops it from the window's
  thread: a file's session gets the engine's `CancelSignal`, a server PostgreSQL's cancel
  request sent from its own thread; a cancel that comes before the run starts stops it as soon
  as it starts. `Esc` (`Cmd+.`) shows `Stopping…`, then `Stopped · N rows (partial)`.
- **The status strings are one module.** `status_line` formats every summary of 2.4 (`3 rows ·
  0.4 ms · 1.2 KB`, `INSERT 0 2 · 0.3 ms`, `5 statements · 3 rows · 12 ms`, `100,000 rows
  shown of 2,104,311 · 1.40 s · 8.2 MB`, `Stopped · …`), the banner, the selection and copy
  toasts, and the spoken form for the live region (`3 rows, 0.4 milliseconds`). Bytes count the
  rows as PostgreSQL `DataRow` messages.
- **Errors are the engine's.** `StatementFailure` now carries the error's byte position and the
  lines `eggdb sql` prints; those lines come from `eggdb::sql::error_lines`, moved there from the
  CLI so the GUI and the CLI print the same text. The error's position (offset by the
  statement's start in the editor) puts the caret, the squiggle under the token there and the
  strip `Error 42P01: … · Ln 1, Col 15` with `Fix: …` from the engine's hint; `Esc` hides the
  strip, editing the line clears both, and `Messages` shows the lines.
- **The grid draws only what is in view.** `ResultGrid` (`grid.rs`) keeps the fetched rows, the
  total, column widths (`column_widths`), the scroll position, the current cell and the
  selection's anchor. Drawing and the accessibility tree take only `visible_rows` and
  `visible_columns`, so a million-row result costs one screen of cells. A result keeps at most
  `ROW_LIMIT` (100,000) rows and counts the rest for the banner. Columns know their
  `ValueKind` (from the engine's values for files, from type OIDs for servers), which right-aligns
  numbers and TTLs and draws `NULL`, blobs, vectors and TTLs as 3.2 says.
- **Keys and copies.** Arrows, `PgUp`/`PgDn`, `Home`/`End` (with `Ctrl/Cmd` the first and last
  row), `Shift` to extend, `Shift+Space`, `Ctrl/Cmd+Space`, `Ctrl/Cmd+A`, `Esc`, and `Tab` leaving
  the grid. `Ctrl/Cmd+C` copies TSV, `Ctrl/Cmd+Shift+C` with the header, `Ctrl/Cmd+Shift+I` one
  `INSERT` per row in the tab's dialect (its quoting of names, strings, booleans and blobs), into
  the source table when the query read one. Copies go to the `Clipboard` trait
  (`clipboard.rs`); `MemoryClipboard` holds them until the platform layer's clipboard arrives.
  The platform layer's `Key` gains `PageUp`, `PageDown`, `F2` and `F5` on every backend.
- **Accessibility.** `main_window::accessibility_tree` gives the toolbar's buttons (disabled
  while running), the dialect pill with its value, the tab (`Query 1, running`), the editor, the
  error strip, the result segments, the status line's spoken summary, the banner, the grid with
  its counts and selection, its visible headers and cells (`null`, `blob, 2 bytes`) and the
  current cell focused. It uses today's roles (`Group`, `Heading`, `Status`); D278 gives them
  the grid, cell, combo box and alert roles.
- **Tests.** Unit tests cover the lexer per dialect, statement splitting and the statement under
  the caret, the source table, every status string, TSV and `INSERT` quoting, the virtualization
  ranges, grid keys and the frame's menu and running states. `tests/query_tab_frames.rs` opens a
  temporary file and runs through the keyboard: the second of two statements, `Run all`, the
  grid's frame and tree, copies on the clipboard, the `42P01` error's squiggle and strip, the
  100,001-row banner, `Esc` stopping `pg_sleep`, and the binary's `--run`.

Not yet: rows streaming into the grid as they arrive and pages fetched on scroll (the engine and
the PostgreSQL client return a statement's rows at once, so the grid holds up to the cap and
draws no `Loading…` placeholders), `· 12,400 rows so far`; the session kept between runs (each
run opens one session, so a `BEGIN` does not outlast its run), and server runs in a dialect
other than PostgreSQL; the spinner's motion and the sweeping bar (static ring and bar for now);
`Ctrl/Cmd+T`/`W` and more tabs, the `Fix:` button opening `Fix 1`; the full-value popover
(`Enter`/`F2`), the right-click menu, pointer selection, column resizing and the scrollbars;
editor scrolling beyond the caret rule and horizontal scrolling; column widths measured with the
drawn face (8 px per character for now); the popover's soft shadow; the toast as its own
surface (it shows in the status bar); the platform clipboard (D279).
