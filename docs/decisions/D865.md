## D865 pgRouting's many-to-many forms — Decided by the code-only session (2026-11-12, D355); follow-up of D831 and D832

- `pgr_dijkstra` gains pgRouting's array overloads: one to many (`bigint, bigint[]`, with an `end_vid` column), many
  to one (`bigint[], bigint`, with `start_vid`) and many to many (`bigint[], bigint[]`, with both). Each reads the
  edges query once, then runs EggDB's Dijkstra for every distinct start and end pair in ascending order, skipping a
  pair whose start is its end and NULL ids, as pgRouting does; `seq` counts across the whole result and `path_seq`
  within each path.
- `pgr_dijkstraCost` gains the many-to-many form (one row per reachable pair with its total cost), and
  `pgr_dijkstraCostMatrix(edges_sql, vids)` returns the costs between every ordered pair of the given vertices.
- They are SQL and PL/pgSQL in the extension script, over the existing `eggdb_route_dijkstra`, so no new Rust graph
  code is involved. Databases that created the extension earlier get them after `DROP EXTENSION` and `CREATE
  EXTENSION`.
- Left: `pgr_analyzeGraph`, `pgr_nodeNetwork`, TSP and the other pgRouting functions, and `combinations` SQL forms.
