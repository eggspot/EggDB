## D595 Script sorts, nested sorts and unmapped sort fields — Decided by the code-only session (2026-11-12, D355); roadmap M8, D348, D518

Search UIs sort by computed values (`_script`), sort parents by a nested field (`offer.price` with
`nested`), and rely on Elasticsearch refusing a sort on a field no index maps unless the request
names an `unmapped_type`.

### `_script` sorts

- `{"_script": {"type": "number" | "string", "script": …, "order": …}}` compiles the script as a
  `ValueScript`: one Painless expression, optionally after `return` and before `;`.
- The Painless subset gains document reads:
  - `doc['field'].value` reads the smallest of the field's values, as Elasticsearch's sorted doc
    values do, with `.keyword` falling back to the field itself.
  - `doc['field'].size()`, `.length`, `.empty` and `.isEmpty()` read the count.
- A document the script fails on, such as one without the field, sorts as missing.
- `type` decides how values compare, as numbers or as strings. `mode` and `nested` are accepted and
  ignored.
- Update scripts can read `doc[...]` too. `search_after` reads a `_script` column as its type.

### Nested sorts

A field sort takes `nested` and ignores it. A field path already reads every object of an array
of objects, so `offer.price` with `mode` picks among all the offers' prices. `nested.filter` is not
applied.

### Unmapped fields

- Before scoring, a search refuses (400 `No mapping found for [<field>] in order to sort on`) a
  sort field when all three hold: no searched index maps it, no searched document holds it, and
  the request gives no `unmapped_type`.
- With `unmapped_type`, the field sorts as missing everywhere.
- A search over no documents is not refused, since it cannot tell an empty index from no index.
- `.keyword` names count as mapped, as dynamic mapping adds them.
