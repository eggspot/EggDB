## D122 SQL Server's TDS protocol and a first Transact-SQL dialect: TDS 7.4 without encryption, SQL logins, names folded to lower case with `dbo` as `public`, SQL Server's batch rules and error numbers — Decided by the build loop and by research (2026-10-28); roadmap item 23a, applies D1, D5, D9, D10, D12, D22, D35, D43, D102, D106, D108, D111

**The crate.** `eggdb-tdswire` speaks SQL Server's Tabular Data Stream protocol, version 7.4,
from Microsoft's public [MS-TDS] specification (D1): packets of an 8-byte header (type, status
with the end-of-message bit, big-endian length, SPID, packet id, window), PRELOGIN, LOGIN7, SQL
batches and the token stream (LOGINACK, ENVCHANGE, INFO, ERROR, COLMETADATA, ROW, DONE). Like
`eggdb-pgwire` (D103) and `eggdb-mysqlwire` (D106) it is generic over
`eggdb_sql::KeyValueStore`, runs one thread and one `eggdb_sql::Session` in the SQL Server
dialect per connection, at most 64 connections and 16 still logging in, 30 s to log in, reads
with a deadline checked before every read and never more than 200 ms per read, messages before
login up to 64 KiB and SQL batches up to 64 MiB (MySQL's packet limit, D106), read in 64 KiB
steps. `eggdb serve --tds-listen <address>` runs it beside the other listeners, on the same
database, user and password, loopback only (D102). The server pieces the three protocol crates
share (the loopback check, the slot counter, the login throttle, the log escaping) are copied a
third time to keep this change small; one shared listener crate is a roadmap item after v0.2.0.

**No encryption.** PRELOGIN answers `ENCRYPT_NOT_SUP` (0x02). Per the table of [MS-TDS] 2.2.6.5,
a client that sent `ENCRYPT_OFF` (go-sqlcmd's default, `-N disable`, SqlClient's
`Encrypt=false`) then runs with no encryption at all; a client that sent `ENCRYPT_ON`,
`ENCRYPT_REQ` or the certificate bit ends the connection itself after the answer, which the
server also closes, so no client that asked for encryption is ever served in the clear. A
connection that starts with a TLS record (TDS 8, `encrypt=strict`) is closed with a log line.

**Logins.** Only TDS 7.4 (`04 00 00 74` in LOGIN7's little-endian DWORD; LOGINACK sends
`74 00 00 04`); an older version is refused with error 18456 and a log line naming it. SQL logins
only: integrated (SSPI) and federated logins and password changes are refused with 18456. The
password arrives obfuscated (each byte's halves swapped, then XOR 0xA5, [MS-TDS] 2.2.6.4), so
the server keeps `PBKDF2-HMAC-SHA-256(password, salt, 4096)` with a 16-byte random salt, derived
at startup and held in memory only (`TdsCredentials`), recomputes it from the decoded password
and compares in constant time; an unknown user is checked against stand-in credentials with the
same work and gets the same `Login failed for user '...'`. The decoded password and the LOGIN7
buffer are overwritten after use. User, password and database are at most 128 characters; the
database must be empty or the served name in any case (`4060` otherwise). The 65th connection
is answered after its LOGIN7, without a password check, with error 17809.

**Types on the wire.** `smallint`, `integer`, `bigint` as INTN; `real` and `double` as FLTN;
`boolean` as BITN; `numeric(p ≤ 38, s)` as DECIMALN; `timestamp(p)` as DATETIME2N (so `GETDATE()`
has its type); `bytea` as BIGVARBINARY; text as NVARCHAR, fixed only when the column's longest
value or declared length is at most 4,000 UTF-16 code units, otherwise `nvarchar(max)` as PLP.
A column with any value the TDS type cannot hold (a date outside years 1 to 9999, NaN, an
unconstrained `numeric`, mixed types) and the types item 39 brings (`date`, `time`,
`timestamptz`, `uuid`, JSON, intervals) go as NVARCHAR text. The collation reported is
Latin1_General_100_BIN2, since comparisons in this version are binary.

**Requests.** SQL batches only: ALL_HEADERS must hold exactly one transaction descriptor header
(read, not enforced in this version) and each header type at most once. RPC, transaction
manager and bulk load requests answer error 40517 (items 23b and 46). Attention is answered with
DONE(ATTN) at request boundaries; a running batch finishes first. RESETCONNECTION status bits
are tolerated and ignored until 23b. Transaction changes are reported with ENVCHANGE 8, 9 and 10
when the session's transaction state changes, and never for a change of `@@TRANCOUNT` alone.

**The dialect.** `Dialect::SqlServer` (`--dialect sqlserver`, also `mssql` and `tsql`) is a fifth
branch of the same lexer, parser and session (D10):
- `[brackets]` with `]]`, `"..."` names (QUOTED_IDENTIFIER is always on; `SET QUOTED_IDENTIFIER
  OFF` is refused), `N'...'`, nested comments, `@@` names, and only Transact-SQL's operators
  (`+ - * / % = <> != < > <= >= !< !>`): any other, such as `^`, `||`, `::`, `~`, is a syntax
  error rather than PostgreSQL's meaning.
- **Names (decided by judgement).** Every identifier and alias, bare or delimited, folds to lower
  case on the shared catalog, which is SQL Server's case-insensitive catalog under its default
  collations, as D106 did for MySQL; result labels therefore come back in lower case, and a
  quoted mixed-case table made in PostgreSQL (`"Users"`) cannot be reached from Transact-SQL.
  Schema `dbo` is `public`. Unnamed expressions are unnamed columns, as in SQL Server.
- Statements end at `;` or where a word that starts a statement begins (the reserved list holds
  each), so batches without semicolons run. `SELECT TOP n` and `TOP (expr)`; `IDENTITY` and
  `IDENTITY(1,1)` on the existing auto-increment column (D106, D111), inline or with a
  table-level primary key, left out of an `INSERT` without a column list, and error 544 for an
  explicit value; other seeds, and an identity column that is not the first primary-key column,
  are 40517. `BEGIN TRAN`, `COMMIT [TRAN|WORK]`, `ROLLBACK [TRAN|WORK]` with `@@TRANCOUNT`
  nesting; `USE` of the served database; a table of accepted `SET` options (40517 for a known
  option with an unsupported value, 195 for an unknown one); `GETDATE()`, `SYSDATETIME()`,
  `GETUTCDATE()`, `SYSUTCDATETIME()`, `CURRENT_TIMESTAMP`, `@@VERSION`, `@@SPID`,
  `@@SERVERNAME`, `@@TRANCOUNT`, `@@LANGUAGE`; other functions are 195, so PostgreSQL's do not
  leak in. `+` with a string operand is 40517 until item 39 brings Transact-SQL's typing.
  PostgreSQL clauses Transact-SQL lacks (`LIMIT`, `OFFSET`, `RETURNING`, `IS TRUE`, `ILIKE`) are
  syntax errors. DDL is transactional, as in SQL Server. Views and `CHECK` constraints are refused
  (40517) in this dialect: each keeps its dialect in the file (D114, D116), and storing a fifth
  dialect there is a file-format change with its own compatibility tests (D35), so it waits for
  item 40; views and constraints made in another dialect work from Transact-SQL, and this item
  changes no file format. A column `DEFAULT` is kept, as MySQL's are (D106), as PostgreSQL text:
  a constant, or `GETDATE()` and its kin. A result wider than 4,096 columns is SQL
  Server's error 1056. The session's time zone is UTC, so
  `GETDATE()` and `GETUTCDATE()` agree.
- **Batches** (`Session::execute_batch`, from the Transact-SQL reference's "Batches"): the whole
  batch is parsed first, so a syntax error runs nothing; then each statement runs. Constraint
  violations and the other statement-terminating errors (2627, 2601, 547, 515, 544, 2628, 8152,
  3902, 3903) end only their statement, unless they rolled back an open transaction (the engine
  has no statement savepoints, D106, D108), which ends the batch; every other error ends the
  batch. Known difference: binding errors (an unknown column of an existing table) are found
  when the statement runs, not when the batch compiles.
- **Errors.** One translation from the engine's SQLSTATE errors to SQL Server's numbers,
  severities and wording, from Microsoft's "Database engine events and errors" (`Msg 208,
  Level 16, State 1 ... Invalid object name 't'.`). An error without a counterpart becomes
  `Msg 50000`, the number SQL Server gives `RAISERROR` user messages, so no client mistakes it
  for one of the engine's numbered errors, with a neutral message rebuilt from its SQLSTATE; no
  PostgreSQL wording or hint reaches a SQL Server client. Features EggDB lacks are 40517, `...
  is not supported in this version of EggDB.`
- `@@VERSION` is `EggDB <version> (compatible with Microsoft SQL Server 2022, 16.0.1000) on
  <os>/<arch>`; PRELOGIN and LOGINACK report version 16.0.1000 and the program name `EggDB`.

**Patents (D43, decided by research, 2026-10-28).** Microsoft's Open Specifications Promise
lists "[MS-TDS]: Tabular Data Stream Protocol" among its covered specifications without a
version (https://learn.microsoft.com/en-us/openspecs/dev_center/ms-devcentlp/1c24c7c8-28b0-4ce1-a47d-95fe1ff504bc),
beside an entry for TDS 7.1 to 7.3, and its FAQ says the promise applies to all existing versions
of a listed specification and is meant to enable open-source implementations. Microsoft
irrevocably promises not to assert its necessary claims against conforming implementations,
except against a party that sues Microsoft over its own implementation of the same
specification. Residual risk, accepted: version 7.4 is not named on its own, the promise covers
only what the specification describes in detail (not TLS or SSPI, which EggDB does not use
here), and it says nothing of third-party patents; a written confirmation could be asked of
iplg@microsoft.com.

**Clean room.** Written from [MS-TDS], the Transact-SQL reference and the go-sqlcmd and
go-mssqldb documentation only, never their source, and never FreeTDS or jTDS (LGPL); what
go-sqlcmd sends was learned from CI runs against EggDB's own server (`eggdb serve
--log-batches`). The examples of [MS-TDS] section 4 that this version can read (the PRELOGIN
and LOGIN7 requests) are test data.

**Size (D6, D115).** The binary grows by the TDS server and the dialect, about 200 to 250 KB as
the MySQL and Oracle steps did; the footprint check reports it and blocks only above 2x.

**Left for later items.** 39: the remaining SQL Server types (`bit`, `tinyint`, `money`,
`datetime`, `datetimeoffset`, `uniqueidentifier`, `varbinary`, `time`), `+` typing,

TIES`, `OUTPUT`, and their TDS encodings. 40: the `GO` script reader for `eggdb restore` and
`eggdb sql`, `IDENTITY_INSERT`, `QUOTED_IDENTIFIER OFF` and `ANSI_PADDING OFF` if scripts need

load. 47: `DECLARE`, `IF`, blocks. After v0.2.0: TLS, MARS, cancelling a running statement,
case-insensitive collations (D19, D30).
