## D462 S3 `GetObject` of a large object sent as a stream, with its length — Decided by the code-only session (2026-11-11, D355); roadmap M6a, extends D325 and D188

- A `StreamedResponse` may now carry a known `content_length`: the server sends
  `Content-Length` instead of the chunked coding, keeps the connection when the body writes
  exactly that many bytes, and closes it when it writes more or fewer, so a client never takes a
  short body as complete.
- `GetObject` (and a ranged `GetObject`) of 1 MiB or more answers such a response: the object's
  stored record is read once for the head, then the body is read 1 MiB at a time, each piece in
  its own read, which first checks the stored record is byte-for-byte the one the head was built
  from. An object replaced or deleted mid-send cuts the body short instead of mixing two
  versions. Smaller objects and `HEAD` keep the whole-response path.
- `eggdb serve` serves the S3 listener through `serve_replies_with_limits`; `Endpoint::answer`
  still returns a whole response (it collects a streamed one) for tests and embedders.
