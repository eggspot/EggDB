## D856 Composites and user-defined ranges read in binary — Decided by the code-only session (2026-11-12, D355); follow-up of D828

- `decode_pg_binary_text` now reads a composite in `record_send`'s layout: the field count, then each field's type
  OID, length (`-1` for NULL) and binary form. Each field is decoded by the OID it carries, so no catalog lookup is
  needed for the fields, and the record comes back as text with every non-null field quoted and a NULL field empty,
  which the composite's text input reads. Nesting stops at 32 levels and a field count past the bytes is `22P03`, so
  hostile input fails rather than recursing or allocating.
- A user-defined range is read like a built-in one, with its subtype from the type registry of the statement
  (`user_types::range_subtype`, which also covers the built-in ranges).
- `COPY ... FROM (FORMAT binary)` and binary parameters now accept composite and user-defined range columns; the
  copy test that expected built-in ranges to be refused on the way out (stale since D828) now expects them to work.
