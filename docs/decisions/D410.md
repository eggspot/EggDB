## D410 MongoDB's `renameCollection` — Decided by the code-only session (2026-11-10, D355); roadmap M9

- `renameCollection: "<db>.<from>", to: "<db>.<to>", dropTarget` runs only against `admin`
  (`Unauthorized`, 13, elsewhere, as MongoDB answers), within one database or across two.
- `Store::rename_collection` moves the collection record (with its index definitions) and every
  document key to the new prefix in one write transaction, so a reader sees the old name or the
  new one, never half. A missing source is `NamespaceNotFound` (26), the same name is
  `IllegalOperation` (20), and an existing target is `NamespaceExists` (48) unless `dropTarget`,
  which drops it in the same transaction.
- MongoDB refuses a cross-database rename of a collection whose name or documents break the
  target's limits; EggDB checks the target names only, since documents keep their own limits.
