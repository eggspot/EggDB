## D529 MongoDB unique indexes enforced — Decided by the code-only session (2026-11-11, D355); roadmap M9

`createIndexes` with `unique: true` (and `sparse: true`) is now accepted and enforced, where it
was refused (indexes besides `_id_` were listed only).

- **Creating:** the definition keeps `unique` and `sparse`; creating a unique index over
  documents that already repeat its key fails with `E11000 duplicate key error ... index: <name>
  dup key: { ... }` (code 11000), as MongoDB does.
- **Enforcing:** every write path checks the collection's unique indexes before it puts a
  document: `insert`, `update` and upserts, `findAndModify` updates and upserts, `$merge` and
  `$out` (whose new documents are checked among themselves). A missing field counts as `null`,
  so two documents without it collide unless the index is `sparse`, in which case documents
  missing every field of the key are not indexed. The error names the index and the duplicated
  values.
- **Cost:** with no index structure in the file yet, a check scans the collection, so writes to
  collections with unique indexes are O(n); the in-file index (the rest of this item, with
  queries using indexes) removes that. Collections without unique indexes pay nothing.
- **Restore:** `mongodump` restores now create unique indexes too, each on its own after the
  documents; one the restored documents violate is skipped and reported, as before.
- **Left out:** partial filter expressions, collations, and indexes used by queries.
