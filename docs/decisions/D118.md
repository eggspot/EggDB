## D118 `eggdb restore` reads a `pg_dump` plain dump as a stream, one transaction per statement, a new file built aside, and a report of what was skipped — Decided by the build loop (by judgement and by research, 2026-10-28); applies D1, D9, D13, D15, D93, D96, D101, D110, D116, D117

Item 35 lets a PostgreSQL database come over by restoring its own dump (D13, D110):
`eggdb restore <file> <dump.sql>`, or `psql -f dump.sql` against `eggdb serve`. Everything is
written from the PostgreSQL manual's pages on `pg_dump`, `pg_restore`, psql and the SQL
statements a dump holds, and from dumps that PostgreSQL 16 and 18 wrote (D1).

**The dump is read as a stream.** `eggdb_sql::restore_dump` reads the dump one line at a time
(lines and statements up to 1 GiB, refused with `54000` before they grow further; a 64 KiB read
buffer) and splits it into statements as psql does: a `;` ends a statement only outside quotes,
quoted identifiers, `E'...'` strings (with their backslash escapes), dollar-quoted strings, `--`
and nested `/* */` comments and parentheses, and outside a `BEGIN ATOMIC ... END` routine body.
A line that starts with a backslash outside a quote is a psql meta-command. The data of a
`COPY ... FROM stdin` is the lines after the statement up to a line `\.` (or `\.` before
`\r\n`), handed to the `COPY` in pieces of 64 KiB through D117's `CopyChannel`; the rest of the
`COPY`'s own line runs after the data, as in psql. A dump that ends inside a quote, a comment or
the data of a `COPY` (before its `\.` line, `22P04`), or with a `\restrict` that no
`\unrestrict` closed, is cut short: an error, never a success, since otherwise a truncated copy
of a dump would restore part of a table and report every row restored. A dump that is not
UTF-8, or has a line or statement over 1 GiB, stops the restore and names its line. A byte order mark is skipped. The reader is fuzzed with random fragments of all of that.

**Meta-commands are psql's, and none is ever run.** `\connect` is noted (one database per file,
D110); `\restrict KEY` and `\unrestrict KEY` (`pg_dump` 17.6 and later, and 16.10 and later) must
carry the same key, or the restore stops as for an altered dump; every other meta-command
(`\set`, `\echo`, `\i`, `\!`, ...) is listed in the report and never run, because a dump is data
and EggDB never runs programs or reads other files for it.

**One transaction per statement, and a new file built aside.** Each statement runs on its own,
as `psql -f` runs it; a `COPY` and its data are one transaction (D117). A single transaction for
the whole restore was considered and refused (research): one write transaction must fit in the
page cache (D86, at most 1 GiB), so a large dump would fail for a reason the user cannot fix,
and with no savepoints a statement that fails as a consequence would roll back everything.
Instead, as `import --create` does (D93), `--create` builds a new file as `<file>.restoring`
with `Durability::Normal`, syncs it when it closes, and renames it into place only when the
restore succeeded, so an error or a killed process leaves no `<file>`; the staging file is removed
after an error (the restore made it), and one left by a crash is refused, never reused or
removed. Without `--create` the file must exist and is restored into in place, also with
`Durability::Normal` and a sync when the file closes (a power loss during the restore can lose its
latest statements, never damage the file): an error stops the restore with the statements before
it committed, which the message and the report say. The
page cache is sized from the dump as `eggdb import --csv` sizes it (D117); `--cache` overrides.

**What runs, what is skipped, what is ignored.** Before a statement runs, its leading words
decide:
- **Skipped**, never run, listed with kind, name, line and reason: functions, procedures,
  aggregates, triggers, event triggers, rules, policies and row-level security, types, domains,
  materialized views, partitioned, partition, inherited and typed tables (with the rows of their
  data, counted), publications, subscriptions, extensions other than `plpgsql`, collations,
  text search objects, operators, casts, languages, foreign data, roles and tablespaces. These
  are what EggDB does not have yet; D110 says functions, procedures and triggers are not run in
  v0.2.0.
- **Ignored**, counted: `GRANT`, `REVOKE` and `ALTER ... OWNER TO` (no roles yet), `ALTER DEFAULT
  PRIVILEGES`, `SECURITY LABEL`, `SET SESSION AUTHORIZATION` and `SET ROLE`,
  transaction control (`BEGIN`, `START TRANSACTION`, `COMMIT`, `END`, and also `ROLLBACK` and
  `ABORT`: every statement commits on its own, so a dump's `ROLLBACK` cannot undo the statements
  before it, which `--create` covers instead), storage settings with no meaning in EggDB (`REPLICA IDENTITY`, `CLUSTER ON`, `SET
  STATISTICS`, `SET STORAGE`, `SET (...)`, ...), `CREATE SCHEMA public`, and `SET` of a
  parameter EggDB does not have (`default_toast_compression`), each name listed once. A known
  parameter with a value EggDB refuses (`client_encoding = 'LATIN1'`) is an error, since the
  data would be read wrongly.
- **`ALTER TABLE` is judged action by action.** Its actions are split at top-level commas, and
  each is recognised by its first words only (`REPLICA IDENTITY`, `ALTER COLUMN c SET
  STATISTICS`, `ENABLE TRIGGER`, `ATTACH PARTITION`, `INHERIT`, `ENABLE ROW LEVEL SECURITY`,
  `ADD CONSTRAINT`, `ALTER COLUMN c ADD GENERATED`, ...), so a word such as `inherit` elsewhere,
  in a table name a foreign key references, changes nothing.
- **Everything else runs.** A schema statement EggDB answers with `0A000` is skipped as "not
  supported yet" with the engine's message (a table so skipped takes its rows with it). A schema
  statement that fails with a missing-object error (`42704`, `42883`, `42P01`, `3F000`) or is
  refused (`0A000`, `42601`, `42809`) while it names a skipped object is a consequence: listed,
  not an error. A name matches only as written, qualified the same way (`public.m`, never a
  column `m`). A table not created as a consequence takes its rows with it, and an identity column
  added to a skipped table (`ADD GENERATED ... (SEQUENCE NAME s ...)`) makes `s` a skipped
  sequence, so the dump's `setval('s', ...)`, `nextval` or `currval` of it that fails is a
  consequence too. Data statements are never consequences: the `COPY` or `INSERT` rows of a
  skipped table are counted before they would run, and any other failure of a data statement is
  an error, so a data error is never hidden. Any other failure is an error: a row that breaks a
  constraint, bad syntax in a supported statement, a data statement refused.

**Errors stop the restore unless `--keep-going`.** The error names the dump's line: the
statement's, the line its position falls on, or for `COPY` the data line that broke (from the
`CONTEXT` line). With `--keep-going` every error is listed and the restore goes on; the command
then exits 3 with "errors ignored" (research: as `pg_restore` without `--exit-on-error` exits 1),
and with `--create` the file is still renamed into place. Skips and consequences never change
the exit code: they are the expected gaps, and the report lists them.

**The report.** Printed at the end in every outcome, in the CLI's `--format` (text on a
terminal, one JSON object in a pipe), to stdout or with `--report <path>` to a file (stdout then
gets only the verdict line). It counts schemas, tables, rows (per table), views, sequences
(identity columns' included), indexes, constraints and comments created, and lists every
skipped object, consequence, ignored kind with its count and meta-command with its line, and
error. Designed by Claude Fable in `docs/ux/cli.md` section 16 (D15). Each list holds at most
10,000 items, past which only a count grows, and at most 100,000 skipped names are remembered
for consequences, so a hostile dump cannot grow the report or the memory without bound.

**Archives are never read (D13).** A file that starts with `PGDMP` (custom format), a directory
that holds `toc.dat` (directory format) or a tar file (`ustar` at offset 257) is refused with
exit 2 before any file is opened or made, with the exact `pg_restore -f dump.sql <archive>`
command that turns it into a plain dump and a pointer to `docs/migrate.md`. A dump compressed
with gzip, zstd or lz4 (`pg_dump -Z`) is refused the same way with the command that decompresses
it.

**What the engine gained for dumps.** What `pg_dump` 16 to 18 write for supported objects now
runs, also over `eggdb serve` for `psql -f`: `x = ANY (ARRAY[...])` and `x <> ALL (ARRAY[...])`
(how `pg_dump` writes `IN` lists in `CHECK` constraints, also with `::type[]` casts), as an `IN`
list, and other comparisons over a constant `ARRAY[...]` on a column or constant, PostgreSQL
dialect only; `ALTER TABLE ... ALTER COLUMN c ADD GENERATED {ALWAYS | BY DEFAULT} AS IDENTITY
[(SEQUENCE NAME s, options)]`, as a sequence owned by the column and the default
`nextval('s'::regclass)` with the column made `NOT NULL` (an identity column made this way, like
every identity column in EggDB, accepts a given value); `INSERT ... OVERRIDING SYSTEM VALUE`
(`OVERRIDING USER VALUE` is `0A000`); `CREATE UNLOGGED TABLE` as an ordinary table; and
`setval('public.s', ...)` and `nextval('public.s')` with a schema written in the name now find the
sequence whatever the search path is, so the dump's `set_config('search_path', '', false)` no
longer hides `public`.

**Tests and CI.** The reader and the runner have unit tests (splitting, meta-commands, `COPY`
data, cut and hostile dumps, limits, every skipped kind, consequences, errors, `--keep-going`,
progress) and a fuzz test; `crates/eggdb/tests/restore.rs` restores dumps that PostgreSQL 16
(plain, `--inserts`, `--column-inserts`) and 18 (plain with `\restrict`, and a custom archive
through `pg_restore -f`) wrote of `scripts/pg-restore/fixture.sql`, and compares every table's
sorted `COPY` output and every sequence's next value with PostgreSQL's, checked in beside them as
`expected.txt`; the fixture's one table with a column of an enum type and an identity column is
skipped as a consequence, with its rows counted and its `setval` a consequence; it also covers
archives, `--create` after an error and after a killed process, and the report. CI's new
`pg-restore` job (a required part of `check`, D101) runs `scripts/pg-restore/check.sh` against
the official `postgres:16` and `postgres:17` containers with about 50,000 rows: it takes the tables
(ordered by their primary keys) and sequences from PostgreSQL's catalog, expects exactly the tables
with a column of an enum, domain or composite type to be skipped, and every form restored by
`eggdb restore`, and the `--inserts` one by `psql -f` against `eggdb serve`, must match PostgreSQL table
for table, byte for byte, and sequence for sequence. The smoke test restores a committed sample dump
(`crates/eggdb/tests/data/pg_dump-sample.sql`, a new file, D96) both ways.

**`psql -f` and skipped tables.** psql sends a dump's statements as they come: when a table
cannot be created, its `COPY` fails before the data, and psql then reads the data lines as SQL,
against EggDB as against PostgreSQL, which can swallow the statements after them. `eggdb restore`
skips that data instead, so it is the way for a dump with skipped tables; over the protocol a
`pg_dump --inserts` dump has no such data. CI's `psql -f` leg restores the `--inserts` dump, since
the fixture has a skipped table.

**Not yet:** objects in the skipped list; `pg_dump --clean` (EggDB cannot drop `public`);
`pg_dumpall`'s roles and several databases; large objects; dumps in encodings other than UTF-8;
SQL Server's and Oracle's scripts (`--dialect sqlserver` and `oracle` answer "comes in a later
release", items 40 and 43).
