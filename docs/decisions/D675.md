## D675 InfluxQL fill() and GROUP BY time() offsets — Decided by the code-only session (2026-11-12, D355); roadmap M16, InfluxQL (D220, D521)

- `GROUP BY time(d)` buckets now start at the Unix epoch, as InfluxDB's do: the translation passes
  `'1970-01-01T00:00:00Z'` as `time_bucket`'s origin (TimescaleDB's default origin, 2000-01-03, splits weeks
  differently). `GROUP BY time(d, offset)` with a positive or negative duration moves that origin by the offset.
- `fill()` takes every InfluxQL mode: `null` (the default), `none`, `previous`, `linear` and a number. With any mode
  but `none`, the empty buckets of each series are made after the SQL query runs: from the bucket of the `WHERE`
  clause's lower `time` bound to the bucket of its upper bound (or `now()`), the bounds read from top-level `AND`ed
  `time >`, `>=`, `<` and `<=` comparisons and evaluated by one more SQL query. Without a lower bound (or with a
  top-level `OR`), only the gaps between a series' first and last points are filled.
- `previous` repeats the previous bucket's value, `linear` interpolates between the nearest points with values
  (integer columns in integer arithmetic, as InfluxDB does), and a whole-number fill value is written as an integer.
- When buckets are filled, `LIMIT` and `OFFSET` apply to each series' points after filling, as in InfluxDB, instead
  of to the SQL query's rows. A fill that would make more than 100,000 points in one series is refused with an
  error asking for a narrower time range.
- Still left of D521's list: `GROUP BY *`, `FROM` regular expressions and several measurements, subqueries, `INTO`,
  `SLIMIT`/`SOFFSET`, `tz()`, math between fields, `distinct()`, and Flux.
