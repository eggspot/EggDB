## D549 The RESP keys grid dims its counts, `–` and `(gone)` cells — Decided by the code-only session (2026-11-11, D355); roadmap M6e, issue #29, D329

`docs/ux/workspace.md` 10.10 draws an aggregate's `value` cell (`12 fields`, `3 items`) in
`textSecondary`, and `–` and `(gone)` in `textDisabled`; every cell was drawn in `textPrimary`.
The grid now asks `ResultGrid::cell_look`, which keeps `cell_text`'s look for every other grid and,
for a keys grid over RESP, dims by the row: `–` in the `type` or `bytes` column, and in the `value`
column `(gone)` or `–` or an aggregate's count, but only when the row's `bytes` cell is `–`. A
string key always has its byte count there, so a string whose value is the text `(gone)` or `–`
is drawn as data.
