## D922 SPARQL in the CLI: `eggdb sql --sparql` — Decided by the code-only session (2026-11-12, D355); roadmap M13, follow-up of D886 to D889

- `eggdb sql <file> --sparql [-c text | script | stdin]` runs SPARQL 1.1 on the file's RDF store, the collection
  `rdf0` that `eggdb serve --sparql-listen` serves, through `eggdb_rdf::query` and `eggdb_rdf::update`.
- The first keyword after the prologue (`PREFIX`, `BASE`) decides: `SELECT`, `ASK`, `CONSTRUCT` and `DESCRIBE` are
  queries, run on a read-only open of the file and printed as SPARQL 1.1 Query Results TSV (or the JSON results format
  with `--format json`; graphs as N-Triples); anything else is an update, run in one write transaction (refused with
  `--read-only`), printing the quads inserted and deleted. Relative IRIs resolve against `http://eggdb.local/`.
- A flag on `sql` rather than a new command, as `--kql` is (D242), since the command model keeps the top-level names
  closed (D143); `--sparql` goes without `--kql` and `--dialect`.

Decided by research:
- **Which store the CLI reads.** The server keeps RDF in the collection `rdf0` (D889); the CLI reads and writes the
  same collection, so a file served over the SPARQL protocol and opened with the CLI holds the same graphs.
