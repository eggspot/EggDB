## D487 MCP over HTTP answers in Server-Sent Events when asked — Decided by the code-only session (2026-11-11, D355); roadmap M6d, D189

- A `POST /mcp` whose `Accept` names `text/event-stream` but not `application/json` (or `*/*`)
  gets its JSON-RPC answer as one SSE event (`event: message`, the JSON on one `data:` line), with
  `Cache-Control: no-cache`, as MCP's streamable HTTP transport allows. Clients that accept both
  keep getting `application/json`, which the transport also allows.
- `GET /mcp` still answers 405, now with `Allow: POST, DELETE`: EggDB sends no server-initiated
  requests or notifications, and the transport lets a server without them refuse the GET stream.
- Progress notifications streamed during a long tool call, and resuming a stream with
  `Last-Event-ID`, wait for tools that report progress.
