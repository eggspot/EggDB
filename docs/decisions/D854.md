## D854 CQL updates of one user-type field — Decided by the code-only session (2026-11-12, D355); follow-up of D853

- `UPDATE t SET home.street = 'Elm', home.number = 9 WHERE ...` sets fields of a user-type column and keeps the
  others. Several fields of one column join into one assignment (`Assignment::Fields`), so the SQL assigns the column
  once; mixing `home = {...}` with `home.street = ...` in one statement is refused, as Cassandra does.
- CQL `UPDATE` is an upsert: a new row stores `jsonb_build_array(...)` with the given fields and JSON `null` for the
  rest; an existing row rebuilds the array field by field, taking the given fields from `EXCLUDED` and keeping the
  others with `COALESCE(column::jsonb -> i, 'null')`. Rebuilding by position, rather than `jsonb_set`, keeps the array
  exactly as wide as the type even for rows written before an `ALTER TYPE ... ADD` (D843), whose arrays are shorter.
  Conditional updates (`IF ...`) use the given terms directly.
- A field of a collection type takes its value as JSON (`(term)::jsonb`); any other field goes through `to_jsonb`.
- Left: nothing for user types in this item.
