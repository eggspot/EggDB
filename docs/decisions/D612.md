## D612 PromQL named capture groups and a query timeout — Decided by the code-only session (2026-11-12, D355); roadmap M16, D334, D441, D611

Two more of D334's PromQL leftovers:

- **Named capture groups in `label_replace`.** Prometheus uses Go's regular expressions, where
  `(?P<host>[^:]+):(?<port>.*)` names its groups and the replacement says `$host` or `${port}`.
  EggDB's regex engine numbers groups only.
  - `functions::named_groups` rewrites each named group as a plain capturing group and records
    its name with its number. Numbers are counted as Go counts capturing groups: `(?:`,
    lookarounds and parentheses inside a character class do not count, and escapes are skipped.
  - `expand_named` resolves a name through that list when it is not a number. `expand` keeps its
    behaviour and calls it with no names.
- **A query timeout.** A subquery over many series at a fine resolution can stay under the step
  and sample caps and still hold a thread for hours.
  - Every query's `Work` now carries a deadline, Prometheus's default `query.timeout` of two
    minutes (`QUERY_TIMEOUT`).
  - It is checked each time a selector takes samples and each time subquery steps run.
  - Past it, the query stops with `Failure::Timeout`, answered as HTTP 503 with error type
    `timeout`, as Prometheus does. `Work::with_timeout` sets another limit.
- Tests: the pattern rewrite and group numbering; `label_replace` building `host-1-9100` from
  `$name-${port}`; and a zero time limit stopping a subquery with a timeout.

Not done: the request's own `timeout` parameter (every query gets the server's two minutes),
string results, and label matchers pushed down into the SQL read.
