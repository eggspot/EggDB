## D1115 TDS attention on local pipes and sockets — Decided by the code-only session (2026-11-13, D355); roadmap M1 (Windows named pipes: attention on a pipe, D942)

- **`eggdb_platform::local_socket::bytes_waiting`** says, without reading or waiting, how many bytes wait on a local
  stream: `PeekNamedPipe` on a Windows named pipe, `ioctlsocket(FIONREAD)` on a Windows `AF_UNIX` socket, and
  `recv(MSG_PEEK | MSG_DONTWAIT)` on Unix systems, which answers only whether a byte waits. A peer that closed its
  end answers `UnexpectedEof`.
- **The TDS attention watcher polls it.** On TCP the watcher blocks in `peek`, which a pipe has no equivalent of
  without overlapped reads racing the connection's own reader; on a local stream it checks every 10 ms while a batch
  runs, and stops polling as soon as the batch ends, so an idle connection costs nothing. An attention packet (or a
  closed client) seen during a batch cancels it exactly as on TCP; the packet itself is then read by the connection.
- The watcher never shuts a local stream down on drop: it does not block, and shutting a pipe down disconnects the
  client.
