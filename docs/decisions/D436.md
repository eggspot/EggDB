## D436 Betweenness and closeness centrality, k-core, Louvain and weighted shortest paths as graph procedures — Decided by the code-only session (2026-11-11, D355); roadmap M13, extends D248

- Five more `eggdb.` procedures for Cypher's `CALL` (`crates/eggdb-graph/src/centrality.rs`),
  named and shaped as D248's are (node ids out, `MATCH ... WHERE id(n) = nodeId` to get nodes):
  - `eggdb.betweenness([directed])` → `nodeId, score`: Brandes' algorithm over unweighted shortest
    paths; without direction (the default) each path counts once.
  - `eggdb.closeness([directed])` → `nodeId, score`: Wasserman and Faust's closeness, which stays
    meaningful in a graph that isn't connected (the reachable share times the inverse mean
    distance).
  - `eggdb.kCore()` → `nodeId, coreNumber`: core numbers by peeling the lowest-degree node first.
  - `eggdb.louvain([maxLevels])` → `nodeId, communityId`: the Louvain method on modularity, every
    relationship weight 1, nodes visited in id order (so a run is repeatable), up to 10 levels
    by default; a community is named by its smallest node id.
  - `eggdb.weightedShortestPath(start, end[, weightProperty[, directed]])` → `nodeIds, totalCost`:
    Dijkstra's algorithm, each relationship costing its `weight` property (or the one named), 1
    when it has none; a negative or non-number weight is an error.
- Betweenness and closeness visit every pair of nodes, so they refuse graphs over 100,000 nodes
  rather than run for hours. Relationships are read once into an index of node positions; parallel
  relationships and self-loops count once.
