## D1091 An IndexedDB-compatible API over EggDB's SQL in the browser — Decided by the code-only session (2026-11-13, D355); roadmap M17 (D48, D221, D1089)

- **Where it lives.** `web/eggdb-indexeddb.js`, our own JavaScript beside the loader (D16): `indexedDBOver(db)` wraps an `EggDB` or `SharedEggDB` opened in the SQLite dialect and returns an `IDBFactory`. Writing it in JavaScript keeps the API's event model (requests, `onsuccess`, `upgradeneeded`, transactions that auto-commit) native to the page. Rust would only have moved the same logic behind a buffer protocol.
- **One storage engine.** Everything is in five SQL tables (`idb_databases`, `idb_stores`, `idb_indexes`, `idb_records`, `idb_index_entries`), so IndexedDB data is ordinary EggDB data that SQL can read and back up (D2's "never a separate database").
- **Key order by encoding.** Keys are stored as text whose byte order is IndexedDB's order: a type digit (number < date < string < binary < array), floats as 16 hex digits with the sign bit flipped or all bits inverted, strings as UTF-16 code units plus one in five hex digits with a `00000` terminator, bytes plus one in three hex digits with `000`, and arrays as their elements and a `0`. Ranges and cursors are then plain `>`/`<` comparisons on a primary key. The original key is kept beside it as a structured clone for answers.
- **Values.** A structured-clone subset serialised as tagged JSON: primitives with `undefined`, `-0`, `NaN`, the infinities and `bigint`, dates, regular expressions, `ArrayBuffer`s and every typed array, maps, sets, arrays and plain objects; `Blob`s and cyclic values fail with `DataCloneError`.
- **Transactions.** One IDB transaction is one SQL transaction (`BEGIN` at its first request, `COMMIT` when no request is left, `ROLLBACK` on an unhandled request error or `abort()`); transactions run one at a time through one queue, which IndexedDB's scheduling rules allow. The upgrade transaction runs inside `open`'s turn and writes the new version in its own commit.
- **Known differences.** Keys and key paths are checked when the request runs, so a bad key fails the request rather than throwing at the call; transactions do not run in parallel; `Blob` values and the `versionchange` and `blocked` events between connections are not implemented.
- **Tests.** `web/test-indexeddb.mjs` runs under Node in CI's `browser` job: upgrades, generated keys, both index kinds, ranges, a reverse cursor, a constraint error that aborts, an explicit abort rolled back, a second upgrade, `databases()` and `deleteDatabase`.

**Status:** code written, unbuilt (code-only mode, D355).
