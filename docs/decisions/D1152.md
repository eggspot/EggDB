## D1152 Every driver benchmarked in embedded mode against SQLite's binding in its language, gated in CI — Decided by the code-only session (2026-11-14, D355); roadmap M5 (D17, D182)

- **One workload in every language.** Each driver gets a benchmark program in `drivers/<language>/bench`
  (`drivers/dotnet/EggDB.Data.Bench`, and the `EggDBBench` target for Swift). It runs the same three workloads
  on EggDB and on SQLite's binding for that language, each on a fresh file:
  - 20,000 prepared inserts in one transaction;
  - 5,000 prepared point lookups by primary key;
  - one stepped scan over every row.

  `DRIVER_BENCH_ROWS` and `DRIVER_BENCH_LOOKUPS` change the sizes. Each program prints
  `<language> <workload> <eggdb ms> <sqlite ms>`.
- **The SQLite side** is the binding each language's users reach for:

  | Language | SQLite binding |
  | --- | --- |
  | Python | `sqlite3` |
  | Node.js | `node:sqlite` |
  | Go | `mattn/go-sqlite3` through `database/sql` |
  | C++ | the C library |
  | Ruby | the `sqlite3` gem |
  | PHP | `SQLite3` |
  | .NET | `Microsoft.Data.Sqlite` |
  | Java and Kotlin | `sqlite-jdbc` |
  | Dart | the `sqlite3` package |
  | Swift | the system `SQLite3` |

  Android keeps its device benchmark against the platform's binding (`BindingBenchmark`).
- **Licences.** The SQLite bindings are benchmark tools, never shipped, and all permissively licensed: MIT, BSD,
  Apache-2.0, or SQLite's public domain (D1). The Go and Dart benchmarks have modules of their own, so the drivers'
  own modules do not depend on them.
- **The runner and its gate.** `scripts/driver-bench.sh <library dir> <work dir> <results file>` builds and runs
  every benchmark whose tools are installed. It writes each line with its ratio and fails in three cases:
  - a ratio is above `DRIVER_BENCH_SLOWEST_RATIO` (2 by default: the same 2x line D7 sets for the engine);
  - a benchmark fails;
  - a language listed in `DRIVER_BENCH_REQUIRED` produced nothing, so a missing toolchain cannot pass silently.
- **CI.** CI's `driver-bench` job runs the script on Linux, requiring Python, Node.js, Go, C++, Ruby, PHP, .NET,
  Java and Kotlin. It publishes the table in the run summary and keeps the results as an artifact, and `check`
  waits for it. Dart and Swift run wherever their tools are installed (Swift on macOS).
