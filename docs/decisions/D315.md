## D315 UDP sockets in the platform layer and its simulation, and syslog over UDP and TCP into the `syslog` table (`eggdb serve --syslog-listen`) — Decided by the build loop (EggAgentCode task 20261104-1214, 2026-11-04); roadmap M1 and M16, extends D39, D70 and D72, applies D8, D9 and D34

The platform layer had TCP only, and D39's logs had no way in. QUIC and syslog both need UDP
(roadmap M1, "UDP sockets in the platform layer, for QUIC and syslog ingest"), and syslog is the
log transport that every Unix system, network device and log shipper already speaks (M16,
"Loki's push API, syslog, and Jaeger and Zipkin traces"). Both are built from their public
specifications: RFC 768 for UDP, RFC 5424 (the syslog protocol), RFC 3164 (the BSD format older
senders still write), RFC 5426 (syslog over UDP) and RFC 6587 (syslog over TCP).

- **UDP in the platform layer.** `Network` gains `bind_datagram(address)` and an associated
  `Datagram` type implementing the new `DatagramSocket` trait: `local_address`,
  `send_to(datagram, to)` and `receive_from(buffer, wait)`. Calls block the calling thread, a
  receive for at most its wait (`TimedOut` after it), because a datagram server is one thread
  reading one socket and checking its stop flag between receives; the completion queue stays
  TCP's until QUIC needs datagrams in it. A datagram is sent whole or refused (`InvalidInput`
  above `MAX_DATAGRAM_BYTES`, 65,507, the IPv4 limit); one longer than the receive buffer is cut
  to it on Unix systems and in the simulation and refused with `InvalidInput` on Windows
  (`WSAEMSGSIZE`), so a caller with a limit receives into a buffer one byte longer and refuses a
  datagram that fills it. `OsDatagramSocket` is the operating system's UDP socket on Unix systems
  and Windows alike; it sets the read timeout only when a receive's wait changes, retries an
  interrupted call, and on Windows skips the `WSAECONNRESET` a past send to a closed port leaves
  behind, which means nothing to a connectionless socket.
- **UDP in the simulation.** `SimDatagramSocket` keeps D72's rules: datagrams cross the
  network's and the hosts' latency and bandwidth, a datagram sent across a cut is lost rather
  than held (UDP does not retransmit), datagrams whose latency differs may overtake each other,
  and each socket holds at most `SimNetwork::DATAGRAM_BUFFER_BYTES` (212,992, Linux's default
  receive buffer) in transit and unreceived, dropping what arrives beyond it. A receive moves the
  clock to the datagram's arrival, or to the end of its wait when nothing arrives in time; binds,
  sends and receives are numbered operations, so injected faults reach them. UDP ports are apart
  from TCP's in both backends.
- **Syslog.** `eggdb_observability::SyslogCollector` takes one message per datagram over UDP, and
  over TCP frames by octet counting (`MSG-LEN SP MSG`) when a frame starts with a digit and by
  line ends (LF, or NUL as some senders use) otherwise, per RFC 6587. A message that says it is
  RFC 5424 (`<PRI>1 `) is read field by field: `TIMESTAMP` (RFC 3339 with up to six fraction
  digits and a `Z` or `±hh:mm` offset), `HOSTNAME`, `APP-NAME`, `PROCID`, `MSGID` (`-` is
  `NULL`), the structured data as sent (elements with escaped `"`, `\` and `]` kept intact), and
  the message without its byte order mark. Anything else is read as RFC 3164: the `Mmm dd
  hh:mm:ss` timestamp, the host, and the tag as the app name with `[pid]` as the process id;
  without a priority a message is `user.notice` (13) with all of it as the text, as RFC 3164
  section 4.3.3 has a relay do, and without a timestamp everything after the priority is the
  text. Each message becomes a row of `syslog` (`received_at`, `facility`, `severity`,
  `timestamp`, `hostname`, `app_name`, `procid`, `msgid`, `structured_data`, `message`),
  created at start and again if it was dropped, written in one `INSERT` per batch (at most 500
  rows, or what arrived within 50 ms), so SQL and every protocol read it.
- **`eggdb serve --syslog-listen <address>`** binds UDP and TCP on the same address and port
  (a bare port is on loopback; the default in the usage text is 514). It is refused on an address
  other than loopback, as syslog has no authentication (RFC 5425's TLS transport is left), and
  takes at most `--max-connections` TCP connections at once. Port 0 is refused: senders are
  configured with the port, and UDP and TCP must share it.
- **Hostile input.** The parsers index nothing they have not checked, and return a row for
  every input: a broken RFC 5424 header falls back to RFC 3164, which cannot fail. Messages
  longer than `MAX_SYSLOG_MESSAGE_BYTES` (16 KiB) are dropped from UDP, and a TCP connection that
  announces or sends a longer frame, or a count that is not a number, is closed. A seeded test
  feeds 20,000 generated messages and streams through both parsers.

Decided by research:
- **The option is `--syslog-listen`, not `--syslog`.** Every other listener of `eggdb serve` is
  named `--<protocol>-listen` (`--nats-listen`, `--observability-listen` and the rest), and one
  concept keeps one name (global naming rule).
- **A `syslog` table, not a logs store.** D39's logs store (LogQL, label indexes) is not built
  yet; until it is, a plain table with RFC 5424's field names keeps every message queryable now,
  and the logs store can read it or replace it with a migration.
- **RFC 3164 timestamps are UTC, in the year they were received.** RFC 3164 timestamps carry
  neither a year nor a zone. The receive year is used, or the year before when that would put the
  message more than 31 days ahead of the clock (a December message received in January), as
  common collectors do; the zone is taken as UTC, since a collector cannot know the sender's.
- **16 KiB per message.** RFC 5424 asks receivers to accept at least 2,048 bytes and lets them
  accept more; 16 KiB doubles the 8 KiB that common senders allow by default, keeps each
  connection's buffer small, and refuses the rest rather than truncating it silently.
- **A host token that ends in `:` or holds `[` is a tag.** RFC 3164 senders often leave the host
  out (`Oct 11 22:14:15 su: ...`); such a token is read as the tag, not as the host.

Left: RFC 5425 (syslog over TLS) and listening beyond loopback with it; the sender's address as
a column and the RFC 3164 relay rules for a missing host; RFC 3164 timestamps in a configured
zone; octet-counted frames on UDP and the RFC 6587 framing auto-detection per connection rather
than per frame; datagrams in the completion queue (`NetOp`) for QUIC, and `recvmmsg`-style
batched receives; a datagram server in the simulation driving `SyslogCollector` through
`SimNetwork`; D39's logs store with LogQL reading the `syslog` table; rsyslog and syslog-ng
themselves in CI; an idle limit on TCP syslog connections (a silent one holds its slot until the
server stops); reporting a batch the collector fails to store, which it drops silently today
along with the batch's later chunks (both found by the batch review).
