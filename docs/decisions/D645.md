## D645 EXEC @result = a Transact-SQL scalar function — Decided by the code-only session (2026-11-12, D355); roadmap M10, D159

Transact-SQL lets a batch call a scalar function the way it calls a procedure:
`EXEC @total = dbo.add_tax @amount = 200`. Arguments can be named and in any order, and the
defaults are taken without writing `DEFAULT`. EggDB refused it with msg 2809 ("is a function
object").

- When an `EXEC` has a status variable and names a user T-SQL function, the session maps the
  arguments onto the parameters as it does for a procedure: positional or `@name = value`, a
  second value for one parameter refused, too many refused. A missing parameter takes its declared
  default and is refused without one. An `OUTPUT` argument is refused (msg 8162).
- The session then builds the call `schema.function(arguments...)` with the expression parser
  (`sqlserver_function_call`), so the call resolves and runs like one written in a query. It
  evaluates the call and assigns the value to the variable.
- `EXEC` of a function without a status variable keeps msg 2809, as SQL Server does.
- Test: `exec_assigns_a_scalar_functions_result_to_its_status_variable`, with a default, named
  arguments in another order, and the refusal.
