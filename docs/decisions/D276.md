## D276 The object browser lists the catalog: `Connection::catalog` reads a file through the engine's schema and a server through its catalog queries, the sidebar's tree expands lazily and answers its keys, and the inspector docks from 1440 px — Decided by the build loop (EggAgentCode task 20261103-0137, 2026-11-03); roadmap M6e, applies D2, D8, D9, D15 and D256, builds section 4 of `docs/ux/workspace.md`

Until now the main window's sidebar drew the golden frame's rows: the table names and fixed
`Views 0`, `Indexes 3` and `Keys` lines whatever the database held. Section 4 of Fable's
`docs/ux/workspace.md` says what the object browser lists, how its keys work and what the
inspector shows. This decision builds it.

- **One catalog type, read two ways.** `catalog::Catalog` (`crates/eggdb-gui/src/catalog.rs`)
  holds the tables (columns with type, `pk` and `not null`, and their DDL), views (columns and
  `CREATE VIEW`), secondary indexes (table, columns, `unique`, `CREATE INDEX`), sequences (current
  value) and key spaces, each in name order. `Connection::catalog` reads it: an open file
  through the engine's own schema (`Session::tables`, `Session::views`,
  `TableSchema::create_statement_in`, `IndexSchema::create_statement_in`) plus its `pg_views`
  and `pg_sequences`, and its key spaces through `ReadTransaction` (the default key space when
  it holds keys outside EggDB's reserved `0xFF` prefixes, then each collection); a server
  through `pg_catalog.pg_tables`, `information_schema.columns`, the primary keys of
  `information_schema.table_constraints`, `pg_catalog.pg_index` with `pg_get_indexdef`,
  `pg_views` and `pg_sequences`. Only the table list must answer; a server that cannot list the
  rest shows tables alone. A server table's DDL is written from its columns, since PostgreSQL
  has no function for it. Key counts stop at 100,000 (`100K+`), so a large collection never
  holds the window. Every catalog read runs off the window's thread: the first one in the open's
  worker, a refresh (`F5`, or after a run that changed the schema) and an inspected table's
  sample rows on a worker that takes the `Connection` the way a run does; the answer shows when
  it arrives, and a run asked for meanwhile waits for the connection to come back.
- **The tree is the catalog plus what is open.** `object_browser::ObjectTree` keeps the
  catalog, the set of expanded rows, the current row (the ring), the selected row (the
  inspector's) and the filter; `rows()` walks only expanded rows, so children are listed when
  their parent expands. Level 0 is the connection (`read-write`/`read-only`), level 1 the groups
  in 4.1's order, each drawn only when the database has that model (`Tables` always), with its
  count; a table expands to `Columns` and, when it has some, `Indexes`. While filtering, every
  group is open, rows whose label holds the text (any case) stay with their ancestors, and a
  group's count reads `1 of 3`. After a refresh the expanded, current and selected rows are kept
  by name.
- **Keys as 4.2 lists them.** `Ctrl/Cmd+1` focuses the tree; `Up`/`Down`, `Home`/`End`,
  `Right` (expand, then first child), `Left` (collapse, then parent), `*` (expand every sibling),
  letters (the next row starting with the typed prefix, 1 s to type more), `Space` (select and
  inspect), `F5` (refresh), `Tab` to the editor and `Shift+Tab` to the filter field, where
  `Esc` clears it and returns. `Enter` on a table or view opens `Query <n>` with
  `SELECT * FROM <name> LIMIT 100;` in the tab's dialect (`TOP 100` in SQL Server, `FETCH FIRST
  100 ROWS ONLY` in Oracle) and runs it; while a run is going it says so in the status bar
  instead. `Shift+Enter` inserts the name, quoted when the dialect needs it, at the editor's
  caret. A run whose statement starts with `CREATE`, `ALTER`, `DROP` or `RENAME` (or calls
  `sp_rename`) reads the catalog again.
- **More than one tab, the simplest way.** `MainWindow` keeps the tab that shows in `tab` and
  the others in `background_tabs`, drawn before it in the strip; switching and closing tabs are
  the next slice.
- **The inspector.** `inspector::Inspector` is docked (a 280 px region at the right edge, the
  main area narrowing to it) by default from a 1440 px window and closed below, where
  `Ctrl/Cmd+I` opens it as an overlay with a shadow and `Esc` closes it. `inspector::describe`
  gives the selected row's name and line (`Table · 3 rows`, `Index on orders`, `Collection ·
  312 keys`, `Database · 3 tables · 1 view`) and its blocks: `Columns (n)` with `pk` and `not
  null` badges, `Indexes (n)` with `unique`, the `DDL` box with `Copy`, and `Sample rows` (5 rows,
  3 columns then `…`) fetched with `SELECT count(*)` and `LIMIT 5` when the row is selected.
  Blocks fold under their headings (`Inspector::toggle_block`). `MainWindow::width` (with
  `set_width`, and `--size` for `--png` on the main window) lets the frame be drawn wider than
  1280: the toolbar's right group, the tab strip, editor, results, grid and status bar follow the
  width, and at 1280 every pixel is where it was.
- **Accessibility.** The tree adds the `Filter objects` field (its text, placeholder and
  focus), the `Objects` group and one node per drawn row named by its label, with its right
  text, level, position, set size and expanded or collapsed as its value, selected and focused
  as states; the inspector is a group named `Inspector` with its name heading, each block
  heading a button whose value is `expanded` or `collapsed`, and the DDL box a read-only text
  field. The platform's tree, tree-item and disclosure roles come with D278.
- **Tests.** Unit tests cover the catalog of a temporary file with tables, a view, indexes,
  sequences, the default key space and a collection, the short counts and a server table's DDL;
  the tree's rows, lazy expansion, every key, type-ahead, the filter, a refresh and scrolling;
  the inspector's default per width, its descriptions and folding; the main window's
  `Enter`-to-`Query 2`, the dialect forms, a 1440 px frame and the sidebar's nodes.
  `tests/object_browser_frames.rs` opens a real file: the groups and counts, the filter, the
  keys and `Query 2` running `SELECT * FROM orders LIMIT 100;`, a `CREATE TABLE` refreshing
  the tree, the docked inspector at `(1160, 44, 280, 732)` with `orders`, `Table · 3 rows`,
  `Columns (3)`, `Indexes (1)`, `DDL` and three sample rows, the overlay at 1280, and the
  binary's `--size 1440x800` frame equal to the library's.
