## D1361 Stop interrupts a RESP connect in the client — Decided by the code-only session (2026-11-25, D355); roadmap M6e "`Stop` interrupting a RESP reconnect's TCP connect itself" (D329)

- **What users get.** Pressing `Stop` while the client reconnects to a RESP server ends the wait within 50 ms (`STOP_POLL_INTERVAL`), instead of when the TCP connect itself ends, which against an unreachable host is the full 10-second `CONNECT_TIMEOUT`.
- **How.** The standard library's `TcpStream::connect_timeout` cannot be interrupted, and a non-blocking connect would need each platform's socket calls in the GUI crate, which D8 keeps in the platform layer. So `RespClient::connect_stoppable` runs the connect on a short-lived thread and waits on a channel, checking the run's cancel handle at every poll interval; when stopped, it fails with `Interrupted` and leaves the thread to finish its connect and drop the socket. `connect_watched` is `connect_stoppable` with a check that never stops, and `RespLink::client` passes the run's cancel check, which already turns the failure into "cancelled".
- **Left.** A connect that the platform layer can abandon without a thread, once `eggdb-platform` offers non-blocking connects to the GUI.
- **Proof.** A unit test sees a stopped connect fail with `Interrupted` well before the connect timeout, and a connect to a listening local socket succeed.

**Status:** code written, unbuilt (code-only mode, D355).
