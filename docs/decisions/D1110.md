## D1110 Filter pushdown into foreign tables — Decided by the code-only session (2026-11-13, D355); roadmap M18 (D29, D229, D916)

- **Where.** A foreign table is a view over `eggdb_foreign(source, query)` (D916), and the engine already moves a query's filters into the derived tables a view becomes (`pushdown.rs`). A new pass, `foreign_pushdown::push_filters_into_foreign_read`, runs when a `SELECT` over a lone `eggdb_foreign` call has a filter. It rewrites the call's query to `SELECT * FROM (<query>) AS eggdb_pushed WHERE <conditions>`, quoting columns for the source's dialect (PostgreSQL and EggDB, MySQL, SQL Server). File sources are left alone, since their query is not SQL.
- **What moves, following postgres_fdw's contract.** As with postgres_fdw, the declared column types are taken to match the remote ones. Pushed, per conjunct comparing one declared column (`(o ->> 'col')::type`) with a literal: equality with any literal, `IN` lists of literals (at most 1,000), `IS [NOT] NULL`, and `<`, `<=`, `>`, `>=` against numbers only, since string order depends on the remote collation. Booleans become `1`/`0` for SQL Server. Anything else (functions, columns compared with columns, `OR`) stays local.
- **Never fewer rows.** The local filter is kept and checks every row again. A remote comparison that matches more (case-insensitive collations, trailing-space padding) only costs bandwidth, and pushed conditions are those whose remote result is a superset when the declared types match. A statement run again does not wrap its query twice.
- **Left.** Pushing joins between foreign tables of one server, aggregates, `ORDER BY` and `LIMIT`, which change the remote query's shape, not just its filter.

**Status:** code written, unbuilt (code-only mode, D355).
