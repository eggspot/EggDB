## D938 Key-value transactions and collections in the Kotlin driver — Decided by the code-only session (2026-11-13, D355); roadmap M4, collections in the drivers (D292), follow-up of D930 to D937

- `drivers/kotlin/src/app/eggspot/eggdb/KeyValue.kt` adds `KeyValue(path, readOnly)` (`begin`, `read { }`, `write { }`
  committing when the block returns, `close`) and `Transaction` (`AutoCloseable`, rolling back unless committed), with
  `get`/`getText`, `put` (bytes or text, with a `kotlin.time.Duration` time to live), `delete`, `scan` (named
  arguments for the range, prefix, reverse, end inclusive and a limit, returning `Entry` values), `createCollection`,
  `dropCollection`, `renameCollection`, `collections()` and `collectionStats`.
- The JNI bridge `eggdb_jni.c` gains one native per call, named for `KeyValue` and `Transaction`; it copies every key
  and value across the boundary once and frees the C API's buffers at once. A scan crosses once and returns its
  entries as one flat array of keys and values, so a scan is one JNI call, not one per entry (D17's batching).
- The natives sit in each class's own private companion: a Kotlin `internal` member would get a mangled JVM name the
  C file could not match.
