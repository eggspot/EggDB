## D824 TDS logins for stored roles — Decided by the code-only session (2026-11-12, D355); roadmap M6b, D183

- A TDS login for any user other than the served one is checked against the stored role of that name in the
  database the login asks for (or the default one): LOGIN7 carries the password itself (obfuscated, and inside TLS
  as the listener negotiates it), so `ScramVerifier::matches_password` (D823) checks it against the role's
  SCRAM-SHA-256 verifier. A role without `LOGIN` or a verifier is refused with error 18456.
- The session opens with `identify_role`, so the role's grants and row security (and SQL Server security policies,
  D822) apply; if that fails the connection is refused instead of running as the served user. Logins are audited
  with the method `stored-role` (D816). `eggdb-tdswire` now depends on `eggdb-auth`.

**Status:** code written, unbuilt (code-only mode, D355).
