## D329 The client's editor gets Fable's right-click menu with `Toggle comment` and `Format statement`, a keys tab filters by prefix and pages 100 keys at a time, and `Show DDL` focuses the DDL box — Decided by the build loop (EggAgentCode task 20261104-1214, 2026-11-04); roadmap M6e, issue #29, extends D310 and D311, applies D15

Claude Fable designed the three in `docs/ux/workspace.md` 10.9 (the editor's menu, `Show DDL`)
and 10.10 (the keys tab's prefix field, paging and servers); this decision builds them in
`crates/eggdb-gui`.

- **The editor's menu.** A right-click on the editor's text moves the caret to the click (a click
  inside the selection keeps it), on the gutter selects the line with its break, on the error
  strip or the scrollbar opens nothing; `Shift+F10` and the menu key open it below the caret's
  line box (the selection's end), in a keys tab at x 320. It is 9.4's popover (240 × 250, two
  separators) with `Cut`, `Copy`, `Paste`, `Select all`, `Run selection` / `Run statement`
  (`Run scan` in a keys tab), `Explain`, `Toggle comment` and `Format statement`, each with its
  shortcut, disabled by 10.9's rules and left in place (`editor_menu::EditorState::enabled`):
  `Paste` reads whether the clipboard holds text when the menu opens. Keys as the other menus:
  `Up` / `Down` over the enabled items without wrapping, a letter cycles (`C` alternates `Cut` and
  `Copy`), `Enter` and a click activate, `Esc` closes. `Ctrl/Cmd+/` and `Ctrl/Cmd+Shift+F` do the
  same in the editor. In a keys tab `Copy` copies the whole `SCAN` line and `Run scan` re-runs it.
- **`Toggle comment`** (`sql_format::comment_edits`) works on the selection's lines (a selection
  ending at a line's start leaves that line out) or the caret's: when every non-blank line starts
  with `--` after its indent, that `--` and one space go; otherwise `-- ` goes in at the smallest
  indent. The selection grows or shrinks with the text, one undo step.
- **`Format statement`** (`sql_format::format_sql`) lays out the selection or the statement under
  the caret from the editor's own lexer: dialect keywords upper-case (strings, quoted names,
  comments and `$$` bodies byte for byte), each top-level clause (`SELECT`, `FROM`, `WHERE`,
  `GROUP BY`, `HAVING`, `ORDER BY`, `LIMIT`, `OFFSET`, `UNION` and its kin, every `JOIN` form,
  `ON`, `SET`, `VALUES`, `RETURNING`) on a line at the statement's indent, select-list items,
  `SET` assignments and `VALUES` rows indented 2 more, a parenthesised sub-query indented 2 from
  its opening line, one space between tokens (none before `,` `)` `;`, after `(`, around `.`, in
  a call's `name(`, or inside an operator such as `::` or `>=`). One undo step, the caret at the
  range's start, `Formatted 1 statement` (`3 statements`) in the status bar for 2 s; a range that
  does not lex stays, with `Cannot format: unclosed string at Ln 1, Col 8`.
- **The keys tab's prefix field.** `Key prefix` at `(884, 388, 200, 28)` in the results header,
  right-aligned at other widths, with `Back` and `Next 100` after it; `/` from the grid or the
  editor and `Ctrl/Cmd+F` focus it with its text selected. Typing re-runs page 1 150 ms after the
  last key (`Workspace::tick`); `Enter` runs at once and returns to the grid; `Esc` restores the
  prefix the field had when it took the focus. The text is bytes in ui.md's spelling
  (`key_scan::unspelled`: `\xNN`, `\\`, `\t`, `\n`, `\r`); a bad escape draws the field in
  `error` with `Error: \x needs two hex digits` under it and runs nothing. The editor line states
  what ran: `SCAN users PREFIX 'user:' AFTER 'user:0099' LIMIT 100`.
- **Paging.** A page reads 101 entries to learn whether more exist (`KeySpaceScan::page`), from
  after the last key shown; the tab keeps every earlier page's start (`KeyPages::earlier`), so
  `Back` re-reads it. `Alt+PgDn` / `Alt+PgUp` anywhere in the tab, and `PgDn` / `PgUp` in the
  grid with the current cell on the page's last / first row, page too; the current cell lands on
  the first row after `Next 100` and the last after `Back`, column kept. `Run` and a changed
  prefix return to page 1; `Esc` in the grid stops a page that loads. The status line and banner
  follow 10.10's table (`100 keys shown · 0.6 ms`, `Keys 101–200 of 1,204 · 0.5 ms`, `0 keys start
  with 'user:' · 0.2 ms`, `Showing keys 101–200 starting with 'user:' in key order.`), and an empty
  filtered page reads `No keys start with 'user:'` in the grid. A page's end travels back from the
  worker thread with the run's answer (`key_scan::PageEnd`).
- **`Show DDL`** focuses the inspector's `DDL` box: a 2 px `focusRing` 1 px outside its border,
  the read-only `DDL` text area focused for screen readers (the tree row no longer reports the
  focus); `Ctrl/Cmd+C` copies the statement, `Esc` and `Tab` return to the tree.
- **Accessibility.** The menu is a group of buttons named by their labels (`Run statement`), each
  with its shortcut, disabled ones exposed disabled; the prefix field a text field named `Key
  prefix` with its value, placeholder and its error as description and `invalid`; `Back` and
  `Next 100` buttons with `Alt+PgUp` / `Alt+PgDn`; screen readers can set the prefix and press the
  buttons.

Decided by research:
- The platform layer has no `menu` / `menuitem` or `searchbox` roles yet (the grid's and tree's
  menus expose groups and buttons, D310, D311), so this menu does the same and the prefix field is
  a text field; the roles come with the platform layer's menu roles.
- `Format statement` reads the editor's highlighting lexer rather than the engine's parsers, so it
  formats every dialect the editor highlights, including text that does not parse, and never
  changes a token's bytes except a keyword's case.
- The caret's x for a keyboard-opened menu uses the grid's fixed character advance (the window
  has no font when it takes a key); the editor's code font is monospaced, so it matches.

Left: the keys tab on a server (10.10's `redis://` connection speaking RESP2/RESP3 with `HELLO 3`
and `AUTH`, the tree's `RESP` row and `resp0`…`resp15` spaces from `DBSIZE`, `SCAN cursor MATCH
prefix* COUNT n` with keys past 100 carried to the next page (`PageStart::Cursor` is ready for
it), the `type` column with `TYPE` / `STRLEN` / `HLEN`… pipelines, the full-value view from `GET`,
`HGETALL`, `LRANGE`, `SMEMBERS`, `ZRANGE … WITHSCORES`, `XRANGE`, the server's error table and
`Query tabs need a SQL connection`); the prefix field's own caret movement and the `Tab` stops on
`Back` and `Next 100` (Tab from the field goes to the grid); the editor keeping its focused look
while its menu is open; the browser's clipboard read on `Paste` with its refusal toast; the
`menu` / `menuitem` / `searchbox` roles in the platform layer.
