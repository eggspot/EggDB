## D597 MongoDB text scores — Decided by the code-only session (2026-11-12, D355); roadmap M9, D197, D530

`$text` searches (D530) matched but could not rank. Applications sort and show results with
`{score: {$meta: "textScore"}}` in `find`'s projection and sort, and in `$sort`, `$project` and
`$addFields` after a `$match` with `$text`.

- `TextSearch::score` follows MongoDB's published scoring. For each string the text index covers
  and each searched term in it (words, and the words of phrases):
  - repeats count 1, 1/2, 1/4 and so on;
  - that sum is multiplied by `0.5 + 0.5 × (the term's repeats ÷ the string's words)`;
  - the products are summed.
  Index weights are not applied: every field weighs 1.
- `Store::find` and `$match` attach the score to each matched document under a top-level name no
  stored document can hold (`$textScore`). `$project` carries it over, as MongoDB keeps metadata
  outside the fields. `$group` and the stages that build new documents drop it.
- `{$meta: "textScore"}` reads it:
  - as a projection value, which does not count as an inclusion, so `{score: {$meta: …}}` alone
    returns every field plus the score;
  - as a sort key, highest first;
  - as an expression.
- Other `$meta` kinds answer `NotImplemented`.
- `find` drops the attached score before the reply, and every pipeline drops it at its end.

Not done: `$where` (it needs a JavaScript engine), and index weights and languages per document.
