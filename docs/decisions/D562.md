## D562 The `nested` query — Decided by the code-only session (2026-11-11, D355); roadmap M8, D196

An array of objects is flattened when a query reads it, so `author: ada AND stars: 5` matched a
post whose Ada comment had one star and whose five-star comment was Bob's. Elasticsearch's answer
is the `nested` type with the `nested` query, which tests each object on its own; EggDB now runs
that query: `{"nested": {"path": "comments", "query": ...}}` scores the inner query against each
object at `path` (seen under its own path, so `comments.author` still names its field) and the
document matches when one object does. `score_mode` is `avg` (the default), `max`, `min`, `sum` or
`none`. The mappings (D559) apply inside it.

EggDB keeps documents as their JSON, so the query works on any array of objects whether or not the
mapping says `nested`, where Elasticsearch refuses a path not mapped `nested`; `inner_hits` and the
`nested` aggregation (D471) are not built.
