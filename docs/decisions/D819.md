## D819 Audit file rotation and retention — Decided by the code-only session (2026-11-12, D355); roadmap D26, D231

- `AuditLog::rotate` moves the audit file aside as `<file>.<unix seconds>` under its lock and starts a new file whose
  first record, `{"prev":<moved file's newest digest>,"event":"rotated","previous_file":<name>}`, carries the chain
  on. `verify_chain` accepts that first link, so each file verifies alone and the files verify as one chain in order.
- `AuditLog::remove_rotated_older_than(days)` removes moved-aside files older than that, each by its exact name in
  the audit file's directory (only names `<file>.<digits>`).
- `eggdb serve` with `EGGDB_AUDIT=1` rotates before a record once the file reaches `EGGDB_AUDIT_ROTATE_MB`
  (512 MiB by default, below the 1 GiB limit at which records stop), and with `EGGDB_AUDIT_KEEP_DAYS` removes older
  moved-aside files then. Without `EGGDB_AUDIT_KEEP_DAYS` nothing is removed.
- A writer that waited on the old file's lock during a rotation appends to the moved-aside file; that record is kept
  and verifies there, but the new file's first link names the digest from before it.
