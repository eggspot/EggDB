## D402 Elasticsearch search templates with our own Mustache — Decided by the code-only session (2026-11-10, D355); roadmap M8, closes part of D331/D348's leftovers

`POST [<index>/]_search/template` takes `{"source": ..., "params": {...}}`, renders `source` (a
string, or an object written out as JSON first) with the params, and runs the result as the body
of `_search` on the same indices (D401's lists and patterns included). `_render/template` returns
`{"template_output": <rendered>}` without searching, `400 parse_exception` when the result is not
JSON.

The renderer (`mustache.rs`) is a clean-room implementation of the Mustache features Elastic's
templates use: `{{name}}` (strings JSON-escaped, since templates are JSON; numbers, booleans and
objects as JSON text; missing as nothing), `{{{name}}}` and `{{&name}}` unescaped, dotted names,
`{{#name}}...{{/name}}` sections (once for a truthy value with it as the scope, once per element
for an array), `{{^name}}` inverted sections, `{{! comments}}`, and Elastic's `{{#toJson}}name{{/toJson}}`
and `{{#join}}name{{/join}}`. Unclosed or mismatched tags are `400 general_script_exception`;
nesting deeper than 32 or output over 16 MiB is refused. Stored templates (`"id"`) are `400`
until stored scripts exist; `_msearch/template` is left.
