## D1066 Telegraf and Prometheus in CI, and benchmarks against InfluxDB and Prometheus — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D7, D220)

- **Senders.** New script `scripts/metrics-senders/check.sh`, run by the CI job `metrics-senders`. It
  serves a database with `--observability-listen 127.0.0.1:18086` and `--metrics-listen 127.0.0.1:19187`,
  then runs two collectors on the host network:
  - Telegraf 1.30 collects `cpu` and `mem` every second and writes them through both its `influxdb` output
    (InfluxDB 1.x `/write`, user and password) and its `influxdb_v2` output (`/api/v2/write`, the password as
    token).
  - Prometheus 2.53.0 scrapes EggDB's own metrics endpoint every second and sends what it scrapes with
    `remote_write` and Basic authentication.
  - The script then asks EggDB's Prometheus query API with curl for `cpu_usage_idle{cpu="cpu-total"}`,
    `mem_used_percent`, `up{job="eggdb"}` and `eggdb_sessions_open{job="eggdb"}`. Each must have a result
    within 60 seconds.
- **Benchmarks.** New excluded crate `crates/eggdb-tsdb-compare` (never shipped, D94). Its only dependency
  is `eggdb-columnar`, for snappy, which is our own. It has its own HTTP/1.1 client. The same requests go to
  EggDB and to each other server:
  - against InfluxDB 2.7: 60,000 points (100 hosts × 600 seconds) written as line protocol through
    `/api/v2/write`, 5,000 lines a request; then 50 Flux queries, each one host's one-minute means over the
    range;
  - against Prometheus 2.53 (started with `--web.enable-remote-write-receiver`): 60,000 samples
    (100 series × 600 seconds) sent as remote-write `WriteRequest` protobufs, snappy-compressed, the next
    20 samples of every series a request; then 50 `query_range` calls for
    `sum by (job) (rate(bench_requests_total[1m]))` at 15-second steps.
  - Each query must answer rows, so no ratio compares empty answers.
  - The report gives throughput, p50 and p99, and EggDB's ratio. It is reported, not gated.
- CI job `tsdb-compare`:
  - InfluxDB runs as a service set up through its documented `DOCKER_INFLUXDB_INIT_*` variables.
  - Prometheus is started with `docker run`, because it needs a flag.
  - Both jobs are in `check`'s `needs`.
- Learned from: the public documentation of Telegraf's outputs, Prometheus's configuration and remote-write
  specification, and InfluxDB 2's API. No source of these products was read.
