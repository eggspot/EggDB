## D378 SQLite's reading and building JSON functions — Decided by the code-only session (2026-11-10, D355); roadmap M5

The SQLite dialect gains `json`, `json_valid`, `json_type`, `json_extract`, `json_array`,
`json_object`, `json_array_length` and `json_quote` (`sqlite_json.rs`), on EggDB's JSON parser
(`json::parse`, which keeps members in order with duplicates).

- **Values.** `json(X)` minifies in document order. `json_extract` with one path returns an SQL
  value as SQLite does: JSON null as NULL, `true`/`false` as 1/0, integers and reals as numbers,
  strings unquoted, arrays and objects as minified JSON text; with several paths it returns a
  JSON array of the results, `null` for a missing one. `json_type` names `null`, `true`, `false`,
  `integer`, `real`, `text`, `array` or `object`, NULL for a missing path.
- **Paths.** `$`, then `.key`, `."key"`, `[N]` and `[#-N]` (from the end); anything else is
  `bad JSON path` (SQLite's error, code 1). A malformed document is `malformed JSON`.
- **Building.** `json_array` and `json_object` write text as JSON strings, numbers as numbers,
  NULL as `null`, and the result of another JSON function as JSON rather than a string: the
  functions return `Value::Json`, which stands in for SQLite's JSON subtype. A blob argument is
  refused, as SQLite does; `json_object` labels must be text.

**Left:** the functions that change documents (`json_set`, `json_insert`, `json_replace`,
`json_remove`, `json_patch`), the `->` and `->>` operators, `json_group_array` and
`json_group_object`, `json_each` and `json_tree`, and JSONB (`jsonb_*`).
