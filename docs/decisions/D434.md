## D434 Oracle's `UTL_RAW` and `DBMS_LOB` functions — Decided by the code-only session (2026-11-11, D355); roadmap M10

- `UTL_RAW.CAST_TO_RAW`, `CAST_TO_VARCHAR2`, `LENGTH`, `CONCAT` (up to 12 parts), `SUBSTR`,
  `COMPARE` (with its pad byte), `BIT_AND`, `BIT_OR`, `BIT_XOR`, `BIT_COMPLEMENT`, `REVERSE` and
  `COPIES`, and `DBMS_LOB.GETLENGTH`, `SUBSTR` (Oracle's `amount, offset` order), `INSTR` and
  `COMPARE` are built-in Oracle functions (`oracle_packages.rs`), reached from `package.function(...)`
  in Oracle's SQL and PL/SQL expressions before a user package of that name would be.
- RAW values are `bytea`; a text argument where a RAW is wanted is read as hex, as Oracle converts
  it (ORA-01465 when it isn't hex), an empty RAW result is `NULL` as Oracle's is, and a result over
  32,767 bytes is ORA-06502. `BIT_*` on RAWs of different lengths keep the longer one's tail, as
  Oracle documents. `DBMS_LOB` counts characters for text and bytes for `bytea`, and its
  `SUBSTR` returns the argument's kind.

  and the rest), `UTL_RAW.TRANSLATE`, `CAST_FROM_NUMBER` and friends, and the other supplied
