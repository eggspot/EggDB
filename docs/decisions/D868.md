## D868 OTLP export over HTTPS — Decided by the code-only session (2026-11-12, D355); follow-up of D567, D666 and D688

- `eggdb serve --otlp-endpoint https://...` now sends metrics, logs and traces over TLS, through the same HTTPS
  client report delivery uses (`eggdb-tls`, full certificate and host-name verification). The collector's
  certificate is checked against the PEM file `OTEL_EXPORTER_OTLP_CERTIFICATE` names, OpenTelemetry's own variable
  for it, or the system's trusted roots when it is unset; a collector that fails verification misses that minute's
  records like one that is down.
- `http://` endpoints work as before. The report-delivery HTTPS helpers gained a form that takes the trust variable,
  so each feature keeps its own (`EGGDB_REPORT_CA_FILE` for reports).
- Left: client certificates (`OTEL_EXPORTER_OTLP_CLIENT_CERTIFICATE`) and OTLP over gRPC.
