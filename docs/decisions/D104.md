## D104 SQL takes `$n` parameters as text bound at parse time, describes statements without running them, and keeps PostgreSQL's run-time parameters — Decided by the build loop (2026-10-27); roadmap item 21, refines D98
**Parameters.** `Session::execute_prepared` takes one `Parameter` per `$n`: the type the client
declared (from its type OID, when EggDB stores that type) and the value's text, or NULL. The
parser substitutes each `$n` with that text as a constant: a quoted constant of unknown type
when no type was declared, so its place in the statement types it exactly as PostgreSQL types
`'42'` (`id = $1`, `VALUES ($1)`), or a cast to the declared type. So text-format values follow
PostgreSQL's input rules for each type, binary values are decoded by the server to the same text
first, and no value is ever spliced into SQL text. The statement is parsed again at each
execution; a plan cache is item 19e's work. `$0` and a missing value are `42P02`.
`Session::prepare` checks a prepared statement's syntax and counts its parameters without
reading the catalog, and refuses more than one statement (`42601`), as PostgreSQL's `Parse`
does; a missing table is reported at execution, not at `Parse`.

**Descriptions.** `Session::describe` parses the statement and resolves its tables and columns
in a snapshot without reading rows, giving `ParameterDescription` and `RowDescription`. A
column's type is the one SQL knows before reading rows: a table column, a cast, a constant, an
aggregate (`count` is `bigint`, `sum` of integers `bigint`, `avg` `double precision`, `min` and
`max` their argument's type), or an operator or function whose result type its operands fix.
Where no type is known (a NULL, an untyped parameter in the select list) the column is described
as `text` and its values sent in text form. Parameters whose type the client did not declare are
described as `text`; inferring them from their place (`id = $1` as `integer`) is later work.

**Run-time parameters.** A session keeps PostgreSQL's settings: `SET`, `SET TIME ZONE`, `SET
NAMES`, `RESET`, `RESET ALL`, `SHOW` and `SHOW ALL`, and the startup packet's parameters.
`server_version` is `16.0 (EggDB <version>)` (drivers read the leading number; distribution
builds of PostgreSQL also append text), `server_version_num` `160000`, `client_encoding` and
`server_encoding` `UTF8` (another client encoding is `0A000`), `DateStyle` `ISO, MDY`,
`TimeZone` `UTC`, `standard_conforming_strings` and `integer_datetimes` `on`, and the other
reported parameters are sent to clients at startup and whenever they change. Settings EggDB does
not apply yet (`statement_timeout`, `lock_timeout`, `search_path`, `extra_float_digits`) are
remembered and shown, read-only ones are `55P02`, unknown names `42704`, and names with a dot are
custom settings. `version()`, `current_user`, `session_user`, `user`, `current_role`,
`current_database()`, `current_catalog`, `current_schema` and `current_setting('name')` answer
from the session. `SET LOCAL` and `SET TRANSACTION` are not supported yet (`0A000`).
