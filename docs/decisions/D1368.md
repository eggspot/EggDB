## D1368 The pointer's shape follows what is under it — Decided by the code-only session (2026-11-25, D355); roadmap M6e "... the column-resize cursor (D310)", designed in `docs/ux/polish.md` section 4

- **What users get.** The client sets the system's pointer from one enum, `PointerCursor`, on every pointer move: the I-beam over text fields, text areas and search boxes, left-right and up-down resize arrows over the sidebar, inspector and results splitters and a grid column separator, a hand over links, a closed hand while a grid handle or a separator is dragged, and the arrow elsewhere. No cursor is drawn by the toolkit.
- **Per platform.** X11 makes the seven cursors once from the standard `cursor` font (`OpenFont`, `CreateGlyphCursor` with each shape's glyph and its mask, the next glyph) and sets one with `ChangeWindowAttributes`, only when it changes; Windows answers `WM_SETCURSOR` over the client area with the chosen system cursor (`IDC_IBEAM`, `IDC_SIZEWE`, `IDC_SIZENS`, `IDC_HAND`, `IDC_NO`, `IDC_SIZEALL` for grabbing, which Windows has no closed hand for) and sets it at once on a change; macOS sets the matching shared `NSCursor`. `Window::set_pointer_cursor` defaults to doing nothing, so Wayland and the browser keep their arrow until they implement it.
- **Left.** Wayland's `wp_cursor_shape_v1`, the browser's `canvas.style.cursor` (the name is ready in `PointerCursor::css_name`), `not-allowed` while a non-file drag is over the window, and the pointer over the status bar's clickable items.
- **Proof.** A unit test pins the X11 requests' layout (opcodes, lengths, glyph and mask characters, the `CWCursor` bit) and a CSS name.

**Status:** code written, unbuilt (code-only mode, D355).
