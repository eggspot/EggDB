## D335 One integration-test program per package, and debug builds with line tables only — Decided (owner, 2026-11-04; built by EggAgentCode task 20261104-2050)

The owner: "the test program for 17gb is not a good solution if later we have more tests the
storage could be a lot". Cargo builds every `tests/*.rs` file as a program of its own, and each one
links the whole engine, so the build folder grew with every test file: 94 integration-test
programs in 13 packages, and a debug folder that reached 17 GB as incremental builds piled up.

- **One program per package.** Every package with integration tests has one test target,
  `tests/all/main.rs`, which declares one module per former file (`tests/all/<area>.rs`) and the
  shared helpers (`tests/all/common/`). `Cargo.toml` sets `autotests = false` and one
  `[[test]] name = "all"`. Test data stays where it was (`tests/data`, `tests/screens`,
  `tests/clients`, `tests/c`). The excluded `eggdb-sqlite-compare` follows the same layout.
- **Names.** Each test keeps its name and body; it only gains its file's module
  (`serve::a_server_answers...`), so `cargo test <name>` still finds it. A test that runs its own
  program again as a child passes the module-qualified name to `--exact` (`process::...`,
  `lock_across_processes::...`); with the bare name the child would run no test.
- **One process per package.** A package's tests now run as threads of one process, so a test
  must not depend on process-wide state that another file's tests change (environment variables,
  the current directory, a fixed port). None did; the full suite passes unchanged.
- **Slimmer debug builds.** The workspace sets `[profile.dev] debug = "line-tables-only"`,
  `[profile.dev.package."*"] debug = false` and `[profile.test] debug = "line-tables-only"`.
  Panics and failing tests still report file and line, and backtraces still name
  `tests/all/<area>.rs:<line>` (checked). CI's `CARGO_PROFILE_DEV_DEBUG` and
  `CARGO_PROFILE_TEST_DEBUG` variables, which set the same, are gone.
- **The guard.** `scripts/check-test-layout.sh`, the first step of `lint-and-test`, fails when a
  package with a `tests/` folder lacks `autotests = false` or its one `[[test]]` named `all`, has a
  top-level `tests/*.rs` file or another `tests/<dir>/main.rs`, or has a module file in
  `tests/all/` that `main.rs` never declares. With `autotests = false` such a file would otherwise
  never be compiled, and its tests would silently stop running.

Measured on the 10-core Mac the EggAgentCode runner uses, a clean `cargo test --workspace
--no-run` (`du -sh target`):

| | test programs | build folder, line tables | build folder, full debug info |
|-|-|-|-|
| before (`main` at #98) | 153 (59 unit, 94 integration) | 4.7 GB | 5.6 GB |
| after | 72 (59 unit, 13 integration) | 2.7 GB | 3.4 GB |

Full debug info is Cargo's default, so a checkout without the runner's global
`~/.cargo/config.toml` (which already set line tables) goes from 5.6 GB to 2.7 GB. The full
`cargo test --workspace` lists the same 4775 tests before and after (4774 pass, 1 ignored) and
took 461 s before and 324 s after. A new test file now adds a module, not a program.
