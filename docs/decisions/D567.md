## D567 OTLP export of the server's metrics — Decided by the code-only session (2026-11-12, D355); roadmap M6c, D25, D188

`--metrics-listen` serves Prometheus text for scrapers; teams on OpenTelemetry push instead.
`eggdb serve --otlp-endpoint http://collector:4318` now posts the same metrics to the
collector's OTLP/HTTP receiver (`/v1/metrics`, `application/json`, the protobuf JSON mapping) at
start and then every minute, from a thread that stops with the server.

- **One list of metrics.** `serve_metrics::families` names every metric once (name, type, help,
  samples with an optional database); the Prometheus text and the OTLP request are both written
  from it, so the two never drift. The text is unchanged.
- **Mapping.** Counters are cumulative, monotonic `sum`s whose points start when the server
  started; gauges are `gauge`s; values are `asInt`; a served database is the point's `database`
  attribute; the resource is `service.name` `eggdb` with `service.version`.
- **Failures.** A collector that is down or answers an error loses that minute's points; the
  next export carries the cumulative totals, so sums lose no counts. The URL is checked when the
  server starts. Plain `http://` only, as the CDC webhook client is; TLS, protobuf, and logs and
  traces are later steps.
