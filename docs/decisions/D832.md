## D832 pgRouting's A*, `pgr_dijkstraCost` and `pgr_bdDijkstra` — Decided by the code-only session (2026-11-12, D355); roadmap D57

- `eggdb_route_astar(edges, start, end, directed, heuristic, factor, epsilon)` runs A* over the same edge JSON as
  `eggdb_route_dijkstra` (D782), with node coordinates from each edge's `x1`, `y1` (source) and `x2`, `y2` (target),
  and pgRouting's heuristics: 0 none, 1 max(dx, dy), 2 min(dx, dy), 3 dx² + dy², 4 the straight-line distance, 5
  dx + dy (the default), with dx and dy scaled by `factor` and the estimate by `epsilon` (at least 1). It answers in
  `pgr_dijkstra`'s form; with an estimate that never overstates the cost left the path is a cheapest one.
- `CREATE EXTENSION pgrouting` adds `pgr_aStar(edges_sql, start_vid, end_vid, directed, heuristic, factor,
  epsilon)`, `pgr_dijkstraCost(edges_sql, start_vid, end_vid, directed)` (one row with the total cost, none when the
  end cannot be reached) and `pgr_bdDijkstra`, which answers as `pgr_dijkstra` (the search direction changes speed,
  not the answer).
- Left: many-to-many and combination forms, `pgr_analyzeGraph`, `pgr_nodeNetwork`, TSP and the other families.
