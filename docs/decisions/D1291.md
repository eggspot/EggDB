## D1291 MySQL's missing string and number functions — Decided by the code-only session (2026-11-18, D355); roadmap M4 MySQL compatibility (D10, D1289)

- **What users get.** In MySQL's dialect: `LOCATE(substr, str[, pos])` (case-insensitive, by characters), `SUBSTRING_INDEX(str, delim, count)`, `FIND_IN_SET(str, list)`, `ELT(n, ...)`, `MID`, `STRCMP`, `ORD`, `BIN`, `CONV(n, from_base, to_base)` (2 to 36, a negative target base keeping the sign, else the unsigned 64-bit form), `CRC32`, `UNHEX` (NULL for a non-hex digit), `RAND()` and `RAND(seed)` (the same value for the same seed), and `LOG2` in every dialect. Later the same night (D1302): `INET_ATON`, `INET_NTOA`, `IS_IPV4`, `IS_IPV6`, `UUID_TO_BIN(uuid[, swap])` and `BIN_TO_UUID(bin[, swap])` (the time fields reordered when asked), `SHA1`, `SHA2(text, 224 | 256 | 384 | 512)` as lowercase hex (224 not yet: NULL), `TO_BASE64` and `FROM_BASE64`. `LOCATE` is what D1255's ODBC escape writes for MySQL connections, and WordPress, Magento and Laravel apps use `SUBSTRING_INDEX` and `FIND_IN_SET`.
- **How.** A module answering only in MySQL's dialect, so PostgreSQL's names stay free, reached through the evaluator's function chain after the mathematical functions (D1289), with result types in typing; NULL arguments give NULL as MySQL does, except `ELT`, whose unused arguments may be NULL. `CRC32` is the IEEE polynomial computed bit by bit; `RAND(seed)` mixes the seed with SplitMix64's finaliser.
- **Left.** `RAND(seed)`'s sequence across rows (MySQL seeds a generator per statement; EggDB gives one value per seed), `FOUND_ROWS()`, `FORMAT`'s locale argument, and the `utf8mb4` collations' accent folding in `LOCATE`.
- **Proof.** Unit tests follow MySQL's manual examples for `LOCATE`, `SUBSTRING_INDEX`, `CONV`, `CRC32('MySQL')`, `UNHEX`, `ORD` and a seeded `RAND`.
