## D1103 Tiered storage: memory, local disk and object storage, by how recently pages were read — Decided by the code-only session (2026-11-13, D355); roadmap M18 (D18, D227, D1099)

- **Three tiers in one path.** A page store's pages (D1099) live in memory in the page cache (hot), on local disk as chunk files (warm), and in object storage, which holds every chunk (cold). A read goes down the tiers until it finds the page and fills the faster ones on the way back.
- **Age means time since last read.** "Age" is taken as recency of use, not row age. Recency is what decides whether keeping a page near pays, it needs no schema knowledge, and it also serves time-ordered data, whose old pages simply stop being read. Each chunk carries a use counter, and past the disk budget (`Options::page_store_disk_bytes`, `serve --page-store-disk`) the least recently read chunks leave the disk. Chunks changed since the last sync never leave before they are uploaded, so nothing durable depends on the disk.
- **One file per chunk.** The local cache became a directory with one file per chunk, named by index and version. Evicting is deleting a file, which frees disk on every file system without hole punching, and the directory listing records which chunk versions are held, replacing the old `.chunks` record. A sync renames each uploaded chunk's file to its new version. A `lock` file in the directory carries the engine's file lock. The writer's cache is `<file>.pages`, and the followers of D1101 alternate `<file>.page-cache-a` and `-b`.
- **Placement per table** (which tables may fall to the cold tier, or must stay warm) is the separate roadmap line on placement rules.
