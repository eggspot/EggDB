## D196 A REST API compatible with Elasticsearch and OpenSearch in our own eggdb-esrest — Decided by the build loop (by judgement, 2026-10-31); refines D5 and D34

Part 4.M8-2 asks for the Elasticsearch REST API (`_bulk`, `_search` query DSL, aggregations,
mappings), checked with an official client.

- **Written from the public API documentation only** (the Elasticsearch and OpenSearch REST
  references). Elasticsearch's source is source-available and is never read (D1); an API's
  request and response shapes are what clients need, and the D34 check for this part found no
  patent or licence term on implementing them. The root endpoint reports an OpenSearch-style
  version (`2.11.0`, distribution `eggdb`) and no Elastic product header, so OpenSearch clients
  accept it and nothing claims to be Elastic's product; Elasticsearch's own client checks that
  header and needs its compatibility switch.
- **Same keyspace interface as RESP and memcached.** Indices and documents live through
  `eggdb_resp::Keyspace` in the collection `es0` of the served file, each request one engine
  transaction (a `_bulk` item its own, as Elasticsearch documents bulk items as independent): an
  index is a record holding its mappings, a document a record keyed by index and id holding its
  version and its JSON source as sent.
- **Search scores with BM25 from `eggdb-search`** (k1 1.2, b 0.75, the Elasticsearch defaults),
  analysing text with its English stemmer; `match`, `multi_match`, `match_phrase`, `term`,
  `terms`, `range`, `exists`, `prefix`, `ids`, `match_all`, `match_none` and `bool` (with
  `minimum_should_match`), nested at most 32 deep, plus `size`/`from` (window 10 000), `sort`,
  `q=` and the `terms`, `avg`, `sum`, `min`, `max` and `value_count` aggregations. A search reads
  every document of the index: correct first, and the inverted index of 4.M8-1 replaces the scan
  when it lands.
- **Basic authentication, loopback only.** Every request needs HTTP basic authentication as the
  server's `--user` with its password (compared as SHA-256 in constant time); the endpoint has no
  TLS yet, so `eggdb serve --es-listen` refuses other addresses. Malformed bodies get `400`
  responses in Elasticsearch's error shape, never a panic.

Left: mappings applied to field types (keyword versus text, dates), `_mget`, `_msearch`,
`_update_by_query`, `_delete_by_query`, scripts, `query_string` syntax, highlighting, scroll and
`search_after`, nested and bucket aggregations beyond `terms`, aliases, index templates,
`_cat` beyond indices, TLS, roles per index, Kibana and OpenSearch Dashboards, and a benchmark
against OpenSearch.
