## D872 SQL Server DDL triggers — Decided by the code-only session (2026-11-12, D355); roadmap M5, event triggers

- The SQL Server dialect parses `CREATE [OR ALTER] TRIGGER name ON DATABASE | ALL SERVER [WITH ...] FOR | AFTER
  <event types and groups> AS <batch>`, `ALTER TRIGGER ... ON DATABASE`, `DROP TRIGGER [IF EXISTS] name [, ...] ON
  DATABASE | ALL SERVER` and `ENABLE | DISABLE TRIGGER name [, ...] | ALL ON DATABASE | ALL SERVER`. A statement is a DDL
  trigger statement when `trigger` is followed by `ON DATABASE` or `ON ALL SERVER` before `AS`. Triggers are kept in
  `eggdb_internal.sqlserver_ddl_triggers` (name, scope, events, body, enabled, created), like the other code-only
  features' records. Only an unchecked (administrator) session manages them.
- Event types follow SQL Server's names for the DDL EggDB runs (`CREATE_TABLE`, `ALTER_TABLE`, `DROP_TABLE`, views,
  indexes, procedures, functions, triggers, schemas, sequences, types, `GRANT_DATABASE`, `REVOKE_DATABASE`), and the
  groups that hold them (`DDL_TABLE_EVENTS`, `DDL_TABLE_VIEW_EVENTS`, `DDL_INDEX_EVENTS`, `DDL_PROCEDURE_EVENTS`, ...,
  `DDL_DATABASE_LEVEL_EVENTS`, `DDL_EVENTS`). An unknown name fails with error 1084.
- Firing: when an outermost SQL Server statement is DDL and an enabled trigger covers its event, the statement runs,
  then each trigger's batch, in creation order, all in one transaction (the caller's when one is open). An error in a
  trigger, or a `ROLLBACK` that ends the transaction (error 3609), undoes the statement. Statements inside a trigger
  are not outermost and fire nothing, so triggers never re-fire themselves (SQL Server's nested triggers are off).
- `EVENTDATA()` returns the `EVENT_INSTANCE` document (`EventType`, `PostTime`, `SPID`, `ServerName`, `LoginName`,
  `UserName`, `DatabaseName`, `SchemaName`, `ObjectName`, `ObjectType`, `TSQLCommand/CommandText`) as `xml` text, so
  `@data.value('(/EVENT_INSTANCE/ObjectName)[1]', 'nvarchar(100)')` reads it (D695); `NULL` outside a DDL trigger.
  `CommandText` is the statement's text when it was run straight from a batch, else empty.
- Server-scoped triggers fire on the same database-level events; server-level events (logins, databases) and
  `LOGON` triggers are left, as are `sys.triggers` / `sys.server_triggers` rows for DDL triggers.
