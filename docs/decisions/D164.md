## D164 Unix domain sockets in the platform layer, and the server connection type they share with TCP and TLS — Decided by the build loop (by judgement, 2026-10-31)

Part 4.M1-1 lets local clients reach `eggdb serve` without TCP, as psql and the mysql client do
by default.

- **Platform layer.** `eggdb_platform::local_socket` binds and accepts Unix domain sockets on Unix
  systems. A socket file left by a dead server is replaced; a live one is refused, after a
  connect test, as PostgreSQL does. The socket is made mode 0600. Windows answers "unsupported"
  until its AF_UNIX support is built; the types still exist there, as empty types, so the servers
  compile everywhere.
- **Connections.** `eggdb_tls::ServerConnection` gains a `Local` variant beside plaintext TCP and
  TLS. Both SQL servers take that one type, set timeouts through it, and accept from an optional
  local listener next to the TCP one (`serve_with_local`).
- **No TLS on local sockets.** TLS is never used on a local socket: PostgreSQL's `SSLRequest` is
  answered `N` and MySQL does not offer `CLIENT_SSL` there. A local connection counts as
  loopback, so it may skip TLS on a server that requires it from other machines (D161).
- **Options.** `eggdb serve --socket-dir` and `--mysql-socket`, designed by Claude Fable
  (ux/cli.md section 31). The servers remove their socket files at stop.
