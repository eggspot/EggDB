## D899 A whole-database logical dump: `eggdb export --dump` — Decided by the code-only session (2026-11-12, D355); roadmap M14, follow-up of D93, D446 and D842

- `eggdb export <file> [<out> | -] --dump` writes one logical file of the whole database, and `eggdb restore <new>
  <dump>` (with `--create` for a new file) loads it back:
  - a first line `-- eggdb-dump 1, sql <n> bytes`;
  - the next `<n>` bytes: the PostgreSQL dump of `eggdb export --sql postgresql` (schemas, tables, rows, indexes,
    constraints, views, sequences, roles, grants, routines and triggers; D446, D842);
  - then eggdb-jsonl version 2 lines (D93): the default key space's entries that are not SQL's (keys outside SQL's
    reserved namespace, `eggdb_sql::is_sql_key`), then every collection's entries, an empty collection as a line of
    its own, and the trailer with the count.
- The SQL part carries its length so the restore knows exactly where it ends: a value inside the SQL can never be
  read as the start of the entries.
- Restore detects the first line, runs the SQL part in the PostgreSQL dialect (whatever `--dialect` says), then
  writes the entries in batches. A failure in either part leaves nothing for a new file (the staging file is
  removed) and names the part that failed; for an existing file, what the SQL part committed stays and the message
  says the entries are not in.

Decided by research:
- **A flag on `export`, not a new top-level `eggdb dump`.** The roadmap named it `eggdb dump`, but the command model
  (D143, `eggdb_commands::KEPT_NAMES`) keeps the shipped top-level names closed: a new command is `<noun> <verb>`
  with a core verb, and `export` is the core verb for "items written out to a file or stdout". `--dump` sits beside
  `--sql`, which already writes the SQL part.
- **The two parts are read from two snapshots** (the SQL session's and one read transaction), as `export --sql` and
  `export` are today; a dump taken while other programs write may see a write in one part and not the other. Dump a
  `eggdb backup` copy for an exact point in time.
