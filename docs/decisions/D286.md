## D286 Statement statistics as `pg_stat_statements`, a slow-statement log on every protocol, and `EXPLAIN (ANALYZE, BUFFERS)` from per-thread page counters — Decided by the build loop (EggAgentCode task 20261103-0137, 2026-11-03); roadmap M6c, applies D25, D9, D6 and D188

D25 asks for a slow-query log, statement statistics and `EXPLAIN ANALYZE` with buffers. Before
this, `eggdb serve` had only `log_min_duration_statement`, which logs a PostgreSQL session's
simple queries with their full text and nothing on the other protocols. Monitoring tools
(pgAdmin, Datadog, pganalyze, PMM) read `pg_stat_statements`.

- **Where it is counted.** In `eggdb-sql`, at the one place every client statement runs
  (`Session`'s statement loop), so PostgreSQL, MySQL, TDS, CQL, the REST API and the metrics
  endpoint's SQL are all counted the same way. `eggdb_sql::statement_statistics` holds the
  table and the log, process-wide like `eggdb_sql::activity` (D188). Only statements that
  complete are counted, as PostgreSQL does.
- **Normalized text, secret-safe.** The key is the statement's tokens with every literal
  (numbers, strings, `x'..'` and dollar-quoted text) replaced by `$1`, `$2`, ... numbered after
  the statement's own `$n` parameters, gaps (spaces and comments) folded into one space and a
  trailing `;` dropped. Comments go too, since a comment can carry a value. Literals never
  reach the table or the log, so `CREATE ROLE ... PASSWORD '...'` is kept as `PASSWORD $1`.
  `queryid` is a 64-bit FNV-1a hash of the whole normalized text (stable across runs and
  builds); the text kept is cut at 4096 bytes on a character boundary.
- **Bounded.** `eggdb serve --statement-statistics <count>`, default 5000 (PostgreSQL's
  `pg_stat_statements.max`), `0` off. Sixteen shards, each a mutex over a hash map holding a
  sixteenth of the count, so sessions on different shards never wait for each other; a full
  shard drops its least-called twentieth (at least one entry) before it takes a new
  statement, and `pg_stat_statements_info.dealloc` counts those drops. Off in embedded use: a
  session costs two relaxed loads per statement then, no clock read and no normalizing (D6).
- **Views.** `pg_stat_statements` and `pg_stat_statements_info` are monitoring relations in
  `pg_catalog`, so PostgreSQL sessions find them unqualified and sessions of the other
  dialects as `pg_catalog.pg_stat_statements`. Columns are PostgreSQL's names for what is
  measured: `userid`, `dbid`, `toplevel`, `queryid`, `query`, `calls`, `total_exec_time`,
  `min_exec_time`, `max_exec_time`, `mean_exec_time`, `stddev_exec_time` (Welford, population)
  and `rows`; planning times and block counters are left out rather than shown as zeros.
  Entries are kept per database and the view shows the current database's.
  `pg_stat_statements_reset()` returns `void` as PostgreSQL 16 does and empties the table;
  with a non-zero third argument it drops only that `queryid`.
- **The slow-statement log.** `eggdb serve --log-slow-statements <milliseconds>` (`0` logs
  every statement). Named for what it does, like `--log-batches`. Each line goes to the
  server's log (stderr, after the UTC time) as `slow statement duration_ms=12.345
  database=app user=eggdb protocol=postgresql rows=1 query="SELECT * FROM t WHERE id = $1"`:
  fixed keys in a fixed order, values with spaces, quotes or control characters in double
  quotes. `protocol` is the connection's dialect (`postgresql`, `mysql`, `sqlserver`), or the
  name a server gives with `Session::set_protocol` (`cql`, `rest`, `observability`). The sink
  holds a sender of the log channel and is dropped when the PostgreSQL listener stops, so the
  log loop still ends at shutdown. `log_min_duration_statement` is kept as it was.
- **`EXPLAIN (ANALYZE, BUFFERS)`.** The page cache counts each hit and each read from the file
  in thread-local counters too (`eggdb_storage::thread_page_lookups`), beside its store-wide
  `CacheStats`. A store-wide difference would mix in other sessions' reads; a statement runs
  on its session's thread, so the thread's difference is its own. `KeyValueStore` gains
  `page_lookups()`, `None` by default, which `eggdb`'s `Store` and `OwnedStore` (and the
  served directory's databases) answer. The output follows PostgreSQL's text form:
  `Buffers: shared hit=N read=M` under the top node and under `Planning:`, with zero counts
  left out and no line when both are zero. `BUFFERS off` and `EXPLAIN` without `ANALYZE`
  print none, as PostgreSQL 16 does for execution.

Not yet: per-node `Buffers` lines (the executor does not count per node, so the statement's
total goes under the top node, which in PostgreSQL also includes its children), `dirtied` and
`written`, local and temp blocks, `I/O Timings`, per-user entries (the key is database and
text; `userid` is the one session-user OID), planning-time columns and `plans`, squashing
`IN (...)` lists of different lengths into one entry (PostgreSQL 18), folding `-1` into one
placeholder, the extended protocol's parse-time statistics, `pg_stat_statements` over the
MySQL wire's `performance_schema.events_statements_summary_by_digest` and SQL Server's
`sys.dm_exec_query_stats`, counters for `TransactionStore` and `SharedWriteStore` sessions
(embedded transactions print no `Buffers` line), and slow-statement lines for failed
statements.
