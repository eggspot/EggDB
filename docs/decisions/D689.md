## D689 Oracle RETURNING ... INTO :bind in eggdb shell — Decided by the code-only session (2026-11-12, D355); roadmap M10, Oracle's `RETURNING ... INTO` (sql.md)

- PL/SQL blocks already run `INSERT`, `UPDATE` and `DELETE ... RETURNING ... INTO variables`. A statement typed at
  the top level in Oracle, `INSERT INTO orders ... RETURNING id INTO :new_id`, needs an output bind, which only a
  client provides. `eggdb shell` now provides it for its `VARIABLE`s: such a statement is run as
  `BEGIN statement; END;` through D686's output binds, so `:new_id` holds the returned value afterwards, as in
  SQL*Plus.
- The statement is recognised by its first word (`INSERT`, `UPDATE`, `DELETE`) and a `RETURNING ... INTO` whose
  first target is a bind variable; other statements run as before, with binds read as literals (D622).
- docs/sql.md's list of what the Oracle dialect does not support is brought up to date: `(+)` outer joins (D432),
  synonyms (D433) and the SQL/XML publishing functions (D454) were done; database links, `ROWID` and the rest of the
  XML functions are not.
