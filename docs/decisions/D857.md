## D857 Oracle `DBMS_APPLICATION_INFO`, `DBMS_SESSION`, `DBMS_LOCK.SLEEP` and `DBMS_STATS` — Decided by the code-only session (2026-11-12, D355); roadmap M10, the other Oracle-supplied packages (D733)

- One package intercept (`dbms_session.rs`, like `DBMS_SCHEDULER` and `DBMS_RLS`) takes calls to four packages, with
  named or positional arguments; an unknown member is `PLS-00302`.
- `DBMS_APPLICATION_INFO.SET_MODULE(module_name, action_name)`, `SET_ACTION` and `SET_CLIENT_INFO`, and
  `DBMS_SESSION.SET_IDENTIFIER` / `CLEAR_IDENTIFIER`, keep their values as session settings (`eggdb.oracle_module`,
  `eggdb.oracle_action`, `eggdb.oracle_client_info`, `eggdb.oracle_client_identifier`), cut to Oracle's lengths (48,
  32, 64 and 64 bytes) at a character boundary; `NULL` clears one. `SYS_CONTEXT('USERENV', 'MODULE' | 'ACTION' |
  'CLIENT_INFO' | 'CLIENT_IDENTIFIER')` reads them, so a VPD predicate (D851) can filter by the client identifier an
  application sets, as Oracle's common pattern does.
- `DBMS_SESSION.SLEEP(seconds)` and `DBMS_LOCK.SLEEP(seconds)` run `pg_sleep`, so a cancel stops them; a negative or
  non-finite time is ORA-20000.
- `DBMS_STATS.GATHER_TABLE_STATS(ownname, tabname, ...)` runs `ANALYZE` on that table (the owner maps to its schema
  as for VPD), and `GATHER_SCHEMA_STATS` and `GATHER_DATABASE_STATS` run `ANALYZE` on every table; their sampling,
  degree and other options are accepted and not used, since EggDB's statistics read every row.
- Left: the `READ_MODULE` and `READ_CLIENT_INFO` out-parameter procedures, `V$SESSION`'s module and action columns,
  and `DBMS_SQL`, `DBMS_METADATA` and `UTL_FILE`.
