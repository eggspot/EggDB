## D552 `IS JSON` accepts `\u0000` in a `json` value — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D302

PostgreSQL's `json` type accepts `\u0000` inside strings on input; only turning the value into
text (`->>`, `#>>`) or into `jsonb` refuses it. `IS JSON` read text, `json` and `bytea` subjects
with the parser `jsonb` uses, so `'"\u0000"' IS JSON` was false where PostgreSQL says true. It now
reads them as `json` input does (`json::parse_json_input`), so the escape is kept as a character;
`jsonb` subjects are unchanged, since they can never hold it. A broken escape such as an unclosed
string is still not JSON.

The `json` type's own input check (`'"\u0000"'::json`) still refuses the escape, where PostgreSQL
keeps it; widening that changes what every `json` function may meet, so it is left for its own
change.

Still open from D302: `IS JSON` on a document nested deeper than the parser's 256 levels gives
false, where PostgreSQL gives true.
