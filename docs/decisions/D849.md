## D849 T-SQL cursor variables — Decided by the code-only session (2026-11-12, D355); roadmap M10, D291

- `DECLARE @c CURSOR` (alone or in a list beside scalar variables) declares a cursor variable, and `SET @c = CURSOR
  [FORWARD_ONLY | SCROLL] [STATIC | KEYSET | DYNAMIC | FAST_FORWARD] [READ_ONLY | ...] FOR query` gives it a cursor,
  with the options `DECLARE ... CURSOR` takes except `LOCAL`/`GLOBAL` and the ISO `INSENSITIVE`/`SCROLL` prefix, as
  SQL Server allows. `OPEN @c`, `FETCH ... FROM @c [INTO ...]`, `CLOSE @c` and `DEALLOCATE @c` work on it.
- A cursor variable is a local cursor named by the variable (`@c`), so the existing cursor engine runs it; it lives
  as a local cursor does. A `DECLARE` of only cursor variables runs nothing.
- Left: assigning one cursor variable to another, cursor-typed procedure parameters (`CURSOR VARYING OUTPUT`), and
  `SET @c = CURSOR` on a variable that already holds an open cursor.
