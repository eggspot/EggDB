## D1365 Encrypting a file and rotating its key by compacting it under the new key — Decided by the code-only session (2026-11-25, D355); roadmap M6b "Encrypting an existing file and rotating keys online" (D23, D187); security-critical (D35)

- **What users get.** `eggdb compact <file> --new-key-file <file>` (and `Database::compact_with_key`) rewrites the file with every page encrypted under the new key: a file that held plain data becomes encrypted, and an encrypted one (opened with `--key-file`) moves to the new key. Programs reading the file keep reading the file they opened until they open it again, now with the new key, as with any compaction.
- **Why compaction.** D187 encrypts each page under a keystream from its LSN and page number, and a page can only be re-encrypted by writing it again. Compaction already rebuilds the whole file from one snapshot as `<file>.compacting`, syncs and checks it, and renames it over the file in one step, so a crash leaves the old file under the old key or the new file under the new key, never a mix of both keys, and no page is ever written under a keystream used before: the new file starts its own LSNs under a new page key. Rewriting pages in place under a second key would need the file to record which pages use which key and a crash story for half-rotated files, for no gain over the swap.
- **How.** `CopyDestination` gains `key: CopyKey`, `Same` (the source's key, what backups and plain compactions keep) or `Use(key)`, which the copy adopts before its first commit, so the new superblock carries the new key's check value and the `ENCRYPTED_PAGES` feature. The key is never printed: `CopyKey`'s `Debug` hides it, and the CLI reads it from a file like `--key-file`.
- **Left.** Removing encryption from a file (a deliberate downgrade, which gets its own option and confirmation), rotating while a program has the file open for writing (it needs that program's writer to hand over, as `BACKUP TO` does for backups), and keys from `--key-source` for the new key.
- **Proof.** Storage tests copy an encrypted file under a new key (no plaintext on disk, readable with the new key, the old key refused) and copy a plain file under a key (the plaintext gone from the copy, readable with the key).
