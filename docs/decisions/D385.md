## D385 PostgreSQL's `ALTER COLUMN ... SET EXPRESSION` and `DROP EXPRESSION` — Decided by the code-only session (2026-11-10, D355); roadmap M5, extends D322

PostgreSQL 17 changes a generated column's expression or turns it into an ordinary column.

- **`SET EXPRESSION AS (expr)`** replaces the column's generation entry and checks the new
  expression as `CREATE TABLE` does (`generated_columns::define`, keeping the column's type), saves
  the definition, recomputes every row in place (`rewrite_in_place` with the table's generator),
  checks `NOT NULL` and the table's `CHECK` constraints on the new values, and rebuilds the table's
  index entries. A column in the primary key or a unique index is refused with `0A000`, since the
  rewrite does not check uniqueness yet.
- **`DROP EXPRESSION [IF EXISTS]`** removes the generation entry and keeps the stored values; it
  is `55000 column ... is not a generated column` on another column, or a notice with `IF
  EXISTS`. A column other generated columns read is refused (`0A000`).
- No format change: the table definition's generated-column list already holds the expression.
