## D1173 Identity and serial sequences answer nextval and setval, a table holds any number of identities with any options, and bound frame offsets are bigint — Decided by the code-only session (2026-11-15, D355); roadmap M6a (SQLAlchemy's dialect suite, D308)

D308 listed what SQLAlchemy's suite still failed on; this batch writes three of them.

- **`nextval`, `currval` and `setval` on an identity's or a `SERIAL` column's sequence.** EggDB counts such a column from the furthest value in the table, so its sequence had no state and these calls were refused. A per-table high-water mark is now stored (key space `0x1B`, the table id, the last value handed out as 8 big-endian bytes). `nextval` hands out the column's next value and moves the mark; `setval(v)` and `setval(v, false)` set it so the next value is `v + increment` or `v`. An insert takes the next value after the further of the mark and the table's furthest value, so values drawn by `nextval` are never given out again. Unlike PostgreSQL, a `setval` below values already in the table does not make inserts collide with them: the next value still follows the table's furthest. `DROP TABLE` deletes the mark; `TRUNCATE` keeps it, as PostgreSQL's default `CONTINUE IDENTITY` keeps the sequence.
- **Several identity columns, identities outside the key, and `MAXVALUE`, `MINVALUE`, `CYCLE`.** EggDB's counted identity (one per table, a key column, D294's format) stays for the first identity or serial column in the primary key. In PostgreSQL's dialect every other identity or serial column, and any identity whose options end or cycle it before its type's range, is created as PostgreSQL itself does it: an owned sequence with those options and a `nextval` default, marked as the column's identity (`attidentity`), through the same code as `ALTER TABLE ... ADD GENERATED ... AS IDENTITY` (now `alter::attach_owned_sequence`). Serial columns get the sequence and default without the identity mark, as in PostgreSQL. Temporary tables refuse limited identities, since their sequence would outlive them.
- **Bound frame offsets.** A `ROWS` or `GROUPS` offset given as an untyped value (a parameter bound as text, or a quoted literal) is read as `bigint`, as PostgreSQL types it; text that is not a number is `22P02`.
- Tests: `identity_columns_show_their_implicit_sequence_in_the_catalog` (now drawing with `nextval` and `setval`), `identity_columns_beyond_the_key_and_with_limits_draw_from_their_own_sequence` and `an_untyped_rows_offset_is_read_as_bigint_as_a_bound_parameter_is`.
