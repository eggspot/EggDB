## D553 `IS JSON` past the parser's nesting limit — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D302

The JSON parser refuses documents nested deeper than 256 levels (`54001`), so hostile input cannot
exhaust the stack, and `IS JSON` answered false for them where PostgreSQL, whose `IS JSON` only
checks syntax, answers true. When the parser stops at its depth limit, `IS JSON` now reads the
text again with `json::scan_json_input`: the same token rules (strings with `\u0000` allowed,
numbers, `true`, `false`, `null`), but with open arrays and objects kept on a heap stack, so any
depth costs memory in proportion to the text and no recursion. It returns the outermost kind,
which `VALUE`, `SCALAR`, `ARRAY` and `OBJECT` test, and whether any object repeats a key, which
`WITH UNIQUE KEYS` tests; each open object keeps the set of its keys. Documents within the limit
still go through the parser, so both paths agree where both apply. `jsonb` subjects never exceed
the limit, since `jsonb` input refuses such documents.
