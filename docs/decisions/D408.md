## D408 MongoDB's projection operators and expressions in `find` — Decided by the code-only session (2026-11-10, D355); roadmap M9

`find` and `findAndModify` projections take what MongoDB 4.4 and later take:

- **`$slice`**: `n` (the first `n`, or the last `-n`) or `[skip, limit]` (a negative `skip` counts
  from the end; `limit` must be positive). It doesn't set the projection's mode: alone it keeps
  every field and slices the array; with inclusions it keeps the array too.
- **`$elemMatch`**: the first array element (a document) matching the filter, as a one-element
  array, or no field when none matches; it makes the projection inclusive when nothing else has,
  and is refused on a nested field, as in MongoDB.
- **Positional `path.$`**: the first element through which the query matched
  (`matched_array_index`, as the positional update operator uses it), kept as a one-element
  array; only one per projection, and never with exclusion. With no match the field is left out,
  where MongoDB fails the query: a known difference. `Projection::apply_matching` takes the query;
  `apply` (without one) shows no positional field.
- **Expressions and literals**: a value that is a string, array, null or an operator document
  (`{total: {$add: ["$a", 1]}}`, `{name: "$profile.name"}`) is evaluated against the document and
  makes the projection inclusive; an expression that evaluates to nothing or fails leaves the
  field out. A nested document of plain fields (`{a: {b: 1}}`) is read as `a.b`.
- `$meta` stays not implemented until `$text` exists; a path part starting with `$` other than a
  final `.$` is MongoDB's error.
