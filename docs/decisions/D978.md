## D978 `eggdb serve --tls-client-ca` — Decided by the code-only session (2026-11-13, D355); roadmap M6b, D803's leftover

- D803 read the trusted authorities for client certificates from `EGGDB_TLS_CLIENT_CA` only. Every other TLS setting
  of `eggdb serve` is an option, and an environment variable is easy to lose in a service manager's unit file, so
  `--tls-client-ca <file>` now names the PEM file directly. It wins over the variable, which is still read when the
  option is absent so existing deployments keep working; errors name whichever source was used.
- Nothing else changes: the listeners ask for a certificate and verify it as D803 does (TLS 1.3), and `cert` rules in
  `--auth-rules` decide what a verified certificate signs in as.
