## D328 MCP agents store and delete keys with `put` and `del` under the agent permission model, and `eggdb serve --mcp-tables` limits every session of the MCP endpoint as `eggdb mcp --tables` does — Decided by the build loop (EggAgentCode task 20261104-1214, 2026-11-04); roadmap M6d, follows D189, D190, D281, D292 and D306, applies D9, D11, D35, D121, D143 and D156; security-critical (D35)

The built-in MCP server read keys (`kv_get`, `kv_scan`, with collections since D292) but could
not change them, and `--tables` (D156, D281, D306) limited only `eggdb mcp`: the MCP endpoint of
`eggdb serve` (D189) always showed every table.

**What users can do.**

- With `eggdb mcp --allow-write`, an agent gets two more tools: `put` stores a value under one
  key and commits, replacing any value and time to live there, with an optional `ttl` (`30s`,
  `5m`, `1h30m`, `7d`, `1500ms`, the grammar of `eggdb put --ttl`) and `collection`; `del`
  deletes one key and commits, and says whether it was there. Keys and values are text (`key`,
  `value`) or hexadecimal bytes (`key_hex`, `value_hex`).
- Every `del` needs the user's confirmation exactly as a destructive `write_sql` does: the
  server asks through `elicitation/create` when the client can ask (the question names the key,
  shown as escaped text or `0x` hex and cut at 200 characters, and its collection, and warns when
  names mix alphabets), and otherwise the call needs `confirm: true`. A decline is
  `declined_by_user`, an unconfirmed call `needs_confirmation`, and nothing is deleted.
- `eggdb serve --mcp-listen ... --mcp-token-file ... --mcp-tables users,orders` gives every MCP
  session the endpoint opens the same `VisibleTables` filter as `eggdb mcp --tables`: the same
  names, column lists and quoting (one parser, `add_table_names`), the same start checks and
  messages (`table_not_found`, `column_not_found`, naming `--mcp-tables` and `eggdb serve`), and
  no key-value tools. `--mcp-tables` without `--mcp-listen` is a usage error.

**How it works.**

- **Registry (D143).** `put` and `del` are the CLI twins' words, as every new tool's name is.
  `put` has effect `change`; `del` has effect `destroy` and the new confirm check `key_delete`.
  Both need the new grant `key_value_write`: `--allow-write` on a server that also grants the
  key-value store, so they are withdrawn under `--tables` (`limited_to_tables`) and for an agent
  signed in with a role (`limited_to_role`, D190), like `kv_get` and `kv_scan`, and refused with
  `read_only` on a read-only server, the default. The time-to-live parser moved from `eggdb-ui`
  to `eggdb-commands` (`parse_time_to_live`), which `eggdb-ui` re-exports, so the CLI, the GUI and
  the tool read one grammar.
- **Store.** `eggdb_sql::KeyValueWrite` gains three default methods for the tools only:
  `put_with_expiry`, `collection_put` and `collection_delete` (the defaults refuse with
  `0A000`). `eggdb::sql::SqlWriter` implements them on `WriteTransaction` and `WriteCollection`;
  the MCP server's `LimitedWrite` forwards them with the call's time limit and its 256 MiB change
  limit, and `VisibleWrite` refuses them (`42501`) whenever it is confining tables.
- **Safety.** A key in SQL's key space (`RESERVED_KEY_PREFIX`) is refused before anything opens
  (`invalid_arguments`): tables change only through SQL, under the table filter and the role's
  privileges. A key the engine keeps for collections and times to live fails with `22023` (the
  engine's `ReservedKey`, now mapped to that SQLSTATE instead of `XX000`). A collection must
  exist; a missing one rolls back and answers `collection_not_found` with the names there.
- **Audit.** A key write goes through the same path as `write_sql`: a `call_started` record
  before it runs and a `call` record with `confirmation`, `committed` and `warning` after, and a
  committed write whose record cannot be written is reported as committed, never as failed. The
  confirmation and audit steps of `write_sql` became shared (`confirmed`, `record_write_start`,
  `PendingWrite::tool`), and the elicitation text takes an `Asked` (a statement or a key).

**Decided by research.**

- *Two tools named `put` and `del`, not one `kv_put`.* D143 names every tool after its CLI
  twin's words, and keeps the old `kv_` names only for the tools that shipped before it; a tool
  per twin also lets `del` alone carry `destroy` and the confirmation.
- *Only `del` asks; `put` does not.* A `put` names exactly one key, like an `UPDATE` pinned by its
  primary key, which D121 and D255 do not ask about; `eggdb ui` and `eggdb del` treat deleting as
  the destructive step. Every `del` asks, whether or not the key is there, so the answer never
  depends on a read the user did not see.
- *`--mcp-tables`, not `--tables`, on `eggdb serve`.* Every MCP option of `eggdb serve` carries
  the `mcp-` prefix (`--mcp-listen`, `--mcp-token-file`), and a bare `--tables` there would read
  as limiting the PostgreSQL, MySQL and SQL Server listeners too, which it does not.

**Tests.** `eggdb-mcp` (`tests/key_writes.rs`): refused on a read-only server, under `--tables`
and for a role; `put` stores and replaces with two audit records each; SQL's key space, a bad or
zero `ttl`, a missing value and an unknown argument refused; `del` needs `confirm: true` and
says whether the key was there; the elicitation asked and its answer obeyed; a store without
collections refuses a collection. `confirmation.rs`: the key question's text, hex keys and the
cut. `tools.rs`: the tools list with and without the grant, and the instructions. The built
binary (`tests/mcp.rs`): refused read-only, a `put` read back with `eggdb get`, a collection
`put` with a time to live read back with `eggdb ttl`, a missing collection, a reserved key, an
unconfirmed and a confirmed `del`, a declined elicitation and the audit records; `tests/serve.rs`:
two HTTP MCP sessions of `eggdb serve --mcp-tables orders` list only `orders` and fail
`SELECT ... FROM secrets` with `42P01`, and an unknown name and a missing `--mcp-listen` stop the
server. `eggdb-commands`: the grant, the confirm check and the moved parser.

Left: `put` and `del` for agents with a role (they would need key-level grants), writes over
`eggdb serve`'s MCP endpoint (still read-only, D189), a key allow-list per session (collections
by name) to offer the key-value tools under `--tables`, counters, compare-and-set and `expire`
as tools, and `expires_at` in `put`'s result to match `eggdb put --json`.
