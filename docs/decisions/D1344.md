## D1344 SQL Server's SELECT ... INTO keeps NOT NULL through inner joins and of non-null expressions — Decided by the code-only session (2026-11-25, D355); roadmap M5 "SQL Server's SELECT ... INTO transferring the identity property ... and keeping NOT NULL through inner joins and of non-null expressions" (D342)

- **What users get.** A table made by `SELECT ... INTO` (and `CREATE TABLE ... AS`) gets `NOT NULL` on every column SQL Server's rules make non-nullable, not only on plain columns of one table (D342): columns of any table of an inner, cross or comma join, qualified by table name or alias or unqualified when the name is unambiguous, `t.*` and `*` across the joined tables, non-NULL constants, `CAST` of a non-null expression, `ISNULL(x, y)` with a non-null `y`, and `COALESCE` with a non-null argument. An outer join, a derived table or grouping sets keep the old rule: nothing is marked, as SQL Server marks nothing that may be NULL.
- **Left.** Transferring the identity property, which needs an identity counter kept outside the primary key, a file format change with its D35 review.
- **Proof.** A SQL Server test copies an inner join with a column of each kind into a new table and gets error 515 for a NULL in each non-null column and none for the nullable one; a `LEFT JOIN` copy accepts NULLs everywhere.

**Status:** code written, unbuilt (code-only mode, D355).
