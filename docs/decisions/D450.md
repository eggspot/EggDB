## D450 Oracle's `IS JSON` (lax, `STRICT`, `TYPE`), `JSON_SERIALIZE`'s `PRETTY`, `ASCII` and `TRUNCATE`, and `JSON_SCALAR` — Decided by the code-only session (2026-11-11, D355); roadmap M10, finishes D302's Oracle part

- **`IS [NOT] JSON` in Oracle's dialect** goes through PostgreSQL's predicate (D302) with Oracle's
  clauses: `FORMAT JSON`, `STRICT` or `LAX`, `ALLOW`/`DISALLOW SCALARS` (accepted), `TYPE (SCALAR |
  ARRAY | OBJECT)` beside the bare shape words, and `WITH`/`WITHOUT UNIQUE KEYS`. Oracle's default
  is lax, so unless `STRICT` is written the subject passes through an internal rewrite of lax JSON
  into standard JSON first: unquoted member names quoted, single-quoted strings double-quoted,
  `TRUE`, `FALSE` and `NULL` in any case lowered, and `+1`, `.5` and `1.` written out. Text that
  isn't lax JSON either is left alone, so the standard check refuses it. Oracle's other lax
  allowances (comments, numbers like `0x1F`) are not read.
- **`JSON_SERIALIZE` in Oracle** takes `PRETTY` (two-space indentation, `"key" : value`, as
  Oracle prints it), `ASCII` (non-ASCII characters as `\uXXXX`, surrogate pairs beyond the BMP) and
  `TRUNCATE` (cut to the `RETURNING` type's length instead of failing), in any order, and accepts
  `ERROR` or `NULL ON ERROR`. The options travel as a third internal argument, so PostgreSQL's
  two-argument calls are unchanged.
- `JSON_SCALAR` and `JSON_SERIALIZE` are now parsed in Oracle's dialect too. Left: `JSON()` in
  Oracle, Oracle's `JSON` type, and `JSON_SERIALIZE ... ORDERED`/`EXTENDED`.
