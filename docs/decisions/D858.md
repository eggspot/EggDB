## D858 Oracle application contexts — Decided by the code-only session (2026-11-12, D355); follow-up of D857 and D851

- `CREATE [OR REPLACE] CONTEXT namespace USING [schema.]package` and `DROP CONTEXT namespace` (a new
  `Statement::OracleContext`) keep the namespace and its trusted package in `eggdb_internal.oracle_contexts`; creating
  an existing one without `OR REPLACE` is ORA-00955, dropping a missing one ORA-04043. `INITIALIZED EXTERNALLY |
  GLOBALLY` and `ACCESSED GLOBALLY` are refused as not supported.
- `DBMS_SESSION.SET_CONTEXT(namespace, attribute, value)`, `CLEAR_CONTEXT(namespace, client_id, attribute)` and
  `CLEAR_ALL_CONTEXT(namespace)` work only from a routine of the package the context names; anywhere else, an
  anonymous block included, they fail with ORA-01031. That check is what makes a context safe to filter rows by: a
  VPD predicate (D851) such as `tenant_id = SYS_CONTEXT('APP_CTX', 'TENANT')` cannot be fooled by a user setting the
  value. The package is compared by its name without the schema.
- The values live in the session's PL/SQL state, beside package variables, not in settings, so `SET` and
  `set_config` cannot reach them. Names compare in upper case, a value holds at most 4,000 bytes (ORA-01401), and a
  session keeps at most 10,000 values. `SYS_CONTEXT` reads them for any namespace other than `USERENV`, and returns
  NULL for an unset attribute.
- Left: `username` and `client_id` scoping of global contexts, `DBA_CONTEXT` and `SESSION_CONTEXT` views.
