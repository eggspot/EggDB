## D917 `IMPORT FOREIGN SCHEMA` — Decided by the code-only session (2026-11-12, D355); roadmap M18, follow-up of D916

- `IMPORT FOREIGN SCHEMA remote [LIMIT TO (t, ...) | EXCEPT (t, ...)] FROM SERVER s INTO local [OPTIONS (...)]` reads
  the remote schema's columns from the source's own `information_schema.columns` through `eggdb_foreign` (PostgreSQL,
  EggDB, MySQL and SQL Server all have it; the query aliases the fields so every dialect answers with the same names,
  and gives SQL Server an `N'...'` literal) and makes one foreign table (D916) per remote table in the local schema,
  with `schema_name` and `table_name` options pointing back at it.
- Remote data types map to EggDB's: the integer, float, numeric, boolean (MySQL's `bit`), date and time
  (`datetime`, `datetime2`, `datetimeoffset`), `uuid` (`uniqueidentifier`), `json`/`jsonb` and binary types to their
  PostgreSQL types, and everything else to `text`, which keeps the value as the source wrote it.
- The import needs the source allowed in `EGGDB_FOREIGN_SOURCES`, like any read; a `file_fdw` server has no schema to
  import and is refused.
