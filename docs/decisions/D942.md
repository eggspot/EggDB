## D942 The TDS server on local connections, and `eggdb serve --tds-pipe` — Decided by the code-only session (2026-11-13, D355); roadmap M1, follow-up of D941

- `eggdb_tdswire::serve_directory_with_local` takes a `LocalListener` beside the TCP listener, as the MySQL server
  already does; `serve_directory` calls it without one. The accept loop yields an `Accepted` connection (TCP with its
  address, or local), and `Wire::new_local` serves a `LocalStream` through a new `TdsStream::Local`.
- **A local connection is this machine.** It counts as loopback for the login rules, has no peer address for the
  throttle and auth rules, and is never offered TLS: `read_prelogin` drops the TLS configuration for it, so a client
  that asks for encryption is answered `ENCRYPT_NOT_SUP`, and `start_tls` on it fails without losing the stream. The
  pipe's owner-only DACL and `PIPE_REJECT_REMOTE_CLIENTS` (D941) are what protect it, as D164 decided for local
  sockets.
- `eggdb serve --tds-pipe <name>` (Windows only, needs `--tds-listen`) binds the pipe; SQL Server's clients open
  `sql\query` for a local default instance (`SQL_SERVER_DEFAULT_PIPE`). The startup lines and JSON status show it.
- **Left.** Attention packets that cancel a running batch are watched with `peek` on the TCP socket; a pipe connection
  has no watcher yet, so a cancel there takes effect when the batch ends.
