## D913 Foreign sources and scheduled copies from object storage — Decided by the code-only session (2026-11-12, D355); roadmap M16, ETL connectors, follow-up of D229 and D769

- `eggdb_foreign(source, '*')`, and so `eggdb_etl`'s scheduled copies (D769), read `s3://bucket/key.csv` and
  `s3://bucket/key.parquet` objects from S3-compatible storage, through the same client and settings as `eggdb
  backup s3://` (D226): the endpoint in `AWS_ENDPOINT_URL` (`http://` for now), the keys in `AWS_ACCESS_KEY_ID` and
  `AWS_SECRET_ACCESS_KEY`, the region in `AWS_REGION`. A CSV object is read like a `file:` CSV (RFC 4180, the first
  record naming the columns, values as text) and a Parquet object like a `file:` Parquet file; at most 1 GiB.
- An `EGGDB_FOREIGN_SOURCES` entry `s3://bucket/prefix/` allows the objects under that prefix of that bucket only:
  the key must continue the prefix after a `/`, and a key with `.` or `..` segments is refused, so an entry never
  reaches a sibling prefix (`s3://lake/sales/` does not allow `s3://lake/salesman/...`). As for files, nothing is
  reachable unless an entry allows it, and `#roles=` limits an entry to roles.
- The CSV reader now reads any buffered input, so files and objects share it; the Parquet reader likewise reads
  bytes.
