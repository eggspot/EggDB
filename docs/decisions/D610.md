## D610 Debezium's schema section — Decided by the code-only session (2026-11-12, D355); roadmap M14, D210, D528

Kafka Connect sinks (JDBC sink, Elasticsearch sink, the S3 sink with Avro or Parquet) need the
record's schema. With Debezium's JSON converter and `schemas.enable=true` each event is
`{"schema": …, "payload": envelope}`. EggDB sent only the envelope.

- `CREATE EXTENSION eggdb_cdc` now also makes `eggdb_cdc.options (name, value)`.
  `INSERT INTO eggdb_cdc.options VALUES ('schemas.enable', 'true')` turns the schema section on
  for every delivery: webhooks, queues and topics. It is off by default, so existing consumers
  keep the bare envelope, and a file whose extension predates the table counts as off.
- When it is on, each event becomes `{"schema": …, "payload": …}`.
  - The schema is Debezium's envelope struct: the `before` and `after` structs named
    `<db>.<schema>.<table>.Value`, then `source` (`io.debezium.connector.eggdb.Source`), `op` and
    `ts_ms`. The whole struct is named `<db>.<schema>.<table>.Envelope`, version 1.
  - Column fields come from `information_schema.columns`, in table order, `optional` when the
    column takes NULL. Each table is read once per delivery round.
- Types follow how `to_jsonb` writes the values, so schema and payload agree:
  - `smallint`, `integer` and `bigint` are `int16`, `int32` and `int64`;
  - `real` is `float`;
  - `double precision` and `numeric` are `double`, as Debezium's `decimal.handling.mode=double`
    gives;
  - `boolean` is `boolean`;
  - every other type is `string`.
- Debezium's semantic type names (`io.debezium.time.*`) are not set, since the values are the
  JSON text forms, not epoch counts.

Not done: transaction metadata (`transaction.id`, `total_order`, `data_collection_order`, and the
BEGIN/END events). A trigger has no transaction id to read yet, so it needs one exposed per
transaction first.
