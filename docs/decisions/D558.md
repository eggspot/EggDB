## D558 A protocol `Describe` of a `DECLARE`d cursor — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D308

psycopg 3's server-side ("named") cursors run `DECLARE "name" ... CURSOR WITHOUT HOLD FOR ...`,
then ask the extended protocol to `Describe` the portal of that name to learn its columns before
the first `FETCH FORWARD n FROM "name"`. SQL cursors live in the session's own portal list, apart
from the protocol's portals, so the wire server answered `34000` (`portal "name" does not exist`)
and the cursor failed. `Session::declared_cursor_columns` now gives a `DECLARE`d cursor's columns,
and the PostgreSQL server answers a portal `Describe` with them, in text format, when no protocol
portal has that name; a protocol portal of the same name still wins, as PostgreSQL keeps both in
one namespace and refuses the second. `FETCH`, `MOVE` and `CLOSE` stay SQL statements, as psycopg
sends them.

**Status:** code written, unbuilt (code-only mode, D355).
