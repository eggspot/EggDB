## D1208 An Airbyte source and destination — Decided by the code-only session (2026-11-17, D355); roadmap M6f, an Airbyte source and destination (D46, D239)

- **What users get.** Custom Airbyte connectors (`connectors/airbyte-eggdb`, one image built per role): the **source** lists a schema's tables as streams with JSON types for their columns and their primary keys, and reads them in full or incrementally after a cursor column, emitting stream state; the **destination** writes each stream into `_airbyte_raw_<stream>` (the record as `jsonb` and its time), appending or overwriting, in batches of 1,000 rows, committing and echoing state at each state message, so a failed sync resumes from the last state.
- **How.** The Airbyte protocol itself (`spec`, `check`, `discover`, `read`, `write`: JSON messages on standard output) written in Python over `psycopg2`, without Airbyte's CDK, since the protocol is small and public; EggDB is reached through its PostgreSQL protocol. D16's rule: a tool's connector in the tool's ecosystem; nothing ships inside `eggdb`.
- **Left.** Typed final tables beside the raw ones (Airbyte's destinations v2 typing and deduplication), change data capture reading EggDB's change stream (D210) as a source mode, server-side cursors for very large tables, publishing to Airbyte's registry (the owner's), and the compatibility job.

**Status:** code written, unbuilt (code-only mode, D355).
