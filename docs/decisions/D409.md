## D409 MongoDB's `$jsonSchema` query operator — Decided by the code-only session (2026-11-10, D355); roadmap M9

- `$jsonSchema` is a filter node holding a schema checked when the filter is parsed
  (`json_schema::check_schema`) and walked for each document (`schema_holds`), in the JSON Schema
  draft 4 subset MongoDB documents: `bsonType` (MongoDB's type aliases, `number` included) or
  `type` (the JSON types; `integer` is refused as in MongoDB, and naming both is an error),
  `enum`, `properties`, `patternProperties`, `additionalProperties`, `required`,
  `minProperties`, `maxProperties`, `dependencies`, `items` (one schema or a list),
  `additionalItems`, `minItems`, `maxItems`, `uniqueItems`, `minimum`, `maximum`,
  `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minLength`, `maxLength` (in code
  points), `pattern`, `allOf`, `anyOf`, `oneOf`, `not`, `title` and `description`.
- As in JSON Schema, a keyword about one type holds for values of other types (`minimum` on a
  string, `required` on an array). `$ref`, `$schema`, `default`, `definitions`, `format` and `id`
  are "not currently supported", as MongoDB says; any other keyword is unknown. Both fail with
  `FailedToParse`.
- Collection validators (`validator` in `create` and `collMod`), which also take `$jsonSchema`,
  are a separate item.
