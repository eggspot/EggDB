## D818 Anchored audit digests — Decided by the code-only session (2026-11-12, D355); roadmap D26, D231

- D231's chain finds edits inside the audit file but not records cut off its end or a file rewritten whole. An
  anchor closes that: the newest digest (SHA-256 of the last line), kept somewhere the file's writer cannot change.
- `eggdb audit <db> --verify` now prints the newest digest (and `newest_digest` in JSON). Run with
  `EGGDB_AUDIT_ANCHOR=<digest>`, it also looks for the record with that digest and fails with `audit_truncated` when it
  is gone, even if the remaining chain is intact.
- `AuditLog::append_with_digest` returns the digest of the line it wrote, and `eggdb serve` with `EGGDB_AUDIT=1`
  prints `audit digest after N records: <digest>` on standard error every 1,000 records, so its log (collected by a
  service manager or a log server) holds anchors as it goes. `verify_chain_to_anchor` is the library check.
- Left: signing digests with the server's key, and retention of old audit records.
