## D1201 OpenMetadata's API, read-only — Decided by the code-only session (2026-11-17, D355); roadmap M6c, the Apache Atlas and OpenMetadata APIs (D51)

- **What users get.** The REST listener answers OpenMetadata's API under `/openmetadata/api/v1` (a client's host and port take the `/openmetadata` prefix): `system/version`, `services/databaseServices`, `databases`, `databaseSchemas`, `tables` (all, or one schema's with `?databaseSchema=<fqn>`), `tables/name/<fqn>` and `lineage/table/name/<fqn>`. Tables come with their columns (OpenMetadata's data types, the SQL type as shown, `NOT_NULL`, position), their `eggdb_catalog` glossary terms as tags, and lineage edges from `eggdb_catalog.lineage`, so a catalog that speaks OpenMetadata's API reads EggDB live instead of through an ingestion job.
- **Names and ids.** Fully qualified names are `eggdb.<database>.<schema>.<table>` (service, database, schema, table), and an entity's id is a UUID made from the SHA-256 of its name, so it never changes while the name does not.
- **Rights.** Each answer is read by the caller's own session, so a role sees only what `information_schema` shows it.
- **Left.** Writes (creating entities, posting tags or descriptions back), pagination cursors, the many other entity types (dashboards, pipelines, topics), and Apache Atlas's API.
- **Proof.** A unit test lists a schema's tables, finds one by name with its columns, and gets 404 and 405 where it should.

**Status:** code written, unbuilt (code-only mode, D355).
