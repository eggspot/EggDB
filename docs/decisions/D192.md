## D192 The official drivers over the network: the C API's SQL session can be a connection through our own PostgreSQL client — Decided by the build loop (by judgement, 2026-10-31); refines D16 and D17

Part 4.M6f-1 asks for the M5 drivers in server mode through a Rust client core over our
protocols.

- **One session type, two backends.** `eggdb_sql_connect(url, &sql)` returns the same
  `eggdb_sql` handle as `eggdb_sql_open`, backed by `eggdb_pgwire::client::PgClient` (our own
  PostgreSQL protocol client with SCRAM and TLS, already used by `eggdb follow`) instead of an
  in-process session. Every driver over the C API gains server mode by passing a
  `postgresql://` URL where it takes a file, with no protocol code of its own (D16).
- **Parameters never become SQL text.** `eggdb_sql_execute_with_parameters` on a server sends
  the extended query protocol (`Parse`, `Bind` with text parameters, `Describe`, `Execute`,
  `Sync`); `eggdb_sql_execute` sends a simple query. Values come back as text and are typed by
  the columns' type OIDs: booleans and integers as integers, `float4`/`float8` as reals,
  `bytea` as blobs, the rest as text, as an in-process session gives them.
- **The client core stays `eggdb-pgwire`'s client** rather than a new `eggdb-client` crate,
  because it already is the Rust client the plan asked for; the C API depends on it.
- Server mode is PostgreSQL's dialect (placeholders `$n`, which the drivers' `?` become).

Left: the MySQL and TDS protocols as backends, a connection pool in the drivers, prepared
statement reuse, binary result formats for speed, cancel, COPY, and the benchmarks against each
language's best driver (D17).
