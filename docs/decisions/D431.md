## D431 Oracle's `DEFAULT ... ON CONVERSION ERROR` — Decided by the code-only session (2026-11-11, D355); roadmap M10

- `TO_DATE`, `TO_NUMBER`, `TO_TIMESTAMP`, `TO_TIMESTAMP_TZ`, `TO_DSINTERVAL` and `TO_YMINTERVAL`
  take Oracle 12.2's `(value DEFAULT fallback ON CONVERSION ERROR [, format [, nls]])`. The parser
  looks ahead for `DEFAULT` before the first comma, so calls without it are parsed as before, and
  wraps the call in an internal Oracle function (`oracle_with_default`) whose arguments are the
  inner function's name, the value, the fallback and the rest.
- Evaluation calls the inner function on the value; when it fails with a data exception (SQLSTATE
  class `22`, which every conversion error of these functions is), it calls it again on the
  fallback with the same format, as Oracle converts the default with the same format and fails if
  that conversion fails too. The fallback is evaluated whether it is needed or not, which matters
  only for a fallback with side effects (Oracle requires a literal, a bind or a constant
  expression there). The result type is the inner function's.
- Left: `CAST(value AS type DEFAULT fallback ON CONVERSION ERROR)` and `VALIDATE_CONVERSION`.
