## D1082 The storage engine without std, with a fixed-frame cache — Decided by the code-only session (2026-11-13, D355); roadmap M17 (D41, D223, D1081)

- `eggdb-storage` gains a default `std` feature. Without it the crate is `#![no_std]` with `alloc`, and the
  B-tree, cursors, overflow chains, page cache, write-ahead log, page file, transactions, the LSM tree and
  value compression all build for a microcontroller.
  - The engine's modules now name `core` and `alloc` (`cell`, `collections`, `fmt`, `ops`, `ptr`, `mem`,
    `cmp`, `iter`, `sync::Arc`, `sync::atomic`). A small prelude brings `Vec`, `Box`, `String`, `vec!` and
    `format!` into no-`std` builds only.
  - The engine reads and writes through `eggdb-platform-core` (D1081): `Error`, `ErrorKind`, `File`,
    `FileLock` and `Clock`. `eggdb-platform` itself is an optional dependency, part of `std`.
- **The fixed-frame cache.** `PageCache::with_frame_buffer(file, buffer: &'static mut [u8])` lays the cache's
  frames over a buffer the caller owns, as many whole pages as it holds. It is the fixed memory budget of
  D223, and nothing is allocated for frames later.
  - `Frames` now has a backing: a platform `MemoryRegion` (with `std`, as before) or the caller's buffer.
  - `lock_in_memory` and NUMA placement exist only with `std`.
  - `PageCache::new` (memory from the platform) is `std`-only.
- **Kept to `std`:**
  - opening and creating a file through a `FileSystem` and a path. `PageFile::create_in` and `open_in`,
    which take a `File`, work everywhere: a flash driver's `File` goes there;
  - `put_from_reader` and `ValueReader`'s `std::io::Read`;
  - `std::error::Error` for `StorageError`;
  - online snapshot copies.
- **Without `std`:**
  - The store's lock is a spin lock (`sync.rs`, two documented `unsafe` dereferences and one `unsafe impl
    Sync`), enough for a single core. It answers `lock` as the standard library's `Mutex` does, so the store
    code is unchanged.
  - Page lookups are counted in two global atomics instead of per thread.
  - Pages are not encrypted: AES and HKDF live in `eggdb-crypto`, which needs `std`. The cipher type cannot
    be made (it holds an `Infallible`), so every encryption path is statically unreachable, and giving a key
    is refused as unsupported.
- With `std`, everything behaves as before. The changes there are import paths and `cfg` attributes, and
  `PageCache::new` sharing its body with the new constructor.
- CI's Cortex-M step now also runs `cargo clippy -p eggdb-storage --no-default-features --target
  thumbv7em-none-eabihf`. As code written in code-only mode, its first run is expected to need a fix-up pass.
- Left: `eggdb-crypto` without `std` (then encrypted pages on devices), wear levelling and the header slots on
  flash, and the QEMU Cortex-M run.

**Status:** code written, unbuilt (code-only mode, D355).
