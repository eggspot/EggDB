## D1346 SQLite's INTEGER affinity for INT columns other than the row id — Decided by the code-only session (2026-11-25, D355); roadmap M4 "SQLite's dynamic typing for INTEGER columns ..." (D305)

- **What users get.** In the SQLite dialect a column whose declared type names `INT` (`INT`, `BIGINT`, `SMALLINT`, `INTEGER` when it is not the row id, ...) now has SQLite's `INTEGER` affinity: text that is a well-formed number is stored as a number, other text stays text, and a real that is not a whole number stays a real, as SQLite's datatype page describes; `typeof()` reports each value's class. D305 had left these columns as `bigint`, which refused `'abc'` and rounded `2.5`.
- **What stays `bigint`.** The row id: an `INTEGER PRIMARY KEY` (column or table constraint, declared exactly `INTEGER`) keeps the engine's 64-bit integer, so row ids, `AUTOINCREMENT`, the SQLite file importer's row-id alias and every integer key work as before. A `STRICT` table keeps its `INTEGER` columns `bigint`, so they refuse what is not an integer. `CREATE TABLE ... AS` in the SQLite dialect gives integer columns the new affinity, declared `INT` as SQLite writes it.
- **The file format.** A new affinity code, `5`, after D305's type tag `25` (table-definition version 13). A release that knows version 13 but not the code refuses the table as damaged rather than misreading it, as D305 specified for unknown codes. Tables already stored keep their `bigint` columns.
- **Left.** An integer compared with a `TEXT` column turned into text first, column-to-column comparison affinity, `CAST(x AS NUMERIC)` giving integers (CAST reads a numeric prefix, unlike storing), views keeping their sources' affinity, per-value classes in the C API's column kinds, and the benchmark of keyed `TEXT` lookups.
- **Proof.** A SQLite-dialect test stores `'12'`, `'abc'`, `3.0`, `2.5` and `'4'` in `INT` and `BIGINT` columns and reads values and `typeof()` back, refuses text as a row id, keys a table by an `INT` column holding text, and refuses text in a `STRICT` table's `INTEGER` column.

**Status:** code written, unbuilt (code-only mode, D355). A file format change, for the build-and-fix pass's D35 review.
