## D489 SQL Server's `sys.dm_exec_sessions`, `sys.dm_exec_requests` and `sys.dm_exec_query_stats` — Decided by the code-only session (2026-11-11, D355); roadmap M6c, D25, D286 and D488

- The TDS listener registers its connections in the session registry (D488), reporting each
  batch's start and end, so they show in `pg_stat_activity` and the process list too.
- `sys.dm_exec_sessions` lists every registered session (`session_id`, `login_time`, `host_name`,
  `program_name`, `login_name`, `running` or `sleeping`); `sys.dm_exec_requests` (new) lists the
  sessions running a statement now, with `start_time`, `command` (the statement's first word),
  `total_elapsed_time` in milliseconds and, as an EggDB column, `statement_text`. Without a server
  both keep one row for the current session.
- `sys.dm_exec_query_stats` (new) shows the statement statistics `pg_stat_statements` reads
  (D286): `execution_count`, `total_worker_time`/`total_elapsed_time`/`min_elapsed_time`/
  `max_elapsed_time` in microseconds, `total_rows`, the statement's 64-bit id as `query_hash`, and
  its normalized text as `statement_text` in place of `sys.dm_exec_sql_text(sql_handle)`, which is
  not written.
- A session's database stays the one it logged in to after `USE`. MySQL's
  `performance_schema.events_statements_summary_by_digest` needs the `performance_schema` schema,
  which EggDB's MySQL catalog does not have yet.
