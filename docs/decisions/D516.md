## D516 AMQP message TTL, dead-letter exchanges and delayed messages — Decided by the code-only session (2026-11-11, D355); roadmap M16

- **Queue arguments:** `queue.declare` now reads its arguments table: `x-message-ttl`,
  `x-dead-letter-exchange` and `x-dead-letter-routing-key`, as RabbitMQ names them. The policy is
  kept in the broker's memory and set again by every non-passive declare, as clients redeclare
  their queues on connecting; it is not stored in the file yet.
- **TTL:** a message's lifetime is the smaller of the queue's `x-message-ttl` and the message's
  `expiration` property (milliseconds), counted from when it was sent (the queue store's
  `sent_ms`). An expired message is dropped when a consumer or `basic.get` would receive it,
  RabbitMQ's own lazy expiry at the head of the queue.
- **Dead-lettering:** an expired message, or one rejected or nacked without requeue, is
  republished to the queue's dead-letter exchange with the dead-letter routing key or its own,
  its properties and body unchanged, never back into the same queue. Messages delivered from a
  dead-lettering queue keep their body with the channel until settled, so a reject can
  republish it. RabbitMQ's `x-death` header is not added yet.
- **Delayed messages:** a published message's `x-delay` header (milliseconds) delays its
  visibility on every queue it reaches, through the queue store's existing delay, as the
  delayed-message exchange plugin does; publishes inside a transaction are not delayed yet.
- **Priorities:** `x-max-priority` is refused with `NOT_IMPLEMENTED`: ordering by priority needs
  a change to the queue store's key layout, which waits for its format review.
