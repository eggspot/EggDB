## D1245 Publications, and the replication stream filtered by them — Decided by the code-only session (2026-11-17, D355); roadmap M14, PostgreSQL's replication protocol served (D18, D1031, D1243)

- **What users get.** PostgreSQL's `CREATE PUBLICATION name [FOR ALL TABLES | FOR TABLE t [, ...] | FOR TABLES IN SCHEMA s [, ...]] [WITH (publish = 'insert, update, delete, truncate')]`, `ALTER PUBLICATION ... ADD | DROP | SET TABLE ...`, `ALTER PUBLICATION ... SET (publish = ...)`, `RENAME TO`, `OWNER TO` and `DROP PUBLICATION [IF EXISTS] ...`, with PostgreSQL's errors (a duplicate name, a missing table or schema, tables added to a `FOR ALL TABLES` publication, a table added twice or dropped when absent), listed in `pg_publication` and `pg_publication_rel`. `--pg-replication` now sends only the changes of the tables the subscriber's `publication_names` cover, and of the kinds they publish, as a PostgreSQL subscription and Debezium expect; a missing publication or a missing `publication_names` is refused. A transaction left with no change is not sent. `eggdb follow` of another EggDB, which creates a `FOR ALL TABLES` publication when the source has none, now finds and creates it there.
- **How.** A `publications` module keeps each publication in its own key space (`PUBLICATION_SPACE` 0x21): flags for all tables and the four actions, the tables by internal name (resolved when the statement runs, so a later rename of a table is not followed) and the schemas. `Session::publication_filter` reads the named ones, and `PublicationFilter::publishes` keeps a change when any of them covers its table and kind, so several publications add up as in PostgreSQL. Catalog OIDs come from a hash of the name in their own range.
- **Left.** Column lists and row filters (refused with `0A000`), truncates in the stream, `pg_publication_namespace` rows and the `pg_publication_tables` view, `publish_via_partition_root`, owners other than the session user, and following table renames.
- **Proof.** A test in `publications.rs`: records round-trip, actions parse; an end-to-end SQL test creates, alters, lists, renames and drops publications with the refusals above, and checks the filter keeps an `INSERT` on a listed table, drops a `DELETE` the publication does not send and a table it does not list, and lets a second `FOR ALL TABLES` publication add the rest; `walsender.rs` tests the `publication_names` option.
