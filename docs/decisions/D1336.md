## D1336 Learned indexes over sealed LSM runs, in memory — Decided by the code-only session (2026-11-25, D355); roadmap M2 "Learned indexes, first over the LSM tree's sealed runs" (D40, D170)

- **What users get.** Point gets on tables stored in LSM trees (`WITH (storage = lsm)`, D1119) read one leaf of each sealed run instead of descending its inner pages, once a run has been read: a model from the key to the leaf replaces the inner levels.
- **The model.** A piecewise linear approximation (the "shrinking cone" construction of the PGM index, written from the paper's description) from a key's first eight bytes, read as a big-endian number, to the position of the leaf whose lowest key comes at or before it, with an error of at most four leaves. A get tries the predicted leaf and its neighbours within the error, nearest first; a leaf answers only when its fence keys cover the key, so keys sharing their first eight bytes over many leaves, or any other miss, fall back to the ordinary descent. The answer is never taken from a model alone.
- **Where it lives.** In memory, in the page cache, by run root page, built the first time a run is read. Nothing is stored, so there is no file format change and no D35 review. A model names the log position (LSN) of its run's root page; a reader, the writer or any snapshot, uses it only when its own view of that root has the same LSN, and builds its own otherwise, so a run merged away and a root page reused can never be read through another run's model. Runs not yet committed (root LSN 0), the delta and a merge's target never use models. Freeing a root forgets its model; a rollback forgets them all; at most 1,024 models are kept.
- **Left.** Storing models with their runs (with a D35 review), learned indexes over B-tree tables, and the roadmap's measurement of point gets with and without them, which belongs to the build-and-fix pass.
- **Proof.** Unit tests: predictions stay within the error for every leaf of a skewed key set; key numbers keep key order. An LSM test writes six runs and reads every key, and keys before, between and after them, twice, through read transactions. The existing random LSM test, with seals, merges and a reopen, now goes through the models.

**Status:** code written, unbuilt (code-only mode, D355).
