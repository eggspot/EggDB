## D778 Reranking models in hybrid search (eggdb_remote_rerank) — Decided by the code-only session (2026-11-12, D355); roadmap M12, reranking models in hybrid search (D31)

- `eggdb_remote_rerank(endpoint, model, query, documents [, api_key])` sends the query and a JSON array of up to 1000
  texts to a rerank endpoint in the shape most rerankers share (`{"model", "query", "documents"}` in, `results` of
  `index` and `relevance_score` out; `data` and `score` are read too), through the same opt-in provider and
  permission rules as D777, and returns the scores as a JSON array in the documents' order, NULL for a document the
  model left out.
- Reranking is the last step of hybrid search: fuse vector and full-text rankings with `rrf_score` (D205), take the
  top candidates, rerank them in one call, and order by the score. Keeping it a function over a candidate list, not
  an operator over a whole table, keeps the remote call to one per query.
- A local reranking model (with the ONNX runtime item) and caching of scores are left.
