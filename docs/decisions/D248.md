## D248 Graph algorithms as Cypher procedures, with communities, triangles and similarity — Decided by the build loop (by judgement, 2026-10-31); refines D206 and D55

Track 4.X-20 asks for Flink-style streaming SQL (event time, watermarks, tumbling, hopping and
session windows, stream joins, `MATCH_RECOGNIZE`), graph algorithms for fraud and
recommendations, and online feature serving. This slice does the graph algorithms.

- **Reachable through `CALL`.** D206 wrote shortest paths, connected components and PageRank,
  but only Rust could call them. Cypher now has `CALL procedure(arguments) [YIELD column [AS
  name], ...]`, standing alone or inside a query, and the algorithms are procedures in the
  `eggdb.` namespace, each yielding node ids that `MATCH ... WHERE id(n) = nodeId` turns back
  into nodes. The names are ours: Neo4j GDS's procedures work on named projected graphs, a
  different model, so copying their names would promise behaviour we don't have.
- **New algorithms:** label propagation communities (deterministic: nodes in id order, ties
  keep the node's label or take the largest), triangle counts per node, and Jaccard node
  similarity over neighbour sets. Node similarity compares only pairs that share a neighbour
  and stops past 4 million pairs, so one hub cannot exhaust memory.
- **Bounded input.** Every count argument is an integer from 0 to 1000, and an unknown
  procedure names the ones that exist.

Left: Louvain and Leiden, betweenness and closeness centrality, weighted shortest paths, k-core,
graph embeddings, the procedures in SQL/PGQ, streaming SQL with watermarks and windows,
`MATCH_RECOGNIZE`, and online feature serving.
