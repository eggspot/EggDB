## D495 Loki's push API — Decided by the code-only session (2026-11-11, D355); roadmap M16, D39

- The observability listener takes `POST /loki/api/v1/push` in Loki's two forms: JSON
  (`{"streams":[{"stream":{labels},"values":[["<unix ns>","<line>"]]}]}`) and Snappy-compressed
  protobuf `PushRequest` (`application/x-protobuf`, as Promtail and Grafana Alloy send it; label
  sets written `{name="value", ...}`, entries with `google.protobuf.Timestamp` times), answering
  204. A gzip `Content-Encoding` on JSON is decoded by the HTTP layer as for other writes.
- Each line becomes a row of `metrics.logs`: one text column per label (added as labels first
  appear, as InfluxDB tags are), the `line` text column and `time`, through the same writer as
  InfluxDB lines and Prometheus remote write, in one transaction per push. At most a million lines
  and 64 labels per stream; structured metadata is ignored.
- Querying logs back with LogQL (`/loki/api/v1/query_range`) is the separate LogQL line.
