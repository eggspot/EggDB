## D1187 Multi-factor sign-in with one-time codes — Decided by the code-only session (2026-11-15, D355); roadmap M6b (D22); security-critical (D35)

- **What users get.** A role can require a second factor from an authenticator app (Google Authenticator, Microsoft Authenticator, 1Password, any RFC 6238 app). `CREATE EXTENSION eggdb_mfa` adds `eggdb_mfa.enroll_totp(role)`, which makes a 160-bit secret with `gen_random_bytes` and returns the `otpauth://totp/EggDB:<role>?secret=<base32>&issuer=EggDB&...` URI to show as a QR code, `eggdb_mfa.remove_totp(role)`, and the view `eggdb_mfa.enrolled`. The secrets table is revoked from `PUBLIC`.
- **The login.** A rule `erin password+totp` makes erin log in over the PostgreSQL protocol with `<password>:<six-digit code>` as the password (split at the last colon, so passwords may contain colons). The password is checked against the role's stored SCRAM verifier first, so a wrong password never spends a code; then `eggdb_sql::mfa::check_totp` accepts the code of the current 30-second step or the one before or after, compared in constant time, and stores the step it matched with `UPDATE ... WHERE last_step < step`, so each code works once, even for two logins in the same moment. As the password goes in clear text, the rule needs TLS or the local socket like `ldap`. Interactive tools (psql, the GUI, DBeaver) need nothing new: the user types the code after the password. MySQL and TDS listeners refuse the rule with a reason.
- **Code.** RFC 4226's HOTP and RFC 6238's TOTP over `eggdb-crypto`'s HMAC-SHA1 and RFC 4648's base32 in `eggdb_auth::totp`, checked against the RFCs' test vectors.
- **SAML** is the other half of the roadmap line and comes in its own batch.
- Tests: the RFC vectors, the window and replay, base32, and `an_enrolled_role_signs_in_with_its_current_code_once`.

**Status:** code written, unbuilt (code-only mode, D355).
