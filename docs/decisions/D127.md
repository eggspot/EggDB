## D127 Restoring Oracle schemas from SQL*Plus-style scripts and SQLcl CSV: item 35's runner with a SQL*Plus reader, schemas for users, disabled constraints dropped and re-added, includes only through the caller's opener, and no file-format change — Decided by the build loop (by plan review, by judgement and by research, 2026-10-29); roadmap item 43, applies D1, D9, D10, D13, D96, D108, D118, D125, D126

D13 puts Oracle's scripts in the group EggDB restores directly and Data Pump, `exp` and RMAN files
behind a documented route. Item 43 builds both on item 35's restore runner (D118), as generalised
by item 40 (D125), and on the Oracle dialect (D108, D126). Nothing new is stored: no format
version, no D35 review.

**Two ways in.** `eggdb restore --dialect oracle` reads a SQL*Plus-style script (SQL Developer's
and SQLcl's exports, `impdp ... SQLFILE=` output, installers such as Oracle's sample schemas)
through an Oracle-dialect session. `eggdb import --dialect oracle --csv` loads SQLcl `UNLOAD` and
SQL*Plus `SET MARKUP CSV ON` files through `COPY`, which the Oracle dialect now parses: an empty
field is NULL (Oracle keeps no empty strings) and dates are read by the session's NLS format, then
as ISO 8601 (D126). SQL*Plus itself cannot connect (no Oracle wire protocol, D10).

**One runner (decision 1).** `restore_dump` dispatches on the session's dialect; Oracle's arm uses
a `SqlPlusReader` (`restore/sqlplus_reader.rs`) and `RestoreRules::oracle()` with
`classify_oracle` (`restore/classify_oracle.rs`). The reader follows SQL*Plus's rules, written from
the SQL*Plus User's Guide and Reference and SQLcl's documentation: a statement ends at `;` outside
strings, `q'..'` quotes, quoted names and comments, or at a `/` line; PL/SQL units (`DECLARE`,
`BEGIN`, a `<<label>>`, `WITH FUNCTION`, `CREATE [OR REPLACE] [EDITIONABLE ...] PROCEDURE |
FUNCTION | PACKAGE [BODY] | TRIGGER | TYPE [BODY] | LIBRARY | JAVA`) end only at a `/` line; a `.`
line ends a statement unrun; text left at the end of a script is listed, unrun. Three differences
from SQL*Plus, by judgement and listed in docs/migrate.md: blank lines never end a statement
(SQL*Plus's default `SQLBLANKLINES OFF` would drop such statements unrun), `/` after a statement
ended by `;` does not run it again (it is listed), and `;` ends a statement anywhere outside
quotes and comments, not only at a line's end. A `/` line inside an open string or block comment
is part of it (research says SQL*Plus may end there; EggDB keeps the text whole).

**SQL*Plus commands.** A line outside a statement whose first word is not a SQL word is a
command, matched with SQL*Plus's documented abbreviations; a trailing `-` continues it, `REM`
included (research: the REMARK page says so). `DEFINE`, `UNDEFINE`, `SET DEFINE | SCAN | ESCAPE |
CONCAT`, `@`, `@@`, `START`, `CONNECT`, `EXECUTE` (a skipped PL/SQL call) and `EXIT`/`QUIT` act;
`SET SQLTERMINATOR`, `BLOCKTERMINATOR`, `SQLPREFIX` and `SQLBLANKLINES OFF` are refused because
they change how the script is read; everything else (`SET`, `PROMPT`, `SPOOL`, `HOST`, `ACCEPT`,
`COLUMN`, SQLcl's `UNLOAD`, ...) is listed, never run. `--` and `/* */` lines between statements
are comments, so `impdp`'s `-- CONNECT HR` never acts.

**Substitution (decision 8).** `&name`, `&&name` and `&name.` are replaced in statements and
command lines (not `REM`), inside strings and comments too, as SQL*Plus does; an `&` not followed
by a name character stays literal (by judgement: the documentation does not say). An undefined
variable is an error only where its text is used: a statement that runs, a user or schema name,
or an include's name; in skipped PL/SQL, client commands and the unused clauses of `CREATE USER`
it stays as written, which is why HR's installer restores with no `--define`. `ACCEPT` never
prompts: its variable takes its `DEFAULT` when that has no undefined variable, or stays undefined.
`--define name=value` and `@script arg ...` (`&1`, `&2`) set variables. Limits: 1,024 variables,
240-byte values (SQL*Plus's DEFINE limit), statements of 1 GiB.

**Includes (decision 9).** `eggdb-sql` never opens a file. `RestoreOptions` gains a lifetime and
an `includes: Option<&dyn IncludeOpener>`; the reader owns the include stack and asks the opener
with an `IncludeRequest { name, relative_to, script, line }`. The CLI's opener resolves `@@`
against the including script's folder and `@`/`START` against the working directory (SQLPATH is
not searched), adds `.sql` to a name without an extension, and opens regular files only, checked
on the opened handle. Nesting stops at 20 (SQL*Plus's limit) and opens at 10,000 per restore;
URLs are never fetched. This is a deliberate difference from item 35's never-run `\i`: SQL*Plus
installers are built on `@@`. `RestoreReport::scripts` names each script as written, and every
listed item carries its script's index.

**Transactions (decision 2).** The Oracle session never autocommits, so the runner commits after
every statement it runs and rolls back after a failure. An anonymous block whose statements are
all `INSERT`, `UPDATE`, `DELETE`, `MERGE`, `COMMIT` or `NULL` (no binds, `RETURNING`, `FORALL`,
`%` attributes) runs statement by statement as one transaction, committed at its `COMMIT`s and
its end and rolled back whole on an error, as Oracle rolls back a failing block; HR loads its
216 rows this way. A script's `COMMIT` is ignored; `ROLLBACK` is ignored with a known difference.

**PL/SQL (decision 3).** Stored PL/SQL and every other block are skipped and listed ("PL/SQL comes
after v0.2.0", D110). The classifier decides before anything runs, so `ALTER TRIGGER x DISABLE`
after a skipped trigger is counted under "PL/SQL settings", never a consequence.

**Schemas are users (decision 5).** `CREATE USER x`, `CONNECT x`, `ALTER SESSION SET
CURRENT_SCHEMA = x` and a `CREATE TABLE | VIEW | SEQUENCE x.name` make schema `x` when it is
missing; logins and passwords are never created, stored or shown, and a statement shown in the
report is cut before the word `IDENTIFIED`. To make this work, a schema-qualified name in the
Oracle dialect now names that schema: `HR.EMPLOYEES` is `hr.employees`, `"PUBLIC".T` the default
schema, and the session user's own name keeps meaning `public` (this supersedes D126's "another
schema is ORA-00942"). A view whose name names another schema is created with `CURRENT_SCHEMA` set
to that schema, as Oracle resolves a view's names in its owner's schema. An index's schema must
be its table's.

**Disabled constraints (decision 6).** `ALTER TABLE t DISABLE CONSTRAINT n` (and `MODIFY
CONSTRAINT n DISABLE`) on a foreign key or a CHECK written in Oracle drops it, keeping its clause
built from the catalog (`constraints::constraint_clause`, with the parent table stored resolved);
the matching `ENABLE` adds it again over the loaded rows, as item 40's add-constraint effect, so
rows that violate it make "not created: existing rows violate it" instead of an error. `ENABLE
NOVALIDATE` checks anyway (a known difference), keys stay enforced (a known difference), a
constraint written `DISABLE` in `CREATE TABLE` or `ADD CONSTRAINT` is remembered from its text, and
one still disabled at the end is not created (a known difference). Nothing is stored.

**Engine syntax (decision 7), each accepted with no effect in the Oracle dialect.** Physical
properties after a table, an index and `USING INDEX` (`SEGMENT CREATION`, `PCTFREE`, `STORAGE
(...)`, `TABLESPACE`, `LOGGING`, compression, `ORGANIZATION HEAP | INDEX` with `PCTTHRESHOLD`,
`LOB (...) STORE AS`, `COMPUTE STATISTICS`, `PARALLEL`, ...); constraint states (`ENABLE`,
`VALIDATE`, `RELY`, `USING INDEX`), with `NOT NULL DISABLE` meaning nullable; `MODIFY (c
CONSTRAINT n NOT NULL ENABLE)`; `ALTER TABLE ... ADD (columns and constraints ...)` applied in
order; `SCALE`, `EXTEND`, `NOSHARD` on sequences (`SHARD` is ORA-03001); `DEFAULT COLLATION`,
`BEQUEATH` and the binary `COLLATE` names; `PARTITION BY ...` (one unpartitioned table, a known
difference). A primary key named like an index of its table on the same columns takes that index
over (the index is dropped and the key takes the name), and a unique constraint named like such a
unique index is that index; a non-unique index with the name is ORA-00955. `ORGANIZATION
EXTERNAL`, clusters and nested-table storage stay 0A000, so such tables are skipped with their
rows counted. Identity columns with options and virtual columns are rewritten out of `CREATE
TABLE` by the restore, with a known difference each.

**Routes (decision 11).** Data Pump, `exp` and RMAN files are refused on content (NUL bytes in the
first 64 KiB); the `.dmp` extension only words the message, which gives the `impdp ... SQLFILE=`
route. Nothing past "is it text" is read.

**Fixtures (decision 12).** `crates/eggdb/tests/data/oracle/hr/` holds Oracle's four HR scripts
unchanged (MIT, each with its notice) from `oracle-samples/db-sample-schemas` commit
`6660bad68c07bd143430ace58565b3f727e17263`, excluded from the crate package; the SQL Developer,
`impdp` and CSV fixtures are ours, written in the tools' documented shapes from HR's values. The
acceptance check restores `hr_install.sql` unchanged and checks the documented counts (regions 5,
countries 25, locations 23, departments 27, jobs 19, employees 107, job_history 10) through
Oracle and PostgreSQL SQL, and Oracle's own verification query.

**Decided by research.** REM lines continue with `-` (SQL*Plus Reference, REMARK); SQLBLANKLINES
is OFF by default and `/` re-runs the buffer in SQL*Plus (both listed as differences); the nesting
limit is 20; `EXCLUDE=REF_CONSTRAINT` and `INCLUDE=REF_CONSTRAINT` are valid `impdp` filters; SQLcl
`UNLOAD` writes `<TABLE>_DATA_TABLE.csv` with a header, `"` enclosures and empty fields for NULL;
the HR scripts' MIT notice kept in each file satisfies the licence.

**Left out (43b).** An index named differently in `USING INDEX` is not taken over (the key gets
its own index); a constraint disabled inside a column definition other than `NOT NULL`; SQL*Plus
commands in `eggdb sql` and `eggdb shell`.

**Superseded in part by D134.** The session user's own name means the schema named after the
user when one exists (decision 6 of D134), and the default schema otherwise.

**Superseded in part by D150.** An index named differently in `USING INDEX` is taken over, constraints disabled inside a column are remembered like table-level ones, identities with options are kept when the engine can keep them, and `eggdb sql --dialect oracle` runs SQL*Plus scripts.
