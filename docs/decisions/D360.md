## D360 MySQL's `COALESCE PARTITION`, Oracle's `MERGE PARTITIONS` and `MODIFY PARTITION ... ADD | DROP VALUES`, and `INSERT IGNORE` outside a partition set — Decided by the code-only session (2026-11-10, D355); extends D358 and D337

Built from D358's pieces: every operation reads the rows of the partitions it changes, drops
them, creates the new partitions and inserts the rows through the parent, so each row is routed
again.

- **COALESCE PARTITION n** (MySQL, hash and key tables) keeps the first partitions by remainder,
  drops the last `n` and spreads every row over the new count, as `ADD PARTITION PARTITIONS n`
  does. Range and list tables are `1509`; removing every partition is `1508`.
- **MERGE PARTITIONS a, b, ... INTO PARTITION c** (Oracle). Range partitions are sorted by their
  lower bound and must touch (`ORA-14274`); the merged partition runs from the lowest start to the
  highest end. List partitions merge their values, and a merge that takes the `DEFAULT` partition
  gives a default partition, as Oracle does. Hash tables are `ORA-14255`. The new name may be one
  of the merged ones. The 12.2 range form `MERGE PARTITIONS a TO b` is not parsed yet.
- **MODIFY PARTITION p ADD VALUES (...) | DROP VALUES (...)** (Oracle, list partitions other than
  `DEFAULT`, `ORA-14457` otherwise). Adding a value the partition has is `ORA-14312`, a value
  another partition has fails in the attach's overlap check; dropping a value it lacks is
  `ORA-14313`, dropping all of them `ORA-14314`. The partition and the default partition are
  rebuilt together. Oracle refuses to move rows: added values whose rows sit in the default
  partition are `ORA-14324`, and dropped values that still have rows are `ORA-14518` (or would
  have no partition). EggDB finds both by comparing the partition's row count before and after the
  rebuild, so the error comes after the rows were written: it relies on the statement's rollback
  undoing the rebuild, as D358's other rebuilds do.
- **INSERT IGNORE** (MySQL) into a partitioned table skips a row outside the statement's
  `PARTITION (...)` set (`1748`) or with no partition (`1526`) and reports it as a warning,
  ahead of the duplicate-key warnings of the rows written. An identity value filled for a skipped
  row stays used, as in MySQL.
