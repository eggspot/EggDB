## D241 DynamoDB's API on the key-value store, with keys encoded in DynamoDB's order — Decided by the build loop (by judgement, 2026-10-31); refines D2, D5 and D48

Track 4.X-13 asks for the DynamoDB, Firestore, Bigtable, Cosmos DB, FoundationDB-style
key-value and CouchDB APIs. This slice does DynamoDB.

- **`eggdb-dynamodb`** serves the JSON protocol the AWS SDKs use, signed with the shared SigV4
  code (D219) for the server's user and password, on `eggdb serve --dynamodb-listen` (default
  port 8000, as DynamoDB Local uses). It covers tables with a partition key and an optional sort
  key, item writes, reads and deletes, `UpdateItem` with `SET` and `REMOVE`, `PutItem` with
  `attribute_not_exists`, `Query` with every sort-key condition in either direction, `Scan`, and
  paging through `Limit` and `ExclusiveStartKey`.
- **Items are key-value entries** in the collection `dynamodb0`, keyed by table, then the
  partition key, then the sort key, each encoded so byte order is DynamoDB's order: strings and
  binary escaped and terminated, numbers as order-preserving doubles. A `Query` is a prefix
  scan and its sort-key condition a byte comparison. Each item is kept as the JSON attribute map
  the client sent, so every attribute type round-trips untouched.
- **Numbers in keys order as doubles**, exact to about 15 significant digits. DynamoDB keeps 38,
  so two keys differing only beyond that would tie. A decimal order-preserving encoding replaces
  it before numbers of that size matter.

`BatchWriteItem`, transactions, streams (on D210), TTL, conditions beyond
