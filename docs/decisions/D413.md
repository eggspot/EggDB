## D413 `eggdb restore` of `mongodump --gzip` and `--archive` output — Decided by the code-only session (2026-11-10, D355); roadmap M9

- **`--gzip`** dumps hold `<collection>.bson.gz` and `<collection>.metadata.json.gz`. A dump
  directory (one database or many) or a single file is recognized by `.bson` or `.bson.gz`, each
  file is gunzipped (`eggdb_documents::gunzip_dump`, through `eggdb-content`'s gzip reader, at
  most 4 GiB expanded) and restored as before; metadata is read from the plain or the gzipped
  file.
- **`--archive`** files start with the magic number `0x8199e26d` (little-endian):
  `read_mongodump_archive` reads the prelude (a header document, one metadata document per
  collection with its `.metadata.json` text, a terminator) and then the blocks, each a namespace
  header document followed by documents up to a terminator, interleaved between collections as
  mongodump writes them in parallel; an `EOF` header with no documents is accepted. A file is
  taken as an archive by its magic number, or, when gzipped (`--archive --gzip`), by a name
  ending in `.archive.gz`, `archive.gz` or `.agz`, since any other gzipped file keeps the existing
  "decompress it first" answer for SQL dumps.
- Archives are read whole into memory, one collection's documents after another: a known limit
  until restore streams them. `admin`, `config` and `local`, and `system.` collections, are
  skipped as for directory dumps.
- Unique indexes and the smoke-test sample dump stay open: unique indexes wait for the M9 index
  item.
