## D220 Metrics as SQL tables, written by InfluxDB and Prometheus clients and read by PromQL — Decided by the build loop (by judgement, 2026-10-31); refines D2, D39 and D57

Part 4.M16-8 asks for InfluxDB's line protocol and a store for metrics, logs and traces with
PromQL, LogQL and TraceQL and OTLP ingest. This slice does metrics.

- **A measurement is a SQL table** in the schema `metrics`: `time timestamptz`, a text column
  per tag and a typed column per field (`double precision`, `bigint`, `numeric` for unsigned,
  `text`, `boolean`), created and widened (`ALTER TABLE ... ADD COLUMN`) as tags and fields
  first appear. A Prometheus metric is a table with labels as tag columns and a `value` column.
  So metrics are rows like any other: SQL, `time_bucket` (D201), columnar analytics, backups
  and every SQL protocol read them, with no second time-series engine (D2). A field whose type
  differs from its column is refused as InfluxDB refuses it.
- **Writes**: line protocol at InfluxDB's v1 `/write` and v2 `/api/v2/write` (with
  `precision`), Prometheus remote write 1.0 at `/api/v1/write` (Snappy and protobuf decoded by
  our own code; Snappy moved from `eggdb-parquet` to `eggdb-columnar`, which both use, with a
  literal-only compressor for tests and replies). A request's points are written in one
  transaction.
- **Reads**: PromQL through the Prometheus HTTP API, so Grafana's Prometheus data source works.
  A metric name resolves to a table with a `value` column, or to `<table>_<field>`, the name
  Telegraf's Prometheus output gives InfluxDB fields. Rates follow Prometheus's documented
  extrapolation to the window's edges; instant selectors look back five minutes.
- **One endpoint, one port** (`eggdb serve --observability-listen`, default 8086) serves both
  protocols, signed in as the server's user with Basic, `Token` or `u`/`p`.

Left: InfluxQL and Flux; gzip bodies; deduplication of points with the same series and time
(InfluxDB overwrites them); remote write 2.0, native histograms and exemplars; PromQL
`topk`, `quantile`, `histogram_quantile`, `label_replace`, subqueries, `on`/`ignoring`/
`group_left` matching and the `bool` modifier; selectors without a metric name; logs with
LogQL, traces with TraceQL and OTLP ingest; retention and downsampling; Telegraf and Prometheus
themselves in CI (the InfluxDB client library and a PromQL request stand in); and benchmarks
against InfluxDB and Prometheus.
