## D1170 User tables answer PostgreSQL's system columns — Decided by the code-only session (2026-11-14, D355); roadmap M6a (the catalog)

- PostgreSQL gives every table the system columns `tableoid` (`oid`), `ctid` (`tid`), `xmin` and `xmax` (`xid`), and `cmin` and `cmax` (`cid`). Tools read them: Npgsql and EF Core use `xmin` as a concurrency token, pgAdmin and DBeaver edit rows of tables without a key through `ctid`, and queries over inherited or partitioned tables group by `tableoid`. Until now only the catalog relations answered `tableoid` (D129).
- When a PostgreSQL-dialect `SELECT` names one of these columns, the name resolver reads each plain table of that `SELECT`'s `FROM` as a generated relation, `GeneratedTable::SystemColumns`, instead of a stored-table scan: the table's own columns, then six hidden columns (`\u{2}` names, as `tableoid` already used) that `*` never shows. Statements that name none of them are unchanged, so the cost falls only on the queries that ask. A table with a column of the same name keeps its own column, as PostgreSQL refuses such a column anyway; temporary intermediates and partitioned parents keep their existing paths.
- Values: `tableoid` is the table's `pg_class` OID (stable across renames since D1169). `ctid` is `(block,offset)` with at most 291 rows a block (PostgreSQL's limit for 8 kB pages): from the hidden row id for a table without a primary key, which never changes for a row; from a hash of the key otherwise. `xmin` is a 32-bit hash of the row's key and stored bytes, at least 3 (the first normal transaction id), so it changes whenever an update changes the row, which is what a concurrency token needs; an update that writes the same values keeps it. `xmax`, `cmin` and `cmax` are 0, as for a row no open transaction has locked or deleted. Exact transaction ids wait for MVCC versions on rows (M3).
- New catalog types `tid` (OID 27, text form only on the wire) and `cid` (OID 29, an unsigned 32-bit number like `xid`), with input, casts and `pg_typeof`.
- Not yet: `UPDATE`/`DELETE ... WHERE ctid = ...` and `RETURNING xmin`, which need the same columns on the DML paths; the system columns of a view's base table through the view.
- Test: `user_tables_answer_tableoid_ctid_xmin_and_the_other_system_columns` in `pg_catalog/tests.rs`.
