## D574 MySQL's `event_scheduler` switch — Decided by the code-only session (2026-11-12, D355); roadmap M10, D421

D421 runs MySQL events on the job scheduler but ignored `event_scheduler`, so an operator could
not pause them. `event_scheduler` is now a known system variable (`ON` by default, shown by
`SELECT @@event_scheduler` and `SHOW VARIABLES`); setting it takes `ON`, `OFF`, `1`, `0` or a
boolean, any case, and refuses `DISABLED` as MySQL refuses it at run time (error 1231). The value
set is kept in the file (`eggdb_internal.mysql_settings`), and the scheduler reads it before each
run: while it is `OFF` no event runs, and turning it back `ON` resumes them at their next due time
(missed runs are skipped, as D421 does after downtime). `SET` and `SET GLOBAL` both change it, since
EggDB keeps one value for the file; a new session still shows `ON` until it reads the variable after
setting it, which is the one difference left. `information_schema.EVENTS` stays empty.

**Status:** code written, unbuilt (code-only mode, D355).
