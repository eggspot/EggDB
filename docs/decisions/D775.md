## D775 Modbus frames decoded in SQL (modbus_decode) — Decided by the code-only session (2026-11-12, D355); roadmap M16, OPC UA, Modbus and Sparkplug ingest (D57)

- `modbus_decode(frame, direction [, framing])` reads one Modbus Application Protocol frame from the public Modbus
  specifications: Modbus TCP (MBAP header: transaction, protocol identifier 0, a length that must match the frame,
  unit) or serial RTU (unit address and a CRC-16/MODBUS that must match). The direction is given, since requests and
  responses of the read functions share function codes.
- Functions 1 to 4 (read coils, discrete inputs, holding and input registers), 5 and 6 (write one coil or register)
  and 15 and 16 (write several) come out with addresses, quantities, coils as booleans (low bit first) and registers
  as unsigned 16-bit numbers; byte counts must match the frame. Exception responses (function code with the high bit
  set) give the exception code and name. Other function codes keep their data as hex. Frames over 260 bytes, the
  protocol's limit, are refused.
- Ingest as frames arrive (a Modbus TCP poller under `eggdb serve`, with registers mapped to `eggdb_iot` properties)
  and OPC UA are left.
