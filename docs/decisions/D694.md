## D694 Kafka transactions — Decided by the code-only session (2026-11-12, D355); roadmap M16, Kafka transactions (D33, D213, D546)

- `eggdb-kafka` now runs Kafka's transactions as one broker that is also the transaction coordinator, so Kafka
  clients' transactional producers (`transactional.id`, `beginTransaction`/`commitTransaction`/`abortTransaction`,
  `sendOffsetsToTransaction`) and `isolation.level=read_committed` consumers work against it.
- `InitProducerId` with a `transactional.id` keeps one producer id per id and raises its epoch on every call (a new
  id when the epoch runs out), aborting the transaction an earlier instance left open, so a restarted producer
  fences its predecessor. `AddPartitionsToTxn` (v0–1), `AddOffsetsToTxn` (v0–1), `TxnOffsetCommit` (v0–2) and `EndTxn`
  (v0–1) are served and listed by `ApiVersions`; `FindCoordinator` already answers with this broker for any key type.
- The coordinator state lives in the keyspace beside the logs: per `transactional.id` its producer id, epoch, the
  partitions of the open transaction and the offsets it will commit; per partition, the open transactions' first
  offsets, and the aborted transactions' first and marker offsets.
- A transactional batch is accepted only in a partition its producer added to the open transaction
  (`INVALID_TXN_STATE` otherwise), with the idempotent sequence checks (D546). `EndTxn` writes a control batch (a
  commit or abort marker) to each partition, records an abort for readers, applies the pending group offsets on
  commit, and closes the transaction, all in one keyspace write.
- `Fetch` (v4) reports the last stable offset (the first offset of the oldest open transaction, or the high
  watermark). With `read_committed` it returns only batches below it, with the aborted transactions in range, so the
  client drops their records as Kafka's does.
- Left out: transaction timeouts (an abandoned transaction stays open until its `transactional.id` is initialised
  again), `DescribeTransactions` and `ListTransactions`, and the flexible request versions.
