## D221 EggDB in the browser through WASI, with a tiny loader and OPFS — Decided by the build loop (by judgement, 2026-10-31); refines D8, D16 and D41

Part 4.M17-1 asks for EggDB in a browser with OPFS persistence and a playground page.

- **The browser build is the WASI build.** The engine already builds for `wasm32-wasip1` (the
  `cross` CI job lints it), with files through the platform layer and no threads. The new
  `eggdb-wasm` crate is a small C ABI over the embedded API and SQL sessions: the host writes a
  path or SQL into a buffer the module owns, calls `eggdb_wasm_open` or `eggdb_wasm_execute`, and
  reads a JSON answer from another buffer the module owns. No host pointer is trusted and the
  crate has no `unsafe`. A database opened this way stays open for the module's lifetime.
- **The browser supplies WASI from `web/eggdb.js`**, the "minimal HTML/JS that loads the browser
  build" D16 allows: the WASI calls Rust's standard library makes, over an in-memory file system,
  with the browser's clock and `crypto.getRandomValues`. Any other WASI call answers `ENOSYS`.
  No `wasm-bindgen` or other third-party code (D1). The same loader runs under Node, which CI
  uses with headless Chrome.
- **Persistence is OPFS, saved after each statement.** After `execute`, the files a statement
  changed are written to the Origin Private File System with the asynchronous API, and the next
  `EggDB.open` loads them back. A tab closed during that write loses the last statement, which
  the playground accepts. Synchronous access handles in a worker would make each page write
  durable, and are left for later.
- **The playground** (`web/index.html`) follows Claude Fable's design in `docs/ux/playground.md`.
  It is a stopgap until the GUI client (D15) runs in the browser from its own Rust codebase.

Left: running in a worker with OPFS synchronous access handles (durable per write, and no
blocking of the page), sharing one database between tabs, a real `poll_oneoff` sleep, the
release workflow publishing `eggdb.wasm` with the web files, size budgets for the module (D6),
`wasm32-unknown-unknown` without WASI, the GUI client in the browser, and a bundle for npm.
