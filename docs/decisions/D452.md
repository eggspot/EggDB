## D452 The rest of Oracle's regular-expression syntax — Decided by the code-only session (2026-11-11, D355); roadmap M10, extends D332

- Oracle's `REGEXP_*` functions run on EggDB's shared engine (D332); a translation of the pattern
  (`oracle_regexp::oracle_pattern`) now gives them Oracle's own pieces:
  - `\z`, the very end of the string, becomes the engine's `\Z`;
  - an equivalence class `[=e=]` inside brackets becomes every letter sharing that base letter
    (`eèéêëēĕėęě`), from a table of the Latin letters with diacritics, as Oracle matches them under
    its default linguistic definitions; a letter without variants stands for itself;
  - a multi-character collating element (`[.ch.]`) is ORA-12731, as Oracle gives it under binary
    sorting; single characters and `[:class:]` pass through.
- A negated bracket (`[^...]`) now matches a newline even without the `n` match parameter, which
  only changes `.`, as Oracle documents. The engine gains an option for this
  (`negated_classes_take_newline`), which only Oracle's dialect sets; PostgreSQL's newline-sensitive
  rules are unchanged.
- Oracle's `\Z` (the end or before a final newline) still means the very end: a known difference.
