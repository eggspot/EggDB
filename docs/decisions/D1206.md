## D1206 Airflow operators: `airflow-provider-eggdb` — Decided by the code-only session (2026-11-17, D355); roadmap M6f, Airflow operators (D46, D239)

- **What users get.** `pip install airflow-provider-eggdb` registers an **EggDB** connection type in Apache Airflow (provider entry point) with `EggDBHook`, `EggDBOperator` (any SQL in a chosen dialect: the connection's Extra `dialect` or the operator's, set as `eggdb.dialect` on each connection) and `EggDBBackupOperator` (`BACKUP TO <path> [CLONE]`, D1023, templated so `{{ ds }}` names each night's copy).
- **How.** Written in Airflow's own provider system (D16's rule for a tool's plugins), on `PostgresHook` and `SQLExecuteQueryOperator` from Airflow's providers, since EggDB speaks the PostgreSQL protocol: `get_records`, `get_pandas_df`, `insert_rows` and `copy_expert` behave as with PostgreSQL. Nothing of it ships inside `eggdb`.
- **Left.** Publishing (an account, the owner's), the compatibility job running a DAG against `eggdb serve`, sensors (a key, a row, a change in the change stream), and the embedded mode.

**Status:** code written, unbuilt (code-only mode, D355).
