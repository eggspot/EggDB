## D115 The binary's growth past twice its v0.1 baseline is the price of the all-in-one SQL features; the footprint baseline moves to the measured size and the weekly pass shrinks it — Decided by the build loop (by judgement, 2026-10-28, on the coordinator's instruction); applies D2, D6, D7, D14, D101

`footprint.binary` (the stripped release `eggdb`, LTO, one codegen unit, `panic = "abort"`,
`strip = true`) was committed at 1,595,088 bytes on Linux (1,297,376 on macOS) before the SQL
dialects existed. Every SQL item since then added to it, each reported as `SLOWER` and left to
the weekly pass (D101), and item 32 (sequences, `ALTER TABLE`, enforced constraints, D114) took
it past twice the line, which blocks. Measured on CI's Linux runner, per merged item:

Item 32's share, split by symbol on a macOS build without stripping: the `ALTER TABLE` executor
about 44 KB, constraint enforcement about 37 KB, sequences about 31 KB, and the rest in the
parser (the four dialects' `ALTER` and constraint grammars), the session and the AST. A bounded
attempt to shrink it in the pull request (error builders made `#[cold]` and `#[inline(never)]`
so their formatting is not copied into callers) changed little: the size is real code for real
features, every one of them required by the all-in-one rule (D2) and by `pg_dump` restores
(item 35). Shrinking further needs a measured pass over the whole binary (monomorphized
collections, the dialect tables, error formatting shared across dialects), which is too large
and too risky to fold into a feature, and must not slow any hot path.

So, as D101 allows for growth that is the unavoidable price of required features: the
`linux footprint.binary stripped_release_bytes` line moves to 3,251,776 and the `macos` line to
2,605,600 (measured the same way on the build machine); no other baseline line changes. The
weekly performance pass on Saturday 2026-10-31 takes a size-reduction pass over the binary
(attribution by symbol, then the largest generic instantiations and duplicated formatting
first) and lowers these lines with whatever it saves. Growth stays reported on every pull
request against the new line with its 1% tolerance.
