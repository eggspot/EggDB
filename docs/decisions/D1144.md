## D1144 Renamed references in views' SQLite text, and the sqllogictest minimum kept in the repository — Decided by the code-only session (2026-11-14, D355); roadmap M5 (D273, D294, D642, D664, D976)

- **Views follow renames in `sqlite_schema`.** SQLite rewrites the text it keeps for views when `ALTER TABLE ...
  RENAME TO` or `RENAME COLUMN` changes a name they use. EggDB keeps each view's original text beside the text it
  would generate (D642); it now rewrites that original the same way.
  - A table rename changes every token that names the table, in any view that names it.
  - A column rename changes the column's name in the views that name the table.

  Each edited text is stored against the view's current generated text, so it stays in use. The edit is
  token-based: a view that names an unrelated column of the same name in another table also has it renamed, where
  SQLite resolves names first. That is a rare case, accepted here and recorded.
- **Left:** triggers' kept text, which lives in the trigger records rather than the schema-text space.
- **The sqllogictest minimum is in the repository.** `benchmarks/conformance.txt` holds `sqllogictest
  minimum_pass_percent`, and the weekly `sqllogictest` workflow fails below it. A manual run's input, or the
  repository variable `SQLLOGICTEST_MINIMUM`, still overrides it for one run. It reads 0 until the first full run
  sets it to that run's rate rounded down; from then on it only rises, as the coverage target does (D1133).
