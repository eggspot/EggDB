## D473 By-query tasks (`wait_for_completion=false`), `_tasks`, `_rethrottle` and `slices` — Decided by the code-only session (2026-11-11, D355); roadmap M8, D331

- `_update_by_query` and `_delete_by_query` with `wait_for_completion=false` run to the end in the
  request, as they always do in EggDB, then keep their report as a finished task and answer
  `{"task":"eggdb:<n>"}`. `GET /_tasks/<id>` answers it in Elasticsearch's shape
  (`completed: true`, the task's action and description, and the report under `response`, or
  under `error` when the run failed). The last 1,000 finished tasks are kept in memory; an unknown
  or forgotten id answers 404 `resource_not_found_exception`.
- `GET /_tasks` lists no running tasks, and `POST /_tasks/<id>/_cancel` and
  `POST /_update_by_query|_delete_by_query|_reindex/<id>/_rethrottle` acknowledge with
  `{"nodes":{}}`, since a task has always finished by the time its id is known.
- `slices=auto` or `slices=<n>` is accepted and checked; the work runs as one slice, so the report
  has no per-slice breakdown. Manual `slice` in the body keeps working (D331).
- A by-query run in the background, with progress while it runs, waits for the job scheduler to
  run HTTP work.
