## D874 Named parameters in libsqlite3 — Decided by the code-only session (2026-11-12, D355); follow-up of D790

- SQLite's dialect already reads `:name`, `@name` and `$name` parameters, numbering them as SQLite does (a repeated
  name shares its slot; a new name or a plain `?` takes the slot after the highest so far; `?NNN` takes slot NNN).
  `sqlite3_bind_parameter_name` and `sqlite3_bind_parameter_index` now follow the same numbering: a named slot's
  name is the text with its prefix (`:a`), a plain `?` has none, and names are matched case-insensitively on lookup
  only through the exact text a program passes, as SQLite does.
- The C interface's scan skips quoted strings and identifiers (`'...'`, `"..."`, `` `...` ``, `[...]`) and comments,
  so a `:word` inside them is not a parameter.
- Left: TCL-style `$name::part(suffix)` names, which EggDB's lexer does not read either.
