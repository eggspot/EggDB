## D1311 Schema USAGE checked in statements — Decided by the code-only session (2026-11-25, D355); roadmap M8 roles (D183, D1190)

- **What users get.** A role that is not a superuser reaches a table, view or sequence's table in a schema other than `public` only with `USAGE` on that schema, held by the role, a role it belongs to or `PUBLIC`, as in PostgreSQL: otherwise the statement fails with `42501 permission denied for schema <name>` before any table privilege is looked at. `public`, `pg_catalog` and `information_schema` stay open to every role. `pg_namespace.nspacl` and `has_schema_privilege` now say the same: `PUBLIC` holds `USAGE` only on those schemas, and the other schemas list their owner and the stored grants (D1190). Superuser sessions and temporary tables are never checked.
- **How.** The table check every statement already makes (`check_table`) first checks the table's schema against the stored schema grants.
- **Changed.** Until now every role could use every schema, which `nspacl` showed as `=U/` on all of them; a program whose roles reach tables in their own schemas needs `GRANT USAGE ON SCHEMA s TO ...`, as on PostgreSQL. The two column-grant tests that read from schema `s` grant it to `PUBLIC`.
- **Left.** Routine `EXECUTE` in statements (with PostgreSQL's default `EXECUTE` for `PUBLIC`), and `USAGE` on the schema of a called function or a type.
- **Proof.** A roles test refuses a granted table in schema `sales` without `USAGE`, answers `has_schema_privilege` for `sales` and `public`, reads it once `USAGE` is granted to a role the user belongs to, refuses it again after the revoke, and still reads `public`; the `nspacl` tests show `myschema` without `PUBLIC`.
