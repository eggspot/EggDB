## D786 Column statistics gathered by ANALYZE and shown in pg_stats — Decided by the code-only session (2026-11-12, D355); roadmap M5, column statistics

- `ANALYZE` reads every row of each chosen table as before, but now keeps a reservoir sample of up to 30,000 rows
  (PostgreSQL's 300 times its default statistics target of 100), with a seeded xorshift so the same table gives the
  same sample, and records per column: the fraction of NULLs, the average width (fixed widths for fixed-size types,
  the text form's length otherwise), the number of distinct values, up to 100 most common values with their
  frequencies, up to 101 histogram bounds over the values that are not among the most common, and the correlation
  between physical order and value order.
- The distinct count follows PostgreSQL: the Haas-Stokes estimator over the sample, the sample's own count when it
  holds every row or no value is seen once, -1 when every sampled value is unique, and a negative fraction of the
  rows when the estimate exceeds a tenth of them. Most common values are kept when seen more than once and more than
  1.25 times the average count, or all of them when there are at most 100 values all repeated.
- The statistics record of a table (key space 0x10) gets record version 2: the row count followed by the columns.
  Version 1 records still read as a row count with no column statistics, so files from before this change open
  unchanged; a column renamed or dropped after `ANALYZE` simply has no row in `pg_stats` until the next `ANALYZE`.
- `pg_catalog.pg_stats` is a new monitoring view (appended after `pg_policies`, so existing OIDs stay) in
  PostgreSQL's column order. `most_common_vals` and `histogram_bounds` are `text[]` rather than `anyarray`, since
  EggDB's catalog has no pseudo-typed array values; tools read them as text either way. Element statistics
  (`most_common_elems` and the rest) are NULL.
- EXPLAIN's estimates (D345) use `n_distinct` for an equality on an analyzed column: one over the distinct count
  instead of the fixed 0.1. Ranges keep the fixed third until the cost-based optimizer reads the histograms.
