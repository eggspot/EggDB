## D443 Merkle trees for anti-entropy — Decided by the code-only session (2026-11-11, D355); roadmap M18, extends D225

- `eggdb_cluster::merkle` builds a Merkle tree over `(key, digest)` entries: keys fall into
  `2^depth` leaves by a hash of the key (so a tree needs no agreed key ranges, which rendezvous
  placement doesn't have), each leaf hashes its entries in key order, and each inner node hashes
  its children. Two trees are compared from the root down, descending only into differing
  subtrees, and give the differing leaves. The hash is a 128-bit FNV-1a with length-prefixed pieces:
  anti-entropy needs agreement, not secrecy, and the cluster crate stays without dependencies.
- `Quorum::anti_entropy` no longer reconciles every key: for each pair of reachable nodes it builds
  both nodes' trees (depth 10) over the keys both are homes of, the digest of a key being its
  replica's versions (vectors, stamps, values, deletions), and reconciles only the keys under
  differing leaves, as before. Equal roots cost one comparison; the simulation's convergence
  checks are unchanged, since every differing key is still found.
- Left: exchanging trees over the network (with the transport of D225's wiring), keeping trees up
  to date as writes arrive instead of rebuilding them, and tombstone collection.
