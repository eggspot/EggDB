## D1131 SQLite's ATTACH and DETACH — Decided by the code-only session (2026-11-14, D355); roadmap M4 (`ATTACH` of in-memory, EggDB and SQLite files, D175)

- **Which dialects.** Of the dialects EggDB speaks, only SQLite has `ATTACH`. `ATTACH [DATABASE] <file> AS <alias>`
  and `DETACH [DATABASE] <alias>` now run in SQLite sessions, and `alias.table` names a table of the attached
  database anywhere a `main.` or `temp.` name goes.
- **An attached database is a schema of the session's store.** A session can only run on one store, and SQL tables
  are key prefixes numbered by table id, so a second file cannot be spliced into the key space. `ATTACH` instead
  creates a schema named by the alias, marked by its comment as made by `ATTACH`, and the parser turns `alias.table`
  into that schema's tables while the session has the alias attached (a per-statement registry, like the search
  path). `DETACH` drops the schema and everything in it. A schema left behind by a session that ended without
  detaching is dropped and made again by the next `ATTACH` of that alias.
- **`:memory:` (or an empty name)** gives an empty schema that lives until `DETACH`: SQLite's scratch database.
- **A file is read in at `ATTACH`.** `eggdb_sql::set_attach_reader` takes a reader that the `eggdb` crate installs
  with the SQL store:
  - A SQLite file contributes its tables with their declared columns and rows, `INTEGER PRIMARY KEY` columns getting
    their rowids back. `WITHOUT ROWID` tables are left out for now.
  - An EggDB file contributes its public tables, opened read-only, with columns by type affinity, primary keys and
    rows.
  - A file that does not exist attaches as an empty database, as SQLite creates one.
- **What differs from SQLite.** Changes made to an attached file's tables stay in this database's copy until
  `DETACH` and are not written to the file. `ATTACH` and `DETACH` are refused inside a transaction block, as SQLite
  refuses them, and an alias in use fails with "database ... is already in use".
- **Left:** writing an attached file's changes back to it (the C API's `sqlite3` surface is where that matters most),
  `WITHOUT ROWID` tables, attached views and indexes, and `pragma database_list` showing the aliases.
