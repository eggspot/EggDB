## D1148 The Python, Go and C++ drivers on the prepared-statement, stepping and COPY calls — Decided by the code-only session (2026-11-14, D355); roadmap M5 (every language driver using the new C API calls, D293)

- **Python.** `Connection.prepare(sql)` returns a `Statement` over `eggdb_sql_prepare`. Its `execute(parameters)` and
  `rows(parameters)` bind typed values: `None`, `bool`, 64-bit `int`, `float` and bytes go to their own bind calls, and
  anything else is bound as text. `rows` steps with `eggdb_stmt_step`. `Connection.iterate(sql, parameters)` yields a
  query's rows one at a time, `copy_from(sql, data)` feeds `COPY ... FROM STDIN` from bytes, text or an iterable of
  pieces, and `copy_to(sql)` yields `COPY ... TO STDOUT` pieces. `Cursor.executemany` prepares once and binds per row.
- **Go.** `conn.Prepare` now prepares a native statement. `stmt.ExecContext` binds typed values (`int64`, `float64`,
  `bool`, `[]byte`, with the text form for the rest), and `stmt.QueryContext` returns rows stepped from the
  connection, so a large result is never held whole. `CheckNamedValue` widens `int`, `int32` and `float32`.
  `eggdb.CopyFrom(ctx, conn, query, io.Reader)` and `eggdb.CopyTo(ctx, conn, query, io.Writer)` use `sql.Conn.Raw`.
  `NumInput` reports the parameter count for `?` statements outside PostgreSQL's dialect.
- **C++.** `session::prepare` returns a move-only `statement` with `bind`, `bind_bool`, `bind_all`, `execute`,
  `columns`, `step` (an optional row) and `reset`. `session::copy_in(text, data)`, `copy_in_pieces(text, source)` and
  `copy_out(text, sink)` cover COPY; result gathering is shared by `gathered`.
- Each driver's test or check prepares an `INSERT`, steps a `SELECT` and round-trips rows through COPY.
- The remaining drivers (Node.js, Ruby, PHP, Dart, .NET, Java, Kotlin, Swift, Android) follow in the next batches.
