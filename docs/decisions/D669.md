## D669 eggdb-lua part 3: the string library and Lua patterns — Decided by the code-only session (2026-11-12, D355); roadmap M7, Lua scripting (D27, D193)

- `string` is installed as a global and as the table string values index into, so `s:upper()` works:
  `len`, `sub`, `upper`, `lower`, `reverse`, `rep` (capped at 512 MB), `byte`, `char`, `find` (with `init` and
  `plain`), `match`, `gmatch`, `gsub` (string templates with `%0`–`%9`, tables and functions, a replacement limit)
  and `format`.
- Lua patterns are our own backtracking matcher in `pattern.rs`, following Lua 5.1's `lstrlib.c` semantics: the
  classes `%a %d %l %s %u %w %x %p %c %g %z` and their negations, sets with ranges, `.`, the quantifiers `* + - ?`,
  anchors, captures and position captures, back references `%1`–`%9`, `%b` and `%f`. Recursion stops at 200 levels
  ("pattern too complex") and 32 captures, so a script cannot overflow the stack.
- `gmatch` keeps its position in a state table passed back by the generic `for`, since native functions are plain
  function pointers without captured state.
- `string.format` is a C `printf` subset in `format.rs`: flags `- + space # 0`, width and precision up to two digits
  as in Lua, and `d i u c x X o e E f F g G q s`. `%s` honours `__tostring`; `%q` quotes as Lua 5.1 does.
