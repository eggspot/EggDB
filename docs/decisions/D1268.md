## D1268 ts_stat — Decided by the code-only session (2026-11-18, D355); roadmap M4 PostgreSQL text search (D1230, D1259)

- **What users get.** `SELECT * FROM ts_stat('SELECT v FROM docs')` returns PostgreSQL's columns `word`, `ndoc` (the rows whose vector holds the lexeme) and `nentry` (its occurrences, a lexeme stored without positions counting once), as tools use it to tune text-search configurations and find stop-word candidates; an alias names it as any table in `FROM`.
- **How.** The query is a string literal, so the PostgreSQL parser rewrites the call into a derived table: the query's first column, unnested with `unnest(tsvector)` (D1259) and grouped by lexeme, counting rows for `ndoc` and summing position counts for `nentry`. A trailing semicolon in the query is dropped. No function has to run a query of its own from inside the engine.
- **Left.** `ts_stat(query, weights)`, which counts only positions of the given weights; a query that is not a literal (a parameter or an expression).
- **Proof.** A test counts two documents' lexemes, uses an alias and a trailing semicolon, and refuses the weights form.
