## D1272 Geometry editing functions — Decided by the code-only session (2026-11-18, D355); roadmap M4 geospatial (D204)

- **What users get.** PostGIS's `ST_Rotate(geom, radians[, x, y | origin])`, `ST_Affine(geom, a, b, d, e, xoff, yoff)`, `ST_SnapToGrid(geom, size)`, `ST_RemoveRepeatedPoints`, `ST_Expand(geom, amount)`, `ST_Boundary`, `ST_Segmentize(geom, max_length)`, `ST_Multi`, `ST_Force2D`, `ST_MakePolygon(line)`, `ST_AddPoint(line, point[, position])`, `ST_RemovePoint(line, index)`, `ST_SetPoint(line, index, point)` (0-based, negative from the end) and `ST_Azimuth(a, b)` (radians clockwise from north, NULL for the same point).
- **How.** The geometry work is in `eggdb-geo` (`rotated`, `affine`, `snapped_to_grid`, `without_repeated_points`, `expanded`, `boundary` with the mod-2 rule for line ends, `segmentized`, `as_multi`, `azimuth`), each keeping the input's SRID; the line edits are done on the line's points in the SQL layer with PostGIS's errors (a single-segment line keeps its points, an open or short shell is refused). `ST_Force2D` returns its input, as EggDB's geometries are two-dimensional. `ST_Segmentize` refuses a length not above zero and a result over the point limit.
- **Left.** `ST_Buffer`, `ST_Union`, `ST_Difference` and the other overlay operations, `geography`, Z and M.
- **Proof.** Unit tests in `eggdb-geo` rotate, map, snap, deduplicate, bound, expand, multiply, segmentize and take azimuths.

**Status:** code written, unbuilt (code-only mode, D355).
