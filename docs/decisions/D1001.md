## D1001 EggDB's ADBC driver — Decided by the code-only session (2026-11-13, D355); roadmap M11, ADBC (D29)

- A new crate, `eggdb-adbc`, builds `libeggdb_adbc`, an ADBC 1.0.0 driver of the embedded database written from the
  ADBC and Arrow C data interface specifications. ADBC's driver manager loads it through `AdbcDriverInit`; the database
  options `path` (or `uri`, `:memory:` by default) and `adbc.eggdb.dialect` choose the file and the SQL dialect.
- `StatementExecuteQuery` runs the statement and returns its rows as an `ArrowArrayStream` of one struct batch, with
  the Arrow types of the Flight SQL service (D1000): validity bitmaps, 8-byte-aligned buffers, and release callbacks
  that free exactly what the driver allocated. Without a stream it reports the rows a statement changed.
- `ConnectionGetTableSchema` (a `LIMIT 0` query) and `ConnectionGetTableTypes` are answered; `GetInfo`, `GetObjects`,
  parameter binding, partitions, Substrait and statement options answer `ADBC_STATUS_NOT_IMPLEMENTED` with a message.
- Each statement commits on its own (`adbc.connection.autocommit` stays `true`); transactions are written as SQL.
- Remote EggDB servers are reached through ADBC's own Flight SQL driver and `eggdb serve --flight-listen` (D1000).
- All unsafe code follows CLAUDE.md: one unsafe operation per block, each with its `SAFETY` note.
