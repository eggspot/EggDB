## D658 DBMS_LOB's locator procedures in PL/SQL — Decided by the code-only session (2026-11-12, D355); roadmap M10, D434

PL/SQL that builds a large text (a report, a JSON or XML document) declares a `CLOB`, calls
`DBMS_LOB.CREATETEMPORARY`, and grows it with `WRITEAPPEND`/`APPEND`. Readers page through one
with `DBMS_LOB.READ`. D434 built `DBMS_LOB`'s functions (`GETLENGTH`, `SUBSTR`, `INSTR`, `COMPARE`)
but not its procedures, so such blocks stopped at the first call.

- A new `dbms_lob` module of the PL/SQL runner answers `DBMS_LOB.member(...)` call steps, as
  `DBMS_OUTPUT` and `DBMS_SCHEDULER` are answered. The arguments are split at the top level and
  evaluated in the block. The locator and `OUT` arguments are found by parsing the call, and
  written back through the runner's ordinary assignment, so declared types and conversions apply.
- EggDB keeps a LOB's value in the variable itself, so the locator procedures change that value:
  - `CREATETEMPORARY` makes it empty, and `FREETEMPORARY` makes it NULL.
  - `APPEND(dest, src)` and `WRITEAPPEND(lob, amount, buffer)` add to the end.
  - `WRITE(lob, amount, offset, buffer)` overwrites from `offset`, padding a gap with spaces
    (`CLOB`) or zero bytes (`BLOB`).
  - `TRIM(lob, newlen)` shortens; a longer `newlen` is ORA-21560.
  - `ERASE(lob, amount[, offset])` blanks a range and returns the count erased in `amount`.
  - `READ(lob, amount, offset, buffer)` returns the piece and its length, and is ORA-01403 when
    `offset` is past the end.
  - `COPY(dest, src, amount[, dest_offset[, src_offset]])` overwrites part of `dest`.
- `OPEN`, `CLOSE`, `FILEOPEN` and `FILECLOSE` are accepted and do nothing. Offsets count
  characters for text and bytes for binary values, from 1, and a zero or negative offset or amount
  is ORA-21560.
