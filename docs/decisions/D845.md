## D845 A stored geometry type — Decided by the code-only session (2026-11-12, D355); roadmap M12, D204

- `geometry` is a type of its own in the PostgreSQL dialect (OID 9005, with `vector`'s pattern from D796): a value
  is kept as its canonical extended well-known binary (EWKB with the SRID, `eggdb_geo::to_wkb`), stored under a new
  row tag, compared bytewise, written out as upper-case hex EWKB as PostGIS shows it, read from hex EWKB, WKT or EWKT
  (`SRID=4326;POINT(1 2)`) and from `bytea` WKB, and sent and read in binary as the EWKB bytes.
- Every `ST_` function takes a `geometry` value as it took WKT text and WKB bytes, so `ST_X(shape)` over a
  `geometry` column works; the functions still answer EWKT text, which a `geometry` column takes on insert. A text
  that is no geometry is PostGIS's `XX000` "parse error - invalid geometry".
- `pg_type` lists `geometry` with the extension types, and `pg_typeof` names it.
- Left: typmods (`geometry(Point, 4326)` with their checks), `geography`, spatial functions answering `geometry`,
  and R-tree indexes over the column.
