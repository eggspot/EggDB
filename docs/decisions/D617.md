## D617 Ed25519 and NATS NKey authentication — Decided by the code-only session (2026-11-12, D355); roadmap M16, D216, D476

NATS deployments sign clients in with NKeys rather than passwords. The client holds an Ed25519
seed, the server holds only the public key, and the client proves itself by signing a nonce the
server sends in `INFO`. EggDB's crypto crate had no Ed25519, so `nkey` sign-ins were refused.

### Ed25519 verification

- `eggdb-crypto` gains `ed25519_verify`, written from RFC 8032 on the X25519 module's field
  arithmetic (radix 2⁵¹), whose element functions are now crate-visible.
- Points use extended coordinates with the unified addition formula, which also doubles.
- Decoding follows the RFC:
  - the y coordinate must be canonical;
  - x is recovered with the `(p − 5)/8` power and `√−1`;
  - "x = 0 with the sign bit set" is refused.
- `s` must be below the group order `L`. `k = SHA-512(R ‖ A ‖ M) mod L` is reduced by binary long
  division.
- The check is cofactorless: `[s]B + [k](−A)` must encode to `R`.
- It handles only public data, so it is not constant-time. Signing is not written.
- Tests:
  - RFC 8032's test vectors 1 and 2 verify;
  - a changed message, a flipped signature bit and an `s` past `L` fail;
  - scalar reduction maps `L` to 0 and `L + 1` to 1.

### NKeys in the NATS server

- `INFO` now carries a `nonce`: 16 bytes from the standard library's per-process random hashing
  seeds, stirred with the client id and the time, written as unpadded base64url.
- `CONNECT` with `nkey` and `sig` signs the user in when both hold:
  - the NKey is one of `--nats-nkey`'s, given once per key and kept in
    `ServerConfig::nkeys`;
  - `sig`, the base64url Ed25519 signature of the nonce, verifies against the key the NKey
    encodes.
- NKeys are decoded as NATS writes them: base32 of the prefix byte `U` (20 << 3), the 32-byte key
  and a little-endian CRC-16/XMODEM, checked.
- Users, passwords and tokens work as before.
- A test round-trips a user NKey through base32 and refuses a changed character. CRC-16 is checked
  against its standard `0x31c3` for `123456789`.

Not done: account and operator JWTs (decentralized auth), NKey seeds on the server side, clusters
and leaf nodes.
