## D697 PostgreSQL's xml type read as text — Decided by the code-only session (2026-11-12, D355); roadmap M6a, PostgreSQL's types (D19), M9 XML documents

- In the PostgreSQL dialect, `xml` columns, casts (`'<a/>'::xml`) and function arguments are accepted and read as
  `text`, as `vector` is until its stored type lands (D437), so schemas and queries that use `xml` with `xpath()`,
  `xpath_exists()`, `XMLTABLE` and `XMLEXISTS` (D690–D693) run.
- What this is not yet: PostgreSQL checks that an `xml` value is well formed on input and reports the type as `xml`
  (OID 142) to clients; EggDB stores any text and reports `text`. `xml_is_well_formed()` checks a value on demand.
  A stored `xml` type with input checks and its own OID is the item that remains.
