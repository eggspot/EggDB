## D1127 Two-phase commit: PREPARE TRANSACTION, COMMIT PREPARED and MySQL's XA — Decided by the code-only session (2026-11-14, D355); roadmap M3 (two-phase commit and XA, D32, D173)

- **What is prepared.** A transaction that runs beside the one writer (`REPEATABLE READ`, `SERIALIZABLE`, D1123)
  keeps its changes in memory. `PREPARE TRANSACTION 'gid'` checks it exactly as a commit would and, when it passes,
  commits only a record of its changes under the reserved key `0xff C O L 0x00 0x09` followed by the gid. The record
  holds puts, deletes, times to live and collection writes, in a versioned, length-prefixed encoding. The record is
  durable: it survives a crash and a restart, as PostgreSQL's prepared transactions do. A block on the one writer
  cannot be prepared: its changes are written in place and only the writer's own commit makes them visible. It is
  rolled back and refused with `0A000`, which names the isolation levels that can be prepared.
- **The second phase.** `COMMIT PREPARED 'gid'` (`Database::commit_prepared`), from any session or process, applies
  the recorded changes and deletes the record in one commit. `ROLLBACK PREPARED 'gid'` deletes the record. An unknown
  gid is `42704` (MySQL `XAER_NOTA`, 1397), and either statement inside a block is `25001`.
  `Database::prepared_transactions` lists what waits.
- **MySQL's XA** maps onto the same pieces: `XA START` opens a `REPEATABLE READ` block beside the writer, `XA END` marks
  it ended, `XA PREPARE` prepares it, `XA COMMIT` commits a prepared one (`ONE PHASE` commits the open block),
  `XA ROLLBACK` rolls back the open block or a prepared one, and `XA RECOVER` lists the prepared ones with
  `formatID 1`. A gid with branch qualifier and format parts is kept as the text written.
- **What a prepared transaction does not hold.** PostgreSQL keeps a prepared transaction's row locks until the second
  phase. EggDB releases them when the preparing session's block ends, so another transaction can change the same rows
  in between, and the second phase then writes over it. Coordinators commit or roll back promptly, and the gap is
  recorded here as the one difference.
- **Left:** keeping row locks across the two phases (and across a restart), `pg_prepared_xacts`, and TDS's
  distributed transactions through MS DTC.
