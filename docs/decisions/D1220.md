## D1220 Pattern exclusion in MATCH_RECOGNIZE — Decided by the code-only session (2026-11-17, D355); roadmap M16, `MATCH_RECOGNIZE` for complex event processing (D55, D1217)

- **What users get.** `{- ... -}` in a pattern: the rows it matches belong to the match (measures and `MATCH_NUMBER()` count them) but `ALL ROWS PER MATCH` leaves them out of its output, as SQL:2016 and Oracle define it.
- **How.** The matcher gets zero-width `ExcludeStart` and `ExcludeEnd` instructions and keeps an exclusion depth with each backtracking point, so each assigned row records whether it was matched inside an exclusion. A match with excluded rows lists their offsets as `"excluded"` (left out when there are none, so earlier outputs are unchanged), and the clause's `ALL ROWS PER MATCH` join skips those rows.
- **Left.** Nothing more for exclusion; union variables in `DEFINE`, `SHOW EMPTY MATCHES` and `WITH UNMATCHED ROWS` remain (the last came next, D1221).
- **Proof.** `row_pattern.rs` (an excluded middle row, an excluded first row inside an alternation, an unclosed exclusion refused) and `streams.rs` (`ALL ROWS PER MATCH` without the excluded down rows).
