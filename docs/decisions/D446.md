## D446 `eggdb export --sql` writes sequences, views, comments and check and foreign-key constraints — Decided by the code-only session (2026-11-11, D355); roadmap M14

- In the PostgreSQL dialect, `dump_sql` now writes, around the tables and rows it wrote before:
  - **first, the sequences** (read from the catalog, so serial columns' `nextval` defaults find
    theirs): `CREATE SEQUENCE` with the type, increment, bounds, start, cache and cycle, then
    `setval` to the last value and whether it was called, so `nextval` continues where it was;
  - **after the rows, the check and foreign-key constraints**, as `ALTER TABLE ... ADD CONSTRAINT
    name <pg_get_constraintdef>`, so loading never trips a foreign key on rows not yet there
    (primary keys stay in `CREATE TABLE` and unique ones in the index statements, as before);
  - **then the views**, from `pg_views`' definitions, in catalog order;
  - **and the comments** on tables, columns and views (`COMMENT ON ...`), which Oracle's dialect
    also gets.
- Other dialects keep counting views as not written. `DumpReport` gains `sequences`, `constraints`
  and `views` counts.
- Left: identity columns' `GENERATED ... AS IDENTITY` (the table text doesn't carry it yet), views
  that depend on views created later, roles, grants, routines and triggers (D24's whole-database
  `eggdb dump` is a separate item), and the other dialects' constraints.

**Status:** code written, unbuilt (code-only mode, D355).
