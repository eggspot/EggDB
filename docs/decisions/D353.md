## D353 Releases come from the merge commit's `Release:` trailer — Decided (owner, 2026-11-10)

The owner: "make both eggos and eggdb to release after each merge pr so we don't need release
coordinator anymore", and then "releases come from the merge commit message, with no separate
release PR". This replaces D75's flow, in which a coordinator opened a version bump PR and pushed
the tag by hand.

- **The batch PR carries the release.** It bumps the version everywhere CLAUDE.md "Releases" lists
  and adds `docs/releases/vX.Y.Z.md`; its squash body ends with the line `Release: vX.Y.Z`. A
  fix-only PR bumps PATCH the same way; docs- and CI-only PRs carry no trailer and release nothing.
- **Tagging.** `.github/workflows/tag-release.yml` runs when the workflow named `CI` completes on
  `main`, only for a successful run of a push in this repository, and only for a commit on `main`.
  It runs `main`'s own workflow and script and reads the merged commit only as git objects, so no
  pull request's code runs with its write token. `scripts/release/tag-from-trailer.sh` reads the
  last two paragraphs of the message (carriage returns and trailing blank lines removed), wants
  at most one `Release:` line, checks its value against `vMAJOR.MINOR.PATCH` before using it, then
  checks the workspace version at that commit, the notes file and the tag on `origin` (absent, or
  already at this commit). With no trailer it does nothing when the workspace version is already
  tagged and fails, naming the version and the retry, when it is not, so a release whose CI run
  was cancelled is noticed instead of lost. The job pushes an annotated tag as
  `github-actions[bot]` and calls `release.yml`.
- **`release.yml` is reusable.** It takes a `tag` input (`workflow_call`, and `workflow_dispatch`
  for a retry; a tagless dispatch stays a dry run of `main`), keeps its trigger for a pushed tag,
  checks out the tag, and names its concurrency group by the bare tag so a called run and a
  pushed-tag run never publish at once. A tag pushed with the workflow's own token starts no other
  workflow, so there is never a second release from the push trigger.
- **Safe to run again.** The Release is created as a draft, every asset is uploaded, and it is
  published last. A run that finds a draft uploads the assets again and refreshes the notes; one
  that finds a published Release uploads nothing. `latest` (the GitHub Release flag and the image
  tag) is set only when the tag is the highest `v*` tag, so publishing an older version again
  never moves it.
- **Attestations.** Provenance now names `refs/heads/main` and the caller workflow when the release
  comes from `tag-release.yml`; `gh attestation verify -R eggspot/EggDB` passes, and a check with
  `--source-ref refs/tags/vX.Y.Z` does not.
- **Gate.** CI alone decides. The Compatibility farm runs only weekly or by hand, never per push,
  so it cannot gate a merge; CI's `compatibility` job already runs the tool matrix strictly.
- **Check.** `scripts/release/test-tag-from-trailer.sh` (CI's `lint-and-test`) builds throwaway
  repositories and checks every case: no trailer on a tagged and on an untagged version, the
  trailer beside a separate trailer paragraph, carriage returns, a `Release:` line in an earlier
  paragraph, two trailers, malformed and hostile values, a version mismatch, a missing notes file,
  and a tag at this or another commit. The first real release, v0.5.0, is the end-to-end check.

Left: a pull-request check that a trailer-bearing PR bumped every file, signed tags, release notes
written for the author, and gating on the Compatibility farm.
