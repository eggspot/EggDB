## D794 FOR SYSTEM_TIME over eggdb_temporal's kept history — Decided by the code-only session (2026-11-12, D355); roadmap M14, system-versioned temporal tables

- A table reference in every dialect may carry SQL:2011's system-time clause, as SQL Server and MariaDB write it:
  `FOR SYSTEM_TIME AS OF t`, `FROM a TO b`, `BETWEEN a AND b`, `CONTAINED IN (a, b)` or `ALL`, after the table name
  and before its alias. MariaDB's `AS OF TRANSACTION` is refused.
- System time is the recorded period `eggdb_temporal` already keeps (D755): `recorded_from` and `recorded_to`, with
  old versions in `<table>_history` and both together in `<table>_versions`. The name resolver, which already turns
  views and partitioned tables into derived queries, turns `t FOR SYSTEM_TIME ...` into
  `(SELECT <t's columns> FROM <t>_versions WHERE <condition>) AS t`, the condition being SQL Server's: `AS OF t` keeps
  `recorded_from <= t AND recorded_to > t`, `FROM a TO b` keeps `recorded_from < b AND recorded_to > a`, `BETWEEN`
  the same with `<=` on `b`, `CONTAINED IN` `recorded_from >= a AND recorded_to <= b`, and `ALL` every version.
- The table must be listed in `eggdb_temporal.tables`; any other table, a view, a CTE or a catalog relation fails with
  42809 ("is not system-versioned") and a hint naming `eggdb_temporal.enable`; a missing table still fails 42P01.
- Left: SQL Server's `GENERATED ALWAYS AS ROW START/END`, `PERIOD FOR SYSTEM_TIME` and `SYSTEM_VERSIONING = ON
  (HISTORY_TABLE = ...)`, MariaDB's `WITH SYSTEM VERSIONING` and `ADD SYSTEM VERSIONING`, mapped onto the same
  machinery with the user's own period column names.
