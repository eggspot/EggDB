## D184 Several databases per server: a data directory of database files, chosen by name at connection — Decided by the build loop (by judgement, 2026-10-31); refines D3

Part 4.M6a-3 asks for several databases behind one server, each reached by name.

- **A data directory is a folder of database files.** `eggdb serve <directory>` serves every
  `*.eggdb` file in it, each named by its file stem (`shop.eggdb` is `shop`), opened at start.
  One file per database keeps D3's "one file" promise per database and makes copying, backing
  up and moving a database the same as for a single file. `eggdb serve <file>` is unchanged.
- **Chosen by the startup packet.** PostgreSQL's protocol picks the database by name (`psql -d
  archive`, `\c archive`); an unknown name is `3D000` after authentication, as PostgreSQL
  answers. `pg_database` lists every served database, so `\l` shows them. Stored roles (D183)
  belong to the database they are created in, and log in to that database.
- **The first in name order is the default** (`--database` renames it) and is the one MySQL's
  and TDS's listeners serve.

Left: `CREATE DATABASE` and `DROP DATABASE` while serving (they need the server to open and
close files on a session's request), MySQL's `USE` and TDS's database change across files,
roles shared across a server's databases, and databases added to the directory while serving.
