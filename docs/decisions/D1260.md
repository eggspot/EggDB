## D1260 SQLNativeSqlW and every text answer of SQLGetInfoW in UTF-16 — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1238, D1256)

- **What users get.** Unicode applications (every Windows application built with `UNICODE`, which the Driver Manager sends to the `W` entry points) get `SQLNativeSqlW`, and `SQLGetInfoW` answers in UTF-16 for every information type whose answer is text: the database name, `SQL_DATA_SOURCE_READ_ONLY`, `SQL_USER_NAME` and the `Y`/`N` and term answers of the fixed table (`SQL_SCHEMA_TERM`, `SQL_SEARCH_PATTERN_ESCAPE` and the rest). Before, only eight hand-listed types were widened and the others came back as narrow bytes.
- **How.** One function in the narrow API, `answers_text`, says which types are text: the computed ones by name and every `Text` entry of the fixed table, so a text answer added to the table is widened without a second list. `SQLNativeSqlW` narrows its input, runs `SQLNativeSql` into a buffer sized from the input, and widens the result with the character count and `SQL_SUCCESS_WITH_INFO` when the application's buffer cuts it.
- **Proof.** The ODBC test translates an escape through `SQLNativeSqlW` and reads `SQL_SCHEMA_TERM` through `SQLGetInfoW` as twelve bytes of UTF-16.

**Status:** code written, unbuilt (code-only mode, D355).
