## D796 A stored vector type — Decided by the code-only session (2026-11-12, D355); roadmap M12, the stored vector(n) type

- `vector` becomes a built-in base type beside `citext` and `hstore` (`DefinedType::VECTOR`, OID 9004, listed in
  `pg_type` as `vector`, category `U`, and `pg_extension` lists `vector` 0.8.0), instead of text (D203). Its values
  are `DefinedValue::Vector(Vec<f32>)`: 1 to 16,000 finite floats, read from pgvector's text form or from a numeric
  array, printed as `[1,2,3]`, compared element by element and then by length, and kept on disk under value tag 29
  as a count and the floats' bits. Index keys use the text form, which is exact for equality; range scans over
  vectors don't follow vector order, which only B-tree indexes on vectors would notice.
- Binary send and receive use pgvector's format: a 16-bit dimension count, 16 unused bits and big-endian floats.
- `vector(n)` checks its dimension with a column check `vector_dims(col) = n` (23514 on a wrong dimension), because
  EggDB's column types carry no modifier slot for a defined type; keeping `n` as the type modifier is left.
- The distance operators and functions read stored vectors directly; text and arrays still work as before.
- Left: `atttypmod` and `vector(3)` in catalogs and `\d`, pgvector's 22000 dimension error, `halfvec`/`sparsevec`,
  `vector[]`, and HNSW/IVFFlat indexes over the stored type (the next item).
