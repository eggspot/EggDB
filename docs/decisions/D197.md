## D197 Documents and the MongoDB wire protocol in our own eggdb-bson, eggdb-documents and eggdb-mongowire, over the shared keyspace — Decided by the build loop (by judgement, 2026-10-31); refines D2, D5 and D34

Parts 4.M9-1 and 4.M9-2 ask for `mongosh` and MongoDB drivers (OP_MSG, BSON, CRUD, query and
update operators, indexes, the aggregation pipeline) from MongoDB's public documentation.

- **Clean room.** MongoDB's server is source-available (SSPL) and is never read (D1). BSON is
  written from bsonspec.org, the protocol from MongoDB's published wire protocol page, and the
  commands and operators from its public manual. The D34 check for this part found nothing that
  stops a compatible implementation of a documented protocol; "MongoDB" appears only as
  "compatible with". `buildInfo` reports version `6.0.0` (wire version 17) so drivers pick the
  commands this server answers.
- **Three crates.** `eggdb-bson` (values, reading with every length and depth checked, writing,
  MongoDB's cross-type comparison order, relaxed Extended JSON), `eggdb-documents` (the document
  model: filters, update operators, projections, sorting, aggregation expressions and stages,
  and a store) and `eggdb-mongowire` (framing, SCRAM-SHA-256, commands, cursors). The document
  model knows nothing of the wire, so SQL over documents (D10) and `mongodump` restores
  (4.M9-3) reuse it.
- **The key-value interface moves to `eggdb-keyspace`.** D194 said `eggdb_resp::Keyspace`
  moves to a crate of its own when a server needs it without RESP; the document store is that
  server. `eggdb-resp` re-exports it, so nothing else changes, and it gains `scan(prefix)`,
  which the `eggdb` binary answers with the engine's prefix scan. SCRAM-SHA-256 moves from
  `eggdb-pgwire` to `eggdb-auth` for the same reason; `eggdb-pgwire` re-exports it.
- **Storage.** Every database and collection lives in the collection `mongo0` of the served
  file: a record per collection (its recorded indexes) and a record per document keyed by
  database, collection and a canonical encoding of `_id`, in which equal ids such as `1` and
  `1.0` give the same key, so `_id` stays unique as MongoDB defines equality. Each command
  statement is one engine transaction; an ordered insert or update batch stops at the first
  failed statement, as MongoDB documents, without undoing the ones before it.
- **Queries read with scans for now.** A filter that is only an `_id` equality reads one
  record; others scan the collection, and aggregation reads with its first `$match`. Index
  definitions are recorded and listed, not used yet; a unique index other than `_id` is
  refused rather than silently not enforced.
- **Regular expressions** use `eggdb-sql`'s engine (PostgreSQL's flavour) with `$regex`'s
  option letters mapped onto it; patterns using Perl-only syntax may differ.
- **Authentication and exposure.** SCRAM-SHA-256 only (SCRAM-SHA-1 needs MD5 of the password
  and is refused), as the server's `--user` with its password; the verifier is derived at start
  with 15 000 iterations and the password is not kept. Unknown users get an exchange that looks
  the same and fails at the proof, and each failure waits 250 ms. Only the handshake, `ping`
  and the authentication commands run before login. The listener has no TLS yet, so it binds
  only to loopback. Cursors are shared by the server's connections, as drivers continue them on
  any pooled connection; idle ones close after ten minutes and at most 1 000 stay open.
- **Hostile input** (message lengths, document lengths, nesting, sections) is an error that
  closes the connection or a command error, never a panic; messages are capped at MongoDB's
  48 MB.

Left: TLS, other users and roles, SCRAM-SHA-1, `OP_COMPRESSED`, indexes used by queries and
unique indexes, collations, positional and `arrayFilters` updates, pipeline-style updates,
`$text`, `$expr`, `$jsonSchema`, `$where`, projection operators, `$facet`, `$bucket`, `$out`,
`$merge`, `$lookup` with a pipeline, change streams and multi-document transactions (both need
the replica-set handshake), `explain`, `renameCollection`, capped and time-series collections,
GridFS beyond plain collections, and a benchmark against MongoDB.
