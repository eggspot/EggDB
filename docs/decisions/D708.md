## D708 read_bam — Decided by the code-only session (2026-11-12, D355); roadmap M11, genomics (D57)

- `read_bam(path)` (PostgreSQL dialect) reads a BAM file through the session's file reader (D703): the BGZF blocks are
  gunzipped with `eggdb-content` (D707), the header text is skipped, the reference list is kept, and each alignment
  becomes a row with SAM's columns: `qname`, `flag`, `rname`, `pos` (1-based), `mapq`, `cigar` (as SAM's text),
  `rnext`, `pnext` (1-based), `tlen`, `seq` (decoded from 4-bit codes), `qual` (Phred+33 text, `NULL` when absent),
  and `tags`, the optional fields as a JSON object of tag to value (characters, integers of every width, floats,
  strings, hex strings and `B` arrays). `*`, unmapped positions and missing references are `NULL`.
- The columns come without a definition list (D706); a list may pick or retype them. Every length is checked against
  its record, so a damaged file is an error.
- Left: CRAM (reference-based compression), htsget, and region reads through a `.bai` index (the whole file is read).
