## D535 GQL `ANY SHORTEST`, `ALL SHORTEST`, `SHORTEST k` and relationship quantifiers — Decided by the code-only session (2026-11-11, D355); roadmap M13

Cypher 25 and GQL (ISO/IEC 39075) write path searches as prefixes and repetition as quantifiers;
EggDB's graph language now reads them beside `shortestPath()` (D333).

- **Prefixes:** `MATCH p = ANY SHORTEST (a)-[:R]->+(b)` is `shortestPath`, `ALL SHORTEST`
  is `allShortestPaths`, and `SHORTEST k` (with an optional `PATH` or `PATHS`) returns up to `k`
  shortest paths to each end node, in order of length. Like `shortestPath`, the pattern must have
  one relationship; `SHORTEST k GROUPS` is refused.
- **Quantifiers:** after a relationship, `+` (1 or more), `*` (0 or more), `{n}`, `{m,n}`,
  `{m,}` and `{,n}` set its hops, the same as `*m..n` in its brackets (at most 15 hops, D206);
  giving both is a `SyntaxError`.
- **`SHORTEST k` search:** a breadth-first search over paths that never visit a node twice,
  keeping the first `k` paths that reach each end node (only the bound end node when there is
  one) and stopping once the bound end node has `k`; it spends the same per-query search and
  result budgets as the other shortest-path searches (D333), and path conditions pushed from the
  `WHERE` (D534) apply to it too.
- **Left out:** quantified path patterns over several elements (`((a)-[:R]->(b)){1,3}`), path
  modes (`TRAIL`, `ACYCLIC`, `SIMPLE`), `ANY k`, and `SHORTEST k GROUPS`.

**Status:** code written, unbuilt (code-only mode, D355).
