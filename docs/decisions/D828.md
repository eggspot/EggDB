## D828 Ranges and composites in PostgreSQL's binary format — Decided by the code-only session (2026-11-12, D355); roadmap M6a, D154

- `encode_pg_binary` writes a range as PostgreSQL's `range_send` does: a flags byte (empty `0x01`, lower and upper
  inclusive `0x02`/`0x04`, lower and upper infinite `0x08`/`0x10`), then each finite bound as a 4-byte length and the
  subtype's binary form; and a composite or `record` as `record_send` does: the field count, then each field's type
  OID, length (`-1` for NULL) and binary form. Field OIDs come from the values (text for a NULL field, since the
  value carries no declared type). So `COPY ... TO (FORMAT binary)` and binary result columns now take range and
  composite columns.
- `decode_pg_binary_text` reads the built-in ranges (`int4range`, `numrange`, `tsrange`, `tstzrange`, `daterange`,
  `int8range`) back into their text form, with each bound quoted; hostile lengths are `22P03`. `COPY FROM` in binary
  takes built-in range columns.
- Left: reading composites and user-defined ranges in binary (their field and subtype types need the catalog at
  decode time), and `LOG_VERBOSITY verbose` notices before a `REJECT_LIMIT` error.
