## D364 An identity or `AUTO_INCREMENT` column anywhere in the primary key, with table definition version 15 — Decided by the code-only session (2026-11-10, D355); closes D337's leftover, with its D35 review

Partitioned tables key on the partition column and the id, and MySQL users write `PRIMARY KEY
(created_at, id)` as often as `(id, created_at)`. EggDB required the identity column to lead the
primary key because the next value came from the last row in key order. It now allows the
column at any position of the primary key:

- **Next value.** When the column leads the key, the last row in key order still gives it.
  Otherwise EggDB reads the first entry of a B-tree index the column leads, and with no such
  index it reads every row once per statement, the same three steps partitions already used
  (D337, `partition_dml::furthest_in_table`).
- **Dialects.** MySQL keeps InnoDB's rule that the column leads some key: the primary key, a
  `UNIQUE` column or an index in the same `CREATE TABLE` (`1075` otherwise). PostgreSQL, Oracle,
  SQL Server and SQLite take the column anywhere in the primary key. A column outside the primary
  key is still refused.
- **`ALTER TABLE ... DROP COLUMN`** keeps the auto-increment flag while the column stays in the
  primary key, instead of only while it leads it.

**D35 review of the format change.** Table definition version 15 is written only for a table
whose identity column is in the primary key but not first; every other table keeps its version
and bytes, so files without such a table stay readable by older releases, which refuse a file
with one by naming version 15. Version 15 holds every section of version 14 and allows the
generated-column count to be 0, since it is written for tables without generated columns too.
A version 15 definition whose identity column leads the key or is outside it is damage, and so
is an older version with the column after the first key column, so each table has one encoding.
No upgrade step is needed. Downgrading means moving the column to the front of the key (a new
table) or dropping the identity. Tests: the version 15 round trip and truncations, a version 2
definition relabeled 15, a version 15 one relabeled 14.

**Left:** MySQL's index rule is checked only in `CREATE TABLE`, not when a later `DROP INDEX`
removes the index the column leads; MyISAM's per-group sequences are not emulated.

**Status:** code written, unbuilt (code-only mode, D355).
