## D831 pgRouting topology — Decided by the code-only session (2026-11-12, D355); roadmap D57, topology and routing at pgRouting's level

- `CREATE EXTENSION pgrouting` adds `pgr_createTopology(edge_table, tolerance, the_geom, id, source, target,
  rows_where, clean)`, written from pgRouting's documentation in PL/pgSQL: it makes `<edge_table>_vertices_pgr` (id,
  cnt, chk, ein, eout, x, y, the_geom), walks the edges in id order, takes each line's start and end point, numbers
  each as the nearest existing vertex within `tolerance` (ties to the lowest id) or a new one, writes the edge's
  `source` and `target`, and counts each vertex's edges in `cnt`. `clean` drops the vertices table first; a negative
  tolerance is `22023`; an edge whose geometry is not a line string keeps its ends unset.
- `pgr_createVerticesTable(edge_table, the_geom, source, target, rows_where)` rebuilds the vertices table from edges
  that already carry `source` and `target`, with `cnt`, `ein` and `eout` and each vertex's point.
- Geometry is read through EggDB's `ST_StartPoint`, `ST_EndPoint`, `ST_X` and `ST_Y` over the text forms the spatial
  functions take, and the vertices' `the_geom` is WKT text until a stored geometry type lands (D204). Nearest-vertex
  search scans the vertices table; a spatial index is left with R-trees.
