## D886 An RDF quad store with N-Triples, N-Quads, Turtle and TriG — Decided by the code-only session (2026-11-12, D355); roadmap M13, D38

- A new workspace crate, `eggdb-rdf`, holds RDF (D38) as a front-end over the one core: quads kept on EggDB's
  key-value transactions through `eggdb_keyspace::Keyspace`, like the property graph (D206), in a database the
  caller names. It depends only on `eggdb-keyspace`.
- Storage: every term (IRI, blank node, literal with datatype and language) gets a number in a dictionary (term to
  number and number to term), and each quad is kept under three orders of numbers: graph-subject-predicate-object,
  graph-predicate-object-subject and graph-object-subject-predicate, so any pattern of bound positions within a
  graph reads one key prefix. The default graph is number 0; named graphs that hold quads are listed, so a pattern
  over every graph reads each of them. Dictionary entries stay when their quads go.
- Readers written from the W3C recommendations: N-Triples, N-Quads, Turtle and TriG, with `@prefix`/`PREFIX`,
  `@base`/`BASE` and relative IRIs resolved per RFC 3986 section 5.2, `a`, predicate and object lists, blank node
  property lists, collections, numeric and boolean shorthands, the four string forms with escapes, language tags
  and datatypes, and TriG's graph blocks (`GRAPH` optional). Nesting is limited to 64; errors name the byte offset.
- `eggdb_rdf::load` stores a document in one transaction, giving each document's blank nodes labels of their own
  (`s<number>_<label>`) so two documents never share a blank node by accident, and optionally puts its default-graph
  triples into a named graph; `eggdb_rdf::export` writes every quad as N-Quads.
- Next: SPARQL 1.1 query and update, the SPARQL protocol over HTTP, and the server and CLI wiring.

**Status:** code written, unbuilt (code-only mode, D355).
