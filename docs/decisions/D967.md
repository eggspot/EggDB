## D967 MySQL's protocol as a backend of the C API's network session — Decided by the code-only session (2026-11-13, D355); roadmap M6f, D192's backends

- `eggdb_sql_connect` takes `mysql://user@host:port/database` beside `postgresql://`, with the password from
  `MYSQL_PWD` as the mysql client reads it (D914's URL rule: never in the URL). The session's new `MySql` backend runs
  each call through D914's MySQL client (`COM_QUERY`, text result sets), so drivers on the C API reach EggDB's MySQL
  listener, or a MySQL server, with no change of their own.
- Parameters of `eggdb_sql_execute_with_parameters` are inlined as literals (`NULL`, or single-quoted with `'` doubled
  and `\` doubled, for MySQL's default `sql_mode`), outside quoted text and back-quoted names; values come back as
  text, since MySQL's text protocol carries no types the client reads yet; a result without columns has the tag
  `OK`.
- Prepared statements, `COPY` and `eggdb_sql_cancel` are refused on these sessions with `EGGDB_ERR_INVALID_ARGUMENT`
  and a message naming what to use instead. An I/O failure marks the session broken, as for PostgreSQL sessions.
- **Left.** TDS: the TDS client (D916's foreign sources) reads only `nvarchar` result columns, so it needs a general
  column reader first; then the same backend shape fits it.
