## D952 On-disk overhead per row and per index entry, with targets — Decided by the code-only session (2026-11-13, D355); roadmap M4, D6 and D354's footprint list

- `eggdb-bench` gains `footprint.disk`, run with the other footprint lines in the Saturday pass (`--only footprint`,
  never in CI's `bench` job). It creates a file, measures it settled (checkpointed and closed) empty, after 100,000
  rows of a PostgreSQL-dialect table (`bigint` primary key, a 16-byte `text`, an `int`: 28 bytes of payload a row),
  and after an index on the `int` column, and reports `bytes_per_row`, `bytes_per_index_entry` and
  `row_overhead_ratio` (bytes per row over payload per row).
- `scripts/footprint.sh` reads the two byte figures and checks them against new targets in
  `benchmarks/footprint.txt` (`disk_bytes_per_row` 64, `disk_bytes_per_index_entry` 40, for Linux and macOS, the
  `embedded` profile, since a file's format is the same everywhere): about 2.3 times the payload for a row and an
  `int` key plus the primary key for an index entry, close to what SQLite's B-tree pages take for the same table. As
  with every footprint target, the pass trims what goes over or near them, and the targets only shrink (D354).
