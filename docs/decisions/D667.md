## D667 eggdb-lua, part 1: the lexer and parser of Lua 5.1 — Decided by the code-only session (2026-11-12, D355); roadmap M7, D27, D193

Redis clients ship their logic as Lua scripts. Locks, rate limiters and job queues (BullMQ,
Sidekiq's reliable fetch, Redisson) are written that way and sent with `EVAL`/`EVALSHA`. D27
chose to run them on an interpreter of our own rather than embed the C Lua, which D45's
no-third-party rule rules out. Redis runs Lua 5.1, so EggDB follows that version.

- A new crate, `eggdb-lua`, with no dependencies. This first part reads source.
- `lexer` produces the 5.1 tokens:
  - names and the 21 keywords;
  - decimal, exponent and `0x` hexadecimal numbers;
  - strings in quotes with escapes (`\n`, `\ddd`, `\` newline), and long strings `[==[ ... ]==]`;
  - comments `--` and `--[[ ... ]]`;
  - the 26 symbols.

  Each token keeps its line.
- `parser` builds a syntax tree (`ast`) by recursive descent with Lua 5.1's precedences:
  `or` < `and` < comparisons < `..` (right) < `+ -` < `* / %` < unary < `^` (right). Every
  statement form is read:
  - `local`, assignment and calls, including method calls and string or table arguments;
  - `do`, `while`, `repeat`, `if`/`elseif`/`else`, numeric and generic `for`;
  - `function`, `local function`, `return`, `break`.

  Nesting deeper than 200 levels is a syntax error, so hostile source cannot exhaust the stack.
- `LuaError` carries its kind (syntax or runtime), line and message, and prints as
  `user_script:LINE: message`, as Redis reports script errors. `check_syntax` is what
  `SCRIPT LOAD` will call.
- Next parts: the interpreter (values, tables, closures, multiple returns, `pcall`, a step budget),
  the standard libraries Redis exposes (`string` with Lua patterns, `table`, `math`, `cjson`,
  `bit`), and `EVAL`, `EVALSHA` and `SCRIPT` in the RESP server.
- Tests: precedence, every statement form, syntax errors with their line, and the depth limit.
