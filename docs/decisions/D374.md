## D374 Oracle's `CORR_S` and `CORR_K` — Decided by the code-only session (2026-11-10, D355); roadmap M5, extends D340

Oracle's rank correlations take two numeric expressions and, optionally, which result to return.

- **Where.** They are two-variable aggregates beside `corr` (D340), parsed in the Oracle dialect
  only (PostgreSQL has neither), with the same `FILTER`, `OVER` and NULL rules: a pair with a NULL
  on either side, or a NaN, is skipped. Unlike `corr`'s running sums they need every pair, so the
  accumulator keeps the pairs (charged to the group's work memory through `held_bytes`) only for
  these two functions.
- **`CORR_S`** ranks each side, giving tied values their average rank, and returns the Pearson
  correlation of the ranks (Spearman's rho).
- **`CORR_K`** returns Kendall's tau-b, `(concordant - discordant) / sqrt((n0 - n1)(n0 - n2))`
  with `n1` and `n2` the pairs tied in each variable, counted with Knight's method: sort by both
  variables, count discordant pairs as the inversions of a merge sort on the second, so `n` pairs
  cost `n log n`.
- Both return a `double precision`, and NULL for fewer than two pairs or when a side has no
  spread. The optional third argument (`COEFFICIENT`, `ONE_SIDED_SIG`, `ONE_SIDED_SIG_POS`,
  `ONE_SIDED_SIG_NEG`, `TWO_SIDED_SIG`) is not parsed yet; the significances need the t and
  normal distribution functions that `STATS_*` will bring.
