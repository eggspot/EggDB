## D1031 PostgreSQL's logical replication protocol served, and logical replication between EggDB versions — Decided by the code-only session (2026-11-13, D355); roadmap M14 (D18, D103, D1030)

- `eggdb serve --pg-replication` accepts `replication=database` connections and answers the walsender commands a
  logical subscriber sends: `IDENTIFY_SYSTEM`, `CREATE_REPLICATION_SLOT ... LOGICAL pgoutput`, `DROP_REPLICATION_SLOT`
  and `START_REPLICATION SLOT ... LOGICAL`, written from PostgreSQL's protocol documentation. The stream is
  `CopyBoth` with `XLogData` carrying `pgoutput` protocol version 1 messages (begin, relation, insert, update with
  the old row, delete with the old row, commit), keepalives every ten seconds, and the subscriber's standby status
  updates confirming the slot.
- **The source is engine capture (D1030).** Each capture record is one transaction; its sequence is the
  transaction's position, shown as an LSN sixteen times the sequence so a transaction's begin and commit positions
  stay below the next one. Slots live in the file under reserved keys with their confirmed position; capture records
  are removed only when every consumer (each slot, and the change data capture deliverer once it ran) has passed
  them, so a slot never loses a change it has not confirmed.
- **Initial copy.** `CREATE_REPLICATION_SLOT ... EXPORT_SNAPSHOT` opens a read-only repeatable-read transaction on the
  replication connection, exports its snapshot (`pg_export_snapshot`), and takes the slot's consistent point from
  that same snapshot, so a copy taken with `SET TRANSACTION SNAPSHOT` plus the stream from the slot hold every change
  exactly once. The snapshot stays valid until the connection's next command, as in PostgreSQL.
- **Logical replication between EggDB clusters and versions** (roadmap M14) follows from it: `eggdb follow
  postgres://<another eggdb>` already speaks this protocol as a subscriber (D296), and rows travel as text values,
  not as the source's key-value layout, so the two sides may run different EggDB versions, which is how an upgrade
  without downtime runs: follow the old cluster from the new one, then switch clients over.
- Left: `pgoutput` protocol versions 2 to 4 (streamed in-progress transactions, binary values), publications that
  name a subset of tables (every table is published), and temporary slots dropped at disconnect.
