## D479 Cypher's `CALL (a, b) { ... }` scope form and `IN TRANSACTIONS` — Decided by the code-only session (2026-11-11, D355); roadmap M13, D351

- `CALL (a, b) { ... }` imports exactly the named outer variables into every part of the
  subquery, `CALL (*) { ... }` all of them and `CALL () { ... }` none, as Neo4j 5.23 writes the
  variable scope clause. An importing `WITH` inside such a subquery, or a variable named twice, is
  refused with Neo4j's wording. The older `CALL { WITH a ... }` form is unchanged.
- `CALL { ... } IN [n CONCURRENT] TRANSACTIONS [OF n ROWS] [ON ERROR FAIL]` is read and runs the
  subquery inside the statement's own transaction: every row is written, and a failure rolls back
  the whole statement, where Neo4j would keep the batches committed before it. Batch sizes and
  concurrency only shape memory in Neo4j, so EggDB ignores them. `ON ERROR CONTINUE`/`BREAK` and
  `REPORT STATUS AS` are refused, since they report per-batch outcomes that one transaction does
  not have.
