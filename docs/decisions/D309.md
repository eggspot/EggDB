## D309 The client's familiar layouts are applied: the picker, the kept setting, regions placed from EggDB's own drawing, and each layout's keys routed to EggDB's actions — Decided by the build loop (EggAgentCode task 20261103-1926, 2026-11-03); inventory item 67, extends D15 and D191

`docs/ux/gui-layouts.md` (Claude Fable) gave every familiar layout its region rects, labels and
shortcut table, and `crates/eggdb-gui/src/layout.rs` held the rects, but nothing used them and the
connect card's `Where are you coming from?` opened nothing. Fable designed the missing piece, the
layout picker dialog, in the same file ("The layout picker").

- **Picker.** `layout_picker::LayoutPicker` is the dialog's model (highlight, focus, keys,
  pointer rows) with its drawing and accessibility nodes; the connect card and the main window
  each hold an `Option<LayoutPicker>` and draw it last, over a new `scrim` theme token. The
  platform layer has no dialog, list box or option roles yet, so the dialog is a `Group`, the
  list a `Tree` and the rows flat `TreeItem`s with their position, selected and checked states.
- **Setting.** `settings::ClientSettings` reads and writes `name = value` lines, keeping lines it
  does not know, in `gui-settings` under `eggdb_platform::user_files::state_directory()` (the
  per-user state directory the shell's history already uses), written owner-only;
  `EGGDB_GUI_SETTINGS` moves it, empty turns it off. A file over 1 MB reads as no settings, a
  leading byte order mark is skipped, a `layout` line this client does not know is dropped once
  the user picks a layout (so the file never holds two), and a save writes a file beside it and
  renames it over the old one, so a crash or a full disk mid-write keeps the old settings. Offscreen `--png` runs read it only when the
  variable is set, so frames never depend on a developer's own settings; `--layout` applies a
  layout for one run without keeping it. A failed write leaves the layout applied to the window
  and says so in the status line.
- **Regions.** The main window keeps drawing every region in EggDB's own coordinates, and
  `Canvas::draw_placed(shift, clip)` moves each region's pixels to the layout's rect and cuts them
  to it (whole-pixel shifts, so EggDB's own frame is unchanged pixel for pixel). The centre width
  follows the layout's editor width; the accessibility tree's bounds go through the same shift and
  clip (`MainWindow::place_nodes`), so the pointer and screen readers find what is drawn. A region
  taller than EggDB's shows the region's background below; a shorter one is cut. A sidebar wider
  than 260 px is filled to its width, Redis Insight's 60 px rail draws its four items, and a
  layout's shown extra region (`projects`, `output`, `shell`) draws as an empty titled panel.
- **Labels.** The run button (`Execute`, `Find`), the three result views (for example `Data
  Output` / `Messages` / `Explain` in pgAdmin's) and the sidebar tree's name follow the layout; a
  familiar layout adds `Works like <product>` to the status bar, whose tooltip is the full
  trademark note naming each owner (`layout::FULL_TRADEMARK_NOTE`; the picker shows the short
  one) and which opens the picker.
- **Keys.** A layout's shortcut table maps keys to EggDB's actions (`Layout::translate`, applied
  while the editor has the focus), so a layout's key reaches the same code as EggDB's own; the
  toolbar's buttons and their announced shortcuts use the layout's keys. `Ctrl/Cmd+K L` opens the
  picker (any other key after `Ctrl/Cmd+K` acts as usual).
