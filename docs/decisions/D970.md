## D970 MySQL `SET` values stored in member order — Decided by the code-only session (2026-11-13, D355); roadmap M10, follow-up of D700

- MySQL stores a `SET` value as its members in the column's order, each once, as the column spells them (`'l,s,S'` is
  stored as `'s,l'`), and reads a number as a bit mask over the members (`6` is `'m,l'`). D700 only checked members.
- `CREATE TABLE` with `SET` columns now also creates one `BEFORE INSERT OR UPDATE` row trigger on the table
  (`eggdb_set_order`, its function in `eggdb_internal`, as D798's `rowversion` trigger is), which rewrites each `SET`
  column with the internal function `eggdb_mysql_set_normalize(value, 'members')`. The trigger runs before the check
  constraints, so numeric values pass D700's check once rewritten; a value with a non-member element is left as it is
  for the check to refuse. The members come from D700's implicit check, so no new catalog field is needed.
- A mask with bits beyond the members is left unchanged and refused by the check, as MySQL refuses it in strict mode.
- Left: `SET` columns added by `ALTER TABLE`, which get the check but not the trigger yet, and `ENUM` ordering by
  member index.
