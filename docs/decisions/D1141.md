## D1141 Data-modifying WITH queries that resolve conflicts — Decided by the code-only session (2026-11-14, D355); roadmap M5 (a data-modifying `WITH` query that resolves conflicts, D299, sql.md)

- **What users can do.** A PostgreSQL `WITH` query may be an upsert, `INSERT ... ON CONFLICT ... DO NOTHING | DO
  UPDATE ... RETURNING ...`, and a later `WITH` query or the main statement reads the rows it returns, as
  PostgreSQL allows. The upsert's own clauses may name the `WITH` queries before it: the `DO UPDATE SET` values, its
  `WHERE`, and the conflict target's index predicate. This is the common "merge a staged batch and report what
  changed" statement.
- **How.** A data-modifying `WITH` query runs through the same insert path as a plain statement, conflicts included.
  What was missing was turning names of earlier `WITH` queries into their materialized rows inside the conflict
  clause: the rewrite visited the `VALUES`, the source query and `RETURNING`, not `ON CONFLICT`. It now visits the
  assignments, the update's predicate and the inferred target's predicate too.
- **Unchanged.** `excluded` still names the proposed row, a row updated twice in one statement is still `21000` as in
  PostgreSQL, and a `WITH` query without `RETURNING` that is named is still `0A000`.
