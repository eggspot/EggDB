## D760 A metering API with chargeback and showback (eggdb_metering) — Decided by the code-only session (2026-11-12, D355); roadmap M6c, a metering API (D44, D58)

- `CREATE EXTENSION eggdb_metering` meters from what the server already counts: `pg_stat_statements` (D286), kept per
  role, database and statement shape on every protocol. `snapshot()` stores the counters it last saw in
  `statement_marks` and appends the differences (calls, execution milliseconds, rows) to `usage`, so usage needs
  neither a hook in the executor nor per-statement writes. A counter lower than its mark (after
  `pg_stat_statements_reset()` or a restart) counts from zero. Usage between the last snapshot and a reset is lost;
  snapshots every few minutes through pg_cron keep that small.
- Tenants are mapped from roles in `tenants`; an unmapped role is its own tenant. Tenancy by schema or row (D234)
  inside one role is not separated.
- The billing hook is a `pg_notify` on channel `eggdb_metering` per tenant per snapshot, with JSON totals, which any
  LISTEN client (or a webhook relay) can forward. `chargeback`, `showback` and `top_statements` are the reports;
  prices are per call, per execution millisecond and per row, in one currency.
- Storage per tenant (bytes kept over time), network bytes, and metering of the key-value, document and other
  protocols' requests beside SQL statements are left.
