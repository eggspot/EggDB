## D359 Partition keys checked as PostgreSQL and MySQL check them: `42883` for an unknown function, MySQL's integer-only keys and allowed functions — Decided by the code-only session (2026-11-10, D355); closes two of D316's leftovers

- **PostgreSQL:** a key expression that calls a function that is neither built in nor a stored
  routine is `42883 function name(types) does not exist`, with PostgreSQL's hint, before the
  `IMMUTABLE` check, as PostgreSQL resolves the function first. Stored routines are looked up
  with the routine cache; user-defined `IMMUTABLE` functions in keys are still refused by the
  `IMMUTABLE` check (D316's leftover).
- **MySQL:** `PARTITION BY RANGE`, `LIST` and `HASH` without `COLUMNS` (and not `KEY`) need an
  integer key. A column of another type is `1659` ("Field ... is of a not allowed type for this
  type of partitioning"); a function outside MySQL's list of partitioning functions (`ABS`,
  `CEILING`, `DATEDIFF`, `DAY`, `DAYOFMONTH`, `DAYOFWEEK`, `DAYOFYEAR`, `EXTRACT`, `FLOOR`,
  `HOUR`, `MICROSECOND`, `MINUTE`, `MOD`, `MONTH`, `QUARTER`, `SECOND`, `TIME_TO_SEC`, `TO_DAYS`,
  `TO_SECONDS`, `UNIX_TIMESTAMP`, `WEEKDAY`, `YEAR`, `YEARWEEK`) is `1564`; an expression whose
  type EggDB knows and is not a number is `1491`. An expression whose type EggDB cannot work out
  is let through, since EggDB's typing of some MySQL functions is wider than MySQL's.
  `RANGE COLUMNS`, `LIST COLUMNS` and `KEY` take any type, as in MySQL.
