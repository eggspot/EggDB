## D1329 PostgreSQL's money type — Decided by the code-only session (2026-11-25, D355); roadmap "PostgreSQL's network address ... `money` ... types" (D19)

- **What users get.** `money` columns, casts and literals in PostgreSQL's dialect. Input takes what PostgreSQL's `money` input takes with `lc_monetary` set to `C`: spaces, a sign or parentheses, `$`, `,` between digit groups and a fraction rounded half away from zero to cents; output is `$1,234.56` and `-$0.75`. Values order and index as amounts, add and subtract with each other, multiply and divide by integers, `numeric` and floats (integer division truncates, as PostgreSQL's does), divide by each other into `double precision`, negate, cast from integers, `numeric` and floats and to `numeric` with two places, and sum with `sum(money)` into `money`. `cash_words` spells an amount out. OID 790 on the wire in text and binary (eight bytes of cents), with `pg_type` rows for `money` and `money[]`.
- **Why cents in an `i64`.** That is PostgreSQL's own representation (`Cash` is an `int64` of the locale's smallest unit), so the range, the overflow points and integer division match it exactly; the `C` locale's two fraction digits are what PostgreSQL's default `lc_monetary` gives on servers installed with the `C` or `POSIX` locale, and what dumps restored into EggDB were written with.
- **How.** A `DefinedValue::Money(i64)`; stored rows tag it 39 with eight bytes, keys keep it as a sign-flipped big-endian word, so primary keys on `money` decode. The network types' keys now decode too, so an `inet` primary key works.
- **Left.** Other `lc_monetary` locales (their symbols, separators and fraction digits), `money` in the other dialects (SQL Server's `money` stays its own type, D123), and `avg(money)`, which PostgreSQL does not have either.
- **Proof.** Unit tests for input and output forms, overflow, arithmetic and `cash_words`; a session test stores amounts in three spellings, orders by an indexed `money` column, sums, multiplies, divides, negates, casts to `numeric`, compares with a literal and calls `cash_words`.

**Status:** code written, unbuilt (code-only mode, D355).
