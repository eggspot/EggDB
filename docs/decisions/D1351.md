## D1351 MCP tools for the file's statistics, check and backup — Decided by the code-only session (2026-11-25, D355); roadmap M6d "Backup, restore and administration tools (D11)"

- **What agents get.** Three MCP tools of `eggdb mcp`, each the twin of the `eggdb` command of the same name (D143): `stats` (the file's page size, pages, free pages, size, last commit and log since the last checkpoint, reading no page), `check` (every page read as of the last commit; `ok` true, or the `damaged` error with what to do), and `backup` (with `--allow-write`: a consistent copy of the last commit written to a new file, built under a temporary name and renamed when complete). Each returns the fields its command prints with `--format json`, after the data notice.
- **Where the copy goes.** `backup`'s `copy` is a file name alone, written beside the database file: a path, `.`, `..`, a separator, `:` or NUL is refused with `invalid_arguments`, and an existing file is never replaced. An agent therefore cannot write anywhere else on the machine, nor overwrite a file, through this tool. `backup` changes nothing in the database, so it asks no confirmation, but it writes a file, so it needs `--allow-write` (effect `change`, grant `allow_write`).
- **Who gets them.** A server limited to tables (`--tables`) or acting as a role sees only parts of the database, while these tools work on the whole file, so they are refused there with `limited_to_tables` or `limited_to_role`. They stay listed, as the grant model has no grant for "the whole file"; the refusal says to ask the user to run the command.
- **How.** `DatabaseOpener` gains `administer(Administration)`, default `None` (answered `not_supported`); `eggdb mcp`'s file opener opens the file for the call alone and reuses the CLI's report functions, so tool and command print the same fields. `check` on a large file can reach the call's time limit; the description says to ask the user to run `eggdb check` then. `Database::backup_to` now passes its progress callback both counts, as `backup_to_reporting` takes them.
- **Left.** `restore` as a tool (it replaces data, so it needs its own confirmation design), `stats --collections` (it reads every key), `compact`, and the same tools on `eggdb serve`'s MCP endpoint, whose opener does not answer `administer` yet.
- **Proof.** The command model's parity test compares `stats` and `check` with `eggdb stats|check --format json`, refuses `backup` on a read-only server and for path-like names, backs up to a new name and checks the copy's entries, and refuses a second backup to the same name; the tools list counts 12 tools read-only and 23 with `--allow-write`.
