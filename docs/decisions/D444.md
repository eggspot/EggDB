## D444 Tombstone collection and membership changes by epoch in the leaderless quorums — Decided by the code-only session (2026-11-11, D355); roadmap M18, extends D225

- **Tombstones.** `Quorum::collect_tombstones` drops a deleted key once every one of its home
  replicas is reachable and holds the same single deletion version, and no hint for the key waits
  to be handed off: then no replica can bring an older value back, which is the condition Dynamo
  states for forgetting a deletion. A key with an unreachable home keeps its tombstone. It returns
  how many keys were collected.
- **Membership by epoch.** `add_node` and `remove_node` change the node set in a new epoch (one
  more per change, from 0), the epoch D212's shard map also counts by. Rendezvous placement moves
  only the keys whose homes changed: after a change every key's versions (reconciled by the key's
  policy) are stored on its new homes, and a former home drops the key once every new home holds
  it. A leaving node hands its versions and the hints it kept to the new homes first; removing a
  node is refused when fewer than `n` would be left.
- Left: running a change while writes continue and across the network (with D225's transport),
  the epoch carried in requests so a node on an old epoch is told to refresh, and joint
  membership during a move.
