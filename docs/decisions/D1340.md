## D1340 Rows streamed from plain scans, first step of the streaming executor — Decided by the code-only session (2026-11-25, D355); roadmap M5 "A resumable executor that streams rows" (D284, D287, D293)

- **What users get.** `Session::execute_streamed` runs statements as `execute` does but hands rows to a callback: columns first, then rows, then the result with its rows left empty. A query reading one table without joins, sorting, grouping, `DISTINCT`, locking, subqueries, aggregates or window functions sends each row as the scan finds it, so a `SELECT` over a large table never holds its result in memory; its tag still counts the rows (`SELECT 500`). Every other statement sends its rows when it finishes, so callers use one interface for both. The callback returning `false` stops the scan.
- **How.** The executor builds each result as one list, and threading a row sink through every layer of it is the larger redesign this item names. This step goes around it without touching the layers: the session checks the statement's shape, arms a sink for the one table it reads, and the scan of that table, the outermost, claims the sink and sends rows instead of collecting them. Claiming takes the sink, so a scan nested inside the rows (a function's query) finds none; a view, whose rows come from another table, never claims it and falls back. The sink lives in a scoped thread-local that the session's guard empties when the statement ends; its two `unsafe` operations (erasing the borrow's lifetime, and calling through the pointer while the guard lives) carry their `SAFETY` notes.
- **Left.** Pausing and resuming a scan, which portals with a row count need; using the stream in the PostgreSQL protocol, the C API's stepping and `COPY TO`; streaming joins, sorts and groups; and, with that, sorts that spill to disk (D1339).
- **Proof.** A session test streams 500 of 1,000 rows from a filtered scan with the right columns, first row and tag; an `ORDER BY ... LIMIT` query falls back and still arrives through the callbacks; a callback that stops after ten rows stops the scan.

**Status:** code written, unbuilt (code-only mode, D355).
