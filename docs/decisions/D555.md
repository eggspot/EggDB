## D555 The requested isolation level in `SHOW transaction_isolation` — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D308

EggDB runs every transaction serializable (one writer, snapshot readers), and showed
`serializable` whatever a client asked for; `SET default_transaction_isolation` was refused.
SQLAlchemy's suite, and drivers that check the level they set, read the level back and fail.
PostgreSQL shows the level a transaction asked for, so EggDB now does too, while still running
serializable, which is at least as strong as every level a client can ask for:

- `default_transaction_isolation` takes the four levels (any case and spacing, kept in lower
  case; anything else is `22023` listing them), set directly or by `SET SESSION CHARACTERISTICS
  AS TRANSACTION ISOLATION LEVEL ...`.
- `transaction_isolation` shows, at the start of each statement, the level the open transaction
  asked for (`BEGIN ISOLATION LEVEL ...`, `SET TRANSACTION ISOLATION LEVEL ...`), else the session's
  default; outside a transaction it is the default. `SHOW` and `current_setting` both read it.
- The rules for when a level may change (before any query, not in a savepoint) are unchanged.

Only the PostgreSQL dialect keeps it in step; MySQL's `transaction_isolation` variable is its own.
