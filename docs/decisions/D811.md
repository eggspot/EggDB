## D811 JetStream mirrors and sources — Decided by the code-only session (2026-11-12, D355); roadmap M16, NATS JetStream (D33, D216)

- A stream may name a `mirror` (`name`, optional `filter_subject` and `opt_start_seq`) or up to 32 `sources` of the
  same form, not both and never itself. A mirror has no subjects of its own, so nothing published lands in it
  directly; a stream with sources and no subjects gets none either (the default subject is only for plain streams).
- When a stream stores a message, every stream that mirrors or sources it and whose filter and start sequence take
  that message stores a copy, through the same path as a publish (limits, rollups, deduplication and consumers
  apply). Sources add `Nats-Stream-Source: <origin> <seq>`; mirrors keep the headers as they are. Copies chain up to
  8 hops, so a cycle of sources stops.
- Creating a mirror or sourcing stream copies what its origins already hold. The configuration (and stream info)
  shows `mirror` and `sources`.
- Mirror sequence numbers are the mirror's own, not the origin's, and there is no lag report or external domain
  (`external`, `domain`); those are left.
