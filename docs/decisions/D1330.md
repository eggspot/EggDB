## D1330 PostgreSQL's bit strings — Decided by the code-only session (2026-11-25, D355); roadmap "PostgreSQL's network address ... bit string ... types" (D19)

- **What users get.** `bit(n)`, `bit varying(n)` and `varbit(n)` columns, `B'1010'` and `X'1F'` literals, and casts in PostgreSQL's dialect. A column refuses a value of the wrong length with PostgreSQL's errors (22026, `bit string length 3 does not match type bit(4)`, `bit string too long for type bit varying(6)`); a cast fits the value instead (`B'101'::bit(5)` is `10100`, `::varbit(3)` cuts), and integers cast to `bit(n)` keep their low `n` bits (`5::bit(8)` is `00000101`). The operators `&`, `|`, `#`, `~`, `<<`, `>>` and `||` and the functions `length`, `bit_length`, `octet_length`, `bit_count`, `get_bit`, `set_bit`, `substring`, `position` and `overlay` work on them; `bit` and `bit varying` compare with each other. OIDs 1560 and 1562 on the wire in text and binary form (the bit count, then the packed bits), with `pg_type` rows for both and their arrays.
- **How.** A `DefinedValue::Bits` keeps the digits as text and whether the type is `bit varying`; stored rows tag the two types 40 and 41, keys keep the digits, so they sort as PostgreSQL sorts bit strings. The parser remembers a `bit(n)` length the way it remembers `vector(n)` dimensions: a column gets a check calling `eggdb_bit_length_check`, which raises PostgreSQL's error, and a cast becomes a call to `eggdb_bit_fit` that pads or cuts. The PostgreSQL lexer reads `B'…'` and `X'…'` into binary digits, refusing other digits with PostgreSQL's message.
- **Left.** Keeping the length as a real type modifier (so `pg_attribute.atttypmod`, `format_type` and `\d` show `bit(4)` rather than a check), text input refused for a length mismatch on an explicit cast (PostgreSQL refuses `'1'::bit(4)`, EggDB pads it), and bit strings in the other dialects (MySQL's `BIT(n)` stays its own mapping).
- **Proof.** Unit tests for literals, fitting, the binary form, every operator and function; a session test stores both types, orders them, runs the operators and casts, and gets both length errors.
