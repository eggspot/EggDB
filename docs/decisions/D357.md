## D357 Our own Zstandard codec for cold values, overflow layout 3, and compression options in the CLI — Decided by the code-only session (2026-11-10, D355); extends D171; a storage-format change for D35's review in the build-and-fix pass

**The codec** (`eggdb-storage/src/compression/zstd`), written from RFC 8878 alone (D1):
- *Decoder:* frames and skippable frames, single-segment and windowed frames, raw, RLE and
  compressed blocks, raw, RLE, Huffman (one or four streams, direct or FSE-coded weights) and
  treeless literals, sequences with predefined, RLE, FSE-coded and repeated tables, repeat
  offsets, and the XXH64 content checksum. Dictionaries are refused. Every length is checked
  against the value's known size before memory is taken, so a hostile frame is an error, never a
  panic, and never more than the expected bytes.
- *Encoder:* one single-segment frame with the content size and checksum; blocks of at most
  128 KiB, each RLE when every byte is the same, raw when compressing does not save, and
  otherwise compressed: greedy matches from a 128 Ki-entry hash of 4-byte words over the whole
  value so far, raw literals, and sequences coded with the three predefined FSE distributions.
  It is a valid, simple compressor, not a tuned one; Huffman-coded literals and table choice per
  block are the next steps when the weekly pass measures it.
- Tests: round trips of empty, tiny, uniform, random, text and mixed inputs, a hand-built frame
  and a Huffman literals block, XXH64's published vectors, every truncation and 2,000 damaged
  frames never panicking, wrong expected lengths and a damaged checksum refused.

**Storage.** `ValueCompression::Zstd` writes values of 4 KiB or more as layout-3 overflow chains
when the frame saves a sixteenth, exactly like layout 2 with LZ4 (D171), and sets the new
incompatible feature `ZSTD_VALUES` (bit 2) at the commit, so a release from before refuses the
file instead of calling the pages damaged. The page cache now remembers which compression
features a transaction wrote, as bits. `Options::value_compression` picks the codec;
`Options::compress_values(true)` still means LZ4.

**CLI.** `--compress lz4|zstd|off` on `create`, `put`, `import`, `sql`, `shell`, `serve`,
`restore` and `follow` (docs/cli.md).

**Left (roadmap M2):** compressed leaf pages and log records with a codec per column and page.
