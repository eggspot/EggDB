## D484 Column grants follow MySQL's `CHANGE COLUMN` — Decided by the code-only session (2026-11-11, D355); roadmap M6b, completes D285

- `ALTER TABLE t CHANGE COLUMN a b ...` renames the column's stored column grants with it, as
  `RENAME COLUMN` already did (`roles::move_column`), so a role granted `SELECT (a)` keeps reading
  the column as `b`, and no stale grant on `a` comes back if a new column named `a` is added.
  The column's comment moves with it too, as for `RENAME COLUMN`. `MODIFY COLUMN` keeps the name,
  so its grants and comment are untouched.
