## D1004 SQL Server's `geometry` and `geography` — Decided by the code-only session (2026-11-13, D355); roadmap M12 (D19, D204, D845)

- `geometry` and `geography` columns in the SQL Server dialect are stored as the PostGIS-compatible `geometry` type
  (D845), as MySQL's spatial types are (D991); a `geography` is a geometry whose SRID is 4326 (or what the value
  gives). `CAST` and `CONVERT` to either read WKT or EWKT text. The catalogs show `varbinary(max)` until EggDB keeps
  declared SQL Server types.
- Static methods: `geometry::STGeomFromText(wkt, srid)` and every `ST...FromText`, `ST...FromWKB(bytes, srid)`,
  `Parse(wkt)` (SRID 0 for `geometry`, 4326 for `geography`), and `Point(x, y, srid)` — for `geography`,
  `Point(lat, long, srid)`, latitude first, as SQL Server takes it.
- Instance methods on columns (`g.Method(...)`, `t.g.Method(...)`) call the spatial functions: `STAsText`,
  `ToString`, `STAsBinary`, `STArea`, `STLength`, `STEnvelope`, `STCentroid`, `STNumPoints`, `STIsValid`,
  `STIsEmpty`, `STNumGeometries`, `STStartPoint`, `STEndPoint`, `STExteriorRing`, `STNumInteriorRing`,
  `STConvexHull`, `STIntersection`, `STPointN`, `STGeometryN`, `Reduce`, the predicates `STIntersects`,
  `STContains`, `STWithin`, `STEquals` and `STDisjoint`, `STGeometryType` (SQL Server's `Point`, not `ST_Point`), and
  `STDistance`, in metres on the sphere for SRID 4326 and planar otherwise.
- The properties `STX`, `STY` and `STSrid` read without parentheses. `Lat` and `Long` are not taken, since
  `table.lat` names a column far more often; `STY` and `STX` read them.
- Left: methods on variables (`@g.STDistance(...)`), `STBuffer`, `STTouches`, `STOverlaps`, `STCrosses`, the
  ellipsoidal distance SQL Server uses for `geography`, and the UDT type in TDS metadata.
