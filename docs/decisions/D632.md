## D632 TOP PERCENT in Transact-SQL DML, and INSERT TOP — Decided by the code-only session (2026-11-12, D355); roadmap M10, D300, D605

D605 built `UPDATE TOP (n)` and `DELETE TOP (n)` and left `TOP (n) PERCENT` there, and `TOP` in
`INSERT`, refused. Archiving jobs copy a table in slices with `INSERT TOP (1000) INTO archive
SELECT ...`, and purges take a share of a table with `DELETE TOP (10) PERCENT`.

- The thread-local DML row limit becomes `DmlRowLimit::Rows(n)` or `DmlRowLimit::Percent(p)`.
  The parser wraps a `PERCENT` count the way `SELECT TOP (p) PERCENT` does
  (`sqlserver_top_percent`), so the session checks it the same way (0 to 100, msg 1031) before
  it runs the inner statement.
- A percentage turns into rows once the candidates are known, rounded up as SQL Server does:
  `DELETE` takes it of the rows that matched its `WHERE`; `UPDATE` counts the rows that pass its
  `WHERE` first and then stops after that share; `INSERT` takes it of its `VALUES` rows or of
  the rows its query returned.
- `INSERT TOP (n) [PERCENT] [INTO] t ...` is parsed through the same wrapper. The insert takes
  the limit as it starts (so triggers and cascades are not limited), runs a query source first,
  and keeps the first rows. An insert into a view with `TOP` is refused, like D605's views.
