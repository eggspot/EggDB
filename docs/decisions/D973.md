## D973 The ODBC driver's wide-character entry points — Decided by the code-only session (2026-11-13, D355); roadmap M6f, follow-up of D968 and D972

- Windows' driver manager calls a driver's `W` functions for Unicode applications, and maps them onto ANSI calls only
  with losses outside the code page. The driver now exports `SQLConnectW`, `SQLDriverConnectW`, `SQLExecDirectW`,
  `SQLPrepareW`, `SQLDescribeColW`, `SQLColAttributeW`, `SQLGetDiagRecW`, `SQLGetInfoW`, `SQLTablesW` and
  `SQLColumnsW`.
- Each converts its UTF-16 inputs (length in characters, or `SQL_NTS`) to UTF-8, calls the ANSI implementation, and
  converts text outputs back into the application's buffer with ODBC's units: characters for connection strings,
  column names and diagnostic messages; bytes for `SQLColAttributeW` and `SQLGetInfoW`. Truncation answers
  `SQL_SUCCESS_WITH_INFO` with the full length, as ODBC asks; non-text `SQLGetInfoW` answers pass through unchanged.
- Data stays as it was: `SQLGetData` and `SQLBindCol` already convert to `SQL_C_WCHAR` (D968).

**Status:** code written, unbuilt (code-only mode, D355).
