## D1296 Oracle's SYS_GUID, STANDARD_HASH, ORA_HASH, NLS_ case functions, LOB constructors, VSIZE, LNNVL, ASCIISTR and UNISTR — Decided by the code-only session (2026-11-18, D355); roadmap M4 Oracle compatibility (D10, D1292)

- **What users get.** In Oracle's dialect: `SYS_GUID()` (16 random bytes as `RAW`, the usual key default), `STANDARD_HASH(expr[, 'SHA1' | 'SHA256' | 'SHA384' | 'SHA512' | 'MD5'])`, `ORA_HASH(expr[, max_bucket[, seed]])` (a bucket from 0 to `max_bucket`, stable for the same input and seed, ORA-01428 out of range), `NLS_UPPER`, `NLS_LOWER` and `NLS_INITCAP` (their `nlsparam` accepted and not used), `TO_CLOB`, `TO_BLOB`, `EMPTY_CLOB()`, `EMPTY_BLOB()`, `VSIZE` (the value's bytes), `LNNVL(condition)` (true when the condition is false or unknown) and `ASCIISTR`/`UNISTR` (`\XXXX` UTF-16 escapes both ways, ORA-30186 for a bad one).
- **How.** Beside D1292's Oracle functions. `ORA_HASH` buckets a SHA-256 of the seed and the value: its numbers are EggDB's own, not Oracle's (whose hash is unpublished), which keeps it right for what it is used for, partitioning and sampling into buckets, but not for comparing with hashes stored by Oracle. `VSIZE` counts text's UTF-8 bytes and numbers' text, where Oracle counts its internal `NUMBER` form.
- **Later the same night.** `TO_MULTI_BYTE` and `TO_SINGLE_BYTE` turn ASCII into its full-width forms (U+FF01–U+FF5E, the ideographic space) and back.
- **Left.** Oracle's own `ORA_HASH` values, `VSIZE` of Oracle's `NUMBER` encoding, and `DECOMPOSE`.
- **Proof.** Unit tests escape and unescape a non-ASCII character and a backslash, and refuse a short escape.

**Status:** code written, unbuilt (code-only mode, D355).
