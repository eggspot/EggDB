## D1335 Compressed pages logged without their zero tail — Decided by the code-only session (2026-11-25, D355); roadmap M2 "Compressed leaf pages and log records" (D40, D171), after D1334

- **What users get.** With `Options::compress_pages` on, the write-ahead log carries a compressed leaf page as its stored form without the zeros after the compressed body, so commits of compressible rows write less log, sync less, and checkpoints and recovery read less.
- **The record.** A new log record type, `ShortPageImage` (6): the page number and the stored page up to the end of its compressed body. It is accepted only when shorter than a page and longer than a page header. Recovery rebuilds the whole stored page by adding the zeros back before checking its checksum, as for a whole image, and remembers each image's length; reads from the log, the in-place writes from the log buffer and from the log file, and the writes ahead of D1333 all zero-fill past it. Whole pages keep the `PageImage` record. The log of a file with compressed pages already needs `COMPRESSED_PAGES` (D1334) to open, so no older release meets the new record.
- **Left.** Compressing other page types and the log's own blocks (the records are short, the blocks they sit in are not compressed), and choosing compression per column.
- **Proof.** A page cache test with 16 KiB pages commits one compressible leaf, sees less than a page of log since the checkpoint, crashes dropping the unsynced in-place write, reopens and reads the page back from the replayed short record.

**Status:** code written, unbuilt (code-only mode, D355). A file format change, reviewed for security with D1334 in the build-and-fix pass (D35).
