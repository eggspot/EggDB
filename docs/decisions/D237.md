## D237 The console's first piece is ER diagrams any SQL client can draw — Decided by the build loop (by judgement, 2026-10-31); refines D15 and D42

Track 4.X-9 asks for an admin console, notebooks, a query builder, ER diagrams and import
wizards in the client, designed by Claude Fable.

- **Screens wait for their design; the diagram is data.** Each console screen gets its Fable
  design in `docs/ux/` first (D15). An ER diagram, though, is a text format that existing tools
  render: Mermaid in Markdown and notebooks, Graphviz DOT anywhere. So the first piece is
  `CREATE EXTENSION eggdb_console` with `eggdb_console.er_diagram(schema, 'mermaid' | 'dot')`,
  built from `information_schema` (tables, columns with types, primary keys, foreign keys).
  It works from every SQL client and every protocol today, and the GUI's ER view will draw the
  same catalog query.
- **In SQL, not in the `eggdb` command**, so pgAdmin, DBeaver, a notebook or an AI agent through
  MCP gets the same diagram without a new tool.

Left: the console screens (server status, sessions, locks, slow queries), notebooks, the query
builder and import wizards, each with its Fable design; diagrams across schemas and with
views, indexes and check constraints; and the GUI's interactive ER view.
