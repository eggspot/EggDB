## D680 InfluxQL subqueries — Decided by the code-only session (2026-11-12, D355); roadmap M16, InfluxQL (D220, D521)

- `FROM (SELECT ...)` takes a subquery, nested to any depth, as InfluxDB 1.5 and later do. The inner query is
  translated as any `SELECT` (D521, D675–D677) and becomes a derived table `(...) AS "subquery"`; the outer query is
  translated against it, so its `WHERE`, aggregates, `GROUP BY time()` and tags read the inner query's output
  columns (`time`, the inner `GROUP BY` tags and the inner items' names, such as `mean`).
- The outer query's columns are learned by running the derived table with `LIMIT 0`; the inner query's `GROUP BY`
  tags count as tags for `GROUP BY *`. Results are named after the inner query's measurement, as in InfluxDB.
- A subquery reads one measurement; a list or a regular expression that matches several is refused. `INTO` is not
  allowed inside a subquery. An inner `fill()` other than `none` does not make empty buckets, as filling happens
  after the SQL query runs (D675); the outer query's `fill()` works as usual.
