## D1139 A set-returning function stopped by a LIMIT given as a parameter or a fixed expression — Decided by the code-only session (2026-11-14, D355); roadmap M5 (D287)

- **Before.** A lone set-returning function in `FROM`, such as `generate_series` or `unnest`, generated only the rows
  a `LIMIT` and `OFFSET` needed when both were integer literals (D287). `LIMIT $1` from a driver's prepared statement,
  or `LIMIT 10 * 2`, generated every row first.
- **Now.** A count whose expression is fixed before any row is read also bounds the function: literals, bound
  parameters (constants by then), casts, unary minus and `+`, `-` and `*` of those. It is evaluated once, as the
  `LIMIT` itself is, with the same conversions. A count that fails to evaluate or comes out `NULL` leaves the function
  unbounded, and the statement then reports the same error at the same point as before. Expressions that could
  change between two evaluations, such as `random()` or a subquery, are never used, so the bound always equals the
  limit applied afterwards.
- **Left:** functions joined with other tables or filtered by `WHERE`, where the rows needed depend on how many pass.
  Bounding those needs the resumable, streaming executor (M5) to pull generated rows on demand.

**Status:** code written, unbuilt (code-only mode, D355).
