## D1247 ODBC's SQLStatistics lists every index — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1237)

- **What users get.** `SQLStatistics` (and `SQLStatisticsW`) now lists a table's plain indexes as well as the ones behind its primary key and unique constraints, so Excel, Power BI and other ODBC tools see every index. A non-unique index says `NON_UNIQUE` 1, a descending key column `ASC_OR_DESC` `D`, a partial index its condition in `FILTER_CONDITION`, and an expression key its expression as the column. `SQL_INDEX_UNIQUE` keeps the unique ones only; `SQL_INDEX_ALL` lists all.
- **How.** The query reads `pg_index` the way pgJDBC's `getIndexInfo` does, which EggDB already answers (`information_schema._pg_expandarray` over `indkey`, `pg_get_indexdef` for each key column, `indoption`'s descending bit, `pg_get_expr` over `indpred`), instead of `information_schema.key_column_usage`, which only knows constraints. Rows come in ODBC's order: `NON_UNIQUE`, `TYPE`, `INDEX_NAME`, `ORDINAL_POSITION`.
- **Left.** The table statistics row (`SQL_TABLE_STAT`), cardinality and pages.
- **Proof.** The ODBC test adds a descending plain index and checks both rows, and that `SQL_INDEX_UNIQUE` leaves it out.
