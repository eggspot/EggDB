## D879 CQL2 filters and queryables in OGC API - Features — Decided by the code-only session (2026-11-12, D355); follow-up of D781

- `/ogc/collections/{id}/items` takes OGC API - Features Part 3's `filter`, with `filter-lang` `cql2-text` (the
  default) or `cql2-json`, and `filter-crs` (only CRS84). Our own reader of CQL2 (OGC 21-065) in `eggdb-api/src/cql2.rs`
  turns both encodings into one SQL condition beside `bbox`: `AND`, `OR`, `NOT`, the comparisons, `LIKE`,
  `BETWEEN`, `IN`, `IS [NOT] NULL`, arithmetic, `CASEI` (as `lower`), `ACCENTI` (accepted, without folding yet), the
  spatial functions `S_INTERSECTS`, `S_EQUALS`, `S_DISJOINT`, `S_TOUCHES`, `S_WITHIN`, `S_OVERLAPS`, `S_CROSSES` and
  `S_CONTAINS` over WKT literals, GeoJSON (in JSON) and `BBOX`, and the temporal functions `T_AFTER`, `T_BEFORE`,
  `T_CONTAINS`, `T_DISJOINT`, `T_DURING`, `T_EQUALS`, `T_FINISHES`, `T_INTERSECTS`, `T_MEETS`, `T_METBY`,
  `T_OVERLAPPEDBY`, `T_OVERLAPS` and `T_STARTS` over `DATE`, `TIMESTAMP` and `INTERVAL` (with `..` for an open end).
- Properties must be columns of the collection's table (`geometry` and `geom` also name its geometry column); a
  filter naming anything else, or malformed, is a 400. Literals are always quoted, WKT is checked to hold only its own
  characters, and the reader limits nesting to 64 and filters to 64 KiB.
- `/ogc/collections/{id}/queryables` describes the columns as a JSON Schema (`integer`, `number`, `boolean`,
  `string`, and GeoJSON's schema for the geometry). The conformance list names Part 3's filter, features-filter and
  queryables classes and CQL2's basic, advanced comparison, case-insensitive, spatial, temporal, text and JSON
  classes. Paging links keep the filter.
- Geometry literals are in SRID 4326 (CRS84); a geometry column in another SRID needs a transform first.
- Left: `ACCENTI` folding, array functions (`A_CONTAINS` ...), property-to-property spatial filters across
  collections, and other filter CRSs.
