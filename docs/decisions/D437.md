## D437 pgvector's `subvector`, `binary_quantize`, bit distances and `sparsevec` text — Decided by the code-only session (2026-11-11, D355); roadmap M12, extends D203

- Vectors are still text until the stored type lands (D203), so this adds what works on text:
  `subvector(vector, start, count)` (1-based, clipped to the vector as pgvector does, an empty
  result an error), `binary_quantize(vector)` (one bit per dimension, set for positive values,
  as bit text), and `hamming_distance(bit, bit)` and `jaccard_distance(bit, bit)` on bit strings
  of the same length.
- `sparsevec`'s text form `{index:value, ...}/dimensions` (1-based indexes) is read wherever a
  vector is, so the distance operators and functions take sparse vectors too; results that are
  vectors come back in the dense form, where pgvector keeps a `sparsevec` sparse.
- `halfvec` needs nothing more while vectors are text (its values read as `real`s); its half
  precision arrives with the stored types. Vector arithmetic (`+`, `-`, `*` between vectors) waits
  for the stored type too: on text those operators would mean something else.
- The vector functions are now one list (`vector_functions::FUNCTIONS`) that the evaluator
  dispatches on.
