## D829 Notices sent before an error — Decided by the code-only session (2026-11-12, D355); roadmap M6a, D154 and D324

- Notices a statement raised before it failed were dropped with its result: PL/pgSQL `RAISE NOTICE` lines before an
  exception, and `COPY ... (ON_ERROR ignore, LOG_VERBOSITY verbose)`'s "skipping row" notices before the
  `REJECT_LIMIT` error. PostgreSQL sends them first.
- `COPY` now queues its notices when it fails, and the session keeps a failed statement's raised notices in a
  per-thread list (at most 10,000) that `eggdb_sql::take_notices_before_error()` empties. The PostgreSQL listener's
  simple-query path sends them as `NoticeResponse`s before the `ErrorResponse`.
- Each statement empties the list when it starts, so a listener that does not send them (the extended-query path
  and the other listeners, left) never sends a stale notice later.
