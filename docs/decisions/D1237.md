## D1237 SQLStatistics, SQLSpecialColumns and SQLProcedures in the ODBC driver — Decided by the code-only session (2026-11-17, D355); roadmap M6f, the ODBC driver (D968, D1236)

- **What users get.** `eggdb-odbc` answers `SQLSpecialColumns` (`SQL_BEST_ROWID`: the primary key's columns with their ODBC types, as tools that edit rows through ODBC ask for; `SQL_ROWVER`: none), `SQLStatistics` (the indexes behind primary key and unique constraints, one row per column, unique, ascending) and `SQLProcedures` (functions and procedures matching the patterns, typed `SQL_PT_FUNCTION` or `SQL_PT_PROCEDURE`), with their `W` forms.
- **How.** Catalog queries over `information_schema` (`table_constraints`, `key_column_usage`, `columns`, `routines`), as D972 and D1236 do.
- **Decided by research.** `SQLStatistics` lists only the indexes that back constraints, because `information_schema` has no indexes and EggDB's `pg_index` reading through `unnest(indkey)` is not something the driver should depend on unbuilt; plain indexes are recorded as left, and no `SQL_TABLE_STAT` row is given (ODBC allows its absence when the cardinality is unknown).
- **Left.** Plain indexes and cardinalities in `SQLStatistics`, parameter counts in `SQLProcedures`, `SQLProcedureColumns`, and the privilege catalog functions.
- **Proof.** The ODBC integration test: the best row identifier is the primary key column, no row-version columns, and the primary key's index listed as unique.

**Status:** code written, unbuilt (code-only mode, D355).
