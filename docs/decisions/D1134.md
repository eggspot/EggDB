## D1134 Runner descriptions, a public results page with dashboards, and the farm's driver and ORM version matrix — Decided by the code-only session (2026-11-14, D355); roadmap M4 (D32, D44, D252)

- **Runner descriptions.** `scripts/runner-description.sh` writes the runner a measurement ran on as a table:
  image and version, system and kernel, processor model, logical processors, memory, compiler and commit. The
  `bench` and `compare` jobs write it beside their results (artifacts) and into the run's summary, so every number
  carries the machine that produced it.
- **The results page.** `scripts/results-page.sh` builds one static page, with no scripts, no third-party assets and
  readable without JavaScript, containing:
  - a chart of every "EggDB to other database" ratio in `benchmarks/baseline.txt`, as horizontal bars around a dashed
    1.0 line (green when EggDB is at or ahead, rust when behind), sorted best first, each bar titled with its exact
    value;
  - the footprint and coverage targets;
  - the SQL conformance counts by status from `docs/sql-conformance.md`;
  - the tools-and-drivers table of `docs/compatibility.md`;
  - the latest farm matrices and runner descriptions.

  The `Results page` workflow rebuilds it when those files change on `main`, weekly, and on request, fetching the
  latest successful farm and CI artifacts, and deploys it with GitHub Pages.
- **The farm's version matrix.** The weekly compatibility farm gains a `drivers` matrix that runs a create, insert
  and select round trip against `eggdb serve` with each version listed: psycopg2 2.9.9 and 2.9.10, psycopg 3.1 and
  3.2, SQLAlchemy 1.4 and 2.0, node-postgres 8.11 and 8.13 (`scripts/farm-driver.sh`). A `drivers-matrix` job merges
  the rows into `drivers.md`, which the results page shows. Adding a version is one line in the matrix. The drivers
  are test tools installed in the runner, never shipped.
- **For the owner.** GitHub Pages has to be turned on for `eggspot/EggDB` (Settings, Pages, source "GitHub Actions")
  before the deploy job can publish. Until then the build job still produces the page as an artifact.
