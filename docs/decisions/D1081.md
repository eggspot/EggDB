## D1081 The platform's error type and the File and Clock traits without std — Decided by the code-only session (2026-11-13, D355); roadmap M17 (D8, D223)

- The storage engine reads and writes through a few platform types: `Error`, `ErrorKind`, `Result`, the
  `File` trait (with `FileLock`) and the `Clock` trait. They lived in `eggdb-platform`, which needs an
  operating system. They now live in a new crate, `eggdb-platform-core`.
  - It builds with `#![no_std]` when its default `std` feature is off, as `eggdb-format` does (D223).
  - `eggdb-platform` depends on it with `std` and re-exports every item under its old path, so no caller
    changes.
- **The error keeps its behaviour.** `Error` is a kind plus, with `std`, the operating system's
  `io::Error` as its source and in its message. `From<io::Error>` and `std::error::Error` exist only with
  `std`.
  - `with_kind` became public, since the platform crate that uses it is now a different crate.
  - `ErrorKind::describe` became public for the same reason.
- `File` and `Clock` moved as they were. The docs no longer link to `FileSystem` and `OpenMode`, which stay
  in `eggdb-platform`.
- CI's no-`std` check (the `thumbv7em-none-eabihf` clippy step of D223) now also builds the core crate.
- This is the first step of running the B-tree, page cache, log and transactions without `std`. Left: the
  storage engine's own `std` feature on top of this crate, with frames from a caller's fixed buffer in place
  of `Memory`, its locks behind a small shim, and opening through a `FileSystem` kept to `std`.

**Status:** code written, unbuilt (code-only mode, D355).
