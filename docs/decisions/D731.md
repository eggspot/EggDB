## D731 `image_metadata`: EXIF and XMP from images — Decided by the code-only session (2026-11-12, D355); roadmap M16, digital asset management: EXIF and XMP metadata (D56)

- `image_metadata(bytea) → jsonb` reads JPEG (APP1 `Exif` and XMP segments, the frame header's size), PNG (`IHDR`,
  `eXIf` and uncompressed `XML:com.adobe.xmp` `iTXt` chunks), WebP (`VP8X`, `VP8L` and `VP8 ` sizes, `EXIF` and
  `XMP ` chunks) and TIFF files, written from the EXIF 2.3 and TIFF 6.0 layouts with EggDB's own code.
- EXIF tags are read from the main image directory and the Exif and GPS directories it points to; values keep
  their TIFF types (strings, numbers, rationals as decimals, lists as arrays, undefined bytes as text when
  printable and hex otherwise). GPS degrees, minutes and seconds also appear as signed decimal `latitude` and
  `longitude`. Maker notes and the interoperability directory are skipped.
- Bounds: at most 1,000 entries per directory, 64 KiB per value, 1 MiB of XMP and 10,000 segments or chunks; an
  offset outside the file skips that value rather than failing.
- Renditions (resizing, re-encoding) with codecs of our own are still left.

**Status:** code written, unbuilt (code-only mode, D355).
