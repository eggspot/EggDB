## D1263 Binary tuples in pgoutput — Decided by the code-only session (2026-11-18, D355); roadmap logical replication to PostgreSQL subscribers (D1243, D1245)

- **What users get.** A subscription created with `binary = true` (PostgreSQL 14 and later send `binary 'true'` in `START_REPLICATION`) gets each column value of the insert, update and delete messages in its binary form (`'b'`), as PostgreSQL's own publisher sends them, which the subscriber applies without parsing text. Without the option, values stay text (`'t'`), as before.
- **How.** The walsender reads the option once per stream and passes it to the message builder, which encodes each value with the same binary encoder as the extended query protocol's results, by the column's type OID from the relation message and in UTC. A value whose type has no binary form is still sent as text, which a subscriber accepts column by column; NULL stays `'n'`.
- **Left.** Truncates, and streamed and two-phase transactions.
- **Proof.** A unit test builds an insert message with an integer and a NULL in binary (the integer as four big-endian bytes) and in text, and the option is read from `START_REPLICATION`.

**Status:** code written, unbuilt (code-only mode, D355).
