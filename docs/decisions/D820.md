## D820 API keys for roles — Decided by the code-only session (2026-11-12, D355); roadmap M6b, D22

- `CREATE EXTENSION eggdb_api_keys` adds `eggdb_api_keys.create_key(role, label, valid_for)`, which returns a key
  `eggdb_<12 hex id>_<64 hex secret>` once and keeps only its SHA-256, `revoke_key(id)`, `check_key(role, key)` (which
  also stamps `last_used_at`) and the view `listed` without hashes. The key table is revoked from `PUBLIC`.
- A rule-file line `<user> apikey` makes that user log in over the PostgreSQL protocol with one of its keys as the
  password, sent in clear text, so only over TLS or the local socket as `ldap` and `jwt` are. The listener checks the
  key against the database it logs in to (`eggdb_sql::api_keys::check_api_key`) and still requires a stored role with
  `LOGIN`. Keys are 256-bit random, so a plain SHA-256 is enough to store them (no password stretching).
