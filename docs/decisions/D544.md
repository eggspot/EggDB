## D544 SQL*Plus `DESCRIBE`, `PROMPT` and `SPOOL` in `eggdb shell` — Decided by the code-only session (2026-11-11, D355); roadmap M5

Oracle users type these three SQL*Plus commands more than any other, so `eggdb shell --dialect
oracle` now runs them, with SQL*Plus's shortest abbreviations (`DESC`, `PRO`, `SPO`).

- **`DESCRIBE [owner.]name`** reads `user_tab_columns` (or `all_tab_columns` with an owner), so it
  shows exactly what the dictionary views show, and lays the columns out as SQL*Plus does: `Name`,
  `Null?` (`NOT NULL` or blank) and `Type` (`NUMBER(p,s)`, `VARCHAR2(n CHAR)`, `RAW(n)`, ...).
  Unquoted names are folded to upper case, quoted ones kept. An unknown object prints
  `ORA-04043: object <name> does not exist` and exits with the not-found code; a database link
  (`@`) or a three-part name is refused as `SP2-0565`.
- **`PROMPT text`** prints the rest of the line as typed, a trailing `;` included, as SQL*Plus does.
- **`SPOOL file [CREATE|REPLACE|APPEND]`** copies everything the shell prints on standard output
  into the file until `SPOOL OFF` (or another `SPOOL file`); `.lst` is added to a name without an
  extension, `REPLACE` is the default, `CREATE` refuses an existing file with `SP2-0771`, and a bare
  `SPOOL` says where output is going. Messages on standard error are not copied. `SPOOL OUT`
  (printing) is refused.
- **Left out:** `VARIABLE`/`PRINT`, which need output binds from PL/SQL blocks in the session, and
  `COLUMN` formatting, which needs per-column formats in the result renderer.
