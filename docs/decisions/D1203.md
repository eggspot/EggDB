## D1203 Plan advice, unused indexes and configuration advice in `eggdb_advisor` — Decided by the code-only session (2026-11-17, D355); roadmap M6c, an index and plan advisor and automatic tuning (D25, D31)

- **What users get.** Beside D780's index recommendations, `eggdb_advisor` now: proposes dropping the indexes no statement has used since the statistics were reset (`find_unused_indexes`, from `pg_stat_user_indexes`, never a primary key or unique constraint's); reads the costliest statement shapes in `pg_stat_statements` for plans that cost more than they need (`find_plan_advice`: reading every column, `OFFSET` paging, `NOT IN` with a subquery, an `UPDATE` or `DELETE` of a whole table, counting a whole table, `lower(column) = $1` without an expression index), with the reason and the better form; and reviews settings (`configuration_advice()`: no `statement_timeout`, no `idle_in_transaction_session_timeout`, slow statements not logged, no statement statistics yet). All of it lands in `eggdb_advisor.advice` (kind, target, detail, DDL when there is one, the time involved), and nothing changes until someone runs the DDL.
- **Why text rules.** The statement shapes carry `$n` in place of values, so the planner cannot be asked about them directly; the rules are the ones that hold whatever the values, and they err towards saying nothing.
- **Left.** Applying configuration changes automatically within operator bounds, multi-column and covering indexes, and advice from real plans (`EXPLAIN` with sampled values).
- **Proof.** A unit test finds an unused index and its `DROP INDEX`, and reads the configuration advice.

**Status:** code written, unbuilt (code-only mode, D355). The extension's script changes reach databases that create it after this change.
