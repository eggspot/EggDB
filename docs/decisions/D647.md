## D647 TimescaleDB's first and last aggregates — Decided by the code-only session (2026-11-12, D355); roadmap M11, D202

Dashboards over time series ask for the opening and closing value of each bucket:
`SELECT time_bucket('1 hour', ts), first(price, ts), last(price, ts) FROM ticks GROUP BY 1`.
EggDB had `time_bucket` but no `first` or `last`.

- In the PostgreSQL dialect, `first(value, time)` and `last(value, time)` are rewritten while
  parsing into `(array_agg(value ORDER BY time [DESC] NULLS LAST))[1]`. The rewrite uses the ordered
  aggregate arguments and the array subscript function that already exist. That makes them
  ordinary aggregates: they work with `GROUP BY`, `HAVING` and `FILTER`, and over windows where
  `array_agg` does.
- Rows whose time is NULL sort last, so they are taken only when every time in the group is NULL,
  where TimescaleDB returns one of them too. Ties take whichever of them sorts first, as in
  TimescaleDB, where it is unspecified.
- Each group holds its values until it ends. A streaming accumulator that keeps only the best row
  is left for when the aggregate machinery takes two-argument user aggregates.
- A user function named `first` or `last` with two arguments is shadowed in the PostgreSQL dialect,
  as it is with the TimescaleDB extension installed.
- Test: `first_and_last_take_the_value_at_the_earliest_and_latest_time`.
