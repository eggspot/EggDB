## D1267 The Django backend — Decided by the code-only session (2026-11-18, D355); roadmap M6 drivers (D16, D957, D1266)

- **What users get.** `DATABASES = {"default": {"ENGINE": "eggdb.django", "NAME": "app.db"}}` runs Django's ORM, migrations, admin and test runner on an embedded EggDB file (`":memory:"`, and Django's in-memory test databases, open in memory; `OPTIONS = {"read_only": True}` opens the file read-only). Django's date, time and string functions (`django_date_extract` and the rest) work, as do `transaction.atomic()`, savepoints and both of Django's placeholder styles.
- **How.** Like the SQLAlchemy dialect (D957), the backend is Django's own SQLite backend connecting through the DB-API driver in EggDB's SQLite dialect, so Django's SQLite compiler, schema editor and introspection apply unchanged. What differs: the connection comes from `eggdb.connect`; Django's functions are defined with `Connection.create_function` (D1266), while the `STDDEV_POP`, `STDDEV_SAMP`, `VAR_POP` and `VAR_SAMP` aggregates Django would define for SQLite are EggDB's own and the math functions are built in; the cursor turns Django's `%s` and `%(name)s` placeholders into `?`; and transactions use the driver's `autocommit` attribute (`autocommits_when_autocommit_is_off` is off), so `atomic()` opens a real transaction instead of relying on Python's `sqlite3` module's isolation levels. `last_executed_query` prints the query with its parameters instead of asking SQLite to quote them.
- **Decided by research.** Building on Django's PostgreSQL backend in EggDB's PostgreSQL dialect was the alternative; it was set aside because that backend depends on psycopg's own types and adapters, while the SQLite backend needs only the DB-API and the functions D1266 adds, and the Python driver's SQLAlchemy dialect already chose SQLite's side.
- **Left.** User-defined aggregates and collations (Django defines none EggDB lacks), `init_command` and `transaction_mode` options, and running Django's own test suite against it.
- **Proof.** `drivers/python/tests/test_django.py` (skipped without Django) runs a parameter, a Django function, a rolled-back and a committed `atomic()` block with named and `executemany` parameters.
