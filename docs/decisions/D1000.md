## D1000 Arrow Flight SQL — Decided by the code-only session (2026-11-13, D355); roadmap M11, Arrow Flight SQL (D29, D999)

- `eggdb serve --flight-listen <address>` serves Arrow Flight SQL from a new crate, `eggdb-flight`, written from the
  Arrow Flight and Flight SQL protocol definitions: Flight's gRPC methods on D999's HTTP/2, a protocol buffers codec of
  our own (proto3 wire format, `google.protobuf.Any`), and results as Arrow IPC messages from `eggdb-arrow`.
- `GetFlightInfo` runs `CommandStatementQuery` and `CommandPreparedStatementQuery` as PostgreSQL-dialect SQL, and
  answers `CommandGetCatalogs`, `CommandGetDbSchemas`, `CommandGetTables` (with schema, table and type filters) and
  `CommandGetTableTypes` from `information_schema`. It keeps the result under a random ticket and returns the schema,
  the row count and one endpoint; `DoGet` returns the schema message and one record batch, once per ticket. Kept
  results expire after ten minutes, 64 at most.
- `DoPut` runs `CommandStatementUpdate` and `CommandPreparedStatementUpdate` and answers `DoPutUpdateResult`;
  `DoAction` creates and closes prepared statements (a prepared statement is its text, run on each use); `ListActions`
  names both.
- Clients sign in as the server's user: HTTP basic authentication on each call, or `Handshake`, which returns a bearer
  token. Loopback only until TLS with ALPN arrives, like the other protocols without TLS.
- Column types follow the Arrow export (D240): booleans, 32- and 64-bit integers, floats, dates, timestamps (UTC when
  the column has a time zone), binary, and text for the rest.
- Left: `CommandGetSqlInfo` (a dense union), parameter binding for prepared statements, `CommandGetPrimaryKeys` and the
  key commands, transactions, streaming results larger than memory in several batches, and ADBC.
