## D1105 Placement rules per table and residency per row, enforced where rows are stored — Decided by the code-only session (2026-11-13, D355); roadmap M18 (D18, D53, D227, D1098, D1103, D1104)

- **One extension.** `CREATE EXTENSION eggdb_placement` holds the rules as tables: `eggdb_placement.tables` (per table: tier, whether edge copies carry it, allowed regions, the column naming each row's home region), `eggdb_placement.residency` (per home region, the regions its rows may be stored in; without a row, only its own) and `eggdb_placement.transfers` (refused transfers, D53's log of cross-border transfers). `eggdb_placement.place(...)` validates a rule and installs a `BEFORE INSERT OR UPDATE` row trigger.
- **Enforced at the store, not the query.** The trigger compares a row with the server's region (`eggdb serve --region`, kept in `eggdb_placement.settings`). A local write the region may not hold fails with a message naming the row's home and the server's region. A change arriving from another server through multi-primary replication (D1098, recognised by `eggdb_mp.applying`) is dropped and logged rather than failing the whole batch, so one peer's foreign rows never stall replication. A server without a region holds everything.
- **Edges and regions.** `eggdb_sql::placement::filter_for_region` removes from a writable copy the tables kept off edges, the tables outside a region and the rows whose residency leaves the region out. An edge server (D1104) serves such a filtered copy, kept beside the archived one and named by region, so an edge in one region never holds what that region may not.
- **Tiers.** `hot` and `warm` mean "keep near": every server reads those tables through once a minute (`placement::prewarm`). The LRU tiers (page cache, then the page store's local chunks, D1103) then keep their pages. `cold` tables are never read ahead, so they fall to object storage first. Pinning by page ownership was rejected: pages carry no table identity at the file level, and read-through keeps the tiers rule-free.
- **Left.** Routing writes to a server in the row's region, which needs the region-sharded cluster to read the rules, and per-row encryption keys kept in-country (D53).
