## D1343 GiST, GIN, SP-GiST and BRIN indexes accepted and kept, searched once their structures exist — Decided by the code-only session (2026-11-25, D355); roadmap M5 "GIN, GiST, SP-GiST, BRIN and bitmap index methods ..." (D32, sql.md)

- **The problem.** `CREATE INDEX ... USING gin (...)` (and `gist`, `spgist`, `brin`) failed with "not supported", so every Rails, Django, Prisma or hand-written PostgreSQL migration that indexes a `jsonb`, array, `tsvector`, geometry or time column the PostgreSQL way stopped at that line, and `pg_dump` files with such indexes did not restore.
- **Decided.** The four methods are accepted, recorded with their method (stored as method codes 2 to 5 in the table definition, shown in `pg_class.relam`, `pg_am`, `pg_indexes` and `pg_get_indexdef`), and kept up to date with ordinary ordered entries of the column values, through the same insert, update, delete, backfill and check paths as B-tree indexes, so nothing that maintains indexes changes. The planner does not search them: results are exactly those of the table without the index. An index changes speed, never answers, so accepting the DDL now and searching later is safe in a way that accepting `USING columnar` while storing rows (D201) was not.
- **PostgreSQL's rules kept.** `UNIQUE`, `ASC`/`DESC` and `NULLS FIRST`/`LAST` are refused for the four methods with PostgreSQL's message (`access method "gin" does not support unique indexes`, 0A000), SP-GiST refuses several columns, operator classes (`jsonb_path_ops`, `gin_trgm_ops`, ...) are read and the methods' storage parameters (`fastupdate`, `gin_pending_list_limit`, `buffering`, `pages_per_range`, `autosummarize`) accepted. Column types B-tree refuses (arrays, `tsvector`, `jsonb`, geometric types) are allowed for these methods.
- **Left.** The search structures themselves: GIN posting lists for array, `jsonb` and `tsvector` containment and matching, GiST and SP-GiST trees for geometric and range operators, BRIN block ranges; Oracle's bitmap, function-based and reverse-key indexes; expression indexes (`gin (to_tsvector(...))`), which belong to the expression-index item.
- **Proof.** A session test creates the four kinds on array, `tsvector`, `jsonb`, point and integer columns, with an operator class and storage parameters, queries, updates and deletes through them, reads their access methods from `pg_am`, and gets 0A000 for a unique GIN index.

**Status:** code written, unbuilt (code-only mode, D355).
