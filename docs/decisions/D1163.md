## D1163 QUIC stage 4: a UDP server, HTTP/3 with QPACK, and `eggdb serve --http3-listen` — Decided by the code-only session (2026-11-14, D355); roadmap M6a (D34, D1160 to D1162)

- **The server.** `eggdb_quic::server::serve_http3(socket, config, handler, stop)` runs QUIC on one platform UDP
  socket (D315):
  - Datagrams are routed to their connections by destination connection ID. The client's original destination
    ID is an alias until it switches to the server's own.
  - A long header of another version gets a version negotiation packet naming version 1, only when the datagram
    is at least 1200 bytes, so it cannot amplify.
  - A client's first Initial starts a new connection with a random 8-byte ID, at most 4,096 connections at once.
  - After each receive, every connection runs its timers, its HTTP/3 session and its sends; finished connections
    are dropped.
- **Unidirectional streams.** `ServerConnection` now accepts client-opened unidirectional streams (3 allowed,
  64 KiB each) and opens its own with `open_unidirectional_stream`, within the client's limits. Streams opened
  before the client's transport parameters arrived get their send limit when the handshake completes.
- **HTTP/3 (RFC 9114).** `http3::Http3Session` drives one connection:
  - It opens the control stream with SETTINGS (`SETTINGS_MAX_FIELD_SECTION_SIZE` 64 KiB, and no QPACK table:
    capacity 0 by default).
  - Each client-opened bidirectional stream is read as HEADERS then DATA frames, with bodies up to 64 MiB. Once
    the stream ends, the pseudo-headers become an `eggdb_http::Request`: `:path` split at `?`, and
    `:authority` as `host`.
  - The request is answered by the same handler the HTTP/1.1 listener uses, with HEADERS (`:status`,
    content type, content length, the handler's headers in lower case) and DATA, then the stream's end.
  - Client control and QPACK streams are read and set aside.
  - Malformed requests close the connection with `H3_MESSAGE_ERROR`, unexpected frames with
    `H3_FRAME_UNEXPECTED`, and oversized ones with `H3_EXCESSIVE_LOAD`.
- **QPACK (RFC 9204) without a dynamic table.** The 99-entry static table of appendix A.
  - Decoding takes indexed lines, literals with a static name reference, and literals with a literal name, with
    Huffman strings through `eggdb-http2`'s HPACK coder (the same code).
  - Any dynamic-table reference or a Required Insert Count above 0 is refused, as a server announcing capacity 0
    must.
  - Encoding uses exact static matches, then name references, then literals, Huffman-coded when shorter.
- **In `eggdb serve`.** `--http3-listen <address>` (UDP, default port 443) serves the `--rest-listen` REST API over
  HTTP/3 too. It needs TLS and `--rest-listen`, uses the server's certificate with ALPN `h3`, and documents
  itself in `docs/cli.md`.
- **Tests.**
  - QPACK: the static table's landmarks, a round trip in order, and refusals.
  - HTTP/3: request mapping and the response's HEADERS and DATA frames.
  - CI's `tls-clients` job sends a real HTTP/3 GET with aioquic 1.2.0 (BSD-3-Clause, a test tool installed in a
    virtual environment, never shipped), checking the chain against the test authority; a missing aioquic fails
    the job there.

**Status:** code written, unbuilt (code-only mode, D355). With D1160 to D1163, HTTP/2, gRPC and QUIC are shared
crates of our own; HTTP/3 serves the REST API.
