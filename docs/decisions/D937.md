## D937 Key-value transactions and collections in the Java driver — Decided by the code-only session (2026-11-13, D355); roadmap M4, collections in the drivers (D292), follow-up of D930 to D936

- The Java driver gains `app.eggspot.eggdb.EggDbKeyValue` (`open(Path, readOnly)`, `begin(writing)`, `read(work)`,
  `write(work)`, `close()`) and `EggDbTransaction` (`AutoCloseable`, rolling back unless committed), calling the C API
  through the Foreign Function and Memory API like the JDBC classes.
- `write` commits when the work returns and rolls back when it throws. Failures are `SQLException`s with the C API's
  message, SQLSTATE and status, so one error type covers the JDBC and key-value calls.
- A transaction has `get`, `put` (with a `Duration` time to live), `delete`, `scan` (a `Range` from `all()`,
  `between(start, end)` or `withPrefix(prefix)`, `reversed()`, `includingEnd()`; with a `Visitor` that can stop, or
  returning a list), `createCollection`, `dropCollection`, `renameCollection`, `collections()` and
  `collectionStats(name)`; a `null` collection is the default key space; `bytes(text)` gives UTF-8 keys and values.
- The library lookup moves to the package-private `NativeLibrary`, shared by `NativeSession` and the new
  `KeyValueApi`.
