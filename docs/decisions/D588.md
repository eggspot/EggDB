## D588 MongoDB change streams — Decided by the code-only session (2026-11-12, D355); roadmap M9, D197, D566

`collection.watch()`, `db.watch()` and `client.watch()` (Mongoose's and Prisma's real-time
features, Kafka's MongoDB source connector) need change streams, which need an oplog.

- **The change log.** `Store::write` now runs every document operation against a recording
  wrapper of its write transaction (`change_log::Recording`), which notes each document stored or
  deleted with its previous bytes; when the operation succeeds, one event per change is appended
  in the same transaction under a new key kind (`4` + a big-endian sequence number, the next
  number under key `5`): `insert` with the full document, `update` with an update description
  (fields whose value changed, fields removed) and the new document, or `delete`, each with the
  database, collection, `_id` and wall time. The log keeps the last 100,000 events, deleting the
  oldest as it goes. Writes through any path (commands, restores, TTL purges) are logged, and a
  rolled-back operation logs nothing. Each logged write costs one extra read of the old document
  and two small writes.
- **The stream.** An `aggregate` whose pipeline starts with `$changeStream` (on a collection, on
  `aggregate: 1` for a database, or on `admin` with `allChangesForCluster`) opens a cursor at the
  log's current position, or just after a `resumeAfter`/`startAfter` token (the event's sequence
  number in hex, `_data`). Events come out in MongoDB's shape: `_id` (the resume token),
  `operationType`, `clusterTime`, `wallTime`, `ns`, `documentKey`, `fullDocument` (inserts, and
  updates with `fullDocument: updateLookup`), `updateDescription`; the stages after
  `$changeStream` (`$match` on `operationType`, `$project`, ...) run over them. `getMore` waits up
  to `maxTimeMS` (one second when absent, at most ten) for new events, without holding other
  cursors, and every reply carries `postBatchResumeToken`.
- **Limits.** Dropping a collection or database logs one `delete` per document rather than a
  `drop`/`invalidate` event; `replace` is reported as `update`; a token older than the kept log
  resumes from the oldest kept event instead of failing with `ChangeStreamHistoryLost`; drivers
  open streams only on a replica set, so `--mongo-replica-set` (D566) is needed.
