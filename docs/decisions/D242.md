## D242 KQL pipelines translated to SQL by `eggdb-kql` — Decided by the build loop (by judgement, 2026-10-31); refines D10 and D49

Track 4.X-14 asks for KQL, SPL, Excel formulas, Dataverse and mainframe data. This slice does
KQL, the query language people know from Azure Data Explorer and Log Analytics.

- **A translator, not a second engine.** `eggdb-kql` turns a KQL pipeline into one SQL query,
  each operator wrapping the previous stage as a subquery, so KQL runs on the same tables,
  indexes, transactions and permissions as SQL (D2). The crate has no dependencies and no access
  to storage; `eggdb sql --kql` translates the text and runs the result as PostgreSQL-dialect
  SQL.
- **Identifiers are always quoted** and string values always become SQL literals with quotes
  doubled, so nothing in a KQL query can end the SQL it is placed in. `contains`, `has`,
  `startswith` and `endswith` escape `%`, `_` and `\` before becoming `ILIKE` patterns, and are
  case-insensitive as in KQL. `has` matches a substring rather than a whole term until full-text
  terms (M8) back it.
- **Refuse rather than guess.** An operator, function or argument count the translator does not
  know is an error naming it, never a best-effort query. Nesting is capped at 64 levels so
  hostile input cannot exhaust the stack (D9).

Left: `join`, `union`, `let`, `parse`, `mv-expand`, `make-series`, `render`, percentiles and the
rest of KQL's functions; a Kusto-compatible REST endpoint; SPL; Excel formulas; the Dataverse
Web API; mainframe data (EBCDIC, COBOL copybooks, packed decimal, VSAM and IMS exports).
