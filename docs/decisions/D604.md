## D604 LISTAGG (DISTINCT ...) OVER — Decided by the code-only session (2026-11-12, D355); roadmap M10, D332, D453

Oracle 19c lets `LISTAGG` drop repeated values in its analytic form too:
`LISTAGG(DISTINCT name, ',') WITHIN GROUP (ORDER BY name) OVER (PARTITION BY dept)`. D453 gave
`DISTINCT` to the other window aggregates through the window call's value treatment. `LISTAGG`
has its own parser, which still refused the combination.

- `LISTAGG`'s analytic form now builds its whole-partition `ARRAY_AGG` window call through
  `whole_partition_call_treated`, with `ValueTreatment::distinct` set when `DISTINCT` was given.
  Plain `whole_partition_call` keeps its signature and passes the default treatment.
- The evaluator's distinct path (D453) feeds the aggregate only the first row of each distinct
  value. The `WITHIN GROUP` order sorts the partition first, so each value appears once, in that
  order.
- A test lists `a,b` for every row of a department holding `b`, `a`, `b`.
- Not done: `KEEP (DENSE_RANK FIRST|LAST ORDER BY …)` after `LISTAGG`. Oracle documents `KEEP` for
  `MIN`, `MAX`, `SUM`, `AVG`, `COUNT`, `VARIANCE` and `STDDEV` (D332 built those), and its
  reference does not list `LISTAGG` among them. The roadmap entry is narrowed to note that.
