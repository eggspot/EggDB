## D618 MySQL's information_schema.TRIGGERS — Decided by the code-only session (2026-11-12, D355); roadmap M10, D199, D420

`information_schema.TRIGGERS` existed with eight columns and no rows. mysqldump's
`--triggers` check, Laravel's and Doctrine's schema tools, DBeaver and MySQL Workbench read it to
list and diff a table's triggers.

- The view now has MySQL 8's columns: catalog, schema and name; `EVENT_MANIPULATION`; the event
  object's catalog, schema and table; `ACTION_ORDER`, `ACTION_CONDITION` (NULL),
  `ACTION_STATEMENT`, `ACTION_ORIENTATION` (`ROW`), `ACTION_TIMING`; the reference tables (NULL)
  and rows (`OLD` and `NEW`); `CREATED` (NULL, as EggDB does not record it), `SQL_MODE`,
  `DEFINER`, and the character set and collations.
- Rows come from the catalog snapshot's triggers that the MySQL dialect created, one row per
  event.
  - The schema is the database for `public`, as the other MySQL views show it.
  - `ACTION_ORDER` counts the triggers of the same table, timing and event in creation order, as
    MySQL numbers them.
  - `ACTION_STATEMENT` is the trigger's text after `FOR EACH ROW`.
- `SQL_MODE` shows MySQL 8's default, which is the mode EggDB's MySQL dialect follows. `DEFINER` is
  the session user at `%`.
- A MySQL-dialect test lists a `BEFORE INSERT` trigger with its order and statement.
