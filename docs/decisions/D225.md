## D225 Leaderless quorums with version vectors for multi-primary writes — Decided by the build loop (by judgement, 2026-10-31); refines D4 and D18

Part 4.M18-1 asks for multi-primary replication and leaderless quorums, checked by simulation
with conflict resolution.

- **Leaderless, as Amazon's Dynamo paper describes it.** `eggdb_cluster::quorum` puts each key
  on the first `n` nodes of its rendezvous-hash order. Any reachable node coordinates a write,
  so every node is a primary; a write succeeds once `w` replicas hold it, and a read asks `r`.
  Rendezvous hashing needs no ring of virtual nodes, and moves only the keys of a node that
  joins or leaves.
- **Version vectors decide what supersedes what.** A write carries the vector of what its
  client read, plus one write by its coordinator. A replica drops the versions a new one
  descends, and ignores one it already has a successor of. Concurrent versions are resolved by
  the key's policy: **last writer wins** on a hybrid-clock stamp (milliseconds, counter, node),
  keeping the merged vector, so nothing concurrent comes back; or **siblings**, kept side by
  side until a write whose context read them all replaces them (a shopping cart, a counter
  merged by the application).
- **Availability through failures**: a write whose home replica is unreachable goes to the next
  node in the key's order with a hint, handed off when the home returns (sloppy quorum). A read
  repairs the replicas it found behind. Anti-entropy brings every home replica of every key to
  the same versions.
- **Checked by simulation**: forty seeds per policy of random writes, reads, partitions and
  hand-offs, then healing. Every key's home replicas end with identical versions, and every
  acknowledged write is still there or superseded by a version that descends it.

Left: the network transport and wiring under `eggdb serve`; Merkle trees for anti-entropy
instead of full comparison; CRDT data types (counters, sets) as resolution policies; row-level
multi-primary for SQL tables, with conflict rules per table; deletion tombstones collected after
every replica has seen them; and membership changes with the epoch scheme of D212.
