## D528 Change delivery retries with backoff and a dead-letter table — Decided by the code-only session (2026-11-11, D355); roadmap M14

The server's change deliveries (`--cdc-webhook`, `--cdc-queue` and `--cdc-topic`) now retry a
refused change with exponential backoff and, after repeated failures, set it aside, so one bad
event or a target that is down for a while no longer resends every second or blocks forever.

- **Backoff:** after the oldest change is refused, its target waits 1 s, then 2, 4, 8 ... up to
  5 minutes between attempts; a success resets it. The state is kept per target in
  `eggdb_cdc.delivery_state` (created on first delivery), so it survives restarts and each
  target backs off on its own.
- **Dead letters:** a change refused 10 times in a row moves, with its Debezium event and its
  target, to `eggdb_cdc.dead_letters`, and the changes after it flow again. Operators read the
  table with SQL and resend or delete rows themselves.
- **Unchanged:** `eggdb_sql::cdc::deliver_changes` keeps its behaviour (no waiting), and
  delivery stays in order and at least once.
- **Left out:** Debezium's `schema` section and transaction metadata, and change capture
  without triggers.

**Status:** code written, unbuilt (code-only mode, D355).
