## D855 FIPS mode for logins and `serve --fips` — Decided by the code-only session (2026-11-12, D355); follow-up of D812

- `eggdb serve --fips` turns on FIPS mode, as `EGGDB_FIPS=1` already did for TLS (D812); either one is enough. The
  TLS setup and the MySQL listener read the same `fips_requested` check.
- In FIPS mode the MySQL listener does not run `mysql_native_password`, which rests on SHA-1. A client that names it
  (or names no plugin) gets an auth switch to `caching_sha2_password` with a fresh nonce, and its answer is checked by
  the SHA-256 fast path; a client without `CLIENT_PLUGIN_AUTH`, which cannot switch, is refused with error 1045 and a
  message that names the reason. Logins are audited under the method that ran.
- Other listeners need nothing here: PostgreSQL logins use SCRAM-SHA-256, TDS and stored roles send the password over
  TLS, and the password hashes kept at rest (SCRAM, PBKDF2-SHA-256) are FIPS-approved. MD5 stays only where a format
  needs it as a checksum (not for security), which FIPS allows.
- Left: a validated-module claim, which needs a CMVP certificate.
