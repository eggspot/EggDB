## D545 Kafka ListGroups, DescribeGroups and DeleteGroups — Decided by the code-only session (2026-11-11, D355); roadmap M16

`kafka-consumer-groups.sh --list`, `--describe` and `--delete`, and the admin clients' group
calls, need three more requests beside the coordinator of D525.

- **ListGroups** (versions 0 to 2) lists every group the coordinator holds in memory, with its
  protocol type. A group that only has committed offsets in the file (no members since the server
  started) is not listed, since the coordinator does not scan the offsets for it; DescribeGroups
  and OffsetFetch still answer for it by name.
- **DescribeGroups** (versions 0 and 1) gives each group's state as Kafka names it (`Empty`,
  `PreparingRebalance`, `CompletingRebalance`, `Stable`, and `Dead` for a group it does not know),
  protocol type, chosen protocol, and each member's id with its protocol metadata and assignment
  once the group is stable. Members whose session timed out are dropped first, as Heartbeat does.
  The coordinator does not record client ids or hosts, so those fields are empty.
- **DeleteGroups** (versions 0 and 1) refuses a group that still has live members with
  `NON_EMPTY_GROUP` (68), removes the group and every offset it committed otherwise, and answers
  `GROUP_ID_NOT_FOUND` (69) when there was neither.
