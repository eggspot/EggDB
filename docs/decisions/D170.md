## D170 An LSM tree made of B+trees, with bounded merge steps, in the storage engine first — Decided by the build loop (by judgement, 2026-10-31); refines D77 and D86

Part 4.M2-4 asks for an LSM storage option for write-heavy data. Research on 2026-10-31 asked for
new engines to be added behind switches, not swapped in. The storage engine has a no-steal page
cache (D79): every page a write transaction changes stays in memory until the commit. That rules
out the usual LSM, whose compactions rewrite gigabytes in one go. So:

- **Components are B+trees.** Writes go to a small *delta* tree. Once it holds 16,384 writes it
  becomes an immutable *run* as it stands, with nothing copied, and a new empty delta takes its
  place. Reads look in the delta and then in the runs, newest first; scans merge every component
  in key order, newest winning. Deletes are tombstones.
- **Merges move in bounded steps.** Once there are more than eight runs, a merge of all of them
  into one new tree starts. Every write moves it forward by at most 256 entries: the merge reads
  past its resume key in every source and appends to the target. Readers ignore the target
  until the last step, which swaps it in for its sources and frees their pages in the same
  transaction. So readers always see the sources' merged view or the finished target, and a
  write transaction never holds more than a step's pages. A merge that includes the oldest run
  drops tombstones.
- **No new page type.** The manifest is a B+tree too (format.md "Keys and trees"), so commits,
  the log, checkpoints, crash recovery and snapshot readers treat an LSM tree like any other
  tree. It is still reviewed as a storage change (D35), because a damaged manifest must be an
  error, never a panic.
- **First in the storage engine.** `LsmTree` and the transactions' `lsm_*` methods come first,
  with a model test against a map, a snapshot test across merges, a crash test, and the
  `lsm.random_put` benchmark: commits of 100 random puts into 100,000 entries, against a B+tree.
  Choosing it for a table or collection (`WITH (storage = lsm)`, `Options`) comes next. It needs
  catalog support for trees other than the one the file is rooted at, and a feature flag, so an
  older release refuses a file it cannot read.
