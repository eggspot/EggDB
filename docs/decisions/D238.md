## D238 BI starts with scheduled reports and alerts, delivered like change events — Decided by the build loop (by judgement, 2026-10-31); refines D46

Track 4.X-10 asks for our own BI application: dashboards, reports, a semantic layer, scheduled
reports and alerts.

- **Reports and alerts need no screen.** `CREATE EXTENSION eggdb_bi` keeps named queries in
  `eggdb_bi.reports (name, query, target, only_when_rows)`. `eggdb_bi.run_report(name)` runs one
  and queues `{report, rows, count, text}` as JSON for its target. An *alert* is a report that
  queues only when its query returns rows. Scheduling is pg_cron (D200):
  `cron.schedule('low-stock', '*/5 * * * *', $$SELECT eggdb_bi.run_report('low-stock')$$)`.
  The `text` field gives chat webhooks a line to show.
- **Delivery works like change capture (D210)**: `eggdb serve` posts queued messages, oldest
  first, at least once, to `http://` targets whose prefix `EGGDB_REPORT_TARGETS` allows.
  Nothing is sent when that variable is unset, because a target is a URL any user who can write
  the table could aim the server at. A message whose target is not allowed is dropped, so it
  cannot block the queue.

Left: dashboards and charts with their Fable design, the semantic layer (named measures and
dimensions over tables), report formats beyond JSON (CSV, HTML, PDF), `https://` targets and
email, sharing and embedding.
