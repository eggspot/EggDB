## D1074 JMAP push — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D56, D894)

- The account's state per type (`Email`, `Mailbox`, `Thread` from the store's state, `EmailSubmission`
  from the count of submissions) is reported as RFC 8620 §7.1's `StateChange`, optionally limited to the
  `types` asked for.
- **EventSource** (`/jmap/eventsource`, RFC 8620 §7.3) is now answered as a streamed response
  (`text/event-stream`), through the HTTP layer's streamed replies:
  - The JMAP listener moved to `serve_replies_with_limits`, and `Endpoint::reply` streams this one path and
    answers every other request whole, as before.
  - The stream sends a `state` event, with the state fingerprint as its `id`, when it starts and each time
    the state moves (checked every second). A reconnecting client's `Last-Event-ID` suppresses a repeat.
  - `closeafter=state` ends the stream after the first change.
  - `ping=N` sends `ping` events every N seconds, clamped to 5–300.
  - A stream ends after 15 minutes, and EventSource clients reconnect on their own.
- **PushSubscription** (RFC 8620 §7.2):
  - `PushSubscription/set` creates subscriptions with a `deviceClientId`, an `http`/`https` URL, `types`
    and `expires` (at most 7 days ahead). At most 100 are kept.
  - It sends the `PushVerification` with a 128-bit random code, and marks the subscription verified when the
    client sends the code back in an update. A wrong code is refused.
  - `types` and `expires` may change, and destroy removes a subscription.
  - `PushSubscription/get` never shows the URL, as the RFC asks.
  - `eggdb serve` runs `Endpoint::run_push` beside the JMAP listener. It POSTs a `StateChange` to every
    verified, unexpired subscription whose last delivered state differs, retrying on the next check until the
    push service answers 2xx, and removes expired subscriptions.
  - POSTs go through `eggdb_http::post`, which checks `https` certificates.
- Left: encrypted push (`keys`, RFC 8291's aes128gcm). Subscriptions that give keys are refused with
  `invalidProperties` until then. Also left: TLS for SMTP, IMAP and JMAP.
- Learned from: RFC 8620 and the HTML EventSource specification. No server source was read.
