## D1198 SCIM 2.0 provisioning of roles — Decided by the code-only session (2026-11-17, D355); roadmap M6b (D54); security-critical (D35)

- **What users get.** The REST listener serves SCIM 2.0 (RFC 7643, RFC 7644) at `/scim/v2`, so an identity provider (Entra ID, Okta, OneLogin, Keycloak) keeps EggDB's roles in step with the company directory: `Users` (`userName`, `externalId`, `active`, `password`) and `Groups` (`displayName`, `externalId`, `members`) with `GET` (one, or a list with an `attribute eq "value"` filter on `userName`, `displayName`, `id` or `externalId`), `POST`, `PUT`, `PATCH` (`active`, `password`, `externalId`, and `add`, `remove` and `replace` of `members`, including `members[value eq "id"]`) and `DELETE`, and `ServiceProviderConfig`.
- **The role model.** A SCIM user is a stored role with `LOGIN`, which `active: false` takes away; a group is a role without it, and its members are role members, so a group's table grants reach its members (D183). A role's id is its name (letters, digits, `_`, `.`, `@` and `-`, at most 63 bytes, quoted), which SCIM never renames. Which roles SCIM made, their kind and their `externalId` live in a table `eggdb_scim.resources`, made on the first call; roles made by SQL are not listed.
- **Who may call it.** Only the server's own user (HTTP Basic, as the REST listener's other administrative calls); a role's token gets `403`. Each change runs as one transaction of `CREATE ROLE`, `ALTER ROLE`, `GRANT`, `REVOKE` and `DROP ROLE`, so a refused step changes nothing; SQL errors become SCIM errors (`409 uniqueness` for an existing role, `404` for a missing one, `400` otherwise).
- **Left.** Bulk operations, sorting and paging (`startIndex` and `count`), filters beyond one `eq`, the enterprise user extension, `/Schemas` and `/ResourceTypes`, and a bearer token of its own for the provider. The LDAP v3 server and MS-ADTS stay on the roadmap item.
- **Proof.** A unit test creates a user and a group with it as member, finds the user by `externalId`, deactivates it, removes it from the group by a filter path, and deletes both.
- **Security review.** As a D35 change it needs a security-only review pass once built: that only the server user reaches it and that names cannot carry SQL.

**Status:** code written, unbuilt (code-only mode, D355).
