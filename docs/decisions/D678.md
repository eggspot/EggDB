## D678 Metrics points deduplicated by series and time, and tags told apart from string fields — Decided by the code-only session (2026-11-12, D355); roadmap M16, InfluxQL and line protocol (D220, D521)

- Every write records each measurement's tag keys in `metrics_meta.tag_keys (measurement, tag_key)`. `catalog`
  reports a string field's `text` column as `string`, so only tag columns are `text`: `SHOW TAG KEYS`,
  `SHOW FIELD KEYS` (field type `string`), `GROUP BY *`, and Prometheus labels and metric names now tell them apart.
  A measurement written before this change has no recorded keys; its first write records all its `text` columns as
  tags, which is how they were read before.
- Tag columns are `text NOT NULL DEFAULT ''`: a point without a tag stores `''`, which InfluxDB treats the same as
  the tag being absent. Older tag columns get `''` in place of `NULL` and the same default. Empty labels are dropped
  when Prometheus series are read back.
- A unique index `<measurement>_series` on `time` and every tag column (rebuilt when a tag key appears) lets each
  insert be `ON CONFLICT DO UPDATE SET field = COALESCE(EXCLUDED.field, field)`: a point with the same measurement,
  tag set and time replaces the fields it carries and keeps the others, as InfluxDB does. Points that collide within
  one write are merged before the insert, the later fields winning.
- The schema, columns, tag keys and index are made before the write's transaction. If the index cannot be made
  (an older table already holds duplicate points), that measurement is written without deduplication, as before.
