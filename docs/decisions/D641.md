## D641 Reading compressed Arrow batches — Decided by the code-only session (2026-11-12, D355); roadmap M11, D240, D573, D640

Feather 2 files are LZ4-compressed by default (`pyarrow.feather.write_feather`), and
`pyarrow.ipc.new_file(..., options=IpcWriteOptions(compression='zstd'))` is common for larger
exports. D573's reader refused every compressed batch.

- A record batch's or dictionary batch's `BodyCompression` (slot 3) names its codec,
  `LZ4_FRAME` (0) or `ZSTD` (1), with the `BUFFER` method; any other codec or method is damage.
- Each buffer then starts with its uncompressed length as a little-endian `i64`:
  - `-1` means the rest is stored as it is;
  - an empty buffer stays empty;
  - otherwise the rest is decompressed to exactly that length, at most 256 MiB per buffer.

  The batch's buffers become owned when decompressed (`Cow`), and decoding is unchanged.
- The codecs are EggDB's own, from `eggdb-storage`:
  - the RFC 8878 Zstandard decoder (D357), now public as `decompress_zstd`;
  - a new LZ4 frame decoder, `decompress_lz4_frame`, over the LZ4 block decoder.

  The frame decoder reads the magic, version, block size, optional content size, linked or
  independent blocks (stored or compressed), and the end mark. It skips the optional block and
  content checksums, and refuses frames that need a dictionary. The block decoder now appends to
  the frame's output, so a linked block's matches can reach into earlier blocks. The block
  function D357 used keeps its checks.
- `eggdb-arrow` now depends on `eggdb-storage`.
- Tests:
  - an LZ4 frame with two compressed blocks, a stored block and a content checksum, with every
    truncation an error;
  - Arrow streams compressed with ZSTD (a raw-block frame) and with LZ4 (a stored-block frame);
  - an unknown codec, and a buffer that is not a frame.
