## D392 Ledger tables refuse `TRUNCATE` and `DROP TABLE` — Decided by the code-only session (2026-11-10, D355); roadmap M6b, closes one of D236's leftovers

D236's ledger tables refused `UPDATE` and `DELETE` with row triggers, but `TRUNCATE` emptied them
and `DROP TABLE` removed them with their chain still listed.

- **`TRUNCATE`**: `eggdb_ledger.protect` now also creates a `BEFORE TRUNCATE ... FOR EACH STATEMENT`
  trigger running `eggdb_ledger.refuse()`, so `TRUNCATE` fails with `55000` like an `UPDATE`.
  Tables protected before this decision lack the trigger; running `protect` again is refused
  because the columns exist, so the build pass may add an upgrade step that creates it.
- **`DROP TABLE`**: no trigger fires on `DROP`, so `execute::drop_tables` asks the ledger
  (`ledger::refuse_dropping`) whether `eggdb_ledger.chains` lists the table, and refuses with
  `55000 table <schema>.<name> is a ledger: it can never be dropped`. Without the extension the
  check costs one catalog lookup.

**Status:** code written, unbuilt (code-only mode, D355).
