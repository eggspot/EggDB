## D1258 DBMS_METADATA synonyms and role grants — Decided by the code-only session (2026-11-18, D355); roadmap M4 Oracle packages (D859, D1254)

- **What users get.** `DBMS_METADATA.GET_DDL('SYNONYM', name[, owner])` writes `CREATE OR REPLACE EDITIONABLE SYNONYM "OWNER"."NAME" FOR "OWNER"."TARGET";`, and with the owner `'PUBLIC'` a `CREATE OR REPLACE PUBLIC SYNONYM` statement, as Oracle's export and schema-compare tools read them. `GET_GRANTED_DDL('ROLE_GRANT', grantee)` writes one `GRANT "ROLE" TO "GRANTEE"` per role the grantee is a member of.
- **How.** The catalog snapshot loads the stored synonyms (one scan of the synonym key space, private ones first) next to the roles; an unqualified name belongs to the session user, as Oracle shows it. A public synonym is found only when the owner `PUBLIC` is given, as in Oracle.
- **Left.** `SYSTEM_GRANT`, until EggDB's Oracle dialect keeps system privileges of its own; `UTL_FILE`.
- **Proof.** The `DBMS_METADATA` Oracle test reads a role grant, a private and a public synonym, and refuses the public synonym without its owner.
