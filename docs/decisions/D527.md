## D527 Change streams into Kafka topics — Decided by the code-only session (2026-11-11, D355); roadmap M14

`eggdb serve --cdc-topic <name>` delivers the changes `eggdb_cdc` captures into a Kafka topic, as
`--cdc-queue` delivers them into a durable queue for AMQP, STOMP and SQS consumers (D217) and
`--cdc-webhook` posts them (D210).

- **Records:** each Debezium-style JSON event becomes one record of its own batch (magic 2,
  CRC-32C, no key, the delivery time as its timestamp) appended to partition 0, oldest first,
  once a second, up to 100 events a round, at least once: an event is marked delivered only after
  its append commits. The topic is created with one partition and no retention limit when it is
  missing, in the same keyspace `--kafka-listen` serves, so Kafka consumers (with consumer groups,
  D525) read it, and it survives restarts with the file.
- **Where:** `eggdb-kafka` gains a public `publish` (and `valid_topic_name`, which the option
  checks), so the server's own producers write through the same log code as `Produce`.
- **Left out:** record keys from the primary key, several partitions by key, and delivery into
  MQTT topics and NATS subjects.

**Status:** code written, unbuilt (code-only mode, D355).
