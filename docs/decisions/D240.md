## D240 More dialects start with Arrow, the format their engines exchange — Decided by the build loop (by judgement, 2026-10-31); refines D10, D29 and D47

Track 4.X-12 asks for GoogleSQL, Snowflake, Spark SQL, ClickHouse, Trino, Db2 and Sybase SQL
each run as itself, and the Arrow Flight SQL protocol.

- **A dialect is not a slice.** Each SQL dialect in EggDB is a `Dialect` with its own lexer
  rules, statements, functions, errors and catalog (269 places name Oracle's alone), so each new
  one is its own milestone-sized part. Shared features (`QUALIFY`, which Snowflake, GoogleSQL
  and Spark SQL have) need a stage after window functions in the executor, which is planned
  with the first of them.
- **What every one of them shares is Arrow**: Spark, Snowflake, Trino, ClickHouse, DuckDB and
  Flight SQL all exchange columns as Apache Arrow. `eggdb-arrow` writes the Arrow IPC streaming
  format with our own FlatBuffers encoding: a schema, one record batch, the end marker. It
  covers booleans, 32- and 64-bit integers, single and double floats, UTF-8, binary, dates,
  microsecond timestamps (UTC when the column is), and 128-bit decimals.
  `eggdb export --table <t> --arrow <file>` writes it, and CI reads it back with pyarrow. Arrow
  Flight SQL is this format over gRPC, so it comes with our own HTTP/2 and gRPC (D34).

Left: the seven dialects, each as its own part; `QUALIFY`; Arrow IPC reading and the file format
