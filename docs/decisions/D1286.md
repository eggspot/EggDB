## D1286 Row factories and eggdb.Row in the Python driver — Decided by the code-only session (2026-11-18, D355); roadmap M6 drivers (D957, D1285)

- **What users get.** `connection.row_factory` and `cursor.row_factory` work as in Python's `sqlite3`: a callable `(cursor, row)` that makes each fetched row, applied by `fetchone`, `fetchmany`, `fetchall` and iteration, the cursor's winning over the connection's. `eggdb.Row` is the ready-made one: read by position, slice or column name in any case, with `keys()`, length, iteration, equality and hashing, as `sqlite3.Row`.
- **How.** The cursor keeps its rows as tuples and makes each one only as it is handed out, so a query read without a factory costs what it did.
- **And asyncio.** `eggdb.aio`'s connection gains `create_function`, `executescript`, `in_transaction` and `row_factory`, the functions running on the connection's worker thread like its statements.
- **Left.** `Connection.text_factory`, and factories for `Statement.rows`.
- **Proof.** A Python test reads a row by position and by name in two cases, lists its keys, and uses a cursor's own factory over the connection's.
