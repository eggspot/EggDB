## D239 Connectors start from the protocols EggDB speaks, proven by a compatibility job — Decided by the build loop (by judgement, 2026-10-31); refines D44 and D46

Track 4.X-11 asks for our own ETL/ELT pipelines and change capture, and connectors for Spark, an
Iceberg REST catalog, Kafka Connect, Trino, dbt, Airbyte, Power BI, Tableau and Grafana, each in
the tool's own plugin system.

- **Most of those tools already reach EggDB** through the PostgreSQL protocol, the Prometheus API
  or the S3 and Kafka protocols. `docs/connectors.md` says how each connects today, so users
  start now, and lists which is checked.
- **Checked, not claimed.** The new `compatibility` CI job runs the real tools against
  `eggdb serve`, starting with dbt (`dbt-postgres`: `debug`, `run`, `test` on a model and its
  schema tests), and writes a pass/fail table to the run's summary. It reports rather than
  gates, because a third-party tool's new release must not block unrelated work. It is the
  first column of D44's compatibility matrix, and each fix it prompts gets a gating test of its
  own.
- **Pipelines are SQL already**: `eggdb_foreign` (D229) to read, `pg_cron` (D200) to schedule,
  change capture (D210) and reports (D238) to send out.

Left: native connectors in each tool's plugin system (a dbt adapter, a Spark data source, a
Trino connector, Kafka Connect source and sink, an Airbyte connector, Power BI and Tableau
connectors, a Grafana plugin), an Iceberg REST catalog over Parquet (D202), more tools in the
compatibility job, and a published matrix.
