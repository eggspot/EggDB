## D440 JsonLogic targeting and fractional rollouts for feature flags — Decided by the code-only session (2026-11-11, D355); roadmap M15, extends D247

- **`eggdb_jsonlogic(rule jsonb, data jsonb) RETURNS jsonb`** (`jsonlogic.rs`) applies a
  JsonLogic rule as jsonlogic.com documents the operations: `var` (dotted paths, array indexes,
  defaults), `missing`, `missing_some`, `if`/`?:`, `==` and `!=` (JavaScript's loose equality),
  `===`, `!==`, `!`, `!!`, `and`/`or` (returning the deciding value), `<`, `<=` (with the
  three-argument "between" form), `>`, `>=`, `in` (arrays and strings), `cat`, `substr`, `+`, `-`,
  `*`, `/`, `%`, `min`, `max`, `merge`, and `map`, `filter`, `reduce`, `all`, `none`, `some`.
  Truthiness is JsonLogic's (`[]`, `""`, `0` and `null` are false). A rule is bounded: 128 levels
  of nesting, 100,000 items per iteration and a step budget, so a hostile rule can't run away.
- **flagd's additions**, so flagd's flag definitions run unchanged: `starts_with`, `ends_with`,
  `sem_ver` (`=`, `!=`, `<`, `<=`, `>`, `>=`, `^` same major, `~` same minor; pre-releases sort
  before their release) and `fractional`, which buckets by the 32-bit MurmurHash3 (seed 0) of the
  given key, or of the flag key followed by the `targetingKey`, scaled to 0-100 and split by the
  buckets' weights, as flagd computes it, so a user lands in the same variant on every call and on
  flagd and EggDB alike.
- **`eggdb_coordination.evaluate_flag`** now takes a JsonLogic object in `targeting` (D247's array
  of "attribute in list" rules still works): the rule runs over the evaluation context with
  flagd's `$flagd` object (`flagKey`, `timestamp`) added, and a result naming one of the flag's
  variants is a `TARGETING_MATCH`; anything else falls to the default variant. Installations made
  before this keep their function until the extension is created again.
