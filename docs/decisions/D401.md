## D401 Index lists and patterns in Elasticsearch URLs — Decided by the code-only session (2026-11-10, D355); roadmap M8, closes one of D331's leftovers

`<index>/_search`, `_count`, `_update_by_query` and `_delete_by_query` took one index name. They
now take Elastic's multi-target syntax in that path segment (`api::resolve_indices`): a comma
list, `*` wildcards (`logs-*`), `_all`, and `-pattern` to drop what earlier parts matched (only
after something matched, as Elastic reads a leading `-` as a name). A named index that does not
exist is `404 index_not_found_exception` unless `ignore_unavailable=true`; a pattern that matches
nothing is no error. The by-query APIs run over each index in turn and add up their counts,
batches and failures in one report; `max_docs` limits each index's run, where Elastic limits the
whole request (a known difference, noted for the build pass).
