## D706 File readers take their columns from the file — Decided by the code-only session (2026-11-12, D355); roadmap M11, the file readers in SQL (D703–D705)

- `read_parquet(path)`, `read_arrow(path)` and `read_csv(path)` no longer need a column definition list when the path
  is a string literal: the parser reads the file through the session's file reader and supplies the definition
  list itself, as if the query had written one. `SELECT * FROM read_parquet('events.parquet')` returns the file's
  columns with their names and types.
- Types: Parquet's and Arrow's booleans, 32- and 64-bit integers, floats, doubles, text, binary, dates, timestamps
  (with time zone when the file marks them UTC) and decimals with their precision and scale; every column of a CSV
  file is `text`, named by its header.
- A written definition list still wins, so a query can pick, rename-by-match or retype columns. A path that is not a
  literal (a parameter, a column) still needs a definition list. The file is read once to plan the query and again
  to run it; a statement prepared earlier keeps the columns it was planned with.
