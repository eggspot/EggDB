## D910 OData navigation properties and `$expand` — Decided by the code-only session (2026-11-12, D355); roadmap M6a, follow-up of D877

- The OData model now reads the schema's foreign keys. Each one gives the referencing entity type a single-valued
  navigation property, named after its column without `_id` when the key has one column ending in `_id`, else after
  the referenced table, and the referenced type a collection-valued one named after the referencing table, as the
  GraphQL API names its relationships (D875). A name that would clash with a property or an earlier navigation is
  skipped.
- `$metadata` declares them as `NavigationProperty` elements (with `ReferentialConstraint`s on the single-valued
  side) and binds them in the entity container with `NavigationPropertyBinding`.
- `$expand=a,b` (or `*`) on a collection or an entity adds each named navigation to every entity returned: the
  related entity or `null`, or the array of related entities. Each navigation is read with one query for the whole
  page (the distinct key values joined by `OR`), not one per row, and `$select` still decides which properties of
  the entity itself are written. Options inside `$expand` (`$expand=books($select=title)`) answer 400 for now.
