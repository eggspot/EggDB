## D508 COBOL copybooks and EBCDIC records — Decided by the code-only session (2026-11-11, D355); roadmap M11

`eggdb import --copybook <layout.cpy> --ebcdic <records> --table <name>` loads a mainframe data set
into a SQL table, its columns taken from the copybook. COBOL's data division, EBCDIC code page 037
and the zoned, packed and binary number formats are public (ISO/IEC 1989 and IBM's published
references), so this needs no legal check.

- **Copybook:** fixed-format lines (sequence area, `*` and `/` comments in column 7, the program
  area to column 72) or free-format with `*>` comments. Level numbers build the tree; `PIC` with
  repeat counts, `USAGE` (DISPLAY, COMP, COMP-3, COMP-4, COMP-5, BINARY, PACKED-DECIMAL, COMP-1,
  COMP-2) inherited from groups, `OCCURS n` (repeated as `name_1`, `name_2`), `REDEFINES`
  (skipped, the first layout wins), `SIGN LEADING|TRAILING [SEPARATE]`, FILLER (skipped) and
  level 88 conditions (ignored). The first 01 level is the record; a copybook with none takes all
  its items in order.
- **Values:** text in code page 037, right-trimmed; zoned decimals with an embedded or separate
  sign; packed decimals; big-endian binaries, signed when the picture has `S`; IBM hexadecimal
  floats for COMP-1 and COMP-2. Numbers with scale 0 and at most 18 digits become `bigint`, others
  `DECIMAL(digits, scale)`; numbers of all spaces or all low-values are null; edited pictures are
  text. Names are lowercased with `-` as `_`.
- **Records:** fixed-length when the file is a whole number of records, else variable records each
  led by a record descriptor word (a big-endian length that includes the word, then two zero
  bytes); fields past a short variable record are null. At most 100 million values per import.
- **Left out:** `OCCURS DEPENDING ON` and `P` scaling (refused with a message), `SYNC` slack bytes,
  other EBCDIC code pages, ASCII-converted data sets, VSAM and IMS exports themselves.
