## D1117 EggDB's own allocator in the default build — Decided by the code-only session (2026-11-13, D355); roadmap M1 (EggDB's own allocator as the default build, D166)

- **What the benchmarks show.** `allocator.small_blocks egg_to_system_allocator` is 0.880 on Linux and 0.523 on
  macOS in `benchmarks/baseline.txt`: `EggAllocator` takes less time than the system allocator on both systems the
  `bench` job measures. Supersedes D166's "opt-in" in part.
- **The `eggdb` crate's default features now include `egg-allocator`,** so the `eggdb` binary, the release binaries
  and the container image install `EggAllocator` as the global allocator, and `serve --memory-limit` bounds every
  allocation (D1086). `--no-default-features` builds the binary on the system allocator; a library user is not
  affected, since only `main.rs` installs it.
- **CI's `egg-allocator` job becomes `system-allocator`**: it runs the tests and the smoke test of a
  `--no-default-features` build, so the build nobody ships by default is still checked, and `check` waits for it.
- Windows has no baseline line yet; the build-and-fix pass adds one from the `bench` job and records it here, and a
  line above 1.0 there turns the feature off for Windows targets.

**Status:** code written, unbuilt (code-only mode, D355).
