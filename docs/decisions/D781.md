## D781 OGC API - Features on the REST listener — Decided by the code-only session (2026-11-12, D355); roadmap M12, the OGC APIs (D57)

- `--rest-listen` serves OGC API - Features Part 1 (Core and GeoJSON conformance classes) under `/ogc/`: the landing
  page, the conformance declaration, the collections (each table of the served schema with a geometry column:
  declared `geometry` or `geography`, or named `geom`, `geometry` or `the_geom`), each collection's description, its
  items as a GeoJSON `FeatureCollection` and one item by id. GIS clients that speak OGC API - Features (QGIS, OpenLayers,
  Leaflet plugins) read EggDB's spatial tables without a separate map server.
- Items are SQL as the request's user (D235, D458), so grants and row-level security decide what a client sees. Each
  feature's geometry is `ST_AsGeoJSON`, its properties the row's other columns, and its id the `id` column when the
  table has one. `bbox` filters with `ST_Intersects` against an envelope in the geometry's own SRID; `limit` (10 by
  default, at most 10,000) and `offset` page, with a `next` link while more remain.
- The `crs` and `bbox-crs` parameters (Part 2), property filters and CQL2 (Part 3), the OpenAPI document of these
  paths, and OGC API - Tiles and Maps are left.
