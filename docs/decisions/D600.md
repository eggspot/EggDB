## D600 Transact-SQL IGNORE NULLS and named windows — Decided by the code-only session (2026-11-12, D355); roadmap M10, D427

D427 left two SQL Server 2022 features out of the Transact-SQL window functions: `IGNORE NULLS` on
the offset functions, and `ORDER BY` coming through a named window. Gap-filling queries over
sensor and price series use the first ("the last known reading"), and the second is how SQL Server
2022 shares one window between several calls.

- `FIRST_VALUE`, `LAST_VALUE`, `LAG` and `LEAD` take `IGNORE NULLS` or `RESPECT NULLS` after their
  closing parenthesis, as SQL Server writes it.
  - The parser reuses the null treatment the Oracle dialect already reads (`null_treatment`, now
    shared within the parser).
  - The call goes through a new `treated_window_call`, which hands the treatment to the window
    functions every dialect shares. Oracle's tests already cover their skipping of NULLs.
- Error 4112 (`OVER` without `ORDER BY`) is now raised only for an inline window that has neither
  an `ORDER BY` nor a base window.
  - `OVER w` and `OVER (w …)` name a window from the `WINDOW` clause, which every dialect parses,
    and that window's `ORDER BY` applies.
  - A named window without `ORDER BY` is not refused with 4112: a known difference, since its
    definition comes after the select list.
- A test checks that `LAG(v) IGNORE NULLS` carries the last non-NULL value across NULL rows, that
  `ROW_NUMBER() OVER w` follows `WINDOW w AS (ORDER BY id DESC)`, and that a partition-only
  `OVER` still gets 4112.
