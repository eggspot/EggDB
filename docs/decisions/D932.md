## D932 Key-value transactions and collections in the Node.js driver — Decided by the code-only session (2026-11-13, D355); roadmap M4, collections in the drivers (D292), follow-up of D930 and D931

- The addon gains `kvOpen`, `kvClose`, `kvBegin`, `kvEnd` (commit or roll back), `kvGet`, `kvPut`, `kvDelete`,
  `kvScan`, `kvCollection` (create, drop, rename, stats) and `kvCollections` on the C API. Store and transaction
  handles are N-API externals whose finalizers close the file and roll an unfinished transaction back, so a handle
  the program drops never leaks a write lock; values come back as `Buffer`s copied from the C API's buffers, which
  are freed at once.
- `new KeyValue(file, { readOnly })` offers `read(body)` and `write(body)`, `better-sqlite3`'s synchronous shape:
  `write` commits when `body` returns and rolls back when it throws. A `Transaction` has `get`, `put` (with
  `ttlMs`), `delete`, `scan({ start, end, prefix, reverse, endInclusive, collection })` (returning `[key, value]`
  pairs), `createCollection`, `dropCollection`, `renameCollection`, `collectionStats` (counts as `bigint`) and
  `collections`; keys and values are strings (UTF-8), `Buffer`s or `Uint8Array`s. The typings cover all of it.
