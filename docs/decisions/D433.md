## D433 Oracle synonyms — Decided by the code-only session (2026-11-11, D355); roadmap M10

- `CREATE [OR REPLACE] [PUBLIC] SYNONYM [schema.]name FOR [schema.]object` and `DROP [PUBLIC]
  SYNONYM [schema.]name [FORCE]` in Oracle's dialect. A synonym is a catalog record in a new key
  space, `SYNONYM_SPACE` (0x17, after the column grants' 0x16), keyed by the synonym's internal
  name, with a NUL byte before the name for a public synonym; the value is a version byte and the
  target's internal name. No table definition changes, so the file format needs no new version;
  an older release ignores the space it doesn't know.
- **Resolution.** In Oracle's dialect the name resolver tries a name as written first: when no
  table, view or sequence has it, the private synonym of that name, then the public synonym of its
  base name, gives the target, followed through chains of synonyms (16 at most; a loop is
  ORA-01775). Every statement that names a relation goes through the resolver, so queries, DML and
  DDL see the target. A synonym for an object that doesn't exist is allowed, as in Oracle, and
  fails where it is used.
- Oracle's errors: a private synonym named like an existing object, or an existing synonym without
  `OR REPLACE`, is ORA-00955; dropping a missing one is ORA-01434; a synonym for itself is
  ORA-01471. A target over a database link (`@link`) is refused until links exist. `FORCE` is
  accepted (EggDB has no dependent objects to keep valid). Left: synonyms in `ALL_SYNONYMS` and the
  other dictionary views, synonyms for routines and packages, and grants on synonyms.
