## D1069 Full FIX and EDIFACT dictionaries, loaded from the standards' own files — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D50, D243, D445)

- **Loaded, not shipped.** Retyping thousands of FIX tags and EDIFACT elements from memory would be wrong
  in places, and shipping the bodies' published files raises a redistribution question for each one. So
  EggDB reads the machine-readable files the standards publish, and the user loads them. The 85 built-in
  FIX tags and 41 EDIFACT segments of D445 stay as the fallback of `fix_tag_name` and
  `edifact_segment_name`.
- **New functions** (`crates/eggdb-sql/src/dictionaries.rs`):
  - `fix_dictionary(xml) → jsonb` reads a FIX data dictionary in the XML layout FIX engines exchange: `<fix
    type major minor servicepack>` with `<fields>` (number, name, type and `<value enum description>`),
    `<header>`, `<trailer>`, `<messages>` and `<components>`. It gives the version (`FIX.4.4`,
    `FIX.5.0SP2`), every field with its enumerations, and each message's layout. Components are inlined,
    and groups are nested with their counter tag, up to 32 levels; an undefined component is an error.
  - `fix_annotate(message, dictionary) → jsonb` names every field and gives the meaning of enumerated
    values. It nests each repeating group's `instances` by the layout of the message type in tag 35: an
    instance starts at the group's first field and ends at the next delimiter or the first tag outside the
    group.
  - `edifact_directory('segments' | 'codes', text) → jsonb` reads UNECE's text directories:
    - the segment directory (EDSD) gives each segment's tag and name, and its elements by position with
      code, name, status and repeat, plus a composite's components with their formats;
    - the code lists (UNCL) give each coded element's codes and names.
    - Change marks in column one are ignored.
  - `edifact_annotate(message, segments, codes) → jsonb` reads the message with `edifact_parse`, then names
    every segment, element and component and gives each code's meaning.
- **Extension `eggdb_dictionaries`:**
  - It keeps loaded dictionaries in the tables `fix_dictionaries(version, dictionary)` and
    `edifact_directories(directory, segments, codes)`.
  - `load_fix(xml)` and `load_edifact(directory, segment_directory [, code_lists])` load them.
  - `fix_describe(message [, version])` takes the version from tag 8 when none is given, and
    `edifact_describe(message, directory)` describes a message the same way.
- Inputs are limited to 64 MiB, layouts to 32 levels, and every reader returns errors as values (D9).
- Left: FIX Orchestra repository XML, EDIFACT element (EDED) and composite (EDCD) directories on their own
  (the segment directory already carries their names and formats), and ISO 20022 message schemas.
- Learned from: the public descriptions of the FIX data dictionary XML layout and of the UNTDID directory
  formats. No FIX engine or EDI library source was read.
