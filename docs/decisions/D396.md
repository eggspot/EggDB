## D396 Redis's `INFO` sections — Decided by the code-only session (2026-11-10, D355); roadmap M7

`INFO` answered three fields. Client libraries read `redis_version`, `role`, `maxmemory_policy`
and the `# Keyspace` lines (`db0:keys=...`), and dashboards read the rest. `INFO` now answers the
`Server`, `Clients`, `Memory`, `Persistence`, `Stats`, `Replication`, `CPU` and `Keyspace`
sections, all of them for no argument or `all`, `default` or `everything`, and only those named
otherwise (`INFO keyspace`, `INFO server clients`). The keyspace lines count each database's live
keys and those with an expiry (`avg_ttl` 0); the other sections give Redis's field names with
fixed values where EggDB keeps no such counter (`used_memory:0`, `total_commands_processed:0`,
`role:master`, `maxmemory_policy:noeviction`), so tools parse them. `blocked_clients` stays the
first field of `# Clients`, as D347's tests read it. Real counters (memory, commands, hits) need
server-wide statistics, left for later.
