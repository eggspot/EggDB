## D1288 PostgreSQL's array editing functions — Decided by the code-only session (2026-11-18, D355); roadmap M4 PostgreSQL arrays (D288, D977)

- **What users get.** `array_append`, `array_prepend`, `array_cat`, `array_remove`, `array_replace`, `array_position(array, value[, start])`, `array_positions`, `trim_array`, `array_reverse`, `array_dims` and `string_to_array(text, delimiter[, null_text])` for one-dimensional arrays, as PostgreSQL answers them: NULL elements are found and removed by `IS NOT DISTINCT FROM`, positions are subscripts from the array's lower bound, a NULL delimiter splits into characters and an empty one keeps the text whole, and `trim_array` past the length is 2202E. EggDB's own PL/pgSQL helpers (table sync, placement, multi-primary, the marketplace and the catalog's column lists) call `string_to_array`, which was not there, so those paths failed at run time.
- **How.** One function in `arrays.rs` beside the existing array functions, reached through the same dispatch, comparing elements with the engine's own `=`; result types follow the array argument (or the element for `array_append` and `array_prepend` onto NULL).
- **Later the same night.** PostgreSQL 16's `array_shuffle(array)` and `array_sample(array, n)` (a partial Fisher–Yates shuffle over the engine's random source, 22023 for a size past the length), and `random_normal(mean, stddev)` (D1289's module, Box–Muller).
- **Also.** `array_fill(value, ARRAY[n][, ARRAY[lower]])` for one dimension, its lower bound kept.
- **Left.** Multidimensional arrays (as before, `array_fill` with more than one dimension included).
- **Proof.** `arrays_tests.rs` builds, edits and searches arrays, splits text with a null marker and into characters, trims, reads the dimensions, refuses trimming past the length, and finds nothing as NULL.

**Status:** code written, unbuilt (code-only mode, D355).
