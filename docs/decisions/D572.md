## D572 Parquet files written with row groups and statistics — Decided by the code-only session (2026-11-12, D355); roadmap M11, D202

`eggdb export --parquet` wrote one row group with no statistics, so readers could neither read it
in parts nor skip any of it. `eggdb_parquet::write` now cuts the rows into row groups of up to
131,072 (`write_with_row_groups` takes another size), each column chunk one plain data page as
before, and gives every chunk its `Statistics`: the null count and `min_value`/`max_value` in the
value's plain encoding (a byte array without its length; a decimal over 18 digits as its 16
big-endian bytes), compared as Parquet's type-defined order says (signed integers and decimals,
unsigned bytes for text and binary, booleans false before true, floats by value with NaN left
out). The footer declares that order for every column (`column_orders`, `TYPE_ORDER`), which
readers require before they trust `min_value` and `max_value`. The deprecated `min`/`max` fields
are not written. Dictionaries, compression, page indexes and nested columns are later steps.
