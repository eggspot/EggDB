## D644 A Transact-SQL procedure called by its name alone at a batch's start — Decided by the code-only session (2026-11-12, D355); roadmap M10, D159

SQL Server runs `usp_nightly 5` as `EXEC usp_nightly 5` when the call is the first statement of
a batch. sqlcmd scripts, Agent job steps and old deployment scripts rely on it, and EggDB answered
with a syntax error.

- When the T-SQL statement dispatcher meets a first word it does not know, it reads a procedure
  call. This happens only in the batch's first statement (only `;` before it), as SQL Server
  allows. The word must also pass these checks:
  - it is not a reserved word or the first word of a T-SQL statement;
  - it is not one of the other statements the shared parser reads (`EXPLAIN`, `SHOW`, `VALUES`,
    `CALL` ...);
  - it is not a label;
  - it is not followed by `(`, `:` or an operator.

  The call is parsed exactly as after `EXEC`, through the shared `sqlserver_execute_call`.
  Schema-qualified names (`dbo.proc`), positional and named arguments and numbered procedures
  (D643) work.
- Later statements still need `EXEC`, as in SQL Server.
- Test: `a_procedure_named_first_in_a_batch_runs_without_exec`.
