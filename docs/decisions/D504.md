## D504 Bolt 5.1–5.4 `LOGON`/`LOGOFF` and `ROUTE` for `neo4j://` URLs — Decided by the code-only session (2026-11-11, D355); roadmap M13, D207

- The handshake picks the highest Bolt 5 minor version a driver offers up to 5.4 (5.0 and 4.4 as
  before). From 5.1 on, `HELLO` carries no credentials: it answers `server` and `connection_id`, and
  `LOGON {scheme: "basic", principal, credentials}` signs in with the same check as before (a
  failure ends the connection after the same pause); `LOGOFF` signs out, so the next request must
  be `LOGON` again. Bolt 5.0 keeps signing in through `HELLO`.
- `ROUTE` answers a routing table with this one server as writer, reader and router, at the
  address the driver gave in its routing context, a TTL of 300 seconds and database `neo4j`, so
  drivers connect with `neo4j://` URLs, not only `bolt://`. Bookmarks sent with `BEGIN` or `RUN`
  are accepted and ignored, since every committed write is visible to the next request.
- Explicit transactions spanning messages (`BEGIN` … `COMMIT` as one unit) stay open: each `RUN`
  still commits on its own (D207).
