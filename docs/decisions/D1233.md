## D1233 Oracle's ROWID pseudo-column in queries — Decided by the code-only session (2026-11-17, D355); roadmap M10, Oracle's `ROWID` (sql.md)

- **What users get.** In the Oracle dialect, `ROWID` in a query's select list, `WHERE` or `ORDER BY` gives each row an 18-character address in Oracle's extended form (six base-64 digits of the object number, three of the file, six of the block and three of the row, in Oracle's `A-Za-z0-9+/` alphabet), stable while the row stays, so `SELECT ... WHERE ROWID = :r` finds a row read before, as tools and ORMs written for Oracle do. `SELECT *` leaves it out, as Oracle does.
- **How.** The same generated-table path as PostgreSQL's system columns (D1170: `ctid`, `xmin` and the rest): when an Oracle query names `rowid`, the table is read with a hidden `rowid` column whose value comes from the table's OID and the same block and offset as `ctid` (the hidden row number, or a hash of the primary key). In the Oracle dialect only `rowid` is a system column; PostgreSQL's keep their dialect.
- **Left.** `UPDATE` and `DELETE ... WHERE ROWID = ...` (PostgreSQL's `ctid` rewrite of writes is not wired for Oracle), the `ROWID` and `UROWID` column types, `DBMS_ROWID`, and addresses that survive a row's primary key being changed.
- **Proof.** `dialect_plan_tests.rs`: two rows get distinct 18-character addresses in the alphabet, one is found again by its `ROWID`, and `SELECT *` does not show the column.
