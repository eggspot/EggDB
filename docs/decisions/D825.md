## D825 The authentication rule file on the MySQL listener — Decided by the code-only session (2026-11-12, D355); roadmap M6b, D185

- `eggdb serve --auth-rules` now also decides how stored roles log in over MySQL (`ServerConfig.auth_rules`), with
  the same lookup as PostgreSQL (`method_for_connection`: user, database and client address, D821). The served user
  (`--user`) keeps its own password, as on PostgreSQL.
- `scram-sha-256` checks the password against the role's stored verifier (D823); `ldap`, `jwt` and `apikey` take the
  password the same way (caching_sha2 full authentication or `mysql_clear_password`, over TLS, the local socket or
  loopback) and check it with that method, then require a stored role with `LOGIN`; `cert` accepts a TLS client
  certificate whose common name is the user; `reject` refuses; `oauth` is refused, MySQL clients having no
  `OAUTHBEARER`. Refusals answer error 1045 and are logged and audited.
