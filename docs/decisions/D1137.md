## D1137 Extended statistics: CREATE STATISTICS with ndistinct and dependencies — Decided by the code-only session (2026-11-14, D355); roadmap M5 (extended statistics, D40, D178, D786, D1136)

- **What users can do.** PostgreSQL's `CREATE STATISTICS [IF NOT EXISTS] name [(ndistinct, dependencies, mcv)] ON
  col, col [, ...] FROM table` and `DROP STATISTICS [IF EXISTS] name [, ...]`, with PostgreSQL's errors: at least two
  and at most eight columns, unknown columns `42703`, a duplicate `42710`, an unknown kind `22023`. With no kinds
  given, both kinds EggDB computes are kept. `mcv` is accepted and computes nothing yet.
- **Stored in the catalog.** Each object is a record in a key space of its own (`0x1A`): the table, the columns, the
  kinds, and what the last `ANALYZE` found. Dropping the table drops its objects.
- **What `ANALYZE` computes**, from the same row sample as the column statistics (D786):
  - `ndistinct`: the number of distinct value combinations of the columns;
  - `dependencies`: for every ordered pair of the columns, the degree to which the first decides the second. That is
    the rows of each group of equal first values that all share one second value, over all rows, as PostgreSQL
    defines it.
- **Where it is used.** The join-order estimates (D1136) combine equalities on two or more columns of one table with
  PostgreSQL's formula `P(a, b) = P(a) * (f + (1 - f) * P(b))` for the strongest recorded dependency `a -> b`, so a
  city and its country are no longer counted as independent filters that shrink the table twice. Learned from
  PostgreSQL's documentation of extended statistics.
- **Left:** `mcv` lists over column combinations, `ALTER STATISTICS`, the `pg_statistic_ext` and `pg_stats_ext`
  catalogs, array element statistics, and using `ndistinct` for `GROUP BY` estimates once group sizes drive plans.
