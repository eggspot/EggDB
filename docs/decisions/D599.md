## D599 MySQL's JSON error numbers — Decided by the code-only session (2026-11-12, D355); roadmap M10, D289, D425

D425 left `JSON_VALUE`'s and `JSON_TABLE`'s errors as SQL/JSON's SQLSTATEs under the general MySQL
error 1105. Applications and ORMs that catch MySQL's JSON errors by number (Laravel, Doctrine,
Hibernate's MySQL exception translators) saw an unknown error instead.

The MySQL translation (`mysql_errors::translate`) now maps:

| EggDB's error | MySQL number | SQLSTATE | Message |
|---|---|---|---|
| a JSON path syntax error (`42601`, "… jsonpath input") | 3143 `ER_INVALID_JSON_PATH` | 42000 | "Invalid JSON path expression. …" |
| `22032` invalid JSON text, and `22P02` for type `json` | 3141 `ER_INVALID_JSON_TEXT_IN_PARAM` | 22032 | "Invalid JSON text in argument 1: …" |
| `22034` more than one item | 3967 `ER_MULTIPLE_JSON_VALUES` | 22034 | MySQL's wording |
| `22035` no item (`ERROR ON EMPTY`) | 3966 `ER_MISSING_JSON_VALUE` | 22035 | MySQL's wording |
| `2203F` scalar required, `2203G` cannot cast | 3156 `ER_INVALID_JSON_VALUE_FOR_CAST` | 22018 | "Invalid JSON value for CAST: …" |

- Every other SQL syntax error keeps 1064.
- `SqlState` gains `INVALID_JSON_TEXT` (22032) and `INVALID_CHARACTER_VALUE_FOR_CAST` (22018).
- The numbers come from MySQL 8.0's error reference. MySQL's character position in 3143's
  message is not given, because the path parser reports the token, not the offset.
- `JSON_TABLE`'s errors of its own (a missing value or an array stored in a scalar column) map
  through the same SQLSTATEs as above, not to MySQL's `JSON_TABLE` numbers.
