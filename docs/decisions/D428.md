## D428 Oracle's `MODIFY col DROP IDENTITY` and `MODIFY col GENERATED ... AS IDENTITY` — Decided by the code-only session (2026-11-11, D355); roadmap M10 (item 37c)

- The refusals 37c names were already in place: a value for a `GENERATED ALWAYS` identity is
  PostgreSQL's `428C9`, which Oracle's error mapping shows as ORA-32795 on `INSERT` and
  ORA-32796 on `UPDATE`. What Oracle's dialect lacked were its `ALTER TABLE` forms.
- `ALTER TABLE t MODIFY id DROP IDENTITY` (also inside `MODIFY (...)`) is PostgreSQL's `ALTER
  COLUMN id DROP IDENTITY`; `ALTER TABLE t MODIFY id GENERATED {ALWAYS | BY DEFAULT [ON NULL]} AS
  IDENTITY [(options)]` changes an identity column's generation and its sequence options
  (`START WITH`, `INCREMENT BY`, `RESTART`, `CACHE` and the rest), as `ALTER COLUMN ... SET
  GENERATED` and `SET` options do. `ON NULL` is read as `BY DEFAULT` (EggDB does not yet replace an
  explicit `NULL` with the next value).
- Oracle can't make an existing column an identity, and neither does this: on a column that is
  not one, the change fails, shown as ORA-30673 ("column to be modified is not an identity
  column").
