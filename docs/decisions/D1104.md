## D1104 An edge server on archived copies: follows the manifest, swaps copies between queries, and evicts old copies — Decided by the code-only session (2026-11-13, D355); roadmap M18 (D227, D226)

- **What it serves.** `eggdb serve --edge-of s3://bucket/prefix` serves read-only the newest copy `eggdb backup` archived there, through the edge cache of D227 (copies named by their SHA-256, checked before use). It needs nothing from the primary and can run in any region, scaled to as many servers as readers need.
- **Refreshed as the manifest grows.** Every 30 seconds the server reads the manifest. When a newer copy is listed, it downloads it and moves to it with `Database::switch_to_copy`, which puts the store over the new file's page cache through `Store::replace_cache` (D1101). That happens only between queries: while a read transaction holds the old copy it is refused, and the server tries again every two seconds. A query never sees two copies, and the next query sees the new one. The cached main tree is checked against the new copy's root, so nothing stale is reused.
- **Cache limits and eviction.** `--edge-cache <size>` caps the bytes the cached copies take. After each move, copies other than the one being served are removed, the least recently used first, until the cache fits. A removed copy is downloaded again if a later `--at` query or server asks for it.
- **Freshness.** An edge server is as fresh as the last archive plus up to 30 seconds. Data that must be fresher uses the live replicas of D209 or the page-store followers of D1101.

**Status:** code written, unbuilt (code-only mode, D355).
