## D954 YCSB's core workloads against SQLite and Redis — Decided by the code-only session (2026-11-13, D355); roadmap M4, D7's comparisons

- `crates/eggdb-sqlite-compare/src/ycsb_mix.rs` holds YCSB's six core workloads as their published operation mixes
  (A 50% reads and 50% updates, B 95/5, C reads only, D 95% reads of the latest records and 5% inserts, E 95% short
  scans of 1 to 100 records and 5% inserts, F 50% reads and 50% read-modify-writes) over 100,000 records, with
  YCSB's Zipfian request distribution (constant 0.99, Gray et al.'s generator, written by us from the paper) and its
  "latest" distribution for D. Keys are spread by the benches' existing key hash, as YCSB scrambles its Zipfian.
  Each side replays the same seeded sequence.
- `eggdb-sqlite-compare` runs A to F (`sqlite_compare.ycsb_a` … `ycsb_f`), each operation its own transaction as
  YCSB's clients run them, against SQLite through prepared statements, both at normal durability.
- `eggdb-redis-compare` includes the same file and runs A to D and F (`redis_compare.ycsb_*`) against the server one
  request at a time, as YCSB's Redis client does; E is left out, since Redis has no ordered key scan without the
  sorted-set index YCSB's binding adds. The Redis numbers include loopback round trips that embedded EggDB does not
  pay, so all YCSB ratios are reported, not gated.
