## D1151 The Java, Kotlin, Android and Swift drivers on the prepared-statement, stepping and COPY calls — Decided by the code-only session (2026-11-14, D355); roadmap M5 (every language driver using the new C API calls, D293)

- **Java (JDBC over FFM).**
  - `NativeStatement` wraps `eggdb_sql_prepare` and the `eggdb_stmt_*` calls. A `PreparedStatement` prepares on
    its first run, then binds typed values: integers up to `long` and `BigInteger` in range, `float` and `double`,
    `boolean`, `byte[]`, and the existing text forms for the rest.
  - `executeQuery` returns a result set over `SteppedRows`, which keeps only the current row and the one ahead, so
    a large result is never held whole; `setMaxRows` caps it. The forward-only position methods (`isBeforeFirst`,
    `isAfterLast`, `isFirst`, `isLast`, `getRow`) are written over "is row n present" so both kinds of result set
    answer the same way.
  - A statement the engine cannot prepare (more than one statement, for example) falls back to the text path it
    used before.
  - `NativeSession` finalizes its statements before closing the session.
  - `EggDbConnection.copyFrom(command, InputStream)` and `copyTo(command, OutputStream)` reach COPY through
    `unwrap`.
- **Kotlin and Android** (one JNI library, `drivers/kotlin/jni/eggdb_jni.c`, which Android builds as well).
  - New native calls: `Statement.nativeStart`, `nativeColumns`, `nativeStep` and `nativeReset`, and
    `EggDB.nativeCopyIn` and `nativeCopyOut`. The copy-out call hands each piece to a `Consumer` as it is read.
  - `Statement.rows(...)` and `EggDB.rows(sql, ...)` are `Sequence`s that cross into the database once per row, and
    `Statement.columns()` gives the column names.
  - `EggDB.copyFrom(sql, pieces)`, `copyFrom(sql, text)`, `copyTo(sql, onPiece)` and `copyTo(sql)` cover COPY.
  - Parameter encoding is shared by the batch and stepping paths (`Encoded`).
- **Swift.** `Statement.forEachRow` steps rows into a closure (`query` now uses it), and `Statement.columns()`
  gives the column names. `Database.copyFrom(_:pieces:)`, `copyFrom(_:text:)`, `copyTo(_:onPiece:)` and
  `copyTo(_:)` cover COPY. Value conversion and result gathering are shared helpers.
- With D1148 to D1150 every driver under `drivers/` (Python, Go, C++, Node.js, Ruby, PHP, Dart, .NET, Java, Kotlin,
  Android and Swift) uses prepared handles, stepping and COPY.
