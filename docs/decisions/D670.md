## D670 eggdb-lua part 4: cjson, bit and cmsgpack — Decided by the code-only session (2026-11-12, D355); roadmap M7, Lua scripting (D27, D193)

- `cjson` (`json_library.rs`): `encode` and `decode` with lua-cjson's defaults as Redis ships them. Numbers are
  written with `%.14g`; `/` is escaped as `\/`; NaN and infinity are refused; an empty table encodes as `{}`; a table
  whose keys are all positive integers is an array, and one sparser than lua-cjson's ratio (largest key above twice
  the item count and above 10) is refused. Nesting stops at 1000 levels both ways. `\u` escapes, surrogate pairs
  included, decode to UTF-8.
- `cjson.null` is a sentinel table owned by the interpreter (Lua has no light userdata here): `decode` returns it for
  `null` and `encode` writes `null` for it, so `cjson.decode('null') == cjson.null` holds as in Redis.
- `bit` (`bit_library.rs`): LuaBitOp's `tobit`, `bnot`, `band`, `bor`, `bxor`, `lshift`, `rshift`, `arshift`, `rol`,
  `ror`, `bswap` and `tohex`, on numbers rounded to nearest-even and wrapped to signed 32 bits.
- `cmsgpack` (`msgpack_library.rs`): `pack(...)` and `unpack(s)` as lua-cmsgpack does them: integral numbers as the
  smallest integer form, other numbers as float32 when exact and float64 otherwise, strings as `str` types, tables
  with keys `1..n` as arrays and others as maps, and tables nested deeper than 16 written as nil. `unpack` reads every
  type except `ext`, with `bin` read as strings. `unpack_one` and `unpack_limit` are left out.

  `redis.status_reply`, `redis.sha1hex` and `redis.log`.
