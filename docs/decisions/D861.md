## D861 WebAssembly multi-value — Decided by the code-only session (2026-11-12, D355); follow-up of D792

- Function types may have several results (the multi-value proposal, part of WebAssembly 2.0). A call leaves all of
  them on the stack in order, and `Instance::call_values` returns them all; `Instance::call` keeps returning the first.
- Block types are read as WebAssembly's signed 33-bit block type: `0x40` (empty), a value type (one result), or a
  type index whose parameters are taken from the stack and whose results are left on it. `block` and `if` labels
  carry the type's results and start below its parameters; a `loop` label carries the parameters, so a branch back
  to a loop passes them again. Re-entering a loop skips the whole block type, not one byte. A type index that does
  not exist traps.
- `CREATE FUNCTION ... LANGUAGE wasm` still binds one SQL result, so an export returning several values is refused
  as not supported; modules may use multi-value internally.
- Left: imports (host functions) and the spec test suite in CI.
