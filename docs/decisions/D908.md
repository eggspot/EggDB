## D908 WebAssembly imported functions, and EggDB's first host functions — Decided by the code-only session (2026-11-12, D355); roadmap M5, follow-up of D232, D792, D793

- `eggdb-wasm-vm` now reads the import section's function imports (module name, field name, type), which take the
  first indices of the function index space as WebAssembly 1.0 says; calls, `call_indirect`, table elements, exports
  and the start function all address imported and defined functions alike. Imported tables, memories and globals are
  still refused at parse time.
- `Instance::with_host(module, limits, host)` gives the instance a `HostCall`, a closure called with the import's
  module and field names and its arguments; it returns the results or a trap. A host call costs 100 units of fuel,
  its results must match the import's type (else the call traps), and `Instance::new` makes an instance whose
  imported functions trap when called. `Module::imports` and `Module::import_types` list them.
- `CREATE FUNCTION ... LANGUAGE wasm` accepts modules whose imports are among the host functions EggDB provides, each
  checked against its type when the function is created and again when it runs:
  - `eggdb.now_micros() -> i64`: the statement's time in microseconds since 1970 (the time `now()` gives), so a
    function stays deterministic within a statement;
  - `env.abort(i32, i32, i32, i32)`: traps, ending the statement with 38000, for modules built by toolchains that
    import it (AssemblyScript).
  Any other import refuses the module, naming the import and listing what EggDB provides.
- These two have no effects outside the call, so they need no permission. Host functions with effects (reading
  tables, logging, the network) are left for the permissions work the roadmap lists.
