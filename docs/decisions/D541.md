## D541 `TABLESAMPLE` — Decided by the code-only session (2026-11-11, D355); roadmap M5

`FROM t TABLESAMPLE BERNOULLI (p) [REPEATABLE (seed)]` (and `SYSTEM`, read the same way) in the
PostgreSQL and MySQL dialects, and SQL Server's `TABLESAMPLE [SYSTEM] (p [PERCENT])`, now return
about `p` percent of the table's rows, where they failed to parse.

- **How:** the table becomes a derived table `(SELECT * FROM t WHERE eggdb_tablesample(p, seed) =
  1) alias` (the alias defaulting to the table's name, so `t.column` still reads), built from
  the statement's own text and parsed in its dialect. `eggdb_tablesample` draws once per row
  read: with `REPEATABLE`, from the seed and the row's place in the scan, so the same seed over
  the same rows gives the same sample, as PostgreSQL promises; without it, a fresh draw each
  run. It is marked as changing, like `random()`, so nothing folds it into a constant.
- **Errors:** a percentage outside 0 to 100, or a seed that is not a number, fails with
  `2202H`, PostgreSQL's code. SQL Server's `TABLESAMPLE (n ROWS)` and other sampling methods
  (`tsm_system_rows`) are refused as not supported.
- **Difference:** `SYSTEM` samples rows, not pages, so it is as random as `BERNOULLI` (PostgreSQL's
  `SYSTEM` picks whole pages); the expected sample size is the same.
- **Left out:** t-digest and the other `APPROX_*` functions.

**Status:** code written, unbuilt (code-only mode, D355).
