## D382 SQLite's `json_each` and `json_tree` — Decided by the code-only session (2026-11-10, D355); roadmap M5, extends D378

In the SQLite dialect `json_each(X [, P])` and `json_tree(X [, P])` in `FROM` are set-returning
functions (`sqlite_json_each`, `sqlite_json_tree`, kept apart from PostgreSQL's `json_each`) with
SQLite's visible columns:

- `key` (array index or member name; NULL for the starting element), `value` (the SQL value, JSON
  text for arrays and objects), `type` (as `json_type`), `atom` (the SQL value of a primitive,
  NULL for a container), `id` (a number unique within the call), `parent` (the parent row's `id`
  in `json_tree`, NULL in `json_each`), `fullkey` (the element's path, `$.key`, `$."odd key"`,
  `$[N]`) and `path` (the container's path).
- `json_each` lists the direct children of the element at `P` (default `$`), or that element
  alone when it is a primitive; `json_tree` walks it and everything under it, parents before
  children.
- `id` numbers rows in walk order; SQLite's are byte offsets, which no query should depend on.
  The hidden `json` and `root` columns are not provided.
