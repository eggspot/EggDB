## D205 AI in the database starts with local, model-free helpers in eggdb-ai — Decided by the build loop (by judgement, 2026-10-31); refines D31

Part 4.M12-3 asks for hybrid vector and full-text search with reranking, embeddings and ONNX
inference from SQL (local models, remote providers off by default), text-to-SQL, semantic
caching and agent memory.

- **Nothing downloaded, nothing sent.** D31 keeps remote providers off by default; a local
  model needs an inference engine of our own (an ONNX runtime written from the ONNX operator
  specification), which is a project of its own. Until it exists, `eggdb-ai` offers what needs
  no model: a feature-hashing embedding of stemmed words and word pairs (`eggdb_embed`), so the
  vector operators and an HNSW index have something to search on any install; reciprocal rank
  fusion (`rrf_score`, from Cormack, Clarke and Büttcher's paper) to merge a vector ranking with
  a full-text ranking; and overlapping text chunks for retrieval. The embedding is described
  honestly as lexical: it matches shared words, not meanings.
- **Same vector text as pgvector (D203)**, so a real model's embeddings, computed by the
  application today and by an in-database model later, use the same columns and operators.

Left: an ONNX runtime and `embed(model, text)` with local models, opt-in remote embedding
providers with keys from the secrets store, reranking models, text-to-SQL through the MCP server
(D11), a semantic cache, agent memory tables, and an end-to-end retrieval benchmark.
