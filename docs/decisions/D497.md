## D497 Zipkin traces: span ingest and the basic query API — Decided by the code-only session (2026-11-11, D355); roadmap M16, D39

- The observability listener takes Zipkin v2 JSON at `POST /api/v2/spans` (answering 202): each
  span becomes a row of `metrics.spans` through the points writer, with `trace_id`, `span_id`,
  `parent_id`, `name`, `kind`, `service` (the local endpoint's service name) and `remote_service`
  as text columns, `duration_us`, the span's string tags as a JSON text `tags` column, and its
  start as `time`. Ids must be hex (16 or 32 digits for traces, 16 for spans); at most a million
  spans per request.
- `GET /api/v2/services`, `GET /api/v2/spans?serviceName=` and `GET /api/v2/trace/<id>` answer
  as Zipkin's API does (the trace as a JSON array of spans), so Zipkin's UI and Grafana's Zipkin
  data source can list services and open a trace.
- Not written: Zipkin's protobuf and Thrift encodings, annotations, `/api/v2/traces` search,
  Jaeger's APIs, and OTLP traces.
