## D174 SQL inside an embedded write transaction, through a store that borrows it — Decided by the build loop (by judgement, 2026-10-31); refines D87 and D98

Part 4.M3-3 lets one transaction mix key-value writes and SQL. `WriteTransaction::sql(dialect,
text)` runs a SQL session on a store that borrows the transaction: reads and writes go to it,
and a statement's commit does nothing, so the transaction's own commit or rollback decides for
both kinds of change. The store logs each statement's writes with the values they replace, so a
failed statement undoes exactly its own writes, as a statement does in its own transaction. A
read and a write of the borrowed transaction are never needed at once, and a second borrow is
refused as an error rather than a panic.
