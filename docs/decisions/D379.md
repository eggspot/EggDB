## D379 SQLite's `json_set`, `json_insert`, `json_replace`, `json_remove` and `json_patch` — Decided by the code-only session (2026-11-10, D355); roadmap M5, extends D378

The functions that change a JSON document, on the parsed tree of D378 (`sqlite_json.rs`):

- **Paths** add `$[#]`, the position after an array's last element.
- **`json_set`, `json_insert`, `json_replace`** take the document and path/value pairs, applied
  left to right. `json_replace` changes only what exists; `json_insert` adds only what is missing
  (an object member, or an array element at `$[#]` or at the array's length); `json_set` does
  both. A missing object member on the way to the last step is created as an object (or an array
  when the next step indexes one), as SQLite does. Values are written as in `json_array` (D378),
  so the result of a JSON function is placed as JSON. A path to `$` replaces the whole document
  (`json_set`, `json_replace`).
- **`json_remove`** removes each path in turn (later paths see earlier removals); removing `$`
  gives NULL.
- **`json_patch`** merges as RFC 7396 says: an object patch merges member by member, a `null`
  member removes, anything else replaces.
- An even number of arguments to `json_set` and friends is SQLite's wrong-argument error.
