## D512 Redis stream consumer groups — Decided by the code-only session (2026-11-11, D355); roadmap M7

`XGROUP` (CREATE with MKSTREAM and ENTRIESREAD, SETID, DESTROY, CREATECONSUMER, DELCONSUMER,
HELP), `XREADGROUP` (`>` and history ids, COUNT, NOACK, BLOCK through the blocking registry as a
consuming waiter), `XACK`, `XPENDING` (summary and extended with IDLE and a consumer), `XCLAIM`
(IDLE, TIME, RETRYCOUNT, FORCE, JUSTID, LASTID), `XAUTOCLAIM` (COUNT, JUSTID, deleted ids) and
`XINFO STREAM|GROUPS|CONSUMERS|HELP`, in `eggdb-resp`'s `stream_groups.rs`.

- **Format:** group state is kept with the stream as stored value kind 6 (`docs/format.md`,
  "RESP values"); a stream without groups keeps kind 5, so existing files read unchanged. The
  decoder refuses unordered names and ids and pending entries of unlisted consumers, so every
  accepted value re-encodes to the same bytes; a pinned vector, every truncation and byte flips
  over the group section are tested.
- **Semantics:** as Redis 7: claimed entries that were deleted from the stream leave the pending
  list; history reads do not count a delivery; `entries-read` is unknown after `$` because EggDB
  does not count entries ever added, so `lag` is then null.
- **Left out:** `XINFO STREAM FULL` answers the plain form; `XSETID`; keyspace notifications.

**Status:** code written, unbuilt (code-only mode, D355).
