## D333 Cypher gets named paths, `shortestPath()` and `allShortestPaths()`, `MERGE ... ON CREATE SET / ON MATCH SET`, `FOREACH`, `UNION [ALL]` and list and pattern comprehensions, and Bolt sends paths as PackStream paths — Decided by the build loop (EggAgentCode task 20261104-1214, 2026-11-04); roadmap M13, extends D206 and D207

D206 left these parts of Cypher out, and a query using them failed with
`Neo.ClientError.Statement.FeatureNotSupported` (or a syntax error). Each is built from the
openCypher 9 reference (the Apache-licensed language documents) and the behaviour Neo4j's Cypher
manual documents for it; no Neo4j code is used or read. The tests are the manual's own examples
(the "Martin Sheen / Oliver Stone / Michael Douglas" graph for shortest paths, "Keanu Reeves" for
`MERGE`, the A-B-C-D chain for `FOREACH`, the actors and movie named "Hitchcock" for `UNION`, and
`[x IN range(0,10) WHERE x % 2 = 0 | x^3]`), one through Bolt.

- **Named paths.** `p = (a)-[:R*1..3]->(b)` in `MATCH`, `OPTIONAL MATCH`, `CREATE` and `MERGE`
  binds `p` to a new value, `eggdb_graph::Path` (`Value::Path`): the nodes in walking order and the
  relationships between them, each in its stored direction. `nodes(p)`, `relationships(p)` and
  `length(p)` read it, `DELETE p` and `DETACH DELETE p` delete its relationships and nodes, it
  equals and orders by its node and relationship ids (paths order between lists and strings, as
  openCypher's orderability says), and `toString` writes it as `(0:A)-[1:R]->(2:B)`. A path is
  only kept while a pattern that names one is matched, so patterns without a name pay nothing.
- **Bolt paths.** A path goes to drivers as the PackStream `Path` structure (signature `0x50`):
  the distinct nodes, the distinct relationships as `UnboundRelationship` (`0x72`, with its element
  id on Bolt 5), and the index list (1-based relationship index, negative when walked against its
  direction, then the 0-based node index), so a driver gives back its usual `Path` object.
- **`shortestPath()` and `allShortestPaths()`.** The pattern must have exactly one relationship,
  whose bounds give the search depth (`[*]` is at most 15 hops, D206) and whose minimum may only be
  0 or 1; otherwise it is a `SyntaxError` with Neo4j's message. The search is breadth-first from
  each start node, following the relationship's types, properties and direction, and stops after
  the hop at which a bound end node is reached. `shortestPath` keeps the first predecessor of each
  node and returns one path per end node; `allShortestPaths` keeps every predecessor at the
  shortest distance and returns every shortest path. The relationship variable binds the list of
  relationships (or the single one without `*`).
- **Bounded against hostile queries.** One search examines at most 1,048,576 relationships and an
  `allShortestPaths` returns at most 4,194,304 paths (the row cap of D206); past either the query
  fails with `Neo.TransientError.General.MemoryPoolOutOfMemoryError` and changes nothing. The
  search keeps only node ids, distances and predecessor ids (tens of bytes a node), reading
  relationships only for the paths it returns, and the records that go to a Bolt driver stay under
  the server's memory budget as before (D207).
- **`MERGE ... ON CREATE SET ... ON MATCH SET ...`.** Any number of `ON CREATE SET` and
  `ON MATCH SET` items, in any order, for node and relationship patterns: when the whole pattern
  matches, the `ON MATCH` items run on each match; otherwise the pattern is created (bound nodes
  reused) and the `ON CREATE` items run on it. A relationship merged without a direction is
  created left to right, as Neo4j does.
- **`FOREACH (x IN list | ...)`** runs `CREATE`, `MERGE`, `SET`, `REMOVE`, `DELETE`, `DETACH
  DELETE` and nested `FOREACH` once for each element, with `x` bound only inside; the rows that go
  on are the rows that came in, refreshed. A reading clause inside is a `SyntaxError`; a null list
  does nothing; a value that is not a list is a `TypeError`.
- **`UNION` and `UNION ALL`.** Each part runs in turn in the query's one transaction; `UNION`
  removes duplicate rows, `UNION ALL` keeps them. Parts whose column names differ fail with
  Neo4j's "All sub queries in an UNION must have the same return column names", mixing the two
  with "Invalid combination of UNION and UNION ALL", and a part that does not end in `RETURN` (or
  `CALL`) is refused before anything runs, all as `SyntaxError`.
- **List comprehensions** `[x IN list WHERE pred | expr]` (either part optional; a null list gives
  null) and **pattern comprehensions** `[(a)-[:R]->(b:Movie) WHERE pred | b.title]`, whose new
  variables are local to them. A bracket that starts like a pattern but is not followed by `WHERE`
  or `|` is read as a list literal, so `[(1 + 2), 4]` keeps working.

Decided by research:
- Paths are a value of their own, not a list of alternating nodes and relationships, because
  Bolt drivers expect a `Path` structure and openCypher gives paths their own type, equality and
  orderability.
- The shortest-path limit is a fixed count of examined relationships in `eggdb-graph` rather than
  a share of the Bolt server's memory budget, because the graph crate is used without a server too
  (embedded, D3) and must never depend on a protocol (CLAUDE.md layout rule); the count keeps the
  search under 64 MB.
- Neo4j refuses `shortestPath` between a node and itself by default; EggDB returns no row for a
  minimum of 1 (and the zero-length path for a minimum of 0) instead of an error, which is what
  Neo4j does when that check is turned off, so cartesian products do not fail.

Left: predicates on the path that Neo4j pushes into the shortest-path search (`WHERE all(r IN
relationships(p) WHERE ...)` filters after the search here, so it can miss a longer path that
passes); `shortestPath()` as an expression outside `MATCH`; quantified path patterns and
`SHORTEST k` from GQL; the bidirectional search Neo4j uses for bound endpoints; `CALL {}`
subqueries; label predicates in expressions (`WHERE n:Movie`); and MERGE's error on a null
property value.
