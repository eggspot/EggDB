## D795 SQL Server's and MariaDB's system-versioning syntax — Decided by the code-only session (2026-11-12, D355); roadmap M14, system-versioned temporal tables

- `eggdb_temporal` gains `enable_system_versioning(schema, table, start_column, end_column, history_table, open_end)`
  and `disable_system_versioning(schema, table)`. Unlike `enable` (D755, bitemporal), it keeps only system time, under
  the user's own period column names: it adds them when missing (`timestamptz`, start defaulting to now, end to the
  open end), creates the history table (`<table>_history` or the name given, in the table's schema, unless it exists),
  a row trigger that copies each old version into the history with its end set to now and stamps new versions from
  now to the open end, and the `<table>_versions` view. The registry `eggdb_temporal.tables` gains `system_start` and
  `system_end` (defaulting to `recorded_from`/`recorded_to`), and `FOR SYSTEM_TIME` (D794) reads its period from them.
- SQL Server: `GENERATED ALWAYS AS ROW START|END [HIDDEN]` columns, `PERIOD FOR SYSTEM_TIME (start, end)` and the
  table option `SYSTEM_VERSIONING = ON [(HISTORY_TABLE = schema.name, DATA_CONSISTENCY_CHECK = ON|OFF)]` in `CREATE
  TABLE` make the table system-versioned once it is created; `ON` without a period fails with 13510, as SQL Server
  does. `ALTER TABLE t SET (SYSTEM_VERSIONING = OFF)` turns it off and keeps the history as a plain table. The open
  end is SQL Server's `9999-12-31 23:59:59.999999` rather than infinity, which TDS cannot send.
- MariaDB: `CREATE TABLE ... WITH SYSTEM VERSIONING` (implicit `row_start`/`row_end` columns, visible since EggDB has
  no invisible columns, ending at `2038-01-19 03:14:07.999999`), explicit `GENERATED ALWAYS AS ROW START|END` columns
  with `PERIOD FOR SYSTEM_TIME`, and `ALTER TABLE ... ADD|DROP SYSTEM VERSIONING`.
- The session runs the switch right after the `CREATE`/`ALTER` succeeds, in PostgreSQL's dialect, installing the
  extension if needed; the two are separate steps, so a failed switch leaves the table created without versioning.
- Left: `SYSTEM_VERSIONING = ON` in SQL Server's `ALTER TABLE` (it needs the period kept from an earlier `ADD PERIOD`),
  `HISTORY_RETENTION_PERIOD`, invisible columns, and MariaDB's `AS OF TRANSACTION` and partitioned history.
