## D457 Upserts, `/rpc/<function>` and an OpenAPI document in the generated REST API — Decided by the code-only session (2026-11-11, D355); roadmap M6a, extends D235

- `POST /<table>` with `Prefer: resolution=merge-duplicates` becomes
  `INSERT ... ON CONFLICT (keys) DO UPDATE SET c = EXCLUDED.c` for every sent column outside the
  keys; `resolution=ignore-duplicates` (or a body holding only key columns) becomes `DO NOTHING`.
  The keys come from `on_conflict=a,b`, else from the table's primary key read from
  `information_schema`; with neither the request fails with `PGRST109`.
- `GET /rpc/<function>?p=v` and `POST /rpc/<function>` with a JSON object call
  `SELECT * FROM <schema>.<function>(p => value, ...)` with named arguments. Query-string values
  are quoted text literals, JSON values go through the same literals as inserts (objects and
  arrays as `jsonb`). A single row with a single column named like the function returns that
  value bare, as PostgREST does for scalar functions; anything else returns rows. Other methods
  answer 405 with `PGRST117`.
- `GET /` with an `Accept` naming `openapi` returns an OpenAPI 3.0.3 document
  (`application/openapi+json`): one path per table with get/post/patch/delete, and a schema per
  table whose property types map PostgreSQL's integer, numeric, boolean and JSON types and list
  the NOT NULL columns as required. Without that `Accept` the root keeps D235's description.
- Left: JWT sign-in with roles per request and embedded resources.
