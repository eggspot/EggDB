## D416 MySQL's `ON UPDATE CURRENT_TIMESTAMP` — Decided by the code-only session (2026-11-11, D355); roadmap M10

- A MySQL column definition takes `ON UPDATE CURRENT_TIMESTAMP` (also `CURRENT_TIMESTAMP(n)`,
  `NOW()`, `LOCALTIME` and `LOCALTIMESTAMP`, as MySQL accepts) on a `DATETIME` or `TIMESTAMP`
  column; on any other type it is MySQL's error 1294, "Invalid ON UPDATE clause for 'c' column".
  `ON UPDATE` with anything else stays refused as not supported.
- The table definition records the stamped columns in a new format version, 16
  (`ON_UPDATE_FORMAT_VERSION`): after the generated-columns section, a count and the column
  positions in ascending order. Only a table with a stamped column is written as version 16, so
  every other table keeps the version older releases read; an older release refuses a version-16
  table by its version, as for every format step. The decoder refuses an empty list, a repeated
  or unordered position and a stamped column that is not a timestamp. The encoder writes only the
  stamped columns that are still timestamps, so changing a stamped column's type drops the stamp
  instead of writing a record the decoder would refuse.
- The stamp follows MySQL's rule: when an `UPDATE` (plain, joined or `INSERT ... ON DUPLICATE KEY
  UPDATE`) changes any other column of a row and doesn't assign the stamped column, the column
  takes the statement's time (local time for `DATETIME`, the instant for `TIMESTAMP`), converted to
  the column's precision. It runs before `BEFORE UPDATE` triggers and generated columns, so both
  see the new time. A known difference: assigning the column its current value prevents the stamp
  in MySQL and here alike, but assigning it in a statement that changes nothing else is not
  distinguished from not assigning it (neither changes the row).
- `ALTER TABLE ... ADD COLUMN`, `MODIFY`/`CHANGE COLUMN` (which set or clear the stamp as the new
  definition says), `DROP COLUMN` and column moves keep the positions right.
  `information_schema.COLUMNS.EXTRA` shows `on update CURRENT_TIMESTAMP` (with
  `DEFAULT_GENERATED` before it when the column has a default), as MySQL 8 does. `SHOW CREATE
  TABLE` does not print the clause yet.
