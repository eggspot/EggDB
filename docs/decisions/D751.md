## D751 `CREATE EXTENSION eggdb_secrets`: sealed secrets and dynamic credentials — Decided by the code-only session (2026-11-12, D355); roadmap M6b, a secrets store with dynamic, short-lived credentials in Vault's style (D54)

- New SQL functions: `gen_random_bytes(n)` (1 to 1,024 bytes from the secure random source, as pgcrypto names it),
  `eggdb_seal(data, key)` and `eggdb_unseal(sealed, key)`: AES-GCM (16, 24 or 32-byte keys) with a random 96-bit
  nonce, the output a version byte, the nonce, the ciphertext and the tag; unsealing checks the tag and refuses
  changed data or a wrong key.
- `eggdb_secrets` keeps versioned secrets by path, sealed under a key the caller passes (the database never stores
  it): `put` (with an optional time to live), `get` (the newest unexpired version, or a given one), `destroy` and
  `rotate_key`.
- Dynamic credentials: `issue_credentials(template_role, ttl)` creates a login role named `v_<role>_<random>` with a
  random 48-hex-digit password, `IN ROLE` the template and `VALID UNTIL` the lease's end (at most 31 days), and
  records the lease; `renew_credentials`, `revoke_credentials` (drops the role) and `expire_credentials` (drops every
  expired one, for a pg_cron job) manage leases. Callers need the privilege to create roles.
- Secrets engines for other systems (cloud keys, other databases), key wrapping with an external KMS and response
  wrapping are left.
