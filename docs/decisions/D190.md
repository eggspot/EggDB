## D190 Agents as stored roles: per-agent grants through the token file, MCP prompts — Decided by the build loop (by judgement, 2026-10-31); refines D11 and D189; security-critical (D35)

Part 4.M6d-2 asks for grants per agent, per database and table, read-only by default and
revocable, shown in the audit, and MCP resources and prompts beyond the schema.

- **An agent is a stored role** (D183). `ServerConfig::agent_role` makes every call of an MCP
  server run its SQL session as that role (`Session::identify_role`), so table privileges, row
  security (D186) and `LOGIN` apply to the agent exactly as to a person. Granting is `GRANT`,
  revoking is `REVOKE` or `ALTER ROLE ... NOLOGIN`, effective on the agent's next call.
- **The token file names the role**: each line of `--mcp-token-file` is a token, or a role and
  a token; the token an agent sends picks its role, and an MCP session stays bound to the token's
  role (another token cannot use it).
- **What a role cannot reach**: the key-value tools are withdrawn for a role (they read the
  store beneath SQL), and the tool that pages through stored rows checks `SELECT` and refuses a
  table that row security filters for the role, pointing to SQL instead.
- **Prompts**: `prompts/list` and `prompts/get` offer `explore_database` and `answer_with_sql`,
  whose text tells the agent to treat database contents as data, never instructions.
