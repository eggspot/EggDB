## D941 Windows named pipes as a second kind of local listener, and `eggdb serve --mysql-pipe` — Decided by the code-only session (2026-11-13, D355); roadmap M1, refines D164 and D267

- **Platform layer.** `eggdb_platform::local_socket::bind_named_pipe(name)` listens on `\\.\pipe\<name>` on our own
  kernel32 and advapi32 declarations (`CreateNamedPipeW`, `ConnectNamedPipe`, `ReadFile`/`WriteFile` with
  `OVERLAPPED`, `GetOverlappedResult`, `WaitForSingleObject`, `CancelIoEx`, `DisconnectNamedPipe`). It returns the
  same `LocalListener` and `LocalStream` as the `AF_UNIX` sockets, now enums inside, so the servers that already take a
  local listener take a pipe unchanged. Other OSes answer `Unsupported` (`NAMED_PIPES_SUPPORTED` is false).
- **Owner only, this machine only.** Every pipe instance is created with a security descriptor whose DACL is the same
  one-entry, current-user list D267 puts on socket files (the ACL builder is now `OwnerOnlyAcl`, shared), and with
  `PIPE_REJECT_REMOTE_CLIENTS`. The first instance uses `FILE_FLAG_FIRST_PIPE_INSTANCE`, so a name another process
  already serves fails with `InUse` instead of joining that server's pipe.
- **Accepts.** One instance always waits in an overlapped `ConnectNamedPipe`; `accept` waits on its event (not at all
  when non-blocking, answering `WouldBlock`), hands the connected instance to the caller and starts the next one. A
  pending connect is cancelled and waited for before its `OVERLAPPED` is freed.
- **Reads and writes.** Each read and write is overlapped and waits on its own event for the stream's timeout
  (`INFINITE` when none, 0 when non-blocking); on expiry it is cancelled and waited for, so the buffer outlives the
  operation, and the caller gets `TimedOut` or `WouldBlock`. A client that went away reads as end of file and fails a
  write with `BrokenPipe`. Shutting down both directions disconnects the client; shutting down one does nothing,
  since a pipe ends when its last handle closes and buffered bytes still reach the client.
- **Serve.** `eggdb serve --mysql-pipe <name>` (Windows only, needs `--mysql-listen`, not with `--mysql-socket`) gives
  the MySQL server the pipe as its local listener; the mysql client reaches it with `--protocol=PIPE
  --socket=<name>`. The startup lines and the JSON status (`mysql_pipe`) show it.
- **Left.** SQL Server clients use the pipe `sql\query`, but the TDS server works on `TcpStream` throughout, so it
  needs a connection type of its own before it can take a pipe.
