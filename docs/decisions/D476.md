## D476 NATS no-responders and token authentication — Decided by the code-only session (2026-11-11, D355); roadmap M16, D216

- A client that connects with `"headers": true, "no_responders": true` and publishes a request
  (`PUB`/`HPUB` with a reply subject) that no subscription receives gets, on each of its own
  subscriptions matching the reply subject, an `HMSG` with the status header `NATS/1.0 503` and an
  empty payload, as nats-server sends it, so request calls fail at once instead of timing out.
  `no_responders` without `headers` is refused at `CONNECT`, as nats-server does.
- `CONNECT` with `auth_token` (and no `user`) authenticates when the token is the server's
  password (its SHA-256 is compared in constant time, as for `pass`), so clients configured with a
  token connect to `eggdb serve`'s one account.
- Not written: NKey authentication (it needs Ed25519 and a list of accepted public keys),
  clusters and leaf nodes.
