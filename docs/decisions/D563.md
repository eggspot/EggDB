## D563 The `completion` suggester — Decided by the code-only session (2026-11-11, D355); roadmap M8, D196

Search-as-you-type boxes ask Elasticsearch for `suggest` with a `completion` suggester over a
`completion` field. A `_search` body's `suggest` section is now answered: each named suggestion
with a `prefix` (or `text`, or the section's global `text`) and `completion.field` lists, after the
hits, the documents whose field holds an input starting with the prefix, letter case ignored as
the default `simple` analyzer does, best `weight` first (then the input, then the document),
one option per document with its `text`, `_index`, `_id`, `_score` (the weight) and `_source`.
`size` (default 5) and `skip_duplicates` are read. Inputs may be a string, an array, or
`{"input": ..., "weight": n}`.

The suggester reads every searched document whatever the query (as Elasticsearch's does) and
scans them, where Elasticsearch keeps an FST; `fuzzy`, `regex`, contexts, and the `term` and
`phrase` suggesters (which answer with no options) are not built.

**Status:** code written, unbuilt (code-only mode, D355).
