## D943 `NotConnected` after a reset on Windows' sockets — Decided by the code-only session (2026-11-13, D355); roadmap M1, completes D314's contract on Windows

- D314 promised one answer on every backend for a reset connection: `peer_address()` and `shutdown_write()` fail with
  `ErrorKind::NotConnected`, and Linux and macOS were checked. Winsock documents `WSAENOTCONN` for `getpeername` and
  `shutdown` on a socket that is not connected, but a socket whose last receive failed with `WSAECONNRESET` or
  `WSAECONNABORTED` may report those again instead.
- So `OsStream` on Windows turns `ConnectionReset` and `ConnectionAborted` from those two calls into `NotConnected`, as
  it already turns macOS's `EINVAL` into it, and the contract test `a_reset_end_has_no_peer_address_and_cannot_shut_down`
  now runs against Windows' sockets on every Windows backend (the portable one, IOCP and `poll`) as well.

**Status:** code written, unbuilt (code-only mode, D355).
