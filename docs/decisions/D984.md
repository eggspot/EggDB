## D984 OpenSearch Dashboards and Kibana against EggDB — Decided by the code-only session (2026-11-13, D355); roadmap M8, Kibana and OpenSearch Dashboards (D12, D196)

- The Elasticsearch-compatible API answers what the dashboards ask at start and when they build index patterns:
  `GET _nodes` (the node's version, address and roles), `GET` and `PUT _cluster/settings`,
  `_cluster/health/<index>`, `GET` and `PUT <index>/_mapping` (new fields merged into the stored mappings, other
  top-level members such as `_meta` replaced), `GET <index>/_settings` (the stored settings over one shard and no
  replicas), `PUT <index>/_settings` (acknowledged), `_field_caps` (each mapped field and multi-field with its type,
  searchable and aggregatable as Elasticsearch decides by type, plus `_id`, `_index`, `_source` and `_type`),
  `_resolve/index/<pattern>`, and empty `_cat/templates`, `plugins`, `nodes`, `shards` and `segments`.
- Index patterns (`orders*`, comma lists, `_all`) are resolved before the index name check, so they reach these
  endpoints.
- EggDB answers OpenSearch's version (2.11.0) to every client except Kibana 7 (its `User-Agent` or
  `x-elastic-product-origin: kibana`), which refuses a cluster whose version differs from its own; it is answered
  7.10.2, the last version under the Apache licence. Kibana 8 checks Elastic's product header and licence API and is
  not targeted.
- `scripts/dashboards.sh` starts `eggdb serve --es-listen`, indexes a document, runs OpenSearch Dashboards 2.11.1 and
  Kibana OSS 7.10.2 in containers on the host network, waits for each to report green, creates an index pattern
  and reads its fields. CI's `compatibility` job runs it strictly (its timeout raised to 30 minutes) and the weekly
  compatibility farm adds its rows to the matrix.
