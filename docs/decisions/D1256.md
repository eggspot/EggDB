## D1256 SQLNativeSql and the SQL_CONVERT bitmasks — Decided by the code-only session (2026-11-18, D355); roadmap M6 ODBC driver (D1255)

- **What users get.** `SQLNativeSql` answers a statement as the driver will run it, with its ODBC escape sequences translated for the connection's dialect (D1255), as tools call it to show the SQL they send. `SQLGetInfo` answers every `SQL_CONVERT_*` type (`BIGINT` to `LONGVARBINARY`) with the types a `CAST` turns it into: numbers into text and every other number type, text into every type, dates and times into text and the other date and time types, binary into text and the other binary types.
- **How.** `SQLNativeSql` reuses the translation `SQLExecDirect` and `SQLPrepare` use, and answers its length and `SQL_SUCCESS_WITH_INFO` when the buffer cuts it, as `SQLGetInfo`'s text answers do. The bitmasks are fixed answers, kept as four groups of `SQL_CVT_*` bits.
- **Left.** `SQLNativeSqlW`; conversions between numbers and dates, which EggDB's `CAST` refuses in some dialects and allows in others, so none are claimed.
- **Proof.** The ODBC test reads `SQL_STRING_FUNCTIONS` and translates a statement with `SQLNativeSql`.

**Status:** code written, unbuilt (code-only mode, D355).
