## D668 eggdb-lua part 2: the interpreter and the base libraries — Decided by the code-only session (2026-11-12, D355); roadmap M7, Lua scripting (D27, D193)

- `eggdb-lua` now runs scripts. `Interpreter::run(source, host, step_budget)` parses the source (D667) and walks the
  tree: values (`nil`, booleans, numbers as `f64`, byte strings, tables, Lua and native functions), lexical scopes
  with closures over shared cells, multiple returns and varargs, numeric and generic `for`, `repeat`, `break`, and
  the metatable events Redis scripts use (`__index`, `__newindex`, `__call`, `__tostring`).
- Tables keep an array part for `1..n` and a hash part in insertion order, so `pairs` is deterministic, which Redis
  scripts replicated by effect rely on less than tests do, but it costs nothing.
- Redis calls go through the `Host` trait (`command(&[Vec<u8>]) -> Reply`, `log`), so the interpreter does not depend
  on the RESP server; `NoHost` answers every command with an error, for tests and syntax checks.
- Every statement and call spends one step of the budget. Running out raises `Unwind::Kill`, which `pcall` does not
  catch, matching Redis `SCRIPT KILL` and `lua-time-limit` semantics in a deterministic, clock-free form. Calls nest
  at most 200 deep.
- The base library: `type`, `tostring`, `tonumber` (with a base), `next`, `pairs`, `ipairs`, `select`, `unpack`,
  `error` (string errors get the `user_script:LINE:` prefix Redis shows), `assert`, `pcall`, `rawget`, `rawset`,
  `rawequal`, `setmetatable`, `getmetatable`, `_G`, and `print` as a no-op as in Redis. `table` (`insert`, `remove`,
  `concat`, `getn`, `sort` with an optional comparator, `unpack`) and `math` (`floor`, `ceil`, `abs`, `sqrt`, `log`,
  `exp`, `fmod`, `pow`, `max`, `min`, `modf`, `pi`, `huge`) are installed too. `math.random` is left out: Redis
  seeds it per script for determinism, and it comes with the Redis integration.
- Next parts: `string` with Lua patterns, `cjson`, `bit`, `cmsgpack`, then `EVAL`, `EVALSHA` and `SCRIPT` in the RESP
  server with `redis.call`, `redis.pcall`, `redis.error_reply` and `redis.status_reply`.
