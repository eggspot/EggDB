## D1360 DELETE removes whole rows of a table listed with columns — Decided by the code-only session (2026-11-25, D355); roadmap M6d "`eggdb mcp --tables`: deleting rows of a table listed with columns" (D306); security-critical (D35)

- **What agents get.** With `--allow-write --tables 'users(id,name)'`, `DELETE FROM users WHERE ...` (and `DELETE ... USING`, MySQL's multi-table delete and `MERGE`'s delete, which share `execute::delete_rows`) removes the whole rows, hidden columns and the index entries over them included. Changing a row's key stays refused (`42501`), as D306 decided.
- **Telling a delete from a key change.** The engine writes a key change as a delete and a put, so the store filter could not tell them apart and refused both. `KeyValueWrite` gains `delete_whole_row`, which only the delete statements call; its default is `delete`, and the writers that wrap another (the savepoint and PL/pgSQL undo logs, temporary tables, the concurrent and boxed writers, nonatomic procedures and read-only transactions) pass it on. `VisibleWrite` takes it as a whole-row delete of a narrowed table and keeps refusing a plain `delete` there.
- **Nothing learned from hidden values.** A delete's outcome must not depend on a hidden value (D306). Deleting a row the agent can see depends on none, unless a foreign key points at the table: an `ON DELETE` rule, or a refusal, could then turn on hidden key columns. So a table any foreign key references keeps refusing deletes; the check reads the definition, never the data.
- **Rollback keeps hidden values.** The savepoint undo log sits above the filter and records the narrowed row, so undoing a delete puts back only the listed columns. `VisibleWrite` remembers the stored row of each row it deleted whole in the transaction, and a put of that key merges the listed values over the remembered row, so a rollback (and a statement rollback) restores the hidden values and their index entries. A new insert of the same key in the same transaction also gets those values rather than the defaults, which reveals nothing, as the agent cannot read them.
- **Left.** Deletes from a referenced table when every referencing key lies in listed columns, and the other D306 items (generated hidden values on insert, unique indexes and foreign keys over hidden columns, a listed child's keys against a hidden parent column).
- **Proof.** An engine test lists `staff(id,name,team,bonus)` and deletes one row inside a savepoint that it rolls back and another it commits: the rolled-back row keeps its hidden salary, badge and note, the deleted one is gone with its hidden index entries, and a key change is still refused. The MCP acceptance test now deletes a row of `users(id,name)` and gets `42501` for changing a key.

**Status:** code written, unbuilt (code-only mode, D355).
