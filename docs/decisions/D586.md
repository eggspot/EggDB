## D586 SQL Server's `GRANT` and `REVOKE` — Decided by the code-only session (2026-11-12, D355); roadmap M6b, D285

SQL Server's dialect refused `GRANT` and `REVOKE` outright, though the PostgreSQL dialect already
stores table and column privileges (D183, D285) that every dialect's checks read. The SQL Server
parser now hands both to the shared privilege parser, which also takes T-SQL's own spellings:
`ON OBJECT::schema.table`, and a column list after the table (`GRANT SELECT ON t (a, b) TO r`)
as well as before `ON`, which applies to every listed privilege that columns take (`SELECT`,
`INSERT`, `UPDATE`, `REFERENCES`); another privilege on columns is refused by name. `ON
SCHEMA::...` and the other securables are accepted and ignored with a warning, as the PostgreSQL
dialect treats grants on schemas. `WITH GRANT OPTION` and `CASCADE` read as they do there.

`DENY` stays refused: it is a permission that overrides grants, which the privilege model does
not have, and quietly granting nothing would be wrong in the other direction.

**Status:** code written, unbuilt (code-only mode, D355).
