## D1207 Metabase, Superset and Power BI connectors in their own plugin systems — Decided by the code-only session (2026-11-17, D355); roadmap M6f, our own connectors in each tool's plugin system (D46, D239)

- **What users get.** EggDB by name in three BI tools' lists of databases, not as "PostgreSQL":
  - **Metabase**: a driver plugin (`connectors/metabase-driver`: `metabase-plugin.yaml` and `metabase.driver.eggdb`) that registers `:eggdb` with Metabase's PostgreSQL driver as its parent, adds a choice of the SQL dialect native questions are written in (sent as the startup `options` `-c eggdb.dialect=...`, which EggDB's PostgreSQL listener reads), and states the features EggDB answers (foreign keys, nested queries, time zones, window functions).
  - **Apache Superset**: an engine spec package (`superset-eggdb`, `EggDBEngineSpec` on `PostgresEngineSpec`, through Superset's `superset.db_engine_specs` entry point) with `eggdb+psycopg2://` URIs.
  - **Power BI**: a Power Query custom connector (`EggDB.pq`), `EggDB.Database(server, database)` with user name and password and encryption, on Power Query's PostgreSQL function, for Power BI Desktop and the on-premises gateway.
- **How.** Each is written in the tool's plugin language (Clojure, Python, M: D16's rule for a tool's plugins) on that tool's own PostgreSQL support, since EggDB speaks the PostgreSQL protocol; none ships inside `eggdb`.
- **Left.** The Grafana data source plugin (Grafana already reads EggDB's Prometheus API), the connector's icons for the Power BI build, publishing each (accounts, the owner's), certification by Microsoft, and each tool in the compatibility job.
