## D358 MySQL's and Oracle's partition maintenance: add, drop, truncate, reorganize, split and exchange — Decided by the code-only session (2026-11-10, D355); extends D169 and D337

MySQL and Oracle manage named partitions with `ALTER TABLE`. EggDB keeps each named partition as
a table `<table>#P#<partition>` attached to its parent (D169), so every operation is built from
the pieces that already exist: create a copy of the parent and attach it with a bound, drop a
child table, take a child's rows and insert them through the parent so they are routed again.

- **ADD.** Range partitions start at the highest existing upper bound and must rise strictly
  (MySQL `1493`); list partitions are checked for overlap by the existing attach; on a hash table
  `ADD PARTITION PARTITIONS n` (or named hash partitions) rebuilds the table with the new modulus
  and routes every row again, since a row's partition depends on the count.
- **DROP** removes the child tables with their rows; never the last partition (`1508` /
  `ORA-14083`), never on a hash table (`1512`). The MCP and the shells' destructive-statement
  check reports it as `DropPartition`. **TRUNCATE** deletes the rows of the named partitions (or
  `ALL`) and is reported as `Truncate`.
- **REORGANIZE / SPLIT** rebuild: rows are read from the old partitions, the old partitions are
  dropped, the new ones created with bounds that continue from the lowest old start, and the rows
  inserted through the parent. Oracle's `SPLIT ... AT (v)` gives the first part `[from, v)` and
  the second `[v, to)`; `SPLIT ... VALUES (...)` moves those list values to the first part and
  must leave the second some. A reorganize of named hash partitions is not supported yet.
- **EXCHANGE** detaches the partition, swaps the two tables' names through the renaming
  `ALTER TABLE RENAME` uses, and attaches the former table under the partition's name, which
  checks every row against the partition's bound. `WITHOUT VALIDATION` is accepted but still
  checks, since a row outside its partition would be lost to every pruned query.

**Left:** `COALESCE PARTITION`, Oracle's `MERGE PARTITIONS` and `MODIFY PARTITION ... ADD VALUES`,
`REBUILD`, `ANALYZE`, `CHECK`, `OPTIMIZE` and `REPAIR PARTITION`, and subpartitions.
