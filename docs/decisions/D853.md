## D853 CQL user-type field selection — Decided by the code-only session (2026-11-12, D355); follow-up of D809

- A `SELECT` list takes `column.field` for a user-type column, with an optional alias. A user type is stored as a JSON
  array in field order (D809), so the field translates to `(column)::jsonb -> <position>`, named `column.field` (as
  Cassandra names it) or by its alias. Selecting a field of a column that is not a user type, or an unknown field, is
  refused.
- Translation now returns the selected result columns with their CQL types, and the server describes and encodes the
  rows from that list by position when it matches the result's width. A selected field is marked as a JSON element and
  encoded from the element's JSON with the field's type, so an unset field reads as null. This also gives an aliased
  collection or user-type column its real CQL type instead of the fallback from the SQL type.
- The system keyspaces refuse field selection; they hold no user types.
- Left: updating one field (`SET home.street = ...`).
