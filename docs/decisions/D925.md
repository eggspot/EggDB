## D925 CalDAV `expand` in `calendar-data` — Decided by the code-only session (2026-11-12, D355); roadmap M16, follow-up of D901

- A `calendar-query` or `calendar-multiget` whose `calendar-data` holds `<C:expand start=... end=.../>` gets each
  calendar object expanded as RFC 4791 section 9.6.5 says: a recurring component (with `RRULE` or `RDATE`) becomes one
  component per instance overlapping the range, each with its own `DTSTART`, `DTEND` and `RECURRENCE-ID` in UTC (or
  `VALUE=DATE` for all-day events) and without `RRULE`, `RDATE`, `EXDATE`, `DURATION` or `DUE`; an instance a
  component with its own `RECURRENCE-ID` overrides is left to that component, which appears when it overlaps the
  range; other components appear when they overlap; `VTIMEZONE` components are left out, since every time is UTC.
  Alarms and the other sub-components stay inside each instance.
- Recurrences use the same reader as the `time-range` filter (D901); a rule it does not follow keeps its component
  unexpanded, so the client still gets the event.
- Lines are written unfolded, as most clients accept; folding at 75 octets is left.

**Status:** code written, unbuilt (code-only mode, D355).
