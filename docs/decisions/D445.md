## D445 HL7 v2 message building and ACKs, FIX building, and FIX and EDIFACT name dictionaries — Decided by the code-only session (2026-11-11, D355); roadmap M16, extends D243

- `hl7_build(jsonb) → text` is `hl7_parse`'s inverse: the same array of `{segment, fields}`, with
  MSH-1 and MSH-2 giving the delimiters (HL7's defaults `|^~\&` otherwise). A field that is a plain
  array is components, an array holding arrays is repetitions of components, and a component that
  is an array is subcomponents, matching how `hl7_parse` writes them; the five delimiters inside
  values are escaped (`\F\ \S\ \R\ \E\ \T\`). Segments end with a carriage return.
- `hl7_ack(message [, code [, text]]) → text` acknowledges a message as HL7's original
  acknowledgment mode does: an MSH with the sender and receiver swapped, the statement's time,
  `ACK^<trigger>^ACK`, a control id of `ACK` and the original's, its processing id and version, and
  an MSA with the code (`AA` by default; `AE`, `AR` and the enhanced-mode `CA`, `CE`, `CR`), the
  original control id and an optional text.
- `fix_build(jsonb) → text` builds a FIX message from `fix_parse`'s `{tag, value}` array: tag 8
  (FIX.4.4 when absent) first, `BodyLength` (9) and `CheckSum` (10) computed (given ones are
  replaced), fields joined by SOH.
- Dictionaries, as data from the public specifications: `fix_tag_name(tag)` names 85 common FIX
  4.4/5.0 tags (session, order, execution and market-data fields), and
  `edifact_segment_name(tag)` names 41 common UN/EDIFACT segments; unknown ones give `NULL`.
- Left: full FIX and EDIFACT dictionaries with value enumerations and repeating-group layouts,
  FHIR validation, ISO 20022 and DICOM.
