## D243 Industry message formats parse into jsonb with SQL functions — Decided by the build loop (by judgement, 2026-10-31); refines D2 and D50

Track 4.X-15 asks for ASOF and window joins, bitemporal tables, order books, ledger primitives
and the FIX, ISO 20022, FHIR, HL7 v2, EDIFACT and DICOM formats. This slice does the three
delimited message formats.

- **Functions, not import tools.** `fix_parse`, `fix_field`, `hl7_parse` and `edifact_parse`
  are ordinary SQL functions returning `jsonb` (or `text` for `fix_field`), so a message can be
  parsed in a query, a generated column, a trigger or a pipeline, and its result indexed like any
  other document (D2). They live in `eggdb-sql`'s `standards` module, beside the other built-in
  functions, and depend on nothing.
- **Faithful structure.** FIX keeps every field in order as `{tag, value}` because tags repeat
  in groups; HL7 keeps HL7's field numbering, including `MSH-1` and `MSH-2`; EDIFACT keeps each
  segment's elements and components positionally. Meaning (field names per message type) comes
  from the dictionaries, which are a later step.
- **Checked, not guessed.** FIX's `BodyLength` and `CheckSum`, HL7's separators (five different
  symbols) and segment names, and EDIFACT's service string advice and release character are
  validated; a malformed message is SQLSTATE `22P02` with what is wrong.

Left: FIX and EDIFACT dictionaries (names per tag and segment), HL7 v2 message building and
ACKs, ISO 20022 XML and FHIR validation (FHIR resources already store as `jsonb`), DICOM, ASOF
and window joins, bitemporal tables and order books. X12 waits for its paid license (D50).
