## D571 `eggdb gui` in the command model — Decided by the code-only session (2026-11-12, D355); roadmap M6e, D191, D15

D191 left the desktop client reachable only as its own program, `eggdb-gui`, because a command
needs its place in the command model. `gui` is now a command there (`eggdb-commands`'
`programs::GUI`): one file operand, `--read-only`, no JSON form (like `ui`, `shell` and `mcp`), the
reading errors, and help and examples like every command; it is one of the kept top-level names
beside `ui`, its terminal sibling, rather than a `<noun> <verb>` pair, since it acts on the
implied noun, the database file. `eggdb gui app.db` runs the `eggdb-gui` found beside the running
`eggdb` with `--open app.db --no-create` (and `--read-only`), waits for it, and exits 0 when the
client did. The server binary never links the GUI (D15): it only starts the separate program,
and fails with `not_found` when that program is not installed beside it.

**Status:** code written, unbuilt (code-only mode, D355).
