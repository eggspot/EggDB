## D803 TLS client certificates and the cert login method — Decided by the code-only session (2026-11-12, D355); roadmap M6b, TLS client certificates

- `eggdb-tls`'s `ServerConfig` gains `client_authentication`: `None` (the default), `Optional { trust }` or
  `Required { trust }`. When set, the TLS 1.3 server sends a CertificateRequest (empty context, EggDB's signature
  schemes) after EncryptedExtensions, then after its Finished reads the client's Certificate, checks the chain to
  `trust` for `id-kp-clientAuth` with the same path search, validity and signature checks the client uses for servers
  (D161), reads and verifies the client's CertificateVerify over the transcript with TLS 1.3's client context string,
  and only then checks the client's Finished, whose transcript now covers those messages. An empty Certificate is
  accepted when optional and refused with `certificate_required` when required. The chain lands in
  `SessionInfo::peer_certificates`.
- TLS 1.2 has no CertificateRequest here yet: a server that requires client certificates refuses TLS 1.2 clients with
  `protocol_version`, and one that only asks for them serves TLS 1.2 clients without certificates.
- `eggdb serve` asks every TLS client for a certificate (optional) when `EGGDB_TLS_CLIENT_CA` names a PEM file of
  certificate authorities, so password logins keep working beside certificate logins; an environment variable keeps the
  command-line surface (and its documented option table) unchanged until the option is designed with the other
  listener options.
- The rule file gains `cert`, as PostgreSQL's `cert` method: the user logs in when the TLS layer verified a client
  certificate whose subject common name is the user name, and a stored role with `LOGIN` has that name; no password is
  asked. A connection without a certificate, or with another name, is refused like a wrong password.
- Left: TLS 1.2's CertificateRequest and CertificateVerify, subject alternative names and user-name maps, a `serve`
  option, and psql with `sslcert` in the `tls-clients` CI job.
