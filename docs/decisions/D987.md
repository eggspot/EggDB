## D987 `eggdb-mongo-compare`: EggDB's MongoDB wire protocol against MongoDB — Decided by the code-only session (2026-11-13, D355); roadmap M9, a benchmark against MongoDB (D7, D197)

- A crate of its own workspace, `crates/eggdb-mongo-compare`, excluded from the main workspace and never shipped,
  like the other comparisons (D94, D177, D985). It reuses the bench harness and the YCSB mix of the SQLite
  comparison (D954), builds its documents with `eggdb-bson` and signs in with SCRAM-SHA-256 through `eggdb-crypto`, so
  no third-party crate and no MongoDB driver is involved.
- Server against server: `eggdb serve --mongo-listen` and MongoDB 7 on the same machine get the same `OP_MSG` commands
  over loopback from one client: batched inserts of 100 documents, range finds on an unindexed field, a `$group`
  aggregation, and YCSB workloads A to F over 100,000 records keyed by `_id` (reads by `_id`, `$set` updates, inserts,
  `_id` range scans and read-modify-writes). Ratios and nanoseconds per operation are reported, not gated.
- Workloads D and E insert past the loaded records, so the records are loaded again before the next workload.
- MongoDB runs without access control in CI; EggDB with its server password, so EggDB's numbers include nothing
  MongoDB's skip except one sign-in per run.
- CI's `mongo-compare` job runs MongoDB 7 as a service, starts EggDB, runs the comparison and keeps the results as an
  artifact; `check` waits for it. Releases update its lock file with `cargo update -p eggdb-bson -p eggdb-crypto`
  (CLAUDE.md, Releases).
