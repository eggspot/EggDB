## D833 OPC UA binary values in SQL — Decided by the code-only session (2026-11-12, D355); roadmap D57, OPC UA, Modbus and Sparkplug ingest

- `opcua_decode(bytes bytea [, 'datavalue' | 'variant'])` returns `jsonb`: one value in OPC UA's binary encoding
  (IEC 62541-6), written from the specification: a DataValue (the default) as `{value, status, source_timestamp,
  source_picoseconds, server_timestamp, server_picoseconds}` with the members its mask holds, or a Variant as
  `{type, value}` with `dimensions` for a multi-dimensional array.
- Every built-in type but DiagnosticInfo is read: integers exactly (Int64 and UInt64 as JSON numbers), floats (NaN
  and infinities as strings), Strings and XmlElements as text, DateTimes (100 ns ticks since 1601) as UTC timestamps
  (0 and the maximum as null), Guids in their usual text form, ByteStrings as hex, NodeIds and ExpandedNodeIds as
  `{namespace, id, namespace_uri, server_index}`, QualifiedNames, LocalizedTexts, ExtensionObjects (`type_id` and the
  body as hex or XML text), and nested DataValues and Variants up to 16 levels.
- Lengths are checked against the bytes before anything is allocated, and bytes left after the value are an error,
  so hostile input is `22P02`, never a panic. DiagnosticInfo is `0A000`.
- Left: an OPC UA client (secure channel, sessions, subscriptions) to ingest values as they change.
