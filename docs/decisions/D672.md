## D672 Redis Functions: FUNCTION and FCALL — Decided by the code-only session (2026-11-12, D355); roadmap M7, Lua scripting and Redis Functions (D27, D193)

- `FUNCTION LOAD [REPLACE]`, `DELETE`, `FLUSH [SYNC|ASYNC]`, `LIST [WITHCODE] [LIBRARYNAME pattern]`, `STATS` and
  `KILL`, and `FCALL` and `FCALL_RO`, in `eggdb-resp/src/functions.rs`. A library's code starts with
  `#!lua name=<library>`; loading runs it once in a fresh interpreter where `redis.register_function` (both the
  `(name, callback)` and the `{function_name=, callback=, description=, flags=}` forms) records the functions and
  `redis.call` is refused. Function names are unique across libraries, as in Redis.
- `FCALL` runs the library's code again in a fresh interpreter, then calls the function with the `keys` and `args`
  tables, in one keyspace transaction as `EVAL` does (D671). A function flagged `no-writes` runs in a read
  transaction; `FCALL_RO` refuses any other function with Redis's "write flag" error. Running the code once per call
  keeps no interpreter between calls: the interpreter is single-threaded (`Rc`) and connections run on their own
  threads, so a kept state could not be shared.
- The scripting state is renamed `Scripts` (from D671's `ScriptCache`): it now holds the script cache and the
  function libraries, shared by one server's connections.
- Libraries live in memory and are gone after a restart. Redis keeps them in its RDB and AOF files; keeping them in
  the keyspace's storage, and `FUNCTION DUMP` and `FUNCTION RESTORE` with them, are left for later.
