## D1182 Realtime channels in Supabase's style, from the engine's change capture — Decided by the code-only session (2026-11-15, D355); roadmap M6a, follows D878 and D1178

- `GET /realtime/v1/websocket` on the REST listener upgrades (D1178) to the Phoenix channel protocol that `supabase-js`'s realtime client speaks: messages as JSON objects (`vsn=1.0.0`, the client's default) or as `[join_ref, ref, topic, event, payload]` arrays (`vsn=2.0.0`). Because a browser cannot set headers on a WebSocket, a WebSocket request without `Authorization` may carry its token as the `apikey` or `access_token` query parameter, verified exactly as a bearer token under `--auth-rules`.
- **Events.** `heartbeat` on `phoenix` and `access_token` are answered `ok`; `phx_join` reads the channel's `config`: `postgres_changes` entries (`event` `*`, `INSERT`, `UPDATE` or `DELETE`, `schema`, one `table`, and an optional PostgREST-style `filter` with `eq`, `neq`, `lt`, `lte`, `gt`, `gte` or `in`) get ids in the `phx_reply`, then a `system` "Subscribed to PostgreSQL" message and an empty `presence_state`, as the client waits for; `phx_leave` ends a channel; `broadcast` comes back to its sender when the channel's config says `broadcast.self`. Joining a table the caller may not read fails the join with the SQL error as its reason.
- **Changes.** `eggdb_sql::cdc::captured_changes_after` reads D1030's capture records after a sequence, decoded into each row before and after as JSON, without moving any consumer's position (a follower, best-effort where a consumer is at-least-once); `latest_capture_sequence` is where a new socket starts. Every 250 ms a socket with listeners reads the commits since its position and sends each matching change as a `postgres_changes` event with `type`, `record`, `old_record`, `schema`, `table` and `commit_timestamp`. It needs capture on (`eggdb serve --cdc-capture engine`), as Supabase needs a publication. Row-level security is checked when a channel joins (the caller must be able to read the table), not per row, unlike Supabase's per-row check; per-row checks, broadcast between sockets and presence are left.
- Tests: `filters_follow_supabase_realtime` and `messages_are_objects_or_arrays_by_protocol_version` in `realtime_channels.rs`, `realtime_channels_join_postgres_changes_and_answer_heartbeats` in `eggdb-api`.

**Status:** code written, unbuilt (code-only mode, D355).
