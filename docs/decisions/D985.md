## D985 `eggdb-opensearch-compare`: EggDB's search API against OpenSearch — Decided by the code-only session (2026-11-13, D355); roadmap M8, a benchmark against OpenSearch (D7, D196)

- A crate of its own workspace, `crates/eggdb-opensearch-compare`, excluded from the main workspace and never shipped,
  like the SQLite and Redis comparisons (D94, D177). It reuses the bench harness, baseline and measuring code and talks
  HTTP through `eggdb-http`'s client, so no third-party crate is involved.
- Both servers run on the same machine and get the same requests over loopback HTTP: `_bulk` batches of 100
  documents, document reads by id, `match` searches and a `terms` aggregation over 10,000 documents with the same
  mappings (`text`, `keyword`, `long`). EggDB runs as `eggdb serve --es-listen`, not embedded, so both pay the same
  HTTP costs. Ratios and nanoseconds per request are reported, not gated, as for Redis.
- Without both servers the program says so and exits successfully.
- CI's `opensearch-compare` job runs OpenSearch 2.11.1 as a service (security plugin off, 1 GiB heap), builds and
  starts EggDB, runs the comparison, and keeps its results as an artifact; `check` waits for it. Its lock file holds
  only our own path crates; releases update it with `cargo update -p eggdb-http` like the other compare crates
  (CLAUDE.md, Releases).
