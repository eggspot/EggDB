## D1355 RESP keys read with Redis-compatible commands from the CLI and MCP; vectors through the existing tools — Decided by the code-only session (2026-11-25, D355); roadmap M6d "Tools that query documents, search indexes, vectors, graphs and keys in their own query languages (D10, D11)", the keys and vectors parts

- **What users get.** `eggdb resp get <file> <command>` runs one Redis-compatible command that reads (as `redis-cli` takes it) on the keys `eggdb serve --resp-listen` serves, database 0, on a read-only open, and prints `{"reply": ...}`. Agents get the twin `resp_get`.
- **Reading only.** The file is opened read-only, so a command that writes fails in storage, never half-applied. Commands that block (`BLPOP`, `BZPOPMIN` and the rest), subscribe, or change the connection (`SELECT`, `MULTI`, `EXEC`, `WATCH`, `CLIENT`, `AUTH`, `HELLO`, `RESET`, `QUIT`, `SWAPDB`, `WAIT`, `MONITOR`, `SHUTDOWN`, `DEBUG`) are refused before they run, since one call has no connection to keep and must never wait. Each call runs `eggdb_resp::execute` with a fresh authenticated RESP3 client and no script cache (`EVAL_RO` runs, `EVALSHA` finds nothing).
- **Who gets it.** `resp_get` reads beneath SQL's privileges like `kv_get`, so it has the grant `key_value_store`: it is withdrawn under `--tables` and refused for an agent acting as a role (D328).
- **JSON form.** Text as a string, bytes that are not UTF-8 as `{"hex": ...}`, integers and finite doubles as numbers (others as text), nil as `null`, arrays, sets and pushes as arrays, and maps and pairs as arrays of `[key, value]`, since a map's keys need not be text. A reply over 1 MiB is refused as `too_large` with how to read less.
- **Vectors.** Vector search already has a query language in two tools: `run_sql` with the pgvector-compatible operators and functions (D2), and `search_get` with the query DSL's `knn` (D196, D1354). A third tool would only repeat them, so the roadmap item's vectors part is answered by those two.
- **Left.** Databases other than 0 (a `db` argument), writing commands through a `resp_run` tool with confirmation, and `SCAN` cursors across calls (each call stands alone; `SCAN` with a cursor works but the agent carries it).
- **Proof.** The command model's parity test restores a `SET`, an `HSET` and a `ZADD` from a hand-written AOF with `eggdb restore`, compares `resp_get` with `eggdb resp get --json` for a string, a hash, a sorted set with scores, `EXISTS` and a missing key, and checks that a write, a blocking pop, a subscribe and an unknown command are `resp_error`; a unit test pins the `redis-cli` splitting; the tools list counts 16 tools read-only and 28 with `--allow-write`.

**Status:** code written, unbuilt (code-only mode, D355).
