## D492 Kafka `CreateTopics` and `DeleteTopics` — Decided by the code-only session (2026-11-11, D355); roadmap M16, D213

- `CreateTopics` versions 0–1 (`ApiVersions` lists them): each topic is created with its partition
  count (`-1` for one, at most 1,024) when its name is valid and it does not exist yet; the
  replication factor must be `-1` or `1` and explicit replica assignments are refused, since EggDB
  is one broker. Version 1's `validate_only` checks without writing, and its answer carries an
  error message per topic. Errors use Kafka's codes: `TOPIC_ALREADY_EXISTS` (36),
  `INVALID_TOPIC` (17), `INVALID_PARTITIONS` (37), `INVALID_REPLICATION_FACTOR` (38). Topic
  configs are read and ignored.
- `DeleteTopics` versions 0–1 delete each topic with every record of its partitions in one write,
  answering `UNKNOWN_TOPIC_OR_PARTITION` for a missing one; version 1 adds the throttle time.
- Producing to a missing topic still creates it with one partition, as `auto.create.topics.enable`
  does by default. Flexible (compact) request versions and SASL are not written.
