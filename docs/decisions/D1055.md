## D1055 Kafka Connect's REST API and worker protocol in eggdb-connect — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D46)

- D46 asked for Kafka Connect's REST and worker protocol in Rust, with our own connectors, so tools that manage Connect
  clusters work with EggDB. `eggdb-connect` serves the REST API on `--connect-listen` (loopback only: Connect's REST API
  has no authentication of its own) and runs a worker inside the server.
- **REST.** The documented paths and answers: the root (version), plugins and config validation (with each field's
  errors), connectors listed (also expanded with status and info), created (`201`, `409` when the name is taken),
  read, reconfigured with `PUT .../config` (creating when missing), status, tasks, offsets, pause and resume (`202`),
  restart, delete (`204`). Errors carry Connect's `error_code` and `message` body.
- **Worker.** Every half second the worker runs one step of each running connector from its stored position and keeps
  the new one; configurations, states (running, paused, failed with the reason as its trace) and positions live in the
  `connect` collections, so a restart resumes every connector. One task per connector.
- **Connectors, in Rust.** A file source (complete new lines of a file, each a record of the topic, the byte position
  kept), a file sink (records of one topic's partition 0 appended to a file, synced, then the next offset kept, so
  at least once) and a topic copy. They also answer to the Apache file connectors' class names, so existing
  configurations run unchanged. Kafka records are written and read through `eggdb_kafka::publish` and the new
  `eggdb_kafka::read_records` (committed records only).
- **Worker protocol.** `protocol` encodes and decodes the join metadata (version, URL, configuration offset) and the
  leader's assignment (error, leader, leader URL, configuration offset, connectors with their task numbers, -1 for the
  connector itself) of Connect's default protocol, and the leader's round robin of connectors and then tasks. One
  server runs one worker today; joining several servers' workers into one group through the Kafka coordinator is
  left.
- Kafka is a trademark of the Apache Software Foundation. Learned from Kafka Connect's REST API documentation and
  KIP-415's description of the connect protocols; no code was read.
