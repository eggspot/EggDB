## D949 A benchmark of bulk writes inside a transaction per dialect — Decided by the code-only session (2026-11-13, D355); roadmap M3, the measurement D317 asked for

- `eggdb-bench` gains `sql_mysql.bulk_write_in_transaction`, `sql_sqlite.…`, `sql_oracle.…` and `sql_sqlserver.…`.
  Each transaction is the dialect's own begin (`START TRANSACTION`, `BEGIN`, `BEGIN TRANSACTION`, or none for
  Oracle's implicit transactions), four multi-row `INSERT`s of 100 new keys each, and `COMMIT`, on one session.
- The reference is the same work in PostgreSQL's dialect, which has no statement-level rollback (an error aborts the
  whole block), so the ratio `ratio_to_postgresql` isolates what statement-level rollback costs: the extra read per
  key for its before-image. `ns_per_row` is reported beside it.
- The lines start without a baseline: a missing ratio line only warns (D80), and the first measured run on CI's
  runners sets them in the Saturday performance pass (D7).
