## D449 SQL Server's `sp_sequence_get_range` — Decided by the code-only session (2026-11-11, D355); roadmap M10

- `EXEC sp_sequence_get_range @sequence_name = N'name', @range_size = n, @range_first_value = @f
  OUTPUT [, @range_last_value = @l OUTPUT] [, @range_cycle_count = @c OUTPUT] [,
  @sequence_increment = @i OUTPUT] [, @sequence_min_value = @lo OUTPUT] [, @sequence_max_value = @hi
  OUTPUT]` reserves `n` values at once, as SQL Server documents, with arguments by name or by
  position. It takes the range's first value with `NEXT VALUE FOR` and moves the sequence past the
  range with `ALTER SEQUENCE ... RESTART WITH`, both through the session's own statements, so the
  sequence's session cache, transaction and rights rules are the usual ones.
- The outputs come back as `bigint` (SQL Server returns `sql_variant` of the sequence's type) and the
  cycle count is 0. A range that would pass the sequence's bounds is error 11732 and a size below 1
  error 11733; a cycling sequence's wrap-around inside a range is not reproduced. An unknown sequence
  is error 208; an unknown parameter error 8145.
