## D776 An in-process inbox for embedded consumers, with a redelivery limit — Decided by the code-only session (2026-11-12, D355); roadmap M16, a dead-letter queue for rejected messages and an in-process inbox (D217)

- `eggdb::inbox::Inbox` is the embedded API to the queue store (`eggdb-queues`, D214) the messaging servers share:
  `open(db, queue)` declares the queue, `send` appends, `receive(wait)` leases the oldest visible message (polling
  every 50 ms while it waits, since an embedded database has no server to push), and `settle` or `handle` finish it as
  done, retried or rejected. Rejected messages use D540's dead-letter queue `<queue>.dlq`.
- The redelivery limit D540 left out: a message whose receive count passes `with_max_receives` (5 by default) is
  moved to the dead-letter queue on that receive instead of being handed out, so one poison message cannot stall a
  consumer forever. It applies to inbox consumers; the servers keep their protocols' own rules.
- The adapter that maps a protocol's key-value databases onto an EggDB file's collections (`DatabaseKeyspace` and the
  collection prefixes) moved from the command-line program into the library as `eggdb::keyspace`, unchanged, so the
  inbox and the servers read the same queues. `eggdb serve` uses it from there.
- Notification when a message arrives (instead of polling), and an inbox for the other queue-like stores (Kafka
  topics, NATS streams) are left.

**Status:** code written, unbuilt (code-only mode, D355).
