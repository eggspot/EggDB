## D1197 Key sources on Azure and Google Cloud — Decided by the code-only session (2026-11-17, D355); roadmap M6b (D23, D187); security-critical (D35)

- **What users get.** `--key-source` (D1196) also reads the database key from an Azure Key Vault secret (`azure-keyvault:<vault>/<secret>`), a Google Cloud Secret Manager secret version (`gcp-secret:projects/.../versions/...`) and Google Cloud KMS, which decrypts a wrapped key kept in a file (`gcp-kms:<key name>@<file>`).
- **Tokens.** An access token in `AZURE_ACCESS_TOKEN` or `GOOGLE_OAUTH_ACCESS_TOKEN`, so any login flow the operator uses works; without one, the machine's own identity: Azure's instance metadata service (`Metadata: true`) and Google's metadata server (`Metadata-Flavor: Google`), which answer only inside the cloud. The token goes only to the cloud's own hosts (`*.vault.azure.net`, `secretmanager.googleapis.com`, `cloudkms.googleapis.com`), over TLS with certificate checks; resource names are checked to plain characters so they cannot change the URL's host.
- **Proof.** Unit tests refuse a malformed vault name and a secret name outside `projects/`.
- **Left.** A native PKCS#11 source.
