## D1048 Databases per tenant moved and rebalanced online — Decided by the code-only session (2026-11-13, D355); roadmap M15 (D18, D32)

- A server of a data directory holds one database file per tenant (D32's tenancy by database). `--moves-listen
  <address>` lends its databases to other servers; `MOVE DATABASE <name> FROM 'host:port'`, run by a superuser on the
  receiving server, takes one in. The listener uses the replication protocol's frames and login (TLS off this
  machine).
- **The move.** The lender backs the database up online and streams it while it keeps taking writes; the receiver
  stages it next to its directory. The receiver then asks for the freeze: the lender fences the database and waits
  for the write transaction open at that moment to finish (`Database::fence_and_drain`), computes the differential
  against the copy it sent (`backup_differential_to`, D1019's change format) and streams it. The receiver replays it
  onto the staged copy, puts the file in place, starts serving it, and confirms; the lender keeps its copy fenced
  with a message naming the new server. Writes pause only for the differential, not for the full copy. If anything
  fails before the confirmation, the lender lifts the fence and the receiver drops its staged files, so the database
  stays where it was.
- **Rebalancing.** `eggdb_cluster::databases::plan_database_moves` plans whole-database moves from the server holding
  the most bytes to the one holding the fewest, always the largest database smaller than the gap between them, so
  every move narrows it and the plan ends; the moves are run with `MOVE DATABASE`.
- Found while writing this: the `SWITCHOVER` statement check sliced the statement's first bytes and could panic on a
  statement starting with a multi-byte character; it and the new `MOVE` checks now compare with `str::get`.
- Left: a process that measures sizes and runs the plan by itself, and keeping the moved database's old file until an
  operator removes it.
