## D830 PostgreSQL's single-byte encodings in COPY — Decided by the code-only session (2026-11-12, D355); roadmap D30

- `COPY ... ENCODING` now reads and writes every single-byte encoding PostgreSQL has beyond the four it had (UTF8,
  LATIN1, LATIN9, WIN1252): WIN1250, WIN1251, WIN1253 to WIN1258, WIN866, WIN874, KOI8R, KOI8U, LATIN2 to LATIN8,
  LATIN10 and ISO_8859_5 to ISO_8859_8, under PostgreSQL's names and aliases (`win`, `alt`, `koi8`, `abc`, `tcvn`,
  `vscii`, `windows1251`, `cp1251`, `iso88595`...), matched case- and punctuation-insensitively as before.
- Each encoding is a table of its high half (`copy/single_byte.rs`, bytes 0x80 to 0xFF to code points, 0 where the
  encoding defines no character), generated from the Unicode Consortium's mapping tables as Python's codecs carry
  them, not copied from PostgreSQL. Bytes the table leaves undefined are `22021` on reading; characters with no byte
  are `22P05` on writing, as for WIN1252.
- Left: the multi-byte encodings (EUC_*, SJIS, BIG5, GBK, GB18030, UHC, JOHAB), `client_encoding` on the wire, and
  the MySQL, SQL Server and Oracle character set lists.

**Status:** code written, unbuilt (code-only mode, D355).
