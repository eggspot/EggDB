## D1295 SQL Server's HASHBYTES, STRING_ESCAPE and APP_NAME — Decided by the code-only session (2026-11-18, D355); roadmap M4 SQL Server compatibility (D10, D1292)

- **What users get.** In SQL Server's dialect: `HASHBYTES('MD5' | 'SHA' | 'SHA1' | 'SHA2_256' | 'SHA2_512', input)` (`varbinary` of the digest, of text's UTF-8 bytes or binary data's bytes; NULL for an algorithm it does not name, as SQL Server does for MD2 and MD4 on new versions), `STRING_ESCAPE(text, 'json')` (quotes, backslashes, slashes and control characters escaped as JSON) and `APP_NAME()` (empty: EggDB's sessions carry no application name yet). Change tracking and ETL procedures hash rows with `HASHBYTES`, and procedures that build JSON by hand use `STRING_ESCAPE`.
- **How.** Beside D1292's functions, with the digests of EggDB's own `eggdb-crypto`. Text is hashed as UTF-8, where SQL Server hashes `varchar` in its code page and `nvarchar` as UTF-16: the same digest for ASCII `varchar`, a different one for `nvarchar`.
- **Left.** `nvarchar`'s UTF-16 hashing, `FORMATMESSAGE`, `COMPRESS`/`DECOMPRESS`, `BINARY_CHECKSUM` and `IDENT_CURRENT`.
- **Proof.** A unit test escapes a quote, a backslash, a slash and a newline.

**Status:** code written, unbuilt (code-only mode, D355).
