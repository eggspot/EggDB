## D522 MCP writes over HTTP — Decided by the code-only session (2026-11-11, D355); roadmap M6d

`--mcp-token-file` lines take `writes=confirmed` (or `writes=none`, the default): that agent's
HTTP sessions are started with `allow_write`, so they offer `write_sql` and, without a role, the
key-value write tools, exactly as `eggdb mcp --allow-write` does over stdio (D190).

- **Confirmation over HTTP:** over stdio a destructive statement is confirmed by the user
  through the client's `elicitation/create` when the client offers it. Streamable HTTP without a
  server-to-client event stream cannot send the client a request in the middle of a call, so
  `ServerConfig` gains `asks_mid_call` (true for stdio, false for HTTP): when false the server
  never chooses elicitation, and every destructive statement needs the agent's `confirm: true`,
  recorded in the audit log as `confirm_argument`, the path stdio already takes for clients
  without elicitation.
- **Per agent:** the option sits on the token's line, so one agent may write while others stay
  read-only; the role on the line still decides what its statements may touch (D183, D190), and
  its time limit and quota (D491) still apply.
- **Left out:** asking the user over a server-sent event stream (it waits for GET event streams,
  D487), and OAuth for remote MCP servers.

**Status:** code written, unbuilt (code-only mode, D355).
