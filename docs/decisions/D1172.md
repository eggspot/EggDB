## D1172 pgAdmin, DBeaver and SSMS checked in CI through the code their windows run — Decided by the code-only session (2026-11-15, D355); roadmap M6a (tools in CI)

- D163 counts a tool as supported once a CI job runs it or replays what it sends. The three GUI tools could not run in CI as desktop apps; each has a headless form that runs the same metadata code, and the new `gui-tools` job in `ci.yml` (in `check`'s `needs`) runs those against `eggdb serve`:
  - **pgAdmin 4:** its official image `dpage/pgadmin4` (PostgreSQL License) in server mode on the runner's network. `scripts/gui-tools/pgadmin.py` (standard library only) drives pgAdmin's own HTTP endpoints, the ones its browser UI calls: sign-in, register a server, connect, list databases, schemas, tables, columns, indexes and constraints, the table's properties and SQL tab (pgAdmin's reverse-engineered DDL, its heaviest catalog work), views, sequences, functions, the dashboards, and the query tool. CSRF checks are turned off by pgAdmin's own `PGADMIN_CONFIG_*` settings, as the client is a script.
  - **DBeaver:** CloudBeaver (`dbeaver/cloudbeaver`, Apache-2.0) is DBeaver's web edition and uses the same DBeaver PostgreSQL plugin and pgjdbc. `scripts/gui-tools/cloudbeaver.py` signs in over its GraphQL API (the administrator configured by its `CB_ADMIN_*` settings; the password sent as its web client sends it, an upper-case MD5), creates and opens a connection, walks the navigator to the table's columns, the view, the sequence and the function, and runs a query in the SQL editor. DBeaver's MySQL and TDS support stay "expected to work" until the job adds those connections.
  - **SSMS:** its licence keeps SSMS itself out of CI (D163). Object Explorer and Generate Scripts are built on SQL Server Management Objects, which Microsoft publishes under MIT; `crates/eggdb/tests/clients/dotnet/SmoCheck` uses SMO 172 over Microsoft.Data.SqlClient to list databases, schemas, tables with their columns, indexes, foreign keys and checks, procedures and views of the sqlpackage fixture, and scripts the tables with `Scripter`.
- Each tool fails the job when a request fails or an expected object is missing, rather than by comparing full transcripts: the tools' labels and ordering change between their releases, the objects do not. Their outputs and the containers' logs are kept as artifacts.
- `scripts/gui-tools/library.sql` is the PostgreSQL fixture: two schemas, an identity and a serial key, a foreign key, a check, an array column, an index, a view, a sequence, a SQL function and a table comment. SMO reads the existing sqlpackage fixture.
- The tools' endpoint paths and GraphQL fields were written from pgAdmin's and CloudBeaver's public source and documentation (both permissive); the first CI run on the built code confirms them, and a renamed endpoint is fixed in the script, not in EggDB.
- `docs/compatibility.md` marks pgAdmin, DBeaver for PostgreSQL, and SSMS through SMO as supported, code written and unbuilt.

**Status:** code written, unbuilt (code-only mode, D355).
