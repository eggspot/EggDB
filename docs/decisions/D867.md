## D867 Audit chains signed with the server's key — Decided by the code-only session (2026-11-12, D355); follow-up of D818

- `eggdb-crypto` gains Ed25519 signing (`ed25519_sign`, `ed25519_public_key`, RFC 8032, checked against its test
  vectors) beside verification. It runs on the same variable-time arithmetic, so it is documented as fit for signing
  EggDB's own digests, where an attacker cannot time many signatures, and not for signing on request.
- `eggdb serve` with `EGGDB_AUDIT=1` and `EGGDB_AUDIT_SIGNING_KEY=<file>` (the private key's 32-byte seed as 64 hex
  digits; serve refuses to start when the file is unreadable or malformed) appends a `chain_signed` record every
  1,000 records, next to the digest it already prints: the signature of `eggdb audit chain <digest>` for the digest
  of the line before, the public key, and the time. It prints the public key at start. The record is chained like any
  other, so removing it breaks the chain.
- `eggdb audit <db> --verify` checks every `chain_signed` record and fails with `audit_signature_invalid` at the first
  that does not hold. With `EGGDB_AUDIT_PUBLIC_KEY=<hex>` it also requires the signatures to be by that key and at
  least one to exist (`audit_unsigned` otherwise), so a file rewritten whole by someone without the key no longer
  verifies; the output says how many signatures hold and which lines the newest covers. Records after the newest
  signature are covered by the chain and the anchor (D818) only.
- `eggdb audit` lists the records as "chain signed by the server's key ...".
- Left: keeping the private key in a KMS or HSM rather than a file.
