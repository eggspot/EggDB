## D583 CQL prepared statements shared between connections — Decided by the code-only session (2026-11-12, D355); roadmap M16, D218

Cassandra drivers prepare a statement on one connection of their pool and execute it on any
other; EggDB kept prepared statements per connection, so an `EXECUTE` on another connection
answered `UNPREPARED` and the driver had to prepare again on every connection. Prepared
statements now live in one map the whole process shares, keyed by the same id as before (an MD5
of the keyspace and the text), holding only the text and keyspace, from which each execution
translates the statement against its own store; an id therefore means the same statement on
every connection and every listener. The map keeps at most the same 10,000-entry limit and is
cleared when a new statement would pass it, after which drivers re-prepare on `UNPREPARED` as
they do after a Cassandra restart.
