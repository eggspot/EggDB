## D466 `INSERT ... ON CONFLICT ... DO UPDATE SET ... WHERE` — Decided by the code-only session (2026-11-11, D355); roadmap M6a, extends D324

- PostgreSQL's and SQLite's upsert take a `WHERE` after `DO UPDATE SET`. It sees the existing row
  (by column name or the table's name) and the proposed row as `EXCLUDED.c`, like the
  assignments. When it is not true for a conflicting row, that row is left alone: no update, no
  row in `RETURNING`, not counted in `INSERT 0 n`, and no update triggers fire, as PostgreSQL
  does. Aggregates are refused in it.
- `OnDuplicate::Update` carries the filter; MySQL's `ON DUPLICATE KEY UPDATE` has none. Name
  resolution, privilege checks and the destructive-statement check read it with the
  assignments.
- Left in this roadmap line: partial unique indexes and indexes on expressions with their
  inference, and `COLLATE`/operator classes on conflict target columns.
