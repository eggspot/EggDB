## D1209 Spark and Trino connectors — Decided by the code-only session (2026-11-17, D355); roadmap M6f, Spark, Flink, Trino and Presto connectors (D46, D239)

- **What users get.** `spark.read.format("eggdb")` and `df.write.format("eggdb")` in Apache Spark (`connectors/spark-eggdb`: a `DataSourceRegister` named `eggdb` that builds the connection from `host`, `port`, `database`, `sslmode` and an optional `dialect` for `query` text, then hands every other option to Spark's own JDBC source, so partitioned reads, pushdown and batched writes work as Spark documents them), and `connector.name=eggdb` in Trino (`connectors/trino-eggdb`: a plugin registering Trino's PostgreSQL client module under the name `eggdb`, with its pushdown).
- **How.** Each in its engine's plugin system (Scala, Java: D16's rule), on that engine's PostgreSQL support and the PostgreSQL JDBC driver, since EggDB speaks the PostgreSQL protocol; the `dialect` reaches EggDB as the startup `options` `-c eggdb.dialect=...`. EggDB's own JDBC driver (`jdbc:eggdb:`) stays embedded and is not used here: a cluster's executors reach one server, not one file.
- **Left.** Flink and Presto (their PostgreSQL connectors reach EggDB today; plugins of their own are not written), type mappings of EggDB's own types (vectors, geometries) in each engine, and the compatibility job.
