## D425 MySQL's `JSON_VALUE` and `JSON_TABLE` with MySQL's path language — Decided by the code-only session (2026-11-11, D355); roadmap M10

- MySQL 8's `JSON_VALUE(doc, path [RETURNING type] [... ON EMPTY] [... ON ERROR])` and
  `JSON_TABLE(doc, path COLUMNS (...)) [AS] alias` have the SQL standard's shape, so the MySQL
  dialect now goes through the same parser and evaluator as PostgreSQL's and Oracle's (D289,
  D302): the internal query call and the `JSON_TABLE` row function. MySQL has no `PASSING`, and
  `JSON_EXISTS` and `JSON_QUERY` stay outside its dialect, as MySQL has neither.
- **Paths.** MySQL's path language is a subset of SQL/JSON's lax mode (`$`, `.key`, `."key"`,
  `[n]`, `[*]`, `.*`, `[last]`, `[last-n]`, `[m to n]`), with one spelling of its own: the
  recursive wildcard `**` may follow `$` or a member directly (`$**.price`), where SQL/JSON's
  extension writes `.**`. A literal path is rewritten (`sql_json::mysql_path`, outside quoted
  keys) when parsed; a path that is not a literal reaches the evaluator as written, so `$**` in a
  path built at run time is refused as a syntax error: a known difference.
- **Columns.** `JSON_TABLE`'s columns take MySQL's types (`INT`, `VARCHAR(n)`, `DECIMAL(p,s)`,
  `JSON`), `FOR ORDINALITY`, `EXISTS PATH`, `PATH` with `ON EMPTY`/`ON ERROR`, and `NESTED [PATH]`.
  MySQL requires the alias; EggDB accepts its absence.
- Errors are SQL/JSON's SQLSTATEs (`22034`, `2203F`, `22035`) where MySQL gives its own numbers
  (3141, 3156): left for the error-number pass.
