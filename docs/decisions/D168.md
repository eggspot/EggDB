## D168 A checkpoint that cuts segments off writes one header slot; the copy waits until the cut space is reused — Decided by research (build loop, 2026-10-31); refines D89 and D97

Part 4.M2-2 asked for `Normal` commits that sync as rarely as SQLite's. D97 left
`sqlite_compare.batch_put_normal` at about 1.1 because each long commit syncs four times. Two of
those syncs are header writes: the new slot, and its copy in the other slot, written so that no
slot names a log through pages the checkpoint cut off the file.

**The copy is only needed once the cut pages hold something else.** The other slot names a log
through the cut segments. While those pages hold the old segments, or new log segments, that
slot is still safe to open:
- a new segment written there carries a sequence above that slot's reservation, so it is
  refused, not misread;
- the old segments still replay to the same commits.

The danger D89 guards against starts only when a page of the cut range is written as data or as
a free-list page. A damaged newest slot would then open the older one over newer pages. So the
writer remembers the cut range. It writes and syncs the copy just before the first such page is
handed out: a data page allocated at the end of the file, or a free-list page placed there by a
commit or a checkpoint. Any other superblock write in between ends the wait (the older slot is
then the cutting header, whose log does not reach the cut pages). So does the next open for
writing, which already makes the older slot a copy (D89) before it shortens the file.

**Results.** In the steady state of `batch_put`, nothing grows into the cut space, so a cutting
checkpoint syncs once for its header instead of twice: three syncs per long commit instead of
four. The format is unchanged: readers accept exactly what they accepted before, and only
the writer's order of header writes changes. Since it touches the file's crash guarantees, it
is reviewed as a security-critical change (D35). The tests:
- a cutting checkpoint leaves the older slot as it was, and the open for writing copies it;
- allocating into the cut space copies the header before the page is handed out;
- the crash sweeps over a cutting checkpoint in `Full` and `Normal` still keep every commit.
