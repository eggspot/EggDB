## D1305 Aggregates the program defines, and any_value — Decided by the code-only session (2026-11-24, D355); roadmap M6 drivers (D16, D957) and M4 functions (D10)

- **What users get.** A program using the C API defines its own SQL aggregates on an embedded session with `eggdb_sql_create_aggregate(sql, name, arguments, step, finish, user_data, destroy)`, as `sqlite3_create_function` does with `xStep` and `xFinal`: `step` sees each input row's arguments, `finish` sets the group's answer with the `eggdb_function_result_*` calls, and `eggdb_aggregate_context(context, bytes)` gives each group its own zeroed memory, as `sqlite3_aggregate_context` does. The Python driver's `Connection.create_aggregate(name, n_arg, aggregate_class)` (and `eggdb.aio`'s) matches `sqlite3.Connection.create_aggregate`: one instance per group, `step(*args)` per row, `finalize()` for the answer, an exception fails the statement, `None` removes it. The calls take `DISTINCT` (one argument, as SQLite allows), `FILTER (WHERE ...)`, `GROUP BY` and `HAVING` like EggDB's own aggregates. Next to them, `any_value(x)` answers a non-NULL value of each group in PostgreSQL's (16), Oracle's (21c) and the other dialects that have it; MySQL's `ANY_VALUE(x)` lets a grouped query name a column outside `GROUP BY` under `ONLY_FULL_GROUP_BY`, and answers its argument unchanged in a query that is not grouped, as MySQL does.
- **How.** `NativeFunctions` (D1266) also keeps aggregates (`NativeAggregate`, a factory of `NativeAggregateState`s with `step` and `finish`); a scalar function and an aggregate of the same name and count replace each other, as in SQLite. When one is defined for the running statement, the parser turns a call of its name into the engine's aggregate `native_aggregate`, whose argument carries the name and the inputs; each group keeps its input rows, charged to the statement's work memory, and steps them through a fresh state when the group finishes. Keeping the rows lets a window's running value be finished at any point later on, at the cost of memory per group that a streaming state would not need. `any_value` keeps the first non-NULL value. MySQL's `ANY_VALUE` parses to an internal call that the grouping step turns into `any_value` and that otherwise answers its argument.
- **Left.** Program-defined aggregates as window functions (`OVER`, SQLite's `xValue`/`xInverse`), refused for now; the Node.js addon's aggregates.
- **Proof.** Engine tests run a one- and a two-argument aggregate per group, with `DISTINCT`, `FILTER`, an empty input and a failing step, refuse `OVER` and forget it outside the definition; `any_value` picks a value per group in PostgreSQL and MySQL, and MySQL's answers every row of an ungrouped query. The C API test keeps each group's longest word in `eggdb_aggregate_context`, answers NULL for no rows, fails on a step's error, runs it prepared, and removes it; the Python test does the same with a class.
