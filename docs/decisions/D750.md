## D750 `CREATE EXTENSION eggdb_pipelines`: SQL models with `ref()`, tests and lineage, and task pipelines — Decided by the code-only session (2026-11-12, D355); roadmap M16, transformations in SQL with `ref()` dependencies, tests and lineage (D46, D244) and pipeline orchestration with dependencies, retries with backoff and backfills (D46, D200)

- Models, in dbt's spirit and EggDB's own SQL: `eggdb_pipelines.models` holds each model's body, schema,
  materialization (`view` or `table`) and tests. `compile` replaces `{{ ref('model') }}` with the model's qualified
  name and `{{ source('schema', 'table') }}` with the table; `run_models()` builds them in dependency order (views with
  `CREATE OR REPLACE VIEW`, tables rebuilt with `CREATE TABLE AS`), refusing cycles (`42P17`), runs each model's
  `not_null`, `unique` and `accepted_values` tests into `test_results`, logs `model_runs`, and records lineage in its
  own table and, when `eggdb_catalog` is installed, in `eggdb_catalog.lineage` (D244).
- Pipelines on pg_cron: `tasks` (command, dependencies, `max_retries`, `retry_delay`), `runs` and `task_runs`.
  `start_run(pipeline [, logical_date])` makes a run; `advance(run)` executes each due task whose dependencies
  succeeded, with `{{ logical_date }}` in its command replaced by the run's date; a failure is retried after
  `retry_delay × 2^(attempts − 1)` until `max_retries`, then marked `failed`, and the tasks depending on it
  `upstream_failed`; the run ends `success` or `failed`. `tick()` advances every open run (scheduled each minute) and
  `backfill(pipeline, from, to [, step])` starts one run per logical date, at most 10,000.
- Tasks run inside the `advance` call's transaction, each in its own subtransaction; WebAssembly transformations,
  incremental models and sensors are left.
