## D769 Scheduled copies from other databases and files (eggdb_etl), and SQL Server and CSV foreign sources — Decided by the code-only session (2026-11-12, D355); roadmap M16, ETL connectors (D46, D229)

- `eggdb_foreign` (D229) gains two sources. `sqlserver://user@host[:port]/database[?encrypt=...]` runs the query on
  SQL Server through EggDB's own TDS client, with `FOR JSON PATH, INCLUDE_NULL_VALUES` appended, so SQL Server
  names and types the columns itself and every row arrives as a JSON object; the chunks SQL Server splits the JSON
  into are joined before parsing. Its password comes from `SQLCMDPASSWORD`, as `eggdb follow` (SQL Server) reads it,
  and an `EGGDB_FOREIGN_SOURCES` entry allows it by user, host, port and database as for PostgreSQL, refusing a
  source that would trust a certificate the entry doesn't. `file:...csv` reads a CSV file under an allowed
  directory: RFC 4180 quoting (quoted commas, doubled quotes, line breaks inside quotes), the first record naming
  the columns, every value as text, at most 1 GiB.
- `CREATE EXTENSION eggdb_etl` defines copies (`define_copy`) from any `eggdb_foreign` source into an existing table:
  `replace` (delete and reload in one transaction, so readers see the old or the new rows, never none), `append`, or
  `incremental`, whose query holds `{last_value}` and whose cursor moves to the target's largest `cursor_column`
  after each run. Rows go in by `jsonb_populate_recordset` in batches (1000 by default), so the target's column types
  convert the source's values. A schedule hands the run to pg_cron.
- `run(copy)` logs every run in `eggdb_etl.runs`; a failure rolls the copy back (a nested block), keeps the run
  record with `failed` and the SQLSTATE and message, and returns NULL instead of failing the pg_cron job, so the log
  is where failures show.
- MySQL sources (EggDB has a MySQL server but no MySQL client yet), files in object storage, and the CI copy from
  PostgreSQL 17 compared by row are left.
