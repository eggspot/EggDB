## D885 Range conditions read graph property indexes — Decided by the code-only session (2026-11-12, D355); follow-up of D728 and D729

- Besides `=` (D729), a `MATCH` start node's `WHERE` comparisons `n.p < v`, `<=`, `>`, `>=` (either way round) and
  `n.p STARTS WITH 'text'`, joined by `AND` and with `v` reading only parameters, literals and bound variables, are
  copied into the node pattern's internal `bounds`. When the pattern's label has a one-property index or uniqueness
  constraint on `p`, the start nodes are the index entries whose value lies in the range: the entries are read and
  decoded, and only the matching nodes are read, instead of every node with the label.
- Values compare as Cypher's do: integers and floats as numbers, strings by code point, booleans; a value of another
  type is outside every range. A `NULL` bound matches nothing; a bound the index cannot hold (a list, a temporal
  value) leaves the label scan in place. The `WHERE` still runs on every match, so the results are unchanged.
- The index key encoding (D728) is not order-preserving (integers in two's complement, floats by their bits, strings
  after their length), so a range reads all of the rule's entries; an ordered encoding, read as a key range, is left
  for a later format change with its D35 review, and so are ranges on composite indexes, `ENDS WITH` and
  `CONTAINS`, and conditions under `OR`.
