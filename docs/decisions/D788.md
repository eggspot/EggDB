## D788 Reading WITHOUT ROWID tables and UTF-16 SQLite files — Decided by the code-only session (2026-11-12, D355); roadmap M5, SQLite files

- `eggdb-sqlite-format` reads the header's text encoding (1 UTF-8, 2 UTF-16LE, 3 UTF-16BE) instead of refusing 2 and
  3, keeps it on the open file (`SqliteFile::text_encoding`) and decodes every text value with it; unpaired
  surrogates become U+FFFD, as UTF-8's invalid bytes already did. Any other number is still damage.
- Index b-trees are walked (`SqliteFile::index_records`): leaf pages (type 10) and interior pages (type 2) whose
  cells each carry a key of their own between the left child and the next cell, so the in-order walk visits every
  entry once. Payloads spill to overflow pages above the index limit, ((usable - 12) × 64 / 255) - 23 bytes, not the
  table leaf's usable - 35. The same loop, depth, budget and cell-pointer checks as the table walk apply.
- `SqliteFile::without_rowid_rows(root, columns, primary_key)` turns a `WITHOUT ROWID` table's records back into
  rows in column order: SQLite stores the primary key columns first, in key order, then the others in table order.
  The caller supplies the key positions from the `CREATE TABLE` it already parsed, so the crate stays free of an SQL
  parser; `creates_without_rowid` spots the table option after the column list. Their rows carry rowid 0.
- `rows()` on a `WITHOUT ROWID` root still answers "not read yet" and names the new call.
- `eggdb`'s SQLite import (`eggdb restore` of an SQLite file, D568) reads `WITHOUT ROWID` tables through it, with
  the primary key EggDB's own parse of the `CREATE TABLE` gives.
