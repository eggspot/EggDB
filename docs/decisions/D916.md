## D916 Foreign servers and foreign tables with declared columns — Decided by the code-only session (2026-11-12, D355); roadmap M18, follow-up of D229

- The PostgreSQL dialect takes `CREATE SERVER [IF NOT EXISTS] name [TYPE '...'] [VERSION '...'] FOREIGN DATA WRAPPER w
  OPTIONS (...)`, `CREATE FOREIGN TABLE [IF NOT EXISTS] name (column type [constraints], ...) SERVER s OPTIONS (...)`,
  `DROP SERVER [IF EXISTS] ... [CASCADE]` and `DROP FOREIGN TABLE [IF EXISTS] ...`; `CREATE`/`DROP FOREIGN DATA WRAPPER`
  are accepted and change nothing, since the wrappers are built in.
- A server names an `eggdb_foreign` source (D229): its `source` option, or a URL built from `host`, `port`, `dbname`
  and `user` for `postgres_fdw` (and `eggdb_fdw`), `mysql_fdw` and `tds_fdw` (`servername`, `database`); `file_fdw`
  tables name their `filename`. A `password` option is refused: passwords stay in the password file or the source's
  own variable, never in the catalog. Servers are kept in `eggdb_internal.foreign_servers`.
- A foreign table becomes a view, `SELECT (row ->> 'column')::type AS column, ... FROM eggdb_foreign(source, query)`,
  so each use reads the source and casts every declared column (`->` for `json` and `jsonb` columns); the query is
  the table's `query` option, or `SELECT * FROM schema_name.table_name` (the table's own name by default) quoted for
  the source's dialect. Foreign tables are kept in `eggdb_internal.foreign_tables`, so `DROP SERVER` refuses while
  tables use it (2BP01) and `CASCADE` drops them.
- Access stays as D229 and D770 set it: nothing is read unless `EGGDB_FOREIGN_SOURCES` allows the source, for the
  roles it names.
- Left: pushing a query's filters into the remote query, `IMPORT FOREIGN SCHEMA`, writes through foreign tables, and
  `CREATE USER MAPPING`.
