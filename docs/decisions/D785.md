## D785 SQL Server Database Mail: sp_send_dbmail and operator notifications sent — Decided by the code-only session (2026-11-12, D355); roadmap M10, SQL Server Agent jobs: sending the notifications (Database Mail)

- `msdb.dbo.sp_send_dbmail` is accepted with SQL Server's parameter names and queues a mail item in
  `eggdb_internal.sqlserver_dbmail_items` (recipients, copy and blind-copy recipients, subject, body, who asked and
  when, status). Without any recipient it fails with SQL Server's 14624. `@query` and `@file_attachments` are refused
  as not supported rather than sending a different mail than asked; profiles are not modelled, so `@profile_name` is
  accepted and ignored.
- The notifications D635 only recorded now also become mail: `sp_notify_operator` and a fired alert queue one item
  per operator that has an `email_address` (for alerts, those enabled and notified by e-mail, method bit 1).
- `msdb.dbo.sysmail_allitems`, `sysmail_unsentitems`, `sysmail_sentitems` and `sysmail_faileditems` are views over the
  queue, as tools and scripts read them.
- Delivery belongs to `eggdb serve`, the long-running process: with `EGGDB_SMTP_SERVER` set it sends up to 100 unsent
  items every 5 seconds through D747's SMTP client (STARTTLS, AUTH PLAIN over TLS only), one message per recipient,
  marking the item `sent`, or `failed` with the first error. Without the variable nothing is sent and items wait.
- Retries of failed items, HTML bodies, profiles and accounts (`sysmail_add_profile_sp`), and pager and net send
  notifications are left.
