## D388 `ALTER COLUMN ... TYPE ... USING expr` — Decided by the code-only session (2026-11-10, D355); roadmap M5

PostgreSQL converts a column to a new type with an expression over the row: `ALTER TABLE t ALTER
COLUMN flag TYPE boolean USING flag = 'yes'`. EggDB's type change already rewrites every row
(`set_type`, through `rebuild`, which also rebuilds the indexes); with `USING` each row's new value
is the expression evaluated over the row's old values (the old table's scope), then assigned to
the new type as before (`42804` with PostgreSQL's hint when that assignment fails). The expression
is checked first: its columns must exist, and a subquery (`0A000 cannot use subquery in transform
expression`) or an aggregate is refused, as PostgreSQL does. `USING` also forces the rewrite when
the type does not change. MySQL's `MODIFY` and the other dialects' type changes pass no
expression. `COLLATE` in the type change is still refused.
