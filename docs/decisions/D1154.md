## D1154 The Python driver through the CPython C API, with buffer-protocol batches — Decided by the code-only session (2026-11-14, D355); roadmap M5 (D16, D17)

- **`eggdb._native`, a C extension of our own.** `drivers/python/eggdb/_native.c` is written against the CPython
  C API. It is an optional part of the driver: `setup.py` builds it with `optional=True`, and without it the
  driver runs on `ctypes` as before.
- **The same library, the same session.** The extension does not link to the EggDB library. `load(path, factory)`
  opens the very file the `ctypes` layer opened (`dlopen` or `LoadLibrary` of the same path gives the same loaded
  copy) and looks the calls up by name. So both layers share one copy of the engine, and the extension takes the
  `ctypes` session's address. Errors come back through the driver's own `_error_for`, so they have the same
  PEP 249 classes and SQLSTATEs either way.
- **What runs in C.**
  - `execute` converts every result value into Python objects in C, with no `ctypes` structure per value.
  - `Statement` binds typed values: `None`, `bool`, 64-bit `int`, `float`, any buffer as a blob, and `str`, with
    the text form for the rest. It steps rows as a C iterator.
  - `Statement.executemany` runs the whole row loop in C.
  - `copy_in` and `copy_out` take and give buffers.
  - Long calls release the GIL.
- **Buffer-protocol batches.**
  - `Statement.execute_columns(columns)` takes one column per placeholder: a one-dimensional numeric buffer
    (`array.array`, NumPy, `memoryview`; formats `bBhHiIlLqQfd?`) read in place, or any sequence. It binds and
    runs row by row in C and returns the number of rows changed.
  - `Statement.fetch_columns(parameters)` returns a result by column name: `array.array('q')` or
    `array.array('d')` for a column holding only integers or only reals (filled from one C buffer), and a list
    otherwise.
  - Both have pure-`ctypes` fallbacks with the same results.
- **Turning it on or off.** `EGGDB_PYTHON_NATIVE=0` turns the extension off, and `=1` makes a missing one an
  error. `scripts/c-api/check.sh` runs the Python tests twice, through `ctypes` and through the extension
  (compiled with warnings as errors), so both paths stay equal.
