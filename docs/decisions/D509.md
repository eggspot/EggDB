## D509 Avro import and export — Decided by the code-only session (2026-11-11, D355); roadmap M11

`eggdb import --avro <file> --table <name>` loads an Avro object container file into a SQL table,
and `eggdb export --avro <file> --table <name>` writes one, beside `--parquet`, `--ndjson` and
`--xlsx` (D202, D505, D506). The Avro 1.11 specification is Apache-licensed and public.

- **Reading:** the header's metadata map, `avro.schema` parsed with EggDB's JSON parser, named
  types resolved by their short names, the 16-byte sync marker checked after every block. Codecs
  `null` and `deflate` (raw DEFLATE through `eggdb-content`, D249); snappy, zstandard, bzip2 and
  xz are refused by name, as EggDB has no decoder for them yet.
- **Columns:** the top-level record's fields. Booleans, `int` and `long` (`bigint`), `float` and
  `double`, `string` and enums (text), `bytes` and `fixed` (`bytea`), `date`, the four timestamp
  logical types (microseconds, `utc` for `timestamp-*` and not for `local-timestamp-*`) and
  `decimal` (bytes or fixed, at most 16 bytes) keep their types; a union of `null` and one type
  takes that type; records, arrays, maps and wider unions become their JSON text.
- **Writing:** an uncompressed file, the record named after the table and every field a
  `["null", type]` union with `"default": null`, names made valid Avro names (letters, digits
  and `_`, de-duplicated), 10,000 rows per block, and a sync marker derived from the schema's
  CRC-32 so the same table writes the same bytes. Timestamps with a zone are
  `timestamp-micros`, without one `local-timestamp-micros`; decimals are `bytes` decimals.
- **Bounds:** files of at most 2 GiB, 2 GiB inflated over all blocks, 100 million values.
- **Left out:** ORC, schema evolution against a reader schema, and compressed writing.

**Status:** code written, unbuilt (code-only mode, D355).
