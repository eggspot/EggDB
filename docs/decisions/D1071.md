## D1071 An OPC UA client that ingests data changes as they arrive — Decided by the code-only session (2026-11-13, D355); roadmap M16 (D57, D833)

- New crate `crates/eggdb-opcua` (it depends on `eggdb-sql` for sessions and DataValue decoding, never the
  other way). It is written from IEC 62541, parts 4 and 6, and has three parts:
  - **Binary encoding** (`binary.rs`): integers, doubles, Strings, ByteStrings, DateTimes, NodeIds in every
    encoding (expanded flags skipped), LocalizedText, ExtensionObjects, DiagnosticInfos and ResponseHeaders.
    Every length is checked before use, and arrays hold at most 100,000 items. NodeIds are read from the
    text form tools write (`ns=2;s=…`, `i=…`, `g=…`, `b=…`).
  - **Client** (`client.rs`):
    - The transport sends `HEL` and takes `ACK`, keeping the server's receive buffer as a limit.
    - It opens a secure channel with the `None` policy, renewed at 75 % of its token's lifetime. Server
      `ERR` messages become errors.
    - `CreateSession` reads the server's endpoints for the anonymous or user-name token policy id the server
      offers in `None` mode. `ActivateSession` sends the matching identity token.
    - `subscribe` makes `CreateSubscription` (publishing interval, keep-alive 20, lifetime 600) and
      `CreateMonitoredItems` calls: the Value attribute, reporting mode, both timestamps, the node's index as
      the client handle, the queue size 10. It returns each item's status.
    - `publish` sends `Publish` with the previous sequence numbers acknowledged. It returns the
      `DataChangeNotification` values, decoded by `eggdb_sql::opcua_data_value_prefix`, and treats a bad
      `StatusChangeNotification` as an error.
    - Chunked responses are reassembled (16 MiB, 4,096 chunks at most), aborts and `ServiceFault`s are
      errors, and `close` sends `CloseSession` and `CLO`.
  - **Collector** (`collector.rs`): `eggdb serve --opcua-subscribe 'opc.tcp://[user:password@]host:port[/path]|node|node…'`,
    repeatable.
    - It follows each server on its own thread and stores every change in the `opcua_values` table
      (`received_at`, `endpoint`, `node_id`, `value jsonb`, `status`, `source_time`, `server_time`), created
      at start. All changes in one Publish answer go in one insert.
    - A failure is logged and retried after 1 second, doubling up to 30.
- The user name and password ride in the URL and are sent as the user-name token. With the `None` policy
  that is plain text, as OPC UA's own `None` mode is: use it only on a trusted network until the signed
  policies land.
- Tested against a scripted server in the crate's tests: the policy id is taken from the endpoints, refused
  nodes are reported, and a data change is decoded.
- Left: the `Basic256Sha256` and `Aes*` security policies (signing and encryption with certificates),
  events and alarms, writes and method calls, and Sparkplug and Modbus ingest as messages arrive.

**Status:** code written, unbuilt (code-only mode, D355).
