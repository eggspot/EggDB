## D791 JDBC DatabaseMetaData in the embedded Java driver — Decided by the code-only session (2026-11-12, D355); roadmap M5, JDBC

- `EggDbConnection.getMetaData()` answers an `EggDbDatabaseMetaData` instead of refusing. Its table, column, key,
  index, schema and routine queries read `information_schema` (`tables`, `columns`, `table_constraints`,
  `key_column_usage`, `referential_constraints`, `schemata`, `routines`) and, for indexes, `pg_catalog` (`pg_index`,
  `pg_class`, `pg_namespace`, `pg_attribute`), and build each row in Java in the column layout and order the JDBC
  4.3 specification gives each method, with JDBC's `Types` codes mapped from the column's type name.
- The connection may speak any dialect, but those catalogs are PostgreSQL's, so the queries run on a second session
  opened in PostgreSQL's dialect on the same database handle (`NativeSession.catalogSession`; a server connection
  already speaks it). That session does not own the database and closes with the connection. It reads committed
  data, so tables created in the connection's own uncommitted transaction appear after it commits; tools ask for
  metadata outside transactions, and sharing the transaction would need the C API to switch a session's dialect.
- `pg_catalog`, `information_schema` and `eggdb_internal` are left out of tables, columns and schemas. JDBC patterns
  go to `LIKE` with `\` as the escape (`getSearchStringEscape`). There are no catalogs (`getCatalogs` is empty).
- Fixed facts: product "EggDB", identifiers stored lower-case, `"` quotes, serializable as the default and only
  isolation level, forward-only read-only result sets, savepoints and batches supported, generated keys not. Procedure
  and function columns, privileges, UDTs, super types, attributes and pseudo columns answer empty result sets with
  the right columns. Booleans in these rows are `Boolean`s.
- The driver's check program reads `getTables`, `getColumns` and `getPrimaryKeys` back.
- Left: the JNI binding for Java before 22, routine parameters, privileges and comments (`REMARKS`).
