## D1089 The browser build in a worker, OPFS sync access handles, one database for every tab, and a real sleep — Decided by the code-only session (2026-11-13, D355); roadmap M17 (D221, D16)

- **A worker, still our own few lines of JavaScript.** `web/eggdb-worker.js` (a module worker) hosts the WASI build, so statements never block the page. It stays within D16's minimal loader: no third-party code.
- **Durable per write.** In the worker the loader's file layer is `OpfsSyncFiles`: each database file is an OPFS `FileSystemSyncAccessHandle`, so `fd_pwrite` writes the file and `fd_sync`/`fd_datasync` call `flush()`; the engine's own commit protocol then gives OPFS the same durability as a disk. Opening an access handle is asynchronous, so the worker attaches the database's path and every existing EggDB file before starting the module; a file the engine creates later (a backup, a compaction's staging file) lives in memory and gets its handle after the statement. A rename onto a handled file copies into it. The OPFS names are those of the in-page loader (`eggdb:` plus the encoded path), so databases saved by either are found by both. The in-page `EggDB` and its `MemoryFiles` store keep working where workers or sync handles are missing.
- **One database for every tab.** Sync access handles are exclusive, and SharedWorkers cannot create them, so the tabs elect a leader: each worker asks for the Web Lock `eggdb:<path>` without waiting; the one that gets it opens the file, the others send `{request}` messages over the `BroadcastChannel` of the same name and wait for `{reply}`, and also queue for the lock, so the next tab takes over when the leader's tab closes (the browser releases its lock and handles). The leader runs requests one at a time, each tab in its own session and dialect: `eggdb-wasm` now keeps one `Database` per path and opens another session on it for each further `eggdb_wasm_open`, so two engines never write one file (which also fixes reopening in the in-page loader).
- **At most once across a leader change.** A request whose leader vanished is not re-sent: the new leader's announcement fails it with a message saying it may or may not have run. Re-sending could run a write twice; only `describe` (version and durability) is re-sent.
- **A real sleep.** `poll_oneoff` now honours clock subscriptions (relative and absolute, realtime and monotonic): it waits for the earliest with `Atomics.wait` on a `SharedArrayBuffer` cell where allowed (workers, Node, cross-origin-isolated pages) and a timed loop elsewhere, and reports only the subscriptions that fired; with any fd subscription it answers at once as before. `pg_sleep(0.2)` in `web/test.mjs` checks it.
- **Tests.** `web/shared-test.html` opens two workers on one database in headless Chrome, writes through both, closes the leader and checks the other takes over with the data, in CI's `browser` job. The playground opens through `SharedEggDB` when the browser has workers and Web Locks.
