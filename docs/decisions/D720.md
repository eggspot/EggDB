## D720 Cypher temporal and spatial values, and Bolt's structures for them — Decided by the code-only session (2026-11-12, D355); roadmap M13, Bolt's temporal and spatial PackStream types (D207)

- Graph values gain `Temporal` (date, local time, zoned time, local datetime, zoned datetime with a fixed offset,
  and duration) and `Point` (2D and 3D, Cartesian and WGS 84: SRIDs 7203, 9157, 4326 and 4979).
- Cypher builds them with `date`, `localtime`, `time`, `localdatetime`, `datetime`, `duration` and `point`: with no
  argument for now (UTC), from an ISO 8601 string, or from a map of components (`{year, month, day, hour, ...,
  timezone}`, `{epochSeconds}`/`{epochMillis}`, `{years, months, weeks, days, hours, ...}`, `{x, y[, z]}` or
  `{longitude, latitude[, height]}` with an optional `srid` or `crs`). Their components read as properties
  (`d.year`, `t.offsetSeconds`, `dt.epochMillis`, `dur.months`, `p.latitude`), `toString` prints ISO 8601, `=`
  compares them, `<` and `>` order every temporal type but durations (null otherwise, as Cypher does), and
  `ORDER BY` places them in Cypher's order between paths and strings.
- Time zones are offsets only: named zones (`Europe/Paris`) are refused, as they need the time zone database.
- Nodes and relationships store them as properties, as a small document marked `$cypher` beside the stored
  scalars.
- Bolt writes them as PackStream structures: Date `D`, Time `T`, LocalTime `t`, LocalDateTime `d`, Duration `E`,
  Point2D `X` and Point3D `Y`, and DateTime as `I` (UTC seconds) on Bolt 5 and as `F` (local seconds) before it;
  the same structures are read as query parameters. Bolt 4.4's `utc` patch is not offered, so 4.4 clients get `F`.
- Left out: arithmetic between temporals and durations, `duration.between`, truncation, `datetime({timezone:
  'Europe/Paris'})`, and `point.distance`.
