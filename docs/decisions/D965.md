## D965 Named parameters in the ADO.NET provider, and NHibernate's driver and dialect — Decided by the code-only session (2026-11-13, D355); roadmap M6f, D16 and D182's .NET list

- **Named parameters.** Dapper, and most .NET code, writes `@name` placeholders and names its parameters. A command
  of `EggDB.Data` now binds a parameter that has a name to every `@name`, `:name` or `$name` placeholder with that name
  (case-insensitive, prefix optional on the parameter), outside quoted text and not after `::`, rewriting them to the
  positional `?` the provider binds; a command whose parameters have no names, or whose text names none of them, binds
  positionally as before. So Dapper runs with its usual SQL and anonymous-object parameters; no Dapper code is needed.
- **NHibernate.** `drivers/dotnet/EggDB.NHibernate` (a project of its own, so the provider depends on nothing) holds
  `EggDbDriver`, a `ReflectionBasedDriver` loading `EggDbConnection` and `EggDbCommand` with positional `?`
  parameters and no multiple open readers, and `EggDbDialect`, NHibernate's SQLite dialect, the SQL the provider
  speaks by default.
- **Left.** The EF Core provider: EF Core's SQLite provider is bound to `Microsoft.Data.Sqlite`'s connection type, so
  EggDB needs a provider of its own (type mappings, SQL generation, migrations and the specification tests).
- The .NET check program now also binds named parameters, in a different order from the text, and leaves a quoted
  `'@colour'` alone.

**Status:** code written, unbuilt (code-only mode, D355).
