## D189 MCP over Streamable HTTP inside eggdb serve: read-only, Bearer token, loopback until TLS — Decided by the build loop (by judgement, 2026-10-31); refines D11 and D119; security-critical (D35)

Part 4.M6d-1 asks for the MCP server over Streamable HTTP with TLS and authentication.

- **Same server, new transport.** `eggdb serve --mcp-listen <address> --mcp-token-file <file>`
  runs the MCP server of `eggdb mcp` (`eggdb_mcp::Server`, one per MCP session) behind our own
  HTTP crate (D188), on the database the server already has open. Each `POST /mcp` carries one
  JSON-RPC message; a request gets its JSON answer, a notification or response gets `202`. The
  `initialize` request opens a session whose id (128 random bits) comes back in
  `Mcp-Session-Id`; `DELETE /mcp` ends it; at most 64 sessions live, the oldest going first.
- **Authentication**: a Bearer token from a file (at least 16 characters), compared in constant
  time. Requests with an `Origin` header are refused, as the transport's specification asks
  servers to guard against DNS rebinding from web pages.
- **Limits for now**: read-only (`write_sql` is refused: confirming destructive writes needs the
  per-agent grants of 4.M6d-2), no `GET` event streams, and loopback addresses only, because the
  HTTP crate has no TLS yet; every call is audited as for `eggdb mcp`.

Left: TLS for the HTTP endpoint and other addresses, per-agent grants and revocation, writes
with confirmation over HTTP, server-sent event streams, and OAuth as the MCP specification
describes for remote servers.
