## D1230 tsvector and tsquery utility functions — Decided by the code-only session (2026-11-17, D355); roadmap M8, text search (D30, D983)

- **What users get.** PostgreSQL's `tsvector_to_array(tsvector)` (the lexemes as `text[]`), `array_to_tsvector(text[])` (lexemes without positions), `ts_delete(tsvector, lexeme | text[])`, `ts_filter(tsvector, "char"[])` (the positions of the given weights, a lexeme left with none dropped, an unknown weight refused), `numnode(tsquery)` (operands and operators counted), `querytree(tsquery)` (the part an index can answer, negations taken out, `T` when nothing is left) and `tsquery_phrase(a, b [, distance])` (`a <distance> b`, 0 to 16384).
- **How.** `TsVector::without`, `filtered` and `of_lexemes` and `TsQuery::node_count` and `indexable` in `eggdb-search`; the SQL functions in `text_search.rs` beside `setweight`, with their result types in `typing.rs`. `querytree` keeps an `OR` only when both sides keep something, as a negated branch makes the whole `OR` unanswerable from an index.
- **Left.** The set-returning `ts_debug`, `ts_parse`, `ts_token_type`, `ts_stat` and `unnest(tsvector)`, and `ts_rewrite`.
- **Proof.** A unit test in `text_search.rs` with PostgreSQL's documented examples for each function and a bad weight refused.
