## D1221 ALL ROWS PER MATCH WITH UNMATCHED ROWS — Decided by the code-only session (2026-11-17, D355); roadmap M16, `MATCH_RECOGNIZE` for complex event processing (D55, D1217)

- **What users get.** `ALL ROWS PER MATCH WITH UNMATCHED ROWS` returns every row of the input: the rows of each match with their measures, and the rows no match took with NULL measures and classifier, as SQL:2016 and Oracle define it. Pattern exclusion with it is refused, as Oracle refuses it.
- **How.** D1217's rewrite joins the matches to the numbered rows; with unmatched rows it starts from the numbered rows and left-joins the matches instead, so a row in no match keeps one output row whose match columns are NULL, and every measure over that NULL match is NULL.
- **Left.** `SHOW EMPTY MATCHES` (the matcher does not report empty matches), and `COUNT` measures on unmatched rows giving 0 where Oracle gives NULL.
- **Proof.** `streams.rs`: a down-run pattern over two partitions returns all seven rows, the down rows classified and the rest NULL; exclusion with unmatched rows and `SHOW EMPTY MATCHES` refused.
