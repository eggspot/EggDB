## D838 Nested Parquet columns — Decided by the code-only session (2026-11-12, D355); roadmap D202, Parquet nested columns

- A Parquet file whose schema has groups or repeated fields no longer fails as a whole: `read_parquet` (and the
  other users of `eggdb-parquet`'s reader) read its flat columns as before and each top-level list, map or struct
  whose leaves are plain values as one text column of JSON, as for nested Arrow and ORC columns (D835, D836).
- The schema's depth-first element list is turned into a tree with each node's definition and repetition levels.
  Shapes read: the three-level `LIST` (with null items), the legacy two-level list and a bare repeated field (an
  array that is never null), `MAP`/`MAP_KEY_VALUE` with plain keys and values (an object keyed by the keys), and an
  unannotated group of plain fields (an object). Other shapes, such as lists of structs, are refused by name.
- Nested leaves are read with their repetition and definition levels (RLE/bit-packed hybrid at the levels' bit
  widths, length-prefixed in v1 data pages, sized by the header in v2), dictionaries and codecs as for flat columns.
  Records start where the repetition level is 0; a definition level below the list's says the list is null, equal
  says empty, and an item is null below the leaf's full level. Values become JSON as in D835 (dates and timestamps
  ISO 8601, decimals scaled, binary hex). Levels and values that disagree are errors, never panics.
- Left: deeper nesting, writing nested columns, and streaming.
