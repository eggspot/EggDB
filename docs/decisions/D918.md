## D918 Transact-SQL's character classes in `LIKE` — Decided by the code-only session (2026-11-12, D355); roadmap M5, D299

- In the SQL Server dialect, `LIKE` patterns take SQL Server's classes: `[abc]`, ranges `[a-f]` and negated classes
  `[^abc]`, beside `%` and `_`; a `[` with no `]` after it stands for itself, as do `]` and the other characters. The
  backslash is an ordinary character (SQL Server has no default escape); `ESCAPE 'c'` makes the character after `c`
  stand for itself.
- A pattern written as a string literal without `[` keeps the plain `LIKE` (and its index use); any other pattern,
  a literal with a class or a pattern computed at run time, becomes a regular-expression match on
  `eggdb_tsql_like_regex(pattern [, escape])`, which writes the anchored regular expression the pattern means, and
  `NOT LIKE` the negated match. `NULL` patterns give `NULL`.
- Case sensitivity is unchanged: EggDB's SQL Server dialect compares `LIKE` with the binary collation it uses
  elsewhere, not SQL Server's default case-insensitive one.
