## D488 Live activity across sessions: `pg_stat_activity` and MySQL's process list — Decided by the code-only session (2026-11-11, D355); roadmap M6c, D25 and D188

- `eggdb-sql` gains `session_activity`, a registry of the sessions the protocol servers of one
  process serve: a connection registers once logged in (its id, protocol, user, database, client
  address and application name) and reports when each statement starts (`active`, the statement's
  text up to 1,024 characters, PostgreSQL's `track_activity_query_size` default) and ends (`idle`,
  `idle in transaction` or `idle in transaction (aborted)`). Dropping the handle when the
  connection ends removes it. At most 65,536 sessions are listed.
- The PostgreSQL listener registers every connection (simple queries, and `Execute` of the
  extended protocol until `Sync`); the MySQL listener registers each connection per database it
  is attached to.
- `pg_stat_activity` lists every registered session (all protocols and databases, `datid` set for
  the current database), with `pid`, `usename`, `application_name`, `client_addr`/`client_port`,
  `backend_start`, `query_start`, `state_change`, `state` and `query`; `pg_stat_database.numbackends`
  counts them. `SHOW PROCESSLIST` and `information_schema.processlist` list them as MySQL does
  (`Query` or `Sleep`, seconds in the state, the statement while it runs). Without a server
  (embedded use) both keep their single row for the current session.
- Not written: the TDS listener's registration and `sys.dm_exec_requests`/`sys.dm_exec_sessions`,
  wait events and locks (`wait_event`, `pg_locks` across sessions), `xact_start`, and
  `pg_terminate_backend`/`KILL`.
