## D1146 The C API's check, stats and the remaining open options — Decided by the code-only session (2026-11-14, D355); roadmap M5 (the C API, D142, D268, D293)

- **`eggdb_check(db, report)`** runs `Database::check` (every page's checksum, the tree's order and shape, lost pages)
  and fills an `eggdb_check_report`, or NULL to only learn whether the file is sound (`EGGDB_ERR_CORRUPT` when it is
  not).
- **`eggdb_stats(db, stats)`** fills an `eggdb_stats` from `Database::stats`: sizes, free pages, the last commit, and
  the page cache's and log's counters, reading no page.
- **The remaining open options without breaking the ABI.** `eggdb_options` is a fixed C struct that programs
  allocate, so new fields would break every program built against the old size. `eggdb_open_v2(path, options,
  settings, db)` takes the rest as a text list of `name=value` pairs separated by `;` or new lines: `lock_cache`,
  `compress_values`, `cache_numa_node`, `memory_limit_bytes`, `snapshot_memory_bytes`, `auto_checkpoint_log_bytes`
  (0 turns automatic checkpoints off), `page_size_bytes`, `write_timeout_ms`, `busy_timeout_ms` and
  `page_store_disk_bytes`. An unknown name or a malformed value is `EGGDB_ERR_INVALID_ARGUMENT` naming it, and a
  later option is one more name, not a new struct. Keys stay out of settings strings: an encryption key goes
  through its own call, never a string that might be logged.
- **Left in the item:** parsed plans kept in prepared statements, binary result formats, and typed `Parse` on server
  sessions.
