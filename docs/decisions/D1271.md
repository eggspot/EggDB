## D1271 DBMS_METADATA.GET_DEPENDENT_DDL — Decided by the code-only session (2026-11-18, D355); roadmap M4 Oracle packages (D859, D1234, D1254)

- **What users get.** `DBMS_METADATA.GET_DEPENDENT_DDL(object_type, table[, schema])` returns, for `'INDEX'`, the `CREATE INDEX` statements of a table's indexes (its primary key's among them); for `'TRIGGER'`, the `CREATE OR REPLACE TRIGGER` statements of its triggers; for `'OBJECT_GRANT'`, the `GRANT` statements of the privileges on it; for `'CONSTRAINT'` and `'REF_CONSTRAINT'`, `ALTER TABLE ... ADD CONSTRAINT ... ENABLE` for its primary key, unique and check constraints or its foreign keys; and for `'COMMENT'`, `COMMENT ON TABLE` and `COMMENT ON COLUMN`, one per line, as Oracle's export scripts and SQL Developer's DDL view call it after `GET_DDL('TABLE', ...)`.
- **How.** The table is found in the catalog snapshot as `GET_DDL` finds it; each index goes through `GET_DDL('INDEX', ...)`, so both write the same statement, triggers reuse their stored text, and grants are written as `GET_GRANTED_DDL` writes them (D1254), each privilege its own `GRANT`; constraints take the definition `pg_get_constraintdef` gives. A name that is not a table fails with ORA-31603, and a table with nothing of the kind with ORA-31608, Oracle's codes.
- **Left.** Constraint definitions in Oracle's own spelling (they use the PostgreSQL text `pg_get_constraintdef` gives, which EggDB's Oracle dialect reads), and `SYSTEM_GRANT` and `UTL_FILE` as before.
- **Proof.** The `DBMS_METADATA` Oracle test reads a table's indexes, grants, check constraint and comment, is refused foreign keys it has none of, and is refused for a view.

**Status:** code written, unbuilt (code-only mode, D355).
