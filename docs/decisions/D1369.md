## D1369 Scroll bar, dialog, tooltip and checkable menu item roles in every accessibility bridge — Decided by the code-only session (2026-11-25, D355); roadmap M6e "menu, dialog and scroll bar accessibility roles" (D310), mapped as `docs/ux/polish.md` section 3.3 lays out

- **What users get.** The platform layer's `AccessRole` gains `ScrollBar`, `Dialog` (non-modal: the value view, the drawer, a popover with focus), `AlertDialog` (modal: the picker, confirmations), `Tooltip` and `MenuItemCheckBox`, so screens that draw them can name them to screen readers in each system's own terms.
- **Mappings.** AT-SPI2: `ATSPI_ROLE_SCROLL_BAR` (48), `DIALOG` (16), `ALERT` (2) for the modal dialog, `TOOL_TIP` (64) and `CHECK_MENU_ITEM` (8). UI Automation: the `ScrollBar` (50014), `Window` (50032, a dialog with `IsDialog`), `ToolTip` (50022) and `MenuItem` control types. macOS: `AXScrollBar`, `AXPopover`, `AXSheet`, `AXGroup` with its text as the value for a tooltip, and `AXMenuItem`. The browser: the ARIA roles of the same names. A checkable menu item offers invoke and toggle.
- **Left.** The properties around them that the design asks for: a scroll bar's orientation and value (UIA `RangeValue`, AT-SPI `Value`, `aria-valuenow`), `IsModal` and the modal state with the window-opened event, `AXHelpTag` and `HelpText` on the described node, and the screens that draw these nodes.
- **Proof.** Unit tests pin the AT-SPI role numbers and names and the UIA control types.

**Status:** code written, unbuilt (code-only mode, D355).
