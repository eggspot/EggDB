## D626 Elasticsearch's legacy _template API — Decided by the code-only session (2026-11-12, D355); roadmap M8, D196, D594

D594 wrote composable index templates (`_index_template`) and left the legacy `_template` API.
Logstash's default template installer, older Beats, Graylog, Fluentd's Elasticsearch plugin and
many Helm charts still `PUT _template/<name>`.

- `PUT` or `POST _template/<name>` takes the legacy body:
  - `index_patterns`, or the older `template` key with one pattern;
  - `order` (a whole number);
  - top-level `mappings`, `settings` and `aliases`;
  - `version`.
  It is checked as D594 checks templates and kept as JSON under record kind 7.
- `GET _template[/<names>]` answers the legacy shape, `{"<name>": {…}}`. `HEAD` and `DELETE` work as
  for the other templates.
- When an index is created and no composable template matches it, every matching legacy template
  applies:
  - their mappings merge in ascending `order` (by name on a tie), so a higher order wins field by
    field;
  - their aliases are added.
  - A matching composable template takes precedence over all legacy ones, as Elasticsearch 7.8+
    does.
- A test checks that two legacy templates merge by order, that the alias is applied, that the
  legacy listing shape is returned, and that a composable template for a narrower pattern wins.

Not done: mapping types inside legacy mappings (`{"_doc": {…}}` of Elasticsearch 6), and
`_template`'s `settings` applied (EggDB indices have no shards or replicas to set).

**Status:** code written, unbuilt (code-only mode, D355).
