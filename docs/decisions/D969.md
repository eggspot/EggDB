## D969 pgRouting's depth-first and breadth-first searches and k shortest paths — Decided by the code-only session (2026-11-13, D355); roadmap M12, follow-up of D905

- `CREATE EXTENSION pgrouting` gains `pgr_depthFirstSearch` and `pgr_breadthFirstSearch` (edges, root, directed,
  `max_depth`; rows `seq, depth, start_vid, node, edge, cost, agg_cost`, the root first with edge -1) and `pgr_KSP`
  (edges, start, end, `K`, directed; rows `seq, path_id, path_seq, start_vid, end_vid, node, edge, cost, agg_cost`),
  written from pgRouting's documentation over EggDB's own graph code in `routing.rs`, as the other pgRouting
  functions (D57).
- The searches visit each node once, taking neighbours cheapest first and then by edge id, which fixes an order where
  pgRouting leaves it to its graph library. `pgr_KSP` is Yen's algorithm: each spur path is a cheapest path on the
  graph without the root path's nodes and the edges earlier paths with the same root leave the spur node by;
  candidates are taken cheapest first, fewer steps first on a tie; `K` is at most 1000.
- The SQL wrappers call two new internal functions, `eggdb_route_traversal` and `eggdb_route_ksp`, beside D905's.
- Left: turn restrictions, contraction and the rest of pgRouting's catalogue.

**Status:** code written, unbuilt (code-only mode, D355).
