## D703 Which files SQL may read, and read_parquet — Decided by the code-only session (2026-11-12, D355); roadmap M11, `read_parquet` and the other file readers (D29, D202)

- D202 left `read_parquet` waiting for a rule on which files a server's SQL may open. The rule follows D631's for
  writing files: **the engine reads no files itself.** A new `FileReader` trait reads them; the embedded entry points
  (`eggdb sql`, `eggdb shell`, `libsqlite3`) give their sessions `eggdb::sql::LOCAL_FILES`, which reads local files as
  DuckDB and SQLite's file functions do, and servers give their sessions none, so a client of `eggdb serve` can never
  read a file on the server's machine (`0A000`). A server-side directory allow-list for administrators can come
  later as its own decision.
- The session hands its reader to the statements it runs through a thread-local scope around each text it runs
  (`Session::set_file_reader`, `run_text`). Statements run through prepared-statement paths outside `run_text` see no
  reader and are refused.
- `read_parquet(path) AS t(name type, ...)` (PostgreSQL dialect) reads a Parquet file with `eggdb-parquet` (D202),
  now a dependency of `eggdb-sql`, and returns its rows. As `json_to_record` does, it takes a column definition list:
  each declared column comes from the file's column of the same name (exactly, then ignoring case), or is `NULL`
  when the file has none, and is cast to its declared type. Dates, timestamps (with and without time zone),
  decimals (with their scale), text, binary, integers, floats and booleans map to EggDB's values first.
- Files are read whole, up to 1 GiB. Left: reading the column list from the file so no definition list is needed,
  other readers (`read_csv`, Arrow IPC files), and globs over several files.
