## D724 JetStream timers: push redelivery, idle heartbeats, pull timeouts, and pending counts for watches — Decided by the code-only session (2026-11-12, D355); roadmap M16, follow-up of D722 and D723

- A JetStream thread in the NATS server ticks once a second. Each tick sends a `408 Request Timeout` status (with
  `Nats-Pending-Messages`) to every pull whose `expires` ran out, delivers again to push consumers what waited
  past `ack_wait` (and anything new), and sends a `100 Idle Heartbeat` status with `Nats-Last-Consumer` and
  `Nats-Last-Stream` to each push consumer with an `idle_heartbeat` that received nothing for that long.
- Consumers keep and show `idle_heartbeat`, `flow_control` and `headers_only`. A `headers_only` consumer delivers
  each message's headers with `Nats-Msg-Size` added and no payload. `flow_control` is accepted, and the server
  never asks for flow control, so clients never wait on it.
- The pending count in each delivery's acknowledgement subject now counts down to 0 on the last message there is,
  including the first values a `last_per_subject` consumer still owes, and `num_pending` counts those too. Key-value
  watches use both to tell when the initial values are done.
- The tick is per server process; a server with many push consumers reads each consumer's state once a second.
