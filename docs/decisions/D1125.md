## D1125 Isolation per request and per session — Decided by the code-only session (2026-11-13, D355); roadmap M3 (isolation per database, table or request, D18, D173)

- **The levels EggDB runs.** *Strict serializable*: a block on the one writer, the default, which also gives every
  weaker level (read committed with per-statement snapshots included) its guarantees and more. *Serializable* and
  *snapshot*: blocks beside other writers, checked at commit (D1123).
- **Per request** is the dialect's own syntax: `BEGIN ISOLATION LEVEL ...`, `SET TRANSACTION ISOLATION LEVEL ...`.
  `REPEATABLE READ` and `SNAPSHOT` choose snapshot, `SERIALIZABLE` chooses serializable, and `READ COMMITTED` and
  `READ UNCOMMITTED` stay on the one writer.
- **Per session**, the new setting `eggdb.isolation` (`strict serializable` by default, or `serializable` or
  `snapshot`) chooses for blocks that name no level. `default_transaction_isolation` is not used for this: EggDB
  reports it as `serializable`, which is honest about the one writer, and following it would turn every existing
  application's blocks into ones that can fail at commit.
- **Left:** per database (`ALTER DATABASE ... SET eggdb.isolation`, which needs per-database settings stored in the
  catalog), and per table (a table that asks for serializable raising the level of any block that touches it, which
  needs the level chosen before the block's first read rather than at its first write).

**Status:** code written, unbuilt (code-only mode, D355).
