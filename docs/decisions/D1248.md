## D1248 Column lists in publications — Decided by the code-only session (2026-11-18, D355); roadmap M14 change streams (D1245)

- **What users get.** `CREATE PUBLICATION p FOR TABLE orders (id, total)`, and the same list in `ALTER PUBLICATION ... ADD` or `SET TABLE`, send only those columns of the table to a subscriber, as PostgreSQL 15 does: a column the table does not have, or one named twice, is refused with PostgreSQL's errors.
- **How.** The stored publication keeps each listed table's columns in an optional section after its schemas, so a record written before has none and still reads. The walsender narrows each change it sends (`PublicationFilter::narrowed`): when any publication the subscriber named covers the table without a list (all tables, its schema, or the table without columns), every column goes; otherwise the union of the lists, in the table's order. The primary key's columns always go, since a subscriber needs them to apply updates and deletes; PostgreSQL refuses a list without the replica identity for such publications instead, which EggDB may add later.
- **Left.** `pg_publication_rel.prattrs`, row filters (`WHERE`), and refusing a list that leaves out the key for publications sending updates and deletes.
- **Proof.** A test creates a list, sees an unknown and a repeated column refused, narrows an insert to the listed columns with the key kept, and sees a second publication for all tables restore every column.

**Status:** code written, unbuilt (code-only mode, D355).
