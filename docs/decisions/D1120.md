## D1120 Subpartitions in the partition ALTERs, and SUBPARTITION TEMPLATE — Decided by the code-only session (2026-11-13, D355); roadmap M2 (MySQL's `SUBPARTITION BY` and Oracle's composite partitioning, D337, D361)

- **`SUBPARTITION TEMPLATE`** (Oracle) after `SUBPARTITION BY`: either a list of named subpartitions or, for hash, a
  count. A partition that names no subpartitions of its own gets the template's, named `<partition>_<template name>`
  as Oracle names them. A range or list template must name its subpartitions (`ORA-14160`).
- **The stored shape is the template.** EggDB keeps no separate template record. A composite table's subpartitioning
  is read from an existing partition: its key, and its subpartitions' bounds with names rebased from that
  partition's name to the new one (`p1_east` becomes `p2_east`; a name without the prefix becomes `p2_<name>`). For
  tables made from a template, which is every Oracle composite table without per-partition lists, this matches
  Oracle's behaviour exactly.
- **The maintenance ALTERs follow it.** `ADD PARTITION` creates the new partition with those subpartitions. Every
  rebuild (`REORGANIZE`, `SPLIT`, `MERGE`, `COALESCE`, hash `ADD`) recreates the new partitions subpartitioned
  the same way and reads the old rows from the leaves. `TRUNCATE PARTITION` and the row counts of `MODIFY ... VALUES`
  reach the leaves. `EXCHANGE PARTITION` of a partition with subpartitions is refused (`ORA-14291`): exchange its
  subpartitions instead.
- **`DROP SUBPARTITION` and `TRUNCATE SUBPARTITION`** (Oracle) name subpartitions across the table. Dropping the
  last subpartition of a partition is refused (`ORA-14629`), and an unknown name answers `ORA-14251`.
- **Left:** `ALTER TABLE ... SET SUBPARTITION TEMPLATE`, `ADD SUBPARTITION` under `MODIFY PARTITION`, `SPLIT` and
  `MERGE SUBPARTITIONS`, and explicit subpartition lists inside `ADD PARTITION`.
