## D628 EXPLAIN (FORMAT XML) — Decided by the code-only session (2026-11-12, D355); roadmap M6c, D286, D531

D531 wrote PostgreSQL's `FORMAT JSON` and `YAML` plans from the text plan's tree, and left `XML`.
pgAdmin's older plan viewer and some monitoring tools ask for XML.

- `EXPLAIN (FORMAT XML)` is now parsed (`ExplainStyle::PostgresXml`). It shows subplans, as JSON and
  YAML do.
- `postgres_formats::xml` writes the same tree as PostgreSQL does: an `explain` document in the
  `http://www.postgresql.org/2009/explain` namespace, one `Query`, its `Plan`, and nested `Plans`.
  - Each field is an element named as the JSON key with hyphens for spaces: `Node-Type`,
    `Parent-Relationship`, `Subplan-Name`, `Relation-Name`, `Alias`, `Index-Name`, `Filter`, and
    the other details.
  - Text is escaped for XML.
- The result is one `QUERY PLAN` text row, where PostgreSQL types it `xml`. EggDB's PostgreSQL
  dialect has no `xml` type yet.
- The formats test checks the document's opening, a relation name, a filter and the closing tags.
