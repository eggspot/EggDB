## D465 PostgreSQL's special date and time inputs — Decided by the code-only session (2026-11-11, D355); roadmap M6a, D19

- `date`, `timestamp` and `timestamptz` input (casts, literals, `COPY`, parameters, every path
  through `parse_date`/`parse_timestamp`) take PostgreSQL's special words, any case, with spaces
  around: `epoch` (1970-01-01 00:00:00, UTC for `timestamptz`), `now` (the statement's
  timestamp, the same value `now()` gives), `today`, `tomorrow` and `yesterday` (midnight in the
  session's time zone).
- `time` and `timetz` take `allballs` (00:00:00, offset +00) and `now` (the local time of day
  with the session's offset); `epoch`, `today`, `tomorrow` and `yesterday` are refused for them, and
  `allballs` for dates and timestamps, as PostgreSQL does.
- `infinity` and `-infinity` were already read.
- `DateStyle` output other than ISO (`SQL`, `German`, `Postgres` with DMY/MDY order) is not
  written: values are rendered by `to_text_in(zone)` after the statement ends, where only the time
  zone is passed, so the style has to travel with the zone through every caller first.

**Status:** code written, unbuilt (code-only mode, D355).
