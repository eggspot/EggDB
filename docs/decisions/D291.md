## D291 SQL Server leftovers: `MERGE ... WHEN NOT MATCHED BY SOURCE`, `OPENJSON` without `WITH`, `sp_getapplock`'s -2 and -3, and SqlClient's `GetSchema("Databases")` through `sysdatabases` — Decided by the build loop (EggAgentCode task 20261103-0137, 2026-11-03); roadmap items 23b, 41, 46, 47 and 48, applies D9, D10, D12, D132, D133, D137 and D138

Applications and tools written for SQL Server still hit refusals that the earlier SQL Server
items left open. This decision closes the ones that fit the existing executors and records why
the rest wait.

- **TDS save points.** Already done before this decision: a transaction manager request
  `TM_SAVE_XACT` runs `SAVE TRANSACTION name`, and `TM_ROLLBACK_XACT` with a name rolls back to
  that save point while keeping the transaction (D138, D173). This is tested in
  `crates/eggdb-tdswire/tests/rpc.rs`. Roadmap item 23b's "Next: save points" was out of date.
- **`MERGE ... WHEN NOT MATCHED BY SOURCE`.** The Transact-SQL parser accepts up to two
  `WHEN NOT MATCHED BY SOURCE [AND condition] THEN UPDATE SET ... | DELETE` clauses, as the
  `MERGE` reference allows. When there are two, the first must have `AND`, and one must be
  `UPDATE` and the other `DELETE`; anything else is Msg 10714. They are kept on the statement
  as `MergeStatement::by_source`. The `MERGE` executor marks each target row that some source
  row matches through `ON`. Every unmarked row goes to the first by-source clause whose
  condition holds, with the source's columns NULL. Matched updates, by-source updates (through
  the same `store_updates` path, with triggers, `NOT NULL`, `CHECK` and keys) and by-source
  deletes run first, then inserts. `OUTPUT` shows a by-source row with NULL source columns.
  Privileges (`UPDATE`, `DELETE`), the destructive-statement check and name binding walk the new
  clauses too.
- **`OPENJSON` without `WITH`.** `OPENJSON(json [, path]) [AS] alias` is the set-returning
  function `*openjson pairs*`. It returns SQL Server's default schema, one row per array element
  or object member, with these columns:
  - `key`: the index from 0, or the member's name;
  - `value`: a scalar's text, NULL for JSON `null`, or the JSON text of an array or object;
  - `type`: 0 null, 1 string, 2 number, 3 boolean, 4 array, 5 object.

  NULL, or a path that finds nothing, gives no rows. Text that is not an array or an object is
  Msg 13609, as `OPENJSON ... WITH` already does.
- **`sp_getapplock` return codes.** The status is -3 (deadlock victim) when the wait would never
  end: the sessions this one waits for wait, directly or through others, for an application lock
  this one holds. Each waiting session records what it waits for in the registry's
  `application_waits` (locked after `held`, always in that order). The session whose request
  closes the cycle is the victim: it checks when it starts waiting and on every wake-up, so the
  others keep waiting. SQL Server weighs which victim is cheapest to roll back; EggDB picks the
  last requester, which is deterministic. The status is -2 when the wait is cancelled, and the
  cancel still ends the batch, as an attention does in SQL Server. Cycles through PostgreSQL's
  advisory locks are not part of this check.
- **`GetSchema("Databases")`.** SqlClient's collection for SQL Server 2008 and later runs
  `IF OBJECT_ID('master..sysdatabases') IS NULL EXEC sp_executesql N'... FROM sysdatabases ...'
  ELSE EXEC sp_executesql N'... FROM master..sysdatabases ...'` by RPC, with `@Name` NULL or the
  restriction. `EXEC sp_executesql` inside a batch already worked (D137). What was missing was
  the compatibility view: `sys.sysdatabases` is now a system view with SQL Server's columns:
  - `name`, `dbid` (the same id as `sys.databases`) and `sid`;
  - `mode`, `status`, `status2`, `crdate` and `reserved`;
  - `category`, `cmptlevel` (160), `filename` (NULL) and `version` (957).

  The parser resolves `sysdatabases` unqualified, as `dbo.sysdatabases` and as
  `master..sysdatabases` to it, as SQL Server resolves system objects from any schema.

**Tests.**
- `crates/eggdb-sql/src/sqlserver_tests.rs`:
  - `MERGE` by source with every kind of clause and `OUTPUT`;
  - the Msg 10714 refusals;
  - `OPENJSON` without `WITH` over every JSON type, a path, NULL and bad JSON;
  - SqlClient's exact `Databases` text by `sp_executesql`, with and without the restriction.
- `crates/eggdb-sql/src/advisory_locks.rs`: two threads whose application lock waits form a
  cycle, so one gets -3 and the other the lock after waiting.
- `crates/eggdb-tdswire/tests/sqlserver_statements.rs`, over the socket:
  - the `GetSchema("Databases")` RPC;
  - `MERGE` by source and `OPENJSON` without `WITH`;
  - two connections that deadlock on application locks.

**Not yet:**
- bcp native files with `varchar`/`char` columns as `SQLCHAR`. A table keeps no record of
  whether a column was declared `varchar` or `nvarchar` (D133's "exact declared type"), so
  `--native` cannot tell which layout bcp wrote.
- `INSERT BULK` and `SqlBulkCopy` skipping `CHECK` constraints without `CHECK_CONSTRAINTS`. SQL
  Server then marks the constraint not trusted (`is_not_trusted` in `sys.check_constraints`).
  EggDB has no untrusted constraint state, so it keeps checking every row rather than skip
  silently.
- A smoke-test step for `--native`.
- Cursor variables (`DECLARE @c CURSOR`, `SET @c = CURSOR FOR ...`), `FOR UPDATE` with `WHERE
  CURRENT OF`, `sp_cursor*` server cursors over RPC, and global cursors dropped by
  `sp_reset_connection`.
- A second `WHEN MATCHED` clause, `$action`, `TOP` and `OUTPUT ... INTO` in `MERGE`.
- EF Core 9 in CI's `tds-apps` job, and `GetSchema("Databases")` added to the `tds-apps` metadata
  program.
- mssql-jdbc's `getSchemas()`.
