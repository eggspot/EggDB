## D167 Large values streamed a page at a time: readers and writers over the overflow chain, with the cache limit kept — Decided by the build loop (by judgement, 2026-10-31); refines D88

Part 4.M2-1 lets a value move between the database and a file or socket without being held
whole in memory.

- **Reading.** `get_reader` on a read or write transaction returns a `ValueReader`, an
  `std::io::Read` over the value. A value in its leaf is copied once (it is at most 750 bytes
  with 4 KiB pages). A value on overflow pages is read a page at a time: each read takes the
  store, reads and checks the next page of the chain exactly as a whole read does (type,
  layout, owner, index, bytes held, the zero tail of the last page), copies, and lets the store
  go. A reader of a read transaction reads that transaction's snapshot, so a commit that replaces
  the value meanwhile changes nothing it reads.
- **Writing.** `put_reader(key, len, source)` checks the limits for `len` first, as `put` does,
  then writes the overflow chain a page at a time as the source is read. It takes the store for
  each page only, so readers are not held up by a slow source. The chain is recorded for its key
  only once complete, and the leaf gets its reference through the same insert as `put`, so
  replacing a value frees the old chain as before. A value small enough for its leaf is read
  into memory and stored by `put`.
- **Errors roll back.** A source that fails, ends before `len` bytes or holds more fails the
  transaction and rolls it back, as any failure inside a change does, so no half-written chain
  is ever reachable.
- **The cache limit stays.** A write transaction's pages stay in the page cache until the commit
  (no-steal, D79), so a streamed value still needs about its size in cache and is refused with
  `ValueExceedsCache` when it cannot fit, before anything is read. Streaming a value larger than
  the cache needs dirty pages spilled before the commit, which belongs to the transaction work
  of M3 (4.M3-1).
- **The CLI.** `eggdb get` with the `raw` format (the default in a pipe) streams the value, and
  `eggdb put <file> <key> @path` streams the file in; stdin, collections and `--ttl` keep the
  whole-value path.
