## D876 GraphQL introspection — Decided by the code-only session (2026-11-12, D355); follow-up of D875

- `__schema` and `__type(name: ...)` answer from the schema the GraphQL API generates from the tables, so GraphiQL,
  Apollo's tools and code generators read it with the standard introspection query (fragments, `includeDeprecated`
  and the 2021 fields `specifiedByURL`, `isRepeatable` and `isOneOf` included).
- The types follow Hasura's names: per table its object type, `<t>_bool_exp`, `<t>_order_by`, `<t>_select_column`,
  `<t>_update_column`, `<t>_insert_input`, `<t>_set_input`, `<t>_inc_input` (numeric columns), `<t>_pk_columns_input`,
  `<t>_constraint` and `<t>_on_conflict` (primary keys and unique constraints), `<t>_mutation_response`,
  `<t>_aggregate`, `<t>_aggregate_fields` and `<t>_<function>_fields`; a `<Scalar>_comparison_exp` per scalar in use
  (with the text operators on `String` and `_contains` on `jsonb`); the `order_by` enum; `query_root` and
  `mutation_root`; and the `include`, `skip` and `deprecated` directives. `_by_pk` fields appear only for tables with
  a primary key.
- Column types become Hasura's scalars: `integer` is `Int`, the text types `String`, `boolean` `Boolean`, `double
  precision` `float8`, `real` `float4`, timestamps `timestamptz` and `timestamp`, and any other type its own scalar
  named after the SQL type (`bigint`, `numeric`, `jsonb`, `uuid`, `date`, ...). Relationship fields and filters are
  described the way D875 names them.
- The model is read from `information_schema` (tables, columns, `table_constraints`, `key_column_usage`) only when a
  request asks for `__schema` or `__type`, as the signed-in user, so a user sees only what the catalog shows them.
- Left: the introspection meta-types themselves (`__Schema`, `__Type`, ...) in `types` (GraphQL clients supply their
  own), descriptions from `COMMENT ON`, and subscriptions.
