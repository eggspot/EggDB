## D475 SCRAM-SHA-1 for MongoDB drivers — Decided by the code-only session (2026-11-11, D355); roadmap M9, D197

- `eggdb-auth` gains `scram_sha1`: a SCRAM-SHA-1 verifier (PBKDF2-HMAC-SHA1, at least 4,096
  rounds) and the server's side of the exchange (RFC 5802), without channel binding, with the
  same failure kinds and the same unknown-user behaviour as SCRAM-SHA-256 (a salt derived from a
  server secret and the name, and a proof that never matches).
- MongoDB's SCRAM-SHA-1 runs over `hex(md5("<user>:mongo:<password>"))`, as MongoDB derives it.
  `eggdb serve` derives that verifier at start from the password it already reads, beside the
  SCRAM-SHA-256 one, with the same salt and 15,000 rounds; the password is still not kept.
- `saslStart` with `SCRAM-SHA-1` runs that exchange; `hello`'s `saslSupportedMechs` lists
  `SCRAM-SHA-1` and `SCRAM-SHA-256`, so current drivers still pick SCRAM-SHA-256. An embedder that
  leaves `sha1_verifier` empty offers SCRAM-SHA-256 only.
- SHA-1 is used here only because MongoDB's older drivers require it (eggdb-crypto's rule for
  SHA-1). Other users and roles stay open in this roadmap line.
