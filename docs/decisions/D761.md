## D761 Evidence reports for SOC 2, HIPAA and PCI DSS (eggdb_compliance) — Decided by the code-only session (2026-11-12, D355); roadmap M6b, evidence reports for SOC 2, HIPAA and PCI DSS audits (D26)

- `CREATE EXTENSION eggdb_compliance` adds six checks that read only what EggDB can show from inside the database:
  privileged roles, login roles without a password expiry within 90 days, table grants to `PUBLIC` (failing on
  classified or tagged tables), the personal-data inventory from `eggdb_privacy` and `eggdb_catalog`, `eggdb_ledger`
  chains verified, and `eggdb_retention` rules with overdue erasure requests. A check whose extension is missing
  reports `review` or `fail` with a note instead of guessing.
- `controls` maps each check to SOC 2 Trust Services Criteria (CC6.1, CC6.3, C1.1, C1.2), HIPAA Security Rule
  sections (164.312(a)(1), 164.312(c)(1), 164.308(a)(1)(ii)(A)) and PCI DSS v4.0 requirements (3.2.1, 7.2.1,
  7.2.2, 8.3.9, 10.3.2, 12.5.2). It is an ordinary table, so an organization adds its own mappings.
- `evidence([framework])` runs the checks once per call, keeps them in `runs` and `results` (the history an auditor
  samples), and returns one row per control. Statuses: `pass` when the check is satisfied, `fail` when it finds a
  violation, `review` when a person must judge the evidence.
- Server events in the audit log (logins, privilege and schema changes), encryption at rest and TLS settings, and
  backups are not checked yet: they are not readable from SQL, and come with the audit-log and encryption items.
  Rendering the report as a PDF through `eggdb_pdf_table` (D746) is left.
