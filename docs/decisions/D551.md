## D551 `menu`, `menuitem` and `searchbox` accessibility roles — Decided by the code-only session (2026-11-11, D355); roadmap M6e, issue #29, D329

The editor's, grid's and tree's right-click menus were exposed as a `group` of `button`s, and the
keys tab's prefix field as a plain text field, because the platform layer had no menu or search
roles. `AccessRole` gains `Menu`, `MenuItem` and `SearchBox`, mapped by each bridge:

| Role | AT-SPI | UI Automation | NSAccessibility | WAI-ARIA (browser) |
|---|---|---|---|---|
| `Menu` | `menu` (33) | `Menu` (50009) | `AXMenu` | `menu` |
| `MenuItem` | `menu item` (35) | `MenuItem` (50011) | `AXMenuItem` | `menuitem` |
| `SearchBox` | `entry` (79), single line | `Edit` (50004), focusable, Value | `AXTextField`, subrole `AXSearchField` | `searchbox` |

A search box is a text role everywhere a text field is (text and editable-text interfaces,
typing, a click focusing it). A menu item invokes as a button does. The three menus now use `Menu`
and `MenuItem`, and the prefix field `SearchBox`, as `docs/ux/workspace.md` 10.9 and 10.10 name
them.
