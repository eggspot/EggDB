## D997 Oracle database links — Decided by the code-only session (2026-11-13, D355); roadmap M10, database links (sql.md, D229, D916)

- `CREATE [SHARED] [PUBLIC] DATABASE LINK name [CONNECT TO user IDENTIFIED BY password] USING '<url>'` and `DROP
  [PUBLIC] DATABASE LINK name` run in the Oracle dialect over the foreign data registry (D229, D916): a link is a
  foreign server whose source is the `USING` URL (`postgresql://`, `mysql://` or `sqlserver://`), with the `CONNECT
  TO` user added when the URL names none. Dropping a link drops the tables imported through it.
- A link to an Oracle database (a TNS name or Easy Connect string) is refused with ORA-02019's code: EggDB does not
  speak Oracle's wire protocol until a lawful public specification exists (D10).
- `IDENTIFIED BY` is accepted and its password is not kept, as passwords stay out of the catalog: the eggdb program
  reads it from `EGGDB_FOREIGN_PASSFILE` or the source's own variable, as for every foreign server.
- `table@link` and `schema.table@link` in a `FROM` clause read the remote table: before the statement runs, the
  session imports each such table that is not imported yet (its columns from the source's `information_schema`) as a
  foreign table in the link's own schema, `eggdb_dblink_<link>`, and the parser reads the reference as that table.
  Without a schema, the remote schema is the source's default (`public`, the MySQL URL's database, or `dbo`).
- Left: writes through links, `@link` on functions and sequences, and links to Oracle databases.
