## D185 External authentication: a rule file per server with LDAP binds and OpenID Connect tokens, in our own eggdb-auth crate — Decided by the build loop (by judgement, 2026-10-31); refines D22 and D183; security-critical (D35)

Part 4.M6b-1 asks for LDAP, Kerberos (GSSAPI), OpenID Connect and client certificates,
configured per listener in an `hba`-style file.

- **A crate of its own**, `eggdb-auth`, depending only on `eggdb-crypto`, so every wire protocol
  can share it: JWT verification (RFC 7515/7517/7518: RS256, RS384, RS512, PS256 and ES256 over
  our own RSA and P-256; `none` and HMAC refused; `exp` required, `nbf`, `iss` and `aud` checked
  with a bounded leeway; `crit` headers refused), LDAP simple binds (RFC 4511 BER written by us,
  user names escaped as RFC 4514 says so they cannot change the bound name, empty passwords never
  sent because LDAP treats them as anonymous binds), and the rule file.
- **The rule file** (`eggdb serve --auth-rules <file>`): `<user|all> <method> [name=value ...]`,
  first match wins, methods `scram-sha-256` (the default for users no line names), `ldap`, `jwt`
  and `reject`. Key sets are read once at start from files next to the rule file; the server
  never fetches anything over the network to check a token.
- **Clear text only under encryption.** LDAP and tokens need the client to send the secret, so
  they use PostgreSQL's `AuthenticationCleartextPassword` and are refused (`28000`) unless the
  connection is TLS or the local socket. A failure looks like a wrong password (`28P01`), is
  logged with its reason, and is throttled like SCRAM failures.
- **External identity, internal privileges.** A user who passes LDAP or a token must still be a
  stored role with `LOGIN` (D183), whose privileges then apply; the token's user claim must equal
  the user name the client sent. The server's own user always uses its SCRAM password.

Left: Kerberos/GSSAPI (it needs the Kerberos protocol and its encryption types, a large clean
room of its own), TLS client certificates (the TLS layer must request and verify them), LDAP
search-and-bind and StartTLS/LDAPS, PostgreSQL 18's `OAUTHBEARER` SASL mechanism, the MySQL and
TDS listeners, and rules by address or database.
