## D603 Oracle's CAST ... DEFAULT ON CONVERSION ERROR and VALIDATE_CONVERSION — Decided by the code-only session (2026-11-12, D355); roadmap M10, D431

D431 gave Oracle 12.2's `DEFAULT … ON CONVERSION ERROR` to the `TO_*` conversion functions. It left
the same clause on `CAST`, and `VALIDATE_CONVERSION`, which data-cleaning queries use to find the
rows that would not convert.

- `CAST(value AS type DEFAULT fallback ON CONVERSION ERROR)` is read in the Oracle dialect only.
  It becomes an internal call, `oracle_cast_with_default`, whose last argument is
  `CAST(NULL AS type)`. That cast carries the target type in the expression tree, so no new
  expression kind is needed (`oracle_functions::type_carrying_call`).
- `VALIDATE_CONVERSION(value AS type)` becomes `oracle_validate_conversion` in the same way.
- The evaluator handles both calls before evaluating their arguments.
  - It casts the value with the same path as `CAST`.
  - On a data exception (SQLSTATE class 22), `CAST … DEFAULT` casts the fallback to the type, and
    fails if that cast fails too, as Oracle does.
  - `VALIDATE_CONVERSION` answers 1 when the value converts or is NULL, and 0 on a data exception.
    Any other error is raised.
- The typer gives `CAST … DEFAULT` the target type and `VALIDATE_CONVERSION` an integer.
- Not done: the format model and NLS arguments of both forms (`CAST('1-1-2020' AS DATE DEFAULT …
  ON CONVERSION ERROR, 'DD-MM-YYYY')`), refused as not supported.
