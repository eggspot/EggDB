## D664 eggdb-sqllogictest, a runner of sqllogictest files — Decided by the code-only session (2026-11-12, D355); roadmap M5, D10, D45

D10 and D45 ask for sqllogictest, the half-million-record SQL suite SQLite's authors published, to
be run with its pass rate published and a minimum that may not drop. EggDB had its own
`correctness/*.test` suites in another format, but nothing that read sqllogictest files.

- A new binary crate, `eggdb-sqllogictest`, runs `eggdb-sqllogictest DIR... [--minimum PERCENT]
  [--engine NAME]`. Each `.test` file under the directories, in name order, gets a fresh
  in-memory database and a session in the SQLite dialect.
- The parser (`records.rs`) reads the format's records:
  - `statement ok|error`;
  - `query <types> [nosort|rowsort|valuesort] [label]`, with its SQL, `----` and the expected
    values, or `N values hashing to MD5`;
  - `hash-threshold N`, `halt`, `#` comments;
  - `skipif`/`onlyif` lines. They are matched against the engine name, `sqlite` by default
    because the dialect is SQLite's, so the files' `onlyif mysql` records are skipped.
- Values are printed as sqllogictest prints them:
  - `I` columns as truncated integers;
  - `R` with three decimals;
  - `T` with `(empty)` for an empty string and `@` for characters outside printable ASCII;
  - `NULL` as `NULL`.

  Sort modes apply to rows or single values. Results longer than the hash threshold, or given as
  a hash, are compared by the MD5 of the values joined by newlines, from `eggdb-crypto`.
- Each failed record is reported with its file and line. Each file's pass rate and the total are
  printed, and the run exits with status 1 when the total is below `--minimum`.
- The suite's files are not in the repository. A CI job that fetches them, publishes the rate and
  sets the minimum is a CI change left for a session that builds.
- Tests: the parser's handling of conditions, sort modes and hashes, and the value printing (MD5
  of nothing).
