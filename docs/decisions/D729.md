## D729 `WHERE` equalities use the graph indexes — Decided by the code-only session (2026-11-12, D355); roadmap M13, follow-up of D728

- Before a `MATCH` pattern runs, each `WHERE` condition of the form `n.property = value` (either side, joined to the
  rest by `AND`) is copied into the pattern's start node as an inline property, when `n` is the pattern's start
  variable, not bound yet, and `value` reads only parameters, literals and variables the row already binds. The
  start nodes then come from a property index (D728) when one covers those properties.
- The `WHERE` still runs on every match afterwards, so results are the same as before; an inline property and
  `=` agree on every value, `null` included (neither matches).
- Only the start node of each pattern and only `=` are used; ranges, `IN` and conditions under `OR` or `NOT` still
  scan the label.
