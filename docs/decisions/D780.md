## D780 An index advisor from statement statistics (eggdb_advisor) — Decided by the code-only session (2026-11-12, D355); roadmap M6c, an index and plan advisor (D25, D31)

- `CREATE EXTENSION eggdb_advisor` works from data the server already keeps: the normalized statement shapes in
  `pg_stat_statements` (D286), whose literals are `$n` parameters, so the advisor reads which columns a statement
  compares with a value without seeing any value.
- `find_indexes` takes the costliest shapes, finds the single table after `FROM` or `UPDATE` and the columns its
  `WHERE` compares with a parameter, keeps the ones that exist in the schema, and asks the planner, through `EXPLAIN`
  of a lookup with a value taken from the table, whether that column is read by a sequential scan. Only those become
  recommendations, ranked by the execution time of the statements that would use them. Text matching on normalized
  SQL misses joins' second tables and expressions; it errs towards proposing nothing.
- Nothing changes without a call: `apply` or `apply_all` above a cost runs the `CREATE INDEX` and records when, which
  a pg_cron job can do for automatic tuning within bounds the operator sets.
- Multi-column and covering indexes, plan advice beyond indexes, dropping unused indexes, and configuration tuning
  are left.
