## D432 Oracle's `(+)` outer joins — Decided by the code-only session (2026-11-11, D355); roadmap M10

- In Oracle's dialect a column followed by `(+)` is parsed into an internal marker (a function
  whose NUL-led name no SQL can write). When a `SELECT`'s `WHERE` holds markers, the parser
  rewrites the query block before building it (`parser/oracle_outer_joins.rs`): the `WHERE` is
  split into its `AND`ed conjuncts; a conjunct whose markers all name one table (by alias or
  name) moves, markers removed, into that table's join condition, and the table's comma join
  becomes a `LEFT JOIN ... ON` the conjuncts (all of them, so `b.status(+) = 'X'` filters the
  joined rows, not the result, as in Oracle). The other conjuncts stay in `WHERE`.
- When the marked table is the first of exactly two (`FROM b, a WHERE a.id = b.id(+)`), the join
  becomes `b RIGHT JOIN a`, which keeps `SELECT *`'s column order. A marked first table of three
  or more is refused with a hint to list it later; a condition naming a table that comes after
  the outer-joined one fails as an unknown table, where Oracle reorders: known differences.
- Oracle's errors: two outer-joined tables in one conjunct is ORA-01468; `(+)` beside an ANSI join
  of that table is ORA-25156; `(+)` in the select list or without a `FROM` is ORA-30563. A marked
  column must carry its table's name or alias (an unqualified one would need the catalog to tell
  its table). `(+)` in `UPDATE`, `DELETE` and subquery correlations is left.
