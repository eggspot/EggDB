## D1166 `JSON_TABLE`'s `PLAN DEFAULT (OUTER | INNER, UNION | CROSS)` — Decided by the code-only session (2026-11-14, D355); roadmap M6a (D289)

- **The clause.** `JSON_TABLE(... COLUMNS (...) PLAN DEFAULT (...) [ON ERROR])` takes the SQL standard's default
  plan, in any order and either part alone:
  - `OUTER` (the default) keeps a row whose nested paths give no rows, with their columns `NULL`.
  - `INNER` drops it.
  - `UNION` (the default) gives sibling nested paths' rows one after another, each with the other's columns
    `NULL`.
  - `CROSS` gives every combination of them. Under `OUTER` a sibling with no rows counts as one `NULL` row;
    under `INNER` it leaves no rows.
- **Encoding.** `TablePlan` carries it as `PlanJoin`, encoded as one trailing number only when it is not the
  default, so plans encoded before this batch decode unchanged. A bad code is a damaged plan.
- **Row counting.** Every combined row counts against `JSON_TABLE`'s row limit.
- **Not built.** The specific `PLAN (p1 OUTER (p2 CROSS p3))` form, which needs named nested paths, is refused
  with `0A000` and a message pointing at `PLAN DEFAULT`. PostgreSQL 17 shipped `JSON_TABLE` without any `PLAN`
  clause, so PostgreSQL clients never send it.
- **Tests.** A plan round trip with a join and a refused bad code. Two sibling paths under each of the four
  combinations: union, cross, inner with an empty sibling, and a document with both empty.

**Status:** code written, unbuilt (code-only mode, D355).
