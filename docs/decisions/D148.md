## D148 SQL Server restore follow-ups: large batches cut by a scanner, identity shapes and types EggDB lacks rewritten by the restore, `XACT_ABORT` and uncommittable transactions in the engine, Transact-SQL sequences, `MS_Description` as comments, `GO` in `eggdb sql` — Decided by the build loop (by judgement and Microsoft's public Transact-SQL reference, 2026-10-30); roadmap item 40-T (batch part 3.04), applies D9, D10, D13, D114, D122, D123, D125, D147; extends D125

D125 left tiers 40-T1 to 40-T4 and four smaller items for later. They are built here, with no
file-format change: what EggDB cannot keep yet is rewritten by the restore and listed as a known
difference, and what both ways in (`eggdb restore` and `sqlcmd -i` against `eggdb serve`) need is
engine syntax.

**Large batches (40-T1).** The script reader still cuts a batch that holds 1 MiB before a line
starting a data statement, now `INSERT`, `UPDATE`, `DELETE` or `SET IDENTITY_INSERT`. A part
still over 4 MiB is no longer refused: a scanner finds statement boundaries at each `;` and
before each line starting `INSERT`, `UPDATE` or `DELETE`, outside strings, names, comments,
parentheses, `BEGIN ... END` (not `BEGIN TRAN`) and `CASE ... END`, and packs the statements into
groups of at most 4 MiB, each found by the Transact-SQL parser as before. One statement over 4 MiB
runs whole when it is an `INSERT`, `UPDATE` or `DELETE` (a large value), and is an error naming
its line otherwise. The token memory bound of D125 holds. A cut that falls between `WITH ... AS
(...)` and its statement breaks that statement (a known limit, as before for `INSERT`).

**Identity shapes and types (40-T2), by the restore.** EggDB's identity must be the first column
of the primary key (D111) and an integer. A `CREATE TABLE` the engine refuses for that (42P16,
Msg 40517) is run again without the `IDENTITY` property; `numeric(p, 0) IDENTITY` with p up to 18
becomes a `bigint` identity (every such value fits) and a wider one loses the property. A lost
identity is a known difference, and the table's `SET IDENTITY_INSERT` lines are ignored and
counted (SQL Server's 8106 would otherwise stop the restore). Alias types (`CREATE TYPE name FROM
base [NOT NULL]`) are remembered by the script reader and their columns take the base type as
written, with `NOT NULL` when the alias has it and the column says neither; the `CREATE TYPE` is
ignored and listed as a known difference. An `xml` column (or an alias of `xml`) becomes
`nvarchar(max)` and is listed: its values stay text, without XML methods or schema collections.
The engine keeps refusing `xml` in sessions, so no session pretends to have an XML type.

**`XACT_ABORT` (40-T3), in the engine.** `SET XACT_ABORT ON|OFF` is a session setting. With it
on, a run-time error rolls the open transaction back and ends the batch, in the batch runner and
in `Session::execute`. As Microsoft documents, compile errors (syntax errors here) and
`RAISERROR` are not affected and `THROW` is. Inside `TRY`, the error moves to `CATCH` and the
transaction stays open but uncommittable: `XACT_STATE()` is -1, `ROLLBACK` ends it, `COMMIT` and
every write are Msg 3930, and a batch that ends with it open rolls it back and reports Msg 3998.
An error raised in `CATCH` while it is uncommittable rolls it back at once (one Msg 3930, no
3998). The restore runs `SET XACT_ABORT` like the other settings; it has no effect there, since
every statement is its own transaction.

**UTF-16 big-endian and sequences (40-T4).** A `FE FF` byte-order mark is read as UTF-16
big-endian, with the same surrogate and odd-length checks as little-endian. Transact-SQL's
`CREATE SEQUENCE` (with SQL Server's defaults: `bigint`, the type's range, starting at its
minimum, or maximum when descending), `ALTER SEQUENCE` and `DROP SEQUENCE [IF EXISTS]` make the
same sequence objects as PostgreSQL's (D114): `tinyint` is a `smallint` sequence from 0 to 255 and
`decimal(p, 0)` a `bigint` one within p digits (p up to 18; wider is Msg 11702). `NEXT VALUE FOR
name` calls the internal next-value function Oracle's `s.NEXTVAL` uses, and is detected as a
sequence call in statements and stored defaults. The restore runs them and counts sequences.

**The rest.** `MS_Description` extended properties become comments: `sp_addextendedproperty`,
`sp_updateextendedproperty` and `sp_dropextendedproperty` on a schema, table, view, or a table's
column, index or constraint are parsed into `COMMENT ON`'s statement, and `sys.extended_properties`
lists the comments of schemas, tables, views and columns. Other properties and object types are
40517 in a session and ignored by the restore. `CHAR(n)` was built by item 39b; SSMS's raw line
breaks and `+ CHAR(13) + CHAR(10) +` both restore. `eggdb sql --dialect sqlserver` splits its
SQL at `GO` lines with the restore's reader, keeping each batch whole (no 1 MiB cuts), runs each
as before (`GO n` n times), stops at the first error, and refuses sqlcmd commands, which only
`eggdb restore` and sqlcmd handle; no new output, so no new design.

**Left for later:** `xml` as a type with its methods; identity on any column; `NEXT VALUE FOR`
returning the sequence's own type and its `OVER` form; `sp_sequence_get_range`; extended
properties other than `MS_Description` and on procedures, functions and parameters.
