## D1092 The Android Archive, emulator runs and Android's 32-bit ABIs in CI — Decided by the code-only session (2026-11-13, D355); roadmap M17 (D222, D8, D16)

- **A Gradle library module beside the driver, not a copy of it.** `drivers/android` is an Android library (`com.android.library`, Kotlin Android plugin) whose `main` source set reads `drivers/kotlin/src`, and whose CMake build compiles `drivers/kotlin/jni/eggdb_jni.c` against `crates/eggdb-capi/include` and links the prebuilt `libeggdb_capi.so` of each ABI. The JVM check, the device tests and the archive therefore run the same Kotlin and C. Gradle, the Android Gradle plugin and AndroidX test are build and test tooling, which D1 allows; nothing from them ships in the archive except the Android runtime's own conventions.
- **Four ABIs.** `scripts/android/build-aar.sh` builds the C API with the NDK's clang (API 23) for `aarch64-linux-android`, `armv7-linux-androideabi`, `x86_64-linux-android` and `i686-linux-android`, putting each library where the module's `jniLibs` expects it, then assembles the AAR. The 32-bit ABIs are therefore built in CI on every PR, not only linted.
- **Emulator runs.** CI's `android` job runs on Linux with KVM and a matrix of `x86_64` and `x86` Android 11 (API 30) emulators, so both a 64-bit and a 32-bit ABI execute the device tests: SQL with a non-BMP character, and the key-value API across `setPowerSource`, `suspend`, `resume` and a read-only reopen (D1087, D1088). The emulator is started by `reactivecircus/android-emulator-runner` and Gradle by `gradle/actions/setup-gradle`, both CI tooling. The public repo pays nothing for the parallel matrix.
- **Left.** Running on ARM emulators (no hosted runner offers them at speed) and publishing the AAR with releases (D58's registry accounts).
