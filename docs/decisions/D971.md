## D971 MySQL's two-digit `YEAR` values — Decided by the code-only session (2026-11-13, D355); roadmap M10, follow-up of D684 and D970

- MySQL reads a `YEAR` value from 1 to 69 as 2001 to 2069 and from 70 to 99 as 1970 to 1999; D684's check (1901 to
  2155, or 0) refused them. The trigger D970 adds for `SET` columns now also covers a table's `YEAR` columns, found by
  D684's implicit check, and rewrites those values before the check runs; 0 and four-digit years are kept.
- MySQL also reads the strings `'0'` and `'00'` as 2000 while the number 0 stays 0; the column is stored as a
  `smallint`, so by the time the trigger runs both are 0, and both stay 0. That difference is left, with `YEAR`
  columns added by `ALTER TABLE`.
