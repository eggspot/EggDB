## D423 MySQL's `LOAD DATA LOCAL INFILE` — Decided by the code-only session (2026-11-11, D355); roadmap M10

- **Statement.** The MySQL dialect parses `LOAD DATA [LOW_PRIORITY | CONCURRENT] [LOCAL] INFILE
  'file' [REPLACE | IGNORE] INTO TABLE t [PARTITION (...)] [CHARACTER SET cs] [{FIELDS | COLUMNS}
  [TERMINATED BY 's'] [[OPTIONALLY] ENCLOSED BY 'c'] [ESCAPED BY 'c']] [LINES [STARTING BY 's']
  [TERMINATED BY 's']] [IGNORE n {LINES | ROWS}] [(column | @variable, ...)] [SET column = expr,
  ...]`. Only `LOCAL` is served: a file on the server's disk is refused with MySQL's error 1290,
  as MySQL refuses it under `--secure-file-priv`, since EggDB's server has no business reading
  its machine's files for a client. `LOAD XML` stays refused. Character sets other than UTF-8,
  ASCII, Latin-1 and binary are refused (the data is read as UTF-8).
- **Wire.** The MySQL server now offers `CLIENT_LOCAL_FILES`. The data travels through the same
  client channel as PostgreSQL's `COPY ... FROM STDIN` (`CopyChannel`), whose `CopyStart` gains the
  file name: the MySQL connection's channel (`eggdb-mysqlwire` `local_infile.rs`) sends MySQL's
  local-infile request (`0xFB` and the name), reads the client's packets until the empty one, and
  the statement's OK or error follows. A client that didn't enable local files gets error 3948.
- **Reading.** A streaming reader of MySQL's format (`session/mysql_load.rs`): the field and line
  terminators, the enclosing character (doubled inside a field, and only at a field's start), the
  escape character (`\0 \b \n \r \t \Z`, and `\N` as `NULL`; without an escape character an
  unenclosed `NULL` is `NULL`), the line prefix (text before it, and lines without it, skipped)
  and the ignored first lines. A record over 64 MB fails the load.
- **Loading.** Rows go into the table in batches of 500 through `INSERT`, `INSERT IGNORE` or
  `REPLACE` statements in the MySQL dialect, so every insert rule, trigger and constraint applies
  as for SQL. A missing target list loads the table's columns in order; missing fields are
  `NULL`, extra ones are dropped; `@variable` targets and `SET` expressions are filled in per row,
  the `SET` expression seeing the row's variables and loaded columns. As in MySQL, `LOCAL` without
  `REPLACE` or `IGNORE` behaves as `IGNORE`. The result is the affected row count with MySQL's
  `Records: n  Deleted: 0  Skipped: n  Warnings: 0` as a note. Known differences: no warnings for
  short or long rows (MySQL gives 1261 and 1262), and a load is not one statement for
  `ROW_COUNT()` or binary logging; a failed batch fails the whole load inside the statement's
  transaction.
- `LOAD DATA ... PARTITION` (roadmap M2) passes the partition list to the inserts.
