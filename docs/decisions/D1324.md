## D1324 Wayland windows, and the client on EggOS — Decided by the code-only session (2026-11-25, D355); extends D256; follows D1323

- **What users get.** On a Linux desktop running a Wayland compositor (GNOME, KDE Plasma, Sway and the others), `eggdb-gui` opens its window as a native Wayland client instead of going through XWayland, and on EggOS it opens through EggOS's Wayland server `eggway` (EggOS D140), with nothing EggOS-specific in EggDB (D1323). The window is resized by the compositor, follows the output's scale (whole factors), closes from the compositor's close button, takes the pointer (moves, the three buttons, the wheel both ways) and the keyboard (the keys the GUI uses, letters and symbols on a US layout with Shift, Caps Lock, Control and Alt, and key repeat at the compositor's rate and delay). Screen readers reach it through the same AT-SPI2 bridge as on X11 (D278), which works beside Wayland over D-Bus: the window's tree, its focus and the readers' requests.
- **Which system.** A Linux window goes to Wayland when a compositor is named (`WAYLAND_DISPLAY` in `XDG_RUNTIME_DIR`, or `eggway`'s socket `/run/user/0/wayland-0` on EggOS), and to X11 otherwise; `EGGDB_WINDOW_SYSTEM=x11` or `wayland` chooses. A compositor that cannot be reached falls back to the X server when one is named.
- **How.** `eggdb_platform::window::wayland` is the protocol, written from the public `wayland.xml` and `xdg-shell.xml` (MIT): the wire format's requests and events, the request and event numbers the window uses, the US map from Linux key codes, and `ARGB8888` pixels; it makes no system call and is tested everywhere. `wayland_window` talks to the compositor over its Unix socket: the registry, `wl_compositor`, `wl_shm`, `xdg_wm_base`, `wl_seat` and `wl_output`, an `xdg_toplevel` with the title, the app id `eggdb` and the smallest size, and two shared-memory buffers in a file of `XDG_RUNTIME_DIR` (unlinked at once), written with `pwrite` and handed over in turn as the compositor releases them. The pool's file descriptor goes with `sendmsg`, our one declaration of a C function here, in one `unsafe` call; the frames themselves need no mapping.
- **Left.** Keyboard layouts other than US (reading the compositor's XKB keymap), input methods, the clipboard and drag and drop (`wl_data_device`), screen positions for the readers (Wayland does not tell a window where it is), fractional scales, and server-side decorations where a compositor draws none.
- **Proof.** Protocol tests write a request with a padded string, split events off a stream with a partial one behind and refuse a size the protocol forbids, read fixed-point numbers, convert pixels, and map keys with Shift and Caps Lock.
