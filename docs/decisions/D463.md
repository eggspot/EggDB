## D463 Elasticsearch `_search` hits sent as a stream — Decided by the code-only session (2026-11-11, D355); roadmap M6a, extends D325

- A `_search` (`/_search` and `/<index>/_search`, GET or POST) now answers a `StreamedResponse`
  through `Api::reply`: the search runs as before up to the ranked page, then the response's head
  (`took`, `_shards`, `hits.total`, `max_score`) is sent, each hit's object is rendered from the
  stored source only when it is written (with `_source` filtering and `sort` values), and the
  tail with `aggregations` (rendered before streaming starts) closes it.
- The search is split into `search_page` (the page) and its renderers, so `_count`, `_msearch`,
  search templates and `Api::answer` keep whole responses from the same code.
- The documents are still read into memory for scoring (a search has no index of its own yet), so
  this saves the rendered body, not the read. Scroll (`scroll=` and `_search/scroll`) does not
  exist in EggDB's Elasticsearch API yet, so "search and scroll" is search only until scroll lands.
