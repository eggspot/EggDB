## D1235 DBMS_METADATA.GET_DDL for triggers, routines and packages — Decided by the code-only session (2026-11-17, D355); roadmap M10, Oracle's packages (D859, D1234)

- **What users get.** `DBMS_METADATA.GET_DDL` for `TRIGGER`, `FUNCTION`, `PROCEDURE`, `PACKAGE` (specification and body), `PACKAGE_SPEC` and `PACKAGE_BODY`: the statement that made the object, as stored when it was created, so an Oracle schema's code can be scripted out like its tables. A function asked for as a procedure, or any missing object, is ORA-31603.
- **How.** These objects keep their source text in the catalog snapshot (the trigger's, the routine's `CREATE` text, the package's specification and body); `get_ddl` returns it as one statement (adding `CREATE OR REPLACE` to a package part kept without it) before looking for relations.
- **Left.** Synonyms, users, roles and grants, Oracle's `"OWNER".` prefixes and `EDITIONABLE` keywords, and `DBMS_METADATA.SET_TRANSFORM_PARAM`.
- **Proof.** `oracle_tests.rs`: a PL/SQL function's DDL holds its name and body, and the same name asked for as a procedure is refused.

**Status:** code written, unbuilt (code-only mode, D355).
