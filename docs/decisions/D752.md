## D752 Blind indexes for searching sealed columns — Decided by the code-only session (2026-11-12, D355); roadmap M6b, blind-index search on encrypted columns (D52)

- `eggdb_blind_index(value, key [, bits])` returns HMAC-SHA-256 of the value under a key of at least 16 bytes, cut to
  `bits` (8 to 256, a multiple of 8; 64 by default) and written in hex. Stored beside a column sealed with
  `eggdb_seal` (D751), it lets `WHERE column_index = eggdb_blind_index($1, key)` find rows by exact value with an
  ordinary B-tree index, without the database holding the plaintext or the sealing key.
- The index key must differ from the sealing key. Fewer bits leak less (more unrelated values share an index) at the
  cost of more false matches, which the application filters after unsealing. Values should be normalized before
  indexing (case, spaces, formats), since only identical bytes match.
- Range, prefix and fuzzy search on encrypted columns are left.
