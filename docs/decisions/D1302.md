## D1302 MySQL's network, UUID, hash and base64 functions — Decided by the code-only session (2026-11-18, D355); roadmap M4 MySQL compatibility (D1291)

- **What users get.** In MySQL's dialect: `INET_ATON` (dotted quads and their short forms such as `127.1`), `INET_NTOA`, `IS_IPV4`, `IS_IPV6`, `UUID_TO_BIN(uuid[, swap_flag])` and `BIN_TO_UUID(binary[, swap_flag])` (with the flag, the time-high and time-low fields swapped so time-based UUIDs index in order, as MySQL 8 does), `SHA1`, `SHA2(text, 224 | 256 | 384 | 512)` (0 meaning 256; 224 from D1303), `TO_BASE64` and `FROM_BASE64` (whitespace ignored, NULL for bad input).
- **How.** Beside D1291's functions, with EggDB's own SHA and base64 code from `eggdb-crypto` and the standard library's address parsing.
- **Also.** `INET6_ATON` (4 bytes for an IPv4 address, 16 for IPv6) and `INET6_NTOA` (IPv6 written in its shortest form).
- **Left.** `MD5` in MySQL's form (PostgreSQL's `md5` already answers), and `AES_ENCRYPT`.
- **Proof.** Unit tests convert addresses (full, short and out of range) and swap a documented UUID's fields both ways.

**Status:** code written, unbuilt (code-only mode, D355).
