## D633 SQL*Plus COLUMN formatting in eggdb shell — Decided by the code-only session (2026-11-12, D355); roadmap M5, D150, D544, D622

Oracle scripts set `COLUMN ename FORMAT a20 HEADING 'Employee'` before their reports, and DBAs
type `COL sal FOR 9,999.99` without thinking. In `eggdb shell` with the Oracle dialect those
lines were sent to the engine as SQL and failed.

- A new `shell_columns` module keeps the session's column formats, by upper-case column name.
  `COL[UMN] name option ...` takes `FOR[MAT] An` (text cut to `n` characters and padded, as
  `TRUNCATED` shows it), `FOR[MAT]` number masks of `9`, `0`, `,`, `.` and a leading `$`
  (rounded to the mask's decimals, right-aligned in the mask's width plus one for the sign, `#`
  across the width when the integer part does not fit, as SQL*Plus shows an overflow),
  `HEA[DING] text` (`|` turns into a space, since the grid shows one header line),
  `NUL[L] text`, `NOPRI[NT]`, `PRI[NT]` and `CLE[AR]`; `ON` and `OFF` are accepted.
  Other options fail with SP2-0158, a bad mask with SP2-0246.
- `COLUMN` alone lists every setting, `COLUMN name` one (SP2-0046 when it has none), and
  `CL[EAR] COL[UMNS]` drops them all.
- Before a result is printed, the shell applies the formats: `NOPRINT` columns are left out,
  headings replaced, and formatted values shown as text. The engine sees none of it.
- Wrapping long text over several lines (SQL*Plus's default `WRAPPED`) is left: the grid shows
  one line per row.
- Tests: the module's tests for setting, listing and clearing, for the result shaping, and for
  the number masks.

**Status:** code written, unbuilt (code-only mode, D355).
