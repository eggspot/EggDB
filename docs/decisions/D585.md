## D585 CQL secondary indexes — Decided by the code-only session (2026-11-12, D355); roadmap M16, D218

EggDB's CQL listener already filters on any column (each query is SQL underneath), but it refused
`CREATE INDEX`, which schemas and migration scripts carry. `CREATE [CUSTOM] INDEX [IF NOT EXISTS]
[name] ON [keyspace.]table (column) [USING '<class>' [WITH OPTIONS = {...}]]` now creates an
ordinary SQL index on the column, named as given or `<table>_<column>_idx` as Cassandra names it,
so queries on the column are served from the index; the index class (SASI, storage-attached) is
read and ignored, and an index on a collection's keys, values or entries is refused, as
collections are. `DROP INDEX [IF EXISTS] [keyspace.]name` drops it. Creating answers
`SCHEMA_CHANGE UPDATED TABLE`, dropping `UPDATED KEYSPACE`, since the dropped index's table is not
looked up.
