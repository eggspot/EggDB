## D493 Kafka SASL/PLAIN authentication — Decided by the code-only session (2026-11-11, D355); roadmap M16, D213

- The Kafka listener takes `SaslHandshake` version 1 (mechanism `PLAIN`; any other answers
  `UNSUPPORTED_SASL_MECHANISM` with `PLAIN` listed) and `SaslAuthenticate` versions 0–1 with a
  PLAIN token (`authzid NUL user NUL password`), checked against `eggdb serve`'s user and the
  SHA-256 of its password in constant time. A wrong one answers `SASL_AUTHENTICATION_FAILED` (58);
  `SaslAuthenticate` before the handshake answers `ILLEGAL_SASL_STATE` (34).
- `eggdb serve` now requires it: until a connection has authenticated, any request but
  `ApiVersions`, `SaslHandshake` and `SaslAuthenticate` closes it, as Kafka brokers with a
  `SASL_PLAINTEXT` listener do. Clients set `security.protocol=SASL_PLAINTEXT` and
  `sasl.mechanism=PLAIN`. An embedder that leaves `credentials` empty serves without SASL.
- PLAIN sends the password in clear text, so the listener stays loopback-only until TLS comes to
  every listener (the M6a line). `SaslHandshake` version 0 (raw tokens after the handshake) and
  SCRAM mechanisms are not written.
