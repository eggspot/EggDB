## D438 More PostGIS functions: centroids, hulls, validity, accessors, affine moves and simplification — Decided by the code-only session (2026-11-11, D355); roadmap M12, extends D204

- `eggdb-geo` gains `operations.rs` (from the OGC Simple Features definitions and PostGIS's
  documentation, no code read): area-weighted centroids (lines by length, points by mean, the
  highest dimension present winning, as PostGIS does), perimeters, convex hulls (Andrew's
  monotone chain; a line or point when the points don't span an area), Douglas-Peucker
  simplification that keeps rings at four points, translation, scaling, axis flips, reversal, and
  a validity check: closed rings of four or more points without proper self-crossings, lines of two
  or more points. Holes outside their shell and polygons of a multipolygon that overlap are not
  checked yet, so `ST_IsValid` can say true where PostGIS says false.
- SQL (`geo_functions.rs`): `ST_Centroid`, `ST_Perimeter`, `ST_ConvexHull`, `ST_IsValid`,
  `ST_IsValidReason` (PostGIS's wording, "Valid Geometry" or "Self-intersection[x y]"),
  `ST_NumGeometries`, `ST_GeometryN`, `ST_StartPoint`, `ST_EndPoint`, `ST_PointN` (negative counts
  from the end), `ST_ExteriorRing`, `ST_NumInteriorRings`, `ST_Reverse`, `ST_FlipCoordinates`,
  `ST_Translate`, `ST_Scale`, `ST_MakeLine(a, b)`, `ST_MakeEnvelope(xmin, ymin, xmax, ymax [,
  srid])`, `ST_XMin`/`XMax`/`YMin`/`YMax` and `ST_Simplify`. Results keep the input's SRID.
- Left: overlay operations (union, intersection, difference, buffer), `ST_MakeValid`, the full
  validity rules and `ST_Transform` beyond Web Mercator.

**Status:** code written, unbuilt (code-only mode, D355).
